# 个人、团队与周期记忆手册

共同规则见项目根 AGENTS.md 第 3–5 节。下列路径均相对项目根目录。

## 个人：保持一份跨轮次记忆

成员先从真实团队/任务读取稳定 memberId，再读取 `.roami/okr/memory/members/<memberId>/memory.md`。首次实际需要时创建，不按 r1/r2 或日期重开记忆。接新任务时读取适用条目、团队约束与最近一次复盘，检查旧知识是否仍适用。

每条候选用以下信息描述：日期/时区、具体结论、适用账号/来源/方法、证据相对路径与本轮 task/revision/run、验证者、状态（待验证/有效/已替代）、下一步。脚本参数或查数方法可以简要记录，原始响应和完整日志仍放交付目录。

成员只维护自己的笔记；共享结论通过群聊交 Main。若宿主只允许 Main 写共享记忆，成员通过群聊交提议；个人笔记按实际文件权限维护，不能把只写 team.md 的接口当成任意文件写入口。原生对话记忆不能替代这份可交接文件，整理对话也不能制造业务成功。

## 团队：从证据提炼可复用结论

Main 每次更新前读取完整文件和当前 SHA/版本。team.md 使用当前项目 memory 的 CAS 操作；decisions.md 和个人文件走各自实际文件权限与单一写入者约定，写前复核原字节，发现变化就合并。Swarm 记忆按其自身 CAS 协议。不能将其中一个接口当作任意路径的写入口，不能拿旧全文覆盖他人刚补的内容。

- `memory/team.md`（位于 `.roami/okr/`）：来源口径、指标映射、职责/交接约定、验证有效的方法及有用的失败恢复方法。
- `memory/decisions.md`：谁在什么时候基于什么来源作出什么决定，范围/负责人、未决项与状态；决定变化时链接被替代条目。
- Swarm 记忆由其自身受支持接口管理。只有实际回读证明同步，才能说与项目文件一致；不凭同名判断同一存储。

群聊提议可按“结论；本轮证据路径；适用范围；待 Main 验证；建议放入哪个文件”写一条短消息。Main 独立检查证据，将验证状态和真实作者写清，再更新长期知识。成员命名为 `main-acceptance` 的文件仍是成员交付，不代表 Main 已验收。

## 时间：事实在日目录，结论按周期提炼

1. 日交付：`materials/YYYY-MM-DD/<渠道或工作类型>/<简短主题>/`。Main 在日 README/manifest 中登记相对路径、所属 KR/方法、所有者、轮次、产出时间、字节数、SHA、来源和验收状态。跨天任务不移动原目录。
2. 日复盘：当天 `reflection/` 中引用实际回执，写结果、数据截至/采集时间、未知、失败与下一实验，不用计划充作完成。
3. 周复盘：`YYYY/reflection/weeks/YYYY-Www.md`，YYYY/周号按项目时区对应日期的 ISO 周年计算。例如 2027-01-01 属于 2026-W53，应放 `2026/reflection/weeks/2026-W53.md`，并链接 2027 的实际日目录。
4. 月复盘：`YYYY/YYYYMM/reflection/month.md`。年复盘：`YYYY/reflection/year.md`。依据实际公历月/年，跨周期的同一文件保留一个原件，用链接引用。
5. 所有周期摘要记录覆盖日期、来源文件/数据修订、已核验结果、缺口、有效经验、被否定假设、下一决定及维护者。没有实际复盘就不预建“已完成”空目录；同一快照不能重复加总为增量。
6. 将仍适用的结论上提到个人/团队长期记忆；证据保留在日期目录，不把所有聊天复制成永久上下文。下一轮主动读相关摘要与索引，需要细节再打开原始证据。

归档不是删除：旧决定、失败回执、原始素材和哈希都保留。任何凭据和登录态都不得进入记忆与产物索引。


## Main 的团队记忆追加入口

先发现 project_okr_context/project_okr_memory_append，读取 context 的 projectFiles.teamMemorySha256，再以 expectedSha256 和仅新增的 content 调 append。这是 team.md 的受管追加入口，不要求通用文件写入权限，也不写其他个人文件。冲突重读合并，成功后回读；同一事实不重复追加，身份核对不能写成登录或发布成功。
