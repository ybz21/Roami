# 团队协作与记忆

每个 OKR 复用自己的 Main，与首页 Main 隔离。`agents/main.json` / main.md 是职责及技能入口，`agents/team.json` 是期望角色；`agents/swarm.json` 指向实际受管团队。配置角色不等于已登记成员，登记不等于已派工。

## 沟通和派工

群聊用于共同进展与交接，给 Main 的消息由 Main 统筹；定向成员消息必须对应其真实 work/task/revision。进入成员原生会话前核对当前任务、运行、执行器、项目归属与会话状态。不能按相似名称、目录里最新实例或聊天里的任意 session 引用跳到另一个项目或首页 Main。

Main 通过当前宿主提供的 register/plan/steer 工具登记、派工与续派，先核对已有成员。每项任务写清范围、输入、交付、验收及硬依赖。新一轮复用稳定成员、原任务和 provider 对话；不要为了更换任务或绕过失败另建 r2/r3 实例。投递成功只表示消息已提交，需要回看实际产物和任务状态。

## 验收和恢复

成员报告当前任务/修订/运行及具体路径。Main 独立读取当前文件、核对依赖和来源证据，再执行受支持验收；不能以成员自称完成、空闲终端或旧轮次文件替代。外部发布分准备、上传、提交、审核、公开，必须对应具体内容授权和平台回执。

会话关闭时先核对原 provider 身份和宿主恢复能力。身份、停止或投递结果不明时对账，不新建替代实例冒充恢复；不要强行改 busy 或宿主验收状态。

## 记忆位置

- `memory/team.md`：团队可复用事实、指标映射与工作约定，由 Main 按当前哈希更新。
- `memory/decisions.md`：重要决定、边界、未决项，注明来源、负责人和状态，保留变化历史。
- `memory/members/<稳定成员ID>/memory.md`：成员个人长期记忆，跨轮次复用。
- `materials/YYYY-MM-DD/<渠道或工作类型>/<简短主题>/`：真正的交付、证据、复盘与平台回执；不是记忆的替代品。

共享日索引由 Main 维护，成员只写各自任务/修订/运行子目录，避免覆盖他人成果。

个人、团队、日/周/月/年记忆的完整规则见项目根 AGENTS.md 第 3–5 节与 [记忆手册](memory.md)。群聊中的记忆提议要注明实际作者、当前轮次和证据，Main 核实后落盘；发言不等于派工、记忆更新或验收。

Main 的当前产物读取、文本验收、CAS 追加和具名群聊命令格式见[自动运行](automation.md)。受管成员后续任务使用原 task_steer；legacy session_send 不作为续派入口。
