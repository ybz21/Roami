# 团队协作与记忆

每个 OKR 复用自己的 Main，与首页 Main 隔离。`agents/main.json` / main.md 是职责及技能入口，`agents/team.json` 是期望角色；`agents/swarm.json` 指向实际受管团队。配置角色不等于已登记成员，登记不等于已派工。

## 成员工作目录

项目根目录供 Main 协调。每位长期成员使用 `workspaces/<成员目录键>/` 放自己的规则和草稿。团队共享 `materials/`，沿用日期与主题目录保存交付和证据。个人长期记忆仍在 `.roami/okr/memory/members/<稳定成员ID>/memory.md`。

1. Main 依据已确认的分工，在项目草稿中为每位成员从 OKR Skill 的 `parts/roles/workspace/` 复制规则模板，填好职责、可用输入和工具、交付、验收及异常上报。每位成员使用一个可读的固定目录键。相同职责的两个实例分别用两个目录键。
2. 登记后用宿主回执把真实成员 ID 写入对应的 `AGENTS.md`，向成员说明规则路径。Claude Code 加一个只引用 `@AGENTS.md` 的 `CLAUDE.md`。更改行为规则由 Main 合并到原文件，成员通过群聊提交修订建议。
3. 开工依次读项目规则、本成员规则、个人记忆和本轮任务。成员只更新自己的草稿和任务约定的共享路径；交接在群聊贴实际路径、任务轮次和证据。Main 根据实际产物独立验收，再登记为团队可复用材料。
4. 只在宿主返回了该成员实际目录绑定时，从子目录启动或恢复受管执行。仍绑定项目根目录的原生会话，开工时显式读取成员规则并用约定子目录整理草稿。由实际执行器确认规则加载。文件约定只负责工作上的分隔，访问限制由宿主权限和沙箱执行。

## 沟通和派工

群聊用于共同进展与交接，给 Main 的消息由 Main 统筹；定向成员消息必须对应其真实 work/task/revision。进入成员原生会话前核对当前任务、运行、执行器、项目归属与会话状态。不能按相似名称、目录里最新实例或聊天里的任意 session 引用跳到另一个项目或首页 Main。

Main 通过当前宿主提供的 register/plan/steer 工具登记、派工与续派，先核对已有成员。每项任务写清范围、输入、交付、验收及硬依赖。新一轮复用稳定成员、原任务和 provider 对话；不要为了更换任务或绕过失败另建 r2/r3 实例。投递成功只表示消息已提交，需要回看实际产物和任务状态。

## 调整成员

用户调整分工时，Main 先用 `swarm_status` 核对实际成员和版本。新职责用 `swarm_members_register` 登记，用回执里的成员 ID 更新项目的 `team.roles` 和个人规则，再用 `swarm_plan` 派工。可以为同一职责新增一个明确需要的实例，给它独立的成员 ID 与工作目录。

删减成员前核对交接和当前任务。用 `swarm_members_lifecycle` 的 `retire` 让已收尾的成员退出，并更新项目中的角色绑定。运行中、待分派、待验收、原生停止状态未知或仍在定时授权中的成员会返回阻塞，需先处理对应原因。定时授权有自己的用户授权范围。退出成员的目录、记忆、原生对话、任务及群聊历史仍可回查。恢复用 `restore` 和原成员 ID，再按实际需求续派。

## 验收和恢复

成员报告当前任务/修订/运行及具体路径。Main 独立读取当前文件、核对依赖和来源证据，再执行受支持验收；不能以成员自称完成、空闲终端或旧轮次文件替代。外部发布分准备、上传、提交、审核、公开，必须对应具体内容授权和平台回执。

会话关闭时先核对原 provider 身份和宿主恢复能力。身份、停止或投递结果不明时对账，不新建替代实例冒充恢复；不要强行改 busy 或宿主验收状态。

## 记忆位置

- `memory/team.md`：团队可复用事实、指标映射与工作约定，由 Main 按当前哈希更新。
- `memory/decisions.md`：重要决定、边界、未决项，注明来源、负责人和状态，保留变化历史。
- `memory/members/<稳定成员ID>/memory.md`：成员个人长期记忆，跨轮次复用。
- `materials/YYYY-MM-DD/<渠道或工作类型>/<简短主题>/`：真正的交付、证据、复盘与平台回执；不是记忆的替代品。

共享日索引由 Main 维护，成员写入本轮约定的 `materials/YYYY-MM-DD/<渠道或工作类型>/<简短主题>/`。任务/修订/运行身份写入 manifest 和宿主回执，不再层层建 UID 目录。已冻结、正在执行或历史交付的路径不移动、不覆盖；成员不得修改他人文件。

个人、团队、日/周/月/年记忆的完整规则见项目根 AGENTS.md 第 3–5 节与 [记忆手册](memory.md)。群聊中的记忆提议要注明实际作者、当前轮次和证据，Main 核实后落盘；发言不等于派工、记忆更新或验收。

Main 的当前产物读取、文本验收、CAS 追加和具名群聊命令格式见[自动运行](automation.md)。受管成员后续任务使用原 task_steer；legacy session_send 不作为续派入口。
