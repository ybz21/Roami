# GitHub 候选采集证据

一次公开请求得到同一仓库的 star/fork，不为两个指标重复拉取。已确认的 repo、稳定
repositoryId、指标单位和日期口径来自当前项目；调用时用 --repository-id 防止同名仓库
被重建后静默换源。首次发现未知 ID 只用于提案，不直接成为已确认观测。

## 原始响应与输出

候选输出包含 candidateOnly、source、asOf、capturedAt、values 与 evidence。
evidence.http.body 是完整原响应的 UTF-8 文本，包括原有空白和末尾换行；保存成 JSON
字符串后重新读取、encode("utf-8") 应得到相同字节和 SHA256。payload 只是解析后的
字段视图，不能用它重新序列化的摘要冒充原响应摘要。

公开 HTTP 状态和 Date、ETag、Last-Modified、Content-Type、X-GitHub-Request-Id
用于核对来源与时间；不包含请求鉴权或 Set-Cookie。不跟随仓库重定向。非200、过大
响应、仓库不符、非法计数或网络失败均停止，不输出伪造候选或将失败变成零。

将 stdout 和原响应保存到当前真实 task/revision/run 的独立目录，成功后回读 JSON、
字节与摘要。未知执行结果不换路径重跑；新文件独占创建，旧事实和其他成员产物保留。
同时保留本次使用的自定义脚本与 Skill 指引的不可变副本和 SHA，或者可恢复的已发布
包版本。修改活目录代码后，不用新文件去验证旧运行的来源。

## Main 确认与看板

Main 读实际本轮 artifact，并核对仓库 ID、字段、指标单位、指标日与采集时间。文件
哈希、执行器成功或一条链接不等于确认观测。当前 collect 接口会再取一次来源；候选
响应与确认响应有不同时间和身份，即使计数相同，也不能说候选已直接批量发布。
只通过支持的项目操作确认，缺少批次能力就记录限制，不改 JSONL/快照/SQLite 绕过。

同日再次采集是另一快照，不是新增增长日；未知互动数不能用于宣传归因。看板复验应
读取实际确认版本并重新进入页面，不能只验脚本 stdout 或演示数据。

## 日索引

Main 的 manifest 明确 pathBase，项目根相对路径包含 YYYY/YYYYMM/YYYYMMDD。
producedAt 来自真实产物证据，不用复盘保存或验收时刻代替。素材批次、源指标日、
文件生成、采集、平台发布与确认写入分开记录；跨午夜运行保留原目录并链接，不挪旧件。

大量内嵌图片的 HTML 是给人审阅的。模型先读侧车清单与正文/ALT/来源，浏览器查看
页面并核对文件 SHA；不要把图片 base64 当成必须全部塞进上下文的正文。
