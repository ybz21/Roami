# Review a saved deck

Review against the requested audience, purpose and edit scope. For a new deck or substantial redesign, inspect these separately:

| Area | Evidence to inspect | Important defects |
|---|---|---|
| Accuracy | Source facts, calculations, chart axes, units, dates and citations | Unsupported claims, misleading plots, inconsistent numbers |
| Organization | A clear takeaway, grouping and information relationships | Unstructured prose, unrelated content, essential facts buried |
| Layout | Hierarchy, alignment, balance, spacing and actual rendered text | Placeholder-like composition, clipping, overlap, illegible labels |
| Visual expression | Appropriate comparisons, process diagrams, images or metric emphasis | Arbitrary decoration or graphics that communicate no relationship |
| Deck narrative | Page order, transitions, repetition and conclusion | Disconnected pages, contradictory messages, unexplained jumps |

Do not average a serious factual or visual defect into a pass. Record the affected page, what is visible, and a concrete revision. Distinguish basic task compliance from suitability as a high-quality reference. A correct but poorly organized deck can satisfy a narrow factual checklist while still needing redesign.

Use supplied content proportionally: a short release brief might emphasize its date and responsibility on one page, then organize its recovery target on another. Do not invent implementation steps to fill space. A data report needs traceable quantitative visuals when those serve its argument; a simple brief does not need an irrelevant chart.

Inspect all saved pages at readable size, including footnotes, chart labels and multiline text. Review the exported result rather than only the editor's structure. Report which checks were actually performed; text extraction alone cannot establish layout quality.
