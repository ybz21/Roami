# Roami Agent runtime

Python owns conversations, model loops, delegation, memory, context and delivery semantics. Go remains the single public authentication boundary and owns the unified CLI and storage catalog. The service, CLI and main chat frontend are runnable; additional executor targets and event-driven proactive generation are still being implemented. Nothing has been deployed to the running user instance.

## Development and verification

```sh
cd agent-runtime
uv sync --frozen
uv run ruff check src tests
uv run ruff format --check src tests
uv run pytest -q
```

Dependencies are pinned in `uv.lock`. Tests use temporary databases and injected model/HTTP transports; they never start a real coding Agent or use a live model account. The cross-language test builds the actual Go CLI, registers the Agent database, starts Python through that CLI, streams from a local HTTP model fixture, reads the durable answer, posts a proactive message and verifies maintenance-lock exclusion. The root quality gate runs these checks too. A separate integration test starts actual Go runners in an isolated tmux server with substitute `codex`/`claude` executables, verifying multiline input, literal shell characters, replay/conflict handling, cancellation, nonzero exits and interrupted-launch reconciliation.

## Run in an isolated instance

From the repository root:

```sh
go build -o /tmp/roami-agent ./cmd/roami
/tmp/roami-agent agent setup --runtime-dir "$PWD/agent-runtime"
scripts/dev/isolated-roami.sh /tmp/agent-demo /tmp/roami-agent agent init --runtime-dir "$PWD/agent-runtime"
cp agent-runtime/agent.example.toml /tmp/agent-demo/agent.toml
# Edit endpoint/name in agent.toml, and supply the selected key_env in the service environment.
scripts/dev/isolated-roami.sh /tmp/agent-demo /tmp/roami-agent agent serve --runtime-dir "$PWD/agent-runtime"
```

`[model].endpoint`, `name`, optional `worker`, and `key_env` select the provider, Main model, Worker model and credential environment variable. Keep credentials in a private file outside the checkout (directory mode 0700, file mode 0600), load that file into the launcher environment, and never place the key in TOML, command arguments, screenshots or version control. Configurations are instance-local; changing them requires restarting that instance's Python service. Verify both streaming and tool calls against the selected model: a model listed by `/models` may still be unavailable to the account.

In another terminal, use the same instance wrapper with `agent status`, `agent new --title NAME`, `agent send --conversation ID --text TEXT`, and `agent history --conversation ID`. Sending returns a durable intake receipt; it does not wait for model completion. `agent report --task ID --run ID --revision N --file result.json` is the local executor callback. `agent notify --conversation ID --source SOURCE --key KEY --file message.txt` is the trusted local trigger adapter. Use stable keys when retrying.

Public HTTP/SSE is `/api/agent/*` on the existing Go server, using its normal login. Python listens only on a private Unix socket (0600 under a 0700 directory); it does not implement a second login service. Go strips browser-supplied owner/cookie/auth headers and forwards the verified current single-user identity. Internal report/notify endpoints are not publicly mounted. For an installed binary, set `ROAMI_AGENT_RUNTIME` or pass `--runtime-dir` to locate the Python project.

## Implemented

- `frontend/src/components/agent/`: authenticated streaming Main chat, per-conversation drafts/history, retained desktop project/session tree and project quick task entry, coding target selection, task progress, source-backed memory editing, context summary/manual compression and six slash commands. In-app notifications stay unread until a completed message is visible and unobscured; opening the inbox alone does not consume them. Mobile keeps the existing four navigation entries. Browser tests cover message replay, stream framing/Unicode, stale conversation cancellation and visible read confirmation; physical Android acceptance remains pending.

The implementation follows the approved [code layers](../docs/design/20261017-agent框架设计/technical/index.html). `app.py` is the composition root and lifecycle entry; the former flat `runtime.py` and `main.py` modules have been removed.

| Layer | Implemented responsibility |
| --- | --- |
| `protocol/` | HTTP payloads, model events, tool contracts, errors and injected Loop ports |
| `server/` | Private HTTP/SSE routes and instance configuration; no business SQL in routes |
| `conversation/` | Idempotent intake, turn mailbox, message history, branches and interruption |
| `core/loop.py` | Main/Worker model loop over injected model/context/journal/catalog/manifest/budget/clock ports; no Web, CLI or SQLite implementation imports |
| `providers/` | Configurable streaming chat-completions adapter, fragmented tool arguments, usage and incomplete-stream errors |
| `context/` | Prompt projection, source/epoch snapshots, manual/automatic compression and paired tools |
| `memory/` | Source-validated candidates/confirmation, background extraction, timezone-aware daily aggregates, versions, tombstones and forgetting provenance |
| `retrieval/` | Validity/scope filtering before limits, literal OR CJK bigram FTS and bounded single-character fallback |
| `dispatch/` | Task intents, preparation, tree/budgets, scheduling, recovery, cancellation and verification |
| `executors/` | Native branches, unified CLI coding adapter, BrowserDriver and Linux X11 DesktopDriver |
| `tools/` | Validated short Main catalog; Worker Shell/files/HTTP/Skills/MCP and observed Browser/Computer input |
| `replies/` | Proactive messages, delivery outbox and monotonic unread confirmation |
| `storage/` | Single SQLite writer, transcript/turn repositories, content-addressed artifacts, locks and transactional migrations |
| `observability/` | Persisted prompt manifests, model/catalog fingerprints and usage trace |
| `migrations/` | Versioned initial DDL and ordered upgrades, also included in installed wheels |
| `backend/agentproxy/` | Go authenticated public proxy with immediate SSE flushing |

`internal/agentruntime` keeps CLI/private transport and unified path/catalog registration. Python owns the Agent business DDL; Go does not write its business tables. Architecture tests enforce the core/contract/HTTP dependency boundaries. Existing lifecycle, restart, coding delegation, memory, compression and SSE tests exercise the refactored services.

The runtime schema started from the dated design's candidate schema, and additionally includes `conversation_reads`. Python owns the business DDL; Go registers the database and coordinates maintenance. Stop the runtime before unified database backup/layout migration. Unified database backup includes live Agent artifact bytes in a versioned recovery package.

## Memory lifecycle

Background extraction uses the Worker model with a separate injectable test port, a durable event cursor, bounded jobs and one low-priority memory slot. It never occupies a Main slot. Model output proposes candidates; owner/scope/hash validation happens again inside the write transaction. Candidates and conflicts remain outside recall until explicitly confirmed. Conflicts do not overwrite active records. Restart requeues interrupted extraction without changing its deduplication key.

The memory panel provides daily, task, conversation, project and preference views, source inspection and candidate review. Ordinary deletion removes a memory from recall and invalidates derived summaries. Complete forgetting additionally excludes traced transcript sources, memory tool blocks and dependent replies from future context while retaining visible history. Queued tasks with forgotten origins cannot dispatch; completion prompts redact their content. Input already delivered to an external model/process cannot be recalled. Older prompt manifests are reconstructed conservatively and can exclude additional dependent context.

Set `[memory].timezone` to an IANA name such as `Asia/Shanghai`; the default is UTC. Daily summaries coalesce by owner/date/timezone and archive after the local day ends. Explicit daily queries refresh current-day counts. Aggregation deduplicates user messages and task IDs, attributes projects separately from unassigned work, handles 23/25-hour days, and recomputes late historical events using an event watermark. Day summaries are not returned as ordinary knowledge unless a day is selected. Tombstones prevent background extraction or daily rebuilding from silently restoring deleted information.

## Coding execution transport

Main can discover targets on demand with `target_search` and `target_resolve`. These short read tools call the configured unified CLI and project API, without a Python project/session catalog or credential scheme. Searches return bounded pages of names and stable IDs, preserving duplicate names. Ordinary questions do not force a lookup. `roami session ls --live --json` reads one live identity snapshot without terminal capture, memory sampling or reconciliation; `roami session resolve ID --strict --json` rejects ambiguous labels and prioritizes exact identity. A failed observation is an error, never an empty catalog.

`roami agent execution launch --file SPEC.json` launches a one-shot coding process in a new, recorded tmux session. `status --key KEY` returns the durable result; `cancel --key KEY` requests cancellation and must be followed by status to confirm it. A spec contains `key`, `executor` (`codex` or `claude`), `prompt`, `timeoutSeconds` (1–86400), and either an absolute `directory` or a `projectId`. `model`/`permission` are optional; project specs additionally accept `base`/`remote`, or `workspaceId` to reuse a registered workspace.

The Go service uses the existing Agent registry, application session service, project store and worktree service. Arguments use argv, prompts use stdin, and private execution receipts live under `<DataRoot>/agents/executions`. It never guesses a Codex conversation ID. A reused key must have exactly the same spec; an unknown launch or interrupted runner is never blindly re-executed. Output remains visible in the session while running, with bounded stdout/stderr tails persisted for retrieval. Coding processes and shared Git workspace operations detach inherited repository bindings (including Git hook context) while retaining Git authentication settings. Timeout, cancellation and shutdown signals terminate the execution process group. The default permission comes from the coding CLI; explicit bypass is only applied when requested in the spec.

`executors/roami_cli.py` connects new loose-session and existing-project tasks to this transport. Set `runtime.coding_directory` explicitly, or provide an absolute `target.directory` for a `new_session` task. Go-launched Python defaults to the same Go executable for CLI calls. Launch returns without occupying a worker for the full coding duration; a separate monitor polls results and records the session binding. External executions have a separate bounded admission count and retain the original task deadline. Python restart observes the original launch; cancellation stays pending until the Go runner returns a terminal result. Missing launch evidence and observation failures are distinct, and uncertain execution is not replayed.

### Existing Codex TUI sessions

An explicit `kind=session, sessionId=ID` target continues an enrolled Codex TUI instead of launching a new process. The Go launcher requires a single pane, a known provider conversation ID and an observed idle lifecycle state. It journals the launch before using the existing paste-buffer/Enter helper, preserves the directory without fetch/reset and holds a durable workspace fence. Repeating an identical launch queries the receipt; uncertain submission is never sent again. Python records the exact provider conversation ID and returns the result to the original conversation. Completion still requires independent task acceptance.

`roami agent execution hook-config --executor codex` prints JSON composition data for the hook groups and `notify` argv. Merge the groups into trusted Codex hooks and the notifier into `config.toml`, preserving existing handlers; this output is not a drop-in TOML file. The command never modifies global configuration, trusts hooks or changes running user sessions. After enrollment, one observed ordinary prompt/completion establishes readiness. Sessions without a recorded complete lifecycle reject continuation before sending. Installation and refresh of this wiring in session creation remain pending.

Callbacks use `agent execution event --executor codex --file -` for hooks, and `--notification JSON` for Codex's notification argument. The implementation follows the official [hook contract](https://learn.chatgpt.com/docs/hooks) and [completion notification contract](https://learn.chatgpt.com/docs/config-file/config-advanced#notifications). `Stop` is deliberately insufficient because other hooks can continue the turn. Only `agent-turn-complete` with matching thread, turn and input hash can settle a launch. In-flight tools, subagent starts without definitive stop evidence, manual takeover or identity mismatches preserve uncertainty. Cancellation denies subsequent supported local tool calls and waits for completion evidence; it never destroys the reused session or treats a cancellation request as proof of stopping. Hook coverage is not a complete enforcement boundary.

Stop confirmation also checks the original pane process identity and dedicated `tmux-spawn-*.scope` cgroup, including reparented background processes. New task processes prevent settlement even when their original shell exited. This requires Linux procfs and a readable dedicated pane cgroup; unsupported hosts fail before submission. Processes already running outside the pane are distinguished by their original ancestry. This is observation of managed work, not an OS sandbox: processes moved outside the scope, remote effects and manual external writes still need reconciliation. Claude TUI continuation remains unavailable because its `Stop` hook alone does not establish final turn completion; one-shot Claude execution continues to work.

Tests use actual Go CLI subprocesses and Python persistence with isolated session fixtures, including duplicate submissions/notifications, mismatched identities, in-flight tools, background/orphan processes, cancellation and delivery to the original conversation. They do not contact a coding provider or message user sessions.

An external task whose deadline passes without a known terminal receipt requests cancellation and becomes `interrupted`, with an explicitly unknown attempt outcome. This releases its scheduler slot; Go's independent resource fence remains in force. The original conversation receives one durable interruption report. Polling continues to reconcile late terminal evidence into that attempt's history without promoting the interrupted task to success or replaying its launch. A known result that wins the database race cannot be replaced by a stale timeout observation. Cancellation of an uncertain reused session records the request while preserving unknown state; it does not claim the TUI stopped.

A `project` target uses `projectId`, with optional `base`/`remote`. Go resolves the stable ID (including aliases) through the existing project store, then uses the shared worktree service. Git projects require a successful fetch and create a new checkout from the returned fixed remote OID; local main stays untouched. Directory projects retain their project identity and execute in their existing directory. A caller cannot override a project's directory or silently substitute the loose-session directory. Preparation is journaled under the launch key, bounded to 120 seconds and charged against the same task deadline; retries return the same workspace receipt. Preparation failure saves a failed result and never starts the coding process. Workspaces are preserved on execution failure for inspection.

Go preparation returns a stable opaque `workspaceId` and persists its project/directory/branch/base/start-OID receipt under the instance data root. Passing `projectId` plus that `workspaceId` resumes the recorded checkout, validates its project and current worktree membership, and preserves local commits and uncommitted changes. Reuse rejects `directory`, `base` and `remote` overrides, unknown IDs, cross-project IDs, missing/moved paths and branch mismatches. It performs no fetch, checkout, reset or rebase; offline continuation is supported. Older receipts without workspace IDs need a new explicit preparation before this reuse path is available.

Managed coding runners take an exclusive writer lock for the canonical Git checkout (or the exact canonical directory outside Git). Symlink aliases and nested directories of the same checkout share the lock; separate linked worktrees do not. The durable writer receipt remains after a runner exits: a later writer requires the earlier run's terminal result, so a lost Go runner cannot release a potentially still-active child merely by losing its OS lock. Busy or uncertain workspaces fail before starting the coding process. This coordination covers framework-managed coding runs; coordination of external/manual workspace changes and non-Shell remote resources remains required.

Python exposes `preparing` until an actual running receipt arrives, persists the resolved target and workspace event, and inherits parent task deadlines. Claude TUI continuation and external checkpoint Fork remain required; enrolled Codex TUI continuation is supported as described above. These targets fail explicitly; callers must not substitute an arbitrary current directory for a project target. External success still enters the verification path; this transport does not equate an exit code with meeting the user's goal.

## New project targets

A `new_project` target supplies `name` and an optional absolute `baseDir`. Native and coding executors first call the existing authenticated `roami project create` CLI, using a stable `--provision-key` derived from the run. Go's project API remains the catalog writer; Python never writes project metadata. The default parent is `<DataRoot>/projects`. The normal create command still supports adopting existing directories; Agent provisioning uses an exclusive path that rejects name/directory conflicts and placement inside another Git worktree.

Go saves intent before directory creation, verifies ownership before recovery/registration, checks catalog persistence and saves a durable resource receipt. Replaying the same request returns the same project ID, while changed parameters or a removed target fail explicitly. An ambiguous directory is preserved for reconciliation. Current Agent provisioning creates an empty directory project; configured templates/clone provisioning are still required. CLI login and the existing Go server connection must already be available; no additional Python login or fallback metadata writer is introduced.

After provisioning, execution uses the normal project workspace preparation and records the resolved project/workspace binding. Memory extraction and daily counts use the resolved project, with daily attribution bounded by the preparation event watermark. A directory project that is later initialized as its own Git repository keeps its workspace ID when continued; the registry refreshes checkout metadata without fetching or resetting it.

## Native Worker workspaces

A native project task uses the same Go workspace preparation and registry as a coding CLI task. Python requests `roami agent execution hold --file -` with a bounded JSON frame and keeps that process open for the task lifetime. Go returns the prepared workspace, holds the shared writer lock, and requires a second explicit `stopped` confirmation before saving a release result. EOF, owner death, a missing acknowledgement, or an unknown write leaves the workspace quarantined. This internal lease protocol does not report task success or satisfy task acceptance.

The native branch receives the trusted workspace in its system context and tool binding. Shell defaults to that directory; relative cwd resolves beneath it, and a task cannot substitute another configured root. Shell removes inherited Git repository bindings while preserving Git authentication settings. This is cwd validation, not an OS filesystem sandbox. Unbound analytical Workers can answer without a workspace; local Shell calls require preparation. Loose native tasks can use an explicit directory or `runtime.coding_directory` as their default.

Preparation consumes the task's original deadline. `preparing` becomes `running` only after the Go receipt and database binding are recorded. Cancellation or source forgetting during preparation prevents Worker admission. Local Shell cleanup stops its process group before cancellation is confirmed; cancelled remote/MCP writes with unknown outcomes cannot release the workspace and leave the task interrupted with an unknown attempt. Preparation failures also close the prepared native turn. Restart preserves uncertain ownership rather than automatically repeating work.

Cross-language tests use the real Go CLI, Python runtime and local Shell processes in an isolated registered project. They verify default cwd, task state ordering, independent acceptance, cancellation/child stop, workspace reuse, and quarantine after an uncertain cancellation. The provider is an injected fixture; these tests do not contact a real model or a user's coding sessions.

## Scheduled reminders and notification policy

Explicit one-shot reminders accept an absolute UTC `whenMs` or a relative `afterSeconds`; daily reminders use `dailyAt` (`HH:MM`) plus an IANA timezone. Main has three short reminder tools, bound to its current conversation and live turn. Ordinary questions still call the model directly. Creating a reminder returns the saved next due time immediately; firing a fixed reminder uses no model call and runs outside Main/Worker model capacity.

`roami agent reminder add --conversation ID --key KEY --text TEXT --after-seconds 60`, `reminder ls`, and `reminder cancel --id ID` use the same Python application service as authenticated `/api/agent/reminders`. Reusing a request key preserves its original due time; changed parameters conflict. Each firing, assistant message, event, completed trace job and next due time commit together. Restart catches up one latest daily occurrence and records the count of skipped dates, avoiding a flood of old reminders. Spring clock gaps move to the first valid minute; a repeated hour fires once per local date. Cancellation preserves existing messages and firing history.

`roami agent notification-preferences get` returns the complete settings object; `set --file SETTINGS.json` replaces it. Authenticated Web clients use GET/PUT `/api/agent/notification-preferences`. Preferences separate task results, decisions, reminders and suggestions, with timezone/quiet hours, explicit attention bypass, hidden previews and suggestion rate limits. Suggestions default off. The policy admission service keeps its rate reservations durable and counts one event once across retries. These settings do not remove chat messages or consume unread state. App/Web Push adapters apply this policy before claiming a send; saving preferences is not evidence of system notification delivery.

Schema 4 adds reminders, firing history and notification policy under the Python-owned migration mechanism. Go backup/restore accepts versions 1 through 5 and rejects newer schemas; Go does not run these DDL migrations.

## App and Web Push delivery

Python owns the outbox, preferences, unread counts and claim/receipt state; Go forwards notifications to the existing App WebSocket and Web Push adapters. The Go loop uses the existing private Unix transport with the local owner and no new login. Its claim and receipt routes are private and are not mounted in the public proxy. The public `/api/agent/notification-deliveries` endpoint returns the latest 50 owner-scoped transport records.

Main conversation creation installs an App channel binding, and proactive/terminal-task messages commit their event and outbox row together. Native Worker branches do not get App bindings. Ordinary direct chat answers stay in the conversation; background task results, pending decisions, explicit reminders and trusted proactive triggers can notify. Task completion events retain task revision/state so changed or continued tasks cannot send old results. Read/deleted/forgotten or superseded messages are skipped before admission. Schema 5 adds a migration watermark so installing this adapter does not push the existing unread archive.

Quiet hours, category settings, preview hiding and suggestion rate limits are checked while claiming. Changing preferences wakes held pending records; it does not recall a send already in progress. A claim has a unique token and 30-second receipt deadline. Go bounds fan-out to four workers and a ten-second overall send context. Confirmed failures retry the same message with backoff, up to six attempts. An expired sender, lost receipt, network ambiguity or partial fan-out stays unknown and is never blindly resent. A late matching terminal receipt can settle that same claim; an older claim cannot overwrite a newer attempt.

`adapter_accepted` means queued to an App connection or accepted by a push gateway. It never means the device displayed or the user read the message; every public receipt retains `deviceDelivered: false`. Offline devices, revoked notification permissions and platform delivery remain outside that acknowledgement. Integration tests use actual Python persistence, Go transport and a connected isolated App WebSocket. Web Push encryption/gateway acceptance and failure cases use the existing SDK with a local injected HTTP client; no real user's devices are contacted.

The notification panel includes reminders, preferences and delivery records. Main reminder tools use the owner's saved notification timezone when no timezone is supplied. New App and Service Worker notifications retain the original conversation/branch/message and open a validated route. The chat positions the target after lazy Markdown layout settles, stops pinning when the user interacts, and preserves the existing visible-message read protocol. Web and Android notification content supports Chinese and English. Android unit tests and desktop/compact browser checks pass; physical-device notification, permission, keyboard and touch acceptance remains pending.

## Provider reference

The streaming adapter follows the official [chat-completions event reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events). It implements this explicit wire contract rather than assuming all provider APIs or models have identical tool/caching capabilities.

`model.max_retries` defaults to two retries and accepts 0–3. Only transient HTTP/transport failures before any normalized event is emitted can retry; partial visible text is never replayed. Backoff respects `Retry-After` and the original request deadline; cancellation interrupts the wait. Permanent/authentication errors, malformed events and redirects do not retry. The endpoint parser rejects embedded credentials, query/fragment values and non-loopback plain HTTP. Redirects are disabled even with an injected HTTP client. Provider diagnostics remain outside model context. See the official [error/recovery reference](https://developers.openai.com/api/docs/guides/error-codes).

`model.capabilities` declares a version and supported tools, streamed usage and cache parameters. Defaults preserve the existing text/function-call wire contract. Cache request parameters are opt-in: the deployment must verify the selected endpoint and both configured models, then declare support before enabling `model.cache`. A stable hashed key varies with route, model settings, namespace, first system message and tools; appending conversation messages preserves it. `mode=explicit` marks only the leading system/developer prefix through content-block breakpoints and leaves the stored context unchanged. It requires a system prefix. `mode=implicit` sends the configured cache options without adding breakpoints. The provider owns actual matching, retention and KV state; local fingerprints do not prove a hit or copy a Fork's KV cache. These optional fields follow the official [request contract](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create).

Prompt manifests now partition fingerprints by endpoint ID, model, serializer and capability/cache settings. They record hashes instead of endpoint credentials or full prompts. Usage retains provider counts and normalizes known input/output/cache-read fields; absent fields remain null, including unsupported cache-write counts. A successful retried attempt does not establish total cost across earlier attempts, so `retryUsageKnown` stays false. Separate endpoints/model versions do not reuse the same application fingerprint. Provider/model routing across different endpoints and performance/cost benchmarks remain pending.

## MCP connections

Configure named servers under `[tools.mcp.<name>]` as shown in `agent.example.toml`. A Worker calls `mcp_discover` for the relevant server; Main never waits for MCP startup or carries the full remote catalog. Each connection owns its SDK session in one actor and serializes its calls. Tools use namespaced, schema/version-bound aliases; catalogs are sorted for a stable model prefix. Directory changes remove old tools, and discovery/call refreshes refuse stale aliases before execution. Failed connections back off and reconnect on demand without replaying calls.

Stdio children receive the SDK's minimal default environment plus explicitly mapped `env_env` variables. HTTP credentials come from `key_env` or `header_env`; endpoint URLs cannot carry credentials. Raw server errors/stderr and progress messages do not enter ordinary logs or model context. Numeric progress events are bounded and persisted against the active turn lease. Calls have bounded queues, deadlines and output; cancellation sends a best-effort MCP cancellation notification and closes the connection. A remote cancellation is not proof that a write stopped: ambiguous outcomes are persisted as unknown, end the current turn and never automatically replay. Only explicitly configured `read_only` tools count as reads; server hints alone do not remove verification.

The adapter uses the official [Python SDK](https://github.com/modelcontextprotocol/python-sdk/tree/v1.30.0) for the [MCP transports and lifecycle](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports). Automated checks use real stdio processes and an authenticated local Streamable HTTP server, plus native Worker discovery/calls, catalog fingerprints, schema changes, timeouts, cancellation and unknown outcomes. They do not contact configured production MCP services.

## Artifact storage

The runtime upgrades schemas v1–v3 transactionally, preserving existing rows. Unsupported future versions fail without rebuilding the database; Go backup validation accepts all three supported schema versions. Artifact bytes live under `<DataRoot>/agent-artifacts/blobs`, addressed by SHA-256, while SQLite stores separate opaque, owner-scoped references. Task/message attachment validates ownership and branch provenance. Writes are atomic and durable before publishing a reference; reads verify size and digest. A cancelled caller cannot release the runtime maintenance lock while filesystem work is still pending.

The authenticated Go proxy exposes `GET /api/agent/artifacts`, `GET /api/agent/artifacts/{id}`, `GET /api/agent/artifacts/{id}/content` and `DELETE /api/agent/artifacts/{id}`. Downloads use attachment disposition, disable caching and sniffing, and never expose storage paths. `[artifacts].max_bytes` defaults to 64 MiB. Deletion tombstones the reference without resurrecting it on a later upload; physical garbage collection remains pending. Unified `roami db backup` emits a v2 package when the Python artifact index exists, deduplicates live blob files, and checks paths, sizes and SHA-256 against the snapshot. Restore into an empty instance stages database and artifact files on their respective filesystems, uses the existing maintenance journal, and keeps writers blocked until both are published and verified. `roami db migrate --recover` reconciles interruptions before or after file publication. Incomplete packages, unsupported schemas and existing artifact destinations are rejected; deleted references remain tombstoned. Older database-only Agent packages with an artifact index are explicitly incomplete. Full artifact handling during a separate data-root/layout migration remains pending. MCP images/audio/embedded resources and oversized text/structured results produce artifact references with source metadata; resource links are stored without fetching their URLs. Worker Shell preserves large UTF-8 logs and exact binary bytes as separate stdout/stderr artifacts, with a bounded preview and the actual exit code. `artifact_read` retrieves bounded text excerpts for Workers and returns metadata for binary evidence. Small ordinary tool results retain their existing format. Filesystem publication failures after execution remain unknown outcomes rather than replayable failures. These endpoints do not accept arbitrary file paths or public uploads. Shell capture has a hard ceiling of 2 MiB per stream (or the smaller configured artifact maximum); exceeding it stops the process group.

## Resource control foundation

`dispatch/resource_leases.py` owns durable browser/desktop control fences, scene observations and action receipts. Only the current active task attempt can claim control. Expiry does not grant another task control. Actions require the latest observation and matching scene/lease epoch; a durable action key returns its existing receipt instead of dispatching twice. Completion invalidates the old observation. Pause blocks new actions immediately and waits for the active action to settle before release; resume requires confirmed release. Runtime recovery quarantines held controls and records unfinished actions as unknown. Browser/Computer drivers use this service for execution, startup recovery and receipt reconciliation. Authenticated API/CLI takeover controls are available; product UI is still pending. The controller must supply actual terminal driver receipts before resolving an unknown action; cancellation of a CLI wrapper is insufficient.

## Native Browser Use

Enable `[tools.browser] enabled = true` to register `browser_open`, `browser_observe` and `browser_act` for Workers. Main keeps its short dispatch catalog. The driver uses `roami chrome` and the configured shared browser connection; it creates background tabs by default, never steals focus, and only adopts an existing target when `existing_tabs = true` is explicitly configured. `endpoint` optionally selects a CDP endpoint and `max_tabs` bounds each task's tabs. Provider credentials are removed from driver subprocess environments.

Every action references the latest task/run/lease-bound observation and checks the browser instance and scene fingerprint before sending input. Observations contain bounded main-frame text and controls, plus a private PNG artifact with viewport/pixel transforms. Password values are excluded from the returned control text. Screenshot/scene failures reject mixed evidence; a timed-out background screenshot falls back to a fresh DOM-only observation with an explicit screenshot error and no image claim; a completed action with unavailable observation retains its successful receipt and requires fresh observation instead of replay. A tab created before observation failure returns its resource ID for recovery.

The CLI persists admission, cancellation markers and execution claims before acting. Duplicate operation IDs cannot repeat input, including after daemon death. Cancellation and timeouts require actual driver stop evidence; unknown input quarantines control. Startup recovery and the browser receipt monitor reconcile late stop evidence and release terminal task leases without promoting an interrupted task or replaying its input. Takeover fences are checked again inside the lease/action transaction. API/CLI takeover controls are available; product UI is still pending. Computer Use uses the separate X11 adapter below.

Native results include at most four artifact references in the completion delivered to Main. Long result text is retained in the child transcript and a text artifact, with a bounded summary and source reference in the task receipt. Automated tests exercise independent task verification, cancellation before and during input, late receipts, invalid scene/screenshot evidence, and answering a separate Main turn while the browser Worker is blocked.

## Cancellation and late results

Execution reports preserve the original result on the attempt and enter verification before any terminal task state. A cancellation request remains authoritative when a result arrives or a verifier returns: it cannot become success or failure merely because completion raced with cancellation. The parent waits for every child to reach a terminal state. Unknown child or own stop evidence leaves the task interrupted instead of claiming confirmed cancellation. Cancelling a task that is waiting for user acceptance requeues its existing verification job. The original conversation receives one terminal cancellation completion; late results remain evidence and do not revive an interrupted task.

## Worker workspace files

Workers have `file_read`, `file_write` and `file_patch` in prepared task workspaces; Main does not. Unbound calls require an explicitly configured absolute root. Reads hash at most 4 MiB and return at most 16,000 bytes per page; non-UTF-8 byte pages are labelled base64. Writes require `expectedSha256` (or null for exclusive creation); patches require a hash and exactly one literal match. Publication checks the file again after the temporary file is durable, preserves existing permission bits, and atomically replaces the directory entry. Changed files and ambiguous patches fail without replacing the target. The workspace writer fence coordinates participating agents; content checks do not provide a filesystem-wide transaction against arbitrary concurrent programs.

Directory traversal uses directory descriptors and rejects symlink components and non-regular files. File I/O has its own bounded admission/thread pool. Cancellation waits up to two seconds for actual I/O completion; an unconfirmed operation stays unknown and cannot release a prepared writer workspace. Runtime shutdown drains outstanding file I/O before storage maintenance locks are released. Failure after publication but before directory durability is reported as unknown and never automatically replayed.

A Native Worker cannot override an unknown write by returning an optimistic summary. The executor checks the persisted tool ledger before returning success; any planned, running or unknown write interrupts the task before goal verification. The completed model text stays in the child transcript as evidence and does not count as acceptance.

## Artifact-backed memory

Memory sources can reference an owned artifact and its immutable content SHA, in addition to messages and events. Confirmation rechecks the source's owner, conversation/task binding and availability in the same transaction. Background extraction includes at most five relevant artifact sources and bounded text from small text/JSON artifacts. Every proposal retains the artifact dependencies supplied to that model call, including when the model cites only a conversation message.

Deleting an artifact reference removes directly dependent memories and their derived summaries from active recall, invalidates embeddings and context snapshots, and advances the owner's memory epoch. Recall filters unavailable artifact sources before applying candidate limits, including records written before this invalidation path existed. Shared bytes belonging to another owner's live reference remain available. A deleted source cannot be confirmed after an extraction finishes late.

Complete forgetting also excludes the artifact's associated source message from future context and blocks model-side `artifact_read` for its forgotten fingerprint. The user can still download retained evidence through the authenticated artifact API. Tool result publication revalidates artifact and memory sources in the database transaction, so a read that races with deletion/forgetting cannot commit stale content to a new conversation.

## Current image observations

Declare `images = true` under `[model.capabilities]` only for a verified provider/model combination. Without it, the provider rejects image requests before network access and the runtime keeps text/DOM-only behavior. Workers can receive one current PNG observation from their own active run; Main retains its text path. The runtime validates the resource owner, run, lease/scene epoch, latest observation, artifact integrity and image dimensions. Each image is bounded to 2 MiB and four million pixels; it is a separate image budget, not a base64 string counted as text input tokens.

Only the selected screenshot is attached to the outbound multimodal request. Transcript and prompt manifests store its artifact/observation IDs, hash and dimensions, never a data URL. Removing or forgetting a manifested image blocks further admission of that in-flight turn. Oversized/unavailable images produce an explicit limitation instead of guessed coordinates. The browser task test exercises image-aware Worker continuations while Main and persisted history retain references only. Desktop input uses the separate X11 adapter below.

## Computer Use: Linux X11 adapter

Enable `[tools.computer] enabled = true` with an image-capable Worker route to register `computer_open`, `computer_observe` and `computer_act`. `display` optionally selects an existing local X11 display and `image_side` bounds model images (256–1600 pixels). The runtime never creates a substitute desktop. No display, Wayland/XWayland and unsupported pixel formats fail explicitly. The first adapter supports clicks, bounded wheel input, named key combinations and printable ASCII text in keyboard group 0; it rejects unsupported text before sending partial input. Other desktop backends remain extension work.

Desktop identity binds the actual Unix peer process/start time and display root. A task owns a durable desktop lease; every input checks the latest model-visible observation, scene fingerprint, focus/geometry, pointer and keyboard state. Active user keys/buttons reject competing input. Observations may crop the focused top-level window without moving focus. Resizing/cropping records the exact scale and origin; actions use image coordinates and the adapter translates them to the desktop. Input success is separate from goal verification.

The adapter records an exclusive operation claim before input and a durable terminal receipt afterward. Cancellation waits for actual bounded input to finish; unknown input holds a quarantine. Late receipts release confirmed control without promoting the interrupted goal or replaying input. Shared cancellation bookkeeping prevents a second cancellation from fabricating stop proof. A cancelled tool that was durably admitted before dispatch releases its unused fence as stopped with unknown outcome, rather than inventing a successful action.

Tests run on independently created Xvfb instances, observe real XTEST key/button events and inspect the receiving form. They cover scaled/cropped coordinates, case-sensitive typing, modifier combinations, changed scenes, Main capacity, cancellation, late reconciliation and unavailable displays. A separately run live `rr/gpt-6.1-sol` test filled and saved the isolated form using image observations; no user desktop was accessed. API sources: [python-xlib](https://github.com/python-xlib/python-xlib), [Pillow raw decoder](https://pillow.readthedocs.io/en/stable/handbook/writing-your-own-image-plugin.html).

## Human resource takeover

Authenticated endpoints expose `GET /api/agent/tasks/{id}/resources`, `GET /api/agent/resources/{id}` and `POST /api/agent/resources/{id}/pause|resume`. Task inspection includes descendants and claims that have not captured an observation yet. It omits typed input and raw driver output from action summaries. Other owners cannot inspect or change a control.

Pause immediately fences new input. An in-flight action returns `pausing` and `takeoverReady = false`; only confirmed input stop plus lease release returns `takeoverReady = true`. A small recovery sweep releases ready pauses and preserves the paused task reservation. Resume invalidates the old lease/observation, so input must acquire control and observe again. Interactive children of the same goal cannot bypass a paused/quarantined sibling or parent by opening a replacement resource. Independent goals retain their separate scope.

Local operators use `roami agent control ls --task ID` and `control show|pause|resume --resource ID`. Poll `show` while pausing; a request being accepted is not takeover confirmation. Browser/desktop receipt recovery also runs when those tools are disabled, and browser recovery reads private durable receipts without starting Chrome, Node or installing dependencies. CLI terminal output and model tool descriptions use the terminal/Agent-content exceptions in the repository i18n standard. Product takeover UI and task continuation remain separate implementation work.

Independent verifier callbacks are read-only and must cooperate with cancellation. They have a 15-second execution limit. A failed or timed-out verifier leaves executor evidence unchanged and requests user acceptance with a stable error code; provider diagnostics are not persisted. Cancellation interrupts verification, while runtime shutdown keeps its queued job available for recovery.

Main and Worker may use independent provider routes. The optional `[worker.model]` table configures `endpoint`, `name`, `key_env`, `timeout_seconds` and `max_retries`; its nested `capabilities` and `cache` tables are independent and default empty. Without that table, the legacy `[model].worker` name continues to inherit Main's endpoint and verified capabilities. Memory extraction uses the Worker provider by default. Computer Use requires image support on the effective Worker route; Main can remain text-only. Framework model credentials are excluded from Shell and unified CLI child environments.

Complete forgetting follows native child messages back to their owning task, delegated task briefs and completion replies. Model-facing task status redacts affected content while user history stays intact. Delegation rechecks context provenance in its creation transaction and namespaces provider tool IDs by turn; completion manifests retain the task origin as an admission dependency. Legacy delegation launch keys are included in forgetting propagation.

Task steering uses `POST /v1/tasks/{id}/steer` with `requestKey`, the current `revision`, and additional `text`. Its durable receipt is queried at `GET /v1/tasks/{id}/steering/{operationId}`. Active task trees stop first; a new revision and attempt are admitted only after stop/resource checks. Queued steering survives restart and explicit cancellation revokes it. Unknown effects block continuation for reconciliation. Native continuation keeps its transcript branch; prepared project/workspace identity is reused, and new-project provisioning keeps its original idempotency key. Old attempts remain historical, old child generations do not fail a new root revision, and superseded Main replies cannot publish final notifications. The unified CLI exposes `roami agent steer --task ID --revision N --key KEY --text TEXT` and `roami agent steering --task ID --operation ID`. Terminal output and model brief text follow the existing i18n exceptions.

Task inspection is available at `GET /v1/tasks/{id}` with bounded attempt history, child links and the latest steering receipt. Control views expose only the observed title/URL/reference and exact browser/target IDs, leaving DOM and typed input out of the response. Internal browser-creation contexts are omitted. The Web inspector supports acceptance, continuation, artifact previews/downloads and confirmed handoff. Task browser links keep instance/target IDs in the route path so terminal query synchronization cannot drop them. Both WebSocket and DataChannel mirrors enforce the supplied instance and target; scoped mirroring never launches a replacement browser or falls back to a different tab. Artifact responses keep attachment/no-store/nosniff and script restrictions, while `sandbox allow-downloads` permits the intended download ([CSP sandbox](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/sandbox)).

Continuation retains the last independently accepted revision. Unaccepted writes and outstanding user acceptance carry into later revisions; a read-only follow-up cannot silently verify earlier effects. An independently verified or user-accepted goal permits subsequent read-only follow-ups. Main receives explicit instructions to distinguish the authoritative task state from the executor result claim.
