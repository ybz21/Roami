# Roami Agent runtime

Python owns conversations, model loops, delegation, memory, context and delivery semantics. Go remains the single public authentication boundary and owns the unified CLI and storage catalog. The service, CLI, Main chat, Native/coding execution, event-driven suggestions and scheduled briefs are runnable. Executor-specific recovery limits and remaining acceptance work are listed below. Deployment and acceptance records are maintained alongside the implementation.

## Development and verification

```sh
cd agent-runtime
uv sync --frozen
uv run ruff check src tests
uv run ruff format --check src tests
uv run pytest -q
```

Dependencies are pinned in `uv.lock`. Tests use temporary databases and injected model/HTTP transports; they never start a real coding Agent or use a live model account. The cross-language test builds the actual Go CLI, registers the Agent database, starts Python through that CLI, streams from a local HTTP model fixture, reads the durable answer, posts a proactive message and verifies maintenance-lock exclusion. The root quality gate runs these checks too. A separate integration test starts actual Go runners in an isolated tmux server with substitute `codex`/`claude` executables, verifying multiline input, literal shell characters, replay/conflict handling, cancellation, nonzero exits and interrupted-launch reconciliation.

## Execution limits

Main/Worker loops, tool-call batches, default model/tool/MCP durations, task fanout and nesting have no framework execution ceiling. `[runtime].timeout_seconds` and `max_depth`, MCP `timeout_seconds`, background generation `timeout_seconds`, and `[artifacts].max_bytes` use `0` for unlimited; explicitly configured positive values remain effective. Legacy task-wide step/turn settings remain accepted without imposing new execution limits. `workers` and `main_concurrency` control scheduling slots: additional work queues rather than failing admission.

Large Shell/HTTP bodies and tool JSON results retain complete artifacts and return previews. Artifact publication streams private regular files, verifies hashes and source stability, and preserves owner/task/message scope. File tools support files larger than 4 MiB while keeping reads paginated and edits conditional on their observed SHA. No default tool deadline or output ceiling can terminate an otherwise valid write.

Connection establishment and recovery/health probes stay bounded. Ownership checks, stale-scene/unknown-write fences, cancellation proof, protocol validity, provider retry rules, context capacity and notification preferences remain enforced. Page/preview bounds protect model context without discarding stored results. Upload/image input limits are separate transport/provider constraints, not execution deadlines. Existing deployments must change explicitly saved `runtime.timeout_seconds=120` and `runtime.max_depth=2` to `0` to use unlimited execution; changing code defaults does not overwrite user configuration.

Compound requests finish a fast handoff only when `requestComplete=true` confirms all parts were handled or delegated. Recent tracked task identities are scoped to the owner, conversation and branch, and recorded as context sources; unresolved outcomes reject continuation immediately. Native delivery retains reported workspace files and observed new file outputs, supplying verified download links even when the model omits Markdown links.

Rerun the real-model dialogue matrix with `uv run --frozen python ../scripts/dev/agent-acceptance/routing_exam.py --live --rounds 3 --output /tmp/fresh-routing-exam` from `agent-runtime`. It uses production scheduling with Worker slots paused in the fixture, and records each question, decision, answer and upstream failure. This checks admission, not completion of professional work.

## Execution traces

`roami agent trace --turn TURN_ID` (or `--task TASK_ID`) joins Main, Native/CLI execution and result reporting. `--format chrome` writes a trace-event JSON file usable by local Perfetto/Chrome viewers. The authenticated HTTP equivalent is `GET /api/agent/traces?turnId=ID`.

Traces contain timing/status/usage metadata, not message bodies or tool arguments. New calls distinguish response headers, first provider delta, first text and retries. Legacy timing is explicitly inferred; unknown outcomes and usage stay unknown. Current coverage begins at Python admission and ends at committed Main reply, excluding client paint and opaque external-Agent internals. See [research and verification](../docs/design/20261017-agent框架设计/reviews/20261019-execution-tracing/README.md).

## Run in an isolated instance

From the repository root:

```sh
go build -o /tmp/roami-agent ./cmd/roami
/tmp/roami-agent agent setup --runtime-dir "$PWD/agent-runtime"
scripts/dev/isolated-roami.sh /tmp/agent-demo /tmp/roami-agent agent init --runtime-dir "$PWD/agent-runtime"
cp agent-runtime/agent.example.toml /tmp/agent-demo/agent.toml
# Edit endpoint/name in agent.toml, and supply the selected key_env in the service environment.
scripts/dev/isolated-roami.sh /tmp/agent-demo /tmp/roami-agent agent serve --runtime-dir "$PWD/agent-runtime"
```

`[model].endpoint`, `name`, optional `worker`, and `key_env` select the provider, Main model, Worker model and credential environment variable. Keep credentials in a private file outside the checkout (directory mode 0700, file mode 0600), load that file into the launcher environment, and never place the key in TOML, command arguments, screenshots or version control. Configurations are instance-local. The system Settings → Agent → Agent settings page can save Main/Worker Base URL, model, API Key and image capability without restarting, while the chat plus menu switches the Main model. Changes require the runtime to be idle; a busy response preserves the current run and unsaved form. UI overrides are stored in `<DataRoot>/agents/model-settings.json` (0600, parent 0700), loaded on restart, and take precedence over TOML. Settings reads return only `keyConfigured`, never the key; an empty key retains the saved credential. Changing the endpoint requires supplying its new credential when the previous endpoint had one. Edits to the underlying TOML still require a restart. Verify both streaming and tool calls against the selected model: a model listed by `/models` may still be unavailable to the account.

In another terminal, use the same instance wrapper with `agent status`, `agent new --title NAME`, `agent send --conversation ID --text TEXT`, and `agent history --conversation ID`. Sending returns a durable intake receipt; it does not wait for model completion. `agent report --task ID --run ID --revision N --file result.json` is the local executor callback. `agent notify --conversation ID --source SOURCE --key KEY --file message.txt` is the trusted local trigger adapter. Use stable keys when retrying.

Public HTTP/SSE is `/api/agent/*` on the existing Go server, using its normal login. Python listens only on a private Unix socket (0600 under a 0700 directory); it does not implement a second login service. Go strips browser-supplied owner/cookie/auth headers and forwards the verified current single-user identity. Internal report/notify endpoints are not publicly mounted. For an installed binary, set `ROAMI_AGENT_RUNTIME` or pass `--runtime-dir` to locate the Python project.

## Chat attachments and provider settings

Authenticated Go routes expose `/api/agent/model-settings` (GET/PUT), `/api/agent/models` (GET, or POST to test unsaved settings), and `/api/agent/attachments` (POST raw bytes with `filename` and stable `requestKey`). The Python socket remains private. Attachment removal uses DELETE `/attachments/{id}` for unbound drafts; sent files remain ordinary source-backed artifacts. Messages accept optional `attachmentIds`, including file-only messages.

Uploads are limited to six files per message and 10 MiB each. Text/code and PDF provide bounded excerpts, not whole-document retrieval. PDF extraction runs with no provider credentials in a resource-limited child process. Recent PNG/JPEG/WebP images enter transient multimodal requests only when Main explicitly has `images=true`; raw bytes/base64 do not enter transcripts. Other formats are stored for download with an explicit unsupported state. Removing/forgetting an artifact excludes its content from future context. Draft reference metadata is mirrored locally, never provider keys or file bytes. Direct task-mode attachments are not supported; reading attachments happens in the Main conversation.

In-app notifications stay unread until a completed message is visible and unobscured; opening the inbox alone does not consume them. Mobile keeps the existing four navigation entries. Browser tests cover message replay, stream framing/Unicode, stale conversation cancellation and visible read confirmation; physical Android checks are recorded below.

The implementation follows the approved [code layers](../docs/design/20261017-agent框架设计/technical/index.html). `app.py` is the composition root and lifecycle entry; the former flat `runtime.py` and `main.py` modules have been removed.

## Memory lifecycle

Background extraction uses the Worker model with a separate injectable test port, a durable event cursor, bounded jobs and one low-priority memory slot. It never occupies a Main slot. Model output proposes candidates; owner/scope/hash validation happens again inside the write transaction. Candidates and conflicts remain outside recall until explicitly confirmed. Conflicts do not overwrite active records. Restart requeues interrupted extraction without changing its deduplication key.

The memory panel provides daily, task, conversation, project and preference views, source inspection and candidate review. Ordinary deletion removes a memory from recall and invalidates derived summaries. Complete forgetting additionally excludes traced transcript sources, memory tool blocks and dependent replies from future context while retaining visible history. Queued tasks with forgotten origins cannot dispatch; completion prompts redact their content. Input already delivered to an external model/process cannot be recalled. Older prompt manifests are reconstructed conservatively and can exclude additional dependent context.

Set `[memory].timezone` to an IANA name such as `Asia/Shanghai`; the default is UTC. Daily summaries coalesce by owner/date/timezone and archive after the local day ends. Explicit daily queries refresh current-day counts. Aggregation deduplicates user messages and task IDs, attributes projects separately from unassigned work, handles 23/25-hour days, and recomputes late historical events using an event watermark. Day summaries are not returned as ordinary knowledge unless a day is selected. Tombstones prevent background extraction or daily rebuilding from silently restoring deleted information.

## Coding execution transport

Main can discover targets on demand with `target_search` and `target_resolve`. These short read tools call the configured unified CLI and project API, without a Python project/session catalog or credential scheme. Searches return bounded pages of names and stable IDs, preserving duplicate names. Ordinary questions do not force a lookup. `roami session ls --live --json` reads one live identity snapshot without terminal capture, memory sampling or reconciliation; `roami session resolve ID --strict --json` rejects ambiguous labels and prioritizes exact identity. A failed observation is an error, never an empty catalog.

`roami agent execution launch --file SPEC.json` launches a one-shot coding process in a new, recorded tmux session. `status --key KEY` returns the durable result; `cancel --key KEY` requests cancellation and must be followed by status to confirm it. A spec contains `key`, `executor` (`codex` or `claude`), `prompt`, `timeoutSeconds` (0 means no deadline; a positive value is an explicit timeout), and either an absolute `directory` or a `projectId`. `model`/`permission` are optional; project specs additionally accept `base`/`remote`, or `workspaceId` to reuse a registered workspace.

The Go service uses the existing Agent registry, application session service, project store and worktree service. Arguments use argv, prompts use stdin, and private execution receipts live under `<DataRoot>/agents/executions`. It never guesses a Codex conversation ID. A reused key must have exactly the same spec; an unknown launch or interrupted runner is never blindly re-executed. Output remains visible in the session while running, with bounded stdout/stderr tails persisted for retrieval. Coding processes and shared Git workspace operations detach inherited repository bindings (including Git hook context) while retaining Git authentication settings. Timeout, cancellation and shutdown signals terminate the execution process group. The default permission comes from the coding CLI; explicit bypass is only applied when requested in the spec.

`executors/roami_cli.py` connects new loose-session and existing-project tasks to this transport. Set `runtime.coding_directory` explicitly, or provide an absolute `target.directory` for a `new_session` task. Go-launched Python defaults to the same Go executable for CLI calls. Launch returns without occupying a worker for the full coding duration; a separate monitor polls results and records the session binding. External executions have a separate bounded admission count and retain the original task deadline. Python restart observes the original launch; cancellation stays pending until the Go runner returns a terminal result. Missing launch evidence and observation failures are distinct, and uncertain execution is not replayed.

### Existing Codex TUI sessions

An explicit `kind=session, sessionId=ID` target continues an enrolled Codex TUI instead of launching a new process. The Go launcher requires a single pane, a known provider conversation ID and an observed idle lifecycle state. It journals the launch before using the existing paste-buffer/Enter helper, preserves the directory without fetch/reset and holds a durable workspace fence. Repeating an identical launch queries the receipt; uncertain submission is never sent again. Python records the exact provider conversation ID and returns the result to the original conversation. Completion still requires independent task acceptance.

New interactive Codex launches through session spawn, swarm and plugin spawn prepare invocation-scoped hook/notification arguments. Explicit session revival prepares the same arguments but leaves the resume command unsubmitted. Preparation uses the installed CLI’s read-only configuration RPC, honors disabled/managed-only hooks, and uses `--no-daemon` to keep pane callback identity local. Older/incompatible binaries keep their ordinary launch without claiming continuation readiness. No running TUI is restarted or changed.

Callbacks carry the exact instance home/data/database/backup paths and tmux executable. Existing notifier argv is preserved in a private immutable file and invoked before Roami observes completion, including when Roami’s own database is unavailable; a failing original notifier does not suppress lifecycle observation. Shell launches paste through stdin and submit exactly once. Restore only pastes. Initial prompts use private files instead of command-line payloads. Codex provider IDs are recorded from observed callbacks, never guessed from the newest rollout.

Codex still requires its own `/hooks` trust review for new callback definitions; Roami never bypasses that check or auto-confirms Codex dialogs. After trust, one observed ordinary prompt/completion establishes readiness. Sessions without that evidence reject continuation before sending. For already running sessions, `roami agent execution hook-config --executor codex` prints JSON composition data for manual composition, not a drop-in TOML file. It never changes global configuration or hook trust. Read-only probes of the installed Codex configuration and isolated fake-CLI launch/notify tests pass; a real provider-backed TUI round trip remains unverified.

Callbacks use `agent execution event --executor codex --file -` for hooks, and `--notification JSON` for Codex's notification argument. The implementation follows the official [hook contract](https://learn.chatgpt.com/docs/hooks) and [completion notification contract](https://learn.chatgpt.com/docs/config-file/config-advanced#notifications). `Stop` is deliberately insufficient because other hooks can continue the turn. Only `agent-turn-complete` with matching thread, turn and input hash can settle a launch. In-flight tools, subagent starts without definitive stop evidence, manual takeover or identity mismatches preserve uncertainty. Cancellation denies subsequent supported local tool calls and waits for completion evidence; it never destroys the reused session or treats a cancellation request as proof of stopping. Hook coverage is not a complete enforcement boundary.

Stop confirmation also checks the original pane process identity and dedicated `tmux-spawn-*.scope` cgroup, including reparented background processes. New task processes prevent settlement even when their original shell exited. This requires Linux procfs and a readable dedicated pane cgroup; unsupported hosts fail before submission. Processes already running outside the pane are distinguished by their original ancestry. This is observation of managed work, not an OS sandbox: processes moved outside the scope, remote effects and manual external writes still need reconciliation. Claude TUI continuation uses the additional evidence described below; `Stop` alone remains insufficient.

Tests use actual Go CLI subprocesses and Python persistence with isolated session fixtures, including duplicate submissions/notifications, mismatched identities, in-flight tools, background/orphan processes, cancellation and delivery to the original conversation. They do not contact a coding provider or message user sessions.

An external task whose deadline passes without a known terminal receipt requests cancellation and becomes `interrupted`, with an explicitly unknown attempt outcome. This releases its scheduler slot; Go's independent resource fence remains in force. The original conversation receives one durable interruption report. Polling continues to reconcile late terminal evidence into that attempt's history without promoting the interrupted task to success or replaying its launch. A known result that wins the database race cannot be replaced by a stale timeout observation. Cancellation of an uncertain reused session records the request while preserving unknown state; it does not claim the TUI stopped.

A `project` target uses `projectId`, with optional `base`/`remote`. Go resolves the stable ID (including aliases) through the existing project store, then uses the shared worktree service. Git projects require a successful fetch and create a new checkout from the returned fixed remote OID; local main stays untouched. Directory projects retain their project identity and execute in their existing directory. A caller cannot override a project's directory or silently substitute the loose-session directory. Preparation is journaled under the launch key and uses the optional task deadline without a separate setup timeout; retries return the same workspace receipt. Preparation failure saves a failed result and never starts the coding process. Workspaces are preserved on execution failure for inspection.

Go preparation returns a stable opaque `workspaceId` and persists its project/directory/branch/base/start-OID receipt under the instance data root. Passing `projectId` plus that `workspaceId` resumes the recorded checkout, validates its project and current worktree membership, and preserves local commits and uncommitted changes. Reuse rejects `directory`, `base` and `remote` overrides, unknown IDs, cross-project IDs, missing/moved paths and branch mismatches. It performs no fetch, checkout, reset or rebase; offline continuation is supported. Older receipts without workspace IDs need a new explicit preparation before this reuse path is available.

Managed coding runners take an exclusive writer lock for the canonical Git checkout (or the exact canonical directory outside Git). Symlink aliases and nested directories of the same checkout share the lock; separate linked worktrees do not. The durable writer receipt remains after a runner exits: a later writer requires the earlier run's terminal result, so a lost Go runner cannot release a potentially still-active child merely by losing its OS lock. Busy or uncertain workspaces fail before starting the coding process. This coordination covers framework-managed coding runs; coordination of external/manual workspace changes and non-Shell remote resources remains required.

Python exposes `preparing` until an actual running receipt arrives, persists the resolved target and workspace event, and inherits parent task deadlines. External checkpoint Fork remains required; enrolled Codex and Claude TUI continuation use the evidence contracts described above. These targets fail explicitly; callers must not substitute an arbitrary current directory for a project target. External success still enters the verification path; this transport does not equate an exit code with meeting the user's goal.

### Existing Claude Code TUI sessions

Explicit Claude session targets use the same durable submission, original provider identity, workspace fence and process-stop proof as Codex targets. New interactive launches and unsubmitted revive commands carry observer-only `--settings` hooks; existing user hooks, permission settings and managed hook controls remain in effect. One-shot execution keeps its existing transport. Shell words, executable paths and scoped settings are quoted separately.

A source `UserPromptSubmit` must carry Claude’s `prompt_id`. A `Stop` records a candidate only when both `background_tasks` and `session_crons` are present and empty and no root tool remains in flight. A later `Notification(idle_prompt)` must match that prompt and candidate; process proof must also pass. More tools invalidate the candidate. Subagent text, `SubagentStop`, missing registry fields, stale prompts, API failures or manual takeover cannot settle it. Cancellation denies further supported root tools and still waits for stop evidence. Completion enters ordinary independent task acceptance.

The idle notification normally arrives about 60 seconds after the response, so this strict adapter adds that delay; short task deadlines can expire first. Older/missing hook contracts and autonomous follow-up prompts that cannot be associated unambiguously remain unknown rather than being replayed. The adapter follows the official [common hook fields, Stop and idle notification contract](https://code.claude.com/docs/en/hooks) and [settings precedence](https://code.claude.com/docs/en/settings). Isolated callback/launcher tests and installed Claude help checks pass; a real provider-backed TUI round trip is still pending.


## New project targets

A `new_project` target supplies `name` and an optional absolute `baseDir`. Native and coding executors first call the existing authenticated `roami project create` CLI, using a stable `--provision-key` derived from the run. Go's project API remains the catalog writer; Python never writes project metadata. The default parent is `<DataRoot>/projects`. The normal create command still supports adopting existing directories; Agent provisioning uses an exclusive path that rejects name/directory conflicts and placement inside another Git worktree.

Go saves intent before directory creation, verifies ownership before recovery/registration, checks catalog persistence and saves a durable resource receipt. Replaying the same request returns the same project ID, while changed parameters or a removed target fail explicitly. An ambiguous directory is preserved for reconciliation. Current Agent provisioning creates an empty directory project; configured templates/clone provisioning are still required. CLI login and the existing Go server connection must already be available; no additional Python login or fallback metadata writer is introduced.

After provisioning, execution uses the normal project workspace preparation and records the resolved project/workspace binding. Memory extraction and daily counts use the resolved project, with daily attribution bounded by the preparation event watermark. A directory project that is later initialized as its own Git repository keeps its workspace ID when continued; the registry refreshes checkout metadata without fetching or resetting it.

## Native Worker workspaces

A native project task uses the same Go workspace preparation and registry as a coding CLI task. Python requests `roami agent execution hold --file -` with a bounded JSON frame and keeps that process open for the task lifetime. Go returns the prepared workspace, holds the shared writer lock, and requires a second explicit `stopped` confirmation before saving a release result. EOF, owner death, a missing acknowledgement, or an unknown write leaves the workspace quarantined. This internal lease protocol does not report task success or satisfy task acceptance.

The native branch receives the trusted workspace in its system context and tool binding. Shell defaults to that directory; relative cwd resolves beneath it, and a task cannot substitute another configured root. Shell removes inherited Git repository bindings while preserving Git authentication settings. This is cwd validation, not an OS filesystem sandbox. Unbound analytical Workers can answer without a workspace; local Shell calls require preparation. Loose native tasks can use an explicit directory or `runtime.coding_directory` as their default.

Preparation consumes the task's original deadline. `preparing` becomes `running` only after the Go receipt and database binding are recorded. Cancellation or source forgetting during preparation prevents Worker admission. Local Shell cleanup stops its process group before cancellation is confirmed; cancelled remote/MCP writes with unknown outcomes cannot release the workspace and leave the task interrupted with an unknown attempt. Preparation failures also close the prepared native turn. Restart preserves uncertain ownership rather than automatically repeating work.

Cross-language tests use the real Go CLI, Python runtime and local Shell processes in an isolated registered project. They verify default cwd, task state ordering, independent acceptance, cancellation/child stop, workspace reuse, and quarantine after an uncertain cancellation. The provider is an injected fixture; these tests do not contact a real model or a user's coding sessions.

### Late Native workspace stop reconciliation

Managed instances run a separate bounded stop-reconciliation monitor. It maps each abandoned Native attempt to its exact persisted `task.preparing` turn, rejects active jobs/turns, and checks at most 256 write calls and resource actions. Terminal writes are retained as evidence; unknown Browser/Computer writes require matching, owner/run-scoped driver actions with explicit input-stop receipts. Missing, running, mismatched or unsupported unknown writes stay fenced. A pass examines at most eight attempts and uses no model slot.

Python sends only an evidence hash and stop assertion through the trusted local `roami agent execution reconcile-native --key KEY --file -` boundary. Go requires the original Native spec/workspace, an inactive holder and the original writer identity before recording a terminal stop marker. Repeated acknowledgements preserve the marker and a later writer. The command never replays execution; it cannot reconcile coding-agent launches. Python then releases eligible original controls and records one `task.native_workspace_reconciled` event in the original conversation. Task/attempt uncertainty and verification requirements are preserved.

CLI paths bind to the validated managed instance and provider credentials are excluded. Unmanaged stores cannot fall back to host defaults. Tests cover actual Go hold EOF, Python persistence, CLI acknowledgement, unchanged task state, control release, stale/busy/mismatched evidence and Main responsiveness while reconciliation is delayed. Generic Shell/HTTP/MCP unknown effects still require their own definitive evidence; this monitor does not infer remote completion.

## Scheduled reminders and notification policy

Explicit one-shot reminders accept an absolute UTC `whenMs` or a relative `afterSeconds`; daily reminders use `dailyAt` (`HH:MM`) plus an IANA timezone. Main has three short reminder tools, bound to its current conversation and live turn. Ordinary questions still call the model directly. Creating a reminder returns the saved next due time immediately; firing a fixed reminder uses no model call and runs outside Main/Worker model capacity.

`roami agent reminder add --conversation ID --key KEY --text TEXT --after-seconds 60`, `reminder ls`, and `reminder cancel --id ID` use the same Python application service as authenticated `/api/agent/reminders`. Reusing a request key preserves its original due time; changed parameters conflict. Each firing, assistant message, event, completed trace job and next due time commit together. Restart catches up one latest daily occurrence and records the count of skipped dates, avoiding a flood of old reminders. Spring clock gaps move to the first valid minute; a repeated hour fires once per local date. Cancellation preserves existing messages and firing history.

`roami agent notification-preferences get` returns the complete settings object; `set --file SETTINGS.json` replaces it. Authenticated Web clients use GET/PUT `/api/agent/notification-preferences`. Preferences separate task results, decisions, reminders and suggestions, with timezone/quiet hours, explicit attention bypass, hidden previews and suggestion rate limits. Suggestions default off. The policy admission service keeps its rate reservations durable and counts one event once across retries. These settings do not remove chat messages or consume unread state. App/Web Push adapters apply this policy before claiming a send; saving preferences is not evidence of system notification delivery.

Schema 4 adds reminders, firing history and notification policy under the Python-owned migration mechanism. Go backup/restore accepts versions 1 through 5 and rejects newer schemas; Go does not run these DDL migrations.

## App and Web Push delivery

Python owns the outbox, preferences, unread counts and claim/receipt state; Go forwards notifications to the existing App WebSocket and Web Push adapters. The Go loop uses the existing private Unix transport with the local owner and no new login. Its claim and receipt routes are private and are not mounted in the public proxy. The public `/api/agent/notification-deliveries` endpoint returns the latest 50 owner-scoped transport records.

Main conversation creation installs an App channel binding, and proactive/terminal-task messages commit their event and outbox row together. Native Worker branches do not get App bindings. Ordinary direct chat answers stay in the conversation; background task results, pending decisions, explicit reminders and trusted proactive triggers can notify. Task completion events retain task revision/state so changed or continued tasks cannot send old results. Read/deleted/forgotten or superseded messages are skipped before admission. Schema 5 adds a migration watermark so installing this adapter does not push the existing unread archive.

Quiet hours, category settings, preview hiding and suggestion rate limits are checked while claiming. Changing preferences wakes held pending records; it does not recall a send already in progress. A claim has a unique token and 30-second receipt deadline. Go bounds fan-out to four workers and a ten-second overall send context. Confirmed failures retry the same message with backoff, up to six attempts. An expired sender, lost receipt, network ambiguity or partial fan-out stays unknown and is never blindly resent. A late matching terminal receipt can settle that same claim; an older claim cannot overwrite a newer attempt.

`adapter_accepted` means queued to an App connection or accepted by a push gateway. It never means the device displayed or the user read the message; every public receipt retains `deviceDelivered: false`. Offline devices, revoked notification permissions and platform delivery remain outside that acknowledgement. Integration tests use actual Python persistence, Go transport and a connected isolated App WebSocket. Web Push encryption/gateway acceptance and failure cases use the existing SDK with a local injected HTTP client; no real user's devices are contacted.

The notification panel includes reminders, preferences and delivery records. Main reminder tools use the owner's saved notification timezone when no timezone is supplied. New App and Service Worker notifications retain the original conversation/branch/message and open a validated route. The chat positions the target after lazy Markdown layout settles, stops pinning when the user interacts, and preserves the existing visible-message read protocol. Web and Android notification content supports Chinese and English. Android unit tests, desktop/compact browser checks and the physical-device checks below pass.

## Main latency and generation controls

`[model.parameters]` and `[worker.model.parameters]` configure bounded `reasoning_effort`, `max_tokens`, `temperature` and `top_p`. Explicit Worker routes start with their own empty parameter map. Invalid values or routing/credential/body override keys are rejected before a provider request. Generation parameters participate in the persisted settings fingerprint and cache namespace; an empty map preserves legacy fingerprints. Unsupported provider settings return their actual request error without silently switching models or replaying a partial answer. Provider-specific accepted values must be verified, for example in the [Z.AI request reference](https://docs.z.ai/api-reference/llm/chat-completion#body-reasoning-effort).

At stream termination, the adapter briefly consumes the terminal HTTP chunk so its shared client can reuse connections. Cleanup has a 50ms/eight-line bound; a provider that leaves HTTP open after `DONE` cannot hold the turn indefinitely. A real local chunked-HTTP test verifies three model calls over one connection, and another verifies the open-body deadline. No post-terminal data is admitted as model output.

## Provider reference

The streaming adapter follows the official [chat-completions event reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events). It implements this explicit wire contract rather than assuming all provider APIs or models have identical tool/caching capabilities.

`model.max_retries` defaults to two retries and accepts 0–3. Only transient HTTP/transport failures before any normalized event is emitted can retry; partial visible text is never replayed. Backoff respects `Retry-After` and the original request deadline; cancellation interrupts the wait. Permanent/authentication errors, malformed events and redirects do not retry. The endpoint parser rejects embedded credentials, query/fragment values and non-loopback plain HTTP. Redirects are disabled even with an injected HTTP client. Provider diagnostics remain outside model context. See the official [error/recovery reference](https://developers.openai.com/api/docs/guides/error-codes).

`model.capabilities` declares a version and supported tools, streamed usage and cache parameters. Defaults preserve the existing text/function-call wire contract. Cache request parameters are opt-in: the deployment must verify the selected endpoint and both configured models, then declare support before enabling `model.cache`. A stable hashed key varies with route, model settings, namespace, first system message and tools; appending conversation messages preserves it. `mode=explicit` marks only the leading system/developer prefix through content-block breakpoints and leaves the stored context unchanged. It requires a system prefix. `mode=implicit` sends the configured cache options without adding breakpoints. The provider owns actual matching, retention and KV state; local fingerprints do not prove a hit or copy a Fork's KV cache. These optional fields follow the official [request contract](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create).

Prompt manifests now partition fingerprints by endpoint ID, model, serializer and capability/cache settings. They record hashes instead of endpoint credentials or full prompts. Usage retains provider counts and normalizes known input/output/cache-read fields; absent fields remain null, including unsupported cache-write counts. A successful retried attempt does not establish total cost across earlier attempts, so `retryUsageKnown` stays false. Separate endpoints/model versions do not reuse the same application fingerprint. Provider/model routing across different endpoints and performance/cost benchmarks remain pending.

## MCP connections

Configure named servers under `[tools.mcp.<name>]` as shown in `agent.example.toml`. A Worker calls `mcp_discover` for the relevant server; Main never waits for MCP startup or carries the full remote catalog. Each connection owns its SDK session in one actor and serializes its calls. Tools use namespaced, schema/version-bound aliases; catalogs are sorted for a stable model prefix. Directory changes remove old tools, and discovery/call refreshes refuse stale aliases before execution. Failed connections back off and reconnect on demand without replaying calls.

Stdio children receive the SDK's minimal default environment plus explicitly mapped `env_env` variables. HTTP credentials come from `key_env` or `header_env`; endpoint URLs cannot carry credentials. Raw server errors/stderr and progress messages do not enter ordinary logs or model context. Numeric progress events are bounded and persisted against the active turn lease. Calls have bounded queues, deadlines and output; cancellation sends a best-effort MCP cancellation notification and closes the connection. A remote cancellation is not proof that a write stopped: ambiguous outcomes are persisted as unknown, end the current turn and never automatically replay. Only explicitly configured `read_only` tools count as reads; server hints alone do not remove verification.

The adapter uses the official [Python SDK](https://github.com/modelcontextprotocol/python-sdk/tree/v1.30.0) for the [MCP transports and lifecycle](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports). Automated checks use real stdio processes and an authenticated local Streamable HTTP server, plus native Worker discovery/calls, catalog fingerprints, schema changes, timeouts, cancellation and unknown outcomes. They do not contact configured production MCP services.

## Artifact storage

The runtime upgrades schemas v1–v6 transactionally, preserving existing rows. Unsupported future versions fail without rebuilding the database; Go backup validation accepts all six supported schema versions. Artifact bytes live under `<DataRoot>/agent-artifacts/blobs`, addressed by SHA-256, while SQLite stores separate opaque, owner-scoped references. Task/message attachment validates ownership and branch provenance. Writes are atomic and durable before publishing a reference; reads verify size and digest. A cancelled caller cannot release the runtime maintenance lock while filesystem work is still pending.

The authenticated Go proxy exposes `GET /api/agent/artifacts`, `GET /api/agent/artifacts/{id}`, `GET /api/agent/artifacts/{id}/content` and `DELETE /api/agent/artifacts/{id}`. Downloads use attachment disposition, disable caching and sniffing, and never expose storage paths. `[artifacts].max_bytes` defaults to 0 (no execution-output size quota); a positive value opts into a per-artifact quota. Deletion tombstones the reference without resurrecting it on a later upload; physical collection uses the policy below. Unified `roami db backup` emits a v2 package when the Python artifact index exists, deduplicates live blob files, and checks paths, sizes and SHA-256 against the snapshot. Restore into an empty instance stages database and artifact files on their respective filesystems, uses the existing maintenance journal, and keeps writers blocked until both are published and verified. `roami db migrate --recover` reconciles interruptions before or after file publication. Incomplete packages, unsupported schemas and existing artifact destinations are rejected; deleted references remain tombstoned. Older database-only Agent packages with an artifact index are explicitly incomplete. Database-root layout migration includes the referenced artifacts in its pre-migration backup and verifies the retained files before publishing. MCP images/audio/embedded resources and oversized text/structured results produce artifact references with source metadata; resource links are stored without fetching their URLs. Worker Shell preserves large UTF-8 logs and exact binary bytes as separate stdout/stderr artifacts, with a bounded preview and the actual exit code. `artifact_read` retrieves bounded text excerpts for Workers and returns metadata for binary evidence. Small ordinary tool results retain their existing format. Filesystem publication failures after execution remain unknown outcomes rather than replayable failures. These endpoints do not accept arbitrary file paths or public uploads. Shell and HTTP tool bodies spool to private files; large results retain their complete bytes with a small preview. Process output size never kills a running command. `artifact_read` hashes the stored file while retaining only its requested page in memory.

Deleted references retain their audit rows. A background collector reclaims a blob only after every reference to its hash is deleted and the last deletion exceeds `[artifacts].gc_grace_seconds` (default 86,400 seconds, minimum one hour). Active artifacts never expire automatically. Successful reclamation records `purged_ms`; interrupted unlink/index updates reconcile safely on a later pass. Publication and collection serialize across store views, including cancelled writes that are still finishing.

Every `[artifacts].gc_interval_seconds` (default 300 seconds), a pass handles at most 100 indexed hashes and examines at most 100 filesystem entries across at most 16 new hash directories. A cursor makes progress between passes. Old unindexed blobs and abandoned private temporary writes are eligible after both filesystem timestamps exceed the grace period. Symlinks, changed files and unrecognized names are preserved; no external directory is traversed. Filesystem work runs in the artifact executor and shutdown drains it before releasing the maintenance lock. Tests cover shared ownership, grace periods, interrupted publication/purge, symlinks, bounded scans, recreation and v5-to-v6 upgrade. Database-root relocation preserves registered relative paths and includes schema versions, shared blobs and tombstones in a validated v2 recovery package. In-place publication and recovery recheck artifact integrity before unblocking writers; older recovery binaries fail closed on that mode. Direct relocation to another data root is rejected: use the existing complete backup and empty-instance restore to transfer the indexed files. This transfers persisted evidence, while active external execution still requires its own reconciliation.

Completion invalidates the old observation. Pause blocks new actions immediately and waits for the active action to settle before release; resume requires confirmed release. ## Cancellation and late results

Execution reports preserve the original result on the attempt and enter verification before any terminal task state. A cancellation request remains authoritative when a result arrives or a verifier returns: it cannot become success or failure merely because completion raced with cancellation. The parent waits for every child to reach a terminal state. Unknown child or own stop evidence leaves the task interrupted instead of claiming confirmed cancellation. Cancelling a task that is waiting for user acceptance requeues its existing verification job. The original conversation receives one terminal cancellation completion; late results remain evidence and do not revive an interrupted task.

A committed `/stop` receipt fences subsequent model output, tool admission, reminders and delegation even before coroutine cancellation arrives. Model-originated delegation also requires a running source turn. Existing delegated tasks keep their independent lifecycle; explicit user task requests remain available. Complete memory forgetting records source omissions and requests cancellation of affected task trees in the same transaction. Existing executor cancellation and reconciliation confirm the actual stop; no uncertain execution is replayed. Deleting a memory without forgetting its sources does not cancel tasks.

## Worker workspace files

Workers have `file_read`, `file_write` and `file_patch` in prepared task workspaces; Main does not. Unbound calls require an explicitly configured absolute root. Reads hash the full file in chunks and return at most 16,000 bytes per page; non-UTF-8 byte pages are labelled base64. Writes require `expectedSha256` (or null for exclusive creation); patches require a hash and exactly one literal match. Publication checks the file again after the temporary file is durable, preserves existing permission bits, and atomically replaces the directory entry. Changed files and ambiguous patches fail without replacing the target. The workspace writer fence coordinates participating agents; content checks do not provide a filesystem-wide transaction against arbitrary concurrent programs.

Directory traversal uses directory descriptors and rejects symlink components and non-regular files. File I/O has its own bounded admission/thread pool. Cancellation waits up to two seconds for actual I/O completion; an unconfirmed operation stays unknown and cannot release a prepared writer workspace. Runtime shutdown drains outstanding file I/O before storage maintenance locks are released. Failure after publication but before directory durability is reported as unknown and never automatically replayed.

A Native Worker cannot override an unknown write by returning an optimistic summary. The executor checks the persisted tool ledger before returning success; any planned, running or unknown write interrupts the task before goal verification. The completed model text stays in the child transcript as evidence and does not count as acceptance.

## Artifact-backed memory

### Existing-session delivery and visible execution facts

Main can use `session_send` to append a message to an exact existing session, including legacy Codex/Claude sessions. The unified boundary is `roami agent execution send-message --file -`, accepting `{key, sessionId, text}` on stdin. A `delivered` receipt confirms submission only; `executionTracked=false` does not prove execution or completion. The Go receipt is persisted before input and reused for the same key; an unknown outcome is never automatically pasted again.

Tracked work uses `delegate` and requires lifecycle callbacks for existing sessions. Chat snapshots include a bounded `activities` projection of tools and tasks; SSE publishes starts, completions and Worker activity to the originating conversation. Task-result generation failures produce a structured status message that remains available to the next Main turn. ## Token-based context admission

Context admission follows Pi's [compaction implementation](https://github.com/earendil-works/pi/blob/482c1381a00d8d00bc81697e4a980c593db6803e/packages/coding-agent/src/core/compaction/compaction.ts): use the latest valid provider input-plus-output usage, then estimate later messages with `ceil(characters / 4)`. Without valid usage, estimate the entire request, including the system prompt, tool schemas, tool-call arguments and tool results. Images use Pi's 1,200-token placeholder rather than counting base64 characters. This is an estimate, not a model-specific tokenizer. OpenAI-compatible prompt usage already includes cached input, so cache counts are not added twice.

Usage is reused only for the same request configuration, unchanged source prefix, snapshot and memory epoch. Model/settings or tool changes, edits, forgetting and compaction invalidate stale baselines. Existing manifests without the new evidence fall back to character estimation; no transcript migration is required. The context panel and `/status` report the same total estimate as request admission.

Context capacity has **no application default or fixed input cap**. Main and Worker each use their exact endpoint/model's context window. At startup and after configuration saves, the runtime reads provider `/models` metadata (including nested `token_limits.context_window`). A role's explicit `contextWindow` in private model settings, or `context_window` in its model TOML block, takes precedence. Switching model or endpoint clears the previous role capacity. Output-only `max_tokens` is never interpreted as a context window. Failed discovery or omitted metadata leaves capacity and percentage threshold unknown; no invented limit is substituted. The settings page can supply the verified model specification. Manual `/compact` remains available.

```toml
[model]
# context_window = ... # optional verified model specification; no default
[runtime]
keep_recent_tokens = 20000
compaction_ratio = 0.75
```

For known model window C, automatic compaction triggers at `floor(C * compaction_ratio)`: a 1,000,000-token model triggers at 750,000, and a 1,048,576-token model at 786,432. Legacy `[runtime].input_budget` and `reserve_tokens` do not reduce this threshold. The API reports `capacityBasis="model_window"` or `"unknown"`. The context panel and `/status` expose the same model capacity and token estimate.

Requests check the soft threshold before inference; completed replies queue background compaction using their actual usage without waiting for another message or generating a summary inline. Cut points preserve complete rounds and tool pairs. No safe cut below the model window is a skip; exceeding a known window remains an error. Recent raw history after compaction retains at most 20,000 tokens, shrinking for the history allowance; this retention policy is not a model capacity. Upload/output byte limits remain separate storage limits.

## Chat image preparation

The browser optimizes PNG/JPEG/WebP images before uploading, accepting source files up to 64 MiB and 64 million pixels while keeping non-image uploads at 10 MiB. Image decoding is serialized; optimized uploads may proceed concurrently. Retries reuse the exact prepared file and request key. The stored attachment is the received optimized image, not a promise to retain the original camera bytes. Source files on the user's device are unchanged.

Python applies EXIF orientation and enforces the selected model's image limits before inference. Compliant images retain their bytes and MIME; oversized images try PNG first, then JPEG quality levels (white background for alpha), then progressively smaller dimensions. Base64 encoded size is bounded, independently of model context tokens. The default image policy follows Pi: maximum 2000×2000, encoded payload 4.5 MiB, initial JPEG quality 80. Explicit model overrides are supported:

```toml
[model.image_limits]
max_width = 2000
max_height = 2000
max_encoded_bytes = 4718592
jpeg_quality = 80
# [worker.model.image_limits] can specify independent limits.
```

The image's actual MIME is used in `image_url` data URLs; transcript JSON retains references, never Base64. Enable the model's image capability only after verifying its actual behavior: the currently configured service advertises text-only metadata, but an isolated real image probe succeeded. These changes cover chat attachments; arbitrary file/MCP images are not claimed to be integrated into this path.
