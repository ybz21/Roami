# Roami 产品演进：从 tmux 工具到多智能体工作台

> 一页讲稿｜约 3 分钟｜依据截至 2026-11-26 的 `eb1f9df1`：约六个月、1208 个提交、5 个版本标签。

**一句话主线：** 管理对象从**会话 → 项目 → 目标**，接入方式从**本机 CLI → 多端、多机**，执行方式从**单个 Agent → 团队、能力与模型编排**。

## 开场

Roami 的演进，不是给终端不断叠加按钮，而是持续抬高它管理工作的层级：先让 AI 能启动和观察一批会话，再让人远程掌控开发机，随后把会话组织成项目交付，最后把任务、团队、目标和模型放进同一个工作闭环。

## 六个阶段

### 1｜5 月：从 tmux 增强工具到 AI 原生编排

5 月 27 日，仓库以 **ttmux** 起步：先解决 tmux 难用的问题，当天就加入 `spawn / group / wait / capture / collect`，让 Claude Code 能批量派活、等待和收集结果；随后又补上多智能体编排与多实例监护。**这一阶段，产品管理的是“会话”，但已经明确了 AI 原生、并行工作的方向。**

### 2｜6 月：从本机 CLI 到远程开发机控制台

6 月 15 日，Go 后端与 Vite 前端组成的 Web 控制台落地；随后蜂群看板、真实 Chrome 镜像、对话与文件、语音输入、HTTPS 和手机镜像陆续进入同一入口。6 月 17 日启用 Roam 品牌，CLI 随后完成 Go 重写。**产品由此跨出本机命令行：用户可以从浏览器观察、操作和接管开发机上的 Agent 与真实工具。**

### 3｜7 月：从“管会话”到“管项目与交付”

7 月 9 日，配置、首次口令、数据目录和单一二进制打包收口，形成 `v0.1.0-rc.1 / rc.2` 两个预发布节点。随后 Monaco 文件工作区、Git worktree、派生会话和多方案竞赛串起开发流程；插件、飞书桥与定时任务开始扩展能力。7 月 14 日“项目”成为主入口，同月还铺设多机数据面与 P2P，月底补上稳定身份。**管理单位不再只是一个终端，而是仓库、任务、分支与结果。**

### 4｜8—9 月：从功能集合到可靠、统一的工作台

这一阶段重点转向“长期使用”：桌面与手机响应式重构、全局搜索、多机中心、统一存储、内存护栏和休眠恢复逐步落地；9 月形成项目／任务／会话树与全局标签组成的工作区。品牌也从 **Roam 更名为 Roami**，`v0.2.0-rc.1` 收口统一命令入口、定时任务记录与工作区体验。**产品开始同时解决好不好用、断开后能否继续、多台机器能否一起管。**

### 5｜10 月：从远程操控 Agent 到内置助手与能力平台

10 月 9 日，手机版首页、会话和 Android App 落地；10 月 19 日接入主智能体运行时，首页逐步整合对话、任务、消息、记忆与产物。能力中心统一 Agent、插件、Skill、MCP 和 CLI，并接入开放市场；模型服务、额度用量与 RSI 实验流程也开始纳入管理，形成 `v0.2.0-rc.2` 与 `v0.2.1`。**Roami 不再只是专业 Agent 的遥控器，自己也能理解任务、调用工具、保存记忆并组织交付。**

### 6｜11 月：从单次任务到目标、长期团队与模型编排

11 月，OKR 工作区把目标、项目文件、Main 对话与蜂群执行连接起来；长期成员、执行轮次、暂停恢复、消息与结果回执持续补强。模型侧则从接入走向统一工作区，补齐模型源、聚合、路由、用量与请求监控，并新增 Gemini CLI、Antigravity CLI。**产品开始围绕长期目标组织团队与资源，而不只是响应一次性指令。**

## 收束

今天的 Roami，是一个**自托管、可远程接管的多智能体工作台**：Agent、代码和工具运行在用户自己的开发机上，用户从手机或电脑发起任务、跟踪进展、查看产物，并在需要时接管。它真正完成的升级，是把“发起—执行—观察—干预—交付—追溯”连成闭环，并以此为底座走向长期目标和团队协作。
