Product Design / 2026-11-01

源配置一次，每个 Agent 用自己的 Key。

模型来源复用本机已配置的模型库。OpenCode、Claude Code、Codex 等通过本地网关调用；网关根据 Key 识别谁在用，再按实际模型用量归账。

这里的“计费”是本地用量归集与费用核算。

它不等于上游扣款确认，也不包含钱包、充值或对外收款。只有实际经过网关的请求，才能由网关归账。

截图里的问题

“模型源”显示上游 URL，用户看不出已通过本地网关，也找不到独立接入身份、Key 或费用入口。

现有自定义模式实际已经走网关；这次需要把接入关系讲清，并补齐多个同类 Agent 的分账能力。

本次主张

  • 自定义模式明确为“Roami 本地网关”。
  • 来源可选“全部已配置模型”，也可按已有来源筛选。
  • 每个 Agent 接入有独立 Key，可单独轮换、停用和查看费用。
  • Roami 托管启动的会话可领用临时 Key，进一步按会话归账。

User Stories

已有来源，直接复用

我在 OpenCode 里选本地模型库，选择一个模型，应用后就能调用，无需再输入上游密钥。

同类 Agent，也能分开记账

“OpenCode · 日常”和“OpenCode · 项目 A”各有独立 Key；可以按 OpenCode 汇总，也可以只看项目 A。

每个托管会话有独立凭据

从 Roami 启动的两个 OpenCode 会话同时运行，各自领用临时 Key，不相互覆盖全局配置。

换源、换 Key，不丢旧账

账本保留当时的身份、模型、真实来源和单价；停用接入不删除历史。

费用口径
按调用开始时保存的单价快照计算，历史费用不随日后改价重算。计费输入为扣除缓存读取后的输入；缓存读取单独计价，避免重复计费。
费用 = 非缓存输入 * 输入单价 / 1,000,000
     + 输出 * 输出单价 / 1,000,000
     + 缓存读取 * 缓存单价 / 1,000,000
本例单价：输入 ¥2、输出 ¥8、缓存读取 ¥0.2 / 百万 Token。已知合计 ¥0.3600；一条调用缺少可信用量，另行待核账。
保留现有计费边界
  • 厂商账单与本地费用分开标注，不能把估算说成已扣款。
  • 未定价、显式零价、用量缺失是不同状态；不据一次零额推断免费。
  • 输入与缓存口径由协议适配器归一。缓存写入等未独立支持的口径，不伪造数量。
  • 跨币种分开展示，不直接相加，不自动换汇。
  • 沿用现有全局日限额；本次不另加 Token 或请求次数上限。

一次请求如何入账
  1. 本地监听器收取网关 Key，校验摘要、状态、到期时间；解析得到 consumer 与可选 lease。
  2. 服务端按 Key 的模型授权过滤 /v1/models，并检查推理路由权限。选择来源只是模型目录筛选，不允许绕过路由授权。
  3. 创建逻辑请求与真实调用记录，保存身份、路由、候选来源、原始模型名、币种、价格与计价状态快照；由 Go 执行现有准入。
  4. 覆盖或移除客户端的身份类 header，选择正确上游协议与上游 Key；下游 Key 不转发给上游。
  5. 从原始上游响应采集用量，保留缓存语义，按既有结算规则写回。结算仍受“仅更新 pending”约束，避免一条结算事件被重复记账。
  6. 只在现有策略允许的连接建立前失败时切候选；一个逻辑请求可有多条真实尝试，汇总只加实际尝试的已知费用。不为核账重新发起推理。
关联 ID 不等于推理幂等键。
客户端重复提交可能真实产生两次上游费用，每次都要记录。不能仅因请求 ID 相同，就把第二次真实费用去掉。


Key 的应用、轮换与回收
动作设计约束
默认应用默认身份首次创建 Key；切换模型复用已绑定身份。只有已验证支持的字段由现有适配器原子修改，并读回确认。
轮换托管 Key新旧 Key 短暂并存，先原子写入配置、读回验证，再撤销旧 Key。配置失败撤销新 Key并保留旧配置；进行中的请求按原快照结束，不自动重发。
崩溃恢复操作日志只记配置指纹与 Key ID；重启后读原生配置并核对摘要，再决定完成或回滚。敏感配置备份受本地权限保护；新 Key 明文不进普通日志或浏览器存储。
手工接入完整 Key 仅在创建 / 轮换时返回一次；之后只显示掩码。遗失时重新轮换；托管进程配置可由节点本地适配器读取以完成恢复。
停用身份拒绝该身份所有 Key 的后续请求；历史不删除。若要停正在执行的任务，另走明确的任务停止流程。
会话 Key（V2）启动时生成会话配置，权限不超过父身份，绑定真实会话；到期 / 会话确认结束后撤销。观测丢失时保持结果未知，不因此伪造结算或立即清理任务。

兼容、计价与失败恢复
  • 现有类型级 HMAC Key 继续识别，并映射到 legacy 默认身份；确认对应客户端已换新 Key 后，逐客户端禁用旧凭据，不能一次替换根 token 使全部客户端失效。
  • 本机已保存源与 CLI 配置只读扫描，显式导入后接管；跳过指向 Roami 自身的连接，避免形成递归代理。地址相同但凭据不同的账号不自动合并。
  • 查价优先级提案：已配置的对外模型价；否则来源 + 原始模型价；再原始模型价、前缀和默认价。V1 仍是同一套本地核算价格，不新增成本 / 售价双账。
  • 新请求区分明确零价、未定价和用量缺失；未定价保留 Token、金额显示“未定价”。旧账沿用当时口径与原金额，不凭旧的零金额反推“免费”或“未定价”。若启用全局金额限额，新请求的未定价 / 待核账沿用网关不确定费用的准入规则，并提供补价格 / 核账入口，不能按零金额绕过。
  • 断流或用量缺失保留已知部分与待核账，不承诺实时厂商扣款。核账修正保存原因和原始证据，不能静默覆盖历史。
  • 未安装工具、版本不兼容、配置修订冲突分别给可操作错误；失败保留来源、身份和模型草稿。应用只影响后续调用，不重启正在运行的 Agent。
  • 共享一个 Key 的外部会话不伪装成按会话计费；内部子 Agent 没有独立凭据时同样归入父身份。
