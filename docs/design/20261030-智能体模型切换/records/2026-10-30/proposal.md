## Product Design

### 产品主张

**模型连接只配一次，再决定哪些智能体使用它。** 在现有「设置 / 模型与连接」下增加「智能体使用」标签；用户按智能体查看和切换默认模型，不再重复输入地址和密钥。

本稿将需求中的 “Cloud Code” 理解为 Claude Code。Codex 指当前节点上的本地 Codex CLI；若还要覆盖托管的 Codex Cloud，需要另做部署和认证接入，不能把本机配置写入当作云端配置。OpenRouter 是模型来源；如果原意是 OpenCode，它也在首批智能体适配范围内。

### 已有能力与缺口

| 当前代码 | 已有能力 | 本次设计补齐 |
| --- | --- | --- |
| `frontend/src/components/settings/agent-settings.tsx` | 一个模型连接、Roami 主智能体和执行智能体选模；已有模型连接 / 代理与计费 / 模型单价三个标签 | 升级为可复用的连接目录；保留现有角色设置与计费入口 |
| `frontend/src/components/capabilities/AgentModels.tsx` | 在每种专业智能体内重复维护连接预设，应用和恢复原配置 | 从统一目录选连接；能力中心保留当前摘要与「切换」快捷入口 |
| `internal/agentproviders/` | Claude / Codex / OpenCode / Pi 原生配置适配、revision 冲突检测、恢复及私有存储 | 绑定统一连接引用，补齐协议能力判断和逐目标结果 |
| `internal/modelgateway/` 与 RSI 单轮 Codex 桥接 | 本地准入、统计和受限调用 | 不能据此声称完整 CLI 的工具循环、图片、续接已兼容；统一网关是后续阶段 |

### 信息架构

不新增顶级导航，不把“模型来源”和“使用模型的工具”混成一张列表。

| 位置 | 用户要做的事 | 主要内容 |
| --- | --- | --- |
| 模型连接 | 接入、维护模型来源 | 名称、已存凭据状态、可用模型、正在被哪些智能体使用；行尾「分配」 |
| 智能体使用（新增） | 看谁在用什么、切换 | Roami、Codex、Claude Code、OpenCode、Pi；当前连接和模型、必要状态、行尾「切换」 |
| 代理与计费 | 看真实用量和限额 | 保留现有入口；仅统计实际经过 Roami 网关的调用 |
| 模型单价 | 维护本地估算价格 | 保留现有入口 |
| 能力中心 / 智能体详情 | 在当前工具内快速改模型 | 展示同一绑定摘要，打开同一个切换界面；安装与升级仍留在原处 |
| 新建会话 / 会话详情 | 确认即将使用或实际使用的模型 | 新建时显示默认来源；运行中优先显示实测模型，未知时显示「待确认」 |

### 主界面

页头显示当前节点，例如「开发主机」。手机远程操作修改的是这个节点，不能让用户误以为修改了手机上的 CLI。

智能体列表采用平面行：工具名、当前模型、来源、一项必要状态与「切换」。Codex / Claude 初次接入时显示「使用原配置」，保留官方登录。未安装工具显示「未安装」和安装入口；不虚构“已接入”。原配置指接管前快照，不能把任意自定义原配置标成官方订阅。

不在每一行显示路径、协议、密钥、延迟、完整错误和账单。未被 Roami 接管或正在直连时，不显示 Roami 限额保护徽标。

### 主路径：给 Codex 换模型

1. 打开「智能体使用」，在 Codex 行点「切换」。
2. 桌面进入同页右侧详情栏；手机进入带单一返回栏的全屏二级页，保留底部四个主导航入口。
3. 先选已保存的连接，再选该连接中适合 Codex 的模型；默认带出当前组合。地址和密钥无需再次填写。
4. 用一行说明作用范围：「修改开发主机上此用户的默认配置；新启动的 Roami 和本机命令行会话使用。」协议不兼容项仍可看见，但不能选；说明「此连接暂不能用于 Codex，换一个连接」。协议名在详情中展开。
5. 可选「测试模型」，明确一次小型验证，最多两次模型请求。检测内容是认证、真实模型响应、流式和工具调用回传；获取模型列表不算验证成功。不默认运行代码、不发送项目正文。测试结果只代表所测版本和组合。
6. 点「应用」。首次接管某工具时用短确认说明本机 CLI 影响，并提供「应用并备份」；已接管且无冲突时后续切换直接应用。
7. 成功后显示「已更新 Codex 默认配置」，给出所选来源和模型，并提示「重新打开 Codex 后使用」。列表显示「默认已设置」，不能直接宣称运行中的会话已切换。

回退：详情内「恢复原配置」。展示将恢复的工具与快照时间，确认后仅恢复接管过的模型相关字段；原来未登录的官方连接仍可能需要登录。恢复成功不等于模型连通。

### 另一条路径：连接配好后分给多个智能体

连接保存成功后出现轻量动作「分配给智能体」，不强制弹向导。在连接列表行尾也能进入。页面列出适配工具，用户勾选工具并逐个选择模型；**共用连接不要求共用同一个模型**。

提交按钮写「应用到 2 个智能体」。首次接管的目标合并成一次范围确认；每个目标独立备份、校验和应用。结果逐项展示，例如 Codex 成功、Claude 配置冲突，主状态为「部分完成」；成功项保留，失败项可单独重试。未安装或不兼容目标不可勾选，原因可见。

### 生效与边界

| 决策 | 产品规则 |
| --- | --- |
| 默认作用域 | 当前节点、当前服务用户的 CLI 默认配置，包含从 Roami 新启动及本机直接启动的对应工具；不是全组织、全设备或跨用户设置 |
| 正在运行的会话 | 不自动终止、重启或重放任务。配置文件热读行为由工具版本决定，因此不承诺原生 CLI 在运行中保持或立即改变；前台显示实际观测值，不能用保存结果代替生效证据 |
| 项目内覆盖 | 如果已有环境变量、项目配置或启动参数覆盖默认值，给出「有更高优先级配置」及可见的详情入口；不静默移除 |
| Roami 内置智能体 | 主智能体 / 执行智能体保留独立选模；保存后按现有请求边界生效。外部 CLI 的默认切换不连带改它们 |
| 官方登录 | 「恢复原配置」恢复原接管字段；官方订阅凭据不导出为可复用 API Key，不暗示能给其他工具通用 |
| 直连与代理 | 首期通过原生配置接入上游。详情明确「直连上游，未纳入 Roami 限额」；不混算本地统计与供应商账单 |
| 密钥更换 | 目录只有一个凭据权威。已物化至原生配置的绑定列为待同步；用户明确应用，逐目标回执，失败保留旧有效配置或说明真实恢复状态 |
| 删除连接 | 有绑定时列出受影响工具，要求先切换或解除绑定；不留下断开的默认配置。源模型下架同理显示不可用，不擅自换另一个模型 |
| 自定义工具 | 已有适配器才能一键应用。未知工具提供「接入说明」及协议选择，默认只展示脱敏配置；不称为兼容一切工具 |
| 后续单会话选模 | 单次选择与默认配置分开；通过启动时隔离实现后再开放，不用全局文件切换伪装“仅本会话” |

### 兼容与验证

产品层呈现「可选 / 待测试 / 不支持 / 测试未通过」，不要求普通用户理解协议转换。可选仅表示有匹配的连接协议与工具适配器；成功测试后显示「已通过模型测试」，不是完整任务质量承诺。

- Codex：本地适配器要求 Responses。仅 Chat Completions 的连接不能因“OpenAI 兼容”就标成支持。
- Claude Code：首期适配 Anthropic Messages，OpenRouter 对应独立入口和 bearer 认证。优先呈现 Claude 模型；其他模型的实验适配不承诺官方支持。
- OpenCode / Pi：依据已安装版本及适配器能力选择具体协议和模型，不把所有版本视为相同。
- 多协议网关：连接可包含不同协议的独立入口与认证方式，共用凭据只是默认；不能机械地把一个 Base URL 复制给全部工具。OpenRouter 预设需要版本化能力声明与实测，不只按域名猜。

连接的鉴权、模型目录、协议、流式、工具调用分别记结果；测试失败保留选择。主动测试可能计费，未知结果不自动重试。实际执行器的工具循环、压缩、图片、续接、取消仍要在实现期跑端到端验收。

### 异常与恢复

| 状态 | 默认展示 | 下一步 |
| --- | --- | --- |
| 未配置连接 | 尚未添加模型连接 | 添加连接；仍可保留原工具配置 |
| 没有兼容模型 | 这个连接暂不能用于 Codex | 换连接；展开协议详情 |
| 认证失败 | 连接密钥不可用，请更新密钥 | 打开对应连接，返回后保留工具和选模 |
| 工具未安装 | Pi 未安装 | 去能力中心安装，不允许应用 |
| 外部修改 | 配置已在其他地方修改，请先读取当前配置 | 读取后展示差异；用户明确选择保留外部配置或重新应用 |
| 写入失败 | 默认配置未更新，请重试 | 保留选择；展示备份和恢复结果，状态未知时不报“已恢复” |
| 多工具部分失败 | 部分完成 | 列出成功和失败工具，只重试失败项 |
| 网关离线 / 每日限额 | 仅代理模式下呈现对应真实状态 | 恢复网关或查看额度；不自动绕过代理改成直连 |

### 手机交互

设置分类保留原四入口底栏；模型页四个标签在窄屏排两行，不截断。切换、分配、恢复都是专用二级页，只有一条等高返回栏和一个内容滚动区。应用操作放在内容末尾，保证 320px 和横屏可滚达；不堆叠桌面抽屉和移动对话框。

返回保留未提交选模；只有明确取消才丢弃。系统返回与页面返回采用同一 URL 历史，不叠加 overlay history。主题、空间、字号和图标复用项目规范。原型为中文设计稿；正式产品所有文案必须进入全局中英 i18n。

## User Stories

| 用户故事 | 验收条件 |
| --- | --- |
| 我已经配好工作网关，希望 Codex 直接使用 | 选择已存连接与兼容模型即可应用，无需再次填密钥；能看出修改的是哪个节点 |
| 我通过 OpenRouter 给不同工具供模型 | 在“来源”中找到 OpenRouter；Codex、Claude 可各选不同模型，适配协议单独判断 |
| 我希望手机上替服务器换连接 | 真机可完成选择、确认、返回、恢复；无横向溢出，底栏与操作可达 |
| 我希望继续使用官方订阅 | 默认可以保留原配置，接管后可恢复；不会把订阅当成通用模型 Key |
| 我只想换下一次启动的默认值 | 应用提示清晰；任务不被自动中止，运行状态不冒充切换成功 |
| 我同时维护两台节点 | 当前节点贯穿列表、详情与确认；连接目录、凭据和结果不跨节点同步 |
| 我也用 CC Switch 或手工改配置 | revision 冲突阻止覆盖；重新读取后可看见当前值，草稿保留 |
| 我一次接入多个工具，但其中一个失败 | 每个目标有独立结果；成功项不回退，失败项可单独恢复和重试 |

## Technical Design

以下是实现建议，不代表本次已交付接口或运行能力。

### 数据与模块

```text
ModelConnection
  id, name, credentialRef, revision
  endpoints[]: protocol, baseURL, authMode, credentialRef?
  catalog[]: exactModelID, endpointRef, advertisedCapabilities

AgentModelBinding
  nodeID, kind, connectionID, exactModelID, endpointRef
  adapterVersion, appliedRevision, nativeRevision, status
  snapshotRef, verificationRef

Verification
  connectionRevision, adapterVersion, exactModelID, checkedAt
  auth, inference, streaming, toolRoundTrip, errorCode

ApplyOperation
  id, requestID, targets[]
  per-target: beforeRevision, backupRef, writeState, readbackState, recoveryState
```

- `frontend/src/components/settings/agent-settings.tsx` 和 `model-settings-route.ts` 增加 `usage` 标签；模型来源编辑延用现有表单，按迁移阶段引入多连接。
- 新增 `agent-model-usage.tsx`、`agent-model-assignment.tsx` 与 `agent-model-binding.ts`，分别负责列表、分配流程与请求/状态契约；不混入账单模块。
- `AgentModels.tsx` 收敛为统一目录的快捷入口，保留旧独立预设迁移与恢复入口。
- `internal/agentproviders/` 延用现有原生字段捕获、私有文件、revision、冲突和恢复机制；新增按引用生成配置的适配层。避免做一套旁路写文件实现。
- 统一连接目录建议归 Go 宿主所有，Python `model_settings.py` 继续接收既有运行时读取结构；迁移不能创建两份互相覆盖的凭据权威。凭据只在宿主解析，摘要 API 不返回原值。
- 新接口建议放在现有 `/agent/professional/:kind/models` 旁：共享连接读取、兼容候选、应用预检、分配操作和结果。mutation 带连接 revision、原生 revision 和幂等 request ID；具体路径实现前确定。

### 应用事务

读取安装版本和当前原生 revision，解析绑定引用、校验端点与模型；预检记录不发送付费请求。首次接管备份涉及字段，应用时再次比较 revision。逐文件原子写、readback 后才报“默认已设置”；跨文件不能原子完成时保留事务日志并恢复。恢复失败显示需要处理，不能用布尔成功掩盖未知状态。

多工具操作按目标事务处理，提供逐项状态和恢复入口；不宣称跨工具原子。客户端请求超时先查操作结果，不重新提交可能已成功的应用。模型验证独立于写配置，不以写入成功或 `/models` 返回代替验证。

不复制 MCP、权限、插件、hooks 或其它无关配置。保留原始字段备份和外部修改检测。进程环境、配置目录、启动参数覆盖必须预检并说明；不能为达到“已应用”静默清理用户配置。

### 迁移与阶段

1. **首期：统一来源与原生切换。** 现有单连接按 ID 导入目录，主/执行角色继续引用；专业工具旧预设保留，用户可选择迁移为统一连接。仅对端点、协议、认证和凭据均可证明相同的条目去重，不按名称或脱敏 Key 合并。优先 Codex、Claude Code，再按已验证版本开放 OpenCode、Pi。
2. **后续：统一代理与计费。** 在 Go 网关实现完整原生 Responses / Messages 透传或经过验证的转换，保留工具、SSE、usage、图片、续接、压缩、取消和错误语义。复用 Go 准入和账本；不在 Python 叠加配额。协议未达到端到端门槛时不得打开“受 Roami 限额保护”。RSI 单轮 JSON 桥接不能直接替代完整 Codex CLI 网关。
3. **再扩展：单会话覆盖、自定义适配器。** 前者使用独立启动配置与会话快照，不写项目级 Codex provider 配置；后者声明版本、格式和应用/恢复契约，再进入兼容目录。首期不做自动故障换模、供应商测速排行或复杂路由规则。

### 实现期验收门槛

使用隔离配置目录与 `scripts/dev/isolated-roami.sh`，不把当前用户 Agent 配置当测试夹具。验证引用迁移、恢复、冲突、写入中断、批量部分成功、凭据轮换与高优先级覆盖。各适配器至少跑真实 CLI 的多轮工具调用与取消恢复；付费测试单独明确调用次数与成本提示。

桌面与 Android 真机覆盖应用、返回草稿、恢复、空态、错误和长名称；随后运行仓库规定的前端与质量门禁。设计原型的验证不代替产品接入验收。

- [OpenRouter / Claude Code](https://openrouter.ai/docs/cookbook/coding-agents/claude-code-integration)：独立 Messages 入口和 bearer 认证；其兼容保证有提供方范围。
- [OpenRouter / Codex CLI](https://openrouter.ai/docs/cookbook/coding-agents/codex-cli)：Codex 通过自定义提供方接入 OpenRouter。目录里的示例型号不作为推荐或固定默认。
- [CC Switch](https://github.com/farion1231/cc-switch)：借鉴供应商切换、恢复和配置保护，原型的默认生效规则以 Roami 自身适配验证为准。
