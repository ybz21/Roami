# 添加模型：最短流程

2026-10-31 产品修订提案。用户要求简化添加，并将定价、聚合策略放到后面的选项卡。本文及 [可交互稿](add-model.html) 用于评审，尚未改动产品运行代码。原型为中文开发评审文档、使用示例数据；正式实现的所有文案接入全局中英 i18n。

## Product Design

上一版合并了“来源”和“模型”的页面，但仍要求理解连接命名、模型 ID、显示名称和手动加行。合并表单没有减少用户要做的决定。

这版只问两件事：**连接哪项服务，添加哪些模型**。普通流程不要求用户理解协议、网关、智能体类型或路由。

### 页面结构

能力下继续并列“大模型”和“智能体”，不增加一级入口。大模型按以下顺序显示选项卡：

| 选项卡 | 内容 |
| --- | --- |
| 模型 | 统一添加、按来源分组的模型列表、连接设置 |
| 定价 | 保留默认、逐模型、前缀定价，以及输入、输出、缓存读取/写入价格和币种 |
| 聚合策略 | 给已添加的模型选择备用来源与模型、排列备用顺序；默认直接使用主来源 |
| 用量与限额 | 保留真实用量、费用、每日限额、时区、核账和记录 |

添加页不显示定价、策略、限额，也不显示“对外模型”。已有聚合策略原样保留，不因简化添加而重置。原型只展示策略的主用及一个备用位置，正式实现保留已有多个候选和顺序。

### 首次添加

1. 点击“添加模型”，打开添加页。桌面为内容面板，手机为全屏二级页。
2. 默认只显示“服务地址”“API 密钥”两个输入，主按钮“读取模型”。“连接选项”折叠；“手动填写模型”作为可见的文字操作。
3. 读取成功后，在同一页将连接输入收为来源摘要及“修改连接”，下面显示可搜索、可多选的模型列表。
4. 用户勾选模型，底部按钮变为“添加 2 个模型”。不默认勾选，不把整个上游目录自动导入。
5. 一次保存来源和所选模型，直接显示添加结果。提供“配置智能体”和“完成”，不再弹第二次保存确认。

“读取模型”只读取目录，不发送付费推理请求。成功文案是“已读取模型列表”，不能宣称模型已通过推理或工具能力验证。来源和未选择的目录项此时均未落库。

### 已有来源再加模型

从某个来源下的“添加更多模型”进入，直接显示该来源的模型选择列表，复用已保存的地址和密钥。主入口“添加模型”默认最近使用的来源；存在多个来源时可切换，并在同一选择器里提供“添加其他来源”。不强迫用户再填一次连接。

已添加的模型标为“已添加”，不可重复选。目录搜索不清空当前选择；“选择本页”仅选择当前过滤范围。切换来源保留各来源的草稿，回到来源时恢复。目录不可用时仍可手动填写已知模型名称，每行一个，支持一次添加多个。

### 自动处理与按需编辑

| 内容 | 默认处理 | 修改入口 |
| --- | --- | --- |
| 来源名称 | 使用服务域名；域名重复时生成可区分的名称 | 连接选项 / 连接设置 |
| 模型显示名称 | 沿用上游模型名称，不再要求再填一份 | 添加后的模型详情 |
| 上游模型标识 | 来自读取结果，完整保存，不自行改写 | 找不到时手动填写 |
| 协议及认证 | 使用现有兼容连接默认值；网关适配各智能体 | 连接选项，保留原生上游格式选择 |
| 聚合策略 | 主来源直连 | 聚合策略选项卡 |
| 定价 | 沿用原有定价匹配和未知价格处理 | 定价选项卡 |
| 智能体选择 | 添加后所有场景可选择，不自动覆盖正在使用的配置 | 智能体的原厂 / 自定义模式 |

不通过一个 `/models` 响应猜测上游支持哪些推理协议。高级格式选项用于上游连接；用户无需为 CC 再建一份来源。智能体页继续“先选来源，再选模型”，原厂 Default 保留。

### 失败与恢复

| 情况 | 页面行为 |
| --- | --- |
| 地址格式错误 | 在地址字段指出问题并聚焦，保留密钥 |
| 密钥无效 | 提示检查密钥；不把手动添加当作认证成功 |
| 不提供模型目录 | 保留地址、密钥，提供“重试读取”和“手动填写模型” |
| 超时 / 临时失败 | 可重试或手动填写，不进入反复自动读取循环 |
| 搜不到模型 | 保留搜索词，显示手动填写入口 |
| 保存失败 | 保留连接、全部勾选和搜索词，按钮可重试；不留下半个来源 |
| 目录修订冲突 | 重新读取后合并仍有效的选择；要求用户处理真正冲突的部分 |
| 返回修改连接 | 保留已选项；地址或认证改变后重新读取，确认仍存在的模型 |

修改已投入使用的连接是独立的“连接设置”操作；只在确实影响现有使用者时确认影响范围。新增来源和模型无需常规二次确认。取消、失败不更改现有智能体配置。

## User Stories

1. 第一次配置时，我只需提供地址和密钥，从目录里勾选所需模型，一次添加。
2. 已有一个可用来源时，我可以直接添加它的其他模型，不再输入连接信息。
3. 上游不提供目录时，我能手动输入模型名称，继续完成配置。
4. 我先把模型添加好；价格和备用策略需要时再到后面的选项卡设置。
5. CC 和 Codex 都能选这些模型；添加模型本身不会替我更换正在使用的模型。
6. 在手机上添加多个模型、搜索、返回修改或重试保存，已填内容和选择不会丢失。

## Technical Design

### 现状与必要变化

- 当前 `ModelHub.tsx` 已支持来源与模型原子保存，但添加入口仍是手填表单。改为单个添加草稿驱动“连接输入 / 模型选择 / 添加结果”状态；这是同一任务中的渐进展示，不增加多个设置页。
- 现有 `/catalog/source-models` 需要已保存的来源、目录修订及 `kind`，无法在首次保存前读取。新增独立目录发现接口，不能先保存空来源来绕过。
- 保存继续复用现有目录的一次 PUT、引用检查和密钥保留机制，价格和账本不迁移、不重建。
- 聚合策略从模型编辑内的入口移到后置选项卡，仍修改同一模型的候选与顺序，不引入额外“对外模型”实体。

### 建议模块

| 模块 | 职责 |
| --- | --- |
| `ModelHub.tsx` | 四个选项卡和统一入口 |
| `ModelAddition.tsx` | 单个添加流程，复用 `MobileSubPage` / 桌面面板 |
| `use-model-addition.ts` | 草稿、目录请求取消、选择、修订及一次保存 |
| `ModelDirectoryPicker.tsx` | 搜索、多选、已添加状态及手动输入 |
| `ModelAggregation.tsx` | 已有主用与备用候选的编辑，保留现有路由 ID |
| `source_models.go` / `agentproviders` | 读取保存前的来源目录，复用既有地址、认证和目录解析 |

### 目录发现契约提案

`POST /api/agent/model-gateway/catalog/discover`

- 已有来源：传 `sourceId` 和目录修订，服务端取保存的密钥；浏览器不接收密钥。
- 新来源：传草稿 `baseUrl`、`apiKey`、可选 `protocol` / `authMode`。鉴权沿用节点管理接口，不要求传智能体 `kind`。
- 返回合法、去重后的原始模型名称及读取状态；不写来源、模型、原生 CLI 或账本，不生成推理调用费用。
- 复用既有 URL 校验、超时、响应大小限制与错误码；凭据不出现在 URL、日志和错误中，不跟随跨来源重定向转发密钥。
- 地址 / 凭据变化时取消旧请求，旧结果不能覆盖新草稿。共享进行中的请求，只在用户读取、重试或连接改变时发起；不新增轮询。

保存前按“来源 ID + 上游模型名称”检查已有绑定，避免重复添加。已有多个高级路由引用同一上游时保留它们的身份及策略，不自动合并删除。名称、目录返回值均作为不可信文本渲染。

草稿密钥只留组件内存，不写 localStorage、URL 或原型演示记录。目录读取成功和最终保存成功分别展示；不会把前者当成配置已生效。

### 验收目标

- 首次添加：默认两个输入，无必填来源名或第二份模型显示名；一次读取、一次添加，无常规确认框。
- 已有来源：默认零个连接输入；勾选后一次添加。跨来源添加不丢失原有来源、模型或策略。
- 默认未选择模型时不能提交；已添加项不可重复添加，搜索不清空勾选。
- 手动输入支持多行、去空、去重、长度限制；认证错误清晰且不伪装成功。
- 保存为原子操作；失败、冲突和返回修改均保留草稿。
- 原有定价、限额、账本及所有备用候选保留；智能体选择的真实配置不被添加流程覆盖。
- 手机仅一层返回栏、一个内容滚动区，底部主动作避让键盘；模型行及动作命中区至少 44px。

交互稿的验证记录见 [原型验收](add-model-review.md)。正式实现仍需完整前后端检查及真实云上游的配置验收。
