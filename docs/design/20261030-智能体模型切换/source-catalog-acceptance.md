# 配置源与批量模型目录

2026-11-01。沿用 [简化添加模型](add-model-design.md) 的连接与目录流程；本次聚焦配置源、读取完整目录和批量添加，不调整用量、定价或智能体模式。

## Product Design

- 模型页按来源分组，入口使用“添加模型源”“配置源”“添加更多模型”。配置源直接展开连接参数，添加更多模型复用已有连接摘要。
- 新来源默认只填地址与密钥；来源名、协议、认证方式放在连接选项。名称留空时采用域名。
- “拉取所有模型”读取完整上游目录，不执行推理，也不提前保存空来源。读取后显示来源摘要、搜索、多选和选择全部；搜索时全选只作用于匹配结果，其他选择保留。
- 已添加的模型显示状态且不可重复选。手动输入支持每行一个模型、去空、去重，与目录选择合并提交。
- 底部固定显示新增数量及提交按钮。新增来源与模型一次保存，不再常规二次确认。修改已有连接仍确认后续调用影响。
- 手机使用 URL 管理的一层返回栏、一个内容滚动区、常驻底部动作和底部导航；没有嵌套目录滚动区。
- 拉取失败保留地址、密钥和选择，提供重新读取与手动输入。保存失败保留选择。另一页面修改来源时，阻止覆盖并允许载入最新连接后重新读取。

## User Stories

1. 我填地址与密钥后，能看到此源返回的所有模型，一次选择并添加。
2. 我可先搜索再选一组，搜索其他模型时，之前的选择仍然保留。
3. 已有来源添加其他模型无需重填密钥，已有模型的显示名和全部备用候选保留。
4. 目录不可用时，我可手动输入多个模型，失败重试不用重新录入。
5. 我在手机上能滚动长目录并随时提交，返回和再次进入时草稿仍在。

## Technical Design

| 模块 | 职责 |
| --- | --- |
| `ModelHub.tsx` | 来源分组、路由与按来源保存的内存草稿、沿用原定价及用量 |
| `ModelSourceEditor.tsx` | 连接参数、请求取消、搜索多选、手动批量输入、原子提交及冲突恢复 |
| `source_models.go` | `POST /catalog/discover` 接受草稿来源与目录修订，复用保存来源的密钥规则，只读返回目录 |
| `catalog.go` | 提取统一来源校验，保存与目录发现共用；最多保存 1,000 个模型，与目录读取容量一致 |
| `agentproviders/model-options.go` | 共用原认证、12 秒超时、响应大小限制、去重排序及游标分页；解除最多 10 页导致目录不完整的问题，保留总量、循环游标和页数边界 |
| `backend/server/agent-runtime.go` | 将新接口注册在已有登录保护的管理接口下 |

目录请求修改地址、密钥、协议、认证方式或离开页面时取消，旧响应无法覆盖新草稿。已保存密钥只在原地址复用；地址改变必须重新提供密钥。来源参数与密钥不写入 URL 或 localStorage，返回内容无凭据，不跟随重定向。

保存使用现有一次目录 PUT 和修订检查；新模型按“来源 ID + 上游模型 ID”去重，已有模型对象及所有备用候选保留。修改来源协议时同步所属模型的协议字段。智能体配置、价格、账本不由此流程改写。
