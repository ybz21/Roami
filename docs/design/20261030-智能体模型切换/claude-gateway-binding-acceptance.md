# Claude 本机网关接入修正

2026-11-02。对应本机 Claude 仍直连上游、Roami 无法记录用量的问题。

## 产品与用户故事

已保存、已应用的本机直连预设不代表已连接 Roami 网关。用户打开智能体模型页时，仍能应用当前选中的来源与模型，将本机 CLI 接入网关；确认成功后才显示“已应用”。直连状态增加一句提示，不显示下游密钥。

## 技术修正

`GatewayModelBinding.tsx` 先核对原生预设地址是否为目录返回的网关地址，再按目录别名识别当前网关模型和“已应用”状态。旧原生预设的来源匹配同时核对上游协议、地址与模型，防止同一服务的 Messages 和 Chat Completions 连接被误认为同一原生配置。选择来源时仍可使用任何由网关支持的上游协议，不限制智能体跨协议适配。

地址比较保留原有尾部斜杠与 `/v1` 归一化；现有修订检查、确认框、备份及原子应用流程不变。原厂模式继续可用。

## 本机真实调用

- 初始本机 Claude 指向第三方上游地址，Claude 账本无调用。
- 通过已有配置 API 备份并接入回环网关；保留原模型 `deepseek-4.1-flash`。没有修改 RSI 的路由、参数、能力或配额。
- 同一服务的原生 Messages 接口在 `message_start` 和 `message_delta` 中均返回全零用量，不能据此得到实际 Token。
- 最终使用节点已保存的 Chat Completions 来源及相同模型，由 Roami 适配 Claude Messages。没有设置测试用的模型、Base URL 或凭据环境覆盖。
- 用已安装的 Claude Code 2.1.316 从空目录运行一次无工具、无会话持久化的最小请求，返回 `OK`。
- Claude 输出：普通输入 297、缓存读取 1,280、输出 2。
- Go 账本：输入总量 1,577（包含缓存读取 1,280）、输出 2，智能体 `claude`，HTTP 200、结算状态 `known`，无 pending。账本记录 ID：`6b5ac1f0-3076-47ae-95e5-bb8eb76068ee`。
- 金额按节点保存的定价计算，为 CNY 0.000280500；这不是服务商对账凭证。此前直连的消耗无法由本次接入追溯补记。
- 已运行的 CLI 不自动重启；新启动的 Claude 已验证使用网关。

真实测试和 UI 测试分别通过 `scripts/dev/isolated-roami.sh` 运行。真实测试只读取本机 Claude 已保存配置并产生少量推理用量；界面测试使用隔离原生配置和假来源，不操作用户会话。
