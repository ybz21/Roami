## Product Design

能力中心并列“大模型”和“智能体”，各自保留一个管理入口。

| 大模型页签 | 用途 |
| --- | --- |
| 模型（默认） | 添加、编辑和删除所有场景共用的模型 |
| 模型源 | 统一维护连接地址、协议与凭据，供多个模型复用 |
| 用量与限额 | 原有账本、用量统计、币种、每日金额限额、时区与费用核对 |
| 模型定价 | 原有默认单价、逐模型及前缀价格、输入/输出/缓存命中价格 |

添加模型只需选择来源、填写服务商的模型 ID，显示名称选填，留空使用模型 ID。保存后即可在智能体选择，不再建立另一层“对外模型”或执行发布操作。列表展示名称、模型 ID、来源和协议，不展示内部路由标识或发布状态。

固定来源为默认策略，主备切换放进模型详情的折叠“聚合策略”，避免普通添加模型流程承担路由配置成本。模型修改后影响后续请求；已有使用方时保存前确认影响范围。

“智能体”继续统一管理安装、登录、启动、模型选择和恢复；模型详情也直接提供安装/升级动作和已安装版本。Roami 的主智能体与后台智能体分别选模；Codex、Claude Code、OpenCode、Pi 从同一份列表选择各自协议兼容的模型。添加模型让其可用，不会替用户更改已有场景的选择，也不重启已有任务。

## User Stories

1. 管理者配置一次模型源后，可添加多个模型，无需重复复制上游凭据。
2. 添加模型并保存后，立即去智能体详情即可选到；没有“创建后还要发布”的中间状态。
3. 不设置显示名称也可保存，模型列表和智能体下拉显示模型 ID。
4. 常用模型更换同协议上游时，原有智能体选择和内部标识保持稳定，后续请求使用新配置。
5. 原定价、限额和账本完整保留；设置旧链接转到唯一模型页面。
6. 手机添加模型使用单返回栏的全屏二级页，保存后回模型列表，再切到智能体选择。

## Technical Design

复用既有 Go 网关目录、凭据隔离、计价和原生工具配置适配器，不新增第二份模型存储。`ModelHub` 直接保存到目录的 `models`，所有消费者读取相同列表；不再写入草稿。历史草稿字段仅为存储兼容保留，不自动启用，避免意外改变使用中的路由。

内部模型路由 ID 自动生成并在编辑时保留，服务商模型 ID 单独保存用于真实转发和计价。产品表单、列表、工具当前配置摘要隐藏内部 ID。来源声明协议，模型协议从主来源自动确定，消费者只显示兼容项；编辑已配置模型保持协议稳定。

前端模块：

- `ModelHub.tsx`：默认模型列表、直接保存、来源配置、可折叠聚合策略，复用原定价与费用表单。
- `GatewayModelBinding.tsx`：外部 CLI 读取共享模型列表；当前默认模型摘要显示名称。
- `RoamiAgentModels.tsx`：主智能体和后台智能体读取同一列表中兼容 Chat Completions 的模型。
- `route-hash.ts` / `model-settings-route.ts`：旧设置入口默认到模型列表，用量、定价、节点上下文继续保留。
- `internal/modelgateway`：沿用现有目录、回环推理、配置备份/恢复和单次计价；统一模型列表修订不修改 Python；后续原厂模式及来源选模由 Go 接口实现。

实现的协议、换源条件和限制见 [implementation.md](implementation.md)。旧 HTML 原型与上一版录屏仍展示发布流程，仅用于历史对照，不代表当前产品。

## 智能体配置模式修订

智能体页提供完整的“安装与启动、模型配置”流程。自动识别当前节点已有的 CC；未安装的工具提供安装，已安装显示版本和升级。打开终端沿用既有启动流程，原厂账户需要登录时在工具中完成。

模型配置有两个一等选项：

| 模式 | 用户操作 | 生效行为 |
| --- | --- | --- |
| 原厂模式（Default） | 选择原厂，确认应用 | 使用工具自身登录和默认模型，移除接管的自定义连接；不恢复旧的第三方连接 |
| 自定义模式 | 先选上一步保存的模型源，再选该源下的模型，确认应用 | 复用该源地址和凭据，不再填写 URL 或 Key |

模型源配置完成就能进入智能体选模，无需事先逐个登记模型。选源后由服务端使用已保存的凭据读取模型目录，与该源已添加的模型合并；不支持模型目录或目录不可用时，可以搜索并输入确切的模型 ID。只有确认应用才将新选择加入统一模型列表并配置智能体，查看目录不写入配置。

选择模式、来源和模型仅编辑草案，应用后才改变真实配置。“当前使用”始终表示已应用状态。新工具以原厂模式开始，已有自定义配置如实保留，不自动重置。换源后模型选择失效，必须重新选；列表按工具所需协议过滤，不假装提供跨协议转换。

旧的逐工具连接预设和“恢复原配置”收进高级区域，避免与原厂模式混淆。恢复仍可回到之前的第三方连接，原厂模式则交回工具默认行为。模式切换保留账户登录、插件、hooks、MCP、权限、历史和其它非模型字段。

参考 [CC Switch 的切换流程](https://github.com/farion1231/cc-switch/blob/main/docs/user-manual/en/2-providers/2.2-switch.md) 和 [配置提供商](https://github.com/farion1231/cc-switch/blob/main/docs/user-manual/en/2-providers/2.1-add.md)，采用“先预览、明确应用、显示实际使用状态”的交互，没有复制其完整路由/聚合功能。[本轮验收](modes-acceptance.md) 记录真实接口和手机操作。

### 模块与 API

- `GatewayModelBinding.tsx`：原厂/自定义切换，来源与模型联动，安装门槛和已应用状态。
- `AgentModels.tsx`：主流程仅保留新模式表单，原预设/备份恢复按需展开。
- `AgentCatalog.tsx`：模型页可安装、升级和打开智能体，保留其它生命周期入口。
- `POST /api/agent/professional/:kind/models/default`：新增真正的原厂切换；`models/restore` 继续恢复旧配置。
- `agentproviders.UseOfficial`：使用现有备份、修订校验、原子写入与回读；显式持久化模式，重开页面仍准确显示。
- `catalog/source-models`：服务端读取来源目录，校验来源、协议和修订，不向浏览器下发凭据；过期响应不能覆盖新来源选择。
- `catalog/apply`：验证来源、模型与目录修订；既有模型复用路由，新选模型在确认应用时生成内部路由并加入统一列表。
- 目录的“正在使用”只统计已应用使用方；停用的连接预设仍保留引用保护，不会因切回原厂而被悄悄删除。

Claude Code 原厂模式保留 `ROAMI_MODEL_MANAGED=1` 控制标记，避免本机已有第三方同步服务在切换后立即写回自定义源；登录资料独立保存。Codex 原厂使用 OpenAI 内置提供商并移除所接管的路由覆盖，保留登录文件。OpenCode / Pi 交回工具默认选择，不删除它们保存的其它提供商定义和登录。
