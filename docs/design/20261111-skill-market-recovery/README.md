# 技能市场失败恢复

## 产品设计

市场暂时加载失败时说明网络、当前节点智能体服务或市场来源的已知错误，保留一处「重试」。错误码与 HTTP 状态放在可展开的错误详情中，不展示原始服务消息。

重试恢复失败的操作，包括首次榜单、榜单切换、搜索分页和技能详情；保留已有结果、输入草稿及成功榜单。搜索结果的返回箭头位于标题左侧。

详情请求在一次加载中复用 HTTP 连接，效果图并行读取；同一详情十分钟内复用已获取的固定版本内容。榜单仍使用一分钟缓存；来源设置变更立即清除缓存。

详情页立即显示名称、来源与安装位置。正文、文件和图片独立更新，各模块使用自己的加载占位；用户可以先读正文、切换文件页或选择安装位置。安装回执仅在完整包准备好后返回，按钮随后启用。加载中可以返回；后续模块失败保留已读内容和安装选择，在详情内重试。

## 用户故事

- 首次榜单失败后，即使已经输入下一次搜索草稿，重试仍加载原来的榜单。
- 详情加载失败后重试打开原技能，返回时焦点恢复到原来的入口。
- 下一页失败后重试续接原搜索的分页，不清空已有结果。
- 可以区分当前节点不可达、节点智能体服务不可用和上游市场错误，并展开错误码辅助排查。

## 技术设计

`CapabilityMarket.tsx` 将错误信息和失败操作快照保存在同一状态中。快照明确区分来源发现、带来源/查询/游标/榜单的列表请求和带来源/条目的详情请求。重试按照快照分派，不读取尚未提交的输入。新请求、来源切换或成功响应清除旧错误；取消的旧请求不能发布错误或覆盖结果。不自动重试安装写入，不增加轮询。

`market-error.ts` 优先读取 API 的结构化 `error.code`，兼容旧的错误码消息，为网络失败和未知错误提供页面相关提示。诊断仅接受受限格式的错误码与有效 HTTP 错误状态，不直接展示服务消息。两份语言包同时提供新文案。

`market_catalogs.connection()` 使用操作作用域的 HTTPX 连接池，经 ContextVar 供并行文件读取复用。每次市场操作结束或取消都会关闭连接；授权头仅属于指定请求，不放入客户端默认头。文件下载失败时先取消并等待同组剩余任务，再走固定提交归档回退，防止遗留下载占用连接。

`CapabilityMarkets._request` 保留现有并发合并与全局数量限制，详情缓存从 60 秒延长到 600 秒；新打开详情仍签发独立安装回执，安装内容继续绑定已审阅的版本。最新上游版本可能在十分钟后重新获取，用户读取与安装始终使用同一固定快照。

`skill_preview_images.py` 并行读取最多三张效果图，共用原有六秒期限、单图 384KB / 合计 768KB 上限和来源校验；超时保留已完成图片，取消并等待未完成请求。原文件、引用及安装内容完整保留。

浏览器向既有 `POST /capability-markets/preview` 请求 `application/x-ndjson`。`market_preview_stream.py` 依次发送可用的 document、files、images 模块与最终 ready 回执；没有该 Accept 的调用继续返回原 JSON。`CapabilityMarkets` 为同一共享请求分发进度并回放已完成模块，断开一个读取者不会取消其他读取者；进度和监听器随任务结束回收，不增加轮询。图片从正文到达后即并行加载。

前端 `streamMarketPreview` 处理分块 UTF-8、流内错误、提前结束与旧节点 JSON 兼容。`CapabilityMarket` 先打开详情，再逐帧合并模块；返回时取消读取，忽略迟到响应。`SkillMarketDetail` 分别呈现正文、文件及图片状态，使用稳定条目 key 保留标签和安装选择。
