# 会话关闭首次点击反馈

## 产品设计

用户从侧栏菜单关闭会话时，需要一次点击就知道操作已收到。原实现先等待
`worktree-status`，检查结束后才弹确认框；检查期间没有反馈，再点会并发检查。
后端的目录快照还会遍历忽略文件，依赖较多时等待尤其明显。

点击后立即使用现有 antd message 显示「正在检查会话…」，检查结束后进入原有确认流程。
检查失败显示可重试提示。关闭会话和清理 worktree 仍需原有确认。

## 用户故事

- 第一次点击即显示等待状态，不需要再点一次才知道操作已收到。
- 等待期间重复点击同一会话，只发送一次检查、打开一个确认框。
- 检查失败后能重试，不使用缺失的 worktree 状态继续关闭。

## 技术设计

`useSessionCloser` 使用 ref 保存正在检查的会话，跨渲染去重；请求结束时在 finally 中
关闭等待消息并释放去重标记。检查失败直接返回。原生会话无需 worktree 检查，沿用即时确认。
侧栏、会话列表和手机会话列表复用此 hook。新增中英文 i18n 文案，沿用现有组件和令牌。

## 验收

- 15 项定向测试通过，包括真实 Dropdown 首次菜单点击、慢检查去重、失败重试、未提交
  worktree 选择以及原生会话；全量前端 1,630 项测试通过。
- typecheck、i18n、hover、生产构建以及 `scripts/dev/quality/check.sh quick` / `full` 通过。
- 独立实例 `/tmp/roami-close-first-click` 只操作临时会话。浏览器人为延迟检查 3 秒：
  修复前首次点击后无消息、无确认框；修复后立即出现检查状态，响应后仅出现一个确认框。
- 浏览器验收使用 Redmi Note 8 的 Chrome 调试连接。桌面尺寸通过设备指标模拟；
  本机 Chrome 启动后导航超时，手机 CLI 返回 `CHROME_BROWSER_IDENTITY_UNAVAILABLE`，
  因此改用同一设备的原生 CDP 连接。没有将模拟尺寸称为桌面真机验收。
- 1280、1920、2560、3440 CSS px 的文档宽度和内容高度断言通过。手机真实 ADB
  DOWN/UP 长按打开菜单，单次点按关闭后显示检查消息，随后只有一个确认框；关闭动作
  命中测试通过，按钮高度 48 CSS px。确认关闭后临时会话已从列表移除。
  顶栏、底栏可见，没有横向溢出。
- 真机截图：`/tmp/roami-close-after-phone.png`；质量、测试、构建日志分别位于
