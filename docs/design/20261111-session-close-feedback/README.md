# 会话关闭首次点击反馈

## 产品设计

用户从侧栏菜单关闭会话时，需要一次点击就知道操作已收到。原实现先等待
`worktree-status`，检查结束后才弹确认框；检查期间没有反馈，再点会并发检查。
后端的目录快照还会遍历忽略文件，依赖较多时等待尤其明显。

点击后立即打开居中的 antd Modal，显示目标会话和「正在检查会话…」，检查期间禁用
「关闭」，保留「取消」。检查结束后进入原有确认流程；失败显示可重试提示。

## 用户故事

- 第一次点击即显示等待状态，不需要再点一次才知道操作已收到。
- 等待期间重复点击同一会话，只发送一次检查、打开一个确认框。
- 检查失败后能重试，不使用缺失的 worktree 状态继续关闭。

## 技术设计

`useSessionCloser` 使用 ref 保存正在检查的 AbortController，跨渲染去重；请求结束时在
finally 中关闭检查对话框并释放标记。取消或卸载会中止请求，忽略晚到的结果，旧请求
不能清除新检查的状态。检查失败直接返回。原生会话无需 worktree 检查，沿用即时确认。
侧栏、会话列表和手机会话列表复用此 hook。新增中英文 i18n 文案，沿用现有组件和令牌。

## 居中检查对话框

用户反馈顶部转圈不够醒目，因此将等待状态移到居中的检查对话框，标题仅显示会话
展示名，避免手机上的长 ID 挤压关闭图标。复用现有 i18n 文案和组件，不增加设计令牌。

- 前端全量 1,633 项测试通过；18 项定向测试覆盖等待期间禁用关闭、取消中止请求、
  取消后晚到响应、重新检查、卸载及原有会话分流。
- full 门禁通过，包括 typecheck、i18n、hover 和生产构建；仅涉及前端与文档，跳过
  无关的 Go 和 Python 检查。
- 桌面使用独立 headless shell 和 `roami chrome`，手机使用 LAN HTTPS、真实 ADB 长按
  和单次点按，检查期间只发起一次预检。测试延迟检查响应 6 秒便于观察等待状态。
- 真机点按「取消」后观察 6.5 秒，请求的 signal 已中止，未出现晚到的确认框。
  1280 / 1920 / 2560 / 3440 CSS px 分别检查工作台开、关两种状态，工作区高度
  1,015 CSS px，无文档溢出或越界。
- 截图和日志在 `/tmp/roami-visible-close-*`，截图通过 PR 的 `pr-shots` 分支附到正文。
  隔离实例未配置 Agent 运行依赖，因此背景出现 Agent 不可用提示；临时 tmux 会话
  及其关闭预检使用实际服务接口。
