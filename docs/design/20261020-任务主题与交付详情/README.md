# 任务主题与交付详情

关联：#381 / #382。先完成 #380 / #384 的合入部署，再实施本设计。

- 主题独立于完整目标：delegate 可提供短 title，随任务意图持久化；不增加模型请求，不强制旧客户端补新字段。续作保留主题。历史记录从完整目标提取文档名、动作与首个主要事项，去掉路径和续作背景，完整要求保持可查看。
- 列表：只显示主题、真实状态、执行器和必要时间；不再显示原始指令片段。
- 详情顺序：主题与真实状态 → 简短结果 → 交付物与可直接打开的链接 → 当前必要动作；完整要求、追加历史、执行报告及日志按需展开。无资源、无文件的空段不占主内容。
- 文件仍来自持久化产物；PR 等链接来自执行报告，展示链接不声称已合入或独立核验。失败或未核验任务不能因报告自称成功而变绿；原始报告保留在记录中。
- 手机保持独立二级页、单返回栏和一个内容滚动区；桌面保持工作台，不引入新浮层导航。

自查：新字段可选且参与幂等校验；不改任务目标、不丢历史；不额外请求模型影响首响。结果层不重写原始报告，验证失败先显示失败原因；只在明确交付链接上提供入口，普通来源不冒充成果。保留暂停/恢复/取消/验收/续作安全条件、错误恢复与已输入内容。

验证：长目标、PPT、续作、历史记录与损坏意图回退；文件/PR/纯文本/失败/执行中/等待验收；中英文、粗指针、窄屏和真实 Android 点击/返回/滚动；运行要求的完整门禁和前端检查，PR 附桌面与手机改前改后截图。

续作取证：#383 的现场复跑出现执行器直接复述历史材料，当前轮没有浏览器调用，验收正确拒绝。Worker 指令和 web-research 明确要求每次执行及续作重新读取来源，逐字保留观察 URL（含查询参数及重定向后的地址）；不改证据匹配或失败状态。
