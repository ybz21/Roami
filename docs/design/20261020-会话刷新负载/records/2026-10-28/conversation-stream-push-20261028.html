首页对话提交即推送 · 2026-10-28

Product Design

首页回答的文本事件提交后立即通过原 SSE 与 Go 网关发送，不再每 200 毫秒查库批量转发。保留现有消息格式、持久化、断线游标与登录边界；不增加页面控件或前端轮询。

User Stories

  • 回答还在生成时即可看到已提交的文本片段。
  • 连接空闲时只有保活帧，不为等待文字反复查询数据库；重连继续读取已提交记录。

Technical Design

storage/conversation_events.py 管理活跃连接的按会话订阅。database.py 在 writer 事务中收集 event() 涉及的会话，COMMIT 成功后在事件循环中唤醒订阅者；回滚不发布，调用方取消也不丢弃已提交通知。通知只唤醒读取，SQLite 仍是事件及游标的唯一事实来源。http.py 在读取前订阅、清除信号，读完后等待提交通知；避免读取与等待之间丢唤醒。10 秒保活不查库，断开连接释放订阅。Go 复用现有 FlushInterval=-1。

验收记录

截图对应的原回答已记录 10 次 message.delta，生成时间约为 1.29～2.35 秒；该记录证明原先有分段落盘，不能将其描述为生成结束才存储。定向测试覆盖提交前不可见、回滚、跨会话隔离、多订阅、取消后提交、读取期间提交、保活不查库、实时文本、重连回放与断开清理。Go 的 Gin／Unix socket 回归要求两段文本均在上游结束前到达。

隔离本地 HTTP SSE 夹具经过实际 ChatCompletions、计费代理、Agent、Unix socket、Go agentproxy 与 Gin；三段文本均在模型结束前收到。这组对照中单段传输耗时由约 78～129 毫秒降至约 5～23 毫秒，不代表生产网络或首 Token 延迟。证据位于 /tmp/chat-streaming-20261028；零付费模型调用，未更新现用服务，无前端组件或文案改动。

quick 门禁通过：Go 全量、Python 静态／格式检查及 1,679 项测试、前端 typecheck／i18n／hover、秘密扫描与文件策略。最终读取竞争与保活修订另跑 8 项定向测试及静态／格式检查通过。新实时回归在原接口上因空闲查库计数增长按预期失败；隔离验证服务与私有 tmux 实例均已清理。报告入口 /tmp/chat-streaming-20261028/index.html。

普通答复默认流式修订 · 2026-10-28

Product Design 与 User Stories

普通答复、解释、PR 结果和后台任务的实际结论直接使用 assistant 正文，随生成显示。reply 保留给需求完整性清单、语言覆盖和原始字段等需要显式元数据的答复；task_reply 保留给任务状态和文件回执。用户能在生成结束前看到正文，特殊回执仍完整校验后交付；不把完整答案拆成假流式。

Technical Design

修改 server/configuration.py、tools/main_catalog.py 和 context/prompt_builder.py，移除所有最终答案必须调用 reply 的相互强化指令。既有普通文本通道继续经过 answer_contract、request_coverage、TurnJournal 与 SSE，不新增模型请求、解析器、事件类型或前端逻辑。reply 参数须等工具调用完成才能校验，因此将其限定为需要结构化交付的场景，不让普通正文默认进入此通道。

验收记录

现用实例只读取证确认，一次 reply 工具答复只有一笔 message.delta，在轮次结束前约 6 毫秒提交；同实例的普通文本也有多笔分段事件，不能泛称所有 SSE 请求都被缓冲。当前配置 deepseek-4.1-flash 的隔离验证中，原指令样本收到 8 段；最终精简指令收到 11 段、69 个模型文本片段，首段约 1301 毫秒、结束约 2768 毫秒，10 段在模型结束前到达。本轮共 3 次成功模型调用。这证明真实模型到 HTTP SSE 的分段路径，并不证明原指令每次必选工具或性能普遍提升。真实浏览器在隔离 Go 网关与延迟上游中确认第一、第二段显示时第三段尚未到达，生成状态仍在，最终完整保留三段。45 项相关回归通过，包括原上下文预算断言；未放宽预算约束。未改写现用对话和配置；本次有真实模型调用，不宣称零费用。证据入口 /tmp/reply-stream-20261028/index.html。
