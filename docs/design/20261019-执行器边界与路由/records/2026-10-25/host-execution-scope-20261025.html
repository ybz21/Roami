通用本机执行作用域 · 2026-10-25

产品设计

修订 PR #452 的处理边界：目录是代码任务的上下文，不是所有本机操作的前提。与项目文件无关且已获用户授权的本机操作由 Main 显式调用 bash scope=host，不创建项目、不借用目录、不误派浏览器 Research。不按进程、磁盘、网络或服务名称增加专用路由。原 host_processes 保留为可选结构化只读接口，不再是提示与恢复的必经入口。

用户故事

  • 用户查询本机状态或要求执行与项目无关的命令时，没有项目也能取得真实命令结果。
  • 用户继续代码任务时，保留原任务、目录和执行器；本机作用域不改变已有工作区绑定。
  • 用户停止命令后，子进程被回收；大输出保留所有者隔离的完整记录。

技术设计

Main → bash {argv 或 command, scope:"host"} → ToolDirectory / Tools.validate
→ shell（Main 且无 taskId / workspace / cwd）→ 临时当前目录 → 既有 process.execute
→ 凭证过滤、进程组取消、完整输出外置 → tool_calls（scope、write、真实状态）
Worker → bash scope:"workspace"（默认）→ 原目录绑定与根目录检查
Research → 原浏览器导航／观察协议

host 是执行作用域，不是只读权限或文件系统沙箱；通用命令一律保守记录 write，不根据命令名推断安全。用户授权仍由原会话与指令约束，不能从网页、记忆或工具结果取得新授权。临时当前目录只避免继承服务代码／数据目录，不限制绝对路径；需保留的文件产物继续使用真实工作区。Main 指令、工具描述、resourceOnly 说明和错误恢复统一描述作用域；移除本机诊断关键词路由。已注册 Roami 命令继续走原参数、角色和回执协议，不能同时指定 host。Worker／Research 不获得 host，运行时再校验 taskId 和 workspace，默认行为保持原工作区约束。
