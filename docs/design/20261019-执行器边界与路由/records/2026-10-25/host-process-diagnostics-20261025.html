本机进程诊断路由修复 · 2026-10-25

产品设计

本机进程、CPU、内存与负载查询由 Main 直接调用受管只读快照，不要求用户提供目录、不新建项目或后台任务。resourceOnly 仍只允许浏览器导航与观察，不将“只读”误解为通用本机执行权限。快照只展示进程名称及资源指标，不返回命令参数和环境变量，不提供终止进程或修改系统的操作。

用户故事

用户询问“帮我看下当前机器的进程占用情况”时，能在原对话收到真实节点数据。没有代码工作区或其他任务占用工作区时仍可查询；采集失败明确报告不可用，不通过换目录、重复委派或网络检索修复。进程 CPU 百分比解释为 ps 生命周期平均值，单次快照不作为持续异常证据。

技术设计

Main / Worker → bash argv: roami agent host processes --input {"limit":10}
→ commands.json / ToolDirectory → host_processes（effect=read）
→ 固定 ps argv + Linux /proc/meminfo + os.getloadavg
→ CPU / RSS 排序、采集时间、指标口径和不可用字段 → 原对话 reply

host_processes.py 独立负责采集和解析，worker_catalog 注册并允许 Main 调用；沿用工具上下文、所有者校验、禁用策略与执行回执。ps 使用最小环境、固定参数和 5 秒超时，不接收 cwd、任意 argv 或 shell 字符串；进程输出只读 comm。Linux 提供整体内存与 swap，其他环境无法读取的指标保持 null。工具发现增加本机语义词，主指令、bash 描述、resourceOnly 字段说明和 WORKSPACE_REQUIRED 恢复提示指向相同入口。Go 命令映射继续从同一 JSON 内嵌读取，不新增公开无认证接口或轮询。

问题证据：原请求先在 Main 因 WORKSPACE_REQUIRED 拒绝 ps，随后被委派到 resourceOnly 并以 TOOL_UNAVAILABLE 失败；换普通目录重试又撞到已跟踪任务的工作区。修复保持浏览器隔离与代码工作区锁，仅补齐本机只读诊断入口。
