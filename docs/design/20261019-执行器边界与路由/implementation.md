# v3 实施与验证记录

2026-10-19。代码已在当前工作区实现，按 PR 流程交付，尚未部署。本文记录实现状态；`cases.json` 的 48 条仍是设计验收预期，不能当作 48 条端到端已通过。

## 已接入的执行链

- Main 在原有模型轮次中提交 `delegate.routing`，给出有界 / 复杂、开放的复杂度依据和用户语言的具体原因。新模型目录要求该字段，旧调用验证保持兼容；不新增分类模型请求或任务类型白名单。
- `dispatch/routing.py` 复核原始用户来源、当前轮次、显式指定、记忆版本 / 作用域、真实目标身份和可用执行器。新有界任务默认 native；复杂任务按明确项目默认、有效偏好、节点专业默认等选择真实已安装且有追踪适配的专业执行器。复杂任务不静默降级。显式执行器约束冲突返回稳定错误，Main 使用现有选择题入口处理。
- 决定先写入 `routing.decided`，再进入任务或投递副作用。同一调用重复使用冻结决定，参数冲突拒绝；未知写结果保留原恢复方式，不换执行器重跑。
- Go CLI 新增 `roami agent execution catalog [--commands python3,...]`，只观察安装和命令存在性，不启动提供商，不把安装当成登录、额度或专门产物能力。目标解析返回会话注册的真实执行器；项目目录返回默认专业智能体。
- 专业任务沿用 Roami CLI 的准备、启动、回报和状态机。简报只带当前目标、可公开路由信息及本次实际获准附件；附件验证所有者、遗忘状态、大小和 SHA256，原名 / MIME 随引用传递，不向专业执行器复制整段主对话或凭据。非编码任务使用普通目录，不强制 Git 项目。
- `task_steer` 以实际 revision 续派，保留执行器，并复核新指令来源。native Fork 仍仅用于原生检查点，专业会话不伪装支持 KV cache Fork 或自动迁移。
- 路由原因进入既有 SSE 过程消息和历史投影，收起时可见，展开查看依据、策略版本及能力未独立验证提示。无路由字段的历史消息保持原展示。
- Main 仍使用七个核心工具；执行器发现与续派通过已有 CLI capability 通道使用，不扩张默认模型工具列表。

节点可在 `agent.toml` 的 `[runtime]` 设置 `professional_executor`、`task_timeout_seconds` 和 `task_max_turns`。预算默认仍为 600 秒 / 16 轮；这是执行预算，不参与复杂度判定，复杂任务应按实际工作另行配置。

## 尚未验收 / 保留边界

- 48 条设计场景未逐条跑真实模型端到端；真实主模型鉴权失败仍需可用连接才能补测。
- PPT、视频、复杂研究等是开放工作举例，本轮 CSV 链路不代表已验收这些专门产物；执行器仍须发现真实 Skill / CLI / 软件并验证输出。
- OpenCode / Pi 可被目录发现，但没有完成追踪适配前不自动派受管任务；登录、额度未知仍显示未知。
- 不新增跨执行器自动迁移、独立产物验收器或跨设备服务端草稿队列。
