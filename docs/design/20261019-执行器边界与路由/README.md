## 核心决策

1. Main 接收与快速答复；native 承接简单、有界的工具工作；Codex / Claude Code 等专业智能体默认承接复杂任务，如复杂调研、原型、PPT、剪辑等；这些是开放举例，不是任务白名单或按领域强制分流。使用什么模型与选择什么执行器是两个概念。
2. 先解析用户指定和已有任务身份，再检查目标、能力和权限；配置偏好只在适配候选内排序。项目默认专业智能体只对明确绑定该项目、且需要专业执行器的新任务生效；简单查询不因项目偏好而升级。
3. 已有会话投递、新受管任务、已有受管任务续接分开处理；`delivered`、执行器报告和独立验收分开显示。
4. 外部事实、网页或记忆不能更换执行器、扩张权限；未知写结果不换执行器重跑。目标歧义或明确指定无法满足时用选择题。
5. 分阶段交付使用有来源的结果引用；native Fork 不等于复制专业智能体会话、模型 KV cache 或账号凭据。

与此前设计的关系：[Agent 框架总览](../20261017-agent框架设计/technical/index.html)、[专业智能体管理](../20261017-agent框架设计/technical/14-professional-agents.html)、[原会话派活回报](../20261019-派活回报/README.md)。

本轮同步路由协议、专业智能体管理入口与审查记录，验收预期由 30 条扩展为 42 条，仍未执行路由任务。专业执行器必须实际具备相应 Skill、CLI、软件和素材访问能力；委派成功不能代替产物验证。非代码任务允许使用已有普通工作目录，不强制新建 Git 项目或 worktree。
