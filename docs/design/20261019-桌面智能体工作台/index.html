本期实现与后续入口

本期先实现「任务 / 记忆」两个桌面入口。右侧首次默认展开，可手动收起，刷新后记住用户状态。第一项统一叫「任务」，直接对应 Roami 的后台任务。原来的「动态」与「任务」合并：列表看一件事的进度与结果，详情看这件事怎么执行。工具调用不再逐条占据一级列表。

入口内容边界
任务需要关注、执行中、近期结束；名称、进度、结果摘要、执行器和时间一条记录对应一个实际后台任务。展开后查看工具、命令、子 Agent 与产物。
审批（规划）真正等待用户允许或拒绝的动作审批绑定协议尚待确认；不与任务待验收混淆，不给常规已授权派活增加确认。
定时（后续入口）提醒、定时任务及下次执行时间本期继续从原通知入口访问；条件监控仍待设计确认。
记忆已保存的偏好、知识与来源Roami 保留统一记忆入口；参考产品第四项是身份 / 个性化，不宣称完全相同。

Muse 列表复刻：本轮只做展示列表

任务与记忆采用同一列表骨架：浅底圆角图标、标题、简短摘要、时间；按日期分组，去掉独立卡片框。筛选按需展开，原操作能力保留。用户明确要求先不做头像，本轮未接入头像素材。以下为简化交互示意，实际渲染以本轮截图与 validation.json 为准。

设计约束与 review

1. 待确认、失败、取消、未知分别展示；派发成功不等于任务完成。截图中“尚未提交”的动作也必须保留真实业务状态。

2. 工具原始输入输出按需读取，默认以简短动作摘要呈现；不为侧栏新增一套模型工具或执行协议。

3. 统一记忆清单和本轮召回证据是两种视图。连接状态只描述当前消息流，不承诺模型、账号或工具全部可用。

4. 任务入口限定当前对话的真实后台任务，工具步骤只有实际关联到任务时才归入详情；普通快问快答和未归属任务的执行过程保留在主对话。全局搜索需明确查询覆盖，不能从最近 200 条推断全量。

5. 界面沿用 Roami 的色彩、SVG 图标、字号和间距规范。大头像与装饰动画排在任务可见性之后。

6. 已授权的常规 Roami CLI 派活沿用原机制，不增加重复确认；真正需要用户决定的动作才使用确认卡。暂不新增 Gmail / Calendar 登录，不扩大授权。新账号、审批绑定、条件监控与跨设备队列进入待确认清单。
