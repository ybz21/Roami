# 任务 / 消息 / 记忆三标签 · 2026-10-19 22:10 修订

## 布局

| 区域 | 最新设计 |
|---|---|
| 右侧工作台 | 固定三个同级标签：任务、消息、记忆；消息放第二个，旁边显示未读数。右侧保留连接状态与收起按钮，删除独立铃铛、更多菜单、上下文和概览入口。 |
| 消息标签 | 合并消息与提醒：已发生的任务回报、主动提醒、定时提醒通知按时间平铺；尚未触发的安排在同一列表的“待提醒”分组中展示。无独立提醒 tab、无消息弹窗、无消息页嵌套设置 tab。 |
| 中间区域 | 主对话始终可用。点击消息定位对应的原对话内容，右侧继续停在消息列表；需要查看任务时再点击“查看对应任务”，切到第一个任务标签。 |
| 左侧 | 保留首页、项目、浏览器、文件、设置和项目会话树，不新增消息导航。 |
| 设置页 | 通知类型、免打扰、时区、预览隐私与投递诊断归入设置页，不放在工作台中。 |
| 输入区 | 原有模型、附件、上下文用量与 /compact 保留。 |

消息每行显示类型、标题、两行摘要、时间、来源与未读点，不复制完整任务卡或长报告。定时提醒可以查看原对话和取消；取消为显式操作，不因已读、切换标签或收起工作台而发生。触发后的提醒进入消息时间流，未触发的提醒不计未读。原型展示取消确认的两个按钮，不向真实服务提交操作。

未读数只放消息标签。进入列表不将所有消息自动标已读；查看来源后确认已读，“全部已读”只处理已发生的消息，不取消未来提醒。消息与后台任务是一对多关系，同一任务多条进展不代表创建了多个任务。只有真实 taskId 才能定位对应任务，无 taskId 的主动提醒只定位对话。

消息、提醒仍复用原主对话归属、来源、已读游标和调度机制。将两个列表合并为一处展示，不合并持久化 ID，不伪造提醒已经触发。通知设置搬到设置页不影响现有时区、免打扰与隐私配置。

## 用户补充：不设连续调用次数和总执行时长硬上限

新要求优先于上一轮“native 600 秒 / 专业 3600 秒 / 16 轮”的设计。执行持续到完成、用户取消或明确不可继续的实际错误；不能仅因达到固定轮次、调用次数或总耗时而失败。记录次数、耗时和 Token 用于观察，不把展示数值变成执行配额。

重复派活防护按任务身份、工作区和真实操作证据处理；不能靠“失败两次就强制终止”的固定次数门槛替代故障诊断。鉴权错误先修连接；写操作结果未知先对账；可恢复错误在同一任务下接续，避免重新创建一串任务。复杂任务仍由专业智能体负责，主智能体保持快速响应，并能处理后来的独立问题。

单次网络请求超时、工具子进程异常、资源心跳、租约和取消确认仍需要可观测状态。这些属于连接 / 控制权恢复机制，不能当成整个任务的总耗时上限，也不能根据一次断线自动重跑结果未知的副作用。

### 实施时需要一起核对的落点（本轮只设计）

| 代码 / 协议 | 需要调整 |
|---|---|
| `core/loop.py` | 取消 max_steps 的强制退出，持久化轮次统计；保留用户中断与新意图调度。 |
| `dispatch/tasks.py`、`runner.py`、`task_revisions.py` | 不再因 maxTurns / deadlineMs 结束任务；去重、故障诊断和续接基于任务身份与事实。取消本轮旧稿的两次失败门槛。 |
| `executors/native.py`、`executors/roami_cli.py` | 不再从任务总 deadline 包装整轮执行，不给专业任务隐式设置总倒计时。 |
| Go `agentexecution` | `timeoutSeconds` 未设置代表无总时限；不能再强制 1–86400 或默认塞 Claude `--max-turns=16`。用户停止仍精确作用于绑定进程。 |
| `resource_leases.py` | 租约由控制权心跳管理，不取任务总 deadline 的最小值，不因老任务期限误判新动作。 |
| 配置与历史预算 | 去掉固定轮次 / 总时限的控制作用，旧预算记录仍可作为历史证据。已经启动的外部进程须核对实际 deadline 能否更新，不能为了应用新规则擅自重启或重复派活。 |
| Benchmark | 补充超过 16 轮仍能继续、无总 deadline、专业 CLI 不传限制、用户停止、单次网络恢复、主对话继续响应等用例。测试执行器自身的超时不冒充产品限制。 |

上一轮 27 条 benchmark 和通过结果是原实现基线，不能用来宣称新“无限次数 / 无总时限”规则已经通过。后续实现时应修改对应预算与失败门槛测试，再补新规则回归。

## 原型的可验证交互

- 顺序固定为任务、消息、记忆；消息合并已发生的通知与待提醒安排。
- 点击消息在主对话定位，消息侧栏保持；显式查看对应任务才切换任务详情。
- 全部 / 未读筛选、未读数变化、全部已读后的空态；未来提醒仍存在。
- 待提醒详情、查看来源、确认取消 / 保留提醒；设置在左侧设置页展示。
- 三标签切换、展开 / 收起、深浅主题；项目与会话树保留。
- 复用项目 280px 导航、右栏 440–640px 自适应尺寸（34vw）和现有 tokens；图标提取自 frontend/src/icons.tsx，无新图案。

本轮仅更新设计与原型，不修改产品导航、消息 API 或 Agent 执行规则。原型使用本地样例，不写真实消息、已读状态、提醒或任务；中文属于开发者设计资料的 i18n 文档例外。运行时“不限次数 / 总时长”的新要求继续有效，不能把原型验证当作运行时已实现的证明。

## 22:20 任务阅读与产物优先

- 右栏由 360px 加宽为 clamp(440px, 34vw, 640px)，1600px 桌面约 544px；保留中间主对话和收起入口。
- 任务详情先展示标题、状态、产物，再展示 Markdown 回复；执行记录默认折叠。产物不埋在日志或会话终端里。
- Markdown 支持标题、列表、强调、表格、链接、代码块；正式实现复用现有 Markdown 渲染组件，禁用原始 HTML 执行。当前原型用静态预渲染示例说明排版，不引入另一套解析器。
- 产物展示文件名、格式、留存状态、预览和下载。示例可实际展开报告并下载示例文件；不是生产任务产物。
- 正式界面：Markdown/文本、图片、PDF 等按类型预览；HTML 隔离预览，禁止继承主站权限；PPT/不支持格式提供原文件下载并如实说明无法预览。大文件不一次性加载。
- 产物读取使用已留存的授权附件接口；文件缺失、留存中、读取失败分别显示状态与可用操作，不能把链接存在当成成功交付。
- 会话结束不影响已留存产物的查看和下载；任务失败仍展示已有部分产物并明确标注。

本轮设计验证：Playwright 在 1280 / 1600 / 1920px 桌面检查右栏边界与页面无横向溢出；展开报告表格、查看 Markdown 原文、实际触发 settings-review.md 下载均通过；浅色主题检查通过，无浏览器异常、无生产 API 写入。仅设计原型，尚未落到产品界面。
