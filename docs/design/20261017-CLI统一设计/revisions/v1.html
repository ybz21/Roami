Roami CLI 统一改造方案

统一公开入口为 roami <能力> <命令>，核心分组为 session、chrome、project，插件继续按名称提供分组。需求中的 romai project 按 roami project 处理，不新增拼写别名。

本轮交付方案；下列命令为目标接口，尚未实现。首期复用现有会话和浏览器引擎，补齐项目命令，保留旧入口兼容。源码目录、数据库字段和 tmux 会话 ID 不随入口改名。

本目录包含：

  • 技术方案：进程调用链、参数与信号、API 认证、数据库维护协议、远端基准准备和实施依赖。
  • 代码架构：包和文件布局、依赖方向、接口草图、存储职责及具体改动与测试位置。
  • 本页作为设计总览，维护命令范围、兼容规则与验收标准。

分派与兼容规则

分派顺序固定为：内置分组、旧入口兼容表、插件精确名称、插件唯一前缀、未知命令报错。固定分组和兼容命令不再被新安装的插件抢占；冲突插件仍可通过 roami plugin run <plugin-id>:<command> 调用。

session、chrome 必须在插件扫描前分派。列会话、浏览器帮助不应依赖插件守护进程健康。

旧写法 新的正式写法 兼容方式
ttmux ls roami session ls 保留原二进制入口
ttmux swarm ls roami session swarm ls 同上，保留完整命令能力
chrome tabs roami chrome tabs 保留兼容 launcher，调用同一浏览器实现
roami ttmux ... roami session ... 总入口别名
roami ls、roami a ... roami session ls、roami session attach ... 使用明确的旧命令表兼容
roami cron list 等插件入口 保持现有写法 保留精确名称和唯一前缀解析
roami、roami -addr ... 推荐 roami server ... 保留原启动行为与 systemd 用法
roam ... roami ... 保留已有兼容软链

当前“所有未知顶层命令直接透传 tmux”的行为收敛为显式兼容表。任意原生 tmux 操作改用 roami session <tmux-command>；例如拼错 roami projet 应提示可用分组并以非零状态退出。兼容表从原 CLI 的公开分支及现有调用点整理，不包含 __autoconfirm、_plugin-host 等内部入口；内部入口继续由原引擎处理。

首期不移除旧二进制，也不向旧命令 stdout 添加弃用提示，以免破坏脚本与 JSON。文档、安装完成提示、Agent 提示词和技能示例统一展示新命令。

三个核心分组的实现

Session

roami session 剥离分组后，将剩余 argv 原样交给现有 Go CLI，复用 forward，不拼接 shell 字符串。标准输入输出、退出码和交互式 attach 行为保持一致；需要验证 Ctrl-C、终止信号和交互终端恢复。

裸 roami session 进入原 ttmux 的交互选择器。roami session help 展示新前缀的帮助；原 ttmux help 保留旧前缀。名称解析继续区分稳定 ID 与展示名，rename 仍只改展示名。

保留后端 TTMUX_BIN 与原有内嵌会话引擎，避免本轮改动 Web 调用链。继续使用精确 tmux target 和 SendPromptSubmit，不重新实现会话发送逻辑。

Chrome

将生成的 launcher 内嵌到 Roami，按内容版本释放到私有运行目录，例如 <数据目录>/bin/roami-chrome。总入口优先使用随发行包携带的 launcher；源码开发允许显式指定开发产物。不得通过 PATH 的 chrome 盲目查找，避免调用到浏览器本体或兼容入口形成递归。

原 chrome 与新入口执行同一份驱动，保留 --tab、--url、--cdp 的位置和语义，以及截图、录制、daemon、锁与浏览器配置读取行为。兼容入口不能转回自身。

同时修正 launcher 的配置目录解析：目前 _roam_data 读取 ROAM_*、TTMUX_* 并默认 ~/.roam，与后端现行 ~/.roami 存在偏差。新入口以 ROAMI_* 为正式配置名，保留旧变量兼容，并通过一致性测试对齐后端的目录解析和旧目录迁移行为，避免操作另一份 profile。

统一入口仍需要 Node、playwright-core 和 Chrome；内嵌 launcher 不等于内嵌这些运行时。roami chrome setup 安装浏览器自动化依赖，help 不触发下载或启动浏览器，缺依赖时给出对应安装提示。

Project

首期通过已有 HTTP API 操作项目，由正在运行的 Roami 服务持有 Store，CLI 不直接读写 SQLite 或 projects.json。这样沿用同一套发现、归档、缓存失效和工作树归属逻辑。项目命令需要服务运行；会话和 Chrome 命令保持本地独立运行能力。远程项目管理不纳入首期验收范围。

命令 对应能力与语义
project ls GET /api/projects，展示项目 ID、名称、目录和会话摘要
project show <id> 首期从同一列表响应中按 ID 精确选择，不新增详情 API；只承诺现有 summary 字段
project create <dir> [--name ...] [--clone ...] POST /api/projects，映射 dir、displayName、cloneUrl
project remove <id> DELETE /api/projects/:key，只移除项目台账，保留目录、worktree 与会话；仍有会话时可能被重新发现
project prefs <id> [--name ...] [--pinned true或false] [--agent ...] [--base ...] PATCH /api/projects/:key/prefs；未传参数不修改，允许显式清空字符串偏好
project activity <id> GET /api/projects/:key/activity，沿用现有提交与收尾留痕响应

create 将调用者的相对路径转换为本机绝对路径，再交后端处理；不存在的目录按当前 API 语义创建。项目选择使用稳定 ID，兼容服务端已有旧 key；不按显示名模糊选择项目。

连接参数使用 --server / ROAMI_SERVER，缺省按本机配置推导地址；设置请求超时，不在失败时偷偷启动后台服务。服务未运行时提示 roami server。

新增 roami auth login 复用 /api/login 的口令及 TOTP 认证，交互输入口令，不把口令放入 argv；仅保存现有认证流程签发的 Cookie，凭据文件权限为 0600，并按服务地址隔离。非交互登录可从 stdin 输入凭据。使用正常 TLS 验证，本机自签证书复用已有 CA；不默认跳过验证。401 时返回认证错误，不自动反复重试登录；logout 清除本地凭据并使用服务端现有退出机制（若有）。

数据库统一管理

数据库随 CLI 一起统一管理：业务元数据继续归入主库，所有 Roami 自有数据库具有统一的路径解析、版本登记和运维入口。主库沿用 meta.db 文件名，避免入口改名引起无必要的数据搬迁。

当前存储与目标边界

存储 当前用途 目标
meta.db 会话、项目及别名、竞赛、会话归属、蜂群注册/成员/看板、插件会话等 继续作为业务元数据真相源，不再为同一实体新建另一套台账
swarms/<id>/swarm.db 每群消息流 posts；旧库可能保留已迁移的成员、看板表 保留消息流分库，成员和看板以主库为准，历史表不再双写
ai-footprints.db Git 提交归档 先保留独立归档库，纳入统一登记、迁移与备份；是否物理并库另行评估容量和写入负载

分库仍需明确用途。蜂群 posts 当前刻意独立，以隔离高频写入和按群归档；统一管理不要求把它并入主库。以后新增数据库必须登记用途、路径、迁移所有者、备份与清理策略。

路径与迁移

默认数据根统一为 ~/.roami，正式配置使用 ROAMI_*。兼容已有 ROAM_*、TTMUX_* 和显式设置的分离 HOME/DATA 路径；升级时发现多个既有库，不凭文件时间猜测、不创建空库替代旧数据、不自动覆盖合并。

数据库实际路径由统一解析和握手结果提供。后端当前通过 ttmux db status --json 获取主库路径，这一契约继续兼容，新公开入口改为 roami db status --json。各命令不得自行拼接默认路径。新旧配置冲突时采用明确且可测试的优先级，并在 status 中展示生效路径和配置来源。

主库 schema 和迁移继续由现有会话引擎的 internal/metadb 单点管理；后端保持业务 DML 权限，不另建同一套 DDL。蜂群库和归档库分别保留各自迁移版本链，由统一入口调度其所有者；归档库现有建表、补列逻辑需收敛为可追踪的版本迁移。已发布迁移只追加、不修改。

数据库异常必须可观察。正常升级路径先备份、迁移、校验，再切换；迁移失败中止并保留原始数据。现有 JSON 降级模式需明确上报状态与原因；受影响的写入命令返回错误，防止用户在不知情时写出另一套台账。终端与浏览器等不依赖故障台账的能力可继续工作。

写入职责与并发

统一入口不等于单一进程。会话引擎和插件宿主、Roami 服务仍可并行运行，沿用表级写入职责：会话/蜂群/插件表由现有引擎维护，项目/竞赛/会话归属由服务端维护。roami project 继续通过 API 写入，避免绕过服务端内存缓存。

连接策略统一规定 WAL、foreign_keys、busy_timeout 和写事务方式，并保留受支持文件系统上的明确降级策略。WAL 不能消除多个写者的竞争；事务保持短小，失败不能吞掉，同一业务变更不能跨库假装具有原子性。需要跨库时采用可重试、可校验的分阶段操作。

运维命令

roami db 作为固定内置分组，旧 ttmux db ...、roami session db ... 继续兼容。首批正式入口为：

roami db status --json
roami db migrate
roami db backup <destination>

status 展示主库、蜂群消息库和归档库清单、实际路径、schema 版本、运行模式及错误原因。原有主库握手字段保持兼容，附加库信息使用新增字段；内部会话历史与恢复命令继续支持，不借本轮改名删除。

backup 生成包含清单、版本和校验信息的备份集，覆盖全部已登记数据库，不能只复制主库文件，也不能直接复制运行中的 SQLite 文件漏掉 WAL。使用 SQLite 一致性备份机制；首期完整备份集要求所有相关写者进入维护状态，拒绝无法协调的并发写入，再顺序取得各库快照。恢复前停写、校验全部快照和兼容版本；作为备份集整体恢复，不把不同时间的库任意拼接。自动迁移前同样遵守该备份要求。

开工前新建 worktree 必须同步远端

Roami 为新任务创建 worktree 时，必须先成功获取选定远端基准分支的最新提交，再从本次获取并锁定的提交 OID 创建任务分支。Agent 在 worktree 准备成功后才能开始工作；不能依赖 Agent 开工后自行 pull 或 rebase 补救。

目前 backend/worktree/service.go 的自动同步仅在 base、remote 都未指定时启用，且 fetch 失败仍会静默使用旧远端引用或本地分支。改造后统一执行以下规则：

  • 先确定远端和基准分支：显式选择优先，其次使用基准分支的 upstream，再回落到 origin 的默认主干；多个远端无法唯一判定时返回明确错误，不猜测。只指定 base=main 也必须同步其对应的远端分支。
  • 每次创建新任务分支都执行有超时的定向 fetch；从本次 fetch 的准确结果取得 OID，并在创建期间固定使用它，避免并发 fetch 更新引用导致起点漂移。基准跟踪引用也按本次获取结果更新，不移动本地主干、不触碰其他 worktree 的未提交改动。
  • 网络、权限、超时或远端分支不存在时，停止创建并返回可重试错误；不得静默退回本地旧分支或缓存引用。没有可用远端的仓库也返回明确错误；如以后支持本地仓库模式，必须作为显式选择提供，不能默认降级。
  • Web、手机、项目开工、子会话和蜂群等新建任务 worktree 的调用点都通过同一个 worktree.Service.Create 约束；CLI 如提供该能力也复用同一业务路径。任务提示只能在同步和创建成功后提交；中途失败清理本次创建的临时会话等资源。
  • “接着已有分支继续工作”保留该分支现有提交，不自动 reset 或 rebase；它与“从远端最新基准新建任务”明确区分。恢复现有会话也不改写任务分支。

这里的“最新”指创建准备阶段成功从远端取得的提交快照；远端随后新增提交不会自动改写已经开始工作的分支。

帮助与输出契约

roami help / roami --help / roami -h 展示统一命令树；Web 参数帮助移到 roami server --help。roami help session、roami session --help 和 roami chrome --help 均可发现各自能力。roami version / roami --version 展示总入口版本，roami completion 补全固定分组、原会话命令和可用插件。

会话与 Chrome 的数据输出和退出码原样保留，不能宣称所有现有子命令都支持 --json。项目首批命令统一支持 --json：stdout 只输出一个 JSON 值，成功沿用 API 的 data 包装，失败输出 error.code 和 error.message 并返回非零退出码；人类提示走 stderr。项目新命令约定 0 成功、2 参数错误、1 业务或连接错误，使用帮助时返回 0。

CLI 终端输出与开发文档按仓库 i18n 标准属于允许例外；如错误信息会同时展示到 Web UI，沿用现有错误码和 i18n，不新增硬编码 UI 文案。

实施顺序与修改范围

  1. 总入口与会话分组：修改 backend/cmd/cli.go、cli_test.go 和 main.go，增加固定路由、旧命令兼容表、server/help/version/completion，复用原会话引擎。先验证插件冲突和原服务启动兼容。
  2. 浏览器纳入发行包：调整 cli/chrome-cli 的帮助与目录解析，新增浏览器 launcher 内嵌模块，更新 scripts/build/build-roami.sh、安装脚本及 .github/workflows/release.yml，验证单独下载 Roami 后可使用 Chrome 分组。
  3. 认证与项目命令：在 backend module 内新增具体命名的 CLI 客户端与项目命令模块，复用现有认证和项目 HTTP API。首期不改项目存储结构、不新增远程主机管理。
  4. 开工基准同步：收紧 backend/worktree/service.go 的基准选择和 fetch 失败处理，审查全部新建任务 worktree 调用点的参数传递、Agent 启动顺序与失败清理，保证显式 base 也使用远端最新 OID。
  5. 数据库统一管理：增加固定 roami db 分组，统一实际路径解析、数据库清单、归档库版本迁移、降级状态以及完整备份集；保留主库 schema 所有权和现有写入边界。
  6. 迁移调用示例与发布说明：更新中英文 README、docs/install、两个 CLI README、skills、Agent 会话提示模板及可见操作指引。内部 tmux 调用、协议字段、历史迁移与兼容测试中的旧名称保留。旧 release 资产暂时继续发布。

每一步可以独立评审；最终交付以三个核心分组均可用为准。首期不合并两个 Go module，不重写 Chrome 为 Go，也不批量改名所有源码中的 ttmux 字样。

验收标准

  • 新旧会话入口使用同一份会话数据；覆盖 ls、new、rename、send 多行提示、capture、attach、fork 和 swarm，验证前缀相近的会话不会被误操作。
  • 原有插件精确名、唯一前缀、歧义报错、停用行为保持正确；与固定分组冲突时，插件完整 ID 入口仍可达。未知顶层命令不能落入 tmux。
  • Chrome 的 tab/url/cdp 参数原样传递；新旧入口复用同一 CDP 实例及已登录 profile；截图和录制产物可打开。新旧环境变量、默认数据目录和缺运行时提示均有覆盖。
  • 项目 ls/create/show/prefs/activity/remove 与 Web API 结果一致；覆盖非 Git 目录、worktree 归位、重名显示名、旧 key、服务未启动、认证过期和 TOTP。CLI 修改后 Web 下一次查询能看到结果，移除项目不删除目录或关闭会话。
  • 用真实本地 bare remote 覆盖：本地主干和远端跟踪引用均落后、显式 base、显式 remote、自定义 upstream、非 origin 远端、并发创建；新任务 HEAD 必须等于本次 fetch 锁定的远端 OID。另测 fetch 失败、超时、远端分支删除和无远端仓库：不能创建旧基准任务、不能启动 Agent、不能泄漏临时资源。已有分支接续不丢提交，本地主干和未提交修改保持完整。
  • 干净 PATH 的 release 安装覆盖 Linux/macOS、amd64/arm64；会话不要求 Node，help 不安装依赖；旧 roami 启动方式和 systemd 服务可继续运行。
  • 数据库验收覆盖新旧配置优先级、HOME/DATA 分离、旧数据幂等导入、重复执行迁移、主库 schema 契约、并发写入与缓存一致性。完整备份恢复后逐库核对版本及数据，测试 WAL 存在、维护状态下仍有写者、磁盘满、迁移中断和版本不兼容，确保失败不产生空库或静默双写。
  • 实现阶段运行 scripts/dev/quality/check.sh quick；运行行为变更开 PR 前运行 full，并补充 CLI 分派测试、真实 tmux 隔离 socket 验证和 Chrome/CDP 冒烟。若改动前端，追加仓库要求的前端检查与 Android 真机验收。
  • PR 按仓库规则附新命令帮助、实际运行或测试结果截图，上传到 pr-shots，不把一次性截图提交到主分支。

Roami CLI 技术方案

本文定义目标实现，尚未落地。产品范围和兼容规则见 设计总览，包结构与接口见 代码架构。

进程与模块选择

保留两个 Go module：backend 负责 Roami 总入口、HTTP 服务和项目客户端，ttmux-cli-go 继续作为独立会话引擎。二者通过 argv、退出码和版本化 JSON 通信，不跨 module 导入 internal 包，也不为入口统一重写 tmux 逻辑。Chrome 仍使用 Bash launcher、Node 和 Playwright。

统一的是公开命令树、配置解析和数据库管理契约。首期发行包仍是一个 Roami Go 二进制，内嵌前端、目标平台会话引擎、生成的 Chrome launcher；Node 和 Chrome 是外部运行时。

启动与路由流程

main 只负责进程组装：构造基础 IO、解析路由、运行目标命令、设置退出码。命令路由在 Web 服务初始化前执行，session help 不加载项目 Store、TLS 服务或浏览器。

  1. 识别根级 help/version 及固定分组；无参数和旧服务参数转换为 server 路由。
  2. 匹配显式旧命令兼容表，包括 ttmux 和旧的会话顶层命令。
  3. 仅在可能是插件时查询插件清单，精确名优先于唯一前缀。
  4. 未知词返回参数错误。禁止顶层任意回落到 tmux；session 分组继续允许原生 tmux 透传。

根级参数只消费总入口已声明的参数，后端引擎参数按 argv 切片传递。尤其 roami chrome --tab 2 ... 和 roami session --quiet ... 的参数不交给 server 的 flag parser。项目连接参数放在对应分组内；全局 -config、-addr 等旧参数保持 server 兼容语义。

插件保留独立查询结果和错误：固定路由无需插件发现；用户请求插件而发现失败时报告发现错误，不能误报“未安装”。插件名称冲突通过 roami plugin run <完整ID>:<命令> 消歧。

子进程与发行产物

会话引擎选择顺序保持显式 TTMUX_BIN、可用的已安装引擎、内嵌引擎；显式路径无效要报错，不能无声忽略用户配置。数据库操作额外校验协议兼容性，必要时明确提示升级。Chrome 使用显式开发产物或内嵌 launcher，不搜索泛称 chrome 的 PATH 程序。

引擎释放到按内容 hash 命名的私有目录，临时文件写入、设置执行权限后原子 rename。并发释放可重入；不能覆盖正在使用的可执行文件。缺少嵌入内容的开发构建必须指向开发产物，并提供可操作的错误。

公开兼容命令与私有引擎路径分离：旧 ttmux 保持原引擎；旧 chrome launcher 调用相同驱动，不能形成 chrome -> roami chrome -> chrome 环。构建顺序为前端、会话引擎、Chrome launcher、Roami，退出 trap 恢复嵌入占位文件。

交互式执行直接连接 stdin/stdout/stderr，不额外套 PTY；非交互 JSON 调用分离 stdout 和 stderr。Linux/macOS 使用子进程启动与信号处理适配：子进程启动失败返回 1，正常退出透传退出码，信号退出映射为 128 + signal。避免同时把终端进程组已收到的 SIGINT 再转发一次；测试前台 attach 的 Ctrl-C、Ctrl-Z 和退出后终端状态。

项目与认证链路

项目命令通过服务端 API 操作，复用现有鉴权中间件和项目 Store。CLI 不从项目 API handler 导入业务代码，也不直写数据库。show 首期使用列表 summary，不承诺完整会话列表；后续若需要详情，单独增加 API。

原架构图以本版本文字说明为准。

HTTP 客户端设置超时、取消和响应体大小上限。POST 创建、clone 和 DELETE 等操作不自动重试；请求超时可能已经产生副作用，提示查询当前状态再重试。服务端错误码保留，网络与 TLS 失败使用客户端错误码，禁止把内部日志拼入 JSON stdout。

auth login 调用现有 POST /api/login，提交 password、code；logout 使用现有退出 handler 对应路由并清除本地 Cookie。凭据按完整规范化 origin（scheme、host、port）隔离，文件原子写入并设 0600；目录设 0700。密码不持久化，不从配置文件明文复用。跨 origin 重定向不能携带凭据，自签 CA 显式加载，不关闭证书验证。

默认 URL 来自本机配置：监听 0.0.0.0 时连接 loopback；HTTPS 名称必须匹配现有证书 SAN。显式 --server、ROAMI_SERVER 覆盖自动推导。首期只保证本机服务：远端目录转换、远端主机选择和服务器自动启动不在范围内。

数据库管理与一致性

主库继续由会话引擎的 metadb 管理 DDL，后端只执行所属业务 DML。将“数据库清单”与“业务 Store”分开：清单记录 ID、种类、实际路径、schema、所有者、运行模式，业务命令只能通过对应所有者操作数据。

公开 roami db status --json 保留旧握手字段，在 databases 增加各库状态。主库路径来自原引擎握手；蜂群库来自同一实例的已登记蜂群目录；归档库由服务配置解析。不得扫描整个 HOME 后把任意 .db 认作 Roami 数据。

迁移分两层：各库 owner 负责版本链和单库事务；总入口负责完整预备份、调度、错误传播和结果记录。跨库升级不承诺 SQLite 原子事务。备份未完成不得开始迁移；迁移中断记录各库完成阶段，校验后可幂等续跑。发生不兼容时停止业务写入，不能自动切到 JSON 继续写。

维护协调协议

当前没有覆盖所有进程的全局维护协议，完整备份要求新增协调能力，不能仅靠现有单连接互斥锁。

  • 同一数据实例使用一个维护锁文件，Linux/macOS 采用现有平台可用的 advisory file lock。正常写入在事务前持共享锁，backup/migrate 持独占锁；锁文件位于主库握手确认的实例目录。
  • 所有受支持写者都参加：服务端 Store、会话 CLI、长驻插件宿主、蜂群消息写入和归档写入。创建/删除分库也属于写入，避免备份期间清单变化。
  • 锁顺序统一为“实例维护锁、进程内 Store/DB 锁、SQLite 事务”。协调器持独占锁后通过显式维护执行上下文调用 owner，不递归申请共享锁；该上下文不能由普通命令行环境变量伪造。
  • 进入维护后排空已有写事务，取得稳定清单，再逐库 VACUUM INTO 生成快照，执行完整性检查和 hash 校验。临时备份目录在全部成功后原子发布 manifest；部分失败不得标记为完整备份。
  • 新协议落地前，整套备份只支持停掉所有写者后的维护窗口。旧版本引擎/插件宿主不支持协调时必须先升级或停止；不能靠“当前没有 SQL 锁”推断之后不会写入。

已有 metadb.DB.Backup 使用 VACUUM INTO，可复用单库快照方式。整套一致性来自停写协调，不能由逐库快照本身保证。首期恢复流程为离线校验、关闭所有连接、保存现有数据集、替换并检查整套快照，重启后端重建内存缓存；失败回滚整个数据集。自动化 restore 命令另行实现，首期提供明确操作文档。

新任务 worktree 的远端起点

新增可测试的准备阶段，放在 worktree.Service.Create 内，所有调用点共同受约束：

  1. ResolveRepo 并解析远端/基准选择。显式 remote+base 优先；只有 base 时解析该分支 upstream；无 upstream 时选择 origin 上的同名基准；完全缺省时使用可明确解析的远端默认主干。
  2. 不明确时返回 REMOTE_UNRESOLVED / BASE_UNRESOLVED；没有远端时返回 REMOTE_REQUIRED，不自行使用当前 feature 分支。
  3. 为本次操作生成独占的临时 ref，例如 refs/roami/prepares/<随机ID>，定向 fetch 远端 refs/heads/<base> 到该 ref。读取该 ref 的 commit OID；不能读取可能被另一 fetch 改写的全局 FETCH_HEAD。
  4. 校验 OID 后更新对应 tracking ref。临时 ref 与引用更新过程放在统一仓库操作锁内，序列化同实例更新；失败或取消时清理临时 ref。网络超时受请求 context 约束，锁顺序固定，不能重复获取已有的非重入锁。
  5. 从固定 OID 创建新任务分支，记录 baseref、startoid 以及新增的远端来源元信息。worktree 创建失败按阶段回收临时分支与目录；不得删除用户原有分支。
  6. worktree 和会话 cwd 绑定成功后才提交 Agent 启动命令及任务提示。会话可先分配，但只能停在普通 shell；失败关闭本次会话。

默认请求每次同步远端，不用 TTL 跳过 fetch。竞赛一次创建多个选手时，首期允许每次各自 fetch，保证各自基于新快照；需要相同基线比较时，应在竞赛层明确准备一个共享快照再传入受控接口，不能对客户端开放任意 OID 绕过同步。

Existing=true 走独立接续路径，不修改已有分支、不自动合入远端。纯会话 fork 若不新建 worktree，也不触发该同步流程。直接使用原生 git 创建的外部 worktree 不在 Roami 新任务创建保证范围内。

核心接口草图

以下是设计级签名，具体 DTO 由实现时与现有协议对齐，不承诺直接复制即可编译。

type Route struct {
    Group string
    Args  []string
}

type Streams struct {
    In  io.Reader
    Out io.Writer
    Err io.Writer
}

type ProcessRunner interface {
    Run(ctx context.Context, bin string, args []string, streams Streams) int
}

type ProjectClient interface {
    List(ctx context.Context) (ProjectList, error)
    Create(ctx context.Context, req CreateProject) (ProjectResult, error)
    Remove(ctx context.Context, id string) error
    SetPrefs(ctx context.Context, id string, patch ProjectPrefsPatch) error
    Activity(ctx context.Context, id string) (ProjectActivity, error)
}

Route 解析是可纯测的决策，不在解析中启动服务或安装依赖。ProjectPrefsPatch 使用指针或可选值保留“未设置”与“显式清空”的区别。App 只持有 runner、client、流、产物解析器和插件目录等明确依赖，不引入通用的全局 service locator。

type RemoteBase struct {
    Remote string
    Branch string
    Ref    string // refs/heads/<branch>
}

type PreparedBase struct {
    Source RemoteBase
    OID    string
}

远端解析与 fetch 分为两个内部函数；PreparedBase 仅由 worktree 服务准备阶段生成。调用者传业务选择，不允许客户端自行提交任意 PreparedBase 绕过同步。创建函数最终消费固定 OID，不再次按可变分支名解析。

type DatabaseDescriptor struct {
    ID            string
    Kind          string
    Path          string
    SchemaVersion int
    Owner         string
    Mode          string
}

type DatabaseOwner interface {
    Describe(ctx context.Context) ([]DatabaseDescriptor, error)
    Migrate(ctx context.Context, scope MaintenanceScope) error
    Snapshot(ctx context.Context, scope MaintenanceScope, dest string) error
}

MaintenanceScope 只由维护协调器在持独占锁时创建，owner 为进程内适配或受控子进程适配；跨进程不能假设一个 Go 值就能传递锁权。子进程 owner 必须使用有生命周期约束的锁句柄继承/握手，不能使用公开的 --skip-lock。设计无法验证锁权时改用离线维护流程，不开放绕锁接口。

完整备份 维护协调器 所有写者停写、稳定清单、manifest 完整发布

数据库先沿用文件路径和表名。新数据库清单返回完整路径时仅面向已授权本机 CLI，不增加公开未鉴权端点。备份 manifest 至少包含格式版本、实例 ID、创建时间、Roami 版本、各库 ID/相对备份路径/schema/hash 和完整状态；不包含密码或 Cookie。

数据根与 CLI 配置通过 config 模块解析；服务启动函数接收已解析配置，不重复隐式迁移。业务子命令只执行它需要的初始化，不因 roami help 迁移真实用户数据。
