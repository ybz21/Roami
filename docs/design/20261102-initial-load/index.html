首次资源与数据不是同一个问题

一个未登录冷访问样本中，HTML 的浏览器 TTFB 为 52.3 ms，FCP 为 1,124 ms，DOMContentLoaded 为 1,017.5 ms。入口静态闭包包含约 728 KB 压缩后的 JS/CSS（解压后约 3.14 MB），含 antd、xterm；认证请求在脚本准备后才开始。这个样本不能证明手机首次访问也只需一秒。

静态资源已有 Brotli 和一年 immutable 缓存；普通 Agent JSON 则仍未压缩。已登录的缓存访问能在约 220 ms 出现首屏文字，但随后消息和任务请求超时。FCP 快不等于历史可读或页面可用。

数据库是否读了全库

运行库约 38.35 MB，另有约 4.13 MB WAL；全库有 2,856 条 message、11,819 条 event 和 51 项 task。主分支读取命中了既有 (branch_id, seq) 索引。问题是读取并展开该分支的全部消息，并非浏览器下载整个数据库文件，也不是每次遍历所有 16 个库。

Python 的数据库读写共用一个 worker，重查询会排队；events WHERE task_id=… 的一个查询计划出现全表扫描。这是增长风险，但该次本机消息接口约 0.24 秒，状态采样队列为 0，不能据此解释公网约 44 秒的完整下载。

Product Design · 先读最近内容

1. 对话先可用

认证和节点归属确认后展示输入区，读取最近一页。加载期间保留草稿；发送前依现有业务状态校验。

2. 历史按需补齐

向上滚动时读取较早消息，保留顶部锚点。只为当前分支加载，读取失败在原位置提供“重试”。

3. 详情单独读取

主对话保留任务进展和阻塞事项；执行预览、完整指令、工具参数和输出在展开详情时读取。

4. 辅助区独立更新

未打开消息时只查未读摘要。任务区先显示短列表，Git/worktree 扫描完成后补充，不阻塞对话。

User Stories

  • 首次公网打开首页，我先看到最近对话和输入区，不等待全部历史。
  • 回看更早消息时，上滚连续加载；分叉继承、任务锚点和工具调用结果保持完整。
  • 从项目或设置进入时，不预取主对话；徽标与导航仍可独立使用。
  • 网络失败时保留已读内容、草稿和滚动位置；只重试失败的区域。

桌面与手机

沿用现有桌面任务／消息／记忆工作区，不增加新的导航。手机继续使用顶栏与首页、项目、工具、设置四入口底栏；任务与消息详情使用 MobileSubPage。首屏不加常驻刷新按钮，不把连接错误等同于任务失败。

长正文通过有标识的“展开全文”读取内容，不静默截断；已展开内容随当前阅读状态保留。加载提示用一句话，局部失败不盖住已经显示的对话或输入区。后续实现统一走中英 i18n。

列表只读身份、短摘要、状态和必要动作；长正文、完整指令、执行结果和历史记录进入详情。接口、SQL 投影和适合纵向拆分的表一起调整。

整改前的任务列表使用 SELECT * FROM tasks 并通过 _view() 返回整行，包含 intent_json / target_json / budget_json；通知列表关联读取 m.content_json。列表即使只画一行，也已经付出了大字段读取和传输成本。本轮 Web 已改用独立轻量查询，旧接口保留兼容；后续再按测量决定物理拆表。

短标题、摘要和用于列表筛选的 projectId 等字段在写入时维护；列表不能每次读取 intent_json 再截取标题。摘要与详情修订、真实状态及投影版本在同一事务更新；执行器报告仍须经过现有任务状态与验证规则，不直接写成“已完成”。详情读取与预期 revision 不一致时明确返回新 revision，由当前详情视图重新读取。

查询和接口的硬边界

  • 分别定义 TaskListItem / TaskDetail 等 DTO；SQL 显式列名，列表不调用详情组装器，不执行 SELECT * 后再删字段。
  • 分页必须先发生在 SQL，再批量补齐本页必要状态；不逐条调用 _get() 或查询来源、attempt、产物。查询次数不随本页条数线性增长。
  • 列表中的 summary 使用有上限的独立字段；不在列表 SQL 中对大正文 substr/json_extract/native_content 后当成已避免载荷读取。
  • 完整 instructions、content_json、arguments_json、result_json、sourceRefs 和历史数组不得作为隐藏字段跟随列表。必要会话入口和下一步动作保留为短引用与状态。
  • 切详情前列表数据即可展示选中项；进入后才请求详情，执行记录展开后再请求。返回恢复原筛选、游标和滚动位置；详情失败不清空列表。
  • 数据库分表不能替代接口精简。消息已使用 native 载荷引用的部分，不再复制一套正文表；通知也不另存一份完整消息作为详情。

迁移与回退

P0 先上线短列表读模型；P1 再新增 task_details 和摘要列，通过主键游标分批回填，避免单个长事务。回填与并发修订按 revision 校验，摘要不从旧版本覆盖新版本。核对行数、关联完整性和 JSON 内容一致性后切换读取；兼容期同一事务维护旧列与新结构，暂不删除旧列。

迁移前清点所有直接读取任务 JSON 的路径，包括 native_sessions、模型任务上下文、任务修订、记忆来源与遗忘传播；统一通过仓库查询或兼容视图读取。不能只改 Web 列表和 tasks 服务，就删除被其他 SQL 使用的旧列。

写入、读取和数据库升级兼容检查必须同批设计；旧版运行时不能误写新 schema。回退期间保留兼容写路径并复核数据，不能只回退二进制就假定安全。记忆若后续拆正文，全文索引、遗忘传播、来源校验与删除必须同步，先以查询投影改善 Web 列表。

列表与详情的专项验收

向某个任务详情追加大段指令、工具输出和修订历史，列表响应体积与详情读取次数应保持不变；单个列表项设计上限 2 KiB，默认 20 项页面不超过 48 KiB 未压缩数据。断言列表查询没有读取详情列或解析 native 工具载荷，列表首次请求不触发详情网络请求。验证分页、修订一致性、越权访问、删除与回退；性能收益仍以实现后的生产构建实测为准。

滚动到边界，才请求下一页

首次只请求当前可见内容的一页。聊天回看触达顶部才取更早消息，普通列表浏览到底部才取后续记录；未浏览的页不请求、不解析、不渲染。

整改前基线：useAgentHistory 用 entries.slice(start) 每次多显示 24 组，属于已经下载后的分批渲染，不会减少全量消息响应。原生会话已有 before 分页与“加载更早”按钮，记忆目录已有 limit/offset 与翻页按钮；这些入口应复用服务端能力，再统一滚动触发和资源预算。本轮主对话已使用真实服务端分页，普通列表已按浏览意图续读；以下完整规则还包含窗口化等后续目标。

滚动加载与下拉刷新各有职责

“向下浏览到列表底部”读取后续记录；“在列表顶部下拉”沿用现有手机刷新入口，更新最新内容，不顺带把全部历史重新拉一遍。对话顶部的回看手势归对话历史容器处理，不能同时触发全页下拉刷新。嵌套容器只由实际滚动的一层接收加载事件。

用户一直停在当前页时，后续分页请求应为零。SSE 或既有摘要刷新只更新当前窗口、状态和计数，不以“数据有变化”为由重新遍历所有已加载页。未打开的标签、折叠区和不可见面板不预取列表正文或下一页。

        失败：保留当前内容，边界显示“重试”
        结束：hasMore=false，停止观察

一页完成不自动触发另一页；需要后续用户浏览或主动加载。
切换筛选 / 节点 / 分支 / 页面：中止旧请求并禁止晚到结果写回。
  • 触发器使用实际内容滚动容器作为 IntersectionObserver root，或复用该容器的滚动事件。页面挂载、尺寸变化、恢复位置、程序化滚动和新数据插入不视作新的用户浏览意图。
  • 不设置跨多屏的预取区域。首批不足一屏、哨兵持续可见或过滤后返回空页时，也不能自动循环补满整个视口；保留一个可触达的“加载更多”作为短列表与键盘操作的入口。
  • 滚动请求在同步锁中按 scope/cursor 去重，复用同一 in-flight。重复 observer 回调、快速滑动与多个消费者不能把同一游标发多次；每个列表最多一个分页请求在执行。
  • hasMore=false、游标缺失或游标没有前进时停止加载。空页但游标前进的情况保留用户继续操作入口，不在后台自动穿透多页。失败不自动无限重试，用户在原边界恢复。
  • 切换机器、身份、会话、分支、筛选或排序时使用新的查询代次；卸载、隐藏或折叠后取消在途分页。旧代次的成功、失败和 finally 均不能覆盖新代次状态。
  • 任务根列表按根任务分页，子任务由展开动作读取；通知未读数、项目计数与任务总状态由摘要接口提供，不能用当前页长度代替全局事实，也不为徽标遍历所有页。

服务端和缓存也必须有界

接口在 SQL 中执行筛选、稳定排序与 LIMIT，再读取本页详情；hasMore 可通过多取一条判断，不默认执行昂贵全量 COUNT。增量较多的列表优先使用稳定游标；已有 offset 接口可先复用，但必须校验并发变化带来的重复/遗漏，再渐进迁移。

后续窗口化目标：前端以节点、身份、资源、筛选与排序作为页缓存身份，缓存键包括游标；页数与字节数同时受限。当前共享缓存已有 16 MB 上限，活动视图未实现正文淘汰和 DOM 窗口。活动阅读窗口和草稿独立保留，远离窗口的页可淘汰正文，保留锚点、游标和必要高度占位；用户重新浏览到已淘汰区域才补读。虚拟列表用于控制 DOM 数量，不能替代服务端分页。

长列表重新进入时优先恢复仍有效的缓存，刷新最新摘要或最近页，不从第一页自动串行请求到原位置。消息、通知或任务的深链接用按 id 定位的有界邻近窗口，不通过翻完全部历史来找目标。删除、遗忘与权限变化仍要失效相应缓存，不能为了少请求继续展示已不可见内容。

请求量验收

  • 未打开面板：列表和详情正文请求均为零；打开面板：只请求首批一页，下一页请求为零。
  • 首批加载完静置 30 秒：后续页请求为零；摘要刷新与 SSE 单独计量，不能混入分页预算。
  • 真实滚动到边界：恰好增加一页请求；一页返回后继续停留：不追加请求；再次用户浏览才允许再取一页。
  • 同一游标多次回调、快速往返滚动和网络慢于滑动：仍只有一个在途请求，没有重复游标请求。
  • 短列表、空页、无下一页、删除后缩短列表、布局变化和程序化恢复滚动：均不触发自动扫页。
  • Android 真机分别验证聊天顶部回看、普通列表底部续读、顶部下拉刷新，确保没有双重触发；历史 prepend 后原消息仍停在原视觉位置。

分页接口与读模型

本轮采用兼容的现有 v1 命名空间。Go 明确挂载新增路由，仍将 /api/agent/… 映射到 Python /v1/…，后端与前端须配套发布。消息接口有 limit 时返回分页 DTO，无 limit 时保持旧契约；任务与通知通过独立列表路径返回分页对象。模型内部读取保持原语义。

游标必须覆盖分支继承

  • 不要直接对当前 branch 做 seq < before LIMIT 50 后宣称完成：父分支消息也属于可见历史，且 seq 不是跨分支唯一位置。
  • 分页仓库从当前分支倒序读取有限行；不足时沿父分支和 fork 截点继续读取，复用既有最大深度约束。游标使用消息 ID，读取时验证 owner、conversation、选定分支谱系和 fork 截点；越权或不匹配游标返回明确错误。
  • 多取一条判断 hasMore；按页面预算逐步读取，不先调用无界 history() 再在 Python 切片。仅对选中行做 native payload 解析和序列化。
  • 超过字节预算的单条消息返回可见的摘要与内容引用，通过鉴权的正文接口完整读取；分页游标必须前进。工具参数、结果配对和活动锚点不能因跨页而遗失，缺少的配对摘要单独补取。
  • 页面内去重以 message id 为准，保持稳定展示顺序；较早页只 prepend，不替换已有最新消息或改变当前输入草稿。

SSE 与翻页的一致性

最近页、活动摘要和 snapshotCursor 在一次短只读快照中取得。只读事务内不做网络或文件传输。页面拿到快照后从该游标订阅 SSE，补齐期间的新事件；历史页返回的游标不能让活动流后退。

继续复用现有事件投影，事件按 id 去重；晚到的历史页不得覆盖 SSE 已更新的状态。分支切换中止旧请求并隔离缓存。删除、折叠和修订事件要更新已加载各页；窗口外消息不主动拉取完整正文。断线只恢复最近窗口与事件缺口，保留先前阅读锚点。

字段与状态的边界

新的消息 DTO 仅保留 content，不发送 content_json。任务摘要保留真实 task 状态和可用操作，不能把 executor 的 succeeded 当成验证成功。模型上下文、审计和原始记录仍使用既有仓库；不要为了加速 Web 删除历史、执行记录或压缩用户记忆。

普通 JSON 压缩

建议在 Go 出口按路由和 Content-Type 明确选择性压缩，先用 gzip，再比较 Brotli 的 CPU 成本。遵守 Accept-Encoding 与 q 值、设置 Vary，移除失效 Content-Length；已有编码不重复压缩，小响应跳过。动态私有 JSON 保持 no-store。

不对 event-stream、WebSocket、模型 token 流、文件下载、Range 和已压缩资源套缓冲压缩器；不得拖延 SSE 首事件和心跳。若外层已有压缩，先验证端到端响应头，避免两层压缩。压缩故障能独立关闭，分页仍然可用。

目录、刷新与索引

项目接口当前会遍历项目、列 worktree、解析仓库、关联会话并检查 Agent，且只有约 5 秒响应缓存。先返回最近快照和更新时间，后台单飞刷新；昂贵统计独立刷新，不让慢 swarms 阻塞已经返回的 projects。旧值须标记过期，错误不能清空列表或伪造实时状态。

新增轮询通过 pollWhileVisible，共享 in-flight，隐藏中止，失败退避；优先沿用已有事件和 useSessionOverview，不新增逐会话轮询。索引候选包括 events(task_id, kind, id)，须以实际查询计划、队列等待及写入成本决定；不在本轮盲目对所有库加索引。

行为与真实设备

覆盖父分支继承、工具配对、并发新消息、删除和 revision、分页交错返回、切换节点、logout、断线追赶、极长正文与加载失败。Android 真机用 ADB 点按和上滑验证阅读锚点、顶栏/底栏、安全区、键盘、草稿与恢复；CDP 同时断言内部滚动和文档无横向溢出。

实现时按影响范围执行仓库 quick/full 与前端完整门禁；Python 改动再同步运行其 lint、格式和测试。性能结论必须来自正式构建的相同数据与相同网络条件。减少请求数不等于减少 CPU 或内存。

发布与回退

先发兼容后端，再发新前端；按节点启用 Web 分页读模型，分别观测体积、超时、错误和队列。新页面契约失败时保留已加载内容并给局部重试；自动降级不能重新触发无界全历史。回退前端、分页读模型与压缩可以分开进行，原始数据不做迁移或删除。
