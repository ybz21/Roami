# 公网首次加载诊断与整改设计

2026-11-02，针对 `https://47.94.183.77:13579/` 的只读排查及本地整改实现。尚未部署。

[打开 HTML 设计文档](index.html) · [脱敏测量记录](records/measurements.json) · [验证与复测说明](records/acceptance.md)

## 本轮已实现

按用户确认，先完成轻量查询、滚动分页和详情按需读取；没有执行物理拆表。

- 主对话首批最多 50 条可见消息，上翻才读取更早一页。分支谱系、fork 截点、深链接和 SSE 游标保持一致。
- 消息不再重复返回 content_json；长正文返回短预览，点击后通过鉴权的消息详情接口取全文。活动不带完整工具输入输出。
- 任务、通知和记忆首批 20 条，滚动到列表末尾才续页；筛选在服务端执行。任务列表不逐条读取详情或完整指令。
- 未打开通知面板只读计数和水位；全部已读只推进到已观察的水位，不会吞掉之后到达的消息。
- 后续页单请求去重，超时可重试；切页、换筛选和隐藏时取消，静置与程序恢复滚动位置不续页。
- 原生会话复用已有 before 分页，增加顶部手势触发。记忆与原生会话原本已有服务端分页。

同一生产 SQLite 只读快照，旧消息响应 **4,266,688 B**，新首批 **57,800 B**，减少 **98.6%**；
任务 **221,133 → 9,990 B**，通知 **305,638 → 9,014 B**，通知角标 **36 B**。
这是响应量对比，不是部署后的公网耗时、CPU 或内存收益。详见 [实现记录](records/implementation.md)
和 [同快照对比](records/pagination-comparison.json)。

## 结论

首页主对话接口未分页，一次返回 847 条消息、162 个 turn 和 268 项 activity，共 4,266,688 字节。
相同接口在本机回环地址总耗时 241.5 ms，禁用系统代理后直连公网入口为 43,714.3 ms；
公网首字节为 306.3 ms，主要时间花在响应传输。前端数据缓存的 15 秒取消机制使首页无法拿到完整数据。
另一次经测量环境 HTTPS 代理的完整样本为 35,903.8 ms；浏览器也复现了 15 秒超时。
这些样本不代表用户设备的网络带宽或 p95。

主对话响应还同时包含 `content_json` 和解析后的 `content`。离线仅删除重复字段，
同一响应由 4,266,688 降到 2,541,905 字节；gzip 离线压缩为 755,235 字节。
这些是对同一响应的体积实验，不是已经上线的性能提升。

数据库确有多个文件，但都位于同一节点的统一 databaseRoot 下；主对话、任务、通知来自同一个
`agents/runtime.db`。没有证据支持合并数据库能解决这次超时。项目列表的 Git/tmux 聚合另有约
2.2–2.4 秒的回环耗时，应从首屏关键路径移出。

## Product Design

首屏只请求当前可见区域的一页，先展示可输入的对话框架和最近消息；较早历史触达顶部时读取，普通列表触底后续读一页。
未打开或未浏览到的内容不预取，静置不续页，不因首批不足一屏而自动连续补页。任务列表只带必要状态与摘要，
执行预览和完整指令进入详情。未打开消息面板时只读取未读摘要。辅助模块独立加载、独立恢复，
保留草稿和已加载内容。桌面沿用现有任务／消息／记忆工作区；手机沿用现有顶栏、四入口底栏和全屏二级页。

## User Stories

- 首次公网访问时先读到最近对话并可输入，不为全部历史等待几十秒。
- 上滚能连续读取更早历史；分支继承、工具调用与结果、实时消息均不丢失或重复。
- 非首页不读取主对话正文；消息徽标、项目导航与任务状态独立可用。
- 慢网和断线后保留草稿、最近快照及阅读位置，重试只作用于失败的模块。

## Technical Design

已实现：有字节预算的分页读模型、独立摘要 DTO 与显式列查询、滚动触发单页请求、SSE 摘要和详情按需读取。
后续 P1：普通 JSON 压缩、任务大字段纵向拆为 task_details、原生会话字段继续收紧、共享目录订阅、昂贵项目扫描异步刷新、终端模块按需载入。
P2：记录数据库排队与查询耗时，再按查询计划补索引；暂不合库、换数据库或扩大超时。

HTML 中包含 API 契约、分支游标与 SSE 一致性、模块职责、发布回退、验收指标及交互式传输预算计算器。
文档区分本轮已交付与后续目标；压缩、物理拆表、DOM 窗口化和项目扫描优化尚未实施。

## 列表与详情拆分补充

[HTML 专项设计](index.html#list-detail) 列出了任务、消息/活动、通知、记忆、原生会话和项目的字段边界。
任务优先：tasks 保留列表必需的身份、短标题、归属、状态和时间；task_details 通过 task_id 存完整
intent/target/budget，摘要与 revision 同事务维护。attempt 的完整结果后续按实测决定是否单独存放。
通知复用 events/messages 的事实源；消息已有 native payload 引用的部分继续复用，不重复保存正文。

列表不允许先 SELECT *、解析全文再截短或删字段，也不逐条调用详情组装器。
已有分页的记忆目录和原生会话仍需做字段精简，不能把它们描述成没有分页。
目标结构、回填与回退、详情增长不扩大列表的验收约束均已纳入 HTML。物理拆表仍待实测后决定，
当前 tasks 仍在原表内通过 JSON 标量投影提取短标题，没有假定大字段已经移出数据库页。

## 滚动后再请求分页

[滚动加载专项设计](index.html#scroll-loading) 覆盖对话、任务、通知、记忆、执行记录和长目录。
首次只读一页，聊天顶部取更早内容，普通列表底部取下一批。顶部下拉刷新与分页加载分开，
同一个触控动作不同时触发两种请求。

整改前主对话的 useAgentHistory 只对已经下载的数据切片；本轮已改用真实服务端分页。
整改须通过网络断言验证：静置不续页、触达边界一次只取一页、短页不自动扫完、同游标不重复请求。
隐藏/切页/换筛选时取消后续页请求，返回优先使用缓存和阅读位置；共享缓存沿用 16 MB 限制。
当前活动视图可随用户主动翻页继续增长，DOM 窗口化和活动视图内存上限仍是后续工作。
