# 任务提示词的精简结构

## 产品设计与用户故事

任务原文置顶，开工动作可直接执行，完成回报有可照填的四行格式。新建任务与派生任务共用执行/产物约定和能力说明，仅按工作区类型与回报通道补充必要差异。

- 新建 worktree 改占位分支和会话展示名；复用分支与续接任务保留既有名称。当前 session 用真实稳定 ID，执行标签显示 8 位。
- 六组能力各先一句话说明用途，再列少量基本命令；总览、分组、子命令帮助在开头统一讲一次。
- 受管任务由 Agent 的最终答复提交，宿主自动调用 Tasks.report 并回传原 Main；旧会话 JSON/CLI 与蜂群 post 保留实际绑定和命令。
- 普通受管任务的完整 task/run/Main ID 由宿主及私有上下文持有，不重复注入正文。Agent 需要发蜂群消息时再给完整协议字段，短显示 ID 不用于协议寻址。

## 技术设计

规范来源为 backend/api/prompts 中的六个 Markdown 文件。Go 返回固定执行约定与可编辑能力说明，Python 专业/原生执行器读取同源文件，wheel/sdist 与容器使用同一资源。自定义能力不覆盖，旧默认按已登记指纹迁移。

普通新建任务沿用本地化工作区简报。派生任务 managed_setup 按新项目、既有工作区、普通目录及续接选择开工动作。当前会话由真实启动回执注入；历史提示词格式和默认关闭的短标签开关保持原字节，保护回调、取消与恢复绑定。

帮助查询先于资源初始化。session fork 的完整边界说明放在其真实 --help；Chrome 根子命令和 record start/stop 的帮助直接进入只读帮助，避免把 --help 当页面操作执行。

## 长度与覆盖验收

以仓库原版 Git 29ad2179 重新生成对照，而非只和中间版本比较：

| 样例 | 原版字符 | 最终字符 |
| --- | ---: | ---: |
| 新建 worktree | 6375 | 2384 |
| 新建普通目录 | 6226 | 2252 |
| 派生普通任务 | 2347 | 3165 |

新建 worktree 减少 62.6%。派生模板因补齐开工命名、当前会话、回报方法与能力索引而比最早版更长；不把这一项描述为缩短。当前基础约定 631 字符，六类能力 1323 字符，分别只注入一次。用户正文、附件、路由、授权和蜂群数据按需增加。

覆盖核对补回会话复用、唯一 ID、任务资源清理、Roami 测试隔离、能力 schema 与未知结果不换请求 ID 重放等必要边界；详细操作教程和重复帮助不放正文。逐项证据、真实提交链路与新旧样例见 [覆盖核对](coverage-audit.md)。
