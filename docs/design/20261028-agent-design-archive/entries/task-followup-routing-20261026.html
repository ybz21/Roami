任务续办、完整交办与会话名称 · 2026-10-26

Product Design

对已有任务追加一句话时，原会话收到新增要求，不再重发旧目标、历史报告和能力说明。主智能体的改写不能增加用户授权；“代码合入”不能扩成发版或部署。主对话保留用户真正输入的消息，系统生成的续办记录留在执行审计中，不再显示成用户又发送了一条长指令；已存历史记录也按同一来源关系处理。独立的新需求另行交办，直接答复与框架修复同时提出时，两项都必须有去向，不能仅回复已记录或要求用户再次说开工。专业会话名称直接使用任务主题，执行器身份沿用现有独立展示。

User Stories

  • 用户追加要求后，在原执行器和会话继续，已有工作与审计记录保留。
  • 用户同时要求报告与产品修复时，可以分别拿到报告和真实任务回执；已列出的第二项不能被后续工具调用丢掉。
  • 用户看到“修复首屏加载”等具体主题，不会把内部能力提示、中括号和执行器前缀当成会话名称。

Technical Design

TaskRevisions 从当前用户消息提取原文，sourceQuote 可选取同条消息中属于原任务的精确片段；持久化 executionText 与 continuation.text，完整 goal 仅保留为任务账目。CodingExecutor 对已绑定会话只投递该增量与本轮完整性验证后的附件，首次启动仍提供能力与交付规范。Go Spec.title 独立承载任务主题，CreateOpts.Label 不从带系统前缀的 prompt 截取，也不添加执行器前缀。

request_coverage.py 校验主智能体声明的逐项原文、状态与同轮已接受的 taskId，并把清单存入既有 events；上下文重建恢复清单。已建立清单后不得遗漏原文项，待处理项阻止结束回复和 requestComplete=true 的最后交办；实际任务回执将 current 转成 delegated。旧工具调用保持兼容，新指令要求每次交办与答复提交清单。清单不能证明模型从未漏识别意图，需结合真实模型验收；不使用关键词拆任务或额外分类模型。

每次交办只绑定一项独立需求，sourceQuote 与该项原文一致；已接受项不能被改回待办后重复派发。同一项目的另一项已核对需求可直接创建独立工作区，不等待旧任务续办完成；原会话、目录与明确复用的工作区仍防重复写入。清单以带轮次前缀的 event_key 写入，读取使用现有唯一索引，不扫描整段对话事件，也不新增轮询。
