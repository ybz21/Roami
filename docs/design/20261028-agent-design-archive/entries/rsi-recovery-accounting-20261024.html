RSI失败恢复与预算 · 2026-10-24

Product Design

开发版Workflow可分别配置Main、Worker和记忆的模型/推理强度；空值继承现有角色默认。Case不再因前序任务占满共享额度而完全没有启动机会。历史题目和失败记录不覆盖。

User Stories

维护者看到预算拒绝、实际取消和模型失败的不同证据。已知调用只结算一次并归还未用额度；对已结束的未知调用可本机显式隔离，保留全额预留及证据，不把未知费用算作零。新独立测试使用剩余额度，原请求不能重放。

Technical Design

Run角色配置 → 冻结路由与模型hash → Case启动预留 + 共享总池
MeteredModel：逐次推进绑定请求ID → 明确本地拒绝 / 供应商响应 → 关闭并结算
Operation：running → completed（实际结算） / unknown → 本机显式quarantined（全额保留）
新题：公开字段类型 / 费用与滑点 / 分页元数据 → 新合同 → 独立判定

operation_accounting统一新付费操作的准入；隔离只接受未知终态和本机证据，不提供Web绕过。measurements和model_gateway显式关闭异步流，避免ContextVar跨任务重置；executors在原期限内等待已运行的维护作业。containers公开有界输入文件目录，不提供隐藏判定数据。正式每日60项与连续观察不变，校准不足仍不计产物通过。

单次输出额度修订：Main和Worker独立配置，空值按角色模型、上下文窗口和Case/整轮剩余预算逐次分配；未配置模型上限时保留一半可用额度给后续步骤。RequestBudgetModel在创建供应商前校验两层余额，计量仍由Case和整轮各自记录一次；本地拒绝不能伪造未知费用。框架实跑优先使用OpenCode与DeepSeek Flash，Native的20项机制在无网络容器逐项验收；评分校准及未知账目仍保持独立门禁。

Native专项执行合同修订：容器请求明确指定内置Native Worker，允许如实报告复杂任务，并用当前请求中的原文形成explicitExecutor与userQuote。此前禁止显式Native选择会让合法的复杂任务进入不存在的专业CLI发现；v4执行器指纹保留这项环境变化，不将旧失败记录改成通过。生产路由规则及明确执行器的来源验证不放宽。Worker的通用交付指令同时要求对视觉产物做可用的本地渲染，检查SVG文字边界和遮挡；无法渲染时保留验证限制。

Worker执行环境修订：普通bash命令使用非登录shell，继承已准备的PATH及虚拟环境；避免登录配置覆盖渲染依赖。回归测试运行PATH中的真实可执行文件，并确认未读取登录profile。显式argv仍允许调用者选择登录shell。

2026-10-25实证：Native机制20/20通过；真实CODE-01通过独立检查，79,420 Token/16次请求，Main/Worker自动输出额度超过8192并随余额变化，过程仍保留TASK_RESULT_REQUIRED与WORKSPACE_REQUIRED恢复记录。OpenCode加deepseek-4.1-flash完成真实文件创建、3项独立测试、重复启动幂等和原对话续接，成功轮42,958 Token/8次请求；本轮含两次失败尝试共169,683 Token，全部结算。前端966项及生产构建通过；桌面7档宽度、中英深浅主题与Redmi真机确认保存、键盘、滚动、返回及44px按钮命中区。原10项的两份产物仍待独立评分，人工参考分未确认，Issue #446未关闭；合同修订不作为旧题收益证据。汇总证据位于/tmp/roami-rsi-continue-report/，未部署现用服务。
