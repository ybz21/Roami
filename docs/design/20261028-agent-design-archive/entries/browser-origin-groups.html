人工与智能体浏览器分组 · 2026-10-22

产品设计

浏览器页面统一归入人工、智能体两组。默认来源为智能体，包括 CLI 和无法追溯来源的历史页面； 界面新建显式传 origin=human，用户可在页签菜单更改分组。查看页面不改变来源。创建来源单独永久记录，后续移组不改写创建来源。服务重启保留记录；Chrome 完全重启按恢复快照延续分组和来源，新页面重新计时。分组、固定和休眠状态持久化。 桌面标签条与手机全屏二级页提供同一组切换和菜单，手机分组栏固定、页面列表独立滚动，休眠页保留标题和地址，选中即唤醒。

智能体组默认共享最多 20 页（可配置），默认空闲 2 分钟休眠、10 分钟关闭，满额优先回收闲页；人工组默认空闲 30 分钟休眠， 自动关闭默认关闭。设置中分别配置两组的休眠和关闭时间，0 表示关闭该策略；输入完成后失焦或回车保存，保存后立即生效，校验失败保留输入。 休眠冻结页面执行并保留页面状态，减少后台运行；关闭才释放页面。不能把冻结宣称为内存释放。

前台、固定、任务占用、人工接管、运行中或结果未知的操作，以及未提交表单、文件选择和媒体播放受保护。 无法确认安全状态时跳过自动处理。旧页面第一次登记从当前时间开始计时，不在升级时立即清空。 用户主动关闭仍为显式行为；更改分组不取消任务租约或未知动作保护。

用户故事

  • 我从界面打开的工作页面自动归人工组；Agent 和终端创建的页面归智能体组，不混在一条长列表中。
  • 我能把 Agent 找到的有用页面移到人工组并固定，刷新或重启后仍保留归属。
  • 后台闲页自动休眠，Agent 的过期结果自动关闭；人工页面默认保留，可自行开启超时关闭。
  • 运行中的任务和未完成的输入不会被回收；休眠页再次使用时先恢复执行。

技术设计

internal/browsertabs/catalog.go       唯一来源目录、跨进程文件锁、原子 JSON 与分组策略
backend/browser/tabs.go               显式来源创建、修改来源/固定、列表元数据
backend/browser/automation/           CLI 默认来源、使用与操作记录、休眠/唤醒、安全维护检查
agent-runtime/executors/browser_tabs.py 发现全部页面，复用资源租约与持久操作回执处理两组生命周期
agent-runtime/migrations/0010_*       分组、保护标记、策略时间与维护动作类型
frontend/components/mirror/           分组标签条、手机列表、移动分组与休眠状态
frontend/components/settings/        两组策略表单；中英文本纳入全局 i18n

目录保存于节点 data root 的 browser-tabs.json，通过 Go 统一访问，按 browserId+targetId 定位； CLI 驱动通过本机隐藏目录事件入口登记，不依赖公开 HTTP 或登录。目录不存页面正文和凭证。 Python 保留唯一回收循环；未绑定任务的 CLI/历史页也登记为可管理资源，活动资源沿用既有租约隔离。 冻结、关闭均记录唯一操作 ID，未知操作不重放；维护预约阻止来源变更与新操作竞争。 CLI、界面和现有浏览器重启恢复同步来源；缺失来源回落智能体，不能用 URL 猜来源。

验收计划

验证默认来源与界面人工标记、历史页登记、目录重启/并发/落盘失败、分组迁移与固定、两组阈值、CLI 活动和未知结果保护、 休眠后实际冻结及唤醒、原生任务与历史页共同容量。运行仓库 full 和前端全部门禁；使用隔离服务、真实 Chrome 和 Android 真机验证界面， 截图保存在 /tmp，不部署到现用服务。
