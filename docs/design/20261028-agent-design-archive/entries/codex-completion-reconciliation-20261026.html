Codex 完成回报与观察恢复 · 2026-10-26

Product Design

Codex 真实完成后回报主会话，交付物与未完成的验收一起呈现；不能长期停在“待对账”或把执行器自述直接变成用户验收通过。已有工作的结果未知时先对账，不重新派发。

User Stories

用户从主会话取得 Codex 的最终总结与 PR 链接。观察恢复时，状态自动更新；再次失去观察时仍明确提示。真正未结束的工具或后台写进程继续阻止完成确认。

Technical Design

session-code-mode.go 仅识别原始已绑定 Codex 进程的直接子进程：可执行文件必须与同安装目录的 codex-code-mode-host 为同一文件，父子 PID 启动标识与原绑定一致。它可作为 TUI 的常驻辅助进程继续存在，其子进程仍按原规则阻止任务完成；同名程序、其他目录、其他提供方和 PID 复用不接受。

session-codex-completion.go 在已有状态查询中恢复丢失的完成回报，不增加轮询或重发输入。只读取已绑定 UUID 的唯一、本机所有者持有、不可全局写入且无软链接的 Codex 会话文件；上限 64 MiB，活动记录先检查至多 256 KiB 的末尾。完整对账核对会话、目录、最后回合、原始请求 hash、所有工具调用的结果、final_answer 与 task_complete，以及读取前后文件身份和时间。终止、其他输入、未完成调用或不一致记录保持未知；原始转录不修改。

确认后以已有私有原子写入记录 completion-source.json 和 result.json，仍执行进程停止与取消检查，再交给 Python 原有 report、verify 和 Main completion 流程。该转录回退按当前 Codex 0.164.0 的实际记录验证，不宣称跨版本私有格式稳定。正常回调仍沿用 OpenAI Hooks 的回合与工具身份字段。

CodingExecutor 对 unknown／running 的真实状态转移各发一次活动事件，恢复后再次未知仍有事件，不修改任务的验收结论。前端既有 task.* 投影直接接收，无新增界面、产品文案或请求。

验证记录

隔离进程测试覆盖可信辅助进程、同名冒充、其他提供方、PID 标识变化和真实工作子进程；转录对照覆盖不同会话／回合／请求、缺失工具结果、其他用户输入、非最终回复、终止、重复文件、软链接、可全局写入、截断及证据冲突，保留原未知和取消保护。真实会话先进行零模型只读校验，再通过限定执行键的正常查询恢复回执，未重跑 Codex。原任务已进入 waiting_user，主会话补发最终总结，原 PR 保持草稿，未将未完成的真机验收记为通过。
