浏览器标签池与回收 · 2026-10-21

产品设计

Agent 新建的标签页按浏览器实例共享最多 20 页；用户自行打开或仅被 Agent 借用的页面不进入回收池。 任务释放页面后保留 10 分钟供查看结果，空闲超时自动关闭；容量不足时按最早空闲顺序提前回收。 活跃任务、人工接管、未知动作及当前前台页面不被自动关闭。全部页面受保护时明确报告容量不足，不抢占任务。

用户故事

  • 作为用户，我能让多个检索任务使用最多 20 个 Agent 标签页，不会因旧的每任务 3 页预算过早失败。
  • 作为用户，我完成检索后仍能短暂查看页面；无人使用的结果页随后自动释放浏览器内存。
  • 作为正在接管页面的用户，我的页面保持打开；后台回收不能切换焦点或关闭我的其他标签页。
  • 作为服务维护者，我重启 Agent 后仍能核对旧页面和关闭回执，避免重复关闭或按变化后的标签序号误操作。

技术设计

protocol/browser.py             默认 max_tabs=20，允许 1..20；idle_timeout_seconds 默认 600
storage migration               持久 browser_tabs，记录来源、使用/空闲时间和关闭操作回执
executors/browser_tabs.py        浏览器实例内的容量核对、空闲 LRU、关闭及重启恢复
executors/browser_driver.py      创建时持有浏览器 context 租约并登记新页；定时触发回收
 dispatch/resource_leases.py      获得/释放控制权时更新使用与空闲时间；关闭中不可重新认领
browser/automation/driver.mjs    精确 targetId + browserId 关闭；回收专用后台页检查，不抢焦点

仅成功创建回执确认的 target 加入池；旧版本页面从成功创建回执补登记，不按页面 URL 猜所有权。 并发创建通过现有 context 租约串行，计数覆盖全部任务的托管页面。关闭前在同一数据库事务中验证空闲、无绑定、无未知动作且未接管， 写入关闭中的隔离状态和唯一 operationId，再执行带持久回执的无重试关闭。页面已消失只清账；身份变化不对另一实例发送旧关闭。 关闭结果未知时保留隔离，后续只核对原回执和稳定 target 是否存在，不重新发送关闭。已知失败退避后再评估。 标签池未变化时，重复满额开页沿用持久失败记录结束重试；释放并回收出容量后允许继续。

验收计划

测试覆盖第 20/21 页边界、跨任务总量、空闲超时与压力 LRU、活动/接管/未知动作保护、用户页面排除、外部关闭、 并发创建、关闭失败及重启恢复；独立 Chrome 验证前台保护和精确目标回收。运行仓库 quick / full 门禁，截图保存在 PR 图片分支。
