Agent 升级与模型预设 · 2026-10-22

产品设计

能力页 Agent 卡片提供“升级”和“模型”直接入口；管理详情保留版本、程序位置、终端和启动命令。升级遵循当前安装方式，原生安装的 Claude Code 与 OpenCode 使用原生升级器，npm 安装的 Claude Code / Codex / Pi 更新原安装前缀；无法识别的安装方式显示终端升级提示，不另装一份冒充成功。显式确认后升级，成功重新读取实际版本，失败保留原目录。

模型页按 Agent 管理服务商预设，填写名称、服务地址、API 协议、模型、API Key 或环境变量引用。保存与应用分开，应用只修改原生配置中对应的连接和模型字段；保留 MCP、插件、hooks、权限、其他服务商及注释。密钥只写不读，留空保留已存密钥。显示实际生效状态和外部改动，不把保存预设当成调用已成功。支持恢复首次应用前的连接与模型字段；每次应用先备份，失败回滚，配置发生外部变化时保留表单并要求重新读取。应用影响后续启动，已有会话由各工具自行处理，不自动重启。

桌面沿用详情弹窗中的模型区；手机在同一 URL 详情的全屏二级页展示，单返回栏、单滚动区，编辑区和保存动作遵循既有安全区与键盘规则。OAuth 仍在各工具终端登录；不代理协议、不复制订阅令牌、不提供未实现的自动故障切换。各工具只接受已验证的原生协议。

用户故事

  • 我能升级当前真正使用的程序，并看到更新后的版本；不会因原生安装与 npm 并存而更新错程序。
  • 我能为不同 Agent 保存多个服务商与模型预设，确认后应用，切换后重开终端使用。
  • 我能恢复原连接和模型；其他工具配置和登录资料保持可用，失败不会清空输入或谎报已切换。
  • 我在手机上可以编辑、保存、应用和返回，API Key 不会在列表和重新打开的表单里回显。

预设位于当前节点 data root 的 agents/professional/provider-presets.json，不使用公开偏好存储保存密钥。所有写入均为临时文件 fsync 后原子替换，文件 0600、私有目录 0700；预设、单次请求和原生文件均有体积上限。API 只返回 hasKey 和白名单字段，原生解析错误不回显文件内容或密钥。

原生路径尊重 CLAUDE_CONFIG_DIR、CODEX_HOME、XDG_CONFIG_HOME、OPENCODE_CONFIG、PI_CODING_AGENT_DIR。Claude 变更用户 settings.json 的模型与认证环境变量；Codex 变更 config.toml 的模型和受管 provider 表，保留 auth.json；OpenCode 区分 V1 / V2 的 provider 字段；Pi 写 models.json 和默认模型 settings.json。服务端修订值防止陈旧页面覆盖新配置；应用前生成私有恢复记录，多文件写入失败按已写入内容比较回滚，恢复时仅还原托管字段。
