RSI冲突恢复与预算证据 · 2026-10-25

Product Design

文件冲突返回明确的恢复步骤：重新读取、核对当前内容和hash后修改，保留其他人的编辑，不用shell绕过校验。诊断运行同时记录原题额度和本轮实际分配额度，避免把共享预算压缩误判为原题预算不足。

User Stories

Worker误用新建模式或遇到并发修改时，能读回最新内容后继续完成原任务。维护者能区分Token、调用次数、时限和未知用量阻塞，而不是只看到委派失败；失败仍阻止成绩通过。

Technical Design

ToolGateway对FILE_CHANGED补充恢复指令；仅文件写入冲突标记writePublished=false，源hash校验保持原样。模型侧图片文件read仅返回hash、大小和分页元信息，contentOmitted=true，不把base64字节当作可视输入塞进模型上下文；底层WorkspaceFiles读取和受控视觉观察保持原有接口。Worker指令要求自行读取现有文件；无图像观察能力时使用DOM、布局和行为检查并报告限制。PipelineRunner在evaluate产物中保存每个Case的原始／有效limits、已知用量、共享上限和后续Case预留。evaluation_tasks只从当前修订的最新失败Attempt提取四种已知预算错误，ContainerExecutor保留该根因；任意模型文本仍只产生通用失败。

产物路径识别同时支持Markdown加粗、中文括注、真实换行及模型输出的转义换行，避免把说明文字并入路径或遗漏README；仍使用原有工作区和文件类型边界。

版本绑定修订：同一任务、修订和Attempt的Main完成回合如果通过文件工具修正了产物，TaskDeliverables按成功工具回执中的sha256创建新的私有快照，保留旧版历史。文件内容不匹配回执时拒绝发布；其他任务的回合、未记录的外部修改以及已删除产物不能借此替换或恢复。使用文件线程池校验暂存内容，不增加后台轮询。

定向112项通过，包含两次文件冲突及并发修改保护、图片元信息与底层原字节接口、当前修订预算根因保留、任意错误文本隔离、原始384,000／有效268,000额度证据，以及加粗路径的两份文件持久交付。上一轮DEMO两项补测实际分配208,000而原题为384,000；已纠正PR #448及Issue #446中的“原Case上限”说法。完整384,000额度下DeepSeek轮仍失败，用量323,370，保留失败；图片元信息修订后以GLM Worker和180,000诊断额度完成，118,408 Token／18请求，容器外硬检查通过、质量待评。路由与额度不同，不据此宣称同条件收益。使用真实生成文件做零模型调用的交付适配器回放，HTML和README在工作区删除后仍可按原hash读取。评分校准仍要求人工参考分。
