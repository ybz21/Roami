## 产品设计

指挥就是现有 Roami Main，绑定发起它的普通 Main 对话。Main 理解目标、拆任务、选择执行器、协调、安排验收并向用户汇报。成员可用 Codex、Claude、Roami（native）及已注册的 OpenCode、Pi；复用既有 Tasks、执行批次、验证与修订，不另开 Claude 指挥。

桌面、手机使用同一套入口：

| Tab | 内容与动作 |
| --- | --- |
| 协作 | Three.js 等距工作室、Main 与成员状态；工位和 DOM 成员列表联动选择 |
| 群聊 | 绑定 Main 的回复、用户消息、成员讨论和当前结果；用户可给 Main 补充，也可回复原任务对应成员 |
| 看板 | 待办、进行、受阻、待审、完成；点击任务查看说明、验收标准、依赖，进入原任务的结果与执行现场 |

切换保留草稿、接收人、选择、页签和滚动位置。群聊显示未读数量，看板显示受阻数量。桌面任务详情内联，手机用 MobileSubPage；任务说明默认收起，完整结果沿既有任务详情查看。手机软键盘弹起时让位并隐藏非必要页头，发送按钮保持可见；回车只换行。

新群目录、项目入口、搜索、CLI 都只读取新服务。旧 SVG/CSS 办公室、广场、手动拖卡片、Claude 指挥接管、旧 Go swarm 存储/编排包、旧启动模板和旧 CLI 已移除。历史库的版本化 schema、备份与已有文件不做破坏性删除，既有会话按普通会话保留。

## 用户故事

| 需求 | 实际行为 |
| --- | --- |
| 并行完成项目 | Main 提交成员计划与验收标准；无依赖项走既有受管任务派发 |
| 指定不同执行器 | 每个工作项保留 executor；缺安装、认证或能力时显示阻塞，不换执行器补跑 |
| 看卡在哪里 | 群聊回到原 Main；看板保留真实任务状态、依赖与错误详情 |
| 修改刚才的部分 | 指定成员的消息续派原任务，保持 revision、executor、workspace 与 session 亲和性 |
| 等上游再集成 | 指定 task revision 验收通过才解锁；整合项覆盖所有工作后才能整群完成 |
| 收尾 | 暂停只停新派发，停止走取消与停止证据，归档只整理展示；资源关闭沿用原任务收尾入口 |

执行器自称完成只进入回报/验收，用户不能手动拖到“已验收”。unknown、失败或旧版本结果都不能被动画显示成成功。

## 视觉与动画

原生 Three.js 0.180.0、正交相机、几何机器人、桌面和屏幕。工作时低幅敲击、呼吸与屏幕变化；真实状态变化触发短消息粒子。材质从现有主题 token 读取，主界面使用 --bg-base、单边分隔线和既有 composer，不增加全页外卡片。

Main 的工位状态来自真实 Main turn；成员来自当前 Task/attempt。关闭动画、系统减少动画、静态终态按需绘制；隐藏页签/页面停止连续渲染。WebGL 失败保留 DOM 成员、群聊和任务，并提供重试。最多展示 24 个工位，成员列表保留全部成员。

桌面 DPR 上限 1.5、手机 1；手机关闭实时阴影，目标为桌面 60fps、手机 30fps。这些是预算，尚未完成生产前后 CPU/内存与真机规模性能对比，不能据单次渲染检查宣称达标。相机聚焦和大规模聚合未实现。
