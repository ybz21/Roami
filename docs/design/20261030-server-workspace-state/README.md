# 工作区会话跨端同步

## 产品设计

打开的会话、排列顺序、当前会话与文件标签由当前节点后台保存一份。桌面、手机及新浏览器读取同一个工作区；地址只表达页面与筛选，不再携带 `terms`、`active`。独立终端深链继续使用已有路由。

手机保留全屏会话覆盖层，切换器先展示“已打开”列表；只挂载当前可见会话、仅探测该会话的渲染状态；打开另一个会话不再清空共享列表。后台同步不主动打开覆盖层或唤起键盘。显式关闭标签会同步到其他端，但不终止 tmux 会话。

## 用户故事

- 桌面打开多个会话后，在手机或新的浏览器打开普通地址，能看到相同列表。
- 两端同时打开不同会话，都保留；一端关闭某标签，不覆盖另一端刚打开的标签。
- 刷新、切换节点或后台重启后，仍恢复该节点的工作区。
- 关闭全部标签后，旧书签、本地缓存或另一台设备不会自动复活旧列表。
- 网络异常保留当前操作，显示简短反馈，自动重试；页面切到后台时停止读取，回到前台立即同步。

## 技术设计

- `backend/api/workspace.go`：每节点 `workspace.json`，互斥锁串行修改、临时文件原子替换，递增 revision；独立于整份覆盖的 preferences，避免设置写入覆盖会话状态。读取损坏文件报错，避免静默清空。
- `GET /api/workspace` 读取，`PATCH /api/workspace` 提交增量批次：新增、关闭、排序、选择会话及文件变更。排序只调整仍存在的标签，保留其他端新开的标签。服务端校验选中项仍存在。
- `frontend/src/app/workspace-state.ts`：一个在途同步请求，乐观变更队列覆盖在已确认快照上；同步成功后移除对应批次，失败保留并重试；相同快照及会话身份表保持引用，避免目录刷新重启终端状态请求。连续同步操作合并为一批写入。
- `useWorkspaceState.ts`：复用 `pollWhileVisible`，可见时每 5 秒读取轻量状态，隐藏时暂停，失败退避至最多 60 秒。会话目录继续复用现有入口；工作区不按会话请求。
- `useTaskWorkspace.ts`：维持现有交互接口，将会话名称映射为稳定 ID 保存；成功读取目录后移除已消失的 ID。手机与桌面共用列表，覆盖层是否展开只属于当前设备。
- 首次迁移：等会话身份读取成功后，后台 revision 为 0 时导入旧 URL 或按节点保存的本地状态。服务端在锁内只允许首次 seed 生效；已有工作区（包括空列表）优先。成功后删除该节点旧本地副本与 URL 中的 `terms`/`active`，保留其他筛选与 history state。后续不写会话本地存储。
- 节点切换只修改节点选择与路由，不再把本地会话列表填进 URL。浏览器/手机镜像的“新页面打开”使用普通路由。
