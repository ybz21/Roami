产品设计

OKR 不是每个项目自动附带的页面。首页只显示已确认保存的目标；新建时才选择关联项目，不为普通项目创建空目标。目标详情首屏先回答：要达成什么、哪些 KR 已达成、真实数据怎么变化、下一步做什么。净增目标按净增展示；绝对阈值按当前值判断，文案2/2不再被周期变化0掩盖。

两个主标签分别是「OKR 与看板」和「具体活动」。看板内用总览、数据记录、复盘切换视图；默认把 KR 并排，展示目标比例、最新值与可核实的日变化，下方是指标趋势和复盘后的下一步。原始记录、来源、同日版本和填数表单不占首屏。趋势使用真实日期；漏采留空，单日只能称基线。

用户故事与交互

用户为 Roami 宣传新建目标，选择项目后点击「聊目标」。首次发送才建立新的 Main Agent 会话，带入本页从真实服务读取的项目、目标、KR、指标日期与复盘快照，再讨论 KR 和指标；用户确认后才能保存。它不复用首页主会话、不建立常驻任务，每次重新打开是独立实例，结束只停止自己的对话。桌面采用本页分栏，不依赖全局检查器的折叠状态；中小屏用全屏二级页。对话保存新目标后，未改动的空搭建页自动切到看板；已有输入时提示新版本，由用户选择是否采用。保存后首页出现这个目标，其他未设目标的项目继续不显示。

用户切到「具体活动」，看到该目标关联的原始蜂群、同一任务板和同一群聊，不复制另建一个群。成员执行、回填后，看板按修订更新；复盘决定下一轮动作，再回蜂群执行。搭建态可与 Main Agent 讨论，运行态通过真实 Swarm 工作；没有关联群时明确提示去配置。

技术设计

新增 GET /api/okr，由 project-okr 存储批量投影已保存目标，返回每个KR当前来源下的基线、截止日前最新值与相邻日期增量，不逐项目请求、不返回整段历史。排除已删除项目。前端首页按可见状态轮询，保留上一份成功数据。

独立对话复用已有 /agent/conversations、messages 与 SSE 契约，首次发送创建、失败以同一请求键重试、输入保留；先确保首页单例已有绑定，再创建独立会话；不向首页会话发送消息，也不改Python runtime、模型路由或费用设置。蜂群只在活动标签激活时挂载，嵌入模式可见时批量读取共享详情、任务与群聊，切走取消请求，隐藏时暂停。其余写入沿用原来的修订冲突和证据快照。

文件与共享工作目录

目标详情增加第三个标签「文件」，与「OKR 与看板」「具体活动」并列。用户在看板确认方向，切到活动查看蜂群执行，再到文件查看同一项目目录中的计划、脚本和产物，随后回看板复盘。以 Roami 宣传为例，目标对应项目目录，X 文案、B站脚本和制作素材保存在其中；看板反映结果，文件呈现实际交付。

默认使用项目目录，未加载目录时不回退到服务器主目录。复用 FileBrowser 和 FileView：桌面并列目录与预览，手机点开文件进入全屏二级页，返回文件列表。首次进入才挂载；切换主标签保留当前目录、打开文件及编辑状态，非激活或页面隐藏时关闭预览的刷新与重型渲染，不新建文件副本或另一份存储。实现位于 OkrProjectFiles.tsx；FileBrowser 新增兼容的 active 属性传给既有 FileView。
