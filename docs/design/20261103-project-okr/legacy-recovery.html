旧蜂群恢复：升级后仍能查看项目历史

2026-11-04。修复项目活动页在新蜂群上线后反复报连接失败的问题。

产品设计

已设 OKR 的项目仍保留原团队引用。进入“具体活动”时，旧引用打开成员、任务卡与群聊历史，明确标注只读且未经当前验收；不会把旧 done 标签转换成新系统的验收结果。

“关联执行团队”打开本项目 OKR 配置，保留未保存输入。用户可选择新执行团队并确认绑定；查看历史不会自动建团队或发送模型请求。新的项目工作区只提交项目 ID，由原生执行器解析工作目录，修复新建团队参数冲突。

用户故事

我升级 Roami 后，宣传项目的活动页仍能看到原来的 4 名成员、6 张任务卡和 11 条群聊。原有脚本和文件还在，我可以核对之前的计划。记录里说“完成”不代表视频已制作或已发布；这些结果要由具体文件和回执验证。

我想继续执行时，点“关联执行团队”，回到 OKR 配置选择实际团队，再保存。新团队使用新的 Main 和任务机制。旧历史不会伪装成正在运行的新团队。

技术设计

模块责任
ProjectOKRLegacySwarm受现有鉴权保护；只读取当前注册项目已绑定的旧团队，校验项目目录相同，不接受任意文件路径。
历史来源当前连接的 meta.db 中 swarm_members / swarm_cards 保存成员与任务；同一数据库根目录 swarms/ID/swarm.db 保留 posts。中心表为空时兼容老组库的 members/cards。
只读快照有界复制旧组数据库与 WAL 到私有临时目录，再用 SQLite mode=ro/query_only 读取；不打开原库的 SQLite sidecar。拒绝符号链接、跨项目、读取中变化、超限文件。缺失部分来源显示可取得的记录。
前端恢复旧 ID 直接读项目历史；受管 ID 的 404 停止循环重试并提供恢复入口。其他连接错误保留正常退避和显式重试。历史与受管快照使用不同类型，不合并完成状态。

验收与边界

独立实例重现升级前错误；测试数据包含 4 名成员、6 张任务、11 条消息。桌面与 Redmi Note 8 真机验证详情展开、内部滚动、关联配置入口和无文档/横向溢出。历史接口测试覆盖 WAL 中未 checkpoint 的消息、原 DB/WAL 字节不变、跨项目及符号链接拒绝、缺失来源与旧结构兼容。

完整 Go 门禁、前端 typecheck / i18n / hover / build 通过，前端 180 文件、1276 测试通过。补充触屏热区和简化文案后重新执行相关前端检查。Python未变，按 PR 完整差异确认后跳过其检查。

此补丁恢复历史查看及新团队准备参数；不恢复旧原生蜂群调度，不自动迁移完成声明，也不宣称 @leader、共享记忆或视频发布已由本补丁交付。它们属于项目 OKR 的后续统一方案。
