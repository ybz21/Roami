团队与群聊合一页

2026-11-04：接续 PR654 的界面优化。进入具体活动就能看到团队，也能立即交流。

用户如何使用

  1. 打开项目的具体活动。桌面同屏显示团队工作室、真实分工和共享群聊；手机先显示同一团队的对话入口，可在当前页展开团队。
  2. 点 Main、成员或工作室里的智能体，查看对应的交流。群聊显示全队消息；Main显示协调对话；成员视图按实际taskId选择该任务的投递、汇报与交付，不把其他任务混成此人的对话。
  3. 所有交流仍来自团队共享记录，不表示新增私人消息或隐私边界。切换对象保留草稿正文并同步开头@提及，不自动发送。
  4. 点“进入会话”，按需读取原任务，核对当前修订、运行和会话关闭状态；专业成员进入其真实会话，内置成员进入其真实nativeSession。关闭、身份变化或缺少会话时回到原任务详情，不创建空会话充数。原任务页的补充要求继续通过宿主控制。
  5. 未派发的成员只能查看计划或向Main调整；不会假装已有可执行对话。看板保留独立入口，桌面可以边看任务边交流。

布局与状态

桌面手机
左侧团队/看板、右侧群聊，两个模块同底、单条分隔线，各自滚动。成员关系和工作室保留，场景不再占掉整个对话空间。对话区域占据主内容，群聊/Main/成员可以直接切换；团队在同页按需展开，点成员后收起团队回到对话。键盘避让和上下栏沿用现有Material规范。

旧的“群聊”页签偏好迁入协作页，保留草稿和收件人。隐藏团队、离开协作、打开记忆时释放Three.js场景。状态、任务板、群聊和完整会话使用原宿主身份，不新增后台智能体或轮询每个成员。

实现与验收

ManagedSwarm负责组合工作区与选择成员；SwarmRelations/SwarmStudio保留关系和动画。SwarmChat按真实taskId组织共享记录，并通过现有任务详情API按点击获取完整会话身份。代码与UI控制不改变任务验收、成员权限或外部发布边界。

验收覆盖同屏布局、群聊/Main/成员的消息归属、草稿保留、未派发计划、关闭/改变运行时不进入旧会话，以及桌面四档、真实手机展开/滚动/命中/键盘。以实际浏览器和真机结果补录，不以单测替代触控验收。
