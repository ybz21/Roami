每种文件如何使用

定义展示与执行
okr.json目标、KR、指标、方法、周期及关联团队。用户确认后的配置驱动页面；模型可以按目标动态决定数量和组合。
dashboard.json注册组件 keyResults、metricTrend、nextAction；组件顺序、选择哪些 KR/指标由定义决定。React 渲染为 HTML，并非写死一张业务看板。
connector.json 与代码GitHub 内置采集器实际读取公开仓库 star/fork。manual 指标由授权成员观察真实账号后记录日期、数值和来源。导出的 Go 代码解释运行实现，修改参考代码不会偷偷执行。
Main 配置与 skillmain.json 列出真实 SKILL.md 路径，main.md 给出协调约定。目标对话可读取这些项目能力，团队上下文携带相同说明及内容摘要；不是放三个没人读取的空目录。
团队绑定、记忆和运行态swarm.json 关联既有团队；共享同一任务板和群聊。记忆保留事实与决定，宿主记录实际任务/run、控制和验收状态。配置或执行器自述不替代交付证据。

动态聊出来，再按确认的定义执行

  1. 用户给出目标，例如“宣传 Roami，提高 star 和 fork”。按需 Main 读取当前定义和已有事实。
  2. Main 提出 KR、短期实验、X/B站方法、指标与看板绑定。完播率、观看时长、曝光与点击先确认账号、口径和来源，缺数不填零。
  3. 用户确认后，受管项目工具带当前 revision 保存；文件和页面使用同一份定义。文件编辑中的草稿与已确认版本分开。
  4. 已支持来源通过实际 collect/record 写入日期事实；具体内容工作接入既有 Swarm。观察、准备、上传、提交、审核与公开分别记录。
  5. 人看真实结果作决定，Main 再提出下一轮方法。目标对话按需创建，关闭时只结束该实例；没有调度器就不宣称已长期日更。

任意脚本 connector 的自动运行、自由 HTML 脚本看板及模型任意改系统配置均不在当前能力中。先把现有定义、数据、素材和团队真正组织起来。
