受管浏览器本机文件上传

先让受管成员完成真实执行：专业 Codex 成员复用 roami chrome，为浏览器文件输入框提供一个实际本机文件。沿用现有标签身份、场景检查与持久操作回执，不增加调度器。

用户故事与验收边界

用户需要行为
把已有 MP4 放入投稿页明确 target、文件输入框 selector、绝对路径；选择一个可读的非空普通文件，保留原文件名及 SHA256。
受管成员可控原生入口必须有准备好的任务工作区；源文件规范路径限制在该工作区。专业终端可用可选 file-root 收窄到已授权文件根。
网络中断后不重复上传同一 operation ID 只派发一次，payload 冲突拒绝；unknown 只查原回执及页面状态，不换 ID 重新执行。
明确知道做到了哪里成功仅表示文件已选入页面；页面可能自行上传，必须继续观察服务器反馈。选择、上传完成、投稿提交和公开可见分别验收。

CLI 与运行时契约

roami chrome upload 'input[type=file]' /absolute/video.mp4 --target TARGET_ID \
  --operation-id STABLE_32_HEX --receipt-root PRIVATE_DIRECTORY \
  --expected-browser BROWSER_ID --expected-scene SCENE_SHA256

可选：--file-root /absolute/workspace --max-file-bytes BYTES
      --expected-file-sha256 SHA256

browser_act({kind:'upload', selector:'input[type=file]', path:'/workspace/video.mp4', sha256:'64位摘要（可选）', observationId:'...'})

上传必须选定稳定 target，不能回落到第一个标签或自动启动新的 Chrome。只接受单文件；目录、相对路径、不可读文件、超出 file-root、源文件变动及摘要不匹配都在输入前失败。先创建私有文件快照并流式计算摘要，再让 Playwright 选择快照；Roami 按块做快照和摘要；当前 Playwright CDP 传输要求文件小于 50 MiB，显式上限还会与现有文件大小配置取更小值。这是当前传输限制，不是投稿平台限制。

技术结构

driver.mjs 的 upload 动词复用 executeVerb / pickHere、目标 CDP 和场景签名；file-upload.mjs 负责源文件检查、受限路径、私有快照及选择结果元数据。原 OperationReceipts 仍负责 once-only 派发和 unknown；输入后的异常不能被归类为已知未执行。

Python 的 browser 工具 schema、紧凑输入 schema 与 BrowserDriver.act 仅增加 upload/path。传递任务绑定的工作区根与现有文件大小设置，经原有 ResourceLeases/operationId 完成动作。不会改 Swarm 调度、registry、模型路由或取消流程。

验收

使用专用 headless Chrome、临时用户目录与本地 HTTP 表单，真实执行 Playwright 文件选择及 multipart 上传，核对文件名、字节数和 SHA256；第二个标签不得改变。另测缺失/相对/越界文件、场景改变、重复 operation ID 和选择后未知结果不重放。

验收不连接用户 Chrome、Bili、X 或手机；本地表单通过不能当作平台投稿已完成。Bili 登录仍是后续实际任务的前置条件。依据：Playwright setInputFiles 官方契约。
