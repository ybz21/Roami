# 普通回复预览与问题卡交付

## Product Design

普通最终回复生成时展示逐段更新的预览，通过审核后交付最终消息。问题参数校验通过后直接展示可选项。

## User Stories

- 用户等待回复时可以看到模型已生成的内容。
- 用户需要补充信息时可以立即看到问题和可选项。

## Technical Design

Agent loop 将普通文本增量接入现有 `ReplyStreamPreview`。预览沿用现有事件、节流和清理流程。当模型改为调用工具时，按工具批次更新或清除预览。最终答案仍由现有回复处理器审核和交付。

`ask_user` 保留工具参数及选项校验，移除同步模型审核。工具完成后沿用现有 question 消息发布路径。

结构化回复首次审核保留独立原文阅读。同一轮次改稿时，按完整用户原文和模型配置复用已读取的结果，每份新草稿仍单独校验。

## Acceptance

线上只读回执显示，问题参数完整后执行耗时 55.6 秒。来源阅读、字段抽取、问题判定依次完成后，问题卡随即发布。

运行时回归覆盖普通文本与显式回复在模型结束前出现预览、审核后交付，以及问题直接结束回合。43 项定向测试通过。

结构化回复改稿回归验证，首次拒绝到改稿通过共三次模型调用，原文只读取一次。字段值误带字段名时可本地拒绝，修正后才调用最终判定。

## 聊天消息恢复

用户截图对应回复在 09:13:46.489 完成，服务端保留完整 message.started、message.delta、message.completed，通知页读取到完成正文，聊天页仍显示旧状态。尚未在用户手机复现造成 SSE 漏收的具体连接故障。

首页通知的完成事件游标领先聊天快照时，触发一次历史补齐。页面恢复可见或 pageshow 时失效缓存、读取最新快照，并关闭旧消息流后从快照游标重连。复用现有请求合并与重连退避。

12 项定向前端回归通过，包含通知先收到完成事件、聊天流漏收及前后台恢复。前端全量 226 个文件 / 1620 项测试通过，typecheck、i18n、hover 和生产构建通过。

真实 Redmi Note 8 通过 LAN 加载实际 useAgentThread 的隔离探针。模拟服务端回复完成而 SSE 不投递完成事件，显式派发可见性恢复事件后，正文出现、状态转为 completed，读取与消息流各从一次增至两次。ADB 执行了 Home 和返回 Chrome，但调试中的 Chrome 没有产生可见性变化，自动前后台恢复仍以回归测试验证，未宣称在真机自动触发成功。这是数据恢复探针，未验收完整应用手机导航。
