# 压缩状态反馈与按需查看上下文

## 产品设计

输入 `/compact` 或选择压缩动作后，首页仅显示「正在压缩」，结束后改为「压缩完成」。状态行可点击查看上下文；失败、取消、不需要压缩和状态未知保持各自含义。详情关闭后继续保留最新状态，不自动展开压缩摘要。

手机将上下文详情作为全屏二级页打开，使用统一返回栏和一个内容滚动区。桌面继续使用现有详情弹窗。保留手动压缩、取消和失败重试入口。

## 用户故事

- 发起压缩后继续看对话和编辑草稿，不被自动弹出的长摘要打断。
- 压缩结束能看到明确状态，需要时点击查看上下文。
- 阅读摘要时内容不定期消失，滚动位置不被重复挂载打断。
- 完成事件早于命令回执到达时，界面保持完成；失败不能显示成完成。

## 技术设计

原 `AgentConversation.loadPanel` 在上下文弹窗打开期间每 3 秒轮询，每次调用先执行 `setSummary('')`，随后重新读取同一快照；这使 Markdown 反复卸载。`/compact` 的命令回执同时会自动打开弹窗。

- `AgentCompactionStatus` 在输入区前显示一行状态与「查看上下文」动作，使用现有快照和 SSE 更新，不增加状态轮询。
- `useAgentThread.accepted` 接收压缩命令回执，立即投影操作身份；同一操作的 SSE 状态已经到达时保留它，避免晚到的 queued 回执覆盖 completed。
- `AgentContextDetails` 仅在用户打开详情时加载上下文和摘要，移除原来的 3 秒轮询。结束状态变化时可以刷新用量，同一 snapshotId 不重复读取摘要，也不先清空已显示的内容。
- 详情读取带 AbortSignal，关闭或切换后忽略迟到响应；详情按节点、会话与分支重新挂载，历史分支查询带 branch 参数。错误保留已加载内容并提供显式重试。
- 移除输入卡内重复的压缩提示；手机首页的上下文查看复用 `MobileSubPage`。原始聊天、压缩算法、模型配置与定时策略不变。

新增文字使用中英文 i18n；控件复用设计令牌、现有 SVG 图标和 44px 触控高度。
