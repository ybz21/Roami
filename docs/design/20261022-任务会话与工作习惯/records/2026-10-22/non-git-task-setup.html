无 Git 项目开任务修复 · 2026-10-22

产品设计

开任务和新建／派生会话按实际目录检查 Git，不依赖项目列表的旧状态。未初始化或没有首次提交时显示短提示，保留直接在目录开工的能力；用户可显式确认将当前文件保存为首次提交，遵循现有 .gitignore，成功后开放 worktree。失败保留任务与 Agent 选择，提供重试。

用户故事

新项目用户能在同一表单初始化 Git、保存项目快照并创建含现有文件的独立工作区；已有空仓库用户能补首次提交；不需要版本管理的用户可直接开工。

技术设计

backend/worktree/repository-setup.go 负责目录探测、初始化和首次快照，以目录锁及现有仓库锁串行写入；有提交的仓库幂等返回，不提交后续改动。GET /git/is-repo 增加 hasCommits 与 root；POST /git/initialize 显式修复。RepositorySetup.tsx 在任务表单共用检查、确认及恢复状态，过期目录响应不能覆盖新选择。remote-base.go 在无任何远端时验证并使用本地分支快照；有远端继续 fetch，失败不回退旧快照。任务目录刷新复用 pollWhileVisible。手机顶栏新会话按钮显式无参调用，防止点击事件被当作目录。

验收计划

验证未初始化、空仓库、有提交、忽略规则、失败重试、幂等与子目录边界；真实新 worktree 包含项目快照，原有远端拉取与失败保护通过。前端覆盖确认／取消、检查失败、任务内容保留与正确提交路径，执行仓库门禁、桌面与 Android 真机触控验收。
