RSI 结果与详情交互修复

Product Design

保留工作流、运行结果与 Issue 三个 Tab，以汇总为入口，单个 Case 展开显示原生评分及原阈值、参考比较和未评分项；基线与候选结果分别展示。工具、工作区文件与模型用量放在折叠的执行记录中，原始 JSON 仍可打开。没有执行的判定不显示零分，未知用量不显示零消费。

工作流默认打开正在执行或失败／阻断的环节，直接显示可理解的原因和重试前需要处理的问题，原错误码保留在执行记录。选择另一轮运行会清除上一轮手选的环节；切换 Tab 或运行回到内容顶部，不沿用旧详情的滚动位置。产物进入后立即显示加载或本地读取失败，关闭／切换运行后不被旧响应重新打开，重试保持原来源运行。设置返回时保留草稿并显示继续编辑和放弃修改；没有开启共享网关时不声称已经生效。

User Stories

  • 我先看 Case 汇总，点击状态或展开 Case，就能核对失败得分、原要求和各轮结果，不必先读原始 JSON。
  • 我打开工作流能直接看到阻断环节及原因，待评分、未执行和未知状态不会被描述为已通过。
  • 我关闭一个正在加载的产物后可以继续操作，不会被晚到响应跳回旧内容；读取失败时可在当前详情重试。
  • 我从设置返回后知道为何暂不能启动评测，并能继续原草稿或放弃修改。

Technical Design

模块职责
useRsiArtifact.ts管理产物请求序号、节点和运行绑定、加载／错误／原始请求状态；关闭、卸载、切换来源或打开内联证据后旧请求不能写回。
RsiCaseEvidence.tsx只读呈现 native_judgment、双 arm 结果与执行记录；有限的原生得分原样展示，未运行判定不伪造分数，工具和文件默认折叠。
RsiWorkflow.tsx、rsi-error-message.ts按实际阶段选中阻断点，已知错误翻译为恢复提示，未知错误保留可核对代码；阻断后不提示自动进入下一阶段。
RsiWorkspace.tsx连接产物状态、切换运行时清空阶段选择、未保存草稿提示和配置状态；结束运行仍不轮询，读取失败不伪装重新执行操作。
RsiRunResults.tsx、rsi-results.cssCase 展开挂载结构化证据；零状态计数隐藏，汇总使用按可用宽度换列的网格，覆盖后加载的通用样式，清除换行后错误的分隔线。沿用设计令牌与中英语言包。
