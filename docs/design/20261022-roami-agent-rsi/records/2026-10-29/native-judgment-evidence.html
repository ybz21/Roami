Product Design

判定器已经返回实际分数、门槛、备选参考比较和部分分值，但进入 Case 汇总后仅剩通过或失败。保留这些有界数值，使既有 Case 详情证据、免费汇总和 Codex 复盘能说明差多少；视频和音频的实际输出文件名也进入既有文件证据。结果、质量分、问题状态和验收门槛不改变；没有新增页面、按钮或 RSI 配置。

User Stories

  • 我能从现有 Case 证据查看实际原生分数及门槛，而不只看到“未达标”。
  • 我能区分零分、尚未执行、原生部分分值与未评分分值；备选参考分别记录，不借用另一轮或另一评测臂的分数。
  • 复盘使用与详情相同的数值；不能根据执行器的成功陈述或某个原生分值为 1，把仍失败的任务改成通过。
  • 我能在文件证据里看到已生成的 MP4／WAV 文件名。保留既有所有者隔离与旧记录，原始参考和判定器输入不进入模型提示或公开报告。

Technical Design

模块职责
evaluation/native_judgment.py纯数据提取，保留有限且在范围内的原生分数、门槛、参考数组、部分／未评分点数、固定范围和结果哈希；过滤隐藏参考、诊断文本和无关字段。布尔值不充当数值，未知不补零。
evaluation/trial_evidence.py将判定写入现有 native_judgment Case 字段；未运行媒体判定器时不展示观测分数，未运行 PPTX 比较时不声称参考不匹配；媒体后缀加入原有文件列表。
workflows/pipeline_reports.py现有免费汇总／公开报告指标 JSON 带原生判定，Codex 复盘也收到同一字段。配对运行分别记录各臂，不借用主结果。
presentation/run_results.py 与现有详情复用既有 owner 检查和选中轮次 caseEvidence；现有“证据”动作即可查看，不修改前端组件、样式或文案。

不修改判定器、原始 Case、质量门槛或状态计算，不新增数据库迁移、模型调用或付费重试。技术字段按国际化标准的协议字段例外保留英文。历史缺失分数不回填原行；实际产物可在无网络只读沙箱重新判定，将补充证据单列归档，并核对原文件、Case 行与轮次总结不变。
