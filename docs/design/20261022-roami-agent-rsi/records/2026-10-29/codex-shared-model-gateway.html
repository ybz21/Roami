RSI 设计修订与验收记录

Codex 复盘接入统一模型网关 · 2026-10-29

Product Design

RSI 的 Codex 复盘、问题分析与修复提案使用模型页已有的模型连接和每日限额。用户继续使用当前 Codex 模型，网关模型目录中的同名项或唯一同后缀别名承接请求；找不到或存在多个匹配时明确阻断，避免换成别的模型。全局 Codex 配置和个人凭据保持原状。免费运行总结先行保存，模型分析失败时仍可读取。

User Stories

  • 完成 Case 后，我能看到运行汇总和真实 Codex 复盘，按原工作流查看每个阶段的结果。
  • 我只维护模型页每日额度，RSI 不再从个人连接绕开限额，也不新增独立 Token 配额。
  • 额度拒绝、实际失败和未知用量分别留证。原来用量未知的付费操作不自动重放，正确完成的回执可以离线复用。

Technical Design

integrations/codex_responses.py 负责纯文本 Responses 请求及 SSE 事件；integrations/codex_gateway.py 负责模型别名、一次性本地认证、宿主提供方与计量。workflows/codex_roles.py 继续负责调用和幂等，persistence 中的原操作账与零消费拒绝归档继续负责持久化。model_calls.py 将既有 Settings 传入 Codex；PipelineReportWorker 由 Runtime 注入当前配置读取器，避免复制设置或凭据。

适配范围是 RSI 明确禁用工具的单轮 JSON 分析角色。客户端 additional_tools 是工具目录声明，可以识别并略过；函数调用、工具输出、图片、继续已有 response 和后台存储请求均拒绝。输出按 response.created、文本增量及 response.completed 发送；工具事件、流中断或缺用量不生成成功终态。接口依据为官方网关兼容要求与Responses 事件参考。

每次操作只监听本机回环随机端口，使用独立临时令牌，子进程仅拿到该令牌；Go 密钥与个人提供方密钥不传入子进程。请求仍通过既有 configured_provider 发送到 Go 网关，沿用其认证和账目。每个桥接实例只允许一次模型请求，取消或超时后关闭监听与连接。Go 的 402 拒绝在没有文本、工具或用量事件时可按零消费归档；发生过输出或计量不完整时保留未知，不据相同错误码猜零消费。未认证的本地探测不覆盖合法操作结果。

request_model.py 可分别标记实际配置角色和观测角色，Go 请求标记为 rsi_codex_review、rsi_codex_issue 或对应修复角色。私有 gateway-usage.json 保存关联标识、模型、脱敏错误和宿主用量，不复制提示和输出正文。完成回执保留 CLI 自报值，但实际统计采用宿主回执，缓存 Token 不重复计数。请求身份包含节点连接配置和适配协议；已完成回执复用时无需重新拉模型目录。旧冻结协议仍可回溯，现用共享模式缺少节点配置时明确失败。

验收记录

真实安装的 Codex CLI 0.164.0 已使用脚本化宿主提供方完成完整单轮，获得合法 JSON 与 123 输入、7 输出 Token 的回执；没有外部模型推理。实际客户端发送 additional_tools 目录声明，初版因此拒绝；修订后仅接受该声明，函数调用仍被拒绝。另以事件屏障证明首段文本在模型生成结束前到达客户端。

定向检查覆盖唯一模型匹配、密钥隔离、无网关禁止回落、真实 CLI、严格终态、CLI 与宿主计量不一致、未知操作禁止重放、402 零消费拒绝后恢复、单实例禁止重复发送、未认证探测隔离和旧协议；完整门禁及真实网关复盘的结果随本次 PR 留证。旧完整轮次的未知付费操作保留，不以新操作编号重复提交相同复盘。新生成的局部轮次可继续其尚未执行的报告阶段，Case 原成绩和独立评分状态保持不变。
