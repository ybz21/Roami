RSI 设计修订与验收记录

超时运行的工具证据恢复 · 2026-10-29

Product Design

Case 超时后，汇总仍应展示已经记录的工具调用，供逐轮排查和 Codex 复盘使用。已确认失败的 Case 保持失败，未完成的工具标为未知；恢复出来的记录明确标注覆盖不完整和内容截断。不能把日志存在当作执行完成，也不能把日志缺失当作没有调用工具。

User Stories

  • 我能展开超时 Case，看到已经执行的工具和错误，而不是空列表。
  • 我能区分数据库记录总数、实际恢复条数和截断字段；进行中的操作没有被冒称成功或失败。
  • 恢复失败时，原始超时原因仍保留；原数据库、Case 成绩和费用不改写。

Technical Design

evaluation/execution/interrupted_evidence.py 提供一次性运行时数据库提取程序及元数据验证，属于评测执行层，不访问 RSI 账本。ContainerExecutor 先按身份停止原容器，再把只读状态目录复制到无网络、只读根文件系统的沙箱内，从私有副本读取 SQLite 和 WAL。已有有效执行日志直接沿用；缺失或写入中断时才恢复。原状态目录不写入，不在宿主打开数据库，符号链接不穿越宿主边界。

提取限定十五秒、两千条工具记录、每字段四千零九十六字符及四百万字节记录预算，并设置 SQLite 指令进度上限。保留数据库总数、恢复条数、截断标志和原始状态；未终结的调用转为未知。截断参数保留调用标识，避免相同前缀被当作重复工作。没有完整 trace 的快照保持 complete=false。

恢复文件保存在容器未挂载的宿主 Case 根目录，权限0600。trial_evidence.py 使用既有路径验证读取日志，拒绝跨目录符号链接，兼容旧的完整日志和部分 JSON 写入；恢复失败写入独立错误，工具数量保持未知。behavior_review.py 标识中断覆盖，不能通过完整日志门禁；pipeline_reports.py 将覆盖信息交给 Codex。原评分、主失败原因、模型用量和禁止重放规则保持原义，不增加模型调用。

验收记录

原音频轮次超时后，runtime.db 仍有八十条工具调用，原运行汇总的列表为空、数量未知。通过冻结 v31 容器的只读副本恢复八十条记录：九次委派、七十次 Bash、一次工具查询。原 Case 记录和数据库／WAL 哈希不变，恢复视图仍为失败、覆盖不完整；长参数截断被明确标记。该验证没有模型调用或重新评分，证据为 /tmp/roami-rsi-interrupted-audio-proof-20261029/proof.json。

三项受控反例在旧 c807b29c 代码下失败，覆盖没有日志、日志写入中断及目录外日志符号链接；修订后通过。定向七十二项通过，包含真实容器读取 WAL、数据库只读、字段与条数截断、恢复失败保留超时、未知工具状态及旧日志兼容。完整门禁与合入记录随本次 PR 留证。未重跑旧失败或未知费用操作，也不据此宣称音频质量或完整六十项已通过。
