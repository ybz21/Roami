RSI 请求来源与统计筛选

Product Design

模型与连接的“代理与计费”页增加来源筛选：全部来源、RSI、其他与未标记。周期汇总、每日/分时趋势、模型明细与最近记录一起筛选；顶部今日用量与每日限额始终包含所有来源。没有来源证据的历史调用不能被断言为正式业务，不猜测回填或抹除历史消费。

User Stories

  • 同一个模型承担日常任务与 RSI 验收时，我能分别核对请求、Token、费用和错误。
  • 旧 RSI 请求即使角色写作 main/worker，只要保留 RSI 会话标识，也能正确识别。
  • 最近记录先筛选再取二十笔，较早的 RSI 请求不会因为较新的其他请求而消失。
  • 我切换来源时保留限额、价格和日期草稿；旧来源响应不能覆盖当前选择。

model-proxy-settings.tsx / model-usage-statistics.tsx复用统计栏的下拉控件、中英语言包及现有令牌；来源切换取消旧请求，无新增轮询；服务端必须回传相同来源，旧节点忽略筛选时显示读取失败，可切回全部来源恢复。响应与请求来源绑定，等待或失败时隐藏其他来源的统计和最近记录，保留全来源今日摘要和设置草稿。
local-model-gateway.ts保留 API 来源；旧回执按角色/会话元数据兼容识别。金额仍使用原纳元累加，未知和在途费用不补零。
