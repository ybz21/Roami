RSI 沿用底层模型配置

Product Design

用户要求 RSI 不自行定义模型，统一走节点已保存配置。此前开发脚本已停用，但生产链路的 Codex 复盘仍将 CLI 模型映射为其他上游模型并覆盖推理参数；独立评分按 profile 另选路由，执行器也强制把重试设为零。这些行为改为由底层配置决定：复盘用 Main，评分 A／B 分别用 Main／Worker，生成和记忆沿既有角色路由，不改模型、参数、能力、重试或超时。冻结历史协议继续保留，用于重放已有受控夹具；本轮不发付费验收。

User Stories

  • 模型页选择的模型就是 RSI 实际调用的模型，CLI 名称与 profile 不能另选上游。
  • 两个评分模型未独立或图片能力不足时，在调用前明确阻断，不临时挑模型、开能力或假装评分通过。
  • 旧模型的回执不能冒充新路由结果，未知操作不重放；不需要独立评分的 Case 不被无关的评分 profile 阻塞。

Technical Design

模块职责
integrations/codex_gateway.py、workflows/codex_roles.pyCLI 模型只用于 Responses 协议身份，实际请求完整使用 Main 路由；不查模型目录、不接收 CLI 推理／输出覆盖。持久操作绑定和网关身份升级 v2，旧回执继续留存并阻止错误复用。
evaluation/artifact_review.py、app.py、workflows/pipeline_runner.py每日策略的评分 A／B 绑定已保存的 Main／Worker，复用每个角色的完整参数、限额与图片能力，保留双模型独立及校准校验；provider 工厂按同一角色收费与记账。原 profile 路由仅服务冻结历史协议。原生判定 Case 不加载无关评分配置。
entrypoints/cli.py校准证书保存不含密钥值的模型路由快照；离线安装校验证书快照，真实加载仍与当前节点路由逐项核对。缺少新快照的旧每日策略证书不能通过安装器冒充新校准。
evaluation/execution/containers.py、executors.py每日策略拒绝临时角色路由、参数和输出覆盖，保留底层重试／超时；Case 总超时仍由执行外层约束。模型指纹升级，原语料和判定门槛不变。

验收记录

使用脚本模型与本地 HTTP 协议回归，不连接付费上游、不保存节点配置、不改变生产用量账目。验证范围包括 CLI 别名／请求字段不能覆盖实际上游 JSON、评分角色完整路由与能力、旧证书失效、容器提前拒绝临时覆盖、重试／超时保留，以及原生 Case 跳过无关评分配置。既有未知计量和操作防重放继续验证。269 项相关回归通过；旧代码在 21 项新测试中有 17 项失败，恢复新版后通过。初始两个测试将“评分 hash 为空”的既有快照结构误写为整项为空，修正断言后全量定向通过；保留首次日志。实际节点零调用核对：CLI 协议模型为 gpt-6.1-sol，实际上游完整使用 Main 的 deepseek-4.1-flash、reasoning_effort=low、重试 2，不查询模型目录；Main／Worker 都是保存的同一模型且 Worker images=false，独立评分在调用前以 MODEL_IMAGES_UNSUPPORTED 阻断。没有创建 provider 或保存配置，原 Case／成绩／未知账未改写。初版 full 2,099 项通过；整合主干 #492 后，full 2,113 项 Python、Go 全量、前端 typecheck／i18n／hover／生产构建及秘密扫描通过，运行时版本 09487ede。v41 冻结镜像的 180 个核心及入口文件逐项匹配，离线启动模型调用为零、Worker 视觉上下文不创建。该预检不使用图片能力覆盖；初始离线脚本按关闭能力的真实行为调整断言后通过。没有运行付费推理或恢复旧未知操作。英文新增内容为内部协议说明，不新增产品界面文案；未部署服务或宣称 Android 真机验收。
