有效模型配置与执行时长

Product Design

独立验收复用正式服务对保存模型配置的解析，包括自动读取上游上下文容量。容量有显式配置时沿用配置，元数据不可用时保持未知，不猜容量。Worker 每次调用可见本次尝试的实际已用时，仅在已有真实截止时间时显示剩余时间；不增加任何执行上限。

User Stories

  • 我在模型页留空容量后，正式服务和独立验收得到同一种自动解析结果。
  • 我能确认验收没有另设模型、参数、能力、重试或固定上下文容量。
  • Worker 能看到本次执行进度；排队和此前尝试的耗时不计入本次尝试。

Technical Design

providers/model_capacity.py 提取既有 ModelSettings.resolve_capacity 的实现；server/model_settings.py 的异步 load_runtime_model_settings 先读取原保存配置，再复用同一容量解析。同步加载接口和正式服务启动顺序保留。路由、凭据环境、参数、图像能力、超时、重试不变；不持久化元数据、不创建推理请求。routing_exam.py 改用该入口，并移除原固定200000容量兜底和请求超时覆盖；受控任务执行夹具保留。

containers.py 分别传递 main_image_input 和 worker_image_input 的启用状态及图像规格，参与运行指纹；container_agent.py 在独立的角色路由上严格验证元数据，不携带真实连接或密钥。先固定 Worker 路由再应用 Main 设置，防止 Main 已开启时通过默认回退暗中开启未指定的 Worker。新增 org.roami.rsi.model-image-input=1 功能标签：Main 图片开启时拒绝不支持的旧镜像；Main 关闭时旧 Worker 图片协议仍可兼容，不强制启用任何能力。当前保存的 Main=true、Worker=false 分别继承。

dispatch/runner.py 将本次已写入数据库的 started_ms 传给 NativeExecutor，避免使用更新前的行。executors/native.py 传递该时间和已有预算中的 deadlineMs；旧调用无开始值时使用执行入口时间，不读取排队创建时间。context/execution_timing.py 校验时间并计算非负秒数；prompt_builder.py 每次重建时附加一条临时系统消息，记录到既有提示清单，不写入对话或压缩快照。时钟位于提示末尾，保留前面历史的缓存前缀，静态 requestBasis 不受秒数变化影响；实际请求哈希仍包含真实提示。时钟不能替代交付证据或改写原任务。

历史验收范围修订

v43至v46旧启动器调用同步保存值加载接口，没有执行正式服务的自动容量查询；保存容量为空时传入容器的仍为空。此外，旧协议只传递 Worker 图片设置，容器中的 Main 图片保持关闭，即使主机侧保存为开启。此前主机侧路由名称、参数、能力、重试的保存值继承证据保留；Worker 图片设置准确，但不能据此宣称容器整体能力及自动容量与正式运行一致。当前只读上游目录公布主/后台容量均为1048576，保存值仍为空；不追溯修改旧清单、成绩或计量。当前元数据不能证明历史服务当时的返回值，也不能证明这些遗漏导致音频超时或消耗。

真实音频v44仍为原1800秒超时，168笔已知请求、21086016 Token；只读原产物核验0.10964499711990358，低于原0.8。此修复不重跑付费Case，不把信息补齐宣称为质量或耗用改善。
