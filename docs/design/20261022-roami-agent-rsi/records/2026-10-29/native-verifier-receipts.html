RSI 原生判定回执与独立检查

Product Design

进程退出成功不等于获得有效评分。媒体判定器缺少分数、回执损坏或超时时，保留未完成判定，不再补零；真实零分仍显示零。CSV 或原生检查点异常不能阻止幻灯片和讲稿各自完成检查。失败依旧失败，未评分项依旧未评分。

Case 详情把“尚未执行 / Not run”改为“未完成判定 / Evaluation incomplete”，准确覆盖未启动和已启动但没有有效回执的情况。沿用既有折叠证据、布局和令牌，不新增配置或界面操作。

User Stories

  • 我能区分真实零分与没有有效分数，不会把判定器异常当作已经完成的质量测量。
  • CSV 无法读取时，我仍能查看幻灯片、讲稿、远端交付及源文件保护检查。
  • 判定器异常不会泄露隐藏参考的异常正文，也不会把历史失败改写成通过。

Technical Design

模块职责
evaluation/benchmarks/media_tasks.py判定回执要求 JSON 对象中显式存在有限的 0–1 数值，拒绝布尔值、字符串及缺失结果；超时返回失败的退出检查。verifier_result_valid 与退出状态分别记录，缺少有效回执时不生成 native_metric。
evaluation/native_judgment.py完成有效判定同时要求成功退出与有效回执；新失败标志阻止补零进入 Case、免费总结和后续复盘。已有未带新标志的历史证据保持兼容。
evaluation/benchmarks/stock_tasks.py原生检查点异常保留 scored_points=null，所有八项未评分；解析失败与比较未完成单列失败检查，继续独立检查图表页和讲稿。正常的严格相等、数值容差、列类型及行顺序要求不变。
i18n/locales 与既有 Case 详情中英同步修正未完成状态文案；没有增加样式、图标、组件或布局分支。

验收记录

旧代码下 17 项媒体回执检查及 4 项真实容器 CSV 检查失败；修改后 91 项相关检查通过，覆盖有效零分、缺失/非法/非数值回执、超时、Case 详情 API、免费汇总、CSV 空文件/解析错误/编码错误及检查点异常。前端 1062 项通过。完整门禁、最终生产包桌面和真机验收随 PR 留证。

在无网络、复制工作区的只读重验中，新旧代码对同一历史产物给出相同结果：视频 0.625、股票原生 0/8 且 7 项未评分，仍失败。原文件、Case 行与运行快照/总结逐项保持原样，没有追加历史回执或重放原操作。现有 v42 镜像只提供判定器依赖，不宣称本轮当前核心的 SUT 能力验收。

本轮没有选择或覆盖模型、发起真实推理、修改节点设置、降低阈值、修改隐藏参考或部署现用服务。媒体原生判定脚本与任务原文仍按原冻结哈希校验。证据入口 /tmp/roami-rsi-verifier-receipts-proof-20261029/，界面测试数据位于 /tmp/roami-rsi-verifier-ui-20261029/；真实任务质量和独立评分仍保留未完成状态。
