失败模型请求的上游编号

Product Design

模型HTTP失败或重试时，执行记录保留该次响应已有的合法上游请求编号，供按编号查证；错误正文仍不读取、不进入回执。

User Stories

  • 我能拿到401的上游请求编号，而不只有本地发起编号。
  • 重试的每次编号与尝试次数一一对应；没有编号或编号非法时不猜测。

Technical Design

providers/chat_completions.py 先发送既有headers遥测回执，再按既有HTTP状态处理。沿用X-Request-Id/Request-Id与原来的1–200字符白名单，不新增错误正文、模型参数或费用字段。headers事件仍是telemetry，不作为模型内容输出，不改变已配置的重试/退避，也不把未知重试用量变成已知。外层错误仍为DomainError与502。

验收记录

新增9项旧代码全部失败，修复后83项相关检查通过。覆盖401/403/429/503/重定向、合法及非法编号、错误正文禁止读取、两次503后成功的三次编号与未知重试用量。完整门禁通过：Python2261项（无跳过）、Go全量、前端typecheck/i18n/hover与生产构建。

本代码验收0真实模型调用，没有修改保存模型配置、参数、能力、限额、重试、历史记录或部署。历史401若当时未保存编号，不能补造，也不能据此宣称上游根因已解决。独立音频验收继续使用固定的v44 Core与原测试代码；此修复不会替换正在运行的代码。没有前端组件或产品文案改动。
