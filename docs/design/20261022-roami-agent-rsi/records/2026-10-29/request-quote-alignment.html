原文引用的换行对齐与交办恢复 · 2026-10-29

Product Design

用户原文按 Markdown 折行，Main 引用相同文字时常合并换行；这不应阻断交办。只对齐空白差异，保存原始用户消息里的实际片段。文字、大小写、标点、路径和反引号仍须一致，不能接受改写或扩大授权；原文范围仍遵循既有引用长度上限。错误恢复提示按当前工具的真实接口说明参数；单份产物的路径、格式和验收条件随该需求保留，不能拆成多项重复交办。

User Stories

  • 同一段文字仅换行不同，仍能正常交办，审计中保留原始换行。
  • 交办失败后不会被提示添加接口不接受的字段；续办仍保留原任务与会话。
  • 另一用户或会话的消息、已接受需求的重复交办、改字或改路径仍被拒绝。

Technical Design

层职责
storage/request_quotes.py纯文本空白对齐，映射回原文范围；优先保留已有需求清单的原始引用身份。
storage/request_coverage.py先验证当前轮次、所有者和会话，再核对原文、重复引用、历史清单与实际回执；不原地改写调用参数。
tools/main_catalog.py续办的可选 sourceQuote 与已校验引用仅允许空白差异，最终投递原始片段。
tools/request_coverage_recovery.py分别说明交办、续办与回复的参数，不再要求 delegate 填 sourceQuote；未知外壳操作采用条件式说明。
context/prompt_builder.py明确独立需求与产物约束，说明续办字段归属；不增加分类模型或按关键词拆需求。

验收记录

只读沙箱核对原音频数据库：八次失败交办中三次使用了不受支持的 sourceQuote（顶层或需求项内部），其余原文引用校验失败，最后一次才接受。数据库和 WAL 哈希不变，核对没有模型调用。

两次经原 Go 网关的独立 Main 参数恢复探测共 11,366 Token，未创建任务或执行 Worker。旧提示返回了不支持的字段；仅修提示后，字段已正确但仍把原文换行合并为空格。最终复用该真实模型参数，旧校验拒绝，新版空白对齐后验证通过，保留实际原文范围，追加模型调用为零。这是参数恢复证据，不是音频质量通过，也不据一次对照宣称费用或耗时收益。

定向七十一项通过，涵盖续办、重复交办、保留清单、所有者与会话边界、原引用长度和初始上下文预算；六项旧版反例失败，新版通过，既有重复引用保护保留。首次提交门禁因提示扩大导致上下文回归失败（此前通过 1,162 项）；修订后压缩说明，相关回归通过，旧失败日志保留。最终镜像沿用冻结 v31 依赖层，核对六个运行时文件哈希。完整门禁、新镜像和 DEMO-02 独立复测的结果随 PR 留证。原成绩、未知费用操作和现用节点设置不改写，不部署现用服务。
