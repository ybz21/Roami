RSI 设计修订与验收记录

Worker 多图对照上下文 · 2026-10-29

Product Design

高推理视频实验反复读取两张联系表，但每次请求仅附最新一张图片，无法在一次模型请求中对照它们。对已读的工作区文件保留最近六个不同路径的快照，同一路径重新读取会替换旧版本。数量与既有六个附件上传名额一致；多图共用既有角色的图片编码字节预算，超出时等比缩小，最小图片仍放不下才省略最旧来源；不增加 RSI Token、请求数或模型配置。

这是一项图片输入能力修正，其对重复读取和交付质量的影响须独立验收。高推理实验最终遇到 Worker MODEL_HTTP_401，视频和音频均未运行原生判定，不能把它们当作零分或多图方案的效果证据；已知生成用量下界 2,101,227 Token，总量未知，原操作不重放。原生证据修复另在 #491 验收。

User Stories

  • 我可以对照几张帧图、图表或页面，不必在两个图片之间反复切换。
  • 同名但不同目录的文件分别保留；同一路径的相对、绝对写法归为同一个来源，重新读取后只使用新快照。
  • 删除、遗忘、无效或失败的新版本不能恢复成同路径的旧图；当前最新回执不可信或不可用时，不借用旧图声称成功。
  • 只有当前可见回执、当前活跃任务与运行中的图片能进入模型。图片仍是不可变工作证据，不提供界面操作权限。

Technical Design

模块职责
tools/workspace_images.py沿现有文件根校验派生规范的工作区相对路径；在私有 artifact 的 sourcePath 与 fileImage.path 回执记录同一身份，无效或偏移读取也标记路径；有作用域的读取失败保留原错误码与失败状态，同时标记不可用路径。
context/workspace_images.py分别负责真实回执校验、图片组合及可见来源选择。最近路径先去重再校验，无法使用的新版本也占用该路径身份，避免恢复旧版本；最多六个来源按原顺序组合进一个瞬时模型消息。无路径的历史回执保持单图行为。
context/image_preparation.py纯函数 prepare_image_bundle 接受最新优先的图片，保留来源索引，校验 Base64 合计字节；从原始数据重采样，记录原始尺寸，不累计有损处理；无法容纳时优先保留最新有效图。
context/chat_images.py、conversation/attachments.py、protocol/image_limits.py既有上传允许六个文件，模型上下文原先只查询三图。统一图片数量常量为六，并在 Main 与 Worker 复用同一编码预算；不扩大读取权限。
tools/gateway.py告知模型图片窗口的实际语义；同一路径重读只替换快照，不追加无限图片，也不分页二进制。

所有图片逐项复用 owner／task／run／turn／tool 绑定、活跃状态、原始哈希、删除及遗忘校验；只从当前 prompt 可见的工具回执选取，不查询补入已经省略的图片。浏览器／电脑观察继续使用已有来源选择和租约校验。原图留在私有 artifact，Base64 只在模型边界出现；manifest 记录所有引用，删除任意已附图片都会阻止下一次模型或工具操作。源文件与 schema 不变，不新增权限、服务、端口、轮询或交付物。

验收记录

73 项定向检查通过，新增 21 项涵盖三图与像素标签、规范路径替换、同名不同目录、可见窗口、旧路径撤销／遗忘／无效／偏移、伪造来源、旧回执、图损坏、任一引用撤销及实际原生循环的两图同次请求。旧版四项反例失败、新版通过；去掉失败读取路径标记的受控变体另有两项失败，恢复后通过；均为协议夹具，不声明付费模型或原视频通过。初始 fixture 导入的 lint 问题已修正，单独格式化后复跑完整定向检查通过。

当前节点的新本地计费 socket 已只读核对，settings／usage 返回 200；每日限额沿节点现有设置，不保存任何配置。此前独立实验使用模型页保存的原远端 Go 连接，不能当作 #490 新本地 socket 的限额验收，也不据此补写旧本地账。后续付费验证必须显式绑定当前节点本地 socket，核对真实调用回执；旧 HTTP_401 与未知量保留。完整门禁、冻结镜像、真实双图探测和任务复测随验收更新，未部署现用服务或启用自动日程。

六图与组合字节预算修订

三图 v38 真实双图探测通过：2 次请求、4,318 Token，同次请求包含两张图，结果匹配，调用 ID 与现用 Go 本地账本对应。原视频复测仍反复轮读六张联系表；随后 Worker 上游返回 MODEL_HTTP_401。已知生成用量下界 725,312 Token／40 笔已知请求，另有未知调用；没有运行原生判定、没有完成原任务，不把输入能力等同于质量达标。未知量阻止付费复盘，程序免费产生汇总并结束后续空阶段。源代码、原 Case、节点配置均未变。

因此将图片窗口与既有六附件名额统一，同时修复 Main 丢失后三张上传图及多图累计字节不受限的问题。上一版三图快照与两图实验单独保留，不重放未知操作。六图及组合预算定向 81 项通过；含实际 Native 循环六图同次请求、Main 六附件、所有者与撤销、原始尺寸、组合 Base64 字节上限、最低尺寸省略旧图。受控恢复旧数量与不累计编码的四项反例全部失败，恢复后通过；首次两个测试夹具的配置对象和噪声文件预算假设已修正，保留日志。完整门禁、冻结镜像与独立真实探测随本轮记录；在获得原任务同门槛的结果之前，视频问题继续保持未修复。英文新增内容为模型上下文指令及协议说明，不新增界面文案。未部署服务，不修改每日限额、不增加 RSI 限额，不宣称 Android 真机验收。
