文件交付的结果总结

Product Design

任务回报必须说明实际结果、必要限制与验收状态，并保留真实文件链接。有附件不再允许把结果总结替换成“任务等待验收”或“任务已完成”的通用短句。用户主动询问进度仍走原有状态短答。

User Stories

  • 执行器生成文件后，我在主对话就能看见做了什么、关键结论和哪些还没确认。
  • 等待验收和核验失败不会被执行器的成功声明覆盖；其他任务的附件也不会混入这次交付。

Technical Design

tools/main_catalog.py 移除终态 completion 回调因存在附件而放行 task_reply 的例外，仍复用 TASK_RESULT_REQUIRED 引导实际答复；同任务校验、外层状态、非终态与主动进度查询语义不变。context/prompt_builder.py 与工具描述统一要求普通结果直接流式说明，显式语言/覆盖清单等使用 reply，不再把文件交付推荐到状态工具。沿用现有附件绑定与语言校验，不新增接口、模型参数、轮询或前端组件。

实际问题

音频v47已生成可下载WAV，Main却调用状态短答，最后只剩“任务等待你回复或验收”和文件列表，没有关键结果或限制。音频真实质量仍未达标，修复交付总结不改变该Case成绩。
