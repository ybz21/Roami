# 空模型连接关闭误报

## 产品设计

桥接socket建立后未发送任何HTTP字节即关闭，不是一次模型请求，不应制造网关失败。已开始的请求、模型断流和实际认证错误仍记录失败。模型、参数、能力和Go网关额度保持原配置。

## 用户故事

- 连接探测或预连接结束时，运行记录不增加虚假的模型失败。
- 排查真实超时、截断HTTP或模型断流时，仍能保留原错误和用量未知状态。

## 技术设计

`improvement/integrations/model_gateway.py`只在读取请求头时识别零字节EOF并正常结束该连接。部分请求头仍进入既有错误路径；完整请求头后的缺失/部分请求体不在豁免范围。模型流执行期间的相同异常不豁免。连接仍经过原finally关闭与任务回收。

这是隔离Actor与宿主配置模型之间的桥接层，不是媒体能力或底层额度实现；不增加Agent工具或新的模型路由。原有传输大小边界、认证阻断、Go准入、计费和未知调用不重放保持。

## 验收与边界

在#552源码用真实私有Unix socket复现：零HTTP字节、零Provider调用仍产生`RSI_GATEWAY_FAILED`。新增回归在旧实现2项失败：空连接误报，以及超时日志混入3条虚假网关失败。

Case73提供测试实际发送的4种公开HTTP字节配方，以及冻结源码/测试的运行器。33项覆盖零字节连接、请求头/体截断、超时日志、上游空读/重置、401/403、用量及真实零分；目录另有17项检查。所有Provider均为明确测试替身，无真实模型调用。不修改正式60项套件或旧成绩。

这个复现证明一个可修复的误报，不能反推v115那一条桥接错误或历史401的根因。音视频、股票实际质量、独立与人工验收及正式观察继续未完成，相关Issue保持开放。
