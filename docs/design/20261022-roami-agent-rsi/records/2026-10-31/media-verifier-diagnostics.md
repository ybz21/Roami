# 媒体验收分项证据

## 产品设计

查看每次音频运行时，除总分还保留受损区修复与未损坏区保留的数值，便于区分问题位置和跨轮变化。无界面新入口，使用已有Case详情和运行汇总中的原生判定证据。

## 用户故事

- 失败时能够区分修复质量不足和干净区域被改坏。
- 多轮结果保留各自分项，不覆盖旧成绩，不把缺失测量写成零。
- 只看公开数值，不看到参考音频、位置窗口、模型、路径或判定源码。

## 技术设计

`evaluation/media_diagnostics.py` 管理公开音频数值字段与有限值过滤；`benchmarks/media_tasks.py` 从原判定回执提取该集合，保持回执SHA和原总分、阈值及合同不变。`native_judgment.py` 再过滤持久证据，并沿既有Case详情及报告路径保存。不把参考素材或完整回执传给Actor。

无效、非有限或不合理的分项显示null；无效总分、失败进程不发布有效分项。旧记录不需要补写、迁移或重跑。该变化属于RSI证据层，不给Agent核心加入音频编辑能力。

## Case与验收

Case70提供可见合成回执，真实子进程、未知字段丢弃、非有限值、失败回执及持久Case详情和报告共39项机制回归。原题音频另行验收，不能用机制通过替代质量。所有模型调用沿用节点保存的路由、参数、能力和本地Go限额；本批无界面文案。
