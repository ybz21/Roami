# 外挂 Skill 的初始发现

## 产品设计

用户安装的工作流应能被 Agent 主动发现。此前 Skill 只在搜索目录中出现；模型认为自己熟悉任务时，可能一直自行写脚本而不搜索已安装的能力。

初始工具信息显示可用外挂的名称、用途和 `skill://` 读取路径。正文、参考、脚本和素材仍由 Agent 按任务需要读取，不因文件名或领域自动执行。

## 用户故事

- 安装本地或托管 Skill 后，主、后台及研究角色的下一次请求可发现它。
- 禁用、更新和移除立即反映在发现信息中；不能读取的 Skill 不出现。
- 读取所需工作流后，通过现有工具执行并交付实际文件。

## 技术设计

`ToolDirectory.skill_entries()` 统一目录搜索与模型工具信息的可读性筛选，同时检查 `read`、`skill_read` 和单个 Skill 的禁用状态。

`Tools.catalog()` 在既有 read 工具说明中附上已启用外挂的简短元数据，直接使用已注册数据。工具名称、参数 schema 和其他工具说明不变；内置流程已有入口说明，不重复加入。元数据随每次工具目录构建更新，并进入既有上下文估算，不增加 Token、请求或费用限制。

新增 Case 66 独立运行。通用回归验证三个角色、生命周期和权限；既有外挂交付回归增加首次 Worker 请求可见元数据的断言，并继续严格检查基础名称/schema、输入、修改范围、持久交付和用户隔离。

外挂检查输出将含混的 `ordinal` 更名为 `drawingOrdinal`，并给出独立的 `topToBottomRank`；位置不可确定时排名为 null。对象列表仍保留绘制顺序，编辑请求里的 `target.ordinal` 仍是显式指定的空间排名。该兼容变化只在可选包内，既有导入快照保留原脚本。最小批量请求示例移到 Skill 入口，避免使用检查能力后又重写已有编辑逻辑。

## 验收证据与边界

- 修复前新增 6 项回归：5 项失败、1 项通过；缺少初始发现信息，且关闭 skill_read 后搜索目录仍展示不可读入口。
- 修复前原对齐题的新诊断已真实加载外挂，但未调用它：47 次请求均经本地 Go 网关，697154 Token、¥0.1641971，全部已知、HTTP 200。原判定仍为 [0,0]，保留失败；不能把未读取外挂认定为失败的唯一原因。
- 补齐元数据只是发现能力修复，实际模型是否使用并正确交付需另行复验；不改原题、参考、判定或历史成绩。
- 真实复验中已观察到首次 Worker 读取外挂并调用检查；补充请求示例后也实际调用了编辑命令。但随后三轮的四次原题执行仍全部失败，对齐按绘制顺序选中了下方正文，颜色题未使用外挂。最后的排名字段澄清也未使原判定通过；这些失败原样保留，不能声称 PPT 质量问题已解决。
- 共四次独立诊断、五次原题执行：132 笔 Go 网关请求、1710150 Token，全部用量已知，均为保存的模型及 RSI 来源。没有运行付费复盘或覆盖正式成绩，不从请求数变化推断成本收益。
- 开发指令、Skill 元数据及测试协议使用英文，无新增产品界面文案。
