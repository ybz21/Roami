# 源副本契约与可选表格导出工作流

## 产品设计

清洗源表和分析表分离。默认保留源列，不因表头未命名或值连续就推断可以删除；派生分析字段不自动进入用户请求的清洗源表。实现留在可选 Skill，Agent 核心不增加 CSV 解析、导出或股票规则。

## 用户故事

- 同时请求清洗 CSV 和分析报告时，源数据的字段身份不被分析字段或隐含删列替换。
- 看到配置了哪些外挂，也能从实际执行记录区分是否读取和使用；有文件和上传回执不代表原题通过。

## 技术设计

Agent 的默认 Main/Worker 指令补充通用副本契约：未请求改动的源字段、标识和有效值表示默认保留，派生分析在独立视图处理。该规则不识别任何文件格式；显式保存的角色指令继续原样使用，模型路由、参数和能力不变。

`skills/tabular-analysis/` 通过已有 managed-import、初始元数据目录和按需读取使用。`scripts/csv_export.py` 负责 CSV 快照、字段投影、明确键恢复和数值规范化；`scripts/table_publication.py` 负责工作区路径、双输入哈希与文件发布；只有标准库依赖，不增加核心工具、模型参数或预算。新股票诊断在独立 Actor 中显式导入原型，原题仍用冻结 v49 套件与原生判定器，宿主基于 #545，镜像增加实际 Agent 默认副本规则。生产节点未安装。

## 可执行导出与默认规则

源码默认规则只影响未显式保存角色指令的节点；当前节点的 Main/Worker 指令未显式保存，因此这次实际 SUT 使用修订后的默认值。没有修改配置文件、保存模型、参数、能力或重试，不属于验收脚本临时覆盖。

导出有两个明确模式：`analysis` 保留清洗编辑后的值，`source` 按分析表所选键过滤/排序源记录并保留原值表示。日期键规范化只在明确选择时比较 ISO 民用日期；键碰撞、不匹配或选择中的非法日期均拒绝。默认源字段投影排除分析专用列，用户明确请求其他 schema 时可选择 `--columns`。数字字段由调用方明确选择，不更改未声明标识字段；小数精度保留。

两份输入的观察哈希在发布前复核；新目标默认不覆盖，已有目标要求观察哈希。写入后无法确认的错误保留 `writePublished`，不能盲目重写。原始输入与旧产物不改。

### v101 和日期键修复

v101 使用修改后的实际 Agent 默认规则，首次读取并执行导出脚本；结果保留了8列和类型，但日期从源时间戳变为纯日期，既有适配值比较和原始严格比较仍失败。74笔请求、2219318 Token、¥0.3489636，均关联本地 Go 的已知 HTTP 200。v100 为93笔、3142977 Token、¥0.4678988；没有把这两轮失败改写成通过。

脚本的缺口是全源列已存在且使用 `analysis` 模式时忽略声明的键。现在所有显式键均校验，日期归一化只用于匹配，默认保留原日期键的表示，同时保留其他字段的清洗编辑。用户明确要求改日期格式时可选 `--analysis-key-values`。增加全列存在时键碰撞、不匹配、日期表示和显式格式变更检查。

默认规则增加了固定指令开销，两个既有回归用固定总长度阈值误判。历史压缩检查扣除固定指令与工具开销后仍要求5倍缩减；中文输入检查以UTF-8字节数的一半作为测试上下文，继续同时验证真实请求可容纳且原始字节数超出上下文。没有更改运行时上下文准入规则或任何节点限额。

Skill和CLI协议文字是可分发资源，不属于产品界面文案；本次无Web界面改动。
