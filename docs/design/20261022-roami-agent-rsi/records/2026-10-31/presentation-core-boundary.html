文稿读取、编辑与最小核心

Product Design

读取文稿结构、计算对象位置、解析编辑器色板和修改属性均属于可选 presentation-edit Skill。核心提供通用文件字节、显式 Skill 读取、执行和交付。任务提到文件名不触发格式解析、文件预读、Skill 系统指令或文稿上下文注入；安装领域能力由用户控制。

User Stories

  • 未安装文稿 Skill 时，基础 read 仍能分页返回原字节和 SHA，不将 PPTX 当成隐式指令或自动任务步骤。
  • 完整外挂包通过通用导入、发现、读取和 bash 运行，检查、编辑和复查原文件，输出可下载结果。
  • 工作流中文检索词来自外挂元数据；核心不维护 PPTX 专用搜索别名。文件与 Skill 调用遵守当前执行策略，包括运行途中禁用。
  • 位置和解析回归随插件迁移；源文件、其他 ZIP 部件及格式保留。脚本成功不代替模型自主质量或视觉验收。

Technical Design

移除 TaskDocumentIntake、WorkspacePresentationReads、核心 documents 解析包与内置 presentation_files，删除 NativeExecutor/PromptBuilder 的 documents 回调与组装。基础 read schema 不再有 document 模式；默认 Worker 指令不再路由 PPTX。外部脚本已独立提供结构检查和编辑，无 roami_agent 导入。通用图片输入和文件交付保持原有职责。

位置的 10 项断言迁入外挂 test_layout，解析断言迁入 test_inspection；通用 test_native_input_policy 证明无隐式文件/流程读取及显式调用的动态策略。test_file_capability_contract 证明原始字节分页、旧格式参数拒绝及领域工作流非内置。真实 NativeExecutor 合同使用显式文稿文件名，证明核心没有预读，领域处理仍由外挂完成。

Case 34 更新为通用输入/Skill 策略入口，原 Skill 版本与引用断言保留；Case 63 使用外挂解析及 10 项位置检查，明确输入是最小 OOXML 结构 ZIP；Case 64 使用完整可编辑 PPTX，严格执行外挂 42 项及宿主交付合同 1 项。旧自动注入专用断言随已删除行为退役，保留能力的断言迁移；不能用测试总数变化宣称质量提升。

RSI 的领域判定器与原参考保留，只更新机制回归入口绑定。旧冻结套件、历史成绩及人工标签不重写；新机制合同必须独立冻结并有执行回执。模型路由、参数、能力及重试沿用节点保存配置，消费准入仅由 Go 网关控制。评估包使用的 python-pptx 不被当作 Actor 的文稿处理接口。

Acceptance

新增无隐式输入测试在旧实现实际 1 失败/2 通过；外挂 42 项独立回归通过，Case 63 迁移后的 10 项断言通过。Case 64 与完整门禁使用最终资源重新冻结验收，失败回执保留，不挑选旧方案结果。

候选镜像从可信基线只替换 Actor 文件，显式删除 7 个退休路径，避免 COPY 覆盖后遗留内置 Skill；外部 Skill 不烘焙进核心镜像。验收须证明核心目录不含旧文稿入口、基础工具不接受 document 模式、插件可通过通用工具交付；完整 Actor 回归、当前机制合同与 CI 通过后再合入。确定性检查不计作真实模型原题或正式套件成绩。本轮不部署、不启用日程，实际 RSI 质量和必要人工/独立验收仍待完成。
