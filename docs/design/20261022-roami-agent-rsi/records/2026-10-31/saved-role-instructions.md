# RSI 容器继承保存的角色指令

## 产品设计

RSI Actor 的容量和图片能力已能继承节点配置，但实际 Main、Worker 指令仍由容器默认配置生成。保存自定义指令后，普通 Agent 与 RSI 的行为因此不同。

私有请求只增加两段角色指令，原样保留多行、Unicode 和显式空字符串。模型连接、模型参数、凭据与重试继续由宿主 Go 网关管理；不改判定器、题面和模型选择。

## 用户故事

- 节点保存的角色指令进入隔离执行请求，不被镜像默认值替代。
- 旧 Actor 不具备该合同，启动前明确拒绝；固定的无模型判定/渲染镜像保持原版本。
- 能区分配置一致性修复和真实内容质量改善，不给历史运行补写指令或分数。

## 技术设计

`execution/container_context.py` 对两段字符串做严格字段校验，组合 Actor 配置；`ContainerExecutor` 通过已有私有 request.json 传递，`container_agent` 在实例化 Runtime 前应用。新 Actor 增加独立的角色指令支持标签，不改变已有 Go 每日准入版本；执行协议指纹升级，指令变更继续参与原指纹。

旧请求缺少字段时保留其原行为；显式新字段非法时拒绝，不能静默默认。部署需匹配宿主代码与新执行镜像，本轮只准备候选。固定判定镜像不调用模型，不要求新标签。

## 验收

新增 16 项在旧代码为 12 失败、4 通过；修复后 123 项相关回归通过。Case 68 的合成配置、镜像标签、工具、来源和独立运行器均在目录中。

当前节点保存的角色指令等于默认值，此缺口不能解释现有音视频或股票内容失败。本轮不做无关的付费重跑，不覆盖旧真实成绩、人工标签、生产服务或日程。英文为开发/协议内容，没有新增产品界面文案。
