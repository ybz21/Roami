# 本地配置 Skill 的资源目录

## 产品设计

本地配置的外挂 Skill 应能使用自身目录中的脚本、素材与依赖。此前托管导入包返回 `packagePath`，本地目录只返回说明，照同一份工作流执行会缺少脚本定位信息。

读取本地 Skill 时返回经过现有目录边界检查的绝对路径，继续通过通用 `bash` 执行。说明、资源不自动塞入任务上下文，PPTX 逻辑仍全部在可选 Skill 中。

## 用户故事

- 用户把完整 Skill 放进已配置的目录，Agent 按需读取后即可执行其脚本，无需重复导入。
- 用户禁用 Skill 后，读取仍被拒绝；越出配置根目录的符号链接仍不被发现。
- 用户得到经检查的实际文件及结果总结，文件在工作区删除后仍能从附件下载，其他用户不能读取。

## 技术设计

`tools/skills.py` 的 configured 条目记录已解析的 Skill 父目录。现有 `skill_read` 结果已支持可选 `packagePath`，因此无需新增工具、schema、任务名称判断或领域依赖。内置 Skill 保持原合同。

本地包使用配置目录中的实时文件；托管导入包使用现有内容寻址快照。这个改动不承诺本地包不可变版本，也不改变本地目录的已有重载规则。

外挂说明同时修正离线启动方式：若任务 Python 已具备脚本声明的依赖，直接使用它；缺少依赖时在联网准备阶段用 uv 建立独立环境。断网且 uv 缓存为空时，不能用重新解析依赖代替已准备的环境。依赖准备属于外挂工作流，核心没有加入文稿依赖或安装逻辑。

通用回归位于 `tests/test_configured_skill_package.py`；实际 PPTX 外挂的配置加载与交付回归位于 `tests/verification/test_configured_presentation_skill.py`，复用导入路径的同一组端到端断言。机制 Case 65 单独运行，不改原正式 60 项或历史判定。

## 验收证据

- 旧代码：新增通用回归 3 项失败、1 项通过，失败均为读取结果缺少 `packagePath`。
- 修复后定向检查：10 项通过；覆盖三种角色、脚本实际读取二进制素材、空格路径、禁用和越界链接，以及导入/本地两种 PPTX 编辑交付链路。
- Case 65：必须完整执行 5 项，无失败、错误或跳过，保存代码及资源哈希、JUnit、日志和实际生成的 PPTX。
- 全部使用脚本化测试模型，真实模型调用为 0；这些证据不等于自主任务质量验收通过。真实质量、独立评分与正式观察仍另行验收。
