# 已安装工作流的执行上下文

## 产品设计

已安装工作流的元数据可见后，模型仍可能因熟悉基础操作而跳过工作流。保存过的角色指令也不会随代码默认指令更新。

有可读外挂时，在实际请求中补充一段通用策略：匹配已安装工作流的请求先按需读取其指令，使用覆盖的操作；未覆盖的工作及用户明确选择继续使用其他能力。它不按文件类型路由，不加载 Skill 正文，不强制执行某个工具。

## 用户故事

- 用户保存的 Main、Worker 指令和模型配置保留，新增外挂仍能进入实际执行决策。
- 禁用或移除工作流后，下一次请求立即反映当前状态。
- 实际请求、压缩估算和调试上下文使用同一规则，避免估算漏掉运行时策略。

## 技术设计

`Tools.optional_skill_metadata()` 复用已注册元数据与读取权限。`context/workflow_instructions.py` 只组合通用策略，不依赖领域或工具实现。Runtime 将元数据回调注入 PromptBuilder，Main 的默认请求上下文也复用同一组合函数。

初始请求直接提供工作流名称、用途和 URI，read 工具中的目录继续提供兼容入口；两者复用同一份权限筛选后的元数据。没有可读外挂时，原请求指令保持不变。策略和元数据纳入已有上下文估算，不增加 Token、请求或费用限制。

文稿的可见顺序语义仅在外挂 Skill 中说明：用户未指定绘制/Tab 顺序时，普通可见文本框序号按明确的几何顺序解释；重叠或歧义如实说明。核心没有加入 PPTX 识别、选择或编辑逻辑。

外挂的 `colors` CLI 直接接受颜色名称列表，将整页非空文本框按几何顺序装配成既有编辑批次，复用色板解析、CAS 与原子发布。名称数量不符、未知色板/名称及改动的源文件不发布结果；部分或混合编辑继续使用已有通用批次。颜色解析未进入 Agent 核心。
