# Main明确读取的本地图片输入

## 产品设计

视频v117的Worker关闭图片输入，读图仅返回元数据，不能把其选片失败记为图像已经可见。另有独立框架缺口：保存Main图片开启、Worker关闭时，Main明确读取一个允许目录下的本地图片，也只有元数据。原有像素读取和投影仅接通Worker，Main只接通聊天上传图片。

复用普通文件读取与图片输入边界，按保存的Main能力提供当前读取快照；不启用Worker图片、不切换模型或执行者，不增加视频领域工具。视频语义质量仍另行验收。

## 用户故事

- 用户明确给出本地图片路径时，支持图片的Main能读取像素，而非把base64当作视觉观察。
- Main和Worker的图片能力互不授予；已配置的文件根目录、读取权限和图片尺寸/载荷参数保持有效。
- 图片撤销、遗忘或读取失败后，旧快照不能继续冒充新证据。

## 技术设计

- `tools/workspace_images.py`：保留Worker运行绑定；Main读取要求当前真实Main回合、助手消息及允许文件范围，排除Native任务分支。快照与页读取哈希相同，Main保存完整路径区分目录。
- `context/main_file_images.py`：从当前工具回执校验所有者、回合、会话、消息、调用、来源路径和未撤销快照，按最新读取去重。
- `context/chat_images.py`：Main文件快照与原有用户图片合并为一次图片准备，沿用Main角色尺寸与总编码载荷。未纳入的来源明确标记，不将文件快照当浏览器坐标授权；持久记录仅含引用和哈希。
- `tools/gateway.py`：不可视读取说明实际限制，避免建议已关闭的Worker接管视觉判断。
- Case77提供与实际测试逐字节一致的公开图片配方、工具和冻结入口；不计为业务交付成功。

## 验收边界

真实保存接口复现Main开启、Worker关闭：旧实现只能返回图片不可用，修复后实际Main模型边界收到源像素。初始测试配置遗漏模型端点造成的配置错误单独保留，不计为功能缺陷复现。修正夹具后旧实现的像素断言失败；修复后113项相关回归通过，包括既有Worker路径、角色独立、来源隔离、撤销、文件边界及混合图片载荷，另核对Case目录。

实际节点模型、参数、能力和重试不覆盖。后续保存配置开发探测与固定镜像证明另存节点私有证据目录；不改写历史成绩、人工标签或原生视频选片分数，不向生产安装或启用日程。
