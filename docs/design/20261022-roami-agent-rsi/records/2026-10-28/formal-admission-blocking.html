设计修订与验收记录

正式评测的共享准入与首发阻塞 · 2026-10-28

Product Design

正式日跑与诊断采用相同的共享准入语义。代理因未知费用、每日限额或币种拒绝后，后续模型任务保留未执行记录，不重复启动，也不被当成候选质量下降。无需模型调用的机制检查继续。运行结束先保存程序总结，独立 Codex 复盘或正式验收仍使用各自回执。

缺少 Token 回执与费用准入分开处理。代理已允许继续时，RSI 不再自行按 Token 未知熔断；计量仍保留未知，效率与正式晋级不能借此宣称通过。原有无代理协议继续保持保守约束，真实未知费用仍受模型页每日策略保护。

User Stories

  • 用户能区分首发 Case 与后续受阻 Case，并看到配对中的 baseline、candidate 和各自证据。
  • 确定未发出的后续任务记零调用；首发未知用量和整轮总量仍保留未知。
  • 候选尚未执行时，不显示质量退步或虚假的效率收益，也不能凭缺测晋级。
  • 付费复盘被阻止时，仍能读取评测总结与原因，不依赖再次消耗模型生成说明。

Technical Design

domain/admission_blocking
  共享拒绝与未知用量分类；未执行结果
workflows/cycle
  冻结 Case、执行分支、原因；保留每条 trial 与宿主阻塞凭据
evaluation/behavior_review → domain/comparison
  区分实际尝试和未执行；缺测不生成候选退步或成功收益
workflows/run_lifecycle → pipeline_reports
  保留首发执行分支、双分支证据和完整用量边界；先落盘可读总结

拒绝原因来自宿主终态、共享代理校验及脱敏模型日志，外部执行器不能自行设置 blocked_by、admission_error 或 shared_admission_checked。配对共用每日准入，首发原因包含 Case、执行分支与错误码；后续模型 trial 不启动执行器，以宿主生成的 admission-blocked.json 保留来源，调用及 Token 为零。镜像协议标签升为 shared-daily-policy=2，旧镜像在预检拒绝。所有原始评分和已发送请求保持原样，不改写历史未知账。

阻塞对照不参与质量差值、基线退步及成功效率计算，仍明确阻止晋级与完整覆盖结论。正式运行投影保留两条分支，首发记录不被另一条未执行的记录覆盖。生成、产物评分及合计用量分别汇总，空记录或缺用量保持未知，避免省略字段后被付费复盘误认为零消费。

验收边界

真实 Docker 保护演练读取当前每日准入策略但不绑定模型传输：60 条记录保留，20 项机制检查通过，首个模型 Case 准入拒绝，其余 39 项沿同一原因标明未执行。仅发生一次只读准入探测，外部模型调用为零，现用账目条数与原未知费用记录均未改变。这是设施保护验证，不是完整能力验收。

脚本模型的 Native 容器验证另复现宿主误报：文件已成功生成，缺少 Token 回执却被提升为 RSI_RUNTIME_REPORTED_FAILURE。共享模式仅对宿主同样确认的 unknown_provider_usage 保留计量阻塞，交付继续按独立断言判定；实际执行错误、无法由宿主核对的标记和旧协议仍拒绝。计量未知继续阻止正式完整结论。

回归、脚本模型与容器保护对照只验证设施，不代替真实模型完整 60 项、人工参考评分或两次完整日观察。原中断账仍待权威回执；自动日程、现用限额与模型配置不因这次修复变更。
