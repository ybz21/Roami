静态页面的存储验收环境 · 2026-10-28

Product Design

静态页面在容器内通过固定来源的本地 HTTP 地址验收，刷新后在既有五秒交互时限内等待状态恢复，再核对草稿、筛选和可见结果。没有持久化、错误筛选、少卡及空结果仍失败。每次独立 Case 使用新浏览器与新端口，不串用历史状态。

User Stories

  • 正确页面的状态恢复不会因为文件来源行为或固定一百毫秒等待而被提前判错。
  • 我仍能看到真实未保存、错误结果和原始失败，不用反复重跑直到变绿。

Technical Design

evaluation/execution/browser_workspace.py 只提供宿主发送到容器的静态预览程序。服务只监听容器内 127.0.0.1 随机端口，沿用禁用外网和只读工作区，生命周期由容器负责；不新增宿主监听或永久服务。authored_grading.py 的看板和响应式检查复用该来源；响应式刷新后等待两个原值恢复，时限仍为五秒，最终六项断言保留。

MDN localStorage 文档说明文件 URL 的存储行为没有保证。原来的 file:// 环境不应承担网页的来源与持久化合同。判定器源码及新执行模块进入既有 grading_hash，不将环境修正称为模型能力提升。

验收记录

1846 项版本的两次 full 分别在 hidden、removed 的正确用例发生状态未恢复：初始五卡、布局和触控通过，草稿、筛选及结果失败。单项和六组单独检查通过，原日志均保留，未以重跑一次通过宣布修好。额外带状态观测的十二次文件来源及十二次 HTTP 检查都通过，不能据此独自证明 Chromium 内部根因。

新增受控反例覆盖文件来源在刷新时丢弃存储、350 毫秒恢复以及真实未保存状态。前两种模拟在旧程序下均失败，HTTP 加有界等待后可通过；真正未保存继续失败。模拟的是允许的来源差异和延迟，不冒称重现了 Chromium 内部故障。定向 164 项通过；DEMO-01 与 DEMO-05 的真实原产物在新 HTTP 判定器下客观检查通过，仍待独立评分，原文件哈希不变。完整门禁结果另随 PR 留证，原产物和原失败不回写。
