## Product Design

指定一个已注册操作时，直接给出该操作可执行的命令和输入 schema；查看整族帮助时仍保留完整目录。镜像准入失败需要保存缺失协议的具体原因，不能只剩一个无法定位的错误码。

## User Stories

- 查询 `task_steer` 后直接填写它的命令，无需在所有 Roami schema 中寻找。
- RSI 因旧镜像停在零 Case 时，可以在私有阶段证据中确认缺失的协议要求。
- 验证显式执行器选择时，核对原请求、实际执行器和目标绑定；元数据的原因标签改变不应制造业务失败。

## Technical Design

### 交付代码

- `tools/foundations.py::ToolDirectory`：操作名、空格形式和完整公开命令的精确查询返回单项命令、当前角色 schema 与 effect。整族帮助和无精确匹配的目录保持；catalogVersion 仍由完整目录计算，不随查询变化。禁用操作、Main 不可用的浏览器操作与普通外部能力继续按原准入处理。
- `improvement/evaluation/execution/containers.py::preflight`：保留 `RSI_CONTAINER_IMAGE_REQUIRED`，在私有 `environment-failure.json` 中保存镜像 ID、缺失/不匹配的必需标签及未启动执行的事实。不会把无关镜像标签或私有阶段详情发布到 GitHub。
- `scripts/dev/agent-acceptance/routing_exam.py`：原 Q03 要求旧 `reasonCode=explicit_executor`，当前简化输入记录 `tool_executor`，导致实际正确派活也被判失败。现在要求实际 intent/decision 执行器一致、sourceMessageId 绑定原请求，以及成功 delegate 中明确选择该执行器；既有项目绑定、任务数、歧义与默认执行器冲突检查保留。

目录的同进程旧/新源码对照，不调用模型：
