# 精简历史保留回复送达事实

关联 [Issue #628](https://github.com/ybz21/Roami/issues/628)，类型fix，优先级P1。

## 产品设计与用户故事

用户在活动安排与算术问题之间切换后，要求仅返回更新的活动JSON。原始对话已经回答算术题，却在后续JSON后追加“上一轮漏答”的旧答案。精简历史保留旧问题，但只保留最近回答，使较早问题看起来没有收到过回复。

用户需要继续当前话题，同时能够按需找回旧回复。曾收到回复只是一条送达事实，不证明答案正确、请求已全部解决或后台任务完成。

## 技术设计

`storage/reply_history.py`一次批量读取历史消息的真实`message.completed`事件。仅接受成功结束的用户轮次、Main来源、当前用户和会话、仍可见的请求及回答。提问、后台回调、失败、缺失事件、遗忘和删除不提升为普通回复送达记录。

`context/prompt_builder.py`只在Main简版历史且存在旧回答时查询。`context/main_history.py`保留最近普通回答原文，将较早已交付回答投影为送达记录，提示原文可经`conversation_history`读取。显式完整历史与Worker路径保持。源消息ID和上下文估算随投影更新，历史视图版本从2改为3，旧用量基准不复用。

没有按字段修补、输出解析、额外模型调用、额度或新的核心工具。标题文字与JSON围栏属于另需实模验证的语义问题，不能由本项宣布解决。

## 验收记录

[Case109 / MECH-AR01](../../../../../cases/case-109-mech-ar01/CASE.md)提供公开交错对话、工具清单、来源、独立冻结入口及18项检查：15项新增、3项既有历史检查。四种回复路径保留可信送达记录，排除八种不可靠/不可见来源，检查跨用户/会话边界，并从显式历史读取恢复原文。原Case107派活记录另外14项保持通过，合计相关32项，存在覆盖重叠，不等同32项独立新增。

旧生产源码对13项行为检查为5失败、8通过；两项新存储查询隔离检查不计旧版缺陷。模拟提供方、真实Runtime及SQLite，不调用外部模型。修复过程的首次SQL把所有权列误写为turns.owner_id，已改为conversations.owner_id；该次中止及后续测试夹具字段错误保留，不计为通过证据或另一个产品缺陷。

最新原始实模对话仍为16场景观察、13通过，58/62轮检查中55通过，4个后续轮因语义失败跳过。准确的三个失败为标题文字改写、JSON后追加旧答案、JSON代码围栏；此前简述成标题null和两个围栏不准确，按未改写的原始记录更正。
