# 精简历史保留可信派活回执

关联[Issue #623](https://github.com/ybz21/Roami/issues/623)，类型fix，优先级P1；关联#445、#605。

## 产品设计与用户故事

用户已把名单交给后台处理，下一轮另建物料清单时，Main应知道前一轮已经接收。历史请求不能因工具记录被收起而显得尚未处理。接收只表示派活成立，不等于交付完成；继续任务仍需要当前用户授权。

实际原场景曾同时重派旧名单与新物料清单。排查发现模型上下文保留旧用户请求，却隐藏了对应delegate回执；recent tasks只有最近三个任务的全局状态，不表达逐轮接收事实。该线索不证明所有模型重复派活都由此引起。

## 技术设计与模块

- `storage/task_handoff.py`在同一次查询中从可见历史的消息ID提取持久回执，只接受实际成功的delegate/task_steer，并要求同轮用户来源仍可见。由已解析的操作名称识别CLI续跑，不按工具输出外形猜测。
- `context/prompt_builder.py`只为Main精简历史读取这些事实。没有历史工具记录时跳过额外查询；显式完整历史读取及Worker路径保持原协议。
- `context/main_history.py`在原请求之后保留紧凑的历史接收记录，列出操作、任务引用与requestComplete事实；不带过期任务状态、执行方长指令和工具额外字段。来源ID保留，重新计算上下文占用，投影版本进入请求身份。

原始消息不改写，完整历史读取可恢复原tool-call/result。失败、未知、拒绝、其他工具伪造、缺失结果绑定、遗忘或删除的来源及跨用户数据不提升为接收事实。部分请求保持requestComplete=false，完成回调不产生新授权。

未增加模型请求、配置、Token/请求/费用限额或领域专用能力；准入仍由本地Go网关决定。原题、评分器和阈值、正式40/60项及历史成绩不变，没有部署或启用日程。

## 验收证据

原版源码上的三项真实Runtime/SQLite集成回归全部失败：首次派活、直接续跑和已注册CLI续跑的接收记录都从精简历史消失。测试使用模拟提供方；任务、来源绑定及命令解析真实执行，不调用外部模型。初版测试曾误以为delegate在CLI命令映射内，该夹具错误与后续拒绝结果夹具丢失tool_call_id的错误分别保留，不计为产品缺陷。

[Case107 / MECH-HR01](../../../../../cases/case-107-mech-hr01/CASE.md)包含14项新增检查与4项既有检查，共18项，提供公开输入、依赖、工具入口和独立汇总。相关历史、派活、压缩与请求调度检查54项通过，包含上述检查的重叠，不累加为独立数量。最终quick/full、CI和原始模型复测以PR回执核对。

本项证明上下文证据保留，不能据此宣称模型不再重复派活、#605通过或音视频/PPT质量通过。实际模型复测仍必须沿用保存路由并单独报告，包括401或不完整用量。
