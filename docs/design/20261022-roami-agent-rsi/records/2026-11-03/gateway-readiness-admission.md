# 本机网关就绪与鉴权准入拒绝

## 产品设计与用户故事

用户需要看到 Go 网关原始拒绝原因，并知道没有发生上游调用。网关关闭、密钥被禁用、排队期间授权失效时，核心框架应直接返回拒绝，避免将其重试或记成未知用量。远端服务的同名响应头不能获得本机网关的信任。

## 技术设计与模块边界

Go 网关继续独占准入、路由和额度决策。`providers/local_gateway.py` 只将私有 UDS 响应中的三种既有预检错误转换为 `ModelAdmissionRejected`：`MODEL_GATEWAY_UNAVAILABLE`、`MODEL_GATEWAY_KEY_DISABLED`、`MODEL_GATEWAY_UNAUTHORIZED`。不新增框架额度策略，不修改保存的模型、参数或能力。

HTTP 提供器已有的跨尝试保护保持有效：之前已发生不确定的上游尝试时，后续准入拒绝不能抹去未知用量。普通远端 HTTP 响应也不能借同名响应头冒充已知零用量。

聊天、执行活动、RSI错误与工作流信号同步提供中英文恢复提示。复用现有失败状态和布局，主流程不暴露错误码或网关配置；禁用连接与鉴权失败分别说明恢复连接、检查配置。

## 验收与限制

[Case102](../../../../../cases/case-102-mech-gp02/CASE.md) 提供输入、工具、来源、冻结清单和独立回执。三个本机控制在修复前均失败：503进入重试，403/401丢失拒绝分类；修复后检查三种拒绝、三种远端伪造反例，以及一次未知尝试后的拒绝，共7项。前端另有4项中英文检查，修改前4项均失败，修改后全部通过；原Case101的8项显示合同保持独立，不改历史验收数。

仅为传输与计量机制验收，零外部模型调用。它不解决已有供应商未知用量，不关闭 #605，也不提高音频、视频、PPT或正式套件的历史成绩。完整质量门禁和 PR 证据以实际运行回执为准。


## 桌面与Android取证

真实聊天回报与执行活动组件运行于独立HTTPS夹具，仅模拟偏好API；任务原始失败与回报失败分别保留。桌面核对文档无横向溢出、提示完整、按钮中心命中和主流程不出现原始错误码。Android Chrome154经浏览器菜单刷新后，用可访问性边界内的真实ADB点按验证三种原因、中英文、详情展开收起，以及首页/项目/工具/设置导航，共15步。顶底栏、安全区及长句截图分别检查；手机不冒充已做DOM精确测量，也不代表生产任务或完整业务路由通过。

夹具初次白屏来自偏好API匹配过宽，误截获`preferences.ts`模块；已收窄为精确API路径后重新截图和验收，不计为产品缺陷。仅为诊断加载故障读取自建桌面标签的CDP日志；导航、截图仍使用`roami chrome`，手机用ADB触摸，不修改浏览器身份保护。
