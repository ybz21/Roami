# 结束工具混合批次的零副作用纠错

关联[Issue #624](https://github.com/ybz21/Roami/issues/624)，类型fix，优先级P1。

## 产品设计与用户故事

模型把回复或提问与其他动作放进同一批时，用户不应立即收到整轮失败，也不能静默丢掉本批剩余动作。保持结束工具独占的约定，执行前整批拒绝，告诉模型怎样改正；连续无进展才结束。合法动作和请求数量不新增限额。

原始多轮澄清场景在第三轮因帮助查询加task_reply触发QUESTION_MUST_BE_ONLY_TOOL，套件在13/16场景中止；94次模型调用全部HTTP200、用量已知。当前结束工具是直接基础入口，核对后撤回最初的CLI漏检猜测；命令映射、重复call ID与提问消息位置的测试夹具错误另存，不计为产品缺陷。

## 技术设计与模块

- `protocol/tool_batches.py`在执行前按解析操作检查ask_user、task_reply、task_queue_reply、reply的独占约定。
- `protocol/ports.py`新增ToolInvoker.reject，契约要求只持久记录失败，不运行处理器。
- `tools/gateway.py`复用既有持久回执路径，拒绝发生在tool.started和处理器之前，注明executionStarted=false、不可原样重试及拆分方式。
- `core/loop.py`将被拒绝的各调用作为工具错误反馈给模型；连续同类批次沿用纠错停滞机制停止，有合法批次后清除该结构错误标记。其他参数纠错、未知执行与权限保护保持。

没有增加工具调用次数、Token或费用限额。纠错可能增加后续模型轮次，仍由保存的模型设置和Go准入控制；不更改原题、判定器、阈值、正式40/60项或历史成绩。不部署、不安装节点Skill、不启用日程。

## 验收证据

完整原版源码导出后，九项回归均失败；修复后同组九项通过。扩展检查四类结束工具的前后顺序、重复错误零副作用、有效进展后再次纠错、30项合法动作、读批次、单独回复以及纠正后的提问。14项新增与4项既有检查构成[Case108 / MECH-TB02](../../../../../cases/case-108-mech-tb02/CASE.md)18项，含公开输入、依赖、工具和独立汇总入口。

相关原生续跑、派活及参数纠错35项通过，与本Case重叠，不累加为独立检查数。最终源码冻结、quick/full、CI和原始模型复测以PR回执核对。机制通过不等同于原始多轮语义或原生音视频/PPT质量通过，#605与汇总Issue继续按实际证据处理。

原始保存模型复测观察全部16个场景，13通过；58/62用户轮次中55通过，没有整轮执行失败。三个失败集中于标题值及纯JSON回复，#605仍未解决。120次调用全部匹配Go的HTTP200已知用量，费用0.3133778元，配置SHA与原始合同保持。

该试验在执行期间源码冻结；结束后公开Case标识改为未占用的MECH-TB02，并将同一校验函数原样迁入protocol、调整唯一导入，以满足既有依赖门禁。原试验、Case标识修订及模块迁移分别保留证明，不宣称两版完整源码树相同；发布树另做最终门禁。第一次不完整quick在发现层级失败后仅停止自有scope，日志不计为通过，架构检查未放宽。
