# 取消期间完整保存执行失败记录

关联 [Issue #631](https://github.com/ybz21/Roami/issues/631)，类型fix，优先级P1。

## 产品设计与用户故事

用户在任务出错时追加要求，续跑不应一直显示“停止中”。原执行的错误与停止证据要保留，用户能知道续跑已应用或被未知结果阻断。

`TaskDispatcher.run`的异常处理分支本身包含数据库等待。取消在此处到达时，不再经过同层`except CancelledError`，导致任务退出、活动槽释放，旧尝试仍running且没有result_json。任务一直cancelling，监督扫描也无法应用续跑。原生执行已经停止，并不代表失败回执已经保存。

## 技术设计与模块架构

`dispatch/runner.py::_finish_failure`承接原有错误分类、会话忙重排、预检进度、未知写入判断与失败结果登记；迁移前后该分支及最后的report语法树一致。

`_settle_failure`通过单独协程和shield等待失败记录完整落盘，再传播取消。重复取消同样等待这次收尾，不重试执行、不改变错误分类。保护范围是已经结束执行后的失败收尾；运行中的执行沿用原取消路径。未知写入仍保持unknown/interrupted并阻断续跑，停止证据与用户授权边界保持。

没有增加模型调用、Token/请求/支出限额或专用工具。模型路由、参数及能力仍读取节点保存配置，额度准入由Go决定。

## 验收记录

[Case110 / MECH-FS01](../../../../../cases/case-110-mech-fs01/CASE.md)提供公开事件门控制、工具清单、来源和独立冻结入口。16项新增与6项既有启动取消检查共22项；另外12项取消/验证检查组成相关34项，存在覆盖重叠，不算34项独立新增。

旧源码16项检查为13失败、3个无取消控制通过。已复现失败轮次登记前/后的一次及重复取消，并区分已知失败、未知工作区和真实工具网关保存的未知写入。关机取消保留原始失败供恢复，预检和超时分类保持。首轮测试夹具误用了不存在的Tool.worker参数及任务详情层级，已修正；该轮不计产品缺陷或验收通过。

上轮CLI续跑曾出现5秒超时，但当时没有保存任务数据库，不能断言一定由本竞态导致。本项依据独立、确定性的状态机复现，不修改该超时条件。

机制检查不替代#605实模语义、原生音视频/PPT、独立评分或正式全套。节点配置、Go账本、原题、判定器、阈值及正式成绩保持；未部署、安装节点Skill或启用日程。
