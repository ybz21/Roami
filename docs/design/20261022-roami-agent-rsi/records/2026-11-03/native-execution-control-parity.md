# 原生验收的管理命令、续跑身份与缓存隔离

关联[Issue #621](https://github.com/ybz21/Roami/issues/621)，类型fix，优先级P1。与[模型能力校验](native-model-capability-admission.md)分层处理。

## 产品设计与用户故事

用户首次请求文件，随后要求修改，验收器应和Agent框架一样，在原任务与工作区续跑。Main需要能查任务、发出获授权的续跑；原生交付仍由Worker完成。Main不能执行操作系统shell或写交付文件，完成回调不构成新的用户授权，未知写入不能自动重放。

## 技术设计与模块

内部Roami管理操作统一从bash工具解析至已注册处理器。原生验收此前把bash整体从Main目录移除，误禁了管理入口；工具白名单也遗漏task_steer。

- `tools/registry.py`记录禁止执行系统shell的角色，并给该角色提供仅限内部管理命令的真实工具说明。
- `tools/foundations.py`先解析并校验注册的内部操作，角色禁止的host及普通命令在执行前拒绝。其他角色及普通应用默认权限保持。
- `improvement/evaluation/execution/evaluation_tasks.py`配置原生验收的Main限制和管理工具集；工作区标识绑定任务，续跑不随run改变身份。
- `executors.py`使用同一管理工具集，shell权限、任务权限和`native-worker-v2-continuations`协议版本参与模型比较哈希及运行记录，防止跨权限复用缓存。

原有Native Worker强制委派、Main禁止交付写入、工作区围栏和用户请求校验保留；没有新增模型配置、Token/请求/费用限制或自动续跑授权。原题、followup、判定器和阈值不修改。

## 验收证据

[Case106 / MECH-NT01](../../../../../cases/case-106-mech-nt01/CASE.md)有公开输入、工具入口与独立汇总回执。新增两个回归在完整原版C619源码上均失败：权限缓存身份相同，用户追问无法修改原文件。修复后同一任务进入revision 2，文件实际更新；进一步发现的工作区标识变化也已修复。

本Case共11项：两个新增检查与九项既有shell、授权及未知写入边界。11项通过、无跳过；更广泛的原生调度和压缩检查91项通过，工具基础及宿主操作等另一批58项通过，二者含重叠，不能相加为独立用例数。

测试只模拟提供方和构造器的容器存在性，文件与任务生命周期真实执行，不启动Docker或外部模型。预备实际镜像、最终quick/full及CI以PR回执核对。本项不宣称原生音视频或PPT质量通过，正式40/60项选择与历史成绩保持，未部署或启用日程。
