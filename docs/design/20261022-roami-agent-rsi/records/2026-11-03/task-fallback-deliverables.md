# 任务回报失败时保留交付入口

关联 [Issue #616](https://github.com/ybz21/Roami/issues/616)，类型 fix，优先级 P1。

## 产品设计与用户故事

作为查看后台任务结果的用户，我希望总结暂时无法生成时仍能打开已经保存的文件，并分清任务结果与总结生成故障。成功任务使用成功边线；失败使用失败边线；待核验、未知或中断使用警示边线。文字状态始终保留，回报失败原因单独显示，不用颜色代替信息。

文件入口显示在回报状态前面，继续使用现有消息链接与手机全屏文件预览。没有产物时维持现有简短提示，不编造总结或成功状态。已有中英文翻译可直接复用，无新增产品文案。

## 技术设计

Agent 核心 `storage/turn_journal.py` 中抽出同一套 `completion_artifacts` 查询，供正常完成和失败兜底使用。最多四个引用按原顺序去重；文件名取持久化记录，只交付同一 owner、同一 task、未删除的 artifact。兜底只生成可信链接，不透传执行器原始 prose、伪造文件名或任意 URL。

原有任务版本、任务状态、分支归属、上下文遗忘、中断和重复事件围栏保持生效。`completion_for_reply` 对网页检索证据不足时扣留候选的规则，也用于失败兜底。文件保存不等于任务成功，真实任务状态仍来自数据库。

前端 `AgentMessageView` 将真实任务状态交给 `agent-activity.css` 的语义色规则；总结失败保留独立原因。没有改写任务、verification 或用量，也没有新增模型调用或重试。

基线 Runtime + SQLite artifact + 本地 UDS 的成功、失败、待核验三项均因缺少下载链接失败；五项围栏控制通过。修复后独立 [Case 103 / MECH-TF02](../../../../../cases/case-103-mech-tf02/CASE.md) 的后端10项、前端6项通过且无跳过，冻结清单前后一致，隔离实例完成清理。Case 目录完整性17项通过；目录共有102个定义，原正式40/60项选择不变。

桌面实际组件检查成功、失败、待核验三种状态；中英文、深浅主题及320、390、820、1100、1280、1600、1920宽度下，边线匹配语义令牌，链接命中正常，文档无横向溢出。Android 验收使用 Redmi Note 8 / Chrome 154 的实际坐标点按，分别检查状态、语言、主题、文件预览及返回和上下导航。截图与完整门禁结果附修复 PR，私有原始回执留在节点，不进入 main。
