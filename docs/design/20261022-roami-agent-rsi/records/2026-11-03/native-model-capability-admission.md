# 原生任务保存模型能力的准入校验

关联[Issue #620](https://github.com/ybz21/Roami/issues/620)，类型fix，优先级P1。

## 产品设计与用户故事

用户在模型页分别保存主、后台模型的能力。原生任务声明需要某种模型输入时，框架应核对实际执行它的后台角色；主模型支持图片，不能使后台角色自动获得图片能力。后台不支持时，在创建任务和准备工作目录之前拒绝该次派活。已有任务排队期间配置变化时，执行前再次检查。

主协调器可以在自身具备能力时先处理所需证据，再把已经明确的观察、决定和剩余执行交给后台。准入检查不切换角色或修改任何保存参数；主模型也不支持时，保留能力限制。

## 技术设计与模块

沿用`routing.requiredCapabilities`，明确两类约定：`cli:命令`核对节点命令可用性；原生任务的`model:能力`核对保存Worker路由中的同名布尔能力，只有实际JSON true满足要求。缺失、关闭、null、数字或字符串均不作支持证明。

- `dispatch/native_model_capabilities.py`读取保存的Worker能力，拒绝不能满足的要求；返回的成功回执只有角色及布尔事实。
- `dispatch/routing.py`在选定native后、持久化路由和创建任务前调用。现有CLI检查和专业执行器路由保持各自职责，未知专业能力仍未获验证。
- `executors/native.py`在创建工作目录、运行工具或模型前复核当前配置，不把旧路由回执当执行依据。无模型能力声明的既有任务兼容。


没有新增Token、请求数或费用限制；模型准入与每日限额继续由本地Go网关决定。

## 验收证据

新增[Case105 / MECH-MC01](../../../../../cases/case-105-mech-mc01/CASE.md)，公开输入给出角色差异及缺失、false、null、数字和字符串状态。依赖、入口和验收合同均在Case目录；name/description只保存在CASE.md。

原代码运行新增回归为10失败、1通过：不满足的声明仍创建任务，旧成功回执也未阻止不具备能力的执行。修复后的11项检查通过、无跳过；含路由、原生文件工作区、角色能力和模型配置的相关检查92项通过。原始失败回执保留，最终工程门禁及源码版本在PR中核对。

这些是模拟模型与执行器的机制检查，外部请求0，不读取或修改节点配置。它们不证明Agent会自主声明所有要求，也不等同于原生视频、PPT或多轮语义验收。原题、判定器、阈值及正式40/60项选择和历史成绩保持；未部署、安装节点Skill或启用日程。

额外的图片输入规划提示未通过小窗口压缩与真实任务检查，已撤回，未修改原有上下文阈值。原始视频试验和失败回执保留；创建前/执行前的声明能力校验才是本项最终变更。新发现的验收管理入口问题另见[任务控制契约](native-execution-control-parity.md)。
