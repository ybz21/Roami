# 重复取消时完整保存停止收尾

关联 [Issue #634](https://github.com/ybz21/Roami/issues/634)，类型 fix，优先级 P1。

## 产品设计与用户故事

用户停止任务或提出续跑时，进程关机等第二个取消请求不能让任务永远停在“停止中”。关机中断、用户取消与未知写入必须保持不同的结果。

PR #632 已保护执行报错后的失败登记，本项补齐首次取消自己的收尾：原取消分支在核对启动事务、结束 Native 回合和登记取消时仍有数据库等待，第二次取消可打断它。活动槽虽然释放，任务却残留 cancelling/running、轮次仍 running 或结果未登记，续跑无法应用。

## 技术设计与模块架构

只修改 Agent 的 `dispatch/runner.py`。现有失败收尾保护改为 `_settle`，由失败与取消分支共同使用；`_finish_cancellation`接收原取消分支，等待已提交的启动事务并完整保存原有停止记录后，再由外层传播取消。运行中的模型、工具及 Native 执行不进入保护范围。

`_finish_failure`语法树保持不变；原取消处理迁移后的语法树仅将内部裸 raise 改为返回外层统一重抛。未知写入仍保存 unknown/interrupted、阻止重放；正常关机仅记 interrupted，不伪造用户取消结果。Go 可核对 CLI 仍保留同一个启动键供恢复，未抢先判定外部 TUI 停止。

Core、Protocol 不新增依赖，专业能力仍通过外挂 Skill 提供。模型、参数、能力、Go 限额及账本保持，不增加 Python 配额或任务重试。
