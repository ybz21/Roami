# 用户目录与最终交付的来源绑定

续 [PR #662](https://github.com/ybz21/Roami/pull/662)，关联 #350、#443、#445、#446。两个来源缺口独立验证，未修改原题、判定器、阈值或节点保存的模型路由、参数和能力。

## Product Design

用户指定的目录被拒绝后，不能通过改写委派内容、删除目录参数而改用私有目录。模型自己猜错的目录仍允许纠正为默认私有目录；用户下一条明确指令可以选择新目的地。

Native 评测需要评价同一请求最终送达的回复，不能把初始排队确认当作最终答案，也不能从历史记录中挑一个符合预期的数字。直接 Main 回复的既有判定保持。

## User Stories

- 用户指定不可用的目录后，得到原目标的错误说明，报告不会被悄悄保存到另一个目录。
- Main 猜错目录时可以自行纠正；用户后续授权新的目录时可以继续。
- 多轮 Native 任务分别核对当前请求和执行版本；上一轮执行记录不能证明下一轮已执行。
- 一个请求委派多个任务时，全部最终交付有来源证明后才选择最后送达的回复；不会绕过缺失的交付。

## Technical Design

`dispatch/tasks.py` 在已有目录拒绝检查中读取全部拒绝记录，兼容 compact 与 legacy 目录字段。用当前 turn 的实际用户请求核对被拒绝目录的原文，不使用助手改写的 goal。只有 Native、自行猜测的目录和默认私有目录纠正才保留例外；用户原文中存在被拒绝目录时继续返回已有 `TASK_TARGET_REVIEW_REQUIRED`。检查按 turn 隔离，新的用户指令不继承旧拒绝。这里核对原文证据，不解析自然语言意图或推测路径别名。

`evaluation/execution/evaluation_tasks.py` 从当前 turn 的成功接收回执查找任务，核对 owner、Main 会话/分支、当前 revision、最新 Native attempt、completion job 的 task/revision/run、已完成的最终回复和 `answerText` 类型。未知结果与未停止输入不构成交付证明。多个已接收任务必须全部匹配，再按送达顺序选择最后回复；选择过程不读取题目预期答案。

`NativeFilesExecutor` 在每个原始问题完成后执行上述核对。缺少证明返回 `RSI_NATIVE_DELIVERY_REQUIRED`，不会借用排队确认、先前问题的执行结果或当前 Main 的直接计算。`allow_tasks=false` 继续使用原 `committed_answer`，原有反挑选答案控制保持。
