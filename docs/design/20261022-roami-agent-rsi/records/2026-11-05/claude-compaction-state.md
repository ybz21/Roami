# Claude 压缩后的会话状态

关联 #350、#443、#445。修复合法压缩事件造成的状态丢失，不对线上历史未知执行补造结果。

## Product Design

正在执行或已经空闲的 Claude 会话完成上下文压缩后，原实现把 `SessionStart` 一概当作未跟踪的新启动，阻断后续正常停止回报与任务续作。现在已认证的原回合在合法压缩事件后保留状态和身份。

## User Stories

- 正在执行的任务压缩上下文后，继续使用同一回合和提示身份，最终由原停止证据收尾。
- 已结束的会话压缩后仍可正常承接后续任务，重复压缩不改写结果。
- 压缩不清除未结束的工具，也不把已中断或缺少身份的回合恢复成运行。

## Technical Design

[Claude 官方 Hook 文档](https://code.claude.com/docs/en/hooks#sessionstart) 将 `SessionStart.source=compact` 定义为压缩后的事件，与 startup、resume、clear 和 fork 分开。`SessionEvent` 增加 source 解析；只对 Claude、非首次启动、busy/idle 已知状态、完整原回合与提示哈希，以及缺省或匹配的事件回合保留原状态。原提供方、执行器和 pane 身份验证继续先执行。

保留的内容包括原回合、提示哈希、启动键、已完成键及未结束工具。压缩仍使此前 Stop 候选失效：即使压缩前收到 Stop，也必须取得新的 Stop 与匹配 idle。空后台任务/定时唤醒登记、进程停止、工具收尾、手工接管、取消和提供方隔离的要求不变。普通启动、恢复、清空、分叉及未知状态继续按原规则处理。

## Acceptance

- 相同最终测试在旧源码上有 5 种合法压缩场景失败：执行中、带同一提示、未结束工具、重复压缩、已空闲。
- 新实现 21 种场景连续 3 轮竞态检查通过，包含上述 5 种正例及 16 种身份/停止边界反例。
- 缺少来源、换提供方或提示、未知/提交中、缺原回合或提示哈希、未结束工具、缺后台登记、后台任务、定时唤醒及旧 Stop 不生成完成结果。
- 完整门禁与提交钩子结果见 PR 检查和私有退出回执。Go 变更按仓库范围检查执行，不将无关 Python 跳过项算作业务验收。

线上 Claude 原生记录确有压缩事件，但旧 Hook 来源字段没有持久保存；这只提示相关路径值得核对，不能唯一证明历史未知状态的成因。本修复不重放旧 Hook、不发送新提示、不停止其他会话，也不把两条未知执行标为已完成。模型配置、额度及历史 RSI 分数保持。
