# Go 模型准入耗时回执

关联 #443、#445、#446、#657。增加观测，不宣称降低延迟或修复模型内容质量。

## Product Design

调用方的完整模型请求时间包含 Go 准入等待，网关账本只在请求获准后开始计时。新回执单独记录准入耗时，便于判断慢在准入还是后续请求路径，避免把完整等待都解释为上游模型耗时。

## User Stories

- 对照一次请求的总耗时与 Go 准入耗时，定位等待阶段。
- 容器、代理和错误回执继续保留可信的准入观测。
- 旧版本或没有取得响应头时保持未知，不能以零代替缺失值。

## Technical Design

节点私有入口和原生目录入口在调用 `admit` 前开始单调计时，返回 `X-Roami-Model-Admission-Ms`；目录来源故障转移累计每次准入耗时。计时包括等待、再校验及账本准入，不包括上游请求。计时回执与已有调用标识共存，提供方同名响应头不能覆盖它。

Python `request_receipts.py` 仅从可信 Go 传输读取非负 int64 范围的整型毫秒，保存为 `gatewayAdmissionMs`；私有桥接继续传递。外部提供方、布尔值、浮点值、负数、非有限值、溢出与坏格式不建立观测。没有头或没有完整回执时不生成零。

观测仍位于执行记录的既有 headers/upstream_headers 事件，不增事件轮询或界面文本。准入次序、权限、额度、重试、请求参数、用量与结算保持，Python 不承担新的预算限制。剩余时间还包含传输等工作，不能简单等同于纯推理。

## Acceptance

- 相同最终控制在旧源码上：Go 三种有效计时场景失败；Python 八种正向传递失败、26 种边界控制通过。
- 新实现的节点入口、目录入口及故障转移三种场景各 5 轮竞态检查通过，覆盖实际排队、排除上游等待及拒绝提供方覆盖；账本行与实际转发次数保持。
- Python 回执、私有 Unix 桥接、失败与重试观测等 131 项相关检查通过；Go 网关整包竞态检查通过。完整门禁和提交钩子结果见 PR 检查及私有退出回执。
- 触发本项调查的 v8 原题复测仍为失败：16 个计划场景只观察 2 个，9 个检查点通过，第二场景超时。39 笔已记录调用均为 known/200。一次 37,856.099 毫秒的包装器调用对应账本 2,532 毫秒；前一请求结束至本次获准间为 35,346 毫秒，其中两笔其他调用共 35,332 毫秒。时间线与共享准入等待吻合，但没有当时的直接排队跟踪，不归因给某个具体调用方。

旧超时、未知账目及正式成绩不改写；没有为挑选通过轮付费重试。生产模型配置、原题期限、判定器及默认镜像保持。本字段为可选观测，旧端缺失时仍可工作；不作为 Actor 能力或晋级证明。
