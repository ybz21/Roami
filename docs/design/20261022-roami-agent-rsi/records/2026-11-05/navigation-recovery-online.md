# 旧未知导航任务的线上恢复核对

关联 #398，核对既有 #401 修复的线上结果。本次没有新增执行器代码，也没有把业务待核验改成已完成。

## Product Design

同一用户再次请求已停止的只读查询时，沿用原任务创建新的执行版本；旧未知结果保留，缺少停止证据或可能存在外部写入时仍阻止重放。

## User Stories

- 原查询不再因第一版未知结果永久阻塞。
- 用户能在主聊天看到新一版检索结论，并在原任务详情核对执行结果。
- 第一次未知回执和只读恢复证据可追溯，业务验收仍由用户决定。

## Technical Design

生产记录中，第一版 attempt 为 unknown；`task.navigation_recovery` 保存六条仅导航动作和一条未知工具的停止证明，inputStopped=true、outcomeKnown=false。随后 `task.steered` 沿用原任务创建 revision 2，原 attempt 没有覆盖。第二版执行回报 succeeded，任务为 waiting_user；主会话存在对应的最终助手消息。

2026-11-05 通过真实 Chrome 进入原主会话，再从任务列表打开详情。用实际组件绑定核对原任务 ID，确认第二版回报和结果可见。开始时选中了另一条同名任务，已更正选择；没有把该差异作为数据一致性缺陷。未提交新查询、点击任务确认或改写生产库。

## Acceptance

- 原自然请求已在 2026-11-04 触发原任务续作，并在主聊天交付新结果；此次核对该持久证据及当前界面，不冒充今天重新执行了检索。
- 旧版 unknown、新版 succeeded、当前 waiting_user 同时保留；修复的是长期阻止只读续作的问题，不代表业务内容已获用户验收。
- 当前源码的导航恢复与 Native 工作区证明共 45 项检查通过。无停止证明、外部写入、仍运行资源和不匹配来源继续拒绝。
