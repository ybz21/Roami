# 参考质量与演示文稿设计

## 产品设计

原发布参考的两页PPT仅有标题和数行正文。字段正确、可读，不足以将其作为高质量演示正例。新建演示稿的质量评审增加信息层级、有意义的视觉组织、版式与整套叙事；白底和克制留白本身不扣分，不强制装饰、无数据图表或虚构信息。局部对齐、改色等任务仍按请求范围核验，不要求额外重设计。

## 用户故事

- 用户可以委托AI判断参考的好坏，记录实际评审来源，不再把这四份逐项打分当作必须等待用户的选择。
- 内容准确但缺少设计的稿件不能以事实字段齐全掩盖呈现短板。
- 设计与重设计方法作为可选Skill提供，核心不增加PPT专用工具。

## 技术设计

`domain/reference_authority.py`负责来源及绑定校验，现有评审模块接通流程，复核摘要模块保留来源计数。`skills/presentation-design/`提供简短入口及按需复核标准，使用现有编辑器、文档库和通用执行能力。节点没有自动安装该包。`improvement/evaluation/artifact_review.py`补充新建演示稿的评审指令并接通参考来源策略；维度、0至3范围、通过门槛、保存模型路由、图片能力及Go网关准入保持。

指令参与`PROTOCOL_HASH`，变更后旧协议校准证书必须失效。零模型协议对照实际拒绝旧证书，返回`RSI_ARTIFACT_CALIBRATION_CHANGED`；没有创建新证书。旧人工标签、历史成绩、原任务与判定器不改写。

默认策略仍是 `human_only`；用户明确委托时，候选配置可选择 `human_or_user_authorized_ai`。AI参考保留 `human_reference=false` 和空 `human_rater`，另存评审者、授权原文、证据哈希及期望分的来源绑定。证据或分数变更即拒绝，证书策略与加载策略须匹配。私有配置决定接受的来源类型，元数据本身不构成独立的身份认证。

校准结果与复核回执保留参考来源数量。已有真实人工标签不改写；显式协议夹具验证8个人工加4个AI的往返、默认拒绝、来源误标拒绝及已开始评分不可重放。新增Case90与实际测试使用相同公开输入，24项机制检查；不是外部模型或真实人工评审。

## 参考修订

四份委托AI评审先作出“导入方案与基础计数器保留、PPT不作高质量正例、备份方案明确顺序后复审”的决定，来源为`user_authorized_ai_review`，不是实际人工评审。

新发布PPT保留两页、Ada、2026-11-02、60秒目标及来源，用统一网格、日期与目标数字层级重做；明确60秒是目标而非测量结果。首版渲染暴露字体间距问题，另存修订版并逐页检查，旧版没有覆盖。新PPT由助手编制，不是Agent自主完成原题或独立评分通过的证据。

备份参考将发布后状态明确为`published_unverified -> verifying_restore -> verified`。记录绑定清单及哈希的verified标记后才允许清理；恢复失败保留最后可用的已验证恢复点，即使超过七天窗口，并补充八天旧备份加新候选恢复失败、验证标记前崩溃等验收情景。这是设计材料修订，没有声称修复了线上备份服务或复现数据丢失。

新参考使用原任务和依据，在既有固定镜像中重新渲染，旧材料与渲染保留。模型调用为零；参考质量复核不能替代实际音视频、股票原题、正式全套及真实观察。
