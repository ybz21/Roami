# 评分证据与产物版本绑定

## 产品设计与用户故事

原生股票评分记录以remote_path保存远端产物哈希，复核原实现只读取path，且只在渲染后核对被渲染文件。原检查与复核之间的产物改动、非渲染CSV变化，以及依据提取或评分期间的改动可能未被拒绝。希望复核与原检查针对同一版本，变动时保持待复核，不能将旧检查与新内容组合成通过结果。

## 技术设计

artifact_sources.py统一解析原记录的path、remote_path与host_native_snapshot，并核对实际文件及快照哈希；冲突别名、冲突哈希、越界与符号链接拒绝。原生股票三份文件均受约束，CSV不因未渲染而跳过。

产物收集器在开始及渲染/依据提取结束后核对；复核器在请求前和评分返回后再次核对原记录与渲染包文件。变化保留pending及错误码，已发生评分回执与用量保留，不重放请求。不增加模型或限额，不修改原阈值、盲评格式及独立性要求；评分校准协议对有效输入保持。

## 验收边界

新增Case83，公开合成文件与实际测试夹具一致，脚本化渲染与模型不作质量成绩。12项新增检查在旧源码失败，另1项旧代码已能拒绝。46项机制检查包括真实LibreOffice页面边界；后续按冻结回执记录最终结果。实际历史产物回放只在副本执行，原模型配置、人工标签、旧成绩及原输出保持。

Worker图片输入与不同保存模型的评分条件仍由用户决定；不绕过、不改保存配置。音视频和股票真实质量、人工及正式观察未因此通过，相关Issue继续开放。
