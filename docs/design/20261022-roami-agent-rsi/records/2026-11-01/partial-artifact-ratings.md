# 部分评分的回执与汇总

## 产品设计与用户故事

第二位评分者失败时，第一份有效评分仍在原始请求事件里，但复核回执ratings会清空。用户希望看清哪些环节已经完成，不能为找回结果而重新发送未知请求，也不能把部分评分算作通过。

## 技术设计

ArtifactReviewer.rate接受由review持有的空收集列表，验证每份评分后即时追加；后续解析、传输、关闭失败或中断不再丢弃完成部分。私有artifact-review.json增加完成/预期数量，仍保留完整评分与用量。artifact_review_receipts.py负责验证与裁剪为维度汇总，trial_evidence把摘要加入既有Case证据，并支持从私有回执恢复。Case摘要不复制评分理由，坏文件和符号链接不作为评分证据。

原盲评输入、双独立评分者、校准协议及阈值保持；未完成维持待复核，取消继续传播，不增加调用或自动重放。没有模型配置或额度规则变化，没有新增产品页面。

## 验收边界

新增Case85；输入、图像、校准与评分者全部为公开合成夹具，零实际模型/人工确认。原控制重现：两个脚本请求中第一份有效评分可从请求事件读取，但旧复核回执有0份评分。后续以冻结机制回执记录结果，不改历史原题与成绩。
