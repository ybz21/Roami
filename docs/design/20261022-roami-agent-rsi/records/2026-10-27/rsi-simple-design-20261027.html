RSI 配置、运行结果与修复追踪 · 2026-10-27

本轮先交付 HTML 交互原型供确认，不修改实际 RSI 调度与额度策略。原型使用隔离演示数据，所有运行、修复、保存操作仅在页面内演示。

生成：cd frontend && node scripts/build-rsi-design.mjs；输出 设计与原型、独立原型。

产品设计

首页以选定的一次 Workflow 运行为中心，先展示 Case 和 Issue 汇总，再查看折叠的单项详情。三个主 Tab 为工作流、运行结果、Issue，默认打开运行结果；页头保留“运行评测”和“设置”。选择本次运行与更早的对比运行，历史结果不受当前设置或其他运行的状态覆盖。运行前选择快速检查 10 项或完整评测 60 项。运行中的进度与停止动作直接可见，停止保留已完成结果。

保留七环节工作流，取消每个环节的大型配置卡与分散表单。工作流 Tab 直接展示七个环节的状态及一句执行摘要；点击环节查看执行者、输入、实际执行情况、产物与下一步，技术日志按需展开。手机使用纵向步骤与就地展开的详情。尚未执行的环节说明等待条件，不伪造产物。结果详情先展示通过、失败、待评分和报告，再展示具体问题、交付物与运行过程；待评分不计为通过，派活完成不等于修复通过。

设置集中为自动评测、评测范围、问题跟进、模型与费用四组。自动评测关闭时隐藏时间和时区；开启后设置每日时间。问题跟进保留自动修复与自动创建 GitHub Issue，修复之后必须独立验收。自动提交 PR、合入和关闭 Issue 不因开关而获得新的默认授权。

RSI 不再提供每日 Token、每次诊断 Token、每次 Codex Token、请求次数、角色输出上限等独立额度配置。主控、执行与记忆模型沿用模型页配置；RSI 设置仅展示共享每日金额限额与“模型页”入口。额度仅在模型页编辑。达到每日限额或费用未知时，说明暂停原因并给出模型页入口，保留已经产生的结果和记录。

桌面保持现有设置导航、基础底色和单线分隔。手机使用等高返回栏与单一内容滚动容器，长设置与运行详情是整页，不使用长弹窗；保存栏在滚动区之外并避让键盘，底部保留首页、项目、工具、设置。原型支持中英文、深浅主题、桌面与手机预览，以及有待处理、运行中、修复中、全部通过、尚无记录、每日限额、费用待核对七种状态；“修复中”展示已完成的复盘、Issue 清单和正在执行的修复。

按运行查看结果与多轮问题追踪

本轮先显示 Case 的计划数、通过、失败、待评分、未执行和运行中数量，并按公开、自有、机制分组。点指标或展开 Case 明细后，用折叠行查看原始结果、证据、跨轮轨迹与关联 Issue。未运行、待评分和模型费用未知不能算通过；Case 由失败变为通过只是本例结果变化，不直接判定整个 Issue 已解决。

Issue 汇总先显示已验证修复、已关闭和仍待解决数量，再显示本轮新增、验证修复、关闭、持续通过、再次出现、仍遗留、未验证与未覆盖。汇总数从同一份 Case 和 Issue 观察记录推导。反复出现的同一问题串联多次运行，一次运行的多条日志只计一次命中。折叠详情展示类型、优先级分析、首次出现、最近失败、关联 Case、验收条件、修复证据和各轮状态。

类型区分 fix 与 feature：fix 违反已有要求，feature 增加能力或覆盖；feature 不混入失败 Case 数。优先级说明保留依据：P0 涉及整体阻断、账目或费用安全；P1 影响核心功能、交付或正确性；P2 为一般缺陷与能力补充；P3 为体验优化。可按本轮变化、类型和优先级筛选，原型展示分级依据，不凭关键词宣称完成自动诊断。

修复必须有绑定当前版本的独立验收回执。已验证修复与已关闭分别统计，至少两个后续完整且同口径的周期无复现才可关闭。再次失败立即重开；待评分、快速检查、部分执行和未覆盖不能累计完整观察次数。比较只覆盖双方相同 Case，评测集、判定器、模型和环境不同则停止自动判定修复或退化，保留原始结果供查看。

运行选择区的折叠记录展示每轮 Case 结果和 Issue 变化；点击可回到该轮汇总。跨轮问题页展示截至选定运行的历史，不泄露未来运行的修复或失败。七环节 Workflow 保留在独立工作流 Tab，阶段摘要、产物文件名和内容均绑定该轮，不再对多轮历史复用全局最新状态。展开项、选择的运行和基准在查看产物后保留。

用户故事

  1. 我打开 RSI 就能知道最近评测通过多少、哪些未通过、哪些仍待评分，并能直接查看对应问题。
  2. 我不用理解流水线节点就能开始一次快速或完整评测，运行中可以停止，并保留已完成的结果。
  3. 我只在模型页维护每日限额；RSI 告知共用额度和暂停原因，不要求再次填写 Token 数。
  4. 我在一个设置页开启每日评测、选择时间和测试环境，修改失败保留输入，离开前提示未保存更改。
  5. 我点开问题能看到验证情况和下一步修复动作；交给 Codex 后显示修复中，只有独立验证通过才进入观察，不提前宣称解决。
  6. 我在手机上能通过真实点按完成设置、保存、查看结果和返回，操作按钮不依赖悬停提示。
  7. 我能看到全部七环节的实际状态；点击环节查看谁执行、用了哪些输入、做了什么、产出了什么，以及接下来等待什么，打开产物后返回仍保留选择。
  8. 我选择某次运行和对比基准，先看 Case、Issue 总量与变化，再折叠展开单项结果和证据。
  9. 我能知道同一问题在哪几轮出现、哪次通过验收、是否再次失败，以及为什么还没关闭；未覆盖不会被误算成已修复。
  10. 我能按 fix / feature 和 P0 至 P3 筛选，展开查看影响与分级依据，而不是只看到没有解释的标签。

原型由 Vite 构建为无外部依赖的单文件 HTML，设计总稿内嵌 sandbox iframe，可切换视口、主题、语言、状态。偏好写入被原型本地响应截获；不调用真实 RSI 接口、不发模型请求、不创建 GitHub Issue。正式页面由 AgentImprovement 接入 RsiWorkspace，复用运行记录及恢复接口；配置集中保存，逐段确认成功版本，失败保留未保存输入和原始运行快照。

正式落地时，模型调用必须经同一个 ModelProxy / ModelBilling，覆盖评测容器网关、复盘、独立评分和其他模型调用。金额限额由模型页现有配置决定，停止新增请求的判定沿用实际费用、币种与未知回执处理。删除 RSI 额度准入校验和动态 Token 压力提示，同时保留实际用量记录、取消机制及隔离执行的必要技术边界；历史额度记录和未知账目不清零、不伪造退款。共享限额运行时已接入，原型本身仍不访问实际模型或账本；落地边界见本节的实现记录。

验收关注：所有场景的主要动作可达；默认页面无独立 Token 输入；模型页修改限额后 RSI 展示同一份值；失败保留输入；完成记录不轮询；桌面及手机无横向和文档滚动；手机返回栏、底栏、保存栏与触控命中正确。

正式页面与共享限额实现 · 2026-10-27

AgentImprovement 接入 RsiWorkspace；RsiRunResults、RsiWorkflow 与 rsi-history 分别负责汇总与明细、七环节、跨轮比较。示例原型复用这些组件，仅替换数据源。正式结果从所有者隔离的 pipeline/runs/{id}/results 读取，按选中运行截断历史，保留冻结的 Case 名称与合同；旧记录缺少比较身份时不伪造可比性。历史最多取 100 次，窗口不完整会明确显示，不能据此确认新增或修复。复发信号与同条件比较分别统计，不推断共同根因。

配置只保留日程、任务范围、工作流自动化和模型页共享金额限额。运行时 Main、Worker、Memory、独立判定和 Codex Responses 代理统一经 ModelProxy / ModelBilling 准入与结算；旧 Token、请求数和角色输出额度不再用于实时 RSI 准入。冻结协议及独立 CLI 仍保留原合同，历史预留与未知回执不清零。隔离执行的时间、进程、文件和独立评分协议边界继续生效；不能接入共享网关的 external 执行器拒绝启动。

本次未复现不等于修复。只有 host_code_verifier_v1 的独立源码对照回执，且 Case 合同、修复源码、模型、环境和判定器全部匹配，才显示已验收；缺失执行日志、未来回执、未知用量和再次失败均不通过。关闭还须实际 observation.closed_fixed 事件与匹配的完整观察周期，界面不会因同一天点两次复测而自动关闭。工作流的 repair、verify、publish、observe 等环节按实际动作状态生成只含允许字段的回执，不展示私有答案或修复提示词。

结束运行不定时请求详情，活跃运行复用可见性轮询；切换节点或运行后旧响应不覆盖当前界面。设置按需读取模型限额，加载失败不显示无限额。三个 Tab 共用选择与筛选；产物在手机全屏二级页查看，返回保留上下文。

验收边界：真实 Codex CLI 已对本机模拟 Responses 服务完成一轮协议检查，确认请求进入共享计量，未访问外部付费模型。实际 Go 网关与 Python 服务使用隔离示例数据验证页面，示例运行明确标识，不作为能力提升或真实 Issue 关闭依据。真实 Android 仍锁屏，尚未完成仓库要求的真机触控验收；四份人工评分锚点和正式完整日观察也未补齐。

正式实现检查：运行时全量 1615 项、前端 140 个测试文件的 1016 项用例通过；typecheck、i18n、hover 与生产构建通过。中文深色、英文浅色各检查 320、390、820、1100、1280、1600、1920 宽度及三个 Tab，共 42 组布局无文档或内容横向溢出；实际接口检查 9 项覆盖冻结元数据、待独立验证、七环节产物、文件完整性、返回保留上下文、无独立 Token 配置和结束记录不轮询。环境或判定器变化、未来回执、复发及不完整验收均有反向回归。手机浏览器预览不替代真机验收。
