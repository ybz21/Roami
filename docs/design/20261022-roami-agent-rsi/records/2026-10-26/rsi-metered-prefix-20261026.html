已计量前缀预留与流错误保真 · 2026-10-26

Product Design

预算准入继续保守预留，但已成功计量、序列化完全相同的文本前缀不再每次按全部 UTF-8 字节估计。每次请求仍扣完整实际输入与输出；没有费用折扣、未知用量补零或 Case 上限提高。已知生成失败保留原异常码，不能伪装成可重试的流不完整。

User Stories

用户不会因重复上下文的过大预估而提前失去必要的收尾调用，也不会为已经明确达到输出上限的记忆提取重复付费。提供方用量未知、上下文变化或工具变化时保持原拒绝与保守回退。

Technical Design

input_reservation.py 保存单个角色实例最近成功、单次请求且输入／输出用量完整的文本指纹与用量。只有消息严格追加、原前缀逐项序列化指纹及工具指纹相同才采用“原完整输入 Token + 新增序列化字节 + 既有 4,096 预留”；图片、编辑、前置插入、工具变化或不完整响应回退。RequestBudgetModel 另计新预算提示的全部字节，双层 MeteredModel 共用同一预留，容器内持久 MeteredModel 也执行相同规则。实际结算与未知用量熔断不变，预留依据写入私有日志。

ChatCompletions 识别 SSE error 帧，先保留已到达的用量，仅透传有限的协议异常码，其他格式归为 MODEL_STREAM_INVALID，不回显提供方内容。部分工具调用不发布；ModelGateway 的 MODEL_OUTPUT_LENGTH 等终止码到达 MemoryJobs 后一次失败，不再降格成 MODEL_STREAM_INCOMPLETE 并重试。协议标为 container-uds-v6-prefix-reservation，不与 v5 混算同合同收益。

诊断和报告首次建立当日预算时使用已配置的每日例数，诊断同时检查例数余额，避免原先 10,000 占位值阻塞后续 120 例配置的正式准入。现用当日预算在确认没有正式 cycle、已用例数为 0 后，从占位值收紧到既有 120；Token 上限仍为用户授权的 20,000,000，用量与预留计数均保留。

验证与角色配置

64 项准入、计量、错误透传相关回归通过，覆盖共享预留、完整扣账、前缀变化／多模态回退、未知用量、失败响应不建立前缀及容器侧持久计量；另有 25 项流水线回归通过，包含先诊断再正式预留和每日例数上限。DeepSeek none 的四次记忆探针共 2,237 Token，但空提取语义断言失败，未采用；GLM low 的四种语义输入均通过，共 2,104 Token。RSI 配置保存为 Main／Worker DeepSeek low、Memory GLM low，Memory 输出上限仍为 2,048，自动调度关闭；不表示部署或改配现用 Agent 服务。
