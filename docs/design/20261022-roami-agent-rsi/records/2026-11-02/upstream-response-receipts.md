# Go网关上游响应关联与错误状态传播

## 产品设计与用户故事

排查间歇401时，已有账本只保存客户端请求编号与结算状态，上游定位编号仅随响应转发。用户需要在调用侧记录不全时仍能从本地账本关联供应商记录，并区分上游响应和本地协议转换失败。历史缺失证据不能从新功能反推或回填。

同次检查实际复现另外两处问题：目录路由透传上游伪造的 `X-Roami-*` 响应头，可能把上游内容误作本地网关决定；协议转换将上游401、429、500统一返回502，掩盖鉴权和限流语义。新回执服务于定位，错误传播修复服务于调用方正确处理响应。

## 技术设计与模块

修复基于最新#584，保留其智能体归属、独立Key和模型源记账。

- `internal/modelgateway/upstream_receipts.go`只提取真实HTTP响应状态及合法请求编号；优先`X-Request-Id`，不合法或缺失时尝试`Request-Id`。允许1至200个ASCII字母、数字及`_.:-`，不截断、不去空格后冒充合法编号。
- 直连和模型目录两条转发路径在收到响应后记录关联字段，再随同一次结算原子保存。协议转换同样保留原始响应信息；例如上游200但转换失败，本地结算502、`upstreamHttpStatus=200`。
- 账本v4新增`upstream_http_status`及`upstream_request_id`，统计API返回`upstreamHttpStatus`、`upstreamRequestId`。原`requestId`仍表示客户端请求。旧记录默认0和空串，不推测上游状态或编号；已有价格、消费、未知状态、归属和请求编号保持。
- 目录路由丢弃上游全部`X-Roami-*`响应头，本地生成调用、来源、别名与协议能力标记。直连既有响应头白名单继续生效。
- 协议编码器保留原HTTP错误状态和`Retry-After`；格式转换自身失败仍使用502，已经开始的流保持原有错误事件机制。不增加自动重试，不选择或覆盖模型、参数、能力、Key或消费额度。

不保存完整响应头、响应正文、凭据或连接异常文本。该功能不分析鉴权原因，也不声称任何401都不会计费；结算和未知用量策略保持。预先拒绝或未收到响应时不创造上游状态和编号。
