# 外挂演示稿的精确文本修订

## 产品设计与用户故事

实际股票任务 v185 的第8页同时保留旧结论和修订结论。用户需要能删除重复文字、纠正文案并保留可编辑对象；对齐和颜色编辑不足以覆盖这个问题。为已有 `presentation-edit` 外挂增加精确替换，原文与次数不符合观察时不发布文件。

这是编辑能力修复。事实核对、图表质量和执行者自主采用仍需独立验收，不能将一次开发者指定的替换算作原题通过。

## 技术设计与模块

- `scripts/edit-request.schema.json`：`replaceText` 定义非空 `old`、可为空的 `new`、正整数 `expectedCount`（默认1）。
- `scripts/pptx_text.py`：只替换普通文本片段内的字面匹配，支持同段落跨片段，精确核对次数后逆序修改；保留片段属性与段落结构。替换文字继承首个匹配片段的样式。
- `scripts/pptx_edits.py`：已有对象选择与整批编辑入口调用文本模块；同一对象的多次文本操作按顺序执行。字段、跨换行或未知内联内容不被展平。文本操作先于同一操作中的对齐和颜色。
- 原有 `document_publication.py` 继续负责工作区、源文件和目标文件哈希检查及发布；任何操作失败都不发布部分批次。
- [MECH-DP01](../../../../../cases/case-64-mech-dp01/CASE.md)：增加公开混合样式输入 `input/text-replacement.json`、CLI 原生输出及严格回执；沿用既有 case，未扩充正式套件。

能力、依赖仍属于外部完整 Skill 包。Agent 运行时代码、基础工具目录、模型配置和 Go 网关额度均未改动；现有集成测试增加文字修订，验证完整包经导入、读取、普通 bash 和现有产物交付机制运行。

## 验收证据

79项独立包测试和1项真实 NativeExecutor 交付合同，共80项通过、0跳过。覆盖跨样式替换、删除、重复次数、多段落、顺序操作、字段与未知节点、XML文字、无效请求、并发源/目标修改及失败批次。输入与冻结实现哈希保持，隔离实例清理成功；无真实模型请求。
