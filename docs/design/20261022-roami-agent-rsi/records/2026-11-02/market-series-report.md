# 事实绑定的外挂行情报告

## 产品设计与用户故事

用户需要可读的董事会报告、五类必需图表和逐页讲稿，并能追溯每个数值的来源。生成文件不等于准确交付：先看摘要，再展开价格、均线、相关性、收益分布、成交量和回撤。沿用用户要求的清洗字段和上传位置。

股票任务多轮出现同类问题：成交量被写成机构持仓或流动性深度、同日相关性被写成次日预测、峰度被当成时间聚集证据、日历分组与滚动窗口混用，以及图表标题与幻灯片标题重叠。再增加一段提醒不能使计算、图表和正文自动一致，因此增加可执行的外挂流水线。

## 技术设计

`skills/market-series-report/` 通过已存在的 Skill 目录和普通 Python 执行使用，专业依赖声明在入口脚本，保持在 Agent 核心之外。无需新基础工具、模型路由、额度或调度配置。

| 模块 | 职责 |
| --- | --- |
| `series_facts.py` | 校验输入、排序、计算明确口径的描述统计、实际日历年分组及配对样本数 |
| `series_charts.py` | 从同一序列生成六幅图，图内不重复幻灯片标题 |
| `presentation_layout.py` | 同一事实生成摘要、六个图表页、结论页及逐页讲稿；文字和形状可编辑，图表为图片 |
| `slide_rendering.py` | 确认实际字体，使用独立 LibreOffice 配置渲染已保存文件，核对页数及文件哈希 |
| `report.py` | 工作区与新目标校验、可选原始字段合同、源快照复核、发布文件和机器回执 |

命令读取已清洗 CSV；清洗和保留原始字段的导出仍使用 `tabular-analysis`。`--matrix` 选择分析字段，不决定导出字段。组合任务使用 `--source-schema` 对比实际原始与清洗文件头，在发布前拒绝字段缺失。

价格变化与含分红总回报分开；CAGR使用实际日历跨度，波动率公开年化假设。日历分组包含日期、样本数及统计口径。峰度和绝对收益的一阶滞后相关分别计算，相关系数不解释为因果或预测。摘要直接从相同事实生成，不需要另写无来源结论。

发布只接受新目录。构建在临时目录完成，复核源文件后创建目标，最后发布 review manifest；已有目标不会覆盖。发布中途未知必须检查目标，不能盲目重跑。回执保留实际PPTX和每页PNG的哈希，并明确 `visualInspectionPerformed=false`。渲染不冒充人工或独立评分；编辑成品后要重新渲染，上传后仍按任务要求读取核对。

## 验收记录

- [Case99 / MECH-MP01](../../../../../cases/case-99-mech-mp01/CASE.md) 提供公开乱序跨年输入、工具清单、来源、冻结运行器和16项机制检查。实际 LibreOffice 渲染九页，复核哈希、源文件不变、字段缺失拒绝和重复发布拒绝；不调用真实模型。
- 原任务试跑 v187 实际采用初版 Skill，但清洗CSV只有7列，原字段合同失败；保留失败。v188清洗CSV通过3735行8列，但未采用报告 Skill，最终12页仍有错误推断、遮挡及异常柱图，不能算修复。
- v189实际采用报告流水线，清洗CSV仍通过，相关性、峰度和回撤说明改善；最终9页逐页检查后，发现 Agent 自行新增摘要再次推断流动性变薄。因此补齐流水线中的事实绑定摘要，再运行原任务验证。
- v190清洗CSV通过，最终8页已渲染并逐页检查；Agent读取报告 Skill 却没有执行流水线，重新编写的稿件仍有流动性推断、旧交叉日期被当成最新日期、零相关被当成独立等错误。因此不能宣称自动任务质量已经修复。此后在统计模块增加按实际日期索引计算的全窗口交叉事件及说明，公开夹具验证它不使用旧行号错配日期；此增量尚未进行新的原任务试跑。
- 以上试跑均沿用节点保存的模型、参数与能力，未修改原始输入、提示、判定器或阈值。v187/v188/v189/v190分别31/60/55/39笔请求，全部按UUID匹配本地Go网关，费用分别0.1471473/0.2887648/0.2692094/0.1729945元。

本地门禁还发现父进程退出测试的两个竞争：PID文件刚创建尚未写完时立即判失败，以及 `poll` 被系统信号中断后误报子进程存活。单独修订该Go测试，等待可解析的正PID，并在原5秒期限内重试EINTR；真实子进程退出和管道EOF断言均保留。实际退出检查重复50轮通过，不能据此声称另有运行时进程泄漏修复。

原股票任务仍需独立质量评分，机制回归不代替原始评分。音频、视频、正式全套和两个实际观察日也不由本项证明。源码合入不表示已在节点安装 Skill、部署或启用调度；失败样本与历史成绩保留。
