冻结运行时回归边界与临时数据

Product Design

候选 Actor 的回归只验证运行时行为。需要完整仓库、下载脚本、私有判定器或宿主 Docker 的验收仍由宿主完整门禁和 CI 执行；不把这些依赖提供给 Actor，也不因环境缺失误判代码质量。

User Stories

  • 升级 Actor 时，真实运行时断言失败或收集异常仍阻止通过。
  • 宿主验收的全部原测试继续运行；Agent 的 host 命令行为仍在 Actor 回归范围内。
  • 任务输出收集回归不依赖外部 Case 目录，Case 61 的规范输入和测试快照保持一致。

Technical Design

把仓库构建、RSI 判定和参考准入检查归入 tests/verification，候选检查明确排除该目录及原 test_improvement 模块。保留 test_host_execution、test_host_processes 和既有 Case 选择器。登录环境检查拆开宿主构建契约与原运行环境选择器。Case 61 的运行时测试从相邻 fixtures 读取合成数据，宿主同步断言及 Case 运行器检查规范输入字节，仍支持显式 Case 输入。

完整回归的临时数据库累积曾造成隔离临时盘写满；采用 pytest 的 tmp_path_retention_policy=failed，在每个通过项结束时释放其临时文件，保留失败项。保持原只读工作区、临时盘容量、超时、内存、网络隔离和全部失败判定。模型限额仍仅由 Go 网关处理。

Acceptance

原完整冻结包在 5 处宿主依赖上收集失败。分层后保留全部 2509 个原测试节点，新增 4 项；Agent 的宿主命令测试未移除。实际容器验证通过项临时文件清理、运行时断言失败和收集失败均保留原失败状态，宿主判定模块不被导入；相关 46 项通过。

临时盘写满的失败记录保留，不计为成功。完整冻结包实际 1502 项通过、12 项因 Go 编译器或外层镜像环境缺失而跳过；宿主 quick 与 full 的 Python 均为 2513 项通过、0 跳过。Case 61 的 Go 与任务输出回归执行、清理成功，原 MECH-MB02 选择器另在冻结镜像实际执行 4 项、0 跳过。完整 full 的前端与最终主线同步，CI 结果随 PR 交付。本修复不代表真实 PPTX、媒体或金融任务达标；不改题目、参考、模型配置或历史成绩，不部署或启用日程。

最终验证镜像基于主线 5ae3ec3c 的受保护代码与 14 份迁移资源，记录 337 个文件哈希；205 个 Actor 文件保持一致。只对齐可信基线，不复制候选判定代码，不挂载 Case 或参考，不修改默认镜像标签。旧镜像的限额检查失败单独保留，不能当作当前主线行为。
