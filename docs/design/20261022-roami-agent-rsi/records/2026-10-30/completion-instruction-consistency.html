完成回报的统一指令

Product Design

后台任务完成后，主对话先说明实际结果、文件及必要的待验收或阻断状态。附件链接不能代替总结；主动询问进度时继续使用简短状态回复。

User Stories

  • 文件生成后，我能直接看到结论及尚未核验的部分。
  • 查看进度和收到完成回报遵循各自的规则，不会反复触发内部拒绝再修正。

Technical Design

replies/delivery_policy.py 保存同一份 COMPLETION_REPORT_INSTRUCTIONS，server/configuration.py 的默认 Main 指令与 context/prompt_builder.py 的回调上下文共同引用。移除默认指令中“progress/completion 使用 task_reply”和“有文件即可短答”的旧例外，保留主动进度查询、终态拒绝保护、所有者和附件作用域。用户自定义的主指令、模型路由、参数、能力及重试不改写。

验收记录

真实回调回归在旧代码中6项全部失败；修复后70项相关回归通过，覆盖成功、待验收和失败状态，以及同任务与其他任务的附件。每次模型请求同时核对默认指令和回调上下文包含相同规则，并保留状态短答被拒绝后的实际结果、文件链接和权限断言。完整门禁待记录。本修复0真实模型调用；已有真实 Main 受控回报证据仍属前轮，不冒称本轮实际质量成绩。RSI 任务质量、独立评分和完整观察仍待完成。
