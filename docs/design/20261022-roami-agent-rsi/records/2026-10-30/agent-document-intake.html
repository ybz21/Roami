Agent 显式文稿输入准备

Product Design

#527 已提供读取能力，但原题复测中 Worker 没有调用该工具或 Skill，仍猜测颜色与对象顺序。此次把真实输入读取接到普通 Agent 的任务准备阶段：只处理委派目标显式引用的本地 PPTX，不扫描目录、猜文件名或写入源文件。

User Stories

  • 我指定文稿后，Worker 第一次请求就有实际结构与来源哈希，不必先猜测二进制内容。
  • 组合内文本与编辑器公开色板能够用于实际任务；模型继续使用现有 read 分页检查更多内容及输出。
  • 缺少、损坏或超出工作区的输入不会伪装成已读；未检查的路径和未完成的视图明确保留。

Technical Design

context/document_intake.py 识别委派目标中显式的本地路径，支持引号内空格、大小写扩展名、按工作区内实际位置合并绝对/相对路径别名及句末标点，排除 URL 与 .pptx.bak。通过 #527 的工作区读取适配器获得只读快照；不存在的预期输出不作为输入。初始预览沿用读取工具的单页大小，剩余路径标注未检查；这只是输入预览分页，不新增模型 Token、请求数或财务准入。

NativeExecutor 在已绑定、已准入的工作区内准备输入，再调用 Worker。PromptBuilder 将内置工作流与外部文档数据分别置于系统和用户角色，按当前请求消息的身份定位后插入，即使已有记忆前缀也不破坏工具结果顺序；文档内容不会升级成系统指令，也不写回聊天历史。快照加入正常上下文估算，manifest 仅记录来源和视图哈希等证据，不把输入快照当作编辑后的验收。旧任务缺少 goal 字段时保持兼容；无相关路径及无工作区时不读取。

读取视图改用紧凑 JSON，减少重复缩进挤占分页；原文件哈希、工作区边界及手动分页语义保留。模型路由、参数、能力与 Go 网关额度不变。improvement、原 Case 提示、参考文件、判定器、人工标签与历史正式成绩不改写。

Acceptance
