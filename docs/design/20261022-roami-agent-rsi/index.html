目标与评定

目标第二层指标通过条件
效果正确、完整、可用、证据可信；真实交付率先过硬断言，再做独立产物评分；待评分不算通过
时间排队、模型、工具、验证；交付P50，样本足够再看P95同机同模型配对；失败不能算更快交付
TokenMain、Worker、记忆、重试；复盘与修复另列全部尝试总量/成功交付；未知用量不能记0

每日固定公开20项、自有真实任务20项、机制20项，稳定版和候选各一次，共120次执行。另有私有验证24项、隐藏30项，用于晋级；当前私有集只覆盖代码契约。新想法作为额外实验，不替换每日题目。

改进范围与晋级门槛

改进范围：记忆生成/检索、上下文、工具发现/执行/回执、Skill流程、规划委派、模型预算、验证停止。工具次数和重复读取用于定位问题，不能取代效果评分。

冻结标准：质量差95%区间下限≥−1分，交付率差下限≥−2个百分点；至少质量+3分、交付P50−10%或单位成功Token−10%之一达标，其余效率退化≤5%。按独立任务家族重采样，样本不足不晋级。不同机器、模型与缓存档分别比较。

用户能看到什么

关闭聊天后仍每天测试；首页展示执行、出分和复盘覆盖，正在修的问题、补丁、前后对比、当前阻塞及下一步。每项成功和失败都能追溯到具体日志。

闭环规则

程序定时发起 → 被测Agent做题 → 独立判定 → 复盘Agent提出问题 → 修复Agent生成隔离补丁 → 独立验收 → 专用实例应用 → 两个后续完整日观察 → 关单。退化回滚并重开，失败回到诊断；Issue/PR是可选同步。

动作、预算和租约持久化；未知执行先对账，不自动重放付费调用。每天完整60项、全部出分、完整计量、规则扫描和逐条语义复盘缺一不可。现用服务部署适配尚未接入。
