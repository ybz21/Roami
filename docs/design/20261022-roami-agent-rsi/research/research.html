Roami Agent RSI 开源做法深度调研 · 2026-10-22

结论：Roami 首版适合采用“评测协议 + GEPA 式反馈搜索 + ACE 式经验条目 + 自有发布门禁”的组合。先让程序员真实任务可验证，再优化记忆、上下文、工具目录与执行策略；代码自进化和权重训练放在后续独立阶段。这是基于下列材料的架构判断，不是已验证的项目收益。

本轮检索覆盖提示 / 配置、流程、经验记忆、程序进化、RL、办公 / 视频与金融任务。只用作者仓库、官方文档和论文作结论依据，按 commit 固定版本并抽查核心函数。检索到的候选没有按热度直接推荐，未安装这些框架、未训练模型、未运行其排行榜实验。

1. 不同路线分别优化什么

提示 / 配置搜索改变 Agent 的可控输入；经验工程积累跨任务可复用知识；流程进化改变步骤与调用关系；程序进化修改实现；RL 则训练模型参数。它们的成本、验证要求和更新频率不同。每日 RSI 可以同时管理这些候选，但首版只开放有限参数与文本变更。

2. 代码抽查改变了哪些判断

反馈要包含“为什么失败”

GEPA 的适配器接收候选组件、返回逐样本分数和可选轨迹，再构造反思数据。Roami 应回传“附件未传给 Worker”“工具目录漏掉正确能力”“视频音轨丢失”等可行动诊断；单个总分不足以指导改进。我们只提供可观察事件与检查结果，不要求采集模型私有思维链。

经验维护不能只增不减

ACE 的作者实现与社区实现分别核对。作者版本的条目操作有实现范围差异，因此 Roami 需显式实现来源、冲突、更新、过期、删除和遗忘传播，并把每种操作纳入 case。条目“有帮助”计数是线索，仍需配对实验判断效果，不能成为自行晋级的证据。

三个目标必须保留各自的证据

GEPA 支持 objective_scores，但默认验收和候选选择仍有自己的分数语义；OpenEvolve 的候选多样性也不直接等于三目标发布策略。Roami 必须独立执行质量硬门槛，分别比较时间和 Token，显式展示取舍，不让总体均值掩盖某个任务类型退化。

长记忆也要测“熟悉环境后办事更好”

LongMemEval-V2 已将经验记忆扩展到工作流、环境陷阱与前提意识；这比只问“记住的口令是什么”更贴近长期助理。Roami 增加多轮序列：先处理项目、产生可追溯经验，再用未见任务检查是否少踩同一坑；同时计入检索与维护成本。论文

真实产物有不同的验证器

代码依赖测试与行为，PPT 依赖内容和渲染，视频依赖时间轴 / 音画 / 成片，新闻依赖时点和来源，数据分析依赖口径与可复算结果。TheAgentCompany、OSWorld 和视频基准提供具体检查范例，但没有一个现成分数可公平代表这几类任务。

3. 从材料推导程序员任务覆盖

采用 60 个真实任务 case（12 类各 5 个），再用 20 个跨场景机制 case 检查记忆、上下文、工具、路由及恢复。首批 80 项是公开开发 / 回归规格，不能伪称隐藏集。正式晋级另建至少 30 个未向优化器公开的独立任务，并覆盖本次变更涉及的任务类别。

覆盖编码、调试、测试审查、部署排障、文档与 PPT、Demo、视频、新闻调研、数据分析、股票信息、策略回测、前沿与个人实验。所有任务记录产物、硬断言、评分锚点、证据、环境、预算和 RSI 决策维度；完整目录及判定见 Case 与评价标准。

4. 对原方案的具体调整

  1. 先建设可重置任务包、独立验证器、成本采集和按类别报告，再开始搜索策略；参考 Harbor 的任务边界，保持 Roami 的资源与身份体系。
  2. 候选以 memory_policy、context_policy、tool_catalog_policy、execution_policy 等受控组件表达，可先使用 GEPAAdapter 的概念验证接入；只有离线验证后才决定引入依赖。
  3. 事实记忆与经验策略分开：用户事实保留原有来源和遗忘语义；经验条目必须关联任务类别、适用条件、证据、版本及失效条件。
  4. 流程变更借鉴 AFlow / EvoAgentX，但首版只搜索明确的白名单参数和少量算子组合；代码变更形成隔离补丁，参考 DGM 的父子档案而不直接修改生产服务。
  5. Agent Lightning v1.0 列为将来可训练模型时的独立路线；不把每日提示优化描述成权重训练，也不照搬早期版本架构。
  6. 评测标准与优化器分离；修正 0～4 档与 80 分门槛的映射，区分 case 正确处理拒绝 / 取消与实际任务交付，不用短期股价涨跌作为 Agent 的质量奖励。

5. 建议先验证的四个实验

实验对照主要观察
工具目录当前目录与按任务检索 / 简洁描述正确工具可达性、发现轮数、任务成功、输入 Token。
记忆与上下文同一记忆快照，对比固定注入与按需检索；再独立比较压缩策略关键事实保留、经验迁移、检索延迟、完整链路 Token。
反馈驱动搜索相同调用预算的人工 / 随机候选，与基于真实失败的反思候选独立任务上的质量 / 时间 / Token，以及优化器自身开销。
流程组合单项 A、单项 B、A/B 联合与当前策略是否只是增加验证 / 并行调用换得表面收益，是否发生联合退化。

先在一个有明确上限的预算内运行，保留全部失败。衡量 RSI 本身的成本回收：预计未来合格任务节省的成本，减去搜索、验证、评分、经验维护和部署观察的成本；只报告已知口径与假设。对未来任务量未知时给出回本所需次数，不宣称净收益已发生。

6. 证据范围与未解决问题

本轮完成材料收集、固定快照和选定源码抽查，未做复现。论文 / README 的收益依赖其数据、模型、预算和评分方式，不能搬成 Roami 的目标值。仓库许可证、数据集许可、模型使用条件是不同层次；这里只登记已读许可证标头和第三方声明，没有将代码或数据搬入本仓库。

尚需实际测试机与模型预算、可用桌面 / 视频工具、允许使用的财经数据源，以及有代表性的真实任务样本。数据获取失败和环境缺失必须单独显示，不能通过删除失败任务提高完成率。新闻采用固定时点回放作为回归，真实联网新鲜度另作观察。
