3. 数据划分与计分

  • 公开任务、问答/记忆组件、自有真实任务、自有机制回归分开报告。保留上游原生分数，再附加Roami的交付质量、时间与Token；不同分数不直接混成一个总分。
  • 保留task ID、split、数据与grader版本、文件hash和改造说明。训练/开发数据与冻结对照按来源分组分开；官方test不用于反思、选参或经验提取。
  • 翻译、简化、改变工具或验证器后的任务标为adapted；抽样结果只能叫内部子集结果，不能作为完整官方榜单分数。
  • 自有case若写在公开仓库，也不是秘密题；正式晋级的私有验证与独立未见任务仍在Agent无法访问的位置另建。
  • 访问受限或环境缺失时明确标待补；覆盖不完整就不宣称完整评测，不静默用容易题替换。

4. 执行顺序

先绑定20个真实上游ID并固定版本，再准备自有夹具；用oracle与空/错基线验证判定器，最后做同机稳定版/候选对照。原来的五天80项轮换仅保留为自建候选池示例，混合集在数据、环境和预算就绪后重新编排。每天完整执行60项。基线与候选各跑一次时是120个episode；机制回归不调用真实模型。新想法另列开发实验，不替换正式题，仅在剩余预算内执行。

日Token和episode总预算由所有测试机共享。必须先保证整套60项A/B足额预算；不足就明确标记阻断，不能自动缩成部分用例或报当日完成。观察、提出建议、编码和复核同样计入预算。公开任务还未全接通，当前不启动正式每日模型评测。

5. 主动实验与修改

RSI每天主动选题，运行Roami Agent，查看工具调用、重复读取、上下文处理、失败恢复和最终产物；形成有证据的修改意见，在隔离源码工作区实施，再做定向回归与同机对照。无需依赖用户当天用过什么。临时新想法进入开发实验区；不能改隐藏答案或评分器来制造提升。修改产物、差异与回归证据归档，正式发布另经过晋级门禁。

6. 每日指标与具体日志回顾

成功和失败的60项均逐项检查：质量和硬断言、真实交付时间、Main/Worker/记忆等所有角色Token、模型轮次、工具调用、重试、错误恢复和产物验证。运行日志保留实际请求/响应、工具参数/结果、trace及回归输出；回顾记录文件hash、具体record/span引用和修改建议，不能只看平均分。

每天归档review.json与report.json。已实现不额外调用模型的规则回顾，可识别未知消耗、重复读取、工具失败/未知写入和配对退步，建议仍需复现验证；完整语义诊断和自主源码修改器仍待接通。日志缺失或回顾不完整不能标记当日完整结束。缺失用例仍保持缺失，不拿现有40项冒充正式60项。
