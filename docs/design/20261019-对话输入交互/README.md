# 对话输入区与待发送队列

参考用户给定的 ChatGPT 输入栏、模型入口和添加菜单截图，调整现有 Roami 主对话；保留项目、专业智能体、附件、停止、上下文压缩及快捷命令。

## 模型与思考强度

- 输入栏右下角同排显示模型与实际强度，模型使用正文强调色，强度使用次要色。桌面与手机共用一个发送模式菜单。
- 打开后在同一面板暂选模型和强度，最后一次「应用」原子提交。暂选、取消、Escape 和遮罩关闭不会写配置；提交失败保留选择与错误，输入栏继续显示已生效值。
- 换模型先恢复该模型默认强度，选择列表按模型过滤；「模型默认」清除显式参数。原有设置页接口与共享连接、角色分离保持。
- 暂选模型的完整名称直接展示、可选择复制；列表与输入栏保留统一中间省略规则。常规高度下只有模型列表滚动，保留搜索、强度和操作按钮；极短视口仍可滚动整个弹层。弹层保持与输入栏对齐和遮罩隔离。

## 加号菜单

「添加 / 技能 / 对话」分组，图标、标题与次要说明组织每行。技能来自当前节点已安装且已启用的目录，支持加载、空目录、失败与重试。选择技能只把名称和 `skill://` 位置写进现有草稿，用户发送后才执行，复用已有 read / skill_read 通道。切换节点取消旧目录请求。

交办任务进入已有项目与专业智能体选择；添加附件、压缩与斜线命令沿用已有入口。能力管理进入设置页现有技能标签。

## 待发送草稿队列

左侧发送模式菜单提供「对话 / 排队 / 交办任务」。选择排队后，发送按钮显示时钟并标注「加入队列」；可切回对话立即发送，也可立即发送队列中的某一项。默认保持对话模式立即发送，避免把快速中转主对话变为等待后台任务结束才能收新意图。

- 队列显示顺序、正文、附件和状态；可暂停/继续、编辑等待中的正文、移出队列或立即发送某一项。编辑先暂停，保存后由用户继续队列。
- 以节点及主对话隔离，保存当前浏览器 localStorage；切换对话不会把旧队列发到新目标。离开对话页、关闭浏览器或其他设备不会代发，返回原对话后继续。界面直接显示此限制。
- 这是发送前的草稿队列，不修改已经接收的历史消息及其自动记忆来源，不新增服务端协议或鉴权。跨设备及关闭页面后自动发送未包含在本轮。
- 等待当前主对话空闲后逐条提交；每项始终复用同一个请求 ID，收到持久化接收回执后才移出队列。服务端接收后交由原有消息、SSE 与意图调度链路处理。
- 上传完成的附件引用随队列保存，未完成上传时保留原草稿，不提交队列。存储失败保留原输入。
- 服务明确返回错误显示「发送失败」；连接异常或刷新时仍在发送的记录显示「未确认送达」。不自动重复发送，不把未知显示为成功；重试原请求，移出本地队列不撤回已接收消息。不允许改写未知请求后复用旧请求 ID。

## 2026-10-19 发送后排队交互修订

用户依据真机截图要求把排队放在输入框上方，并在发送后提供打断执行入口。本节覆盖下文早期“先切换排队模式”的描述；原模型 / 强度与加号交互保持原设计。

- 删除发送模式菜单中的「排队」选项，仅保留对话 / 交办任务。Main 正在回复、压缩进行中或已有待发送消息时，普通正文发送自动进入输入框上方的队列；空闲且没有队列时直接发送。
- 等待中的每条消息显示可见文字操作：Main 忙时「打断并立即执行」，空闲时「立即发送」；保留编辑、移除、暂停和恢复。按最新参考图收敛为一行待发条：正文省略、右侧「立即执行」、删除及更多；数量入口展开全部。完整正文、编辑与暂停操作可展开查看，桌面与手机均不横向溢出。
- 优先执行仍提交该消息原有 requestKey，复用 ConversationService 的新意图抢占机制：在可中断的模型等待或安全边界让 Main 让位，不先发 `/stop` 再发新消息，不取消已派出的独立后台任务，不保证正在执行的不可安全中断工具立刻停止。其余草稿保留原顺序。
- `/stop` 等斜线命令直接执行，不排到正在进行的回复后面。压缩、断线或历史只读状态下禁用立即发送；未知回执仍需显式重试，不自动重投。
- 继续使用当前设备的本地草稿队列，离开页面暂停，关闭浏览器不承诺服务端代发。尚未发送到服务端的消息清楚标为待发送。

本轮验证与截图见 [queue-revision-validation.json](queue-revision-validation.json)。此修订不包含新的 `/approvals` 命令，末尾命令含义待用户澄清，不擅自增加审批权限或协议。

- 桌面与 Redmi Note 8 实际触控：模型和强度同一次提交、取消不保存、完整模型名、选择技能先入草稿、发送后实际 skill_read、左侧模式切换排队、桌面 Enter 入队、排队修改 / 移除 / 暂停 / 刷新保持及恢复后依次发送，无重复消息。
- 端到端使用真实 Go 鉴权 / HTTP、Python 运行时、SSE 和数据库；生成供应商使用可控本地流式夹具，第一条停在响应阶段，第二、第三条保持未发送，恢复后按顺序进入模型。没有伪造模型性能结论，没有创建业务任务。模型和强度 UI 使用实际接口保存到隔离实例。
- 另外使用既有私有网关的真实模型目录（12 项）只读验证，桌面中英文、手机四项底栏、能力管理跳转、原生触屏模型列表滚动及 44px 弹层操作按钮均通过，未向正式对话发送测试消息，也未修改正式模型连接或 Key。
- 配额 / 存储失败、旧节点请求返回、未知回执不自动重试、显式重试保留原请求、发送期间换对话不丢队列、服务错误与网络未知分别展示，自动回归覆盖。
- 首次浏览器验收遇到脚本选择器、前端重建期间的 404、动画截图等待及手机键盘动画点击时机问题；修正环境与脚本并重新完整验证。实际手机截图发现发送额外按钮挤压模型名，改为左侧模式菜单；队列去除横向滚动。

排队是当前设备的待发送草稿，不包含跨设备与关闭页面后的服务端代发；此限制在界面及本报告直接说明。上述测试不等于主对话延迟、复杂追加意图或所有旧研究失败已经解决。

## 主对话上下文用量

输入框内部、正文输入区与底部操作栏之间保留紧凑入口，例如「上下文：约 12.4K / 128K Token · 10%」。使用既有服务端上下文预估，包含系统指令、工具与历史，不按字节或输入草稿长度计数，也不虚构模型容量。容量未知时显示未知，不显示百分比；K / M 仅缩写数字，点击打开原上下文详情和手动压缩入口，可查看完整数值与自动压缩阈值。达到服务端压缩阈值时提示色加深，超过容量时保留真实百分比。

打开对话、回复状态变化、切换模型和压缩结束时刷新；执行期间每 5 秒刷新，空闲不持续轮询，隐藏页面不请求。切节点 / 模型后不显示旧目标结果；读数更新失败保留上次数据并明确标注，不置零。历史分支不展示当前主分支的误导性读数。

前端类型、i18n 2954 keys、hover、97 文件 / 690 项测试及生产构建通过。Redmi Note 8 实际触控验证上下文详情、压缩入口与四项底栏，桌面 / 手机无横向溢出。隔离真实 Go / Python / SQLite 配合可控模型供应商，实际生成摘要快照；最终移动到卡片内部后的重测中，压缩前后预估为 11,468 / 7,275 Token。128K、1M 和未知容量展示分别验证，结果见 [context-usage-validation.json](context-usage-validation.json)。这不是对实际模型压缩摘要质量的评测。尚未部署。

用户在 2026-10-19 17:04 补充要求将用量移入对话框，已调整到输入卡片内部；队列仍紧贴输入框上沿，不挤进模型与发送按钮所在的一行。最终 PR 采用移动后的截图与验证结果。
