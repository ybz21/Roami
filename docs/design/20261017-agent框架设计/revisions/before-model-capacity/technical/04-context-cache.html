上下文、压缩与 Cache 如何协作

应用缓存减少本地工作，Prompt Cache 减少供应商对相同前缀的处理。两者都不等于记忆，也不保证模型每次立即出字。

固定前缀后台快照按版本失效供应商 cache 能力隔离
技术总览对话保存记忆存储记忆召回上下文与 Cache运行时与模型任务与 CLIAPI 与流转发运行与验收工具网关浏览器与电脑主动联系与未读

四类缓存，各有真相来源

层缓存内容与 key失效方式
进程内热状态branch head、task snapshot、profile；key=owner+实体+version提交后版本通知；容量 LRU；重启从库重建
Context Snapshot稳定前缀摘要、切点、来源 hash；key=branch+cut+epoch+policy来源变化、忘记 / 删除、快照策略变更
Recall Cache查询结果 ID / revision；key=owner+scope+query+memoryEpoch+versions记录更新、删除、scope 变化；TTL 兜底
Provider Prompt Cache供应商持有的输入前缀计算；本地只记 usage / fingerprint依 provider/model/序列化/参数/TTL；跨模型和跨供应商不共享
Python 本地不拥有 API 模型的 KV cache，不能把缓存序列化到 SQLite 后声称跨进程 / 跨 provider 继承。外部 Claude Code / Codex 的上下文缓存也由其各自运行时管理。

Prompt 的固定顺序

版本化系统 / 角色指令
稳定工具目录与 schema（由 provider adapter 按 API 规范编码）
用户已确认偏好与长期约束（固定版本）
当前 ready snapshot 的结构化摘要
已完成的近期 messages + 成对 tool calls/results（只追加）
当前用户消息 / 本轮按需检索证据 / 最新进度 / 必要时间信息
  • 序列化器固定字段、工具和来源顺序；已提交的前缀不每轮重新措辞。
  • 用户偏好修改属于有意失效；不会为了命中旧 cache 继续带过时约束。
  • 不把实时钟、随机 requestId、变化中的任务列表放进系统前缀；这些信息放必要的动态尾部。
  • 按需 memory_search 的工具结果追加到当前历史，不把整个长期记忆库每轮插入开头。
  • Main 保持短上下文：cache 命中仍占上下文窗口，长输入也可能变慢；不为凑最小 cache 长度添加无关材料。

可复用边界演示

演示的是可复用前缀边界，实际是否命中受供应商、模型、路由、TTL 与最小长度限制。

供应商适配

OpenAI 官方文档按模型代际区分 cache 参数：当前部分模型使用 prompt_cache_options / prompt_cache_breakpoint，旧模型参数不同；命中统计见 input_tokens_details.cached_tokens，部分模型还有写入统计。具体 TTL / 最小长度由已选模型能力表决定。

OpenAI · Prompt caching

Anthropic 使用 cache_control 标注可缓存边界；用量区分 cache_read_input_tokens / cache_creation_input_tokens。默认 / 可选 TTL、断点数和最小长度按模型与平台文档配置，不与 OpenAI 混用。

PrefixFingerprint = sha256(provider_endpoint_id + model_key +

本地 fingerprint 用于诊断与隔离，不等同供应商真实 cache key，也不是鉴权。相同 fingerprint 不代表必然命中。模型能力表在实施时按官方文档与探测验证后锁版本。

统一用量口径

Usage = { inputTotal, cacheRead, cacheWrite, inputUncached,
  outputTokens, providerRaw, knownFields }

Anthropic: inputTotal = input_tokens + cache_read_input_tokens
                     + cache_creation_input_tokens
OpenAI:    inputTotal = usage.input_tokens
           cacheRead = usage.input_tokens_details.cached_tokens
           cacheWrite = 当前模型存在时读取相应字段

cost = uncached_input_cost + cache_read_cost + cache_write_cost + output_cost

原始 usage 保留用于核对，缺失字段记 unknown。价格来自部署时的模型配置，不在内核写死；cache 写入成本和命中读取成本分开计算。只有相同场景的冷 / 热请求对比，才能评估收益。

压缩的精确切点

2026-10-18 用户确认：75% 自动压缩。以已配置模型上下文窗口 C 为容量；窗口未知时用配置的输入容量作为依据，并明确标注。触发线 T = min(floor(C × 0.75), 输入硬预算 B)，回复预留或其他硬限制要求更早时优先采用更早的线。请求前检查，回复完成后再用有效 usage 检查并排队后台压缩，不等待下一条用户输入。T 是软触发线；当前轮暂无安全切点但仍低于 B 时可继续，超过 B 时仍明确拒绝，不能丢弃当前问题或打断工具配对。

设输入预算 B = min(modelContextWindow, configuredSoftCap) − outputReserve − safetyMargin，预算包含 schema、图片估算和所有待发消息。Main 先以小窗口运行；超过阈值时后台挑已完成轮次前缀压缩，近期完整轮次与当前要求保持原文。

# 设计示例，不绑定具体模型的真实窗口
softCap = 32k; outputReserve = 4k; safetyMargin = 4k
inputBudget = 24k
allocate = tools/system 3k + summary 2.5k + recent 12k
         + retrieval 2k + current 2k + remaining_margin 2.5k
1. 选择前缀

固定 cut_seq、ancestry hash 与分支 epoch；禁止切开工具块。

2. 生成摘要

提取目标、约束、已做 / 未做、精确 ID 和来源引用。

3. 验证并提交

来源前缀不变才激活；期间新增后缀可继续 append。

4. 重建投影

summary + 最近完整轮次 + 最新要求；记录新 prompt manifest。

若分支改写、来源屏蔽或 memoryEpoch 变化，丢弃正在生成的旧快照。快照失败继续用上一个有效版本；已超硬预算时必须压缩或拒绝超大输入，不悄悄删除最新要求，也不无限重试。

如何确认 cache 真有收益

指标用途
首字、首段有效回答、完整回答延迟区分服务器接收快与用户真得到答案快
cache read/write tokens、总输入、输出 tokens按 provider 自己的口径归一化；不把未知量填成零
prefix fingerprint / first changed segment定位随机字段、schema、摘要或记忆注入导致的失效
同场景冷 / 热 A/B固定模型、参数与提示版本；记录成本和延迟，不预设命中率

OpenAI · Cache diagnostics

不在网页日志输出完整用户 Prompt。Manifest 记录版本、引用、hash 与用量；必要调试副本受数据保留配置控制。

用户手动压缩：/compact

Main 与原生子 Agent 共用 ContextService，但每次压缩只作用于指定 conversation / branch。用户在当前主对话输入 /compact，或 /compact 保留部署决策和未完成事项，可主动整理上下文。输入 / 或 /comp 时显示命令提示，Tab / 点按补全；Enter 或发送执行。多行消息、引用、代码块中的字符串不解析为控制命令；未知斜杠命令明确提示。

命令由 Python 请求入口在模型推理前识别，作为持久化 control request 处理，不把它当普通问题交给模型，也不使用它新建编码任务。界面按钮与文本命令调用同一服务；默认绑定当前主对话，不因目标选择器选中项目或执行会话就转发给 Claude Code / Codex。外部 Agent 自己的 /compact 属于其原生运行时，需进入对应会话操作。

状态界面与处理
queued显示“等待当前回答结束”；同 branch 排队，不能切开流式回答与工具调用 / 结果块。
running显示“正在压缩”；固定已完成 cut_seq、branch epoch 与来源 hash，模型在事务外生成摘要。
completed同事务激活 ready snapshot、保存控制结果与事件；显示压缩前后输入估算、保留范围及“查看摘要”。
skipped历史过短或没有新增可压缩前缀，明确“无需压缩”，不强制生成低质量摘要。
failed / cancelled旧快照继续有效；显示原因与重试入口。取消不覆盖原上下文，不把任务取消状态混进压缩状态。

聊天记录不删除，控制记录作为独立事件显示，不加入模型 transcript。摘要保留目标、确认决策、约束、未完成事项、精确资源 ID 与来源区间；自定义关注项只调整摘要重点，不能覆盖系统指令、扩大访问范围或丢掉必要约束。摘要查看为只读，附来源范围与当前版本。

压缩时可以继续输入，新消息正常持久化；同分支的下一次模型请求在快照激活短临界区选定版本。在硬预算内可继续使用旧快照，若硬预算已满则等待压缩，明确显示状态。摘要生成期间新完成消息作为后缀保留，不重新纳入固定切点。手动 / 自动请求共用一条分支压缩管线；并发请求返回已有 operation，重复 requestKey 不重复执行。

软预算不足不是手动压缩的必要条件：用户可提前压缩。UI 常驻一行上下文状态，打开后可查看摘要或点“压缩上下文”；移动端保持一个紧凑入口，命令建议不遮挡输入与发送按钮。真实估算包含 system、tools、图片、summary 和消息；标注估算与预留额度，不能只按聊天字符数冒充 token。压缩前后比较使用同一 estimator 与模型版本。后台任务、记忆提取和完整历史不因压缩被清除。

失败保留旧版本并可幂等重试；分支切换、删除和取消需验证 epoch / operation revision，迟到摘要不能激活。候选协议与持久化复用见 API 模块。验收覆盖命令解析、流中排队、工具配对、手动与自动竞争、新消息并发、取消 / 失败、无需压缩、断线恢复及摘要来源。
