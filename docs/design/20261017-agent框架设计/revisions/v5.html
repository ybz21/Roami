Roami / Agent Runtime设计提案 v5 · 2026.10.17
ARCHITECTURE PROPOSAL

快问快答，后台把事情办好

Python 实现完整 Agent 服务与流式消息，Go 统一鉴权并透明转发。Main Agent 优先快速、直接地回答，耗时工作交后台独立执行；编码重活通过现有 Roami / ttmux CLI 派给 Claude Code、Codex。

快问快答优先Python 完整服务 / Go 统一入口按意图选择执行目标任务 / 对话 / 每日记忆复用现有 CLI
首要产品目标：快问快答。Main 能直接回答就立即回答，不要求每条消息都规划、检索记忆或创建任务。需要干活时，快速记录请求并回复“已安排”，后台再准备资源和执行；新建项目、开会话、安装依赖都不阻塞当前对话。
如何保证快：响应路径与验收目标

普通问答：当前消息 + 精简主提示词 + 最近对话 / 已有摘要，直接流式回答。意图判断与回答放在同次模型调用中，不强制先跑一个分类模型。只给 Main 暴露少量派活、查状态与记忆查询工具，其他工具按需加载到 Worker。

需要干活：Main 提交轻量任务意图，Python 落库后返回任务 ID；后台做目标解析、建项目 / 会话、准备 worktree、执行与验收。“已安排”表示持久化接收，“已启动”必须有执行器启动回执，“完成”必须经过结果验证。资源准备慢也不占用主对话。

记忆与上下文：常用偏好、有效约束、当前绑定和进度快照按版本缓存；不每轮扫日记、查全部项目或读长日志。需要历史事实时才检索，慢查询可交后台并说明正在查证。每日摘要、记忆提炼与压缩尽量在空闲时准备；约束和最新用户消息不能为了速度被省略。

执行隔离：主对话预留模型请求容量，后台通知低于用户消息优先级。慢工具、建资源与大文件处理走独立 Worker；阻塞调用移出 Python 事件循环。用户新消息及时入队，在安全边界处理；不重跑已接收的任务。

验收：目标是首段有效回答 P95 ≤ 2 秒，常规简短问答完成 P95 ≤ 5 秒；这是待实测的设计目标，统计包含模型 / 网络等待，不拿“收到”占位或 SSE 心跳充数。另记录接收、首字、完整回答、任务入队与执行启动耗时，分别定位瓶颈。

一套内核，两类执行器

Go 是 Web、手机和 IM 的统一入口，只处理登录鉴权和转发。Python 提供消息 API、SSE 事件流、Main / 子 Agent，并直接调用现有 Roami / ttmux CLI。点击模块可看职责。

模块职责

    推荐技术路线：Python 完整实现消息接口、流式输出、Main / Worker、工具、Memory、压缩、调度与 CLI 执行器。Go 复用 Roami 现有鉴权，透明代理请求与事件流；Agent 业务与状态集中在 Python。
    为什么推荐这一种分工
    方案取舍
    Python 对外并单独鉴权Agent 服务独立，但需要接第二套登录和会话；当前 Roami 场景没有必要。
    Go 鉴权与转发，Python 完整服务推荐。复用已有入口；消息、流、执行和状态在一个服务内，框架可以独立测试，接入 Go 时只需代理。
    Go 编排流与执行，Python 只推理一次业务变更往往改两种语言，还要维护额外执行 RPC 与状态对账；首版负担更大。

    先把 Python 服务和 CLI 执行闭环跑通，再接入 Go 统一入口。Python 本地开发可直接访问；正式接入 Roami 后，用户统一从 Go 入口访问。

    Python 与 Go 怎么协作
    边界Go 负责Python 负责
    用户入口现有登录鉴权、公共路径映射、原有节点转发对话 / 任务 API、消息接收、回答、任务进度
    流式消息转发响应字节与必要头部，及时 flush，透传断线游标SSE / 可选 WebSocket、事件格式、事件持久化、重放与去重
    Agent 与执行提供既有项目 / 节点能力，不新增执行 RPC 层Main / Worker、执行目标选择、工具、CLI 派活、运行回执与恢复
    状态不保存第二份 Agent 业务状态消息、任务、记忆、检查点、运行记录与事件的唯一写入方

    通信：Python 提供 HTTP + SSE 服务，Go 将 /api/agent/* 映射到 Python。SSE 由 Python 原生生成，Go 不转换事件格式；如果以后需要 WebSocket，Python 实现协议，Go 做连接代理。首版单机用 loopback 地址，后续按部署需要再换 Unix Socket。

    回执与流：Python 先持久化消息并按 requestId 去重，再确认接收。事件带 eventId / conversationId / taskId / revision / type，由 Python 持久化和重放。Go 保留事件 ID，避免代理缓冲和短请求超时截断流。连接断开只结束订阅，后台任务通过独立取消接口停止。

    鉴权：只复用 Go 入口的一套用户鉴权。Go 覆盖 Agent HTTP、SSE 和 WebSocket 路径，并覆盖重连；Python 不再提供登录、Token 签发或第二套认证。Python 首版只监听本机地址；需要用户信息时由 Go 覆盖写入可信身份头，不采信客户端伪造的同名头。任务与记忆仍按项目 / 对话归属检索。

    运行：Python 独立进程，首版用现有服务管理方式启动；Go 仅做连接与就绪检查，暂不新增进程监管框架。Python 不可用时 Agent 入口返回可重试错误，其他 Roami 功能继续工作。Python 重启后自行核对 CLI 会话与运行记录，不重复派活；Go 重启不影响 Python 后台任务。

    02

    Main 根据意图选择去向，项目归属可选

    一次意图可以拆成多个任务，每个任务绑定自己的执行目标。用户指定某个散会话或要求新建项目时，优先尊重明确目标；不能因为当前页面在某个项目里，就把所有事情派进该项目。

    去向适用场景路由行为
    直接处理回答问题、查状态、轻量操作Main 直接响应；耗时工作仍可交原生子 Agent，不要求项目归属。
    已有项目“把 Roami 的布局改一下”选项目、工作区与执行器，新建任务或延续明确关联的会话。
    已有会话（含散会话）“让刚才那个调研会话继续查”按稳定 sessionId 续派；沿用实际 cwd、Agent 与历史，不擅自换目录或归项目。
    新建散会话“单独开个会话研究这个问题”创建独立会话和工作目录，projectId 留空；不自动建项目。
    新建项目“新建一个记账 App 项目”准备项目目录 / 仓库，登记项目，再创建工作区与会话并派活。
    目标解析、创建与续派规则

    解析优先级：用户明确指定或要求新建，其次引用的任务 / 会话，再其次当前对话绑定，最后才是项目别名等候选推断；多个目标均合理时简短追问。未识别到项目不等于需要新建项目，也不等于必须新开会话。

    // 建议目标模型；以下字段不是当前 CLI 已有参数
TargetIntent =
  { kind: "direct" }
  | { kind: "project", projectId, workspaceId? }
  | { kind: "session", sessionId }
  | { kind: "new_session", label?, nodeId?, workdir? }
  | { kind: "new_project", name, nodeId?, baseDir?, template? }

ResolvedTarget = { kind, nodeId?, projectId?, workspaceId?,
  sessionId?, workdir?, executor? }

    创建：新项目与新会话先进入 preparing，资源就绪才 queued；记录 requestId、taskId 与已创建的资源 ID。重试查回资源，不重复建目录 / 仓库 / 会话。同名项目不静默覆盖；创建失败报告具体阶段，保留可恢复记录。封装现有项目创建与 CLI 会话能力，缺少的结构化入口在实现时补齐。

    续派：以 sessionId 定位，展示名只作候选；忙碌时追加修订并排队，沿用已有安全边界。休眠会话先按已关联对话 ID 恢复，无法确认关联时说明缺失，不猜别人的历史。会话、项目和工作区分别建模，选择已有会话时无需另建项目。

    记忆：projectId 为空时，任务记忆与会话记忆仍正常工作，每日记录标为“未归属项目”，不混入其他散会话的上下文。后续归入项目时更新归属并保留历史来源；任务仍用 taskId 去重，不能在日记里重复计数，也不把整段历史自动晋升为项目长期记忆。

    流程模拟
    交互原则：任务意图持久化成功后，Main 立即回答“已安排”，不等待目标解析、资源创建或执行器启动；有真实启动回执后再显示“已启动”。完成和失败由事件唤醒 Main，合并汇报。用户补充要求会生成任务修订，运行中的 Worker 在安全边界接收；旧版本结果保留为历史，不冒充最新完成。
    04

    内核只保留六个职责

    Agent Loop

    组装上下文、调用模型、收集完整工具参数、校验执行、追加结果，循环到回答、挂起或结束。流式事件贯穿每一步。

    Model Adapter

    Python 统一消息、文本 / 图片、工具调用、用量与取消。模型按能力选择；主对话优先低延迟，执行模型按任务配置。

    Tool Gateway

    统一工具 schema、权限、deadline、执行记录与结果引用。只读独立调用可并行；改文件、浏览器和桌面操作按资源串行。

    Session & Context

    持久化消息与分支，维护输入队列、上下文预算和压缩检查点。一个会话同时只有一个写入者。

    Task Supervisor

    创建 / Fork / 追加要求 / 取消 / 回收，控制并发、深度与父子总预算。原生 Agent 和 CLI 执行器共用任务状态。

    Memory & Events

    记忆按范围检索，记录来源与有效期。任务事件持久化后推送；断线可重放，后台完成不会依赖当前网页在线。

    工具具体怎么接：MCP、Shell、HTTP、Browser、Computer
    适配器实现边界执行约束
    Shell / 文件命令、读写、patch、日志及 artifact 引用显式 cwd / env；进程组取消；大输出落盘
    HTTP按配置定义 method / URL / schema / credentialRef凭据运行时注入；限制目标域和重定向；写请求按幂等约定重试
    MCP先支持 stdio 与 Streamable HTTP，按需加载 tools；resources / prompts 后续扩展初始化、版本协商、鉴权、断线恢复和结果大小限制，交给协议库 [S5]
    Browser Use先封装现有 chrome 能力；DOM / 可访问性快照、定位、点击、填表、截图一个任务独占 tab / context；动作后检查页面变化；同 tab 的行为串行
    Computer Use屏幕截图、鼠标、键盘、滚动的系统驱动；配支持图像输入的模型一个桌面一个控制租约；标记屏幕坐标 / 缩放；可暂停交给人；按动作验证结果

    两种 Use 都走“观察、决策、动作、验证”循环，复用内核。浏览器优先 DOM；桌面走图像与坐标。截图保存 artifact，只向模型发送当前必要画面。外部页面和工具结果作为数据，不提升为系统指令。

    压缩与 Fork：长期对话不会拖慢主 Agent

    压缩：每轮请求前预算包含系统指令、工具 schema、检索记忆、历史、图片与预留输出。接近预算时，在空闲或后台按稳定前缀准备摘要，提交时核对消息版本并接上新增轮次。若当前请求已超窗口，必须先构造有效上下文，不能为追求速度跳过必要压缩。总结旧轮次并保留最近完整轮次。固定保留目标、用户约束、未完成事项、任务 ID 和证据引用；tool call / result 成对切分。检查点原子提交，失败保留原文并有限重试；仍放不下就报告需要缩小输入，不静默丢约束。借鉴 Pi 的追加压缩条目，不删原始历史 [S2]。

    Fork：默认用任务简报创建隔离子会话；需要历史时，从明确 checkpointId 分支，复制相关上下文快照，之后独立写入。返回结构化摘要与 artifact，原始子对话按需读。子权限取父权限与角色权限的交集，预算计入父任务树；首版建议并发 3、深度 2，可配置。

    注意边界：原生 Agent 的上下文 Fork、Git worktree、ttmux fork 是三种操作。现有 ttmux fork 建立会话父子关系并继承目录 / 环境，并不会复制模型历史；外部编码 Agent 接收任务简报和选定记忆。

    调度、恢复与取消：最小可靠性约定

    Main 优先直接回答，只执行有明确时间预算的短工具与任务入队；超出预算转 Worker。为主对话预留模型请求槽位与连接，用户新消息优先于后台完成通知。首段有效回答与完整问答耗时按页首标准验收；后台启动耗时单独统计，不阻塞回答。

    任务状态为 preparing / queued / running / waiting_user / verifying / succeeded / failed / cancelling / cancelled / interrupted。状态转换与 outbox 同事务提交；事件带递增序号，客户端按 ID 去重。任务记录 leaseOwner / leaseUntil / attempt / revision；执行前核对租约与版本，丢失租约的执行器不能继续提交状态。

    重启后先核对 CLI 会话、运行进程和回执，再恢复领取。执行状态不明时标记 interrupted，不自动重跑有副作用的命令。取消向原生子树传递；CLI 会话先请求停止，再验证进程退出，取消 CLI 调用本身不等于编码 Agent 停止。

    同工作区只允许一个写任务，多个编码任务用独立 worktree，最后交集成任务检查。结果须包含证据，编码任务完成后还要验证目标 commit、测试和验收要求。预算覆盖模型、工具耗时和子任务；拿不到外部 Agent token 用量时显示“未知”，用时长 / 并发限制兜底。

    05

    记忆按任务、对话、日期组织

    这些是可组合的检索维度。同一条记录可关联任务、对话、项目与日期，保留一份原始事实，通过索引查看；跨维度摘要注明来源，避免把总结当成新事实反复累积。

    示例

    写入

    消息、工具和任务事件先追加原始记录。工具结果提取工作记忆；用户明确表达的偏好、验证过的任务结果可晋升项目 / 用户记忆。推断标注“待验证”，冲突新增版本并指向被替代条目。

    读取

    先按用户、执行目标、任务 / 会话和日期过滤，再用关键词 / FTS 排序。当前任务优先，补相关对话、近期日记、项目知识，固定预算内加载；向量检索可后加，不能绕过范围过滤。

    压缩摘要与长期记忆分开：压缩服务于当前模型窗口，记忆服务于未来检索。每日摘要是原始事件的可重建视图，不是跨天复制的整段聊天。按用户时区聚合，保留 UTC 时间与时区，支持日记迟到更新。
    记忆的数据与生命周期

    每条记忆带 userId, projectId?, taskId?, conversationId?, occurredAt, timezone, kind, sourceRefs, status, supersedesId?, expiresAt?。任务 / 对话是范围，日期是时间索引，项目 / 会话共同构成检索边界，散会话不要求 projectId；类型区分事实、决策、偏好、摘要。

    用户可查看、修改、删除和设置保留时间；任务细节归档，长期事实按有效性更新。删除条目同步失效 FTS、向量、日记与派生摘要，防止后续检索复活；已发送给外部编码 Agent 的简报无法撤回，下次续派用新版本。凭据只存引用，不进记忆正文。

    06

    Claude Code / Codex 统一走现有 CLI

    采用你指定的接入方式：Python 执行器直接调用现有 Roami / ttmux CLI，复用会话、启动与恢复能力。两个编码 Agent 的差异封装在 CLI 层。

    环节可复用的现状框架需要补的部分
    执行目标路由项目台账、稳定会话 ID、散会话、仓库 / worktree 归属、默认 Agent解析直接处理、项目、会话或新建意图；先准备资源，再固定 ResolvedTarget。项目归属可空，已有会话优先续派。
    创建与派活roami ttmux 转发；swarm add --kind claude|codex；插件 agent.spawn薄 CLI 适配层：结构化请求、返回稳定 sessionId、任务 ID 与幂等键；长简报走文件 / stdin
    继续与观察ttmux send、capture、ls --json、swarm status --json，Agent 恢复注册表任务与会话 / 对话 ID 绑定；续派保持原 ID。忙碌时排队，不向正在执行的 TUI 盲发控制键
    完成与验证会话、日志和现有状态信号可观察结构化运行回执、退出状态、结果 / 证据文件与验收步骤；会话消失或提示符出现仅作信号
    取消与恢复CLI 会话树、休眠 / resume 元数据请求取消、停止确认、超时与回收的任务语义；重启对账；活跃任务防重复启动
    现状与设计边界：已有 CLI 能派活，但不能把 send 返回成功或会话退出直接当作“任务做对了”。下面的结构化契约是待新增能力，不是声称当前 CLI 已支持。

    以下命令已在本机 help 和源码核对，由 Python CLI 执行器调用。仅用于说明复用路径；新框架不应对外承诺未经验证的参数。

    07

    分三步做成，每一步都有闭环

    第一步 · 能聊、能派、能收

    最小可用框架

    Python 自研 Loop、消息 API / SSE、Main / Worker、工具、Memory、压缩、目标路由与 CLI 派活；支持项目、散会话及创建流程。闭环可独立运行后，接 Go 统一鉴权和透明转发。

    验收：Go / Python 消息与事件可断线续接；用户追问不阻塞；已有散会话可续派、新会话可独立工作、新项目可创建后派活；重启不重复建资源或派活。

    第二步 · 能扩展、能并行

    完整工具与协作

    MCP、原生 Fork、领域配置、预算继承；worktree 写入隔离；Browser Use；记忆编辑 / 删除联动；队列、限流和上下文评测。

    验收：两个项目并行不串记忆；子任务可取消；MCP 可断线恢复；浏览器任务留下可验证结果。

    第三步 · 能操作整台电脑

    Computer Use

    桌面驱动、截图观察、输入动作、独占租约、人工接管与录像；根据运行数据再扩节点调度、语音入口和向量记忆。

    验收：真实桌面任务完成；失焦能发现；人工接管立即停动作；同桌面不被两个 Agent 同时控制。

    首轮实现建议：先验收普通问答速度，再跑通“Python Main 快速接收任务意图并回话，后台识别目标、准备资源、经 CLI 启动 Codex；用户持续聊天，完成后流式汇报并写入记忆与日记”；随后把消息与流接到 Go 的统一鉴权入口。每次增加工具或记忆能力，都回归主对话延迟，避免后台能力拖慢问答。
    08

    调研结论与依据

    截至本次查阅：Pi 值得借鉴的是轻量循环、事件流、会话分支与追加式压缩；OpenClaw 值得借鉴的是运行时外围的会话、工具和子任务协作。当前 OpenClaw 主分支文档已描述自有 agent-core，不能把“底层始终直接依赖 Pi”当作不变前提 [S3]。本报告其余部分是针对 Roami 的设计建议。

    S1 · Pi Agent Core

    模型边界转换、流式事件和工具执行循环；核心不承担 Roami 的项目管理。

    S2 · Pi Compaction

    预算触发、保留近期消息、追加检查点；会话原始记录独立保留。

    S3 · OpenClaw Runtime Architecture

    区分 agent-core、会话层、工具层与模型传输；核对当前运行时边界。

    S4 · OpenClaw Sub-agent Reference

    独立与 fork 上下文、父子任务、工作区与完成交付等协作机制。

    S5 · MCP Transport Specification

    按明确协议版本实现 stdio / Streamable HTTP，避免把普通 HTTP 工具等同 MCP。

    S6 · OpenClaw Memory

    持久化记忆与会话上下文的分工；本方案增加任务、对话、日期的组合检索。

    S7 · Codex 官方接口文档

    已核对原生集成路径。按你的决定，本期采用现有 Roami CLI，不直接接 App Server。

    S8 · Claude Code 官方 CLI 文档

    核对编程调用能力；具体启动、恢复与差异继续封装在现有 CLI 层。
