统一工具网关：MCP、Shell 与 HTTP

工具调用有统一的参数、资源、输出、取消和回执契约。模型只提出调用，运行时决定如何执行并持久化结果。

注册与调用契约

ToolSpec = {
  name, version, description, inputSchema, resultSchema?,
  effect: read | write, timeoutMs, maxOutputBytes,
  concurrencyKey?, requiredResources, retryPolicy, implementationRef
}
ToolInvocation = { callId, turnId, taskId?, runId?,
  toolName, toolVersion, arguments, deadlineMs, idempotencyKey }
ToolResult = { callId, state, text?, artifactRefs,
  structuredData?, errorCode?, retryable, outcomeKnown }

Registry 以完整工具名与版本定位实现，如 shell.exec、http.issue.create、mcp.docs.search。provider adapter 负责模型侧名称编码与 schema 格式；核心仓储保留规范名与版本，不把工具代码塞进 Prompt。

一次调用的状态与流水线

1. 完整参数

等待 ToolCallReady；schema 与预算校验；落 planned 记录。

2. 资源准备

取得工作区 / tab / desktop 等资源；检查版本与调用范围。

3. 事务外执行

标 running；deadline / cancel 向驱动传递；输出限长。

4. 提交结果

结果与 tool message / event 同事务；模型读取短结果或 artifact。

独立只读工具可以并行，但写回的 tool results 按原 call 顺序构造模型消息。需要同资源顺序的调用不能因模型一次发出多个工具就盲目并行。工具报错也产生配对结果，不留悬空 call。

Shell 与文件

  • Python 子进程调用明确 executable / argv / cwd / env；用户确实需要 shell 语法时，显式选择 shell 模式，不把框架参数混进 shell 字符串。
  • 子进程有运行标识、进程组、deadline 与取消信号；取消 CLI 包装进程不能自动当作子工具已停止。
  • stdout / stderr 分开采集，命令退出码与任务验收分别记录；大日志落 artifact，模型只接摘要和引用。
  • 文件读取支持范围、编码与最大字节；patch / write 记录目标文件 hash，提交前发现已变化就返回 conflict。
  • MCP / Shell 都可能产生副作用；outcome unknown 时记录事实，恢复后先对账，不能无条件重放。

HTTP 工具

HttpToolConfig = {
  name: "http.issue.create", method: "POST",
  endpointRef: "project_issue_api", pathTemplate: "/issues",
  argumentsSchema, credentialRef?, responseProjection,
  timeoutMs, maxResponseBytes, redirectPolicy,
  idempotencyHeader?  # 目标 API 确实支持时才启用
}

以配置定义目标服务、schema 和响应投影，凭据在执行时解析。每次请求记录 method、去敏 URL、状态码和结果 hash；不将 Cookie / Authorization 写入普通日志。只读重试遵守 deadline，写请求只有在目标 API 幂等契约明确时自动重试；否则超时后先查回执行结果。

MCP 连接与目录

1. 初始化

按固定协议版本完成 initialize 与能力协商。

2. 发现

tools/list 后校验 schema，命名空间隔离，生成 catalogVersion。

3. 执行

tools/call 对应规范 callId，支持 progress、deadline 与取消。

4. 重连

连接失败退避；重新协商目录，变化时更新版本与可用状态。

首版支持 stdio 与 Streamable HTTP，使用协议库承担传输 / 版本协商。服务自己的凭据沿用该 MCP 配置，不再建用户登录系统。stdio 的 stdout 是协议通道，日志走 stderr；HTTP 连接与会话按服务契约管理。

MCP · Transports

目录可以按角色预加载或按需发现；目录 / schema 变化会改变模型输入，必须进入 tool catalog version 与 cache fingerprint。工具已移除时，即使模型仍记得旧描述也拒绝执行并返回 tool_unavailable，不能猜一个相近工具替代。
