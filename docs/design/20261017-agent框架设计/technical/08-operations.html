SQLite 单写与背压

使用专用 DB writer 线程持有写连接，应用队列串行执行短事务；async 服务等待 Future，不把 sqlite3 阻塞操作放进事件循环。读连接在线程内创建 / 使用，避免跨线程乱用同一连接。所有写事务在调用模型、CLI 或网络前结束。

  • WAL + foreign_keys=ON + synchronous=FULL 为可靠性起点，busy_timeout 有上限；长期读事务和 WAL checkpoint 需监控。
  • Writer 队列满时在入队前拒绝新的未接收请求，返回可重试状态；已提交请求超时用相同 requestKey 查询结果。
  • 流片段批量提交，Main 接收命令优先，后台索引 / 日记低优先级；主请求不会排在无限后台写队列之后。
  • 运行时库只允许一个 Python 实例迁移 / 写入；同时遵守统一 storage.lock。升级使用统一备份编排，覆盖数据库和 artifact 文件。
  • 迁移逐版本执行；破坏性变更拆成扩展、回填、切读写、清理，不在启动时先删旧数据。

纳入统一存储与维护协议

数据库固定在统一 DatabaseRoot 下，拟用 agents/runtime.db；catalog 描述记录 id=agent-runtime、kind=agent、owner=python-agent 与相对路径。目录登记由 Go internal/storage 适配统一执行，Python 不自行重写 catalog.json。登记采用 pending → 迁移完成 → ready；已登记文件丢失必须报错，禁止静默重建空库。

第一版使用保守的进程级维护租约：Python 启动访问数据库前，持有 DataRoot/locks/storage.lock 的共享 flock，直到关闭全部数据库连接和产物写入才释放；另持有独占 agent-runtime.lock 防止第二实例。与 Go 使用同一个持久 inode，锁文件永不删除或替换。维护需要 storage.lock 独占锁，忙时明确 STORAGE_BUSY，不强抢。首版不承诺运行中维护。

升级、布局迁移、全库备份 / 恢复前停止 Python 并确认进程退出和锁释放，按 Go 统一 db 流程维护；启动版本迁移保持共享维护租约与 Agent 独占锁，事务内按版本升级。候选 DDL 使用 schema_meta 保存版本，兼容当前备份清单的版本读取。Go 仍不拥有 Python 业务表的 DDL。

当前 roami db backup 会拒绝未登记库并快照 catalog 中的数据库，现有 restore 只对 main 强制最高 schema 限制；Agent 集成还需增加 owner schema 兼容检查。现有备份只涵盖数据库与布局清单，不是 Agent 完整恢复包。实施时扩展备份编排：维护锁期间冻结产物 GC，收集 Agent artifact hash / 文件并写清单校验；恢复到空实例后先验证 Agent schema 兼容和全部产物，再启动 Python。

schema.sql 与临时库检查仅证明候选结构有效，不证明上述 catalog、跨语言锁、备份 / 恢复桥接已经实现。运维验收必须增加双进程 flock 竞争、维护期间拒绝写入、pending 恢复、路径覆盖、未登记库拒绝、缺失产物与新版本库拒绝启动。
