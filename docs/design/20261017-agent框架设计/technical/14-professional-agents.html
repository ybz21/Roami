设置如何组织

设置 → 智能体分为：模型与连接、专业智能体、技能 Skills、工具与 MCP。模型与连接只设置一份 Base URL / Key，再选 Main 与原生后台模型。专业智能体使用各自 CLI 的登录与供应商配置；不把 Main 的 Key 自动复制给它们。

“可执行文件”改为“专业智能体”，原有地址 agent.bin 保持兼容。每张卡片默认只显示连接状态、派活能力、用量摘要和操作；命令路径、版本、运行节点放进详情。手机单列卡片，桌面双列，不拉成长行。

如何使用

  1. 主对话：用户说“发给某项目的 Codex”，先查项目下完整会话列表，唯一目标直接投递；候选冲突才用选择题。明确已有会话就不新建。
  2. 后台新任务：用户要求新建，按项目默认执行器 → 用户偏好 → 已启用且能力满足的候选选择。记录最终执行器、节点、模型与会话；结果回原 Main。
  3. “使用”按钮：打开任务创建表单并预选此专业智能体；选择已有项目、散任务或新项目，未提交前不生成空会话。
  4. 额度不足：展示真实限额与重置时间，可选“稍后继续 / 换专业智能体 / 取消”。切换需要已授权的策略或用户选择，不静默转入更贵的 API。
  5. 普通查询：Main 快问快答；联网检索走原生后台 Browser。专业编码智能体承接适合它的工程任务，不因“需要工具”就默认创建 Codex。

专业智能体会话仍在原项目 / 工作会话树中，主对话只显示后台任务与过程事件，不增加第二套分支聊天导航。CLI 自身必要的权限确认保留；产品不为已授权的普通消息投递重复加确认。

用量与额度：分清四种口径

指标展示与来源
会话上下文当前上下文 tokens / 模型窗口；压缩相关，不能作为套餐消耗。
实际调用用量输入 / 输出 / cache read / cache write 分列；单位 tokens，按原生事件或日志记录。去重后才能按天、项目、任务汇总。
套餐 / 速率额度按账号、提供方、窗口记录 usedPercent / resetsAt；来自明确限额数据。最后一次观测过期时标“已过期”，无观测显示“未知”。
费用币种、来源与口径独立保存：CLI 估算、价格表估算、供应商账单。订阅内用量不能直接推算已付费用；不同币种不直接相加。

详情页选择“今日 / 7 天 / 本月”，按智能体 → 账号 → 项目 → 后台任务查看，显示采集覆盖率和最后更新时间。只统计可归属的记录；归属不明放“未关联”，不猜项目。一个账号在多节点共享额度时，同一限额快照按账号 + 窗口去重；节点切换不是额度重置。

实现边界与代码层次

internal/agent/                 复用 Kind、启动参数、原生身份与恢复能力
backend/agentcatalog/           拟新增：节点探测、能力声明、专业智能体设置聚合
backend/agentusage/             拟新增：原生用量采集、去重、额度快照与汇总
backend/server/                 Go 统一鉴权、节点路由与管理 API
agent-runtime/.../executors/    复用 RoamiCLIExecutor；新增种类必须补生命周期契约
agent-runtime/.../dispatch/     目标解析、能力筛选、预算策略；不读取专业 CLI 密钥
frontend/.../settings/          专业智能体卡片、详情与用量入口

Go 拥有节点与专业会话服务，专业智能体目录与用量采用 Go 管理存储规范；Python 仅消费 CLI 的能力与任务结果，不直接写 Go 数据库。新增表走正式迁移；不在本文静默修改运行库。

账号引用只保存脱敏别名与稳定内部标识；日志、管理 API 和卡片不返回 Key。配置、探测、禁用、卸载彼此独立：禁用阻止新派活，不自动杀掉正在工作的会话；卸载另行评审。

拟定 API 与统一 CLI

以下为提案，尚未注册生产路由；合入前先做路由冲突检查。既有 /api/agent/capabilities 是工作会话能力指南，禁止覆盖。

GET   /api/agent/professional-agents                 节点范围目录与能力
PATCH /api/agent/professional-agents/:id             启用、模型偏好、命令引用
POST  /api/agent/professional-agents/:id/probe        有界、只读探测
GET   /api/agent/professional-agents/:id/usage        用量、额度、来源和覆盖率

roami agent executors list --json                   拟定发现入口
roami agent executors probe <id> --json             拟定探测入口
roami agent usage --executor <id> --json            拟定用量入口

roami project sessions <id> --json                  现有项目会话发现
roami session / execution                           现有投递与生命周期路径

探测使用 argv、超时与输出上限；不自动执行安装脚本或触发交互登录。任务创建继续复用既有服务和幂等键，不另造裸 tmux 操作。启停后再次校验工具与执行器策略，旧模型上下文不能绕过禁用状态。

分步交付与验收

  1. 管理入口：改名、卡片、只读版本 / 连接探测，高级设置保留。手机触控、无文档滚动、桌面密度验收。
  2. 已有专业智能体：Claude / Codex 状态与用量接入，同一事件重复读取不重复计数；缺失和过期如实显示。
  3. OpenCode / Pi：以安装版本验证原生身份、恢复、结束事件与用量协议；补“失败 / 崩溃 / 未知 / 取消 / 重复回报”后才开放 Main 自动派活。
  4. 路由与额度策略：项目默认、账号额度与用户授权联动；不因额度未知而封死已有会话投递，也不把未知视为无限额度。
需要评审的是新增专业智能体管理、用量聚合与追踪适配方案。当前落实入口命名、专业智能体卡片与原有命令高级配置；用量、额度、安装与登录探测仍明确标为未接入，不把本页演示宣称为已实现的后台能力。
