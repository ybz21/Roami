系统边界

1. Go 入口

复用登录鉴权；HTTP / SSE 原样代理；既有节点转发。

2. Python 服务

消息 API、Main / Worker、检索、上下文、工具、调度与回复。

3. 状态与证据

单写 SQLite；原始消息、记忆版本、检查点、事件；文件保存大输出。

4. 外部执行器

Python 调 Roami 统一 CLI；Claude Code、Codex 保持自身运行时。

三个独立概念：Transcript 保存发生过什么；Memory 保存可复用知识及来源；Context 是当前请求交给模型的、有版本的投影。缓存只加速投影与模型输入处理。

两条执行路径

阶段普通问答快路径执行任务路径
接收同事务保存 request、user message 与 queued turn同样接收；Main 使用 delegate 工具提交轻量 TaskIntent
处理读取热快照；一次模型调用直接回答，不强制分类 / 检索保存任务与准备 job，立即获得“已安排”；Worker 后台准备资源
输出Python 持久化流片段后 SSE 输出；Go 及时转发Worker 回报 → 验证 → Main mailbox → 在原主对话回报
后台提取候选记忆、日记、快照压缩状态对账、产物、来源与长期事实晋升
Main 只拥有少量短工具：delegate、status、memory_search、memory_get。建项目、启会话、长 Shell、MCP 和桌面操作交给 Worker。

存储与一致性

下载完整候选 DDL：schema.sql。首版单节点、单 Python 实例拥有一个数据目录；Python 拥有运行时业务表与迁移；Go 统一存储层负责路径、目录登记及维护协调，不写 Agent 业务表，meta.db 仍由 Go 共享业务服务管理。

<DatabaseRoot>/agents/runtime.db    canonical messages / tasks / memories / events
<DataRoot>/agent-artifacts/    content-addressed evidence / logs / images
<DataRoot>/locks/agent-runtime.lock  单实例数据目录锁
<RuntimeRoot>/agent.sock          本机 CLI 回报入口（非用户第二套登录）

多节点阶段不共享 SQLite 文件。主会话与 Memory 保留在所属 runtime；远端只接 TaskSpec 并回报事件 / artifact。跨节点传输沿用 Roami 节点通路，执行状态由原 runtime 对账。

与统一 CLI v4 对齐

当前基线 a27f13a（#328）。Go 只有根 module 与 cmd/roami 一个入口；Web 与 CLI 复用应用服务。Python 是外部执行进程，使用统一 CLI 是合法边界，Go 服务内部直接复用 SessionService，避免再启动自身二进制。

标准命令为 roami session、roami chrome、roami project、roami db；ttmux / chrome 与 roami ttmux 只作兼容。新增 report / reply 放在同一二进制的明确 agent 命名空间中，仍为待实现提案。

Agent 库拟登记为 agent-runtime / agent / agents/runtime.db / python-agent，共享统一路径解析、catalog、storage.lock 与备份集。路径解析与登记桥接、Python 维护协调和产物备份尚需实施，不能仅创建数据库就宣称接入完成。

完整决策与实现缺口见 CLI 对齐清单；新工作区准备见任务模块，数据维护协议见运行模块。
