记忆如何存储和更新

任务、对话、日期是组合维度；项目归属可空。记忆不是所有聊天的副本，每条可复用知识都保留来源、状态与版本。

来源可追溯版本化项目可空后台提炼
技术总览对话保存记忆存储记忆召回上下文与 Cache运行时与模型任务与 CLIAPI 与流转发运行与验收工具网关浏览器与电脑主动联系与未读

三层数据

层保存什么持久化位置
原始记录消息、工具结果、任务状态、文件 hashmessages / events / task_attempts / artifacts
结构化记忆事实、偏好、决策、摘要；来源和有效时间memory_records / memory_sources / memory_edges
派生索引与缓存分词、FTS、可选 embedding、上下文摘要memory_fts / memory_embeddings / context_snapshots
原始记录保真，记忆按规则晋升，索引可以重建。model/provider 的 cache 不承担记忆保存。

记录字段与范围

MemoryRecord = {
  id, ownerId,
  kind: fact | decision | preference | summary,
  projectId?, conversationId?, taskId?, dayKey?, timezone?,
  title, body, canonicalKey?, state, revision,
  supersedesId?, validFromMs, validUntilMs?, expiresMs?,
  sourceWatermark?, createdMs, updatedMs
}
MemorySource = { memoryId, sourceKey,
  messageId? | eventId? | artifactId?, sourceSha256 }

一条事实可同时关联任务、对话、项目与当天；不按五种维度复制五份。独立散会话使用 conversationId / taskId，没有 projectId 也可写读。用户级长期偏好不带项目；项目决策带 projectId，不能仅因措辞相似就升级为全局偏好。

后台写入流水线

1. 事件触发

turn 完成、task 验收、用户明确记住、每日归档触发 job。

2. 候选提取

只读有限新增来源；提取简短原子事实、来源 ID 和建议范围。

3. 校验与去重

检查来源存在、hash、owner、tombstone；按范围 + canonicalKey 比较。

4. 事务提交

写版本与来源，旧版本 superseded；更新 FTS、memory_epoch 和后续 job。

提取模型只生成候选，不可直接写 active 记录。用户明确偏好、已验证任务事实可以激活；模型推断保留 candidate，检索默认只读 active。新信息与旧信息矛盾时记录 conflict / supersedes，不把更晚的模型猜测自动当成事实。

memory.extraction(job):
    sources = load_sources(after=job.watermark, bounded=True)
    candidates = extractor.propose(sources)
    for candidate in candidates:
        validate_source_ids_and_owner(candidate)
        reject_tombstoned_source(candidate)
        resolve_scope_and_conflict(candidate)
    writer.commit_versions_sources_fts_epoch(candidates)
    enqueue_daily_summary_if_needed()

每日记忆如何形成

保存用户时区的 dayKey 与 UTC 事件时间，按 owner + date + timezone + scopeKey 唯一。scopeKey 为项目 ID 或 unassigned；日志由原始事件截至 sourceWatermark 重算，迟到事件覆盖新版本，不在旧日记后重复拼接。

统计口径
用户轮次user message / request 去重；不把 tool 回调算用户对话
下任务数按 taskId 去重；修订和重试不新增任务计数
完成任务数按终态事件截至 watermark 计算；失败另列
跨天执行创建日与完成日分别记录，查询明确展示口径

长期知识可由任务结果晋升，但日记本身只用于时间回顾；不得每天复制前一天全文。日界线用 IANA 时区库计算当地零点到下一个零点，不硬编码 24 小时。

删除、失效与重新学习

  • 删除条目：同事务将 state 改 deleted、写 tombstone、移除 FTS，递增 owner memory_epoch；embedding 及派生摘要失效。
  • 通过 memory_edges 找受影响的 summary；重建前不可作为 active 命中。共享同一个来源的其他事实不自动删除。
  • 普通记忆删除不等于删除历史对话。产品需区分“删除记忆”和“彻底忘记相关信息”。
  • 彻底忘记：通过来源及 prompt_manifest 追踪受影响消息，在 context_omissions 登记模型投影屏蔽项，失效相关快照并重建；工具块整体处理。历史原文另按用户选择保留或删除。
  • 后台提取再次看见相同来源时先查 tombstone，不能把已删除的记忆重新自动写回。用户明确重新记住时创建新来源与版本。
  • 已发送给模型供应商或外部编码 Agent 的输入无法由本地数据库删除动作撤回；后续续派使用新的上下文版本。
修改缓存不是删除的全部：索引过滤、派生摘要、分支上下文、CLI 续派简报都必须遵循新的 epoch。
