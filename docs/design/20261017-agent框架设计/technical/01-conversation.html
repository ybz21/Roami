接收一条用户消息

1. 鉴权与解析

Go 提供已验证 owner；Python 校验会话归属与请求 schema。

2. 单次短事务

去重 request，分配 seq，写 user message / queued turn / turn.run job。

3. 确认接收

COMMIT 后返回 202 + turnId / messageId / cursor；不承诺已执行。

4. 调度 Main

领取该 branch 的 turn；释放 DB 事务后调用模型。

def accept_message(owner, conversation_id, request_key, payload):
    digest = canonical_sha256(payload)
    with writer.transaction(immediate=True):
        old = requests.find(owner, request_key)
        if old:
            require(old.payload_sha256 == digest, conflict=409)
            return old.receipt
        conversation = conversations.get_owned(owner, conversation_id)
        seq = branches.allocate_seq(conversation.active_branch_id)
        request = requests.insert(...)
        turn = turns.insert(state="queued", trigger_kind="user", ...)
        messages.insert(role="user", status="completed", seq=seq, ...)
        jobs.enqueue(kind="turn.run", dedupe_key=turn.id, ...)
        events.append(kind="message.accepted", event_key=request.id, ...)
    return receipt  # 只有 commit 后才作为已接收返回
DB 超时且提交结果不明时，客户端用原 request_key 查询 / 重试，不换新键。不能因为 HTTP 请求超时就断言没有入库。

流式消息的保存策略

先创建 status=streaming 的 assistant message。模型 delta 在内存累计到 100ms 或约 1KiB，先同事务更新 message content_json 与追加 message.delta 事件，COMMIT 后再发布到订阅者；达到末尾时追加 message.completed。数字为可配置起点，需以实测调整。

event = {
  "id": 1241, "type": "message.delta",
  "conversationId": "c1", "branchId": "b1",
  "turnId": "turn7", "messageId": "m9",
  "revision": 1, "payload": {"offset": 24, "text": "下一段文字"}
}
  • 流片段没有在提交前对用户可见；进程丢失内存缓冲时，只丢尚未发布的 token。
  • 重连先取 message snapshot 与截至游标，再订阅其后的事件；按 messageId + offset 合并，不能直接重复 append。
  • 模型中断时保存已有文本，status 标记 interrupted；恢复重新生成要创建新的 attempt / message，不能伪装成上一条已完成。
  • 工具调用参数必须完整通过 schema 校验才执行。工具结果消息记录 toolCallId，即使出错或取消也给出明确结果状态。

分支、上下文与恢复

Fork 是逻辑分支：新 branch 指向父分支某个已完成 message，不复制全部消息。读取时逐级解析祖先截止点，再拼 child 的 seq；限制分支深度并可后台物化索引。CLI 的 roami session fork 只建会话关系，不等同模型上下文分支。

  • 保留对话历史原文，UI 默认显示 active_branch；模型只读取所选分支及允许的上下文投影。
  • 启动时检查 lease 过期的 running turn；模型请求不能凭断开的 HTTP 自动续接，标 interrupted，并保留 partial output。
  • 已提交的 delegate 工具回执按 idempotency key 查询后续接，不能把整轮模型原样重跑造成二次派活。
  • 旧分支任务完成时，在主对话邮箱记录来源分支；按任务 revision 决定可见回报，避免旧结果覆盖新要求。

保留、备份与验收

历史对话分页读取，按 branch + seq 查询；大文本与图片在 artifacts，消息只存引用与 hash。列表和对话正文分别索引，不能每次打开都扫描全部日志。SQLite WAL 支持读写重叠，但写入仍需控制事务；备份使用 SQLite backup API，不能只复制正在写入的主 db 文件。
