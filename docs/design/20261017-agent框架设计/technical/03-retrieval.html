什么时候检索

问题路径
普通知识问答 / 简单对话不检索私人记忆，直接使用短上下文

中文与英文索引

首版用 SQLite FTS5，先在应用层分词再写入 tokens 列。中文连续片段生成相邻双字词，英文 / 数字标识符保留原 token；查询使用同样 tokenizerVersion。单个汉字通过指定范围内最近 N 条的有限 LIKE 补查，不能无界全表模糊扫描。

# 示意：统一入库与查询分词；实现时加长度、字符与词数上限
"Agent 记忆方案"  -> ["agent", "记忆", "忆方", "方案"]
"会话"            -> ["会话"]
query_tokens       -> quote_each_literal(tokens)  # 不接受用户原始 FTS 语法
fts_query          -> OR(query_tokens)            # 用绑定参数传给 MATCH

FTS5 自带 trigram 可以做子串索引，但少于三个 Unicode 字符的 MATCH 有限制；两字中文短词不能直接假定能查到。因此此处选择显式双字词方案，词典分词或 trigram 可作为后续替换。

SQLite FTS5 · Tokenizers

SELECT m.id, m.revision, m.body, bm25(memory_fts) AS rank
FROM memory_fts
JOIN memory_records m ON m.id = memory_fts.record_id
WHERE memory_fts MATCH :literal_query
  AND m.owner_id = :owner_id
  AND m.state = 'active'
  AND (m.expires_ms IS NULL OR m.expires_ms > :now_ms)
  AND (m.valid_until_ms IS NULL OR m.valid_until_ms > :now_ms)
  /* scope_predicate 由固定 ScopeFilter 生成，不拼用户字符串 */
ORDER BY rank ASC LIMIT :candidate_limit;
完整过滤条件必须在 LIMIT 前应用；先全库取 top-k 再过滤会漏掉合法候选。ownerId 从已验证请求上下文取得，不能直接信任请求正文。

候选、排序与证据装箱

1. ScopeFilter

owner 必选；按当前 task / conversation / project / date 与类型限制。

2. 候选召回

FTS top 40；可选向量 top 40；精确 ID / alias 优先。

3. 排序去重

按范围与匹配排序；向量启用后用 rank fusion；同 canonicalKey 取当前有效版本。

4. 证据预算

先取 8 条，再以约 2k token 装箱；附 memoryId / revision / sourceRefs。

不直接把 BM25 与 cosine 裸分数相加。首版先用词匹配排名、范围优先级和有效性排序；向量启用时用 RRF：score = Σ 1 / (60 + rank)，再作来源 / 版本去重。时效只对时间敏感事实加权，不能让“新”自动胜过已确认的长期约定。

MemoryHit = {
  memoryId, revision, text, sourceRefs, scope,
  validFromMs, expiresMs?, rankReason, tokenEstimate
}
RecallResult = { memoryEpoch, hits, truncated, tookMs }

向量召回与缓存

向量是第二阶段的可插拔 Retriever：embedding 带 modelKey / dimensions / revision，记录更新后旧向量立即失效，新向量后台计算。小规模可在已过滤候选上精确比较，规模增长后再选 ANN；首版不因向量服务不可用阻塞问答。

检索缓存 key 包含 owner、scope fingerprint、normalized query、tokenizer / embedding / ranking version 与 memoryEpoch；TTL 只是兜底。取出后再核对记录状态与 revision。epoch 不一致立即失效；快照与 provider cache 使用另外的键。

检索没有证据时，不把相似问题缓存中的旧自然语言答案直接当作回答。
