一个主对话，后台执行

发现目标、直接投递、后台新建与真实回报。

2026-10-18 · 根据本会话确认：Main 是长期大总管，Codex / Claude / 原生子 Agent 是后台任务。项目与工作会话树保留，不再展示多主对话或分支聊天入口。

四层边界

  1. 技能：内置 roami-dispatch，复杂派活时通过 skill_read 按需加载；稳定指令只保留授权、目标解析与结果真实性规则，避免每轮灌入 CLI 手册。
  2. 结构化工具：target_search / target_resolve、session_send、delegate、task_status、ask_user。Main 无需开放任意 Shell。
  3. Python 适配：以 argv 调正式 roami CLI；写入载荷走 stdin、工具调用 ID 派生幂等键。排除模型密钥环境变量，限制超时与返回体。
  4. Go CLI：复用既有项目服务、稳定会话身份、提示词提交、工作区准备与执行器生命周期，不另建会话目录或直接模拟 tmux 按键。

目标选择

用户意图执行路径
给指定 Codex 发消息严格解析唯一会话 → session_send；不重复确认。
某项目里的 Codex查项目 ID → roami project sessions ID --json → 项目范围查询；完整分页，不能用前三条卡片判断没有会话。
多个合理候选ask_user 提供 2–4 个可识别选项；选择后继续原派活意图。
在已有项目新建任务delegate(project) → 后台准备工作区 → CLI execution launch。
新散任务 / 新项目delegate(new_session / new_project)；使用已知目录，或项目创建服务。仅在用户意图包含新建时新建。

完成证据

session_send 的 delivered 只证明提示词已提交；旧会话没有任务回调时返回 executionTracked=false，不能假装任务完成。delegate 的初始回执仅表示入队；由执行器的启动、进度、报告推进真实状态，结果回原始 Main。失败照实显示；未知写入结果不自动重试、不另建会话规避。

唯一 Main 的保存

Python schema 7 新增 main_conversations：owner_id 唯一绑定 conversation_id。单 writer 事务选取该用户最早的非子任务历史对话；没有则创建。并发请求与刷新返回同一 ID，后续不随最后活跃记录跳转。历史数据保留，不合并、不删除；带历史定位的链接只读。应用入口不再创建第二个 Main，后台任务仍拥有独立内部执行上下文。

可观察与验收

工具调用和执行器事件逐条推入主对话 SSE，展示类型、目标、时间及真实状态。验证包括：同名会话选择题、项目内第 4–6 个会话仍可发现、原会话直接投递、新项目后台启动、并发唯一 Main、重载后的身份稳定、CLI 失败与未知结果；隔离测试不得向正在工作的生产 Codex 输入自检指令。
