四层边界

  1. 技能：内置 roami-dispatch，复杂派活时通过 skill_read 按需加载；稳定指令只保留授权、目标解析与结果真实性规则，避免每轮灌入 CLI 手册。
  2. 结构化工具：target_search / target_resolve、session_send、delegate、task_status、ask_user。Main 无需开放任意 Shell。
  3. Python 适配：以 argv 调正式 roami CLI；写入载荷走 stdin、工具调用 ID 派生幂等键。排除模型密钥环境变量，限制超时与返回体。
  4. Go CLI：复用既有项目服务、稳定会话身份、提示词提交、工作区准备与执行器生命周期，不另建会话目录或直接模拟 tmux 按键。

完成证据

session_send 的 delivered 只证明提示词已提交；旧会话没有任务回调时返回 executionTracked=false，不能假装任务完成。delegate 的初始回执仅表示入队；由执行器的启动、进度、报告推进真实状态，结果回原始 Main。失败照实显示；未知写入结果不自动重试、不另建会话规避。

唯一 Main 的保存

Python schema 7 新增 main_conversations：owner_id 唯一绑定 conversation_id。单 writer 事务选取该用户最早的非子任务历史对话；没有则创建。并发请求与刷新返回同一 ID，后续不随最后活跃记录跳转。历史数据保留，不合并、不删除；带历史定位的链接只读。应用入口不再创建第二个 Main，后台任务仍拥有独立内部执行上下文。

设置页能力管理

设置 → 智能体独立列出模型与连接、技能 Skills、工具与 MCP。技能显示来源、内容版本与原文，支持停用读取；工具显示 Main / 后台角色、读写类型与参数，支持逐项启停；MCP 展示已配置连接的实际观察状态。节点级开关写入 agents/capability-settings.json，0600 原子替换，成功落盘后才切换运行策略。新一轮工具目录剔除停用工具，已有上下文中的陈旧调用仍在执行入口校验；delegate(session) 同样遵守 session_send 开关。已经发出的操作不被开关取消，技能文本若已进入历史也不自动擦除。技能与工具采用卡片、搜索、启停开关和详情弹层；工具参数与技能原文按需展开。上传 Skill / 导入工具入口预留：GET /api/agent/capability-imports 返回契约，POST /api/agent/capability-imports/{skills|tools} 当前明确返回 501 CAPABILITY_IMPORT_RESERVED，不落文件、不执行。MCP 编辑与实际安装仍从节点配置加载，界面明示边界。

共享模型连接与联网检索

模型与连接只保留一份 Base URL / Key，Main 与原生后台各选模型。旧的分角色保存格式仍能读取；用户保存共享连接时迁移 Main 的凭据，清除重复角色连接，空 Key 保留现有值。专业 CLI 的独立认证不受此配置覆盖。

Main 提供 capability_overview 发现实际可用能力；web_research 将联网问题直接交给无代码工作区的原生后台任务，不要求新项目或 Codex。内置 web-research 技能按需加载，后台仅可读取本技能、打开任务自有标签、观察和导航，执行入口再次校验。实际网页观察记录、抓取时间与来源 URL 必须随结果返回；只读检索验证后直接回 Main，无需手动验收；失败、阻断与未知状态照实回报，检索记录不等于金融事实验证。
