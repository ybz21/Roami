async def run_turn(turn, cancel):
    lease = await turn_store.claim(turn.id)
    plan = await context_builder.build(turn, lease)
    while budget.allows_next_round():
        request = provider.build_request(plan, cache_policy)
        async for event in provider.stream(request, cancel):
            await recorder.persist_then_publish(event)  # delta 批量提交
        calls = validate_complete_calls(recorder.assistant_message)
        if not calls:
            return await turn_store.complete(turn.id, lease.epoch)
        results = await tools.execute(calls, budget, cancel)
        await recorder.append_tool_results(results)
        if only_delegate_receipts(results):
            return await replies.complete_with_receipts(turn, results)
        plan = await context_builder.continue_after_tools(turn, results)
    await turn_store.finish_with_budget_reason(turn.id)

Model Adapter 的职责

  • 只接受规范化的 ContextPlan；负责 roles、图片、工具调用、thinking / reasoning、缓存参数与供应商错误映射。
  • 将供应商原始 finish reason 转为统一状态；输出截断导致的半段工具参数不能执行。
  • 每次请求保存 prompt_manifest：模型 / endpoint 标识、serializerVersion、工具 / Prompt 版本、引用与 hash、用量。
  • retry 仅对明确可重试的请求失败，并有次数与 deadline 限制；已经展示的 partial output 不能在同一消息中重放出重复前缀。
  • 模型 / endpoint 切换产生新的 cache / 能力边界；先验证图像、工具与上下文支持。未知用量保持 unknown，不能记为 0。
  • API key 只从运行配置的 credentialRef 解析，不进聊天、记忆或任务简报。

并发与中断

一个 branch 只有一个写 actor，用户消息队列优先于完成回报队列。Main 预留模型并发槽，后台 Worker 有独立配额。模型网络调用 async；阻塞驱动、SQL 与文件处理移到专用线程或子进程，不阻塞 SSE 事件循环。

  • 用户普通追加消息先入库排队；明确停止 / 改变当前要求时在安全边界取消模型请求，保存 partial output，再处理新 turn。
  • 取消模型调用不会回滚已经执行的工具。任务取消与仅停止当前回答是两个接口。
  • 完成事件到达时若 Main 忙，先入邮箱；使用新 revision 决定是否回报，不把子 Agent 原文直接提升为系统指令。
  • memory_search 超过短工具预算时，Main 可说明正在查证并转 Worker；不能为了快就把未验证事实写成答案。
  • Python Worker 的逻辑并发与 OS 进程 Fork 无关；原生子 Agent 从检查点创建分支，权限与预算不扩大。
