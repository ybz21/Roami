正式设计：工具收敛与按需发现

Tool / CLI / Skill / MCP 的职责

Tool：怎么执行

少量调用入口，负责结构化参数和返回。

CLI：能做什么

项目、会话、浏览器等稳定业务命令。

Skill：如何做好

派活与检索的步骤、选择规则和验收标准。

MCP：外部连接

连接配置与工具目录；按需发现、调用。

Go 继续拥有项目、专业会话、节点与统一鉴权；Python 拥有主对话、后台任务、记忆和模型循环。CLI 调用现有服务，不另建一套状态库。

保留 roami-dispatch Skill

查项目下完整会话 → 唯一目标直接投递 → 仅明确新建或没有适用目标时创建；结果回原 Main。更新为 CLI 指令，不继续依赖将移除的专用工具名。

保留 web-research Skill

Main 使用通用 delegate 派原生检索 Worker；Worker 通过 Chrome CLI 获取真实页面、来源和时间。删除 web_research 独立工具封装，不删除网页检索能力。

MCP 通过连接卡片管理，工具目录按需查询，调用走 CLI 适配。当前未配置 MCP，不能宣称已有 MCP 实测覆盖。HTTP 接口也通过注册适配器或 MCP 调用，不默认把每个端点变成一个常驻模型工具。Computer Use 继续保留后续适配边界，不将尚未实现的能力算进现有数量。

Skill 能提供步骤与脚本，不能授予权限；长正文不常驻上下文。默认不追加一堆“可选但全部启用”的工具，也不为精简工具数量额外引入新的代码执行虚拟机。

以上待补名称为建议命名，不能让模型现在照着执行。接入时从统一命令注册表生成帮助，避免 Skill 文案、工具说明与真实 CLI 漂移。

CLI 模式以 argv 调用，不拼 Shell 字符串。现有 session 根命令会透传未知子命令到 tmux，因此不能简单放行所有 session 子命令；必须验证已注册的叶子操作。

源码评审发现的迁移阻碍

  1. 通用 delegate 缺少无代码工作区的模型入口。web_research 内部已用 resourceOnly 资源模式，但 delegate 的模型 schema 没开放等价配置。先补宿主校验的检索 profile，再移除包装工具；禁止因此为普通搜索创建代码会话。
  2. 浏览器封装承载真实执行状态。浏览器身份、租约、观察签名、operationId 和回执应下沉到 CLI / 服务适配，不能直接删掉后裸跑命令。导航超时、未知状态不能显示成功。
  3. 通用 bash 不能只依赖固定副作用标记。在 ToolGateway 记录开始事件之前，由真实命令注册元数据解析副作用、幂等性、权限和超时。不能相信模型声明；也不能把只读查询全部标成写操作，导致又处处确认。
  4. 网关存在工具名耦合。记忆来源、遗忘来源访问限制、任务状态投影，以及 ask_user 等待态需迁移成操作策略。重命名后仍须保留来源约束。
  5. 安装探测遗漏标准路径。现有 exec.LookPath 受 Web 服务 PATH 影响；本机 OpenCode 在 ~/.opencode/bin，服务 PATH 未包含该目录。使用统一探测器覆盖用户标准安装路径、配置命令和版本，卡片展示来源与时间。

已核对本机 Claude Code、Codex、Pi、OpenCode 命令均有安装路径。安装、登录、可用能力与额度是不同状态；额度未知不能显示“未安装”，安装成功也不能冒充登录可用。复用已有插件探测与额度采集，避免三套实现相互矛盾。

HTTP 请求收到响应不等于业务成功：4xx / 5xx、工具报告失败和无法确认结果都应分别映射。未知写操作先查回执，不自动重试造成重复派活。

设置页如何展示

基础工具

展示 read、bash、edit、write、tool_search、delegate、ask_user，并标明当前角色实际可见数量。某个 CLI 业务命令不再占一张工具卡片。

Roami CLI 能力

按项目与会话、浏览器、任务、记忆、提醒分组展示帮助和可用状态。它们是能力目录，开关由对应能力策略控制。

技能与 MCP

Skill 独立卡片显示简介、版本和来源；MCP 显示连接、工具数量、最近检测和展开目录。继续保留上传接口位置。

专业智能体

Codex / Claude Code / OpenCode / Pi 各自展示安装版本、登录、执行能力、额度来源与采集时间。检测入口可主动刷新。

过程消息显示业务动作名称，例如“查询项目会话”“向 Codex 投递”“读取网页”，同时保留底层 bash 调用信息。每次调用保留 actionType / target / startedAt / endedAt / status / taskId / operationId，按发生顺序实时推送。进行中、成功、失败、取消、未知分别呈现，历史事件保持兼容。

迁移顺序与验收

  1. 先修已有探测缺陷。共用安装探测，覆盖服务 PATH 不含 OpenCode 的情况；登录与额度未知独立展示。
  2. 补齐 CLI 和契约。完善检索 profile、查询分页、任务 / 记忆 / Skill 入口，注册逐命令副作用及执行回执。业务状态只保留原服务一份。
  3. 接入基础四工具、tool_search 和角色工具目录。旧工具保持历史渲染；新会话按配置逐步切换，清理 Skill 中旧工具名。只有新路径实测通过才移除旧模型入口。
  4. 删除重复包装并收拢设置卡片。移除 web_research 等独立工具 schema，保留 Skill、CLI、资源状态机和过程消息。
验收场景通过标准
已有项目中向 Codex 发消息先列完整会话，唯一目标直接可靠提交；没有多余确认或重复会话。
候选冲突 / 明确新建冲突用选择题；明确新建只创建一次并关联原 Main。
普通联网问题原生检索 Worker 不占代码工作区；真实网页来源、时间、流式过程和回报均可追踪。
工具数量Main 默认 schema 为 7 个（基础 4＋搜索 1＋编排 2）；Worker 采用显式 profile；新增 Skill 不增加常驻工具数量。
记忆 / 提醒 / 产物现有功能可达；召回来源、提醒幂等、有界读取与图片能力不回退。
失败 / 未知 / 历史失败不标成功，未知不自动重试；旧工具事件可渲染。
桌面与手机能力分组清晰；真机触控、选择题、滚动和过程展开全部通过。
已确认方向：采用 read / bash / edit / write 基础四工具，加 tool_search 搜索 Skill 与 CLI，保留 delegate / ask_user 编排工具的方向。本次用户修订已同步正式设计 15 模块；生产接口及工具开关尚未迁移。
