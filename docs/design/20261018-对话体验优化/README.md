# 对话体验优化

2026-10-18。现有主对话的功能入口较分散、按钮边框过多，本次按用户要求完善真实页面。

- 阅读区：统一阅读宽度，用户消息使用轻量气泡，回复保持开放排版；复制和保存记忆降为图标操作，支持回到最新消息。
- 输入区：复用 `.tt-composer`、`.tt-cbar`、`.tt-pill` 和 `.tt-send`；正文输入、附件预览和底部控制条组成一个输入卡。
- 常用入口：“＋”菜单添加文件、压缩上下文；命令面板支持键盘选择；使用“对话 / 交办任务”按钮切换实际发送方式，保留项目和 Codex / Claude Code 选择。
- 附件：选择、拖放或粘贴后上传到当前用户的私有 ArtifactStore，待发送区可移除，发送后可下载。文本、代码和 PDF 提供有界内容摘录；图片仅在 Main 明确声明支持图片时进入视觉请求。解析失败和能力不足会明确显示，不将文件名当作已读取内容。
- 连贯性：上传不产生模型调用、不隐式提交消息；正文和附件一起进入同一条幂等消息，切换会话保留草稿。原始附件不覆盖工作区文件。
- 手机：沿用顶栏和四个底部导航，控制条保持触控命中区，验证键盘、横屏、菜单滚动和附件卡片。

参考：[ChatGPT 输入框附件菜单](https://help.openai.com/en/articles/20001052-using-library-to-manage-files-in-chatgpt)。视觉和间距遵守仓库 Web 设计令牌；本次不改变已批准的 Agent 执行架构。

- 模型与配置：聊天“＋”里搜索、手输或选择主模型；系统设置 → 智能体 → 智能体设置，分别配置 Main / Worker 的 Base URL、API Key、模型和读图能力。支持测试未保存配置并获取模型列表。空闲时原子应用，忙时保留当前任务并提示稍后重试；换服务地址时不沿用旧密钥。密钥保存在实例私有文件中，接口不回传，重启自动加载。
- 验证：使用独立实例与模型夹具验证模型切换确实影响下一条请求、草稿保留、压缩入口、附件内容进入请求、设置保存与刷新；另做 Android 真机触控、键盘和横竖屏验收。实际模型可用性仍取决于服务商及账号权限。

## 部署试用反馈修正

模型名称移入输入卡底部，提供直接切换入口；手机将发送方式合并为菜单，长草稿最多展示五行，输入框外不再重复显示模型。保留加号里的模型入口。

首个文本片段立即持久化并发送，其后仍按有界批次落盘；SSE 建连立即输出注释帧并禁止中间层转换。服务停机给长连接设置有限退出时间。Main 在查询目标前先简短回应，减少无关记忆检索，委派参数明确定义合法目标种类，防止模型反复尝试无效目标。上述调整延续原设计的快问快答和持久化事件流，不修改任务成功判定或原始历史。
