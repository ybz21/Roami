统一对话界面 · 2026-10-25

产品设计

首页、Codex、Claude Code 与本地子智能体使用专业会话的消息气泡、工具行与输入卡。文字区、底部工具条、圆形发送／停止按钮、字体、留白与命中区共用组件和样式。工具条左侧提供添加与模式，右侧提供模型、已有语音功能与主动作；窄屏可换行，主动作始终可达。首页保留对话／任务选择、项目、执行器、模型与推理强度；专业会话保留真实权限模式、模型、文件和终端控制；子智能体继续原任务，任务详情、产物和关闭放在添加菜单。

用户故事

  • 用户在四类对话间切换时，输入、发送、停止和查看输出的位置与样式一致。
  • 用户在首页直接选择对话或任务模式，并保留项目、执行器、模型、附件与排队；专业会话的权限与模型继续由原 CLI 确认。
  • 手机用户使用 Enter 换行、可见按钮发送，输入法确认候选词不误发；失败保留草稿，弹出键盘后所有动作可点。

技术设计

chat/ConversationComposer.tsx + conversation.css
  文本区、附件／提示／选项插槽、统一工具条、发送／停止与键盘规则
  ← AgentChat / ChatShell（Codex、Claude Code、OpenCode）/ NativeSession
chat/Message.tsx
  共用正文、气泡与复制，开放消息附加动作
  ← AgentMessageView（首页提问、附件、记忆与已读标记）/ NativeConversation / 专业会话
ComposerPlus / AgentComposerPlus / AgentModelPicker
  继续承担各自真实配置与接口，只统一触发控件和锚点

网络请求、草稿、排队、附件与提交协议留在原控制器；公共输入组件不调用服务端。移除首页和本地会话重复的输入卡样式覆盖，布局只走 useLayout。验证覆盖中文输入法、手机 Enter、发送失败、停止两阶段、模式／模型操作、队列与消息已读，以及桌面和 Android 真触控、键盘和返回。
