# 项目里的 OKR：创建、聊天搭建与运行

2026-11-12，设计提案。此稿更新此前 Studio 的进入方式；不改变已经停止的宣传项目，不启动成员、日程或发布。历史设计保留为历史，以下产品流程优先于旧入口方案。

[可点击原型](project-creation-flow.html)。原型使用本地示例，无真实模型、文件写入、派工、账号或定时调用。

## 产品设计

OKR 是项目的一个 Tab，与会话、文件等同级；不在左侧单列 OKR 或展开整组成员。左侧保留项目入口，通知、搜索和旧链接准确落到项目内原 OKR/原消息；现有会话的关联与历史不能因隐藏入口而删除。一个项目的工作根目录不改变。

Tab 没有 OKR 时显示一句空态和“创建 OKR”。已有 OKR 显示名称、周期和真实状态的平面列表，打开原工作台；“创建 OKR”仍可见。架构支持同项目多个 OKR，但当前按 projectId 单例的宿主必须先完成独立 okrId 迁移；不能在同一 projectId 上循环 save 假装创建多份。第一阶段尚不支持多份时，已有实例只显示“打开 OKR”，新增按钮明确受能力约束。

### 创建与搭建

1. 点击创建即进入项目内草稿，只有一句“你希望团队完成什么？”和统一输入框。用户描述目标，可选模板起步，不要求先填 O/KR、Connector、目录和团队表单。创建草稿不启动任务。
2. 同一专属 Main 在整个生命周期连续工作：聊天澄清必要目标与周期，使用 okr-development Skill 在隔离草稿复制完整 assets，组合模板，再产出目标、实施手段、看板、取数 Skill、团队与记忆约定。现有用户原文保留，不能把生成文件拼成新授权。
3. 桌面聊天居中，右侧按需打开“预览”；预览只有“目标 / 看板 / 团队”，切换不丢草稿。聊天里用简短变更结果呈现生成过程和失败原因，完整过程复用首页工具渲染。手机预览为全屏二级页，返回恢复原输入与位置。
4. 角色在“团队”中编辑：名称、职责、Agent、状态。默认只列这四项；打开某一角色后再看 Skill、记忆目录、依赖与当前实例。用户可以继续用聊天改，不必两处重复填写。Main 固定为本 OKR 的独立 Roami 协调实例，首页 Main 不是此实例。成员 executor 与模型选择分开，不能用 Agent 下拉悄悄改全局模型。
5. 用户点“开始运行”才激活所确认的范围；若缺账号或 Agent，指出具体角色及“配置 / 换 Agent / 稍后运行”，保留草稿，不启动半套团队。只有配置已保存且读取核对、团队身份已绑定、当前用户目标和权限已确认，才允许提交首批任务。
6. 点击后显示“正在启动”，逐成员展示真实启动/阻塞；只有目标激活与派工回执不算运行成功。进入原 Main 聊天，在工作台看任务、工具过程与真实结果。日程默认关闭，用户明确要求自动运行且确认时间/时区和动作范围后才启用，不另加逐条人工审批。

运行态默认“对话”，收件对象顺序为群聊、Main、成员。用户主要跟 Main 说话，由 Main 派给原成员；群聊、单聊的当前收信目标在输入框上方清楚可见。成员对话复用对应原生 Agent 的渲染与终端两种视图。看板仅显示数据；文件和团队记忆从文件入口查看。右侧任务列表与团队视图切换，可拖宽、关闭后归还空间。开发编辑作为次要动作“调整”，回到同一 Main/草稿，保留运行版本，确认变更后生效。

## 角色和 Agent

| 身份 | 选择 | 约束 |
|---|---|---|
| Main | 固定专属 Roami Main | 一个 OKR 一份持久身份；与首页及其他 OKR 隔离 |
| 执行成员 | Codex / Claude Code / OpenCode / Pi / Roami | 从宿主 capability/catalog 读取可用性，不假装已登录或工具验证通过 |
| 模型 | 沿用该执行器当前配置 | 如需覆盖，单独明确展示并授权，不写全局路由 |
| 长期职责 | 用户命名、可增删 | 不写死 X/B站/数据；模板只建议数量和职责 |
| 接续 | 原 member/task/provider，新的执行轮次 | 不每轮建实例；失效先可信恢复，未知先对账 |

“已安装 / 登录待核验 / 已验证可执行 / 运行中 / 受阻”是不同状态。选择 Agent 不代表获得浏览器、手机、MCP 或发布权限。切换已运行成员 Agent 需要说明是执行器迁移，冻结原任务、确认停止、保留历史和个人记忆，再绑定新实例；不得覆盖原 provider。示例里的角色和 Agent 选择不是通用产品默认值。

## 用户故事与异常路径

- 我从已有项目创建 OKR，说需求就能拿到完整方案；刷新后回到原草稿和 Main，不重复建实例。
- 我用聊天补一句“数据分析用 Claude”，团队预览更新，缺少登录或工具验证时看到真实提示，不更换其他成员。
- 我先看目标和看板再运行；确认前没有平台发布或定时任务。
- 我停止后，定时和续派都停止；返回“调整”不会自动恢复，运行按钮应是明确的“恢复运行”。
- 保存冲突保留本地草稿，读取新版本后合并；不清文件或确认状态。启动超时先查询原请求，不换 key 再发。
- 部分成员启动失败，展示真实成员状态和恢复入口；不把全部团队涂成成功。未知状态禁止自动重建。
- 离开、切 Tab、手机返回都保留输入；空态、错误、加载和无权限有短文案与下一步。

## 技术设计

### 复用与模块边界

- Projects.tsx 与 MobileProjectDetail.tsx 共享项目 Tab 定义；新增 OKR 子路由，旧 /projects/:projectId/okr 链接继续解析。导航树不再插入 OKR 专用根项/成员，普通项目会话功能不受影响。
- ProjectOkr 作为项目内部工作台；抽取 OkrProjectEntry（空态/列表）、OkrDraftWorkspace（同 Main 聊天+预览）、OkrReadiness（实际能力/权限/确认版本）、OkrActivation（启动/恢复状态）。名称为建议，落地前对照已有模块。
- Main 对话、输入框、工具过程、消息流和停止动作直接复用首页组件；成员复用 NativeAgentChat/原生会话入口及当前真实身份校验，不另写只返回最终正文的聊天实现。
- 创建/搭建/运行不共用一个 boolean：draft → building → ready → starting → running；paused、blocked、failed 独立保留原因。文件生成与执行结果分别存证。预览模型只投影当前草稿，运行态读取确认版本。

### 身份、文件与数据

当前仓库以项目为作用域的 OKR 单例不能直接支撑同项目多 OKR。新增 owner/node/project/okr 复合身份、唯一 Main/Swarm/成员映射与目录绑定；旧实例迁移为默认 OKR，保留原 Main、team、provider、delegation、日程、消息和全部证据 ID。旧 URL 指向默认实例，不隐式创建。新增多份能力只有迁移、访问控制与回读接口完整后开放。

建议新实例目录 .roami/okr/workspaces/<okrId>/，默认实例保留既有 .roami/okr/；目录由宿主记录，不能让调用方传任意路径或通过更改 cwd 混淆项目。项目根 AGENTS.md 保存通用协作约定，实例 AGENTS.md、O/KR、dashboard、connectors/<skill>/、agents、memory、schedules 和 data 放在本实例包。资产仍从 skills/okr-development/assets 完整复制，再组合 parts/templates，不复制凭据、观测样例或实例 ID。

看板继续采用 HTML/组件定义加宿主只读数据桥；Connector Skill 可以用 Python/MCP，源数据 SQLite 与已确认指标分离。候选只有原 Main 独立核验并 record 后进入看板。构建预览不能写生产 observations/current 或清空旧数据。多 OKR API/SQLite keys、Connector batch、日程 key、通知、收信和缓存全部加入 okrId，禁止只靠页面筛选隔离。

### 创建与运行契约（拟议，不能当作已有 API）

1. 创建请求带 projectId、requestKey，宿主在事务中创建草稿与唯一 Main 绑定；失败不能遗留第二个 Main。重试返回原身份。多 OKR 服务未就绪前不开放同项目第二份。
2. 构建轮次沿用同 Main，文件草稿含 expectedRevision；可流式显示工具过程，最终按真实文件差异生成预览。
3. readiness 读取本机 executor、工具/账号实际验证、角色依赖和当前确认范围；不能根据安装目录或注册回执宣称执行可用。
4. 激活请求绑定草稿版本、当前用户目标来源、确认配置 hash、delegation 和 requestKey；拒绝陈旧草稿、跨 OKR 身份、已暂停后未经用户恢复及未知原任务。
5. 首批任务在保存与绑定成功后提交，返回每个成员的真实状态。重复请求不重复派工；重启后查询原批次继续，不能重放未知外部动作。
6. 停止先封闭新派工与日程，再取消本 OKR 当前任务和 Main 回合；未获可信停止回执显示取消中。页面离开或调整草稿不能解除停止。

### 分批实施与验收

A. 项目入口、空态和旧链接兼容，原实例不变；B. 聊天草稿、完整 Skill 包和目标/看板/团队预览；C. readiness、确认与首批启动/停止；D. 多 OKR 完整作用域迁移和长运行接续。每批独立 PR，不把原型演示记作代码交付。

交互验收：项目Tab进入、创建、发送需求、改角色Agent、预览、返回保留草稿、缺能力受阻、开始/停止/显式恢复、重试不重复、旧链接定位原会话。覆盖1280/1920/2560/3440桌面、右栏开关和手机布局；真实Android触控需在允许手机操作后单独验收。隔离运行实例验证身份、并发创建CAS、跨OKR访问、错误恢复与日程不串项目；不触当前已停宣传任务。
