④ 守护200 开关 + 两行状态：第一行是态（守护中 / 未守护 / 已停手），第二行是最近发生了什么 开关和它的后果必须挨着。把「催过 2 次」拆去别的列，人就得左右对

固定列合计 28+96+200+176 + 4×12(gap) = 548，加上 ② 的下限 260 → 这张表的最小可用宽度是 808px。插件详情区在 1440 下约有 1100px，宽裕； 窄于 1100 时把③并进④（「安静 41 分钟 · 3 分钟前催过」），窄于 900 直接换手机卡片（§07）。

行高 52px，两行文本

一行 32px 只塞得下名字，目录就得丢——而目录是认人的那一行。 52px = 名字（--fs-body/20）+ 目录（--fs-micro/16）+ 上下各 8。 一屏（760px 的详情区、去掉横幅句子和过滤条约 450px）能看见 8 行， 正好是本机会话数的中位数——常见情况下不用滚。

颜色只用三次

绿=刚刚催过（且只亮 5 分钟）、暖=安静超阈值、红=已停手。 其余一律是中性灰。守护中的行不整行染绿——十行全绿等于没有重点， 而这张表真正要你看见的是那一两行出事的。

未守护的行不做灰化处理

它们是候选，不是禁用项。压暗会让人以为「这些不能开」， 而这一页一半的价值恰恰是让你从这些行里挑一个打开。

开关就是全部操作

点开关即刻生效，没有保存按钮，没有确认框。回执是那一行右边的状态字当场改写—— 眼睛在那一行上，反馈就该出现在那一行上，不在屏幕角落弹 toast。

3.1 默认全关，而且只能手动开

装上插件 ≠ 开始守护

builtin 插件默认启用，但守护表是空的：一行开关都不会自己打开。 插件启用只意味着「这一页能用了」，不意味着有任何会话正在被催。 第一次进来看到的是一整列灰开关（§07.4 空态）。

新会话也不会自动进来

点过一次「全部守护」之后再新建的会话，仍然是关的。 没有「以后新建的自动守护」这个选项，下拉里那一条是灰的、写着「不提供」。 每一条守护都必须有人亲手打开过——因为每一条都会替你花钱、 往你的会话里写东西。

所以「全部守护」不是主按钮

它在横幅右端，是个普通幽灵钮，排在「发送记录」「守护语规则」后面。 主路径是在列表里挑一个、打开它右边的开关——一次开一个， 你清楚地知道自己开了谁。批量只是给「我就是要全守上」的人一个不用点十下的出口， 而且带确认。

04排序与过滤

默认排序不是按名字，是按「该管谁」：守护中的在前，同组内按安静时长倒序。 最该被你看一眼的那行永远在第一行。

组顺序理由
1 · 已停手置顶出事了。它是唯一需要你做决定的一类
2 · 守护中按安静时长倒序越久没动静越靠前
3 · 未守护Agent 在前，再按安静时长倒序下一个可能要开的就在这一档的顶上

「安静了」那一列的列头可点，切换成纯按时长排序（跨组）。只有这一列可排序—— 再多就变成一张需要学习的表。

过滤条：会话 > 8 个才出现

本机常年 5~8 个会话，给一条常驻的搜索 + 分段筛选纯属占地方。 超过 8 个才渲染，且分段的三档各自带计数（全部 9 / 守护中 3 / Agent 6）—— 没有计数的筛选器，用户点进去才知道是空的。

5.1 为什么默认不是「继续」

✗ 「继续」

它不给 Agent 留台阶。一个真的已经干完的 Agent 收到「继续」， 最常见的反应是去找点事做——翻出一个无关的改进、再重构一遍刚写好的东西。 你本来只想确认它还活着，结果换来一次计划外的改动。

✓ 「你是不是已经完成了你的任务？没有完成，那么继续。」

它先问后推：干完了就回一句「干完了」，没干完才接着干。 对停在等待态的会话，效果和「继续」一样；对已经收尾的会话， 它换来的是一句交代而不是一堆新改动。所以它是默认兜底语。

5.3 三个约束

换行会被折成一行

守护语经 paste-buffer 打进 TUI，而在 Claude/Codex 的输入框里换行即提交 ——多行文本会被拆成好几次输入。所以宿主侧的 session.send 统一把 \n 折成空格。输入框里可以敲回车（那是保存）， 但别指望守护语能分段；真要发长文，那是定时任务插件拉 Agent 的活。

上限 500 字

它是「一句话」，不是一篇 prompt。超了就在计数器上标红并拦住保存， 不截断——悄悄截掉一半的句子发出去，比不让保存糟得多。

改完下一轮生效

守护语落插件私有 storage，常驻循环每轮重读（设计稿 §10）。 失焦即存，≤30 秒后下一次巡检用的就是新的，不用重启任何东西。 句子本身就是回执，不另弹提示。

5.4 越界当场拦住

三个数字输入 0 或 9999 时，输入框转红并在下方一行小字说清区间 （1–1440 分钟），不静默夹值——静默夹值会让人以为自己设成了 0 而实际跑的是 10。 Esc 撤销回原值。

07「全部守护」展开的样子

它是个下拉而不是直给的按钮：直接一键把所有会话都守起来，是个会花钱的动作， 必须先让人看见「守哪些、跳过哪些」。

守护全部 Agent 会话6 个里有 4 个还没守 · 跳过 3 个认不出是 Agent 的 连非 Agent 会话也守9 个全守上 · 往裸 shell 打字会得到 command not found
以后新建的会话自动守护不提供 —— 每一条守护都得你亲手打开
全部取消守护3 条守护停用 · 配置留着，随时可以再打开

选完弹确认，确认文案说的是结果而不是问句： 「将开始守护 4 个会话，跳过 3 个（认不出是 Agent）。它们安静 10 分钟就会各收到一句『继续』。」 ——用户要确认的是这句话，不是「你确定吗」。
