# 首页执行链路追踪

状态：设计已自审并实施，PR 与部署验收进行中。关联 #330、#350；简短回报单独在 #351 实施。

## 要解决什么

用户需要回答：这句话是否送到、当前等在哪里、谁在执行、为什么慢、结果在哪里。
首页三点菜单增加「链路追踪」，按一次用户请求串联主会话、模型、工具、任务执行和最终回报。
已有 Python 执行追踪数据是第一期事实来源；不把未采集的 Go 入口、浏览器绘制或专业执行器内部过程伪装成已测量的链路。

## 怎么看

1. 打开首页三点菜单，进入「链路追踪」，先显示请求列表，选中后才读取链路详情。
2. 看时间线中最长或尚未结束的阶段；展开查看耗时、状态、模型、任务与错误。排队和接收指令都不等于完成。
3. 若还没开始，切到「队列」；若模型慢或上下文大，切到「上下文」。复制链路 ID 或导出 Chrome Trace / Perfetto JSON 继续分析。

界面只保留「链路 / 队列 / 上下文」三个页签；上述说明收在「怎么看」里，默认折叠。
首次进入空页面只显示一条简短空状态，不放大段技术说明。

## 页面与导航

- 首页桌面与手机均通过同一三点菜单进入，图标用现有 MoreIcon，按钮有 aria-label。
- 手机用 URL 支持的整页二级页面、一根返回栏、一个滚动容器；沿用 MobileSubPage，不能重复叠加 overlay history。
- 桌面展示请求列表与阶段详情；手机先请求列表，选中后展示纵向阶段树，系统返回恢复选择和滚动位置。
- 用 useLayout、现有设计 tokens、i18n；触摸目标至少 44px。无常驻刷新按钮，打开时按需更新，关闭后停止轮询；浏览器刷新和手机下拉刷新仍可用。
- 时间范围 15 分钟 / 1 小时 / 24 小时仅筛选历史，不是执行截止时间。仍在排队或执行的请求独立列出，不能被时间筛选隐藏。

## 链路

根节点为原始用户 turn；任务子树、原生 worker turn 和 completion turn 通过已有因果关联连接，不按时间相邻猜测。
阶段展示已有数据中的 context、model.request、tool、executor、Main report。队列等待必须用服务端同一时钟的创建/开始时间计算。
每个节点显示名称、状态和耗时；展开显示完整 ID、角色/模型、首 token 时间、错误码以及采样来源。
明确区分实测、历史推断、未知；未结束阶段展示「进行中」，专业执行器内部标注不可见，不能给虚构百分比。
点击任务打开现有任务详情；成果展示已验证的文件、页面、PR 链接，不从总结文本猜造路径。

现有 GET /v1/traces 支持 turnId 或 taskId，复用其 owner 校验、原始根回溯、跨度和 Chrome Trace 导出。
前端下载需要解开 API data 信封。导出不包含完整 prompt、响应、工具原始参数、密钥或本机待发送消息。
现有 trace 节点/跨度读取上限属于调试查询保护，不得中断真实任务；超过范围要明确提示查询受限，不能让用户误以为任务执行已停止。

## 队列

分别展示：

| 队列 | 来源 | 展示 |
| --- | --- | --- |
| 此设备待发送 | 浏览器 outbox 的只读订阅 | 顺序、等待/发送中/未确认/失败，不上传草稿正文 |
| 服务端会话 | 当前 owner、conversation、branch 下的 turn/job | 创建时间、等待时长、触发类型、当前状态 |
| 后台任务 | 已关联任务与调度状态 | 排队/运行、执行器、任务链接、并发槽位 |

不得第二次挂载 useAgentOutbox，否则会产生第二个发送器。给现有发送器增加只读快照订阅，发送中状态不从 localStorage 重新解释。
无法确定等待原因就写「等待执行」，不能把并发排队说成失败或时长限制。队列收据不是完成证据。

## 上下文与限制

分开显示「当前会话上下文」和「选中模型请求」。前者由 context projection 获取，后者来自请求时保存的 manifest；不能用当前配置冒充历史配置。
展示窗口容量、估算输入、实际 usage（如有）、输出预留、压缩阈值与 snapshot/epoch；未采集的字段写未知。
branchId 必须传给上下文读取并验证归属。执行超时 0/None 显示「不限」，正值显示显式配置；历史未记录时显示未知。
不在此页面渲染全文 prompt，不触发模型推理、任务重试、队列发送或任何写入。

## 数据接口与性能

新增只读 debug projection：作用域明确到当前节点、owner、conversation、branch；返回请求列表、服务端队列和当前上下文摘要。
历史分页默认 50、最多 200；活动队列独立分页，返回总数及截断标记，不默默丢弃旧的活动项。
复用 trace detail 接口，进入或展开时才读详情；仅可见页面 2–3 秒按需刷新。关闭页面不发送 debug 请求。
作用域、缓存版本与关闭订阅防止切换节点/分支后的迟到响应覆盖新页面；允许共享缓存中已经发出的只读请求完成。缓存键包括 node、conversation、branch、turn。
调试字段采用白名单，所有 owner 和资源归属校验在服务端完成，不依赖前端传参可信。
