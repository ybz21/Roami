# 设计评审

方式：基于现有 execution_traces、prompt_builder、context projection、mailbox、outbox 与手机导航实现进行自审。此表是实施前自审；运行验收另外记录，不能把设计评审当作运行通过。

| 级别 | 问题 | 已修订的决定 |
| --- | --- | --- |
| P0 | 本机 outbox 和服务端队列混合会误报已接收，重挂 hook 可能重复发送 | 分区显示，只读订阅现有发送器，不重挂发送 hook |
| P0 | 当前上下文/超时配置不能解释历史请求 | 历史使用 manifest；缺失标未知，不回填当前值 |
| P0 | 用户、节点、分支切换可能串数据 | 后端鉴权、完整缓存键、取消请求及迟到响应版本检查 |
| P0 | 专业执行器内部未采集、客户端和服务端时钟不同 | 显式未知，不虚构内部 span，不跨时钟计算延迟 |
| P1 | 时间范围会藏掉长时间排队项 | 活动队列独立查询与分页，不受历史时间范围影响 |
| P1 | 追踪 API 本身有节点/跨度读取保护 | 明示查询范围限制，不能传递成执行失败或取消 |
| P1 | 工具参数校验失败记录为 {}，难以解释重复调用 | 后续记录脱敏结构/字段级问题，绝不导出原始敏感参数 |
| P1 | 默认不限后，大输出仍可能因返回上限导致已写入却报失败 | 完整输出流式落文件，返回预览与真实成果引用，避免无限堆内存 |
| P1 | 基线测题有 12 次模型请求上限，连续两问驱动逆序处理 | 区分测试夹具与产品缺陷；改用真实调度顺序，保留原始失败记录 |
| P1 | 提示词堆详尽过程会拖慢响应、掩盖成果 | #351 单独修复及时分派与简短交付，不用字符串截断隐藏内容 |
| P1 | 手机信息面板变成长弹窗、双返回和横向溢出 | 专用二级页面、单返回栏/滚动、纵向阶段树，真机验收 |
| P2 | 大量技术说明违背简洁要求 | 主视图只有三页签和必要状态，阅读方法折叠，详情按需展开 |

评审结论：以上问题已在设计中给出明确处理方式，可以按 README 的顺序实施。实现后仍需接口、真实模型及真机验收；设计评审不承诺尚未验证的功能已经上线。
