# 团队一键暂停与恢复

## 产品设计

团队页直接显示“暂停工作”，暂停后改为“恢复工作”。桌面协作栏收起、手机主对话均可直接使用。状态区区分正在停止、已暂停、需要核对。旧“暂停派发”仍在更多菜单中，语义保持不变。

## 用户故事

- 项目负责人临时离开时，一次点击停止 Main 和团队正在执行的工作，不清理成员、会话或成果。
- 返回后恢复原任务，排队工作继续，完成的工作不重复执行。
- 外部操作结果未知时，先核对任务详情，不能因恢复点击而重放。

## 技术设计

- `dispatch/swarm_work_control.py`：`pause_work` / `resume_work` 控制，沿用命令回执、团队锁与版本校验。
- `storage/swarm_work_pause.py`：以持久化 `swarm.work.pause` job 保存原任务 ID / revision 和 Main turn；暂停期间保持 queued，恢复完成后 done。不新增轮询和数据库版本。
- 暂停原子地写 fence 并通过已有取消机制停止运行任务树；Main 使用绑定 turn 的 interrupt，以 `control.pause` 区别终止，不撤销长期目标授权。排队任务不取消。任务/turn 的领取及任务修订均检查 fence。
- 恢复经原任务 `TaskRevisions.request` 续接，遵守原执行器、资源释放、未知结果与子任务停止校验；Main 中断后提交显式恢复指令。该英文指令为执行协议提示，与现有任务续接指令一致，产品按钮和状态均中英双语。
- 当前团队工作条目及项目 Main 创建的该项目根任务属于控制范围；子任务递归取消。其他项目不在控制范围。
- 接口只有确认停止后才允许恢复；动作命令与每个续接指令均可重试去重。重放旧暂停不会停止新任务。
