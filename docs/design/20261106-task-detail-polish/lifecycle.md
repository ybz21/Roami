# 任务与对话的生命周期设计

状态：交互提案，尚未接入产品接口。对应用户反馈：任务状态不清楚，缺少进入任务对话、关闭任务、关闭对话和删除对话的完整入口。

[打开可交互原型](lifecycle.html)。原型使用合成内容，所有关闭、删除、发送与下载均为模拟，不调用业务接口。

## Product Design

### 信息架构

任务详情首屏固定顺序：

1. 任务主题、执行器和分支。
2. 明确标注的“任务状态”和“对话状态”。两项始终可见，不靠有无按钮推断状态。
3. 操作区：“进入对话”为主动作，“关闭任务”为次动作，“更多”包含“关闭对话”“删除对话”。
4. 执行结果、可用文件、验收入口。
5. 任务内容、执行记录、下发方式与外部工具。

任务列表只显示短主题、必要任务状态和对话状态；任务详情承担解释与风险确认。任务入口不会因为执行结束而消失。没有创建过对话时显示“对话尚未创建”；已关闭显示“查看对话”；已删除显示禁用的“对话已删除”及保留结果的说明。

### 三种操作的含义

“关闭任务”采用建议含义：结束这项工作，并移出默认待处理列表。运行中先停止执行，再关闭；已完成只关闭工作项。关闭不等于验收通过，不改写成功、失败、取消或未验收的执行事实。

| 操作 | 执行与任务 | 对话 | 任务结果、文件 |
| --- | --- | --- | --- |
| 进入对话 | 不改变任务状态 | 打开对应对话；已关闭则只读 | 保留 |
| 收起对话 / 返回详情 | 不改变任务状态 | 只隐藏面板，不停止、不关闭 | 保留 |
| 关闭任务 | 运行中先停止；已稳定则关闭工作项 | 保留历史和独立继续的入口 | 保留 |
| 关闭对话 | 活跃任务仍依赖它时，确认文案明确说明将停止并关闭关联任务；已结束任务不改写结果 | 停止执行资源，转为只读历史 | 保留 |
| 删除对话 | 不删除任务、不改写执行结果 | 仅在对话已关闭且没有活跃执行时可用；确认后移除历史入口 | 保留 |

“停止执行”是关闭中的过程，不使用成功图标表示关闭。任务列表区分“已完成”和“任务已关闭”；例如详情可以显示“任务：已关闭 · 执行失败”，不会将失败隐藏为笼统的已完成。

已关闭任务的对话如果继续，应走独立会话的消息路径，不再对旧任务调用 steer，也不偷偷打开旧任务。原型模拟了这一行为；实现必须补齐独立对话承接能力，不能只改按钮文案。

### 状态与动作

| 当前情况 | 主动作 | 关闭任务 | 关闭对话 | 删除对话 |
| --- | --- | --- | --- | --- |
| 排队 / 准备中，尚未创建对话 | 对话尚未创建（禁用） | 可关闭并取消排队 | 不可用，显示原因 | 不可用 |
| 执行中，对话可继续 | 进入对话 | 确认停止后关闭 | 确认联动停止与关闭任务 | 禁用，先关闭对话 |
| 待验收 | 进入对话；结果区突出验收 | 可关闭，保留“未验收”事实 | 可关闭，保留未验收事实 | 关闭对话后可用 |
| 已完成 / 失败 / 已停止，对话可继续 | 进入对话 | 可关闭工作项 | 可关闭 | 禁用，先关闭对话 |
| 任务已关闭，对话可继续 | 进入对话 | 显示已关闭、不可重复提交 | 可关闭 | 禁用，先关闭对话 |
| 对话已关闭 | 查看对话（只读） | 按任务真实状态显示 | 显示已关闭 | 可用、危险操作确认 |
| 对话已删除 | 对话已删除（禁用） | 按任务真实状态显示 | 不可用 | 显示已删除 |
| 正在关闭 / 删除 | 保留可读内容 | 处理中，禁用重复提交 | 处理中，禁用重复提交 | 处理中，禁用重复提交 |
| 状态未确认 / 关闭失败 | 保留可读历史 | 明确显示失败原因和重试入口 | 未确认前不可显示已关闭 | 禁用 |

### 操作位置与确认

- 详情顶部的操作区不受结果是否存在、是否已完成影响。不能像旧实现那样仅由零散 sessionId / agentConversationId 条件决定操作是否整组消失。
- 对话头部也提供“任务详情”和同一套关闭、删除菜单，用户不用先退出对话寻找管理动作。
- 菜单中的禁用项保留短原因。触屏不依赖 Tooltip。
- 关闭运行中任务：确认说明“先停止执行，再移出待处理；不会标记为已完成”。
- 关闭仍被任务使用的对话：标题为“关闭对话并停止任务？”，不能伪装成只关闭面板。
- 删除对话：确认说明删除范围、不可恢复及任务文件保留；默认焦点落在取消。
- 取消确认不修改任何状态；提交后显示中间态，服务端确认后再显示已关闭 / 已删除。失败保留上下文和输入。

### 桌面与手机

桌面任务列表、详情、对话构成可伸缩的工作区。打开对话才为它分配宽度；“收起对话”立即释放空间。详情与对话各自滚动，文档不滚动。对话宽度沿用项目专用工作台尺寸契约，不让消息铺满超宽屏。

手机任务详情为全屏二级页；“进入对话”打开全屏对话，用一条返回栏回到原详情。对话中隐藏底栏；返回后恢复底栏和原来的详情滚动位置。顶部操作可换行，关闭和删除不会藏进只靠图标或悬停发现的入口。长历史只有一个滚动容器，输入草稿切换时保留。

## User Stories

1. 我打开任务就能看见它是否还在执行、是否已关闭，以及对话能否继续。
2. 即使任务已经完成，我仍能进入对应对话，或阅读已关闭对话的历史。
3. 我关闭任务后能保留结果与对话，且以后继续聊天不会重开这项任务。
4. 我只想收起对话时，不会误停止任务；我真正关闭对话时，能事先知道关联任务是否会停止。
5. 我能清理已关闭的对话，但不会因此丢失任务交付物。
6. 状态更新慢、请求失败或重复点按时，不会误显示成功，也不会丢失草稿。

## Technical Design

### 当前能力核对

已核对 `AgentTasks.tsx`、`NativeSession.tsx`、`session-actions.ts`、`agent-task-protocol.ts`、`task_sessions.py`、runtime HTTP 路由与 Go gateway 路由。

- 已有 cancel、verify、steer 和 close-session。`TaskSessions.request()` 会针对活跃任务请求取消，close-session 不是纯前端关闭面板。
- 现有 `task.state` 表示执行事实；`sessionClosure` 表示执行会话关闭流程，没有独立“任务工作项已关闭”的属性。
- NativeSession 的发送仍绑定任务 steer；直接保留输入框无法满足“任务关闭后独立继续对话”。
- 当前 gateway / runtime 路由没有通用对话删除接口。不能用隐藏 DOM 或删除本地缓存冒充删除。
- 现有任务对话入口受 retainedSession 条件限制；缺少任务关联的权威入口与可用动作回执，导致状态和操作不一致。

### 数据与接口边界（拟新增，尚未实现）

保留三个独立概念：

- execution：现有 task.state，保留真实执行结果。
- lifecycle：工作项 open / closing / closed，关闭时间、操作者与版本。
- conversation：未创建 / 可继续 / 关闭中 / 已关闭 / 已删除，提供确定的关联身份与是否可读、可发消息。

建议 TaskDetail 增加服务端计算的 lifecycle、conversation 和 actions，不让前端从 latestAttempt 的可选字段猜测权限与状态。actions 返回 enabled、稳定的 reasonCode，以及操作需要的 taskRevision、runId、conversationRevision；前端翻译禁用原因。

新增任务关闭动作需要独立幂等 requestKey 与 revision fence。活跃执行先复用既有取消及资源回收，完成前保持 closing；已完成任务只记录 lifecycle.closed，不覆盖 task.state。关闭失败记录错误，不提前从待处理列表移出。

对话管理统一适配 native 与专业执行器，复用现有 close-session 的资源关闭、子任务回收和身份校验，但将对话可读状态、任务工作项状态分开返回。删除动作需要验证 owner、关联对话、修订、关闭成功且无活跃执行，不能根据前端传入的路径删除文件。Roami 对话数据与执行器原始日志的所有权边界需要在实现时明确；不得宣称已清理第三方执行器的原始日志。

删除不能级联删除任务、结果快照与已交付 artifacts。仍被任务引用的审计记录单独保留必要事件和结果快照；消息查询、搜索、通知、会话列表及续聊入口统一尊重删除标记。重复删除幂等；引用过期或节点切换时拒绝执行。

已关闭任务上的独立续聊需要明确新的运行归属、会话身份与草稿 key，native 与专业执行器均不可继续调用旧 task steer。未实现该适配器前，只能保留只读历史并清楚解释限制，不能上线一个假可用的“继续”按钮。

### 模块划分

- `TaskInspector`：组合任务身份、结果、正文，不再内嵌零散管理按钮。
- 拟新增 `TaskLifecycleActions`：任务 / 对话状态和顶部动作；列表与对话头部复用同一 action contract。
- 拟新增 `TaskConversationPanel`：桌面可选面板、手机全屏路由、只读历史与独立续聊。
- 拟新增 `useTaskLifecycleMutation`：幂等、修订围栏、提交中状态、错误恢复与事件更新。
- Python dispatch：任务关闭工作流；conversation：对话关闭和删除的领域服务；Go gateway 只暴露受权路由，不重复实现状态机。

正常结束的详情仍不轮询，复用 task / conversation 事件刷新。请求结果未知时按 operationId 对账，不自动再次执行删除。可见面板开关和草稿继续复用本地镜像及已加载偏好契约。

### 实现验收要求

覆盖所有表格状态，特别是关闭不等于成功、取消确认、重复点击、修订变化、网络结果未知、工作区未释放、子任务仍运行、节点切换、对话删除后的历史访问和任务文件保留。native / Codex / Claude 路径都需真实校验，不可只使用一种执行器的合成对象代替。

## 原型验收

交互原型是设计验证，不代表上述接口已经落地。原型没有联网业务操作，产品文案仍需实现时按 i18n 标准接入中英文。设计稿中文字是开发评审内容，没有加入产品语言包。

原型直接复用项目 `layout.ts` 的编译输出，图标由 `icons.tsx` 渲染，表面、字号、间距和颜色来自现有令牌。单文件内嵌 runtime 是为了在 Roami 文件预览中离线打开；不作为产品运行时代码。

桌面 1280 / 1920 / 2560 / 3440 的对话打开、收起共 8 组布局已验证无文档溢出。交互验证覆盖关闭任务的确认与取消、关闭后独立发送不重开任务、关闭对话保留历史、删除前禁用、删除后文件与任务状态保留，以及 7 种初始场景。

另验证 320 / 390 / 820 / 1100 窄视口的对话打开、收起共 8 组布局，以及确认框取消、菜单禁用、返回后草稿保留。窄视口为桌面模拟，本轮尚未完成该原型的 Android 真机触控验收，不能作为产品上线验收。
