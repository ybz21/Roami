技术方案

请求放大路径

  1. 工作台探测。 桌面把全部 terms 传给 useTerminalRuntime，手机仅在会话覆盖层打开时传入当前会话。每个 CLI 会话串行查三个提供方，不同会话并发，每次启动立即查。terms 依赖 sessIds，后者随概览数据变化重新构建。即使会话名完全相同，数组引用改变也会重启探测和标签抓屏。固定间隔的慢请求可能重叠。运行时轮询 · 会话索引 · 标签集合
  2. 抓屏。 TerminalPane 每 4 秒给所有 CLI 标签读取 50 行，标记等待和恢复状态。工作台折叠时 Workspace 仍保留终端坞的子树。终端 PromptDialog 和对话 PromptPanel 分别走 1.2 秒抓屏，隐藏的对话仍挂载提示组件。仅可见且需要实时输出的对话还可触发 LiveTail 的 40 行、800 毫秒周期。项目详情在每 5 秒刷新树和注解后重建 cliMine，可能提前重启 6 秒的逐会话探测，已展开工作区另有 8 行尾行预览。终端面板 · 交互提示 · 项目详情
  3. 转录。 各实例单独保存游标并安排下一次请求。active=false 只把下次间隔改为 6 秒。现有轮询没有文档可见性暂停、取消或失败退避。工作台与项目原生 Main 可经不同入口渲染相同 CLI 会话，截图里相同参数与这种机制相符，实际发起方需看 Initiator。增量读取 · 执行器对话入口

状态接口会执行 tmux 查询并遍历进程树，命中 Claude/Codex 时还要定位转录，命中 OpenCode 时会抓屏并查 SQLite。capture 经会话 CLI 读取 tmux 屏幕。带 boff=1 的 Claude 转录使用字节游标，重复调用仍会过鉴权、文件定位或打开与读取。浏览器请求数和服务端工作量都需要测量。Claude 与批量探测 · Codex · OpenCode · 抓屏入口

实施顺序

一 · 共享状态并收窄 Agent 详情

工作台、独立会话页和项目详情共用 useAgentKinds 与 useSessionOverview。前者给进程种类，后者给活状态，running 表示正在响应。项目详情用概览的 waiting 和 tail，展开预览需要完整尾行时再按需取。先按稳定的会话身份与订阅可见性更新集合，避免普通概览变化重跑探测。

只有可见且需要路径、对话 ID 或恢复命令的会话请求对应 Agent 详情。首次进入、进程换代、显式启动与恢复时立即校验，前台以 5 秒周期保底。批量种类只有每会话一个结果，遇到刚启动、快照未确认或多 pane 匹配歧义时，当前会话可有界补探并保留已有正确绑定。核验手动切换视图、不同提供方和普通 shell 启停。

二 · 同一可见会话共享屏幕快照

待输入标记取概览；可交互的 PromptDialog、PromptPanel、LiveTail 和恢复检测共享同一读源。使用经验证足够的 50 行读取窗口，再按各消费者当前的 40/50 行口径裁剪。普通确认按 1.2 秒间隔，实时尾行有需求时可用较快的 800 毫秒间隔。按键结果复核与恢复动作前使用新读，保留原有时序与安全校验。

可见性由页面活动、终端坞模式、活跃文件或终端标签以及文档可见性共同决定。只给订阅终端详情的可见会话调度；最后一个消费者离开就取消请求和定时器。继续使用已有 pollWhileVisible 的串行、超时和退避语义。失败时保留上次观测并停止通过旧提示执行按键；恢复后立即刷新。

三 · 合并转录读取，按活动调整间隔

以节点、稳定会话身份、提供方和已验证的转录来源或执行代次绑定读源。默认只为可见消费者运行一条增量链。若两个入口后端确认同一来源，则共用请求和游标，分别保留滚动位置、草稿和各入口的业务回合状态。从 offset 继续追读，活跃时约 1.5 秒、确认空闲连续多轮后按 10 秒预算，下发消息、恢复可见和重连时提前唤醒。

首屏 50 条、before 历史分页、Pi 窗口替换和受管绑定仍走各自协议。转录轮转、截断或进程换代重建游标，丢弃晚到的旧响应；普通隐藏或断网恢复沿原游标补读。在现有工作区有界缓存中保留可重建快照。收到鉴权或绑定变化就失效，切换节点时立即终止旧节点请求。

三步分别验证、提交和回滚。已有会话生命周期事件继续触发状态刷新。只有生产对照仍显示明显开销时，再评估服务端共享采样与可携带游标的推送，并验证断线追赶。

上线前复测

  1. 同一生产构建配置、节点、客户端和会话集，首屏稳定后采集 30 秒 HAR/CDP。场景包含 0/1/8/20 个 CLI 标签、坞开合、文件、项目详情、同会话双入口、独立页、隐藏与恢复。分开记录首屏、稳态与恢复阶段。
  2. 按方法、路径、会话、查询参数和 Initiator 归类，同一目的的请求记录状态、取消、重叠、空增量比例和传输字节数。共享证据时只保留归类后的计数，移除会话路径和敏感参数。使用 scripts/dev/isolated-roami.sh 启停本地测试实例。
  3. 同批记录 Go 端实际的请求时长、list-panes 和 capture-pane 执行次数、转录读取量以及服务端 CPU/RSS，另测 Chrome 主线程和内存。请求下降比例只用于描述请求。
  4. 测试乱序响应、慢响应、短暂无文件、旧版本节点、节点切换、多 pane 同名 Agent、会话原地重启、同名会话重建、转录换文件及权限失败。持续检查用户可见行为，并以相同阶段的预算和实测为准。
