技术设计

复用已有 roami-sessiond 布局树与前端 SplitTree.tsx，把 Web 端原生会话从「单 WS 字符合成」切换为「每窗格独立 WS + DOM 独立 Terminal」。

1. 模块职责与边界

层次 / 文件 职责 改动方式
internal/sessionhost/host.go
internal/sessionbackend/layout.go		 单点维护 Session → Window[] → LayoutNode → Pane、每 pane 独立 PTY、独立 control_gen、独立 5000 行 VT 状态机。 基本不动；确保 SplitPane / ResizeSplit / FocusPane / ClosePane / NewWindow / SelectWindow / CloseWindow 均发 EventLayoutChanged。
backend/pty/compat_native.go Web 端 /api/term/:name 透明桥接。支持 ?pane=:paneId 单窗格直连模式：跳过 nativeattach 多窗格字符合成与底部假状态栏，直接把单一 pane 的字节流与 resize / move-cursor / scroll / control 透传到 SessionBackend。 新增 serveNativeSinglePaneWS 分支（当带 ?pane= 参数，或 Web 端统一走单窗格模式时启用）；保留旧路径只给未传 pane 的兼容调用方。
backend/api/pane.go
backend/server/server.go		 提供 GET /api/sessions/:name/layout（返回完整 windows[] 含每个窗口的递归 layout 树、version、activeWindowId、activePaneId），以及 POST /api/sessions/:name/terminal-action（补齐 resize-split 动作，与现有 split-right / split-down / focus-pane / new-window / select-window / close-window 收口在同一入口）。 扩展 SessionWindows 或新增 SessionLayout；执行动作后直接返回最新完整 layout 快照，并向订阅者推送布局变更事件。

frontend/src/components/terminal/NativeSplitWorkspace.tsx（新） 管理原生会话的窗口列表与当前窗口的 SplitTree，用 renderPane={(paneId, active) => <Terminal key={paneId} name={session} paneId={paneId} ... />} 挂载独立终端个体；多窗口时渲染极简窗口条；通过 ref 映射把工具栏「滚动 / 重绘 / 重连 / 关闭聚光灯 / 拖拽注入」路由到当前激活窗格。 新增独立领域组件（与 SplitTree.tsx 组合，不把分屏状态塞进臃肿的 TerminalPane.tsx）。
frontend/src/components/terminal/TerminalPane.tsx

internal/cli/nativeattach/attach.go
internal/cli/nativeattach/compositor.go		 CLI（roami session attach）纯字符 TTY 场景下的多窗格合成器。 保留给 CLI 使用，Web 端彻底解绑；CLI 端 ShowStatusBar 默认改为 false（默认隐藏底部蓝色状态栏，仅支持 --status-bar / ROAMI_STATUS_BAR=1 按需显式开启）。

2. 布局数据契约与实时同步

2.1 布局快照接口：GET /api/sessions/:name/layout

{
  "data": {
    "backend": "native",
    "activeWindowId": "w-1",
    "activePaneId": "p-2",
    "windows": [
      {
        "id": "w-1",
        "index": 1,
        "name": "main",
        "active": true,
        "version": 4,
        "activePaneId": "p-2",
        "layout": {
          "id": "s-1",
          "kind": "split",
          "dir": "horizontal",
          "ratio": 0.52,
          "first":  { "id": "n-1", "kind": "pane", "paneId": "p-1" },
          "second": { "id": "n-2", "kind": "pane", "paneId": "p-2" }
        }
      }
    ]
  }
}

2.2 布局变更实时推送（零轮询）

  • 同端操作零延迟：前端调用 POST /terminal-action（分屏、切窗、关窗、拖拽比例）或 POST /panes/:paneId/close 后，HTTP 响应直接返回最新完整 layout，前端原地更新 SplitTree。
  • 跨端操作实时同步：单窗格 WS 在收到 roami-sessiond 的 EventLayoutChanged 时，通过控制文本帧 {"type":"layout","sessionId":"...","version":5} 通知前端；NativeSplitWorkspace 收到后按防抖（50ms）拉取一次 GET /layout 同步整棵树（支持 CLI 分屏、另一台设备切窗、后台进程自动退出关窗格）。
  • 防闪断与状态保留：SplitTree 以 key={paneId} 稳定挂载 <Terminal />。新增或关闭兄弟窗格时，React 不会卸载原有窗格——已连接的 WS、5000 行本地历史、正在跑的命令与未提交输入 100% 无损保留。

3. 关键工程边界与风险防控

  • 浏览器 WebGL 上下文上限：Chrome/Safari 单页通常上限 8–16 个 WebGL 上下文。同一会话开启 ≥ 4 个分屏窗格时，Terminal.tsx 仅对当前活跃窗格（及最近使用的至多 3 个窗格）启用 WebGL，其余自动回退 xterm Canvas/DOM 渲染器，杜绝 webglcontextlost 黑屏。
  • 每窗格独立控制权（control_gen）与手机兼容：
    • 每个独立 Terminal 只对自己绑定的 paneId 执行 ClaimControl / Resize。
    • 手机端（compact）只挂载当前激活窗格的 Terminal，后台窗格不抢桌面控制权、不把桌面隔壁窗格压窄。
    • 电脑端 SplitTree 拖拽分隔线期间，仅在指针 pointerup 落盘后触发各子窗格的 FitAddon.fit() 与 Resize，拖拽过程中只做纯 CSS Flex 重排，60fps 无抖动且避免给远端 TUI 狂发 SIGWINCH。
  • 每窗格独立拖放与粘贴：文件/图片拖放到任意窗格时，事件由该窗格自己的 Terminal 容器接住，直接向该窗格的 paneId 注入 @路径，不再需要先猜测像素坐标调用 select-pane。
  • 每窗格独立复制与全选：
    • 鼠标拖选直接由该窗格的 xterm.js 处理，跨行/折行原生连贯。
    • 新增 TermHandle.selectAll()（调用 term.selectAll()），右键菜单「全选当前窗格」与快捷复制仅针对当前聚焦窗格。
  • 导航状态归属：遵循 view-state.tsx 规范，仅缓存纯数据布局快照（cache 策略），不把 xterm / WebSocket 实例放进全局 store；页面隐藏或切换会话时按活动生命周期清理连接。

4. 验收清单

  1. 复制与全选验收：左右分屏（左输出多行代码/堆栈，右运行交互命令）→ 左侧跨 10 行拖选复制，粘贴内容不含任何边框字符或右侧文字；在左侧点「全选当前窗格」并复制，仅包含左侧输出。
  2. 独立滚动验收：左侧输出 500 行后上滚到顶部查看，同时在右侧持续输入命令，左侧视口不被拉回底部。
  3. 拖拽比例与稳定性验收：拖 1px 分隔线调整为 30/70，刷新页面比例持久化保留；新建/关闭兄弟窗格时，存活窗格的 WS 不断线、历史不清空。
  4. 关闭窗格聚光灯验收：在 2×2 四分屏下任选一格点「关闭当前窗格」，红框与确认卡像素级贴合目标窗格 DOM 边界。
  5. 跨端同步验收：桌面开 1280 / 1920 / 2560 / 3440px，手机真机开 390px（compact 折叠为顶部切换条 + 单窗格全宽）；在 CLI 执行 roami session pane split，桌面与手机 Web 布局树实时同步。
  6. 三平台与旧会话回归：Linux / macOS / Windows（ConPTY）原生会话均正常分屏；旧 tmux 会话仍按单画布正常工作。
