技术设计

三平台共用一套 Go 会话宿主和终端接口。一个窗格对应一个 PTY，宿主负责持有进程、管理连接和提供可核对的生命周期。

  • 平台接口。 Start(spec) 接收可执行文件、argv、cwd、env 和初始尺寸，返回可读写的终端、Resize、Wait 和具名的停止与释放操作。启动请求的 context 只约束创建，在创建确认后由宿主持有进程。分离连接只取消订阅，优雅停止、强制停止和资源释放各走明确的操作。Wait 只由宿主执行一次，之后共享退出结果。输入、读出、关闭及进程回收之间定义所有权，关闭和失败收尾可重试。
  • 会话接口。 覆盖创建、观测、附着、定向输入、捕获、进程停止和布局操作。附着订阅和服务端启动请求分别定生命周期。允许观测返回「确认存在」「确认退出」「状态待确认」，并附对应证据。
  • 本机 IPC。 Web 和 CLI 通过用户级 Unix socket 或 Windows 本地命名管道连接。socket 使用用户专属运行目录和同 UID 校验，命名管道使用显式 DACL 和本地连接限制。握手绑定实例根、宿主 ID 与可协商协议版本。
  • 授权和并发。 每次输入先核对会话归属、窗格代次、当前控制权及生命周期围栏；受管任务走已有修订和提示绑定。自动粘贴、提交和交互输入共用单窗格有序写队列，粘贴与 Enter 作为同一操作中的两个有序动作。写入回执只证明写入已发生，任务结果仍由执行器证据和宿主观察确认。阻塞后状态不明确时禁止自动重投。

宿主托管与不停会话升级

建议把 roami-sessiond 打包成独立版本的最小 Go 二进制，与 Roami 共享终端接口和协议代码。Web 服务与宿主各自托管，start.sh 的 Web 重启路径不持有宿主，也不停止宿主进程组。Linux 使用独立的 systemd user unit，macOS 用独立的用户 LaunchAgent。Windows 首轮验证按用户登录运行的计划任务。验证登录、锁屏、退出登录和开机行为后再决定长期托管范围。

每个节点和实例根只有一个接收新建的宿主；同一实例允许多个按宿主 ID 寻址的排空宿主。每个宿主有独立 IPC 端点和服务注册。宿主登记保存 host_instance_id、启动代次与系统进程身份、二进制版本、协议版本范围、端点和状态；每个会话写入后端、宿主 ID、窗格 ID、运行代次和进程身份。标签、工作区、任务及恢复来源沿用台账。

  1. 准备。 安装新版本到版本化路径，独立启动并通过身份、权限、上线健康检查和协议握手。宿主日志按版本与实例归档。Web/CLI 需能同时与新旧宿主的协议版本通信，失败时保持既有路由。
  2. 切换。 旧宿主先停止接收新建、让已受理创建完成或落下可查回执，再用持久化的当前宿主指针和代次将新建指向新版。创建请求携带该代次，迟到请求由旧宿主拒绝。已有会话按登记宿主继续附着和输入。切换中断时以持久化代次重新确认准入宿主，确认前暂缓新建。
  3. 排空。 旧宿主持有已有 PTY/ConPTY，等会话自然退出后再撤服务注册并清理旧二进制。升级验收必须证明旧会话的宿主和窗格进程身份不变、新会话归新版。回滚只改新建指针，仍兼容已经创建的两代会话。
  4. 故障。 有权限的本地 CLI 可在 Web 不可用时继续普通会话，受管任务仍依赖已有围栏和宿主证据。IPC 权限错误、超时或协议不兼容都保留待确认，不自动开替代会话。宿主异常退出由系统重拉新运行代次，旧进程按可验证身份对账；机器重启后只启动当前配置的准入版本。确认原窗格已退出才允许从台账重开。

Unix socket 放在短路径的用户私有运行目录，绑定实例根的摘要及宿主 ID。Linux 用 SO_PEERCRED，macOS 用 getpeereid 核对 peer UID，并检查端点所有权。Windows 管道要求用户或登录 SID 的访问控制和远程连接限制，详见Windows 整包移植。

平台适配

将接口和启动参数放在同一 Go 包，由构建标签选中 Unix 或 Windows 的实现。上层使用统一的列行尺寸、退出结果和字节流接口。Unix 的 *os.File、Windows 的管道和句柄留在各自适配器里。两种后端在现有 Go 依赖上即可实现，可随 Roami 按目标平台编译，无需为 PTY 层引入 CGO 或额外运行时。

同一组契约测试覆盖启动、双向输入输出、初始尺寸、在线调整、退出与重复关闭。能力存在平台差异时由适配器明确报告，例如信号、暂停和进程组观测，上层根据能力提供操作。

macOS / Linux

以 StartWithSize 建控制终端和初始尺寸，子进程使用登录 shell 或指定可执行文件。由 master 读写，以 Setsize 更新尺寸并由系统通知前台进程组。宿主记录 PID、系统启动标识、进程启动时间以及 session ID / PGID。交互 shell 会把作业放入不同进程组，回收前验证运行身份并以 Linux cgroup 或经验证的 macOS 会话进程归属核对退出。启动参数显式携带获准的每会话环境，登录 shell 初始化 PATH、nvm 与用户配置；SSH_AUTH_SOCK 等会话变量按启动来源传入。验证 TERM 与真实 VT 能力、平台可用的 UTF-8 locale。

Windows / PowerShell

Windows 适配器通过系统 ConPTY 启动 PowerShell 和 Agent。先评估 crosspty、go-pty 与直接调用 ConPTY 对进程身份、关闭排空及 Job Object 的支持。启动、引号、管道、签名与整包移植的验收条件见Windows 整包移植。

屏幕捕获、输入与重连

  1. 一个流。 宿主始终读取 PTY，并把输出按窗格代次和单调序号排入有界缓冲。记录尺寸变化事件和输出位置，server-side VT 状态按相同顺序更新。Web 保持 xterm.js，CLI 在本机终端 raw mode 中渲染。双方都要支持二进制输入输出和独立控制帧。
  2. 一次衔接。 新连接在同一序号边界取得屏幕快照和订阅，然后收到严格晚于该边界的输出。短断线可从同代次最后已确认序号补发，输出落后超出缓冲时重取快照。快照尺寸与宿主一致；慢客户端只影响自身，丢失顺序时重同步。客户端按同一顺序应用输出与尺寸变化。
  3. 终端语义。 快照需保留正常/备用屏、滚动记录、光标、样式与键盘/鼠标模式。由屏幕状态提供 capture 普通文本，用输出日志做审计或诊断。验证换屏、中文宽字符、跨块 UTF-8、Ctrl/Cmd 组合键、括号粘贴和交互滚动。对终端查询指定唯一响应方，避免多客户端向应用复制响应。首次实现先比较 Go charmbracelet/x/vt 的模式覆盖和 @xterm/headless + Serialize 的快照表现，后者用作对照。用同一批流录制做一致性验收后，再定 Go VT 库版本和最小自研边界。
  4. 输入权。 用宿主端控制权代次排除迟到的输入、滚轮和尺寸事件。普通屏向上翻查历史；备用屏根据当前模式发送滚轮，或按应用验收结果转为明确的翻页按键。尺寸以有效且显式接管的客户端为准，合并连续变化。

连接与回放协议

消息最小字段处理
hello / attach协议范围、实例、宿主、会话、窗格、运行代次，可选最后已应用序号。协商版本和能力，核对身份，判断续放或快照；不兼容时保留观测为待确认。
snapshot窗格代次、屏幕尺寸、截止序号、VT 屏幕与模式状态。建立同一序号边界的快照和订阅，客户端应用后从其后接收连续事件。
output / resized / exited一条窗格事件流的连续序号。终端字节用二进制帧，改尺寸及退出用控制帧。按顺序应用，区分进程退出和输出读完。出现序号缺口或缓冲溢出，暂停旧订阅并重取快照。
claim / input / resize请求 ID、窗格代次、控制权代次、目标窗格。resize 含列行，input 另有输入载荷。宿主授权、排序、校验并发世代。相同尺寸去重；丢弃过小、超界或迟到尺寸。可查询写入回执，超时的不确定输入不重放。
resync / detach窗格代次与最近应用的序号。释放订阅或恢复输出，不触发进程终止。

Web 以一条附着流对应一个窗格。首版 WebSocket 控制帧用 JSON，输出二进制帧用 8 字节大端序号加 VT 数据，输入控制帧携带请求 ID 和 UTF-8 文本或字节数组。本机 IPC 用 4 字节大端帧长、消息种类和载荷，使用每窗格独立附着流。输出记录和每客户端发送队列分别设上限。上线前根据录制和 30 会话基线确定默认值；达到上限时慢客户端重同步，日志则轮转并暴露可查询范围。

迁移、故障与回滚

  1. 先抽业务接口。 以现有 tmux 为第一个 SessionBackend。按迁移清单迁移 API、CLI 和 Agent 调用点，先跑旧行为回归。TerminalBackend 只供原生宿主调用，处理 PTY、进程和操作系统能力。Windows 整包单独立项，候选 PTY 探针可并行。
  2. 宿主与普通会话试点。 Linux 和 macOS 从单窗格开始，完成屏幕捕获、断线回连和 Web 重启恢复。先在隔离实例开启原生后端，复用会话台账和连接入口。旧记录识别为 tmux。新建记录写入不可变的后端与运行身份，部署版本支持双读，首个用户可用版本由独立宿主持有 PTY，并通过双版本排空演练。
  3. 迁移剩余功能。 补齐窗口、分屏和 CLI 操作，接入 Agent 输入和执行生命周期。启动前先持久化操作 ID、目标和工作区租约，再向宿主发起同一操作可查的创建。一旦创建结果中断，按操作 ID 查询当前宿主和已写入的观测证据，禁止重新开一个窗格来碰运气。
  4. 确认退出再恢复。 Web 重启时按宿主实例与窗格代次接续。宿主不可达时保留工作区围栏。进程等待结果、带身份的系统观测或宿主重启证据明确后，才对历史做相应状态变更。宿主或整机重启后，可按台账重开并用支持的 Agent 对话 ID 恢复；新会话有新运行身份和恢复来源。原进程内存和未持久化输出随宿主故障丢失。
  5. 切换与回滚。 一次只改变新建默认项；运行中的会话继续按已登记后端连接。保留支持两种后端的版本和恢复路径，避免回退到无法读取原生会话的版本。旧后端只有在活跃会话自然排空、历史和复原路径验收后，才评估停止安装和维护。

验证记录与试点门槛

  • 已验证。 Linux 的系统 PTY、双向 I/O、改尺寸和退出码。两种候选在 Linux 跑通基本交互，退出后 EOF 行为有差异。macOS 与 Windows 完成探针交叉编译，Windows 整包基线复现文件锁、磁盘和进程控制编译阻塞。
  • VT 试点门槛。 用同批录制对比 Go VT 与 xterm headless/Serialize。最少覆盖正常/备用屏、宽字符、换行、滚动记录、鼠标、括号粘贴、DA/DSR/OSC 唯一响应、快照后接续与纯文本捕获。比较 1、10、30 会话 CPU、RSS 与延迟，选择可承担常驻开销的实现。
  • 宿主试点门槛。 两个隔离实例分别运行，停止一个后另一个会话、端点及进程仍存活。Web 重启、宿主滚动升级、协议错配、宿主崩溃和围栏对账都要有证据。将隔离脚本扩展为只核验并清理对应实例的已登记宿主。进入实现时将 tmux 目标、提交等仓库规则明确作用于兼容适配器。
  • 发布门槛。 先过 Unix 原生试点，再按能力灰度。Windows 分别核对 ConPTY、整包、安装和 Agent 交互，发布范围见Windows 整包验收。
