技术设计

把平台 PTY 与会话策略解耦。一个窗格对应一个 PTY，Go 会话宿主负责持有进程、管理连接和提供可核对的生命周期。

进程归属与接口

Web xterm.js / roami session
          │  会话操作、终端输入、订阅
          ▼
Roami 会话服务（授权、台账、工作区与执行绑定）
          │
          ├─ tmux 兼容适配器 → tmux server
          │
          └─ 本机 IPC → Go 会话宿主（独立于 Web 服务）
                          ├─ 窗口与窗格、VT 状态、日志、退出观测
                          └─ PTY 适配器 → 每窗格一个 shell / Agent
  • 平台接口。 Start(spec) 接收可执行文件、argv、cwd、env 和初始尺寸，返回可读写的终端、Resize、Wait、Close 与具名的进程终止操作。Wait 只由宿主执行一次，之后共享退出结果。输入、读出、关闭及进程回收之间定义所有权，关闭和失败收尾可重试。
  • 会话接口。 覆盖创建、观测、附着、定向输入、捕获、进程停止和布局操作。附着订阅和服务端启动请求分别定生命周期。允许观测返回「确认存在」「确认退出」「状态待确认」，并附对应证据。
  • 本机 IPC。 宿主先复用同一 Roami 二进制的独立实例，Web 和 CLI 通过用户级 Unix socket 或 Windows 本地命名管道连接。socket 使用用户专属目录和同用户校验，命名管道使用显式 DACL 和本地连接限制。绑定实例根和发行协议版本，每个实例根只允许一位宿主拥有者。
  • 授权和并发。 每次输入先核对会话归属、窗格代次、当前控制权及生命周期围栏；受管任务走已有修订和提示绑定。自动粘贴、提交和交互输入共用单窗格有序写队列，粘贴与 Enter 作为同一操作中的两个有序动作。写入回执只证明写入已发生，任务结果仍由执行器证据和宿主观察确认。阻塞后状态不明确时禁止自动重投。

平台适配

macOS / Linux

以 StartWithSize 建控制终端和初始尺寸，子进程使用登录 shell 或指定可执行文件。由 master 读写，以 Setsize 更新尺寸并由系统通知前台进程组。按进程身份回收目标进程。交互 shell 可能将作业放入不同进程组，不能只按 shell 的组判断已清理。Linux 可沿用现有 cgroup 能力，macOS 先验证会话内进程归属和未能确认的退出行为。验证 TERM 对应的终端能力和两边的 UTF-8 locale，避免向应用宣称尚未支持的控制序列。

Windows / PowerShell

  1. 解析并验证 pwsh.exe 的绝对路径、cwd 和环境。通过 CreateProcessW 的明确可执行路径、按目标程序约定编码的 UTF-16 命令行和 Unicode 环境块启动。测试空参数、引号、尾部反斜杠、非 ASCII 路径及大小写不敏感的环境覆盖。Agent 等原生程序使用 argv 直接启动。shell 输入另外按 PowerShell 语义处理。
  2. 用两条同步管道与 CreatePseudoConsole 建立 ConPTY，STARTUPINFOEX 带 PROC_THREAD_ATTRIBUTE_PSEUDOCONSOLE。进程悬挂创建，先加入 Job Object 再恢复主线程。具体核对宿主所在 Job 的嵌套限制、拒绝路径和部分初始化失败后的句柄清理；与 Job 无法关联时按配置的能力要求拒绝或报告降级。
  3. 独立读写循环处理 UTF-8/VT，PTY 流写入受尺寸转换、队列和并发约束。对 Ctrl+C、PSReadLine、多行粘贴和 TUI 的修饰键分别录制探针结果。交互键、进程退出及强制结束 Job 分开处理。
  4. 关闭先停止接收新输入，同时保持输出排空或在放弃尾部输出时显式关闭读端。等待进程退出与输出结束分别记录，按期限用 Job Object 完成确定的进程回收。即便系统关闭调用立即返回，也需观察进程和输出终态。

屏幕捕获、输入与重连

  1. 一个流。 宿主始终读取 PTY，并把输出按窗格代次和单调序号排入有界缓冲。记录尺寸变化事件和输出位置，server-side VT 状态按相同顺序更新。Web 保持 xterm.js，CLI 在本机终端 raw mode 中渲染。双方都要支持二进制输入输出和独立控制帧。
  2. 一次衔接。 新连接在同一序号边界取得屏幕快照和订阅，然后收到严格晚于该边界的输出。短断线可从同代次最后已确认序号补发，输出落后超出缓冲时重取快照。快照尺寸与宿主一致；慢客户端只影响自身，丢失顺序时重同步。客户端按同一顺序应用输出与尺寸变化。
  3. 终端语义。 快照需保留正常/备用屏、滚动记录、光标、样式与键盘/鼠标模式。由屏幕状态提供 capture 普通文本，用输出日志做审计或诊断。验证换屏、中文宽字符、跨块 UTF-8、Ctrl/Cmd 组合键、括号粘贴和交互滚动。对终端查询指定唯一响应方，避免多客户端向应用复制响应。首次实现先比较 Go charmbracelet/x/vt 的模式覆盖和 @xterm/headless + Serialize 的快照表现，后者用作对照。用同一批流录制做一致性验收后，再定 Go VT 库版本和最小自研边界。
  4. 输入权。 用宿主端控制权代次排除迟到的输入、滚轮和尺寸事件。普通屏向上翻查历史；备用屏根据当前模式发送滚轮，或按应用验收结果转为明确的翻页按键。尺寸以有效且显式接管的客户端为准，合并连续变化。

迁移、故障与回滚

  1. 平台探针。 先做纯 Go PTY 启动与回收。Windows 整包编译已复现 Unix 文件锁、磁盘查询和进程控制等阻塞。优先为存储、会话生命周期等核心模块补平台实现，对宿主监控和手机模拟器等可选功能按能力启用，再验证安装、工作区路径和 Agent 启动。
  2. 宿主与普通会话试点。 完成单窗格、屏幕捕获、断线回连和 Web 重启恢复。先在隔离实例开启原生后端，复用会话台账和连接入口。旧记录识别为 tmux。新建记录写入不可变的后端与运行身份，部署版本支持双读。Web 服务与宿主独立托管，服务更新保持协议兼容。
  3. 迁移剩余功能。 补齐窗口、分屏和 CLI 操作，接入 Agent 输入和执行生命周期。启动前先持久化操作 ID、目标和工作区租约，再向宿主发起同一操作可查的创建。一旦创建结果中断，按操作 ID 查询当前宿主和已写入的观测证据，禁止重新开一个窗格来碰运气。
  4. 确认退出再恢复。 Web 重启时按宿主实例与窗格代次接续。宿主不可达时保留工作区围栏。进程等待结果、带身份的系统观测或宿主重启证据明确后，才对历史做相应状态变更。宿主或整机重启后，可按台账重开并用支持的 Agent 对话 ID 恢复；新会话有新运行身份和恢复来源。原进程内存和未持久化输出随宿主故障丢失。
  5. 切换与回滚。 一次只改变新建默认项；运行中的会话继续按已登记后端连接。保留支持两种后端的版本和恢复路径，避免回退到无法读取原生会话的版本。旧后端只有在活跃会话自然排空、历史和复原路径验收后，才评估停止安装和维护。

上线前对比旧链路与原生链路的首屏、重连耗时、输入延迟、忙窗格资源占用与高输出下的断连行为。以相同机器、尺寸、输出负载和会话数记录，详见验证记录。
