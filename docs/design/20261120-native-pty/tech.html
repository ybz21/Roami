服务重启和宿主升级

升级时保住正在跑的会话

roami-sessiond 独立运行。Linux 用 systemd 用户服务，macOS 用 LaunchAgent，Windows 先验用户登录任务。Web 重启后按宿主 ID 接回原窗格。

新宿主通过健康和协议检查后，在同一事务里检查排空上限，再 CAS 更新 current_host、generation 和新旧宿主的接收状态。回滚同样递增代次。旧宿主继续服务已有会话。

重试最多创建一次

每次创建带 operation_id 和 expected_generation。宿主在和切换串行的事务中核对权限、参数、指针和代次，写入唯一受理记录。工作线程用 CAS 将记录改为启动中，再打开 PTY。

旧宿主用 STALE_GENERATION 拒绝未受理的过期请求。客户端重读路由并查原操作 ID。已受理的仍由原宿主处理。确认未受理时才用原 ID 重试。结果不明时保留归属和工作区围栏，先查证。

旧宿主什么时候退出

每实例最多两代排空。满了先暂停升级，节点诊断列明挡住升级的会话。用户可等待，或明确确认结束指定会话。按台账重开需先确认原进程退出。

确认没有活跃窗格和未结请求后，在台账里标为退役，确认宿主退出再清端点。二进制无引用才删除，最多留一个已退役版本供回滚。

各平台怎么启动进程

系统差异留在适配器

  • macOS/Linux 用 creack/pty 建 TTY。Linux 可用 cgroup，macOS 按进程归属核对退出。停止前核对 PID 和启动身份。
  • Windows 首选 crosspty v1.2.0，新增模块，最低 Go 1.24.0。go-pty v0.2.3 作对照，最低 Go 1.25.0。回退时用现有 x/sys/windows。
  • 本机通信也分平台。Unix socket 校验同一用户，Windows 命名管道用用户访问控制并拒绝远程连接。

断线怎么接回

断线后怎么接回画面

  1. 宿主持续读 PTY，把输出和尺寸变化按窗格代次排序。断开浏览器或 CLI 只取消订阅。
  2. 同代次有缓存就从最后序号续放。缓存不足时先取快照，再接收更晚的输出。慢客户端独立重同步。
  3. 快照先用 charmbracelet/x/vt v0.1.0 试验，要求 Go 1.24.2。与 xterm headless 比对换屏、滚动、宽字符和终端查询。
  4. 当前控制方可以输入和改尺寸。宿主丢掉旧控制方迟到的事件。

终端连接协议

连接与回放协议

消息最小字段处理
hello / attach协议范围、实例、宿主、会话、窗格、运行代次，可选最后已应用序号。协商版本和能力，核对身份，判断续放或快照；不兼容时保留观测为待确认。
snapshot窗格代次、屏幕尺寸、截止序号、VT 屏幕与模式状态。建立同一序号边界的快照和订阅，客户端应用后从其后接收连续事件。
output / resized / exited一条窗格事件流的连续序号。终端字节用二进制帧，改尺寸及退出用控制帧。按顺序应用，区分进程退出和输出读完。出现序号缺口或缓冲溢出，暂停旧订阅并重取快照。
claim / input / resize请求 ID、窗格代次、控制权代次、目标窗格。resize 含列行，input 另有输入载荷。宿主授权、排序、校验并发世代。相同尺寸去重；丢弃过小、超界或迟到尺寸。可查询写入回执，超时的不确定输入不重放。
resync / detach窗格代次与最近应用的序号。释放订阅或恢复输出，不触发进程终止。

Web 以一条附着流对应一个窗格。首版 WebSocket 控制帧用 JSON，输出二进制帧用 8 字节大端序号加 VT 数据，输入控制帧携带请求 ID 和 UTF-8 文本或字节数组。本机 IPC 用 4 字节大端帧长、消息种类和载荷，使用每窗格独立附着流。输出记录和每客户端发送队列分别设上限。上线前根据录制和 30 会话基线确定默认值；达到上限时慢客户端重同步，日志则轮转并暴露可查询范围。

迁移和回滚

迁移和回滚

  1. 先让 tmux 按统一会话接口工作，复用原台账和任务绑定。
  2. 原生宿主先跑单窗格，验重连和升级，再开分屏与受管任务。Windows 单独验整包。
  3. 切换和回滚只改变新建默认项。已有会话按原归属连接。宿主崩溃时，确认原进程退出后才可按台账重开。
