三平台原生终端

推荐由 Roami 自己管理会话，底层复用系统 PTY。Unix 用现有 creack/pty，Windows 先对比 crosspty、go-pty 和直接调用 ConPTY。

浏览器目前通过一个外层 PTY 运行 tmux attach。真正的 shell 和 Agent 在 tmux server 持有的窗格中。只换外层 PTY，底下仍要有 tmux server。三平台原生运行需要由 Roami 接手窗格进程、分离重连、屏幕捕获和退出观测。

Windows 适配放在哪一层

creack/pty 的 Unix 接口交给调用方一个双向 *os.File，子进程由 exec.Cmd 启动和等待。Windows 版本的 StartWithSize 目前返回 ErrUnsupported。ConPTY 需要分别管理输入管道、输出管道、控制台句柄及进程句柄，启动时还要将控制台作为属性传给 CreateProcessW。

在 Roami 内定义终端契约，让适配层包装系统 API 或通过验证的库。分离附着连接、进程停止与 PTY 资源释放，终端协议与会话宿主跨平台复用。直接扩展 creack/pty 原签名仍需解决双管道封装和 exec.Cmd 的等待兼容。

实施顺序

  1. 先抽接口。 将业务会话操作与 PTY 句柄分到 SessionBackend、TerminalBackend。先把 tmux 接到会话接口，沿用稳定 ID、台账、工作区与任务关联。
  2. Unix 先试点，Windows 并行验证。 Linux 首个端到端试点由独立宿主持有单窗格，随后验 macOS。同批跑 Windows PowerShell 的 crosspty、go-pty 与直接 ConPTY 探针，按真机结果选 Windows 实现。
  3. 按平台灰度。 Unix 的宿主升级、VT 重连和受管任务过关后开放原生新建。Windows 单独过整包、用户身份、安装和 Agent 启动门槛，再开放原生节点。

运行中的会话始终按登记后端路由。实际探针结果和待验证项见验证记录。
