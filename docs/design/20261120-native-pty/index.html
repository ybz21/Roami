三平台原生终端

推荐 macOS、Linux 用现有 creack/pty，Windows 用系统 ConPTY 启动 PowerShell 7。让独立的 Go 会话宿主持有两类 PTY。

浏览器目前通过一个外层 PTY 运行 tmux attach。真正的 shell 和 Agent 在 tmux server 持有的窗格中。只换外层 PTY，底下仍要有 tmux server。三平台原生运行需要由 Roami 接手窗格进程、分离重连、屏幕捕获和退出观测。

建议支持范围

平台PTY交互 shell首轮实机验收
macOS系统 PTY，经 creack/pty用户登录 shell，通常为 zsharm64；保留 amd64 构建，发布前实测
LinuxUnix 98 PTY，经 creack/pty用户登录 shell，通常为 bash，也支持显式配置amd64；保留 arm64 构建，发布前实测
Windows系统 ConPTY，经 x/sys/windowspwsh.exe（PowerShell 7），缺失时给出安装提示Windows 11 24H2 或更新的受支持版本，先 x64，再验 arm64

Windows 的 API 自 Windows 10 1809 起可用。产品首发建议从 Windows 11 24H2 起验收，因为 ConPTY 关闭行为在该版本改变。Windows PowerShell 5.1 的 powershell.exe 与 PowerShell 7 并存，留作后续独立兼容项。Windows Server、WSL 和旧版 Windows 暂不承诺。

方案适配 Roami 的收益成本与判断
现有 Go 依赖 + 系统 API 复用现用的 creack/pty v1.1.24 和 x/sys v0.41.0。Go 宿主可控制创建、句柄、关闭顺序和进程事件。 推荐。Windows 平台适配器要负责参数与环境、关闭顺序和 Job Object，需真机测试。
charmbracelet/x/conpty v0.2.0 Go Windows 封装，提供建管道、启动、读写、调尺寸与关闭。原型可以快速接入。 备选。审阅的 Spawn 收起了主线程句柄，若要挂 Job 后再放行，需验证或扩展接口。Close 调用原生关闭后才关输出读端，必须保持输出排空。
aymanbagabas/go-pty v0.2.3 把 Unix PTY 与 Windows ConPTY 统一为 Go 的启动、读写、尺寸和等待接口。 调研版本要求 Go 1.25，仓库基线为 1.24。统一接口仍需补会话宿主和进程组治理，可作为平台适配参考。
microsoft/node-pty 支持三平台，VS Code 等使用。适合作 PowerShell 和 ConPTY 行为对照。 作为默认宿主会引入 Node 进程和按平台发布的原生扩展，增加安装、升级和故障定位链路。
Unix 保留 tmux，Windows 使用 WSL 最快保住现有分屏和会话用法，可用作过渡期对照。 WSL 中的 tmux 持有的是 Linux PTY。原生 Windows PowerShell 路线仍需 Windows 控制台语义和独立验收。

先验证三件事

  1. 系统 PTY。 验证原生 shell 双向交互、尺寸变化、Ctrl+C、退出码和进程树清理。先验 Windows 的关闭排空与 Job Object，再决定可复用多少上游代码。
  2. 会话宿主。 让 Web 与 CLI 断开后仍可接回同一窗格，并在 Web 服务重启后恢复屏幕和输入。用 Codex、Claude Code 和 vim 检查备用屏、中文、鼠标与多行粘贴。
  3. Roami 迁移。 原生后端先承接新建普通会话。待分屏、受管任务、停止对账和安装发布逐项达标，再扩大默认范围。运行中的旧会话继续由创建它的 tmux 后端持有。

本次已在 Linux 验证独立 PTY 的基本交互，macOS 与 Windows 已完成轻量探针的交叉编译。完整应用和三平台运行验收列在验证记录。
