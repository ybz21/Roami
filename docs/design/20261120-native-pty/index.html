三平台原生终端选型

会话交给 Roami 自己的 Go 宿主 roami-sessiond。macOS 和 Linux 用 creack/pty，Windows 首选 crosspty 接系统 ConPTY，默认打开 PowerShell 7。

开工用的技术栈

  • 会话宿主。 实现 roami-sessiond，复用 Roami 的会话台账、工作区围栏和任务绑定。Linux/macOS 用 Unix socket，Windows 用本地命名管道。现有 WebSocket 和浏览器 xterm.js 沿用。
  • 平台 PTY。 Linux 和 macOS 继续使用已在 go.mod 中的 creack/pty v1.1.24。Windows 开发和首轮真机验收按 crosspty v1.2.0 实施，新增该 Go 模块。
  • 服务端屏幕状态。 首选用 charmbracelet/x/vt v0.1.0 做 Go 原型，新增模块且最低 Go 1.24.2。通过录制回放、快照和资源占用验收后再并入工程，xterm headless 用作一致性对照。
  • 已有会话。 tmux 适配器保留到旧会话排空。新会话通过同一 Roami 接口按已启用的后端创建。

Windows 回退条件。 如果 crosspty 在真机上无法满足 Job 清理、退出取证或关闭排空，且小范围适配无法补齐，改用现有 x/sys/windows 直接接 ConPTY。go-pty 和 Zellij 保留为调研对照。

第一步怎么做

  2. 实现 Linux 单窗格宿主。 用 creack/pty 跑通创建、断开、重连和 Web 重启，再验 macOS。并行用 crosspty 探针验证 Windows 11 24H2+ 的 PowerShell 7。
  3. 按平台灰度。 Unix 先验快照、宿主升级和受管任务。Windows 单独验整包构建、安装、用户身份和 Agent 启动。运行中的会话按登记后端连接。

统一 Go 接口 + 系统 API 复用现用的 creack/pty v1.1.24 和 x/sys v0.41.0。Go 宿主可控制创建、句柄、关闭顺序和进程事件。 Unix 采用现有库，Windows 直接调用是 crosspty 未通过门槛时的回退。Roami 可控制参数与环境、关闭排空、进程证据和 Job Object。
Kodecable/crosspty v1.2.0 纯 Go 统一 PTY，Unix 内部复用 creack/pty，Windows 使用 ConPTY，含可选 Job 进程组清理。采用时新增模块，最低 Go 1.24.0 和现用 PTY 依赖版本与 Roami 对齐。 Windows 首选。Close 会终止子进程，Wait 返回 -1 时可能是观察失败。需要验证最后输出、退出证据、宿主崩溃和 Job 归属。
charmbracelet/x/conpty v0.2.0 Go Windows 封装，提供建管道、启动、读写、调尺寸与关闭。原型可以快速接入。 备选。审阅的 Spawn 收起了主线程句柄，若要挂 Job 后再放行，需验证或扩展接口。Close 调用原生关闭后才关输出读端，必须保持输出排空。
aymanbagabas/go-pty v0.2.3 把 Unix PTY 与 Windows ConPTY 统一为 Go 的启动、读写、尺寸和等待接口。 与 crosspty 用同一批探针对照。v0.2.3 需要 Go 1.25，采用它将同时涉及主工程及传递依赖升级；Windows Job 和启动时的主线程控制仍要单独评估。
microsoft/node-pty 支持三平台，VS Code 等使用。适合作 PowerShell 和 ConPTY 行为对照。 作为默认宿主会引入 Node 进程和按平台发布的原生扩展，增加安装、升级和故障定位链路。
WezTerm portable-pty 0.9.0 WezTerm 的 Rust PTY 库，可独立使用，覆盖 Unix PTY 和 Windows ConPTY。 可作为 API 与终端行为对照。接进现有 Go 服务要另发 Rust 进程或维护 FFI，Roami 仍需做会话管理。
Zellij 完整 multiplexer，包含会话、分屏、远程附着和自动化。0.44.0 于 2026-03-23 引入原生 Windows 支持，已查到 v0.46.0 的 Windows x64 安装包。 如果目标改为复用外部 multiplexer，先对照实测。接管生命周期、受管输入和屏幕捕获需要重新适配它的 CLI 与状态语义。

Windows 适配放在哪一层

creack/pty 的 Unix 接口交给调用方一个双向 *os.File，子进程由 exec.Cmd 启动和等待。Windows 版本的 StartWithSize 目前返回 ErrUnsupported。ConPTY 需要分别管理输入管道、输出管道、控制台句柄及进程句柄，启动时还要将控制台作为属性传给 CreateProcessW。

在 Roami 内定义终端契约，让适配层包装系统 API 或通过验证的库。分离附着连接、进程停止与 PTY 资源释放，终端协议与会话宿主跨平台复用。直接扩展 creack/pty 原签名仍需解决双管道封装和 exec.Cmd 的等待兼容。
