tmux 迁移清单

先把现有调用收进按业务操作定义的 SessionBackend，再逐项接上原生宿主。每项能力决定哪些入口可以开放给原生会话。

现有能力、原生契约与试点范围

现有能力原生宿主契约试点与验收
会话身份与事务按稳定 ID 和运行代次创建、观测、关闭。由现有台账处理工作区、派生关系、任务与客户端重试。兼容适配器内继续严格匹配 tmux 目标。单窗格试点必需。重名、超时、重试、双后端并存时不得误接另一个会话。
终端附着与尺寸每窗格独立订阅同一输出流。连接分离与进程停止分别处理。改尺寸使用控制权代次。新建、列出、附着、分离、关闭和断线续放首轮可用，覆盖 Web 与 CLI 多客户端。
最近活跃时间替换 window_activity。宿主分别记录最近实际输入与输出时间，会话聚合取最近值，按现有列表使用场景对照。首轮纳入列表验收。附着、被动回放和健康探测不增加工作活跃时间。
纯文本 Capture返回运行代次、屏幕模式、最近 N 行文本及有效范围。分别提供可见屏和含历史的调用，用屏幕模型构建结果。首轮供 capture。自动确认、互审命中、内存整理使用的文本须在同一输出录制上比对后启用。
滚动、光标、点选由 VT 状态给出备用屏、光标、鼠标跟踪模式与编码；窗格焦点使用窗口布局。普通屏查历史，备用屏按当前模式路由滚轮或翻页。原生单窗格先过滚动和按键回归。布局及 pane 级坐标路由随分屏启用。
持久终端日志宿主接手 pipe-pane。输出带窗格代次和序号，按流顺序写入可轮转日志，明确可回看区间。保留会话日志入口与来源。首轮必需。对照同一序号的日志与快照，区分原始输出、解释后的屏幕和执行器结构化回执。
普通与受管输入普通会话支持文本、按键和粘贴。受管会话发送多行内容时按当前应用模式编码括号粘贴，独立发送 Enter，两动作由同一操作串行，不可被并发交互插入。普通输入首轮可用。受管入口在提示绑定、独立提交、IME、Shift+Enter 和结果不明时防重投验收后开放。
每会话内存治理Linux 为原生会话建立 cgroup scope，按新宿主和会话身份解析 scope，沿用配置上限与归属。Windows 用 Job Object 评估内存限制，不可声明 Unix 压缩与回收等价。有管理要求时必须在启动前获得约束，否则报告缺失，试点仅开放明确允许该能力组合的会话。默认切换前验单会话超限不影响同机其他会话。
进程和恢复用 PID、启动身份、Unix 进程组/cgroup 或 Windows Job 证明进程归属。停止与重新创建继续受资源围栏约束。processes / process-stop / pause / resume / reclaim / compact 按能力启用。原生会话不借 tmux 的进程观测结果推断退出。
窗口、分屏、蜂群宿主记录 window/pane 布局、活动窗格和按窗格的会话能力。受管任务独立对齐执行证据和提示绑定。首轮单窗格不提供 nw / lw / kw / sp / kp。fork、蜂群和受管任务按迁移与回归进度开放。旧会话继续走 tmux。

代码迁移顺序

  1. 沿 backend/ttmux、internal/session 和 internal/tmuxruntime 理清调用。先迁移创建、列表、目标解析、退出观测，再迁移捕获、定向送键和窗口操作。兼容适配器继续使用已验证的 tmux 调用规则。
  2. 处理直接执行 tmux 的旁路。基线用 Go 文件筛查得到 30 行直接调用匹配，包含测试。按用途识别旁路并按落点复核，迁移后以直接调用集中在兼容适配器和对应测试为准。
  3. 原生提供者接入后按会话能力开放入口。业务代码用台账和能力查询决定操作，停止、历史与受管任务保留真实证据。
