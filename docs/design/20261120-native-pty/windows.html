Windows 整包移植

Windows 11 24H2 或更新的受支持版本先验 x64。ConPTY 探针与 Unix 原生宿主试点并行，Windows 节点独立过发布验收。

同一批探针比较三种 ConPTY 封装

  • crosspty v1.2.0 优先。 采用时新增 Go 模块，最低 Go 1.24.0。能悬挂启动、分配 Job 后再恢复。现有 Job 句柄封装在库内，默认组清理与 Roami 的证据、内存约束需要对齐。成功启动后，库的 Close() 执行进程终止流程。客户端断开只取消订阅。检查非默认 Job 限制、只关闭 I/O、崩溃后进程组退出、输出排空和失败清理能否通过包装或小改实现。
  • go-pty v0.2.3 作对照。 采用时新增 Go 模块，工程与 CI 的最低 Go 版本需要升至 1.25.0，同时评估传递依赖。核对主线程与 Job 控制、进程等待证据和关闭排空。当前版本的 Windows 启动路径在库内关闭主线程句柄，使用悬挂启动时要验证放行机制。
  • 直接调用 ConPTY 作对照和回退。 若库需要绕过其进程模型才能满足宿主管理契约，使用现有 x/sys/windows 写薄适配器，复用 Microsoft 原生 API。启动时 EXTENDED_STARTUPINFO_PRESENT | CREATE_SUSPENDED，将进程放进 Job，再 ResumeThread。

在 crosspty 的 Windows 实现中，WaitForSingleObject 未确认进程终止，或 GetExitCodeProcess 取退出码失败，都可能使 Wait() 返回 -1。这一个返回值无法区分两种情况。宿主缺少独立证据时保留待确认状态和工作区围栏。

为三种候选录制相同的交互与进程场景。验证嵌套 Job、JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE 或等价的退出回收证据，确认只有目标 Job 受影响。PTY 输出排空和进程退出分别观察。同步管道使用独立读写循环，由收尾路径关闭 ConPTY；24H2 的 ClosePseudoConsole 可立即返回，仍以管道 EOF 或保留的截断证据及进程结果判定终态。

24H2 起有公开的 ReleasePseudoConsole 让控制台随最后一个客户端断开退出。crosspty 对之前的系统版本存在访问旧 HPCON 内部布局的兼容分支。首发基线要求公开 API 路径，旧版本兼容独立评估。Windows 真机结果决定封装选型。

模块Windows 方案与验证
存储、工作区围栏、Agent 注册、浏览器标签用 Windows 专用锁实现替换 Flock。验证 LockFileEx 的共享/独占范围、非阻塞错误、进程退出释放和其他打开者语义。不同进程统一锁同一字节区间，覆盖路径大小写、工作区别名和拒绝时的围栏状态。
磁盘容量和内存守护Statfs 对应 GetDiskFreeSpaceExW 所需容量字段，验证目标卷和用户配额。Job Object 验证有效的进程树和内存策略。Unix 压缩交换区、信号暂停/恢复暂按能力关闭。
宿主监控和手机模拟器隔离 Setsid、Setpgid 和 Kill 调用。只启用 Windows 实际支持的功能，查验禁用路径不会阻塞核心节点启动。
用户身份与 IPC试点用登录用户的计划任务运行独立宿主，保持其 home、profile、环境、凭据访问及节点绑定。命名管道显式 DACL，校验用户或登录 SID，启用 PIPE_REJECT_REMOTE_CLIENTS，锁屏与登录切换均测试。系统服务的 Session 0 行为单独验证。
安装、签名、升级试点用有校验和的 ZIP，正式包评估签名的 MSI 和 SmartScreen 表现。安装注册用户级宿主，卸载与升级遵循排空策略。验证安装路径含空格、用户目录非 ASCII、最小权限、升级失败回滚。

PowerShell 与 Agent 入口

依据宿主绑定用户的显式设置与受信任安装位置探测 pwsh.exe 和 powershell.exe。首发优先 PowerShell 7。5.1 作为独立选择，完成其输入、编辑和退出验收后才启用。用户指定的 shell 缺失时保留选项，并返回可处理的安装或切换提示。

原生 .exe 用绝对路径和按目标约定编码的 UTF-16 命令行启动。npm 安装可能给出 codex.cmd 或 claude.cmd，不能把批处理的路径当原生 PE 传给 CreateProcessW。先验证注册的原生可执行文件或可识别的 Node 入口。确需使用批处理包装器时，单独识别 PATHEXT 和受信任入口，经适配过引号语义的 cmd.exe 启动。验证 cwd、空参数、尾部反斜杠、引号、非 ASCII 与用户 PATH。受管任务的提示沿原有输入和绑定协议交付。

开放原生 Windows 节点的条件

  1. PTY。 在真实 Windows x64 上对比三种封装。测试启动失败、阻塞输出、Ctrl+C、关闭排空、Job 清理、句柄回收与两个并发会话隔离。重复同样测试后再声明 arm64。
  2. 交互。 PowerShell 7 与所声明的 5.1 选项，使用真实 PSReadLine、中文、多行粘贴、窗口调整。Codex 与 Claude Code 分别验原生和适用的 npm 启动方式，验证全屏交互、分离后存活和关闭时进程归属。
  3. 整包。 在干净 Windows 上通过构建、安装、权限校验、系统用户工作区和 CLI/Web 重连。重启 Web 服务和升级宿主版本时接回旧窗格，回滚后原归属仍可连接；失败证据不导致清除工作区围栏。
