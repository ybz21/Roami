产品设计

用同一套 Roami 会话入口，在 macOS、Linux 和 Windows 上接回正在运行的原生终端。

第一阶段体验

现有 CLI 和 Web 的普通会话入口继续使用稳定会话 ID。创建时由宿主根据平台与设置选 shell，用户可以覆盖。原生会话首轮提供单窗格、新建、连接、分离、重连、会话列表、捕获和关闭。普通会话支持现有的文本与按键入口。Windows 从原生 PowerShell 7 起步。节点探测已安装的 PowerShell，经过验收的 5.1 可由用户显式选择。

窗口、分屏、会话内上下文和受管任务是后续切换条件。原生后端按检测到的能力开放操作，例如 Windows 的暂停能力需要单独设计与验证。切换默认值之前，正在运行的旧会话继续通过旧入口可用。

电脑和手机如何接管

  • 拥有权限的客户端点按终端进入输入状态，或在终端聚焦时输入首个实际按键，以此请求控制。获得控制后提交本机有效尺寸并发送这次输入，失败给出可操作反馈。挂载、后台探测与浏览历史不会接管。
  • 同一时间一个前台客户端控制。各端跟随宿主确认后的尺寸重排，显示谁正在控制。被动查看的窄屏保持字号，允许水平查看溢出内容，点按可接管并按手机宽度重排。明确的只读客户端保留查看权限。
  • 控制方分离或流失联后释放控制，尺寸保留到下次接管。不设空闲回收时间，以免读屏时频繁切换。旧控制方迟到输入和 resize 按代次丢弃，尺寸守卫沿用现有下限并合并手机键盘、地址栏和旋转触发的变化。

用户故事与场景原型

展开查看每种操作对应的会话状态和可见反馈。

在 Windows 打开 PowerShell

作为 Windows 用户，我要在项目目录里打开原生 PowerShell，使用本机 Git、脚本和终端工具。

  1. 在项目中创建终端。节点用项目目录和当前授权用户启动 PowerShell 7。
  2. 看到 PowerShell 提示符。输入、输出、中文路径和窗口尺寸走同一个终端连接。
  3. 节点缺少 PowerShell 7 时，创建返回可处理的安装提示。安装后可以用原目录重试。
在手机上接回桌面的终端

作为开发者，我要离开电脑后能继续操作正在运行的程序。

  1. 桌面关闭终端页面，程序继续运行。手机从会话列表打开同一个会话。
  2. 手机收到屏幕快照和后续输出。点按终端接管后，输入和有效尺寸跟随手机，其余客户端跟随新尺寸。
  3. 同一个程序继续运行。若它在离线期间退出，页面显示退出结果和最后的可用输出。
服务更新后继续工作

作为节点使用者，我要升级 Web 服务之后仍能接回现有终端。

  1. Web 服务重启后按宿主身份接回原进程。升级宿主软件时，原宿主持有现存会话直到自然结束，新会话由新宿主接收。
  2. 宿主暂时不可达时显示状态待确认。输入和继续任务等待宿主状态或其他可靠证据。
  3. 确认宿主或窗格已退出后，按现有恢复策略保留历史。符合条件的会话可以新建进程并接续已识别的 Agent 对话。
继续运行中的旧会话

作为已有 Roami 用户，我要在试用新终端时继续接回 tmux 中原有的工作。

  1. 同一会话列表展示旧会话与试用期的新会话，连接时按各自的后端归属路由。
  2. 退出试用后，新建会话回到原来的默认后端。仍在运行的原生会话保留自己的连接路径。
  3. 旧会话退出后，可在原项目目录新建原生会话。如果用户明确恢复支持的 Agent 对话，保留恢复来源关系。

切换默认值的条件

  • 三平台真实终端通过交互验收，Web、CLI 和 Android 同一会话重连无重复与丢失。
  • CLI 窗口和分屏、Web 活跃窗格与屏幕捕获达到相应验收项，或在试用范围明确标注可用功能。
  • Codex 与 Claude Code 的启动和继续按节点能力验收。托管任务以宿主和执行器的结构化证据更新状态。
  • 对已纳入支持范围的平台，打包、安装、升级和回滚都经过实测。
