打开设计与可点击原型

产品设计

问题与目标

现有目录把类型“偏好”与范围“个人／对话／项目／任务”放进同一筛选；同一行反复展示标题、正文、展开和来源按钮。列表内展开挤乱阅读位置，手机来源弹窗截断长内容。统一目标是让用户快速回答：记住了什么、适用于哪里、来自哪句话、如何纠正。

入口与信息架构

桌面首页保留右侧“任务／消息／记忆”工作台；记忆头部的展开入口进入完整浏览，设置旧入口继续兼容。手机从已有记忆入口打开全屏二级页，不增加主导航项。目录默认“已记住”，旁边为“待确认”和“每日足迹”；“待确认”同时容纳候选与冲突，冲突显示文字提示，计数为零则隐藏。足迹是使用统计，不混入可复用记忆。

首层只放搜索和范围选择，默认全部范围。个人长期、项目、对话、任务是范围；偏好、事实、决策、摘要是类型，收进可展开筛选。选择项目／对话／任务范围后，完整实现提供对应实体选择，不能把“范围类别”冒充某个实体。“对话”筛选指存放在该对话的记忆；个人长期单独列出，不用“当前可用”暗示当前回答已采用。

列表与详情

列表使用平面行：短标题、最多两行正文摘要、适用范围和更新时间。去掉日期主分组、永久总数栏、每行来源与展开按钮；整行可键盘和触摸打开详情。非当前范围显示具体项目／对话／任务名称，缺失名称显示“来源不可用”等可读状态，完整 ID 仅在技术详情中。搜索支持标题、正文，范围选项和类型共同过滤，空结果提供清除筛选；只有一页时不显示分页。

完整桌面浏览为列表与详情并排，两区独立滚动；窄工作台在同一面板内从列表切详情，返回恢复筛选和滚动位置，不新增第三栏。详情依次呈现完整内容、真实状态、适用范围、来源原文和折叠变更记录。个人长期说明“可在其他对话中检索使用”，不声称每次都会使用，也不填造召回次数或最后使用时间。

来源在详情中直接预览原句、对话名称和时间，打开来源对话定位原消息；返回记忆恢复位置。多来源分别展开，来源变化或不可用显示相应状态和恢复动作，不清空记忆正文。归并的旧对话副本放进变更记录，只保留一条有效目录项；不在客户端做模糊去重，不隐藏未确认的真实冲突。

待确认、删除和足迹

候选详情先展示内容和来源，再确认记住或拒绝。冲突同时展示现有记忆与待确认内容，确认替换前使用短确认框，旧版本保留。来源变化需重新核实，不能在未加载可靠来源时确认。删除记忆与彻底忘记继续放在更多菜单，确认文案明确“保留来源”和“屏蔽后续上下文”的区别，沿用后端真实语义；失败保留列表、详情和选择，不伪报成功。

每日足迹按日期、项目浏览，列表仅呈现对话轮数和任务完成数，详情展开已有活动统计；没有记录的指标显示“未记录”，不补零。原型使用明确的示例统计，不推断生产活跃度。

手机与状态反馈

列表、记忆详情和来源对话都是 URL 管理的全屏二级页，只使用一层等高返回栏及一个内容滚动容器，保留四个底部入口。返回不叠加 overlay history；候选确认栏位于滚动区外，由 MobileSubPage 统一避让安全区和键盘。搜索、过滤、详情返回保留当前位置。图标有可访问名称，触控目标至少 44px，悬停只对鼠标生效。加载采用占位；后台更新失败保留最近列表，显示短错误和重试，不新增永久刷新按钮。

用户故事

  1. 我在工作台扫一眼就能看懂已保存的偏好和适用范围，不必逐条展开，也不会看到归并后的两条副本。
  2. 我可以搜索 Codex，点开记忆看到原话及来源对话；查看来源后返回原来的列表位置。
  3. 我可以区分个人长期与某个项目／对话／任务的规则，不误以为已保存就意味着每次回答都会采用。
  4. 我能查看待确认内容，发现与现有偏好冲突时先对比原文，再决定替换或拒绝；网络失败不丢失当前查看内容。
  5. 我在手机上能完成搜索、筛选、读全文、查看来源、返回与删除确认，长内容不被小弹窗截断。
  6. 我可以单独查看每日足迹；它不挤占偏好和知识的目录，不把未知统计当作零。

查询、状态与接口边界

沿用 GET /memories/catalog、GET /memories/{id}/sources、POST /memories/{id}/confirm 和 DELETE /memories/{id} 的所有者与范围边界。目录状态名映射为已记住 active、待确认 candidate＋conflict、每日足迹 category=activity；候选＋冲突必须在服务端统一筛选、排序、计数和分页，不能客户端分别抓一页再拼接。范围类别筛选同样在服务端分页前处理，具体实体继续传 projectId／conversationId／taskId，类型单独使用 kind。

已补充只读详情 GET /memories/{id}/detail 与按需历史 GET /memories/{id}/history，支持 active／candidate／conflict 的详情与关联当前版本，返回可读实体名称、来源状态和受所有者约束的归并／修订历史。历史只沿可信 canonical_key、supersedes_id、memory_edges 及相同来源指纹追踪，不因共享一条来源就把不同内容合并为版本。来源证据加载及确认提交继续复验，客户端不从标题或摘要推断冲突。原 GET /memories/{id} 的有效记录语义保持；目录新增 state=review 与 scope，GET /memories/facets 返回同一视图下的可读实体选项及待确认数量。确认提交携带 expectedCurrentId，来源及版本变化返回冲突，保留当前内容供重新核实。

扩展现有 home/memory/{origin} 路由的记忆详情／来源状态，保留节点参数和来源返回路径；旧 settings/agent/memory 链接映射到完整目录。筛选保存在 URL，草稿和滚动按节点／视图保留；回退、刷新和横竖屏不丢选中项。复用已有事件与可见性刷新，不新增逐条轮询；详情与来源按需加载，忽略过期结果并合并并发请求，辅助失败不覆盖正文。未知召回关系不展示，真实召回证据仍从对应回复的执行记录查看。

设计阶段交付与验收边界

设计阶段交付可点击示例原型；以下为原型阶段的隔离边界，正式实现见落地修订。原型复用项目主题令牌、图标、全局 i18n、useLayout 与 MobileSubPage；中英文切换只翻译界面，示例用户原文保留中文。浏览器原型使用 sandbox、内存偏好和禁出网 fetch，不写实际服务配置。底部主导航为宿主环境示意，本轮可操作范围为记忆浏览及其详情、来源、筛选、候选确认、删除和返回。开发者设计正文使用中文，属于 i18n 文档例外。

验收计划：桌面完整浏览与工作台、手机真机搜索／筛选／返回／滚动／键盘；中文深色和英文浅色；加载、失败与空结果；确认替换、拒绝、删除取消及来源变化；页面无文档或横向溢出。原型验证不等于业务接口已实现，落地验收另需服务端范围与分页、所有者隔离及来源失效测试。

落地修订 · 2026-10-22

用户确认后，实际 AgentMemory 已替换为同一套目录／详情组件，完整页面、桌面工作台和手机入口共用查询与路由。删除旧卡片组件和样式；完整页面打开期间只保留原对话事件连接，不再挂载隐藏的第二份记忆工作台。旧设置地址继续显示完整目录。范围、类型、实体、搜索、分页与选中项进入 URL，搜索和筛选替换当前记录，选择详情增加一条历史；Android 返回逐层恢复，列表滚动按节点及筛选保留。
