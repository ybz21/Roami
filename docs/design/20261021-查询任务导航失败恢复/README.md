# 查询任务导航失败恢复

关联 #395。原请求已创建 native 任务，随后来源站点连接超时。原标签保留 Chrome 错误页及 ERR_CONNECTION_TIMED_OUT；驱动将它统一记录为未知结果，整个查询中断。原任务存在与查询成功是两件事，不能把入队宣称为交付。

只在 `page.goto` 明确拒绝、且错误为已列举的网络失败时记录 `CHROME_NAVIGATION_*`。回执为失败、结果已知、输入已停止；worker 重新观察同一资源，再在原任务内改用可访问的来源，不重开任务或重放表单。保留具体网络错误分类，便于链路排查。

不改变超时配置。等待生命周期超时、CDP 连接丢失、取消/ERR_ABORTED、未知异常和 click/fill/press 等输入动作继续保留未知语义。场景、owner、lease、幂等和控制权校验保持原有规则。旧任务的未知历史不能因代码更新改写为已知，更不能自动重跑。

自查与验收：真实原任务只读核对卡片入口、详情、过程及会话；隔离 Runtime 验证失败来源后同任务同标签继续成功；真实 Chrome 验证失败导航回执与备用来源；自然原题和济南天气各三轮真实 Main 建任务测试，结果与执行器测试分开报告。新增回归覆盖连接超时、拒绝、DNS/空响应，以及真实未知不降级。既有 #352 的回复文风和 #388 的唯一项目匹配仍独立跟踪。

## 本机目录与外部检索

原题真实 GLM-5.3-flash 三轮复测：一轮建任务，两轮仅调用 `tool_list(kind=mcp)` 后凭记忆列免费额度，未建任务；济南天气三轮均建任务。失败记录保留，不能只以截图中已有任务推断分配稳定。Main 的 MCP 列表按角色过滤，零条尤其不能证明节点未接入 MCP。

目录回执明确 `scope=current_role` 和用途边界；Main 提示词区分本地可调用能力与外部服务事实。查当前额度/价格等外部事实需要实际检索，不能用目录结果代替来源、凭记忆填数字或擅自改成安装服务。用户明确查本机接入情况时仍直接使用目录，不强制一切问题派任务。

当前修后复测：同样两题各三轮，真实 Main 6/6 建任务（MCP 3/3、天气 3/3）；私有真实 Chrome 三轮连接拒绝后均在同标签打开备用来源；原始生产任务桌面及 Android 卡片可进入详情、过程和会话。以上分别验证分配、浏览器驱动和展示，不将“已建任务”计为最终事实交付。

反例各三轮：列出当前对话可直接调用的 MCP 工具、解释 MCP 概念，均未创建外部任务（6/6）。另外覆盖首次打开来源即失败：保留已创建标签的 resourceId，使 worker 能观察它，而不是遗失资源标识后再开标签。
