# 原 Skill 发布与平台回执：机制草案

交互原型为 [publication-native-skill.html](publication-native-skill.html)。本文与原型为设计草案，不代表已部署能力。

## Product Design

保留独立项目 Main、原 X/B站成员和数据成员。用户与 Main 对话；Main 审核当前内容后，通过原成员的 Skill 继续已确认的真实通道。历史 X 手机 ADB、B站网页成功路径不是必须改成新 API 的理由。现行设备、账号边界仍有效，范围没有明确前不触设备或账号页。日常自动模式不附加逐条人工批准。

群聊呈现实际交接和阻塞，不能代替受管续派。已审核、已提交、平台已确认、已取数分开记录；错误或未知不能被绿色“已发布”覆盖。发布未知后只读对账，找不到匹配项不足以证明未发布。一个真实发布事项保持同一业务键，旧冻结版本和旧尝试留在历史。

## User Stories

- Main 审核通过后，仍由原实例执行；新轮次只追加任务，用户可以进入渲染或原生对话。
- 提交失去回执后，原成员和 Main 查原尝试，不重开实例、换键或自动再次点击发送。
- 平台确认后，原数据成员对新平台对象执行 Connector，Main 确认看板并复盘、续派。
- 执行范围未明确时保留已审核素材，明确停在哪个外部动作；不把它伪装成内容审核失败或永久人工审批。

## Technical Design

多个 OKR 复用 Go CLI/网关与 Python 协调运行时，不新增一套 C 进程间消息总线。项目目录保存定义、Skill 和物料；运行时 SQLite 保存受管身份、命令与事实索引。每条通信和发布记录同时限定 owner、project、Main 与 Swarm，解析原成员和当前 task/run；消息中的旧实例引用不能切到首页 Main 或其他项目。群聊持久记录、成员收件箱、受管续派和完成回调分层处理，投递回执不替代执行或验收。

现有 `publication/automatic_mode.py`、`approved_assets.py`、`publisher_identity.py`、`post_journal.py`、`reconciliation.py` 是内部基础；已注册 prepare/review。以下执行与事实接口仍需实现，不是可直接调用的 CLI。

1. **完整批准输入。** 当前正文/图片可冻结，原项目五条已有真实 Main 审核。实际 X ALT 仍是侧车文本，未被当前 content schema 单独绑定；B站音视频审核也尚未支持。执行前必须让真实使用的正文、图片、ALT、字幕、音频和视频都进入不可变版本与独立审核，不能用当前五份正文/图片批准覆盖所有侧车变化。
2. **发布批次与原实例。** Main 形成固定版本/审核/账号/通道清单，续派原成员。绑定 project/Main/swarm/member、真实 task/revision/run、release 和每条业务键，核对实际 applied steer 证明。制作作者可以推进后续轮次，批准素材通过不可变版本保留，不要求永远停留在制作轮次。
3. **通道与账号。** 通道以已确认的项目 Skill 与包摘要声明，Python/MCP/API 或原生 UI 均为实现方式，不强制 OAuth/API。公开作者 ID 是身份候选，不是当前登录；执行前核对所用资源和真实账号，声明的账号不能由成员自己改成另一个。凭据不进入项目、群聊或记忆。当前用户对手机/人工账号页的范围澄清仍未收到，不在草案中替用户回答。
4. **提交前持久记录。** 复用 `swarm_commands` 的发布事项账本：版本、账号、资源、业务键和尝试身份确认后，先记录 submitting，再交原 Skill 操作一次。重启或另一次 tool call 不自动产生第二次发送资格；上传和最终提交分别记录，上传成功不是已发布。
5. **保留实际结果。** 已知平台 ID/URL 立即留存，即使任务随后停止也保留事实。成员回报只作为待核验候选；未知仍是未知，不能靠写本地 receipts.json 或改 task 状态证明已发布。
6. **独立平台核验。** 宿主/独立 Main 对已知平台 ID 做只读核验，匹配账号、正文及媒体，保留原始响应与采集时间。URL 仅允许已确认平台和合法对象 ID，不开放任意 URL 抓取。X 图片经过平台转码，不能把平台 JPEG 与上传 PNG 字节相同作为条件；需保存上传媒体身份与当前版本的关联，核对平台公开媒体。检查模块不产生 POST 或发送权限。
7. **具体平台事实验收。** 现有 `swarm_verify` 明确拒绝 external_action，自报 consent 不能绕过。需要专用宿主事实入口将上述可信发布记录用于验收，保留其他外部动作的原限制；不能改成接收任意 URL、通用外部动作或成员声明。
8. **取数、记忆与下一轮。** 原数据成员用 Connector Skill 采集实际新对象；Main 按项目 revision/批次业务键确认数据，验证 HTML 数据接口与卡片。来源失败保留旧值，未知不补零。Main 用团队记忆 CAS 追加已核验经验，记录实验窗口与下一任务，继续原实例。

## 接受条件

- 隔离测试覆盖跨 OKR/账号/成员/旧执行拒绝、素材变化使旧批准失效、同一业务键不能重复提交、停止后保留平台事实、未知不自动重试以及核验模块零 POST。
- 原型中的结果未知场景不把“执行发布”标为完成；范围待明确场景不能继续发布。原型全部结果显式为演示，不生成真实回执。
- 真正验收必须是原 Main 和原成员完成实际发布、新对象取数、看板核对和记忆复盘，连续至少两轮。当前实际新发布循环仍为零；设计和模拟测试均不代替它。


## 本轮实现候选：图片 ALT

content.imageAlts 以数组位置与 images 一一对应，路径仍相对发布清单所在目录。原准备入口冻结其文本字节，版本摘要与内容摘要包含有序 ALT 引用；Main 必须在实际模型上下文中完整读取这些冻结文本后才能批准。改变 ALT 会生成新版本并使旧版本的批准不能继续使用；没有放开账号、发送或外部动作验收权限。旧的不带 ALT 的版本仍按其原始输入处理，不冒称已审核任何侧车文本。

模块涉及 storage/publication_versions.py、dispatch/publication_review.py、tools/publication_catalog.py 与错误恢复说明。继续复用现有不可变版本、artifact_read 和模型图像证据，不新增数据库 schema。原 Skill 执行、实际平台回执以及视频/音频审核仍是后续工作。
