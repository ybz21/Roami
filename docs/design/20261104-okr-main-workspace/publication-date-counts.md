# 日发布量与登记集合

关联 #833。

## 产品设计

日节奏判断使用平台发布时间换算到项目时区后的日期。登记集合覆盖数、采样日期和素材目录日期是不同概念，不可互相替代。未知发布时间不算零，也不能从目录名猜。

## 用户故事

Main 在每天复盘前读取当前账号的实际日发布统计，能区分今天新发和历史登记；同一个平台对象重复采样或重新登记不增加发布次数。纠正数字不会自动扩大已有发布权限或改变节奏。

## 技术设计

真实集合库已逐条正确保存 publishedAt（带时区），与12条B站公开响应 pubdate 一致：无需新建库或重写历史。扩展既有 collection_store.py 的 list-publications，提供配对的 --published-on YYYY-MM-DD / --timezone IANA 参数。以 datetime 的时区转换和自然日区间选择记录，明确输出登记覆盖数及该日去重对象数，保留每条原始时间和证据哈希。

按 platform/accountId/objectId 去重，不按 businessKey 或采样次数计数。同一对象的发布时间发生冲突时返回明确错误而不是猜一个日期；不完整、无时区或非法时间不落成虚假0。默认未传日期时保持既有 Connector 全集合读取兼容。Main 和手册必须显式使用日统计，不自行对全集合长度套日频限制。

现有 X 回执已保存平台发布时间，当前集合库仅包含 B站记录；不能声称给 B站集合库加过滤就自动覆盖 X。X 复用其实际回执来源做相同的时区与去重处理，或由 Main 独立核验后按原注册协议补登记，不能制造发布事实。

## 验收

覆盖 UTC/上海日期跨日、不同 offset 表示同一时刻、历史稿当天登记、同对象重复登记/重复采样、时区与日期参数缺一、未知和冲突时间。真实只读回归应得到登记12条、上海时区11月9日10条，不改宿主确认观测或看板。生产审计候选位于 materials/2026-11-09/data/publication-date-audit，需原 Main 独立核验，不能当成已经完成代码修复。
