# 团队与会话入口一致

## 产品设计

当前团队名单是共同入口：左侧对话目录与右侧协作场景显示同一组成员和相同名称。未派发或尚无原生会话的成员仍有位置，以真实任务状态显示，不能因为未上线而从动画消失。Main 使用与目录相同的名称。群聊是共享通信入口，不另造一个智能体。

旧职责的会话归档后从主要会话目录移出，历史内容和失败/不确定回执保留。不能只修改标题为“历史”，却继续让旧任务排队；执行器迁移由用户明确授权，当前角色绑定切到新执行器，旧历史不冒充新 provider 的记忆。

## 用户故事

- 新增评论运营或更换为 Claude 数据分析后，未首次启动也能在目录和协作场景找到该职责。
- 从任一处选择成员，都选中相同 memberId，并进入该成员的对话；没有实例时给出真实任务入口，不发给 Main 或别的旧会话。
- 当前角色与历史角色区分；归档不删除原对话，当前任务的每轮继续复用已绑定原生会话。

## 技术实现

`swarmRoleMembers(...).current` 作为当前团队的唯一投影，同时提供给 `SwarmConversations` 与 `SwarmStudio`。场景不再按另外一份在线 session 名单裁剪成员，姓名、身份和状态都沿用同一个角色对象，减少一个场景专用 native-session 订阅。

场景选择仍通过 `selectMember → openChat(memberId)`；打开真实终端/渲染对话时，`SwarmMemberChat` 的新鲜 task/revision/run、节点/项目/原 Main、provider 执行器和会话关闭检查全部保留。可见的逻辑角色不等于可用的原生会话，不因此放宽路由边界。

原生历史会话通过宿主 `close-session` 的 revision/run CAS 归档；现有 native-session 列表过滤 closed/closing，历史原文仍由显式历史接口读取。禁止直接改 task/busy，禁止按标题是否含“历史”推断成员身份。

首次启动失败携带预留 sessionId 的续派缺陷独立跟踪于 #880；它需要运行时修复，不能通过新开替代成员或在前端假造在线状态解决。
