# 用户原文与 OKR 草稿分离（#777）

## 产品设计

用户在原项目 Main 输入的消息就是实际的人类指令。页面不再附加旧的禁发指令、项目手册、团队记忆、Skill 全文或历史看板。继续复用首页的完整输入、流式正文和工具过程；不增加按钮、确认步骤或新实例。

已确认的配置、能力和数据由 Main 通过绑定当前项目的受管工具读取。Studio 未保存的改动仍能随当前问题讨论，但属于参考数据，不能成为授权、真实数据或已保存结论。

## 用户故事

- 用户要求自动审核、发布和取数，服务端收到的 text 与输入原文一致，不混入相反限制。
- 用户修改未保存的 O/KR、看板或分工再询问 Main，Main 能看到这份草稿及其基准修订，同时知道它尚未确认。
- 网络丢失回执时，复用同一请求键、原文和冻结草稿；刷新和后续编辑不改变旧请求。
- 原 Main、成员、群聊与历史保持原身份；旧消息可查，生成的历史附注不能授予执行权限。

## 技术设计

`messages` 接口新增可选 `okrContext`，版本 1：`{version:1,revision,draft?}`。不接收客户端 projectId、目录、成员身份或额外指令。draft 仅允许配置字段；整个 JSON UTF-8 上限 64 KiB，超限保留输入并明确报错，禁止静默截断。正常已保存对话仅传版本和修订，不重复配置。

服务端在同一 intake 事务内核对真实 conversation identity 为 project_main；拒绝首页、原生成员和不属于当前用户的会话。绑定项目由服务端决定。JSON 单独保存在消息 content.okrContext，text 不变；非空元数据参与请求摘要，保持无元数据旧客户端摘要不变。附件、命令及计划唤醒继续保留既有协议，斜杠命令不带草稿。

上下文投影把草稿作为明确的未可信参考数据，不能替代真实 project_okr_context/受管 Swarm 回执。它不进入用户授权引文和用户偏好提取。共享 pending/outbox 冻结 text 与元数据，未知结果重试不生成新请求或变更草稿。

历史 `<roami-okr-context>` 附注不改数据库：仅识别旧页面的 JSON + 固定说明 + 结束标签组合，在模型投影和授权引文中使用前面的真实输入；保留原 content、source hash 和历史明细。新版有版本字段的消息按字面保留，即使用户主动输入同样的标签。分页在截断前处理旧附注，列表仅保留新版版本/修订标记，不携带草稿；即时发送的乐观消息也保留同样标记。完整历史明细继续返回原字节。审核使用相同的人类原文边界，同时原始历史依旧可追溯。受影响来源的旧摘要不再用于模型投影，保留原摘要记录，以新投影规则重新生成；普通对话旧摘要仍可用。模型估算的请求版本同步更新，避免复用附注被移除前的用量基线。仅最新用户消息的草稿进入模型参考，历史草稿不重复堆积。已存在委托恢复必须重新验证其引文仍属于人类原文，不能借历史附注延续权限。

宿主状态声明 `okrMessageContext`。新页面在不支持的宿主上允许已保存对话按原文发送；有未保存改动则保留输入提示升级，避免静默丢草稿。不探测写入、不降级到旧的拼接协议。

## 验收

验证真实 HTTP intake、请求键冲突/重放、附件、首页/成员隔离、历史附注授权拒绝、新版标签字面保留、模型参考投影，以及完整共享 composer 的即时与 outbox 路径。前端全量与受影响后端专项/完整检查按仓库门禁执行。真实 UI 仅使用自有 QA 浏览器；不操作手机或人工浏览器。
