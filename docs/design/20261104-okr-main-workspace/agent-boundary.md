# OKR 与通用 Agent 的职责边界

## 产品设计

普通对话只需要会话和消息。项目页决定某个 OKR 使用哪个 Main、团队和项目目录，将已核验的会话交给统一聊天组件。各项目在自己的目录里定义目标、团队职责、看板、Connector、复盘和定时策略。项目层把这些能力登记为工具和 Skill，并在调用时校验当前会话的归属。

用户回到已有项目时继续使用原 Main、Swarm、成员和历史。操作重复投递时，原回执仍可查。项目的不可信草稿是参考数据，授权和实际待执行请求独立保存。定时唤醒沿用原 Main，遇到已有工作或未答复的问题由宿主拒绝此次唤醒。

## 技术设计

| 层 | 职责 |
| --- | --- |
| 通用会话和工具 | 会话创建与查询、消息准入、请求去重、原子写入、执行状态、活动流、任务与工具调用 |
| OKR 产品适配 `roami_okr` | 主会话归属、注册项目与团队校验、草稿校验、定时准入、项目文件读取范围、目标与项目团队工具、团队记忆、编写 Skill、日程证据、原生 Main 绑定与能力校验、协作批次策略 |
| Go 项目服务与项目目录 | `.roami/okr` 定义与版本、看板、Connector、复盘和记忆的实际数据、回执与持久写入 |

生产宿主装配 `roami_okr.http` 以保持现有 Go 网关和客户端路径。基础 Agent HTTP 的请求只包含会话创建和消息字段。现有 `projectId`、`okrContext`、`/wake` 的兼容定义由产品入口处理。

创建项目 Main 时，产品解析器复用 Agent 的会话创建事务和幂等记录。在同一事务内校验旧绑定和预期会话，保留既有摘要算法与请求作用域。草稿和定时入口交给通用消息准入执行归属校验、去重、写入和唤醒。已接收请求的重放沿用原回执。未接收的定时请求需在同一事务中通过空闲检查。这些改动沿用已有数据库表和键。原生 Main 的项目身份、模型指令、能力和运行代次由产品适配处理。调度器接收对应的目录查询，在现有队列中调度，无需解释项目字段。Swarm 通过可选存储适配读取项目团队记忆，工具目录通过可选策略投影当前批次。产品后端不可用时，项目记忆写入继续失败，避免生成备用副本。

## 仍需迁出的依赖

| 位置 | 现状与迁出边界 |
| --- | --- |
| `storage/swarm_scopes.py` | 团队隔离仍直接查旧项目映射。身份判定和首页应排除的既有会话由产品适配负责。先提供通用的持久会话归属与独占绑定，再迁移现有身份；保留首页与项目隔离、跨账号校验和旧会话 ID。 |
| `conversation/okr_message_context.py`、`conversation/pages.py`、`context/projection.py` | 历史读取认识旧产品字段和文本标记。后续由产品适配将旧消息投影成人类文本与引用数据，并验证分页、搜索、摘要失效、任务来源和引用兼容。原历史字节和消息 ID 是迁移基线。 |
| `dispatch/swarm_provider_generations.py` | 成员绑定仍查询旧项目 Main 表，防止重用已归属的 provider 或 session。后续用通用的执行器身份注册表统一校验唯一归属，并保留原代次、会话和已完成回执。 |
| `dispatch/swarm_plans.py`、`storage/swarm_repository.py` | 旧团队存储仍识别项目绑定。过渡中由产品适配管理日程、记忆与协作工具，后续需让团队接口接收已核验的通用资源范围，并沿用旧项目、团队和回执映射。 |
| `commands.json`、`skills/roami`、`storage/migrations.py` 及 SQL | 旧命令名、文档资源和已装实例的迁移入口仍在当前发布物。产品命令与资源待独立注册，旧迁移编号与已安装库保留可升级性。 |

本阶段代码可在原运行时包内随产品一起交付。通用 Agent 对端到端的产品依赖仍需完成上表迁移。
