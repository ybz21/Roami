# OKR 与通用 Agent 的职责边界

## 产品设计

普通对话只需要会话和消息。项目页决定某个 OKR 使用哪个 Main、团队和项目目录，将已核验的会话交给统一聊天组件。各项目在自己的目录里定义目标、团队职责、看板、Connector、复盘和定时策略。项目层把这些能力登记为工具和 Skill，并在调用时校验当前会话的归属。

用户回到已有项目时继续使用原 Main、Swarm、成员和历史。操作重复投递时，原回执仍可查。项目的不可信草稿是参考数据，授权和实际待执行请求独立保存。定时唤醒沿用原 Main，遇到已有工作或未答复的问题由宿主拒绝此次唤醒。

## 技术设计

| 层 | 职责 |
| --- | --- |
| 通用会话和工具 | 会话创建与查询、消息准入、请求去重、原子写入、执行状态、活动流、任务、工具调用和原生会话传输 |
| OKR 产品适配 `roami_okr` | 主会话归属、注册项目与团队校验、草稿校验、定时准入、项目文件读取范围、目标与项目团队工具、团队记忆、编写 Skill、日程证据、原生 Main 的项目绑定和工具授权、协作批次策略 |
| Go 项目服务与项目目录 | `.roami/okr` 定义与版本、看板、Connector、复盘和记忆的实际数据、回执与持久写入 |

生产宿主装配 `roami_okr.http` 以保持现有 Go 网关和客户端路径。基础 Agent HTTP 的请求只包含会话创建和消息字段。现有 `projectId`、`okrContext`、`/wake` 的兼容定义和状态能力声明由产品入口提供。通过项目入口安装的客户端继续收到原有能力键。

创建项目 Main 时，产品解析器复用 Agent 的会话创建事务和幂等记录。在同一事务内校验旧绑定和预期会话，保留既有摘要算法与请求作用域。草稿和定时入口交给通用消息准入执行归属校验、去重、写入和唤醒。已接收请求的重放沿用原回执。未接收的定时请求需在同一事务中通过空闲检查。这些改动沿用已有数据库表和键。`roami_agent.providers.native_conversation.NativeConversation` 负责通用原生会话传输，包括绑定校验、提交去重、轮询、取消确认与完成回执。Agent 也为原生会话和普通任务统一签发并原子保存私有工具上下文。OKR 为原 Main 提供项目指令、作用域和既有请求键格式。项目身份、运行代次和工具授权由产品适配处理。调度器接收对应的目录查询，在现有队列中调度，无需解释项目字段。Swarm 通过可选存储适配读取项目团队记忆，工具目录通过可选策略投影当前批次。产品后端不可用时，项目记忆写入继续失败，避免生成备用副本。

历史读取、搜索、摘要、任务引用和授权校验共用 Agent 的消息内容投影。在 OKR 产品入口装配 `roami_okr.message_content`，由它解释旧文本标记，保留草稿的版本与修订号，并只在当前模型输入里附加不可信的草稿参考。原消息字节、消息 ID、授权来源哈希和现有有效摘要继续兼容。普通 Agent 入口按原文读取消息。

## 仍需迁出的依赖

| 位置 | 现状与迁出边界 |
| --- | --- |
| `storage/swarm_scopes.py` | 团队隔离仍直接查旧项目映射。身份判定和首页应排除的既有会话由产品适配负责。先提供通用的持久会话归属与独占绑定，再迁移现有身份；保留首页与项目隔离、跨账号校验和旧会话 ID。 |
| `dispatch/swarm_plans.py`、`storage/swarm_repository.py` | 旧团队存储仍识别项目绑定。原生提交状态复用已通过的团队范围校验，从当前活跃分支和租约读取通用事件。后续需让团队接口接收已核验的通用资源范围，并沿用旧项目、团队和回执映射。 |
| `app.py` | 宿主装配仍直接导入 OKR 服务。由产品宿主注册工具、身份策略和调度回调，Agent 提供运行器及其通用接口。 |
| `publication/`、`tools/publication_catalog.py`、`storage/publication_versions.py` | 发布流程含 X、B 站的账号格式、域名和回执。Agent 提供来源核验、审批与持久回执，平台规则由预先登记的产品适配处理，执行步骤由项目 Skill 定义。 |
| `commands.json`、`skills/roami`、`storage/migrations.py` 及 SQL | 旧命令名、文档资源和已装实例的迁移入口仍在当前发布物。产品命令与资源待独立注册，旧迁移编号与已安装库保留可升级性。 |

本阶段代码可在原运行时包内随产品一起交付。通用 Agent 对端到端的产品依赖仍需完成上表迁移。

## 消息投影验收

117 项专项覆盖原文与草稿分离、旧标记兼容、消息分页、历史检索、摘要复用、任务分派和源消息授权。已确认旧消息 ID、原始正文与委托来源哈希仍可用于现有记录对账。

## 状态能力验收

60 项专项覆盖基础与项目 HTTP 的能力声明、既有 Main 的原生提交确认、项目间隔离、旧数据升级和原生路由恢复。基础入口仅公布自身支持的能力，项目入口沿用客户端已使用的六个能力键。

## 原生执行身份

Agent 核验长期成员已有的 session、provider 和 launch key。OKR 装配在同一个绑定事务内检查项目 Main 的既有保留身份，项目 Main 自己绑定时也调用 Agent 的成员检查。两个入口沿用原表和错误码，冲突时保留先绑定者、成员代次、团队修订和幂等回执。
