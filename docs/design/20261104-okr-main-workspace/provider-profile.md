# 恢复时保留配置目录模式

## 产品设计与用户故事

原Claude成员恢复后应继续使用原账号、设置和provider历史，不能因为恢复过程改变了默认
配置文件的位置而重新出现欢迎、主题和工作区初始化页面。自定义配置目录仍保持原路径。

真实复现中，未设置CLAUDE_CONFIG_DIR的实例从默认目录读取历史，但全局状态文件位于
`~/.claude.json`。恢复代码仅保存了解析后的`~/.claude`，再把它显式写入CLAUDE_CONFIG_DIR，
客户端因此转而寻找`~/.claude/.claude.json`。目录与provider都相同，配置模式却改变了。
本次没有复制旧凭据或改变模型配置；原生初始化后原provider已经恢复并产生真实回复。

## 技术设计

在SessionBinding新增可选布尔providerHomeExplicit，首次可信绑定时记录环境变量是否非空。
恢复继承原字段：明确false时删除专用恢复进程中的目录变量，明确true时设置原目录；随后
重新解析路径，必须仍匹配已验证的原providerHome。作用域仅限即将exec为provider的独立
进程，不修改父服务环境、用户配置、账户、路由或费用。

旧回执没有该字段，保留原来的显式目录恢复行为，不根据路径猜测旧实例的配置模式。
新增字段在正常状态回读中保留；false必须序列化，不能和旧回执的未知混为一谈。
沿用既有目录/主机/停止/显式关闭检查，不能为解决初始化问题绕过可信恢复条件。

## 验收

分别覆盖Claude/Codex的默认、自定义及旧回执，恢复后核对变量是否存在及有效目录；错误的
默认模式与自定义路径组合必须拒绝。JSON往返保留false与未知的区别。另跑原provider恢复
专项、仓库quick/full；截图展示实际命令结果。已经初始化的真实成员保持运行，不为测试重启。
