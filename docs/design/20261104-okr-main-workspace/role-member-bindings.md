# 职责绑定与历史成员

## 产品设计

项目的职责定义与真实成员分开保存。`.roami/okr/agents/team.json` 的职责使用明确 `memberId` 指向原 Swarm 成员；对话默认显示当前职责，过去成员仍在“历史成员”中，以原状态和原任务访问。场景只展示当前职责中具有真实活实例证据的成员。工作列表默认聚焦当前职责，“更多 / 包含历史任务”可查看全部。

这不会关闭、合并、移动或重派任何实例，也不会改变旧任务的阻塞、失败、验收及 unknown 状态。没有显式绑定的旧项目继续原显示；部分绑定失效时列出未连接职责，不用同名成员替代。

## 用户故事

- Main 始终指挥原 X、视频及数据职责成员；工作追加仍走其原 task/revision。
- 用户默认找到 Main、群聊和当前职责；需要查旧失败时展开历史，原入口仍可用。
- 修改目标或看板的旧客户端不会无意清除成员绑定。
- 项目、团队或执行器不匹配时，保存失败且确认文件与历史保持。

## 技术设计

`TeamRole.memberId` 是可选的真实成员 ID。省略/null 保留同 role.id 原绑定；空字符串显式解除。角色 ID、显示名与 task/work ID 均不替代 member ID。同一成员不能被两个职责占用；新模板不制造 ID。

SaveValidated 与 SyncValidated 在项目修订 CAS 事务中先合并旧客户端省略的字段，再验证最终配置。Go 调用既有 `roami swarm status` 读取同宿主/owner 的真实成员：团队 ID、project target、项目 ID、memberProtocol=1、非归档、成员所属团队和执行器必须匹配。只读查询，不登记或派发成员。失败不会推进确认版本。其他配置保存前的 Swarm 名称解析仍保留。

前端逐层传递项目已确认职责定义，用准确绑定产生当前/历史视图。不变更底层 Swarm 数据，不增加请求或轮询。别名只改变展示；群聊发送仍使用原 workId/taskRevision，原注册名的草稿亦可按同一真实成员解析。查看原生会话继续复核 fresh task/revision/run、owner/node/project、原实例与会话关闭状态。未连接职责不可发送给猜测收件人。
