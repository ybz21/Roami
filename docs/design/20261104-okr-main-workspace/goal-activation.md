# 持续目标启动与群聊事件唤醒

## Product Design

只保留原项目 Main 和原长期成员。持续目标产生持久启动通知，成员提问与真实结果分别唤醒原 Main。独立审核、实际发布、Connector 数据与每日槽各有回执，不以首次唤醒代替自动闭环。

[HTML 机制原型](goal-activation.html)。原型是方案说明，不是线上状态。

## User Stories

- 用户在原 Main 说明持续目标，已有角色和任务直接接续，不重建团队。
- 成员提出问题时 Main 及时处理，不等任务最终结束。暂停或 Main 忙时保留通知。
- 原任务结果返回后 Main 实际读取并独立验收，群聊回告可追溯。
- 用户授权自动模式后 Main 审核冻结的素材自动进入发布环节；平台确认与取数结果据实记录。

## Technical Design


现有事实：目标委托、受限协调批次、原成员续派、完成结果桥接和业务写入已部署；原 Data 第19轮已由原 Main 自动接回验收。目标表仍为空，模型尚无公开启用入口；没有每日生产者和真实发布通道。恢复准备服务仍在隔离副本，不是执行授权。

下一批优先接通当前用户目标→Main入口→首批派工，让已有机制开始承担真实工作；同批次恢复、每日槽及发布冻结仍保留后续交付，不以初次派工冒充完整循环。

## 用户路径

用户在项目 Main 说明持续目标及角色；Main 读取本团队当前目标版本，引用当次真实用户原文，选择既有成员启用目标。宿主保存委托及一个持久启动通知。当前用户回合结束后，原 Main 得到一批明确标记的首次目标工作，无需制造成员提问或伪造结果。启用不新建成员/任务/日程，不改变发布权限。Main 根据目标实际核对成员、续派并回报；后续真实结果使用已上线的结果桥接。

## 技术边界

- 公开工具仅是既有 SwarmDelegations 的角色绑定入口；模型不提供用户消息ID、模型账目、请求键、turn或lease。
- 启用与首批通知在同一 writer 事务；通知按原 delegation ID 幂等。当前用户源/所选成员/版本不符则整体回滚。
- 启动通知使用独立 `swarm.goal.start` job，在已有 control 容量中运行；它不是外部发布。只在原 Main 空闲且原委托仍有效时冻结批次。暂停保留同一通知，撤销/遗忘/换分支则不启动。
- 首批允许没有成员消息/结果，使用宿主确认的 initialGoal 标记；后续普通 enqueue 仍须真实待处理输入，不改已有空队列语义。启动通知重放不制造第二批。
- 受限协调目录不包含目标启用/撤销入口；成员和继续回合不能自行授权。原 Main 当前真实 user 回合是唯一写入口。
- 没有把此次启用理解为装定时任务、取得平台登录或独立素材审批。每日槽、素材冻结及真实发布必须另接宿主能力并以实际回执验收。

## 验证

覆盖真实工具/CLI发现与校验、同请求重放、失败事务回滚、初次空输入批次、当前用户优先与Main等待、双项目/首页/成员隔离、暂停/撤销/忘记/分支切换，以及初次批次→原成员续派→结果接回。完整门禁后再合入部署，通过 roami chrome 在原项目 Main 用实际持续目标验收。

## 成员提问的事件唤醒（隔离候选已接线）

record_post 在同事务写入真实成员路由、Main 收件箱及 swarm.inbox.wakeup 通知；只对原目标所选成员的当前 task/revision/run 起作用。进度消息与 Main 自己的消息不唤醒；人的群聊发送继续走既有 SwarmPlans.send→chat.submit 真实用户回合，不重复制造协调回合。通知重查目标、停止来源、原成员/项目与最新执行轮次；Main忙/暂停保留同通知，已冻结不冒充已回答，已回答不重复投递。超过首批20条的晚到提问保留到后续批次。通知与消息写入一起成功或回滚。

146项专项（含 Skill 资源检查）覆盖入口、首批、提问、结果、原收件箱及双项目范围；尚未 full/PR/部署，不计真实原项目自动循环已运行。公开入口已在同一事务强制所选角色有当前任务；素材发布授权边界及完整集成验收仍需补齐。新 Scheduler jobs 不是每日排期，插件 cron 也尚未安装。

## 定时调度的实际约束

已核对既有 plugins/cron：默认 action=agent 会新建 Agent，会破坏原Main/长期成员接续，不能用于本目标。应复用插件 action=exec 调用项目 daily-operations Skill 中的 Python 入口，再通过经过范围验证的原目标唤醒命令创建幂等日期槽。必须先实现该命令/真实目标授权、原Main空闲处理、停止和撤销，再登记仅本项目的 cron job；不能把普通提醒或只读 daily brief 当作执行生产者。保留其他项目的 cron/serve，部署前不新增日程。
