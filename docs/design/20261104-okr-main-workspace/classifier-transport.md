# Claude 自动分类请求的传输适配

## 产品设计与用户故事

数据分析的原Claude实例已恢复、能生成真实回复，但Bash执行反复被自动分类器拒绝，提示
没有可用答案。保留用户原自动权限模式，不能禁用分类器或伪造allow结果来宣称自动化通过。

当前WorkBuddy源的独立实测：非流式请求返回400、code11101、Non-stream chat request is
currently not supported；同路由流式请求及Claude客户端可返回200。自动分类器的请求失败与
该不兼容相符，先在统一网关支持非流式Anthropic请求；真实分类器恢复前不将关联当作最终
根因证明。不改变OKR角色、provider、模型别名或计费配置。

## 技术设计

仅针对已选WorkBuddy插件、上游openai-completions、下游anthropic-messages的转换：复制
已解析的请求，将上游stream打开并请求真实usage。桥接器保留客户端原stream标志；客户端
要求非流式时，用既有有界结果聚合器收齐并验证终止/用量，再返回一个Anthropic JSON消息。
文本与工具参数仍来自真实模型，别名和实际配置模型不变；其他插件与同协议直通保持原行为。

不增加请求重试，不生成权限判断，不改路由或费用策略；实际usage由原网关账目记录，仍是
一条正式调用。中断、错误、缺终止或缺用量保持失败，不能把partial文本交给分类器当成功。
规则在统一网关生效，不把宣传项目或某一个OKR的ID硬编码进框架。

## 验收

纯桥接测试覆盖流式聚合回单个JSON、文本/工具内容、模型别名、实际输入/输出/缓存用量及
截断流失败。Bun沙箱插件集成模拟只接受stream的源，经真实插件选择、鉴权、模型绑定、网关
和账目路径验证：上游使用原配置模型，客户端仍收JSON，正式调用仅一条且归属原source。
现有协议矩阵和整个网关专项另外运行。quick/full与CI通过后再部署；实际Claude分类成功、
登记和Connector取数仍须生产实例验证，不能用沙箱allow文本替代真实生产权限或执行结果。
