# 首页与项目 Main 共用对话能力

关联 #748。用户进入 OKR 的 Main 后，应像首页一样立即看到生成中的内容、执行状态，并能继续输入；原项目 Main 与首页保持不同身份，已有历史不迁移。

## 产品与故事

- 项目私聊始终发送给已验证的原 Main；打开通知只定位原消息，历史分支只读。
- 首页和项目使用相同消息流、执行记录、问题回答、附件、模型选择、语音、命令、排队、分页和滚动。
- OKR 自有团队/任务右栏继续由活动工作区管理；不再额外套首页工作台和导航。
- 发送结果不明时，保留原正文、附件、上下文和请求键；切页晚回不能清除新草稿或投到其他节点。

## 组件与模块

`AgentChat` 为首页入口，`OkrMainChat` 负责固定项目 Main 的身份恢复。两者使用同一个 `AgentConversation`，后者拥有唯一的 `useAgentThread`、首页消息/活动时间线、输入与 outbox 生命周期。

项目适配只提供 `ensureConversation/isCurrent`、草稿存储位置、消息上下文转换和宿主更新回调。它不提供虚构的首页 inbox，也不借首页 Main 换取可编辑状态。首页自动选择 Main 的行为只在首页启用。用户正文的隐藏上下文只在展示时去除，SSE 原文、offset、分页缓存不变。提取 `okr-conversation-context.ts` 保留已有上下文契约，本轮不扩大为提示词迁移。

保留已有项目 draft/attachments/pending 存储键；读取旧 pending 格式。队列发送前冻结实际 payload，失败和刷新后使用原键与原 payload。正文完成后触发宿主取数更新，不将投递或工具执行当成任务验收。

## 真正流式的另一层

2026-11-07 原 Main 最近一次成功回复的只读事件记录显示：模型执行约 26 秒，最后的 `reply` 工具核验通过后，765 字正文只产生一次 `message.delta`。因此共享前端是必要条件，但不能单独修复这一条流式通道。

后端需另行设计并验证真实生成预览：仅将明确的回答正文作为带轮次身份的暂态预览，最终仍经过原有来源核验；拒绝、取消或改写时撤回/替换预览，不能把未核验内容标成最终结果。禁止通过客户端打字机效果伪造流式，禁止关闭回复核验或修改用户模型路由。预览的断线恢复、工具参数解码与跨轮隔离需专项验收，未实现前不宣称完成 #748。

## 验收

共享组件以递增事件证明正文在 completed 前可见；验证 late POST、lost receipt、旧 pending、项目/首页隔离、命令、附件、历史只读、队列与切节点。使用自有 QA 页经 roami chrome 操作，覆盖四档桌面和紧凑模拟。遵守当前不操作手机边界，紧凑模拟不计真机验收。前端执行 typecheck、i18n、hover、Vitest、build 与仓库 quick/full 对应范围检查。
