# B站公开统计 Connector Skill

关联 [#736](https://github.com/ybz21/Roami/issues/736)。延续本目录的项目 Main、长期成员、文件看板与 Connector 批次设计。

## 产品设计与用户故事

用户已获得某个 B站视频的公开统计，希望数据成员按项目 Skill 重复取数，Main 审核后让看板更新，而不是每次从聊天抄六个数字。一个视频的一次响应服务多个指标，避免各卡片取到不同时间的结果。

这条来源只表达指定 UP 主/稿件的累计播放、点赞、弹幕、评论、分享和收藏。它不代表全账号总量、每日新增、完播率或平均观看时长。平台未返回的字段仍未知，明确返回的零才显示零。更换稿件是来源变更，由 Main 明确确认，旧事实不迁移到新稿件。

## 技术设计

可选包位于 `skills/okr-development/parts/connectors/bilibili/`，不是所有新项目的默认来源。完整模板仍先复制 assets，再按项目需要组合这个部分。

- `SKILL.md` 说明来源、字段映射、确认流程、运行权限和定时边界。
- `scripts/bilibili.py fetch` 使用标准库单次匿名 GET 公开 view API，禁止重定向，限制响应大小，核对 HTTP200/code0、公开状态、BVID、owner.mid、aid 与非负安全整数；保留原 UTF-8 响应及 SHA，不输出登录态。
- `prepare` 离线复核候选和原响应，要求当前宿主批次能力、确认修订、代码包摘要、相同来源和 snapshot 窗口。时区取确认配置；只映射存在的字段，并使用指标已确认单位。
- 来源 identity 为 `bilibili:<MID>:<BVID>`。Host 的通用来源绑定 manual 指标，绑定后当前看板只读取新来源的事实；旧未绑定观测保留。因此确认来源后必须实际发布一批新观测再验收页面，不能把历史保留误认为当前来源已有值。
- 准备命令只创建项目相对路径的原响应与请求，拒绝路径越界、符号链接和不同内容覆盖；同字节重放保留原批次。Main 使用受支持 record 确认，未知结果先按原 batch id 对账。
- 通用宿主对批次做完整性与绑定校验；远端真实性、账号、累计语义由 Main 独立审查。SHA 不是外部真实性证明。

新 Skill 不触发账号写操作、不注册定时器、不替换成员、不直接修改确认文件或运行时数据库。原 Main 续派原数据任务，成员只交当前轮候选，Main 负责独立验收、共享索引和记忆。
