# Main 优先的团队对话入口

关联 #656 / #658，接续 2026-11-05 用户对单聊、群聊与全局输入框的反馈。

## 产品设计

团队默认打开本 OKR 的 Main 对话。桌面左侧明确列出 Main、群聊和成员，点击即可切换；
手机通过有文字的“对话”按钮打开全屏联系人列表。协作场景和任务保留为次级页签，
不与聊天挤占两列。打开场景才展示动画，返回聊天释放场景资源。

Main 继续使用本项目的固定会话，与首页 Main 独立。Main、群聊和成员分别保留草稿；
输入提及不会偷偷切换接收人，跨对象的提及冲突保留输入并提示明确选择。
Main 发言直接进入固定对话；群聊发言走共享讨论入口，指定成员时保留真实任务修订。

## 用户故事

- 进入团队就能告诉 Main 要做什么，由它继续协调原团队。
- 清楚选择群聊或某位成员，离开再回来还能继续自己的草稿。
- 查看成员原任务或会话时，遇到修订变化、执行器不符和未知关闭结果，返回当前任务。
- 需要看团队协作时再打开场景，聊天不被动画或大型角色卡压到下方。

## 技术设计

`ManagedSwarm` 提供对话、协作、任务三个视图。`SwarmConversations` 展示显式联系人；
`swarm-members` 优先使用服务端成员注册表，只在旧协议下从工作项兼容读取。
不会裁剪 r2/r3 名字或猜测合并职责。`SwarmMemberDetails` 按需加载、分页读取真实轮次，
不轮询历史详情；来源不可见的轮次不提供绕过入口。

项目通过 `renderMain` 复用 `OkrMainChat`，核对固定 conversationId。独立团队使用
`SwarmMainChat`；两者复用全局 `NativeConversation` 与 `ConversationComposer`，
避免复用会自动选择首页 Main 的整个 `AgentChat` 容器。直接 Main 消息不写共享群聊。
待确认请求保存原幂等键；重开、节点变化和发送中继续编辑均保留正确的草稿归属。

成员会话进入前复核最新 member/instance、task/revision/run、项目、执行器和关闭状态；
原生实例另核对 conversation/nativeSession 绑定。CLI 同时对照共享活会话概览的名称、
执行器和存活状态。没有新建替身或恢复终端的副作用；CLI provider 身份的完整宿主证明、
无任务 CLI 启动和旧重复职责的显式整理继续由长期成员需求接续，不能因页面变更关闭整单。

场景只在显示时订阅真实 Main turn 和批量成员状态，避免私聊 Main 运行时仍画为空闲。
消息正文与输入卡按全局阅读宽度居中，布局外壳填满画布；手机联系人、任务和记忆互斥显示。
