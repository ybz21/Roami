# 报告中的输入引用与交付文件

## Product Design

原 Data 第 19 轮已返回三件真实产物，但摘要里作为输入说明出现的
`schedules/daily.json` 被列为缺失产物。相对路径含目录不代表它是交付声明。
缺失提示应该帮助 Main 找到真正缺少的交付，而不是要求成员重新执行已完成的工作。
任务等待 Main 验收与缺失产物提示是两个独立状态，不根据后者推断前者成因。

## User Stories

- 成员在摘要中用行内代码引用配置或输入，不因此产生虚假的缺失附件。
- 成员用 Markdown 链接声明交付；链接对应文件缺失时，Main 仍能看到明确提示。
- 行内相对路径指向真实可读文件时仍保留文件；实际观测到的文件写入失效时仍报告缺失。
- 符号链接、隐藏路径、越界路径、被删除附件和附件限额不能通过输入引用规则绕过。

## Technical Design

`storage/task_deliverables.py` 保留现有发现与安全读取。Markdown 链接和工作区绝对路径
继续是明确交付声明；行内相对路径是尽力发现附件的提示，不根据层数升级为声明。
仅在真实工作区目录存在、候选未被声明且未被实际文件操作观测、读取结果确为
FileNotFoundError 时忽略这个提示。其他失败及明确声明保留 unavailable 记录。
不修改任务状态、不替成员验收、不修改既有结果或历史。

自动收集原生结果与后续详情读取共用这一模块。回归覆盖多级缺失输入、显式相对/绝对
交付、原生执行返回、实际写入文件删除、限额、已删除附件与路径安全。
