# 团队记忆容量与长期运行

关联 [#831](https://github.com/ybz21/Roami/issues/831)。

## 产品设计

团队长期记忆是有界的当前知识摘要。完整交付和每轮日志留在日期目录，历史记忆由宿主按 SHA 保留，不能靠扩大上下文或清空历史维持运行。

## 用户故事

Main 在每日复盘追加知识时，能够知道当前容量，并在满时整理历史条目后继续追加，不需要用户逐条介入。原成员与原对话不变化。

## 技术设计

复用 CAS 和现有 swarm_memory_edit，不增加另一个归档入口。Go 的 MemoryCapacityError 携带当前、请求后和上限的 UTF-8 字节数；HTTP 返回 409 / OKR_MEMORY_CAPACITY。其他参数错误仍用原校验。容量失败发生在 prepareOperation 前，不污染幂等操作身份。Python 的真实读取回执携带 sizeBytes / limitBytes。Main 根据实际读取的旧片段做有界摘要，宿主先将精确旧全文写入 memory/history/<SHA>.md，再替换当前摘要。成功后重新读取 SHA，再追加原来的新知识。

每个协调批次只有一个稳定编辑身份，需一次规划整理方案；不能循环改写相同操作键。未知结论、有效规则、证据路径和原作者必须保留。此变更不自动生成模型摘要，也不默默删除项目内容。

## 验收

专项覆盖近上限失败不改原文、编辑保留完整历史、随后原追加身份可恢复、旧 CAS 冲突，以及中文按 UTF-8 字节计数。上线后还需通过原 Main 的真实受管编辑和回读验证，不以单元测试代替生产闭环。
