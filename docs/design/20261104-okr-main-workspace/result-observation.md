# 成员结果如何进入原 Main

关联 #744、#761。执行回执已将成员的执行事实与 Main 的审核分开；本段补上冻结输入和实际观察，暂不开放自动生产者。

## 产品与用户故事

用户只需与项目 Main 沟通。成员同一轮先发交接、后完成执行时，Main 必须收到后来的结果。Main 已实际看到的同一份结果不重复提醒；新问题仍保留独立的群聊身份。Main 自己审核通过不构成另一份执行结果。沿用原项目、原 Main、原成员与原任务，不增加页面入口。

## 技术设计

执行事实是 `task.execution_result_recorded` 事件，稳定身份为宿主回执与规范结果摘要。新增 schema26 显式迁移，保存两类记录：批次冻结的实际执行结果，以及实际模型请求中提供过的回执；Go 备份兼容范围同步扩展，不启动时偷偷建表。它们与群聊 inbox 分开，不能把先前的 handoff 或同 run 的旧 unknown 当作后来结果已读。

`storage/swarm_coordination_results.py` 从当前委托选中的原成员、当前任务 revision 和最新 run 选择真实回执；核对宿主摘要后，把当时的实际结果字节冻结进 SQLite。不会从历史任务字符串补造回执。每个委托与回执只绑定一个批次，重试复用；晚到结果进入后续批次。原 `storage/swarm_coordination.py` 同时冻结群聊与结果输入，空批次不创建 turn。群聊去重不吞掉成员的新业务消息。

`context/swarm_coordination.py` 投影冻结结果。结果回执表示宿主已获得执行结果，不表示 Main 读过附件、独立验收或取得发布许可。`PromptManifests.record` 在实际模型请求留档时写观察记录，预览或候选 prompt 不写。实际成功的 task_status 结果必须出现在该请求的工具消息中，且与宿主保存的 tool_call/result_message 一致；仅工具成功、传入某个 receiptId 或截断摘要不算模型已观察。失败调用、被遗忘来源、错误项目、旧 lease 及被剔除的工具结果不能写观察。

观察记录保留委托、原 Main、turn、manifest 和结果回执身份。后续 completion 桥接只依据当前委托的真实观察，不按 runId 或任务 succeeded 猜测。停止、撤销、遗忘和切分支仍通过原准入门；已冻结的历史不删除，不通过换键重建批次恢复执行。显式同批次恢复及生产者接线另行验收后启用。

## 验收

覆盖先冻结 handoff 后晚到结果、同 run unknown 到 known、重复结果和独立新问题、Main 自验收无新结果、模型请求与预览差异、成功及失败 task_status、截断/伪造工具正文、跨项目/来源遗忘/停止/旧 lease、迁移失败回滚重试。冻结输入不随当前结果变化；不向 SSE 复制完整结果。通过后仍不能宣称真实平台发布循环已完成。

已有[通信机制原型](communication-engine.html)与[同批次恢复原型](coordination-recovery.html)展示读取、独立验收和停止恢复的关系；它们是机制模拟，实际接线以代码和隔离证据为准。

## 通用模板与实际项目约定

将原 Main 实测有效的 artifact 分页、图像真实输入、独立验收、单条注册 CLI、具名群聊回告和 CAS 追加经验提取到 [OKR 开发 Skill](../../../skills/okr-development/references/automatic-loop.md)。完整 `assets/` 初始化目录同时带上根 AGENTS、OKR AGENTS 和自动运行手册，复制后可独立阅读；已有项目保留定制与历史，不用整套覆盖。

工作模式跟随用户选择。授权自动模式时由 Main 审核冻结版本，通道实际可用后自动发布，不为每条内容重复申请批准；制作交付、发布资格和平台成功分别核验。手册不创建宿主授权、账号连接或定时任务，未支持的步骤保留具体能力缺口。此迁移记录团队执行事实；看板指标的 SQLite 方案继续由 #743 跟进。
