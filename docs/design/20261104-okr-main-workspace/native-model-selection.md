# 原生会话内切换模型

## 产品设计

项目用户在 Main 的共用聊天入口选择网关已配置的模型。下一轮使用所选模型，原项目、Main 对话、原生会话、历史和团队继续沿用。界面先显示当前实际模型，再显示切换确认状态。存在进行中的输入或结果未知时，用户可继续查看原对话和结果，宿主在得到可信的停止证据后处理切换。

宣传项目的 Main 目前使用 `free` 聚合。11 月 28 日带图工具历史会触发该池的可用性问题。另一个已配置模型 `openrouter/free` 已通过长图文和 Claude 自动分类测试。项目内切换使用已有选项，共享模型目录由节点设置管理。用户明确选择已配置的套餐额度或其他计费路由时，仍由 Go Gateway 处理当前准入与用量。

## 用户故事

- 给原 Main 选择一个可用模型后，我仍能读到以前的消息，Main 仍然能给原团队交办任务。
- 另一个项目继续使用自己的模型。我能在状态里看到所选模型是否已经生效，并区分上游暂不可用与切换待确认。
- 异常时原任务回执仍可对账。带有未知发布结果的任务由 Main 先读已有回执，确认以后再决定是否继续。

## 技术设计

| 模块 | 职责 |
| --- | --- |
| Go Gateway | 从已配置目录解析可用模型和公开模型名，核验价格、已注册的协议与调用准入。 |
| 通用 `agentexecution` | 对绑定的原生 provider 执行有幂等键的模型控制操作。验证原生配置的归属，维护初始模型和当前已确认模型的各自证据。 |
| 通用 Python 会话运行时 | 通过原会话的准入和执行租约登记意图、阻止切换和下一轮交叉提交、回读模型控制结果和发布会话事件。 |
| OKR 适配层 | 验证项目与 Main 的绑定，使用原有配置入口保存项目选项。按已确认的原生模型构建下一轮的适配器。原队列、成员、计划、复盘和计价继续走各自接口。 |

1. 请求提交已登记的模型 ID、会话与预期当前模型、幂等键。宿主重新核对拥有者、当前 provider、注册执行器和项目授权。免费调用按现有免费准入执行。排队消息保留原请求键和顺序。
2. 在同一会话的准入边界登记控制操作，记录原生会话身份和受验证的日志位置。只有旧输入已知停止，且会话与执行记录仍匹配，才允许 `/model`。宿主确认该命令由已登记操作发出并核对目标模型名。Claude 在已有缓存历史时可能提示重读上下文，选择请求可一并提供对此次精确选择的确认。若原生提示与规范不同，返回待确认状态并保留原证据。
3. 复用原生转录读取与宿主身份校验。在同一 provider 和稳定文件内匹配该命令与 stdout 回执，校验同一 prompt ID、原模型、目标模型、命令顺序和会话空闲。保留控制操作的编号、来源摘要和时间，供重试和宿主重启对账。仅凭终端屏幕、提交返回或模型名相似无法更新状态。
4. Agent 用当前操作的收据更新绑定的有效模型，初始化凭据仍用于校验原生身份。后续运行读取有效模型，已在途执行采用其冻结配置。完成与拒绝均保留原轮次。切换确认未知时，先读取当前操作证据再决定续接，避免重复输入或启动任务。

## 原生配置的归属

Claude `2.1.332` 的 `/model <模型>` 同时写入其配置目录的 `settings.json` 顶层 `model`，终端明确提示已保存为新会话默认模型。正常轮次和受控 400 后均观察到此写入。宣传原 Main 当前使用节点共享 Claude 配置，禁止对它投递保存默认值的选择。

原生模型列表支持只对当前会话生效的选择。提交一次无参数 `/model` 后，在已核验的模型行使用 `s`。原生提示要求重读历史时再核对当前目标，完成确认。保持一次提交，避免第二次 Enter 在模型列表上保存默认值。Agent 须以原 provider、同一模型控制 prompt ID、当前会话确认记录和正式 Gateway 模型标识核对结果。相同模型可能以源限定的 Gateway 名称出现，宿主解析目录中的确切映射。界面回显用于操作引导，已核验的控制回执作为提交有效模型的依据。 [Claude Code 模型列表](https://code.claude.com/docs/en/model-config)

新建原生实例时，Agent 可为单个实例绑定专属配置目录，并在启动回执里记录经过核验的归属。Agent 维护目录创建、权限和绑定，产品层选择哪个实例使用这项能力。切换前复核当前进程的配置归属和目录真实路径。首页和其他项目继续使用各自配置。

既有共享配置实例应先使用已验收的会话级控制路径。原生版本或状态不支持时，可以在旧执行已可信停止后使用启动参数恢复同一 provider。接续未确认时，当前项目和团队仍保留已有绑定。验收需要两个同机实例跑一次切换，逐一读取配置与实际模型回执，并覆盖配置路径别名、切换期间配置被替换和回执缺失。

## 验收

- 2026-11-28 已用真实 Claude `2.1.332` 做独立会话实验。初始 `free` 由 Ernie 返回，输入 `/model` 时 Claude 询问是否切换和重读历史。确认后原生转录在同一 provider 下记录了命令和精确的模型确认。下一轮由 `openrouter/free` 返回，正确复述了切换前的词。三笔网关调用的实际费用为零。该实验经过隔离的 Roami 会话和实际网关。原生命令还修改了该测试实例的默认模型。
- 单独实测 `openrouter/free` 完成约 3.1 MB、449 项历史、6 张工具结果图片的合成请求。隔离的 Claude 自动模式另验证了实际分类、只读 Bash 及最终回复，三笔费用均为零。
- 2026-11-28 隔离实测确认本机 `2.1.332` 支持按 `s` 选择 `openrouter/free`。当前进程和 provider 保持，原设置逐字节一致，后续真实网关响应准确复述切换前的内容，实际费用为零。
- 实现后验证跨项目和首页隔离、拒绝无权限或旧模型期望的请求、忙闲竞争、未知结果与重启后的对账、原 provider 和历史保持，及有效模型的真实后续请求。生产闭环按原 Main 的任务、交付、平台回执、采集及复盘验收。

## 恢复原 provider 时选择启动模型

通用 Agent 的 Claude 恢复入口可以接收网关已配置并启用的免费模型 ID。在原执行已有已知停止结果、原物理会话已退出、转录及原生 provider 身份通过核验后，恢复进程以启动参数选用模型。准备和启动各检查一次网关目录，启动时核对原 profile 仍连接同一节点网关。请求未选模型时沿用原配置。恢复回执带原执行键和已绑定的配置模型，实际模型及费用仍以网关回执为准。

这一入口用于已停止的原生会话。运行中选择模型、项目配置迁移及产品层接回 Main 依赖各自的验收。真实隔离试验使用原 provider ID 在私有配置下启动，成功复述旧夹具内容，核对旧转录与旧配置保持字节一致，实际结算为零。

## 通用 Agent 会话选择回执

`roami agent execution select-model --file JSON` 接收操作键 `key`、已核验启动键 `preparedFrom`、当前模型 `expectedModel` 和目标模型稳定 ID `model`。默认选项为 Gateway 已启用并确认免费的 Claude 模型。明确使用目录中的套餐额度或计费路由时，同行为附上 `allowMetered: true`。Agent 根据同一版 Gateway 目录核对模型行、源限定名称和执行器配置，再在已停止的原生会话发起模型选择。

宿主独占该会话和窗格的 Roami 输入。原生选择器只提交一次无参数 `/model`。定位到目录中唯一的目标项后用 `s` 应用到本会话，有独立确认时逐项核对目标。回执需要原 provider 日志中同一 prompt 的控制命令和“仅本会话”结果。读取从切换前的文件位置开始，复核文件身份、锚点摘要和设置文件摘要。

同一操作键重试时读取或补齐回执，以原生证据对账。准备信息分别核对初始模型和本次已经确认的有效模型。后续框架执行仍绑定同一 provider。OKR 负责校验当前项目和 Main 的授权、保存项目配置及处理原有队列。永久配置和网关准入由节点原有入口管理。

## OKR Main 运行时接入

项目通过 `POST /v1/conversations/{cid}/execution/model` 提交项目 ID、命令键、原绑定代次、预期当前模型和目标模型 ID。明确选择计费路由时同时记录 `allowMetered: true`，它属于同一命令键的校验和原生回执。OKR 在一个数据库事务里核对归属、记录操作和保留原 Main 队列。用户消息、定时任务和群聊继续使用各自的请求键。等待期间，首页和其他项目仍由各自队列处理。

现有调度器调用通用 Agent 入口，读取选择回执和当前准备状态。两份结果都与原启动键、会话、provider 和目标模型一致时，OKR 在同一事务更新当前代次的模型、记录事件并放行队列。同一个命令键返回已有状态。宿主超时、重启或回执不匹配时，保留队列并按原操作键对账。宿主确认拒绝发生在投递前时，原模型恢复接收队列。

验收覆盖原团队和代次、切换期间的定时轮次、首页并行、错误 provider、控制进程超时、按原键重试及原有运行记录。

11 月 28 日，节点已有的 WorkBuddy `wb-ds` 通过真实 Claude 普通生成、自动工具分类、只读 Bash 及最终回复。用相同消息数量和媒体形状的合成请求验证，453 条消息、43 个工具及 6 张图的历史得到完整流式响应。Gateway 账目为零，WorkBuddy 按套餐额度规则处理该路由。项目仍须按正式发布、Connector 和看板回执验收实际运行。

## 项目独立审核路由

项目 Main 的原生推理和工具审批由现有会话绑定决定。独立回复审核、长期目标复核和自动发布策略审核可以使用项目单独选择的 Gateway 模型。保存时验证项目归属、Main 已空闲、原生代次及审核配置修订，Gateway 负责确认模型可用和计费准入。未明确同意套餐或计费时，只接受已确认免费的路由。

通过 `PUT /v1/conversations/{cid}/execution/review-model` 提交项目、Main 代次、审核配置修订、模型 ID 和命令键。模型设为 `null` 时恢复默认审核路由。项目配置与当前 Main 对话绑定，并保留在同一 Main 的原生会话换代之后。处理每一轮时只读取该项目的配置。普通对话和其他项目读取各自的审核设置。

验收需确认项目选择、清除、幂等、旧修订拒绝及跨用户隔离。真实 Gateway 的 `wb-ds` 试验返回了独立回复审核所需的结构化裁决，实际账面费用为零。线上仍通过各自审核工具确认回复或发布策略。

## 接续模型拒绝的日槽

原 Main 切换模型后，可以用已完成的切换操作键申请接续当日失败的日槽。宿主核对原任务由当前长期授权派生，原批次的上下文仍有效。查询原日槽和随后同分支回合的原生停止证明，确认同一 provider 在输出和工具之前收到输入拒绝。任何已执行工具、已有模型输出、未确认的停止、变更的授权或过期日槽都拒绝接续。

接续保留原日槽、批次、对话回合和交付引用。重排和写回执在同一事务提交，重复请求读取原回执。重排使用恢复前已经核准的最新上下文，包含随后已提交的用户消息。排队期间收到新消息时，原快照因上下文变化而退出，交给 Main 按当前授权处理。

## 工具审批模型接续

推理请求和 Claude `auto` 模式的审批请求各有模型路由。宣传项目 11 月 28 日恢复原日槽时，`wb-ds` 完成推理及最终回复，原生转录同时记录了 `free` 审批路由导致的 11 次工具拒绝。本轮没有形成派工、交付验收、入库或复盘回执。运行状态应能显示这类阻塞。

独立试验通过同一 provider ID 恢复带已有历史的 Claude 会话。启动时使用会话级 `--settings` 指定审批模型，维持 `auto`，并核对配置文件字节一致。网关记录了四次成功请求，其中包含一次独立审批。受限的只读 Bash 成功，后续回复正确引用此前已持久化的内容。 [Claude 会话设置](https://code.claude.com/docs/en/settings)

计划由 Agent 提供受管的会话级路由配置和可信接续。配置分别记录推理与工具审批使用的 Gateway 稳定模型 ID，并按同一目录版本校验。套餐额度沿用用户已确认的路由选择和 Gateway 准入。启动配置只传给对应的 Claude 进程，保留既有权限模式、钩子、项目根目录和原生 provider 历史。

已有会话变更需要核对原回合结束、进程归属和独占输入。确认新启动的会话仍绑定原 provider 后再更新持久绑定。OKR 适配层负责项目授权、角色选择与续派时机。验收用同一持久会话的实际审批和受管工具回执，以及后续的原任务轮次和业务结果。

## 原成员换载当前模型目录

Claude 的长会话可能保留启动时的 Gateway 模型列表。目标已启用而当前选择器无法确认时，可以用受管启动参数恢复同一原生对话。Agent 核对旧任务停止回执及原生日志摘要。若原日志追加了本机命令，只接受同一 provider 的原模型确认和空闲退出回执。模型拒绝后出现新任务、工具活动或未完成的命令时，续接请求退出。

Claude 也可能在空闲退出时只追加费用、最近提示和文件历史等元数据。已核验原进程退出、宿主空闲退出事件和原任务停止摘要时，允许这些记录出现在原摘要之后。新增的用户输入和工具活动仍需要独立核对。

Swarm 的 `PUT /v1/swarms/{id}/members/{memberId}/execution` 接收预期成员代次、任务 ID、任务修订、执行 ID、旧模型、目标模型及新准备键。宿主核对恢复所用的原执行键、已知停止结果和同一个原生 provider，在同一事务提交成员的新代次。原任务和执行历史保留，下一轮续派使用验证后的新会话。其他成员继续使用各自队列。

专项验收包含 11 月 28 日真实 B 站拒绝回执与原生历史副本，以及同成员重绑后复用原任务、拒绝跨界绑定、拒绝未知停止结果和按命令键重试。
