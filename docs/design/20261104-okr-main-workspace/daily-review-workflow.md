# 日期槽与真实复盘

## Product Design

每天唤醒同一个 Main 不等于执行了该时段的工作。开工应推进有界任务，复盘应核对实际结果、保存复盘，并在有新有效经验时更新团队记忆；不能以重复批准已有内容代替复盘，也不能为了复盘制造发布或观测。

## User Stories

- 原 Main 先读取当前绑定项目与已声明的日常 Skill、阶段提示，再安排本轮。
- 复盘中已确认、未知和阻塞分开；没有新发布就明确未发布，缺数不补零。
- 经验经核验后按项目记忆的当前哈希去重追加；无新知识不重复写，写后回读。
- 项目自定义 Skill 使用其已声明路径；缺文件或能力如实说明，不猜路径、另建 Main 或扩大账号/设备范围。

## Technical Design

`context/swarm_coordination.py` 对日期唤醒增加阶段流程指引。继续使用既有 system 协调说明和结构化 dailySlot；不把项目文件拼成新的 user 消息，不改变真实原始目标或来源 ID。先读 swarm_project_context 及项目声明的日常 Skill；标准模板的入口是 `.roami/okr/skills/daily-operations/SKILL.md`，对应 prompts/kickoff.md 与 prompts/review.md。自定义项目按声明选择，不能从任意 slot 字符串拼接文件路径。

已获原目标授权的复盘通过协调批次允许的 swarm_project_update（operation=review）和最新 revision 保存真实总结；有新有效经验时，先 swarm_memory_read，再用其 sha256 调 swarm_memory_write 追加并回读。普通会话的 project_okr_update/project_okr_memory_append 不在协调回合准入内，不能用它们替代批次去重封装。它们与群聊回告、制作任务验收、内容发布审核分别留证。指引不强制未授权写入，不解除外部动作限制，不添加自发唤醒或定时任务。

日期槽去重、当前目标验证、暂停/过期、原 Main/成员绑定和完成回调均保持既有协议。此次不新增持久 schema 或发送接口。

## 触发证据与验收

原项目的 review 日期槽回合已结束，共64个工具调用，未读取已声明的日常 Skill 或阶段提示，没有项目 review/memory 写入，团队记忆哈希前后相同；只重新批准了五份已冻结内容。线上协调模块与此次审查的基线源码字节相同。私有记录在 `/tmp/okr-review-workflow-20261108/actual-main-review-proof.json`。

隔离验证继续覆盖原用户来源、同槽去重、暂停、过期和原成员身份。流程是否生效必须由部署后的原 Main 实际读取阶段文件，保存真实复盘，并在有新知识时取得记忆追加/回读回执；不由 Root 代写，不从提示文案或测试模型推导实际完成。#800 在此之前保持开放。

工具契约回归在真实日期槽、claim 与模型上下文上提取指引引用的工具名，与本轮实际目录准入交叉校验；旧候选确实因两个普通项目写工具被拒而失败。修正后仍需原 Main 的真实复盘和记忆回执，不把此结构回归当作生产执行。

服务端新建 OKR 的默认 AGENTS 同步使用 materials/日期/渠道/短主题，任务身份保留在 manifest；现有自定义文件不覆盖。Main 无直接文件写能力时续派一个原成员维护日索引并独立核对。真实项目与完整模板同时区分普通 Main 工具、协调批次写回封装及原生成员 CLI；不把缺少专用发送工具当作原通道不存在，也不解除现行设备限制。
