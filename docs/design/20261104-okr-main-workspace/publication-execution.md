# 自动发布执行与回执对账

## 产品与用户故事

用户与项目 Main 确认持续目标，Main 独立审核原成员交付，原成员发布，数据成员采集真实新对象的数据，Main 复盘并安排下一轮。用户不需要逐条确认。平台连接缺失应明确显示为能力缺口，不能伪装成永久人工审批，也不能声称已发布。

一条待发布内容沿用一个项目范围业务身份。网络结果未知时先查原尝试；更换工具调用、版本或执行轮次不能绕过原尝试而重复发帖。发布已发生后，即使目标停止，也必须保留真实平台 ID。

## 技术结构

本次增加内部协议模块，尚未注册发布工具或连接生产账号：

| 模块 | 责任 |
| --- | --- |
| `publication/automatic_mode.py` | 基于本项目真实用户消息审核持续自动模式；后续真实用户限制使旧证明失效 |
| `publication/approved_assets.py` | 查询原项目不可变版本、最新有效审核与资产索引；不要求创作者永远停在原轮次 |
| `publication/publisher_identity.py` | 核验原成员当前任务、真实 applied steer 操作及执行 run |
| `publication/post_journal.py` | 复用项目范围 `swarm_commands`，写前记录提交，保存已知平台 ID；并发与重启不重复提交 |
| `publication/x_channel.py` | 显式账号凭据的 X 协议适配；上传图片、创建帖子及独立回读作者、正文、媒体 |
| `publication/reconciliation.py` | 对已有平台 ID 只读对账并保存 public 事实；不产生再次发布权限 |

模式证明、账号连接、素材审核和当前执行身份分别校验。模式判断使用保存的模型配置和独立审核请求，不复用 continuation 的快捷放行。资产索引通过不等于物理文件已校验，宿主仍须读取冻结字节并验证哈希。账号凭据不进入项目文件、记忆或交付。

写前账本的准入依赖默认拒绝；发布与对账依赖由宿主提供，成员自报不能代替。创建帖子前 await 持久提交记录；收到平台 ID 后立即保存。独立 GET 匹配实际作者、正文与媒体后，才追加 public 事实。对账可以在任务停止后保存已经发生的事实，但不能开启新的 POST。

## 尚待接通

2. 绑定原成员批次发布任务与稳定 release，增加公共受管入口及 Skill；先冻结并审核整批素材，再推进原制作成员。
3. 对没有平台 ID 的未知结果做原账号和媒体身份对账。零个候选也不自动证明未发布；只有确定未产生帖子才允许同业务事项重试。
4. 完成专用宿主平台事实验收，不放开现有 `swarm_verify` 对 external action 的限制。
5. 接通 Bilibili 视频与音频独立审核和发布，Connector 采集新对象，并完成至少两轮真实闭环。

## 验证范围

59 项专项通过：真实隔离 SQLite、真实 task revision/dispatch 流程、显式模型 fixture 和 HTTPX 模拟传输。对账专项覆盖停止后留存事实、未知 ID、错误作者、内容变化、跨用户隔离与缺失宿主依赖，断言不产生 POST。

这些验证不代表真实账号可用、真实帖子已发布或自动闭环已完成。生产审核基础由 PR #791 提供，本文件中的发布协议仍需后续接线。

原 Main 的真实接续暴露了参数易错点：它曾将正文原文作为 `content.body`，收到笼统清单错误后改猜清单 ID。现将清单引用、正文和图片的字段说明具体到 artifact ID 与相对文件名，未声明的内容路径返回专用错误。真实注册命令回归覆盖错误正文与项目目录前缀，纠正输入后沿用同一业务事项成功冻结；冻结入口与清单共 19 项专项通过。
