# 项目 Main 的文件读取范围

关联 [#759](https://github.com/ybz21/Roami/issues/759)。原项目 Main 读取自己的审稿文件时被拒绝为 `WORKSPACE_OUTSIDE_CONFIGURED_ROOTS`；回复中的「没有 shell 工作区」不能帮助它完成文件验收。

## 产品设计与用户故事

用户让项目 Main 统筹长期成员。Main 应能直接读取本项目的交付、说明和截图，再使用任务验收能力；不需要用户重复提供目录，也不应为读文件新建替代实例。

本次只补项目文件读取。项目写入仍使用既有受管操作或成员任务；首页 Main、工作成员、自动协调授权、命令执行和配置根目录保持各自规则。

## 技术设计

新增 `tools/project_file_scope.py`，组合现有 `SwarmCoordinationPolicy`。先执行自动协调的限制，再对普通 Main 的 `file_read`（包括 `read` 别名解析结果）补充可信范围：

1. 从宿主当前 owner/conversation 的 `project_okr_conversations` 绑定取得项目；模型不能指定或改写它。首页没有项目绑定时保持原行为。
2. 经现有 `TargetDirectory.project_workspace` 读取已注册、未归档项目的真实目录。只为本次文件读取绑定该目录，不赋予 shell 或写文件权限。
3. 文件服务继续执行既有逐级 `O_NOFOLLOW`、路径包含检查、有界读取和内容摘要。相对路径从项目根解析，绝对路径也必须位于同一目录。
4. 执行前重复准入及读取后重新核对项目绑定和目录；变化时丢弃结果，不能把旧目录的内容返回给模型。原自动协调已注入的范围仍由其原策略核验。

`app.py` 仅替换准入组合入口。无数据库迁移、全局 roots 修改、模型变更或界面变更。

## 验收

隔离回归覆盖两个项目与首页、其他 owner、成员工作区、相对/绝对路径、符号链接、读取中解绑/改绑/改目录，以及 `read` 别名和原自动协调策略。生产还需原 Main 读取本项目已知文件的真实回执；部署或代码通过不能代替它。

61项专项通过，包含新的项目读取边界、既有文件服务、项目 Main 身份和自动协调限制。再用真实项目绑定、Go项目接口和只读运行时数据库联调，读出项目AGENTS.md且全文SHA一致，全局shell roots未改；这是开发端诊断，不替代原Main执行。

完整门禁日志及只读联调记录位于 `/tmp/okr-project-file-scope-20261107/`。真实Main读取仍需部署后另行验证，不将本地通过写成线上恢复。
