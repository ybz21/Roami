# OKR Main 的完整输入框

关联 #723。用户希望 OKR Main 复用现有 Roami 输入框，包含加号、模型、思考强度、语音和发送。

## 产品设计与用户故事

Main 继续是原项目负责人，输入框的结构、样式和工具与现有对话一致。用户可加附件、粘贴图片、
选择 Skill、查看模型与思考强度、用语音填写草稿，再发送到原 Main。已有模型配置只读取；
只有用户在选择器明确确认时才沿用现有模型配置操作，提示说明当前节点所有 Main 共用此模型。历史分支保持只读。

附件上传中或失败时不发送；纯附件也可发送。投递不明时保留原请求正文、附件和幂等键，
关闭再开可继续；旧请求晚回不清空后来输入的文本。切换 Main / 群聊 / 成员不共用项目之外的草稿。

## 技术设计

`OkrMainChat` 继续使用已有项目 Main 恢复、引用身份检查与 `useAgentThread`，组合现有
`ConversationComposer`、`AgentComposerPlus`、`AgentModelPicker`、`VoiceInput` 及
`useAgentAttachments`，不实例化会根据首页 Main 重定向的 `AgentChat`。

附件展示提取为 `AgentDraftFiles`，同时由首页 AgentChat 与 OKR Main 使用，保留现有图片
预处理、上传状态、错误、重试与移除行为。模型 hook 使用 main 角色，沿用现有选择器与配置
事件；语音按原项目草稿作用域回填，历史/发送中禁用。没有额外轮询。

发送仍指向经核对的项目 conversationId。普通文本附原 OKR 上下文，显式斜杠命令原样发送；
附件 ID 与正文一同保存在待确认请求中。仅被接受的输入消费当前附件，保留后来输入的草稿。
原旧请求没有附件字段时按空附件兼容。群聊和成员路由、原 provider 和配置不变。

## 验收记录

前端全量 207 文件 / 1527 项，typecheck / i18n / hover / build 通过。专项覆盖完整工具栏、
main/worker 模型区分、真实附件上传等待、纯附件投递、跨卸载不明重试、原项目身份、
晚回保留新文本、历史分支禁写、斜杠命令参数及首页队列的附件回归。

浏览器使用独立样例验证入口与布局，模型选择器只打开查看，不保存配置；语音复用现有组件，
本轮不录制真实音频。真实手机未触控，紧凑模拟单独记录。证据目录
`/tmp/okr-main-composer-20261106/`；生产复验在合入部署后补记。


独立样例中经 roami chrome 上传真实 61B 文本、填写并发送一次，观察唯一 POST 到
`main-demo`，带原附件 ID，成功后仅清除该输入与附件。模型与思考强度菜单实际打开后关闭，
模型保持原值、草稿保留。四档桌面开合、控件边界与原 Main 绑定通过；390 粗指针模拟
验证完整输入框，未触真机。证据为 browser-send.json、browser-controls.json、layout.json
与 compact.json；这些样例请求没有连接线上 Agent。
