# 会话同等展示，任务独立留存

## 产品设计

Roami、Codex、Claude 等都是同等地位的会话。列表行、分组、排序、搜索、筛选、长按/右键菜单保持同一套实现，只替换 Logo。任务是会话背后的关联对象，任务状态与验收不进入会话管理流程。

- 所有会话都可打开聊天、改名、停止当前执行和关闭。
- 会话自己的名字独立保存；改名不改任务目标。
- 项目列表使用普通会话行，不追加“内置智能体”标签、特殊移除按钮或任务核验状态。
- 任务成功、失败或待核验后，会话仍可聊天；后续消息复用原会话，通过后台任务执行。
- 关闭会话保留任务、执行记录、对话及文件。执行中的会话先停止，关闭操作不验收任务，也不清理工作区。
- 聊天界面展示会话名字及在跑/空闲状态。任务详情是按需打开的关联信息，不作为进入聊天的前置步骤。

## 用户故事

1. 在同一项目中，我看到按相同规则排列的 Roami 与 Codex 会话；除 Logo 外没有专属行样式或额外状态标签。
2. 我长按任意会话，都用同样的改名、停止、关闭菜单。
3. 我把 Roami 会话改名为“附件沟通”，关联任务的目标和历史仍保持原样。
4. 任务执行结束后，我继续在该会话聊天，不需要先做会话验收。
5. 我关闭旧会话后，它从会话列表退出；任务记录依然可查。

## 技术设计

- `session-record.ts`：将不同执行器的记录归一成会话字段；来源身份只用于路由和操作分发。
- `native-session-list.ts`：用现有共享可见性轮询读取 Roami 会话，多个界面复用请求和稳定快照。
- 手机项目列表与桌面项目页将 Roami 记录合入原列表，统一走原 row 渲染、排序、搜索、筛选和菜单。移除 `NativeProjectSessions` 的专属渲染。
- 桌面会话树也接入同一会话记录，普通打开/改名/关闭动作通过来源适配，不能误发给 tmux。
- 会话操作适配层统一处理改名、停止、关闭；原 tmux 行为保留，Roami 通过版本绑定的任务执行通道操作。
- 原生会话持久化独立 `label`，保证任务目标与会话名不会互相覆盖。
- 聊天路由保留各执行器的渲染器；Roami 聊天直接占用当前工作区，不再作为 Main 旁边的特殊任务面板。

## 修订自审

第一版只增加了专用移除按钮，仍存在两套列表、专用标签和特殊会话页面。用户明确要求“只有 Logo 不同”后，该设计作废。

本版逐项检查：列表必须真正共用行代码，而不是复制相似样式；改名必须有持久化身份且不改任务；跨节点异步请求不得误操作新节点；聊天续接不能要求验收；关闭不能删除任务或文件；任务身份不能传入 tmux 路径。

### 集成审查

1. 产品：删去专属行、内置标签和行尾移除按钮；任务详情中的原生会话入口也打开普通工作区标签。已关闭会话从任务详情进入只读记录。
2. 身份与数据：创建和旧数据迁移时固化初始会话名，重命名写 `native_sessions.label`；追加需求不会改变会话名字。任务目标、版本、结果和对话不变。数据库升级至 21，并同步 Go 备份恢复的兼容上限。
3. 生命周期：加载新的会话清单前不清理已保存标签；跨节点或任务绑定变化时停止操作。结束态不新增逐会话轮询。原生记录只经过任务执行通道，不进入 tmux 抓屏、探测或发送接口。
4. 项目与工作区：原生会话纳入项目计数、排序、会话树、工作区标签、手机切换单和 worktree 占用判断。会话关闭不自动清理目录。
5. 聊天：共享聊天输入组件；模型失败显示可理解的原因，允许继续输入。会话间介绍发送到原生会话时使用版本绑定的续接接口；给原生会话的访问入口使用可打开的聊天链接。

模块入口：`sessions/session-record.ts` 管身份与归一化，`native-session-list.ts` 共享清单，`session-actions.ts` 分发同名动作；`TerminalPane` 选择会话对应的聊天渲染器。`storage/native_sessions.py` 维护会话名称与元信息，任务关闭仍由现有持久化关闭作业负责。
