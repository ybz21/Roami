# 上游拒绝误记未知费用

## Product Design

完整收到上游 3xx / 4xx 拒绝时，目录代理与协议转换路径按现有直连路径的规则记零费用，保留失败状态、HTTP 状态、错误码和上游回执，不补造 token。断流、5xx 和成功响应缺失用量仍记未知，启用日限额时继续阻止后续调用。

## User Stories

某个 Agent 遇到鉴权或限流拒绝后，其他 Agent 不应因这笔请求被误记未知费用而全部收到 409；真实未知费用仍需要核账。

## Technical Design

`internal/modelgateway/catalog_http.go` 原本两条错误返回分支均未设置零费用结算标记。原协议透传路径现依据 HTTP EOF 标记完整拒绝；转换路径在返回协议错误前丢弃并确认错误正文完整结束，最多读取 4 MiB 加一字节，超限或读取失败保留未知状态。复用 `Ledger.Settle`，不修改历史账目的状态或迁移规则。

## Acceptance

- 修复前新增回执断言在目录透传、协议转换的 400 / 401 / 403 / 429 共 8 个子用例失败，直连用例通过。
- 修复后回执回归通过；新增跨 Agent 日限额回归覆盖 OpenCode 原协议、Codex 原协议、Claude 转换及 Codex 转换。每种路径均验证 401 / 403 / 429 后 OpenCode 与 Codex 连续请求可用，并验证 5xx、错误正文截断及缺失 usage 保留未知且不再请求上游。
- `scripts/dev/quality/check.sh quick` 通过，包括 Go 全量测试。完整检查结果与界面验收补充见[模型编辑验收](../../../20261030-智能体模型切换/records/2026-11-03/source-model-editing.md)。未修改 Python，不运行 Python 依赖同步或测试。
- 本机故障账本中唯一的未知费用来自上游 401。使用现有 `roami agent gateway reconcile` 接口核账为零，保留原始 401、错误码和核账理由。核账后未知与在途均为 0，已知费用 9.349113600 CNY，日限额保持 100 CNY；随后已观察到真实请求恢复 200 并正常结算。
- 未重启或替换现用服务。防复发代码需要随新版服务上线；本机账目修复已生效。隔离验收不请求付费模型。
