# 逐笔 Token 与未知费用请求记录

## Product Design

费用未知与 Token 未知分开呈现。请求记录显示输入、输出、缓存 Token 及完整到秒的日期时间；有回执的数字照实显示，缺失字段显示“未知”，真实零保留为零。汇总用量缺失时显示“已知”数量或“未知”，不把缺失回执当作零用量。

记录详情提供账目 ID、HTTP 状态以及已记录的客户端请求、上游请求、会话、本地模型和模型源 ID。错误与核账理由仍放详情，不保存请求或响应正文，也不估造缺失 Token。

未知费用提示提供“查看请求”；记录列表可切换“仅看费用未知”。先按费用状态筛选再取最近 20 笔，旧未知费用不会被后续正常请求挤出窗口。该筛选只影响请求记录，日期、来源和 Agent 筛选继续有效，汇总和每日限额不变。

## User Stories

1. 我能看到费用未知但 Token 已知的请求用量。
2. 我能区分未收到回执与实际消耗零 Token，并复制记录 ID 反馈问题。
3. 产生更多正常请求后，我仍能查找旧的未知费用请求并核账。

## Technical Design

`local-model-gateway.ts` 保留 API 已有的逐笔 Token 和关联 ID，不再在适配时丢弃。`ModelProxySettings` 展示逐笔用量和详情，使用 `recentState=unknown` 请求过滤记录。`ModelUsageStatistics` 对缺失回执标记已知部分，图表数字仍是实际已返回用量，不补造缺失值。

`Ledger.StatisticsForCalls` 仅在近期记录查询中应用费用状态过滤；原统计入口保留兼容包装。API 校验并回显状态，前端检查回显和请求上下文，拒绝将旧节点未过滤的数据显示成未知费用记录。没有新增轮询、账本迁移或准入变更。

## Acceptance

- Go 回归覆盖两笔未知费用（一笔 Token 未知、一笔未定价但 Token 已知）后追加 25 笔正常请求，仍可筛选找回旧记录；验证真实零、缺失用量、关联 ID、汇总不受影响，以及非法状态返回 400。
- 前端回归覆盖适配保留逐笔用量和 ID、未知费用行显示数字与未知值、服务器端筛选，以及汇总区分未知与真实零。
- 主分支前端 167 文件、1224 项测试通过；保留完整 OKR 的整合源 173 文件、1252 项测试通过。两者均通过 typecheck、i18n、hover 与生产构建；Go 网关回归及整合 Go 全量通过，仓库 full 门禁复跑通过（首次会话续接测试出现时序失败）。
- 使用独立实例的 27 笔测试账目验收，未向生产账本写入测试数据，也未产生新的付费模型调用。桌面点击与 Android Redmi Note 8 真机触控验证“查看请求”、未知费用筛选、详情展开、滚动及返回导航；汇总保持 27 次、每日限额保持 100，缺失回执不补零。页面无横向或文档溢出，上下导航与操作栏可达。
