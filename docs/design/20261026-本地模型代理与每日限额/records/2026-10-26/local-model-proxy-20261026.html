本地模型代理与每日限额 · 2026-10-26

Product Design

内置主智能体、后台任务、记忆与压缩的模型 HTTP 请求统一经过当前节点的本地传输代理。沿用模型连接与密钥配置，不增加监听端口。模型与连接页展示今日已知费用、Token、请求与未知费用笔数，可按模型填写人民币每百万 Token 的输入、输出、缓存命中单价，并设置可选每日限额。价格为空代表未定价，零代表明确免费；本地记账不修改上游账单。

统计视图提供今日、近 7／30／90 天与累计周期；总览展示已知费用、请求数、总 Token、缓存命中率及输入／输出拆分，每日趋势可切换 Token 与费用并打开完整数值表，模型明细保留相同计量口径。完全未知的模型费用显示“未知”，部分未知时只展示“已知”金额；累计趋势限定最近 90 天并明确提示，总计与模型统计不丢弃更早历史。

User Stories

  • 我能在原模型设置页查看内置智能体的合计花费，并在重启后保留账目。
  • 我可按节点时区设置每日限额，达到后停止新请求；最后一笔在途调用可能超额。
  • 我能区分已知消费与缺价格、缺用量或中断后的未知费用；限额启用时未知费用阻止继续消费，失败不伪报免费。
  • 我能切换统计周期，对照每日趋势、分模型用量与总计，并保留正在编辑的限额和价格；缺少计量的请求不会被伪装为零消费。

Technical Design

providers/model_proxy.py 实现 httpx 传输代理、透传 SSE 与用量提取；model_billing.py 负责配置验证、固定精度人民币计价和 SQLite 请求账本。参考 ~/codes/llm-gateway/internal/observe 的三类 Token 计价，OpenAI 缓存命中从总输入中扣除，避免重复收费。每笔请求冻结价格，完成后只结算一次，不存提示词、响应正文或密钥。启用限额时主／后台请求串行准入，拒绝未定价模型、当天未知账目和达到限额的新请求。进程恢复将未结算请求保留为未知，不重放。每日按 memory_timezone 归属请求发起日。

统计修订：代理与计费支持今日、近 7／30／90 天与累计，展示周期总计、每日 Token／已知费用趋势及模型明细，分别统计输入、输出、缓存命中、请求、未知费用、未定价、缺用量、在途与失败。缓存 Token 属于输入，不重复加入总 Token。累计模式的总计与模型统计覆盖完整账本，每日序列最多最近 90 天并明示日期；无请求日期补零，最多展示 200 个模型并明确截断。providers/model_usage.py 按已持久化的请求归属日聚合，GET /agent/model-usage?days=0..90 保留今日接口字段。前端 model-usage-statistics.tsx 使用 CSS 图表与可展开的每日表格，不增加图表依赖或轮询；周期切换取消旧请求，统计失败不清空编辑草稿。

model_settings.py 原子保存 proxy 配置并保留现有所有者隔离、忙时拒绝与失败保留输入。GET /agent/model-usage 通过原 Go 登录网关返回当天合计及最近请求；页面进入与保存后读取，不增加轮询。价格编辑与限额复用现有设置草稿、令牌、中英语言包及手机表单。

上游费用回执修订 · 2026-10-26

产品设计与用户故事

费用使用上游已有回执，不再维护模型单价。用户可直接看到已知金额、币种和未知费用；今日、周期、每日与分模型费用按币种分别展示，不换汇。旧账保留为“历史估算”，不混入上游费用。每日限额选择币种；未知费用、未结算、历史估算或不同币种使后续限额请求暂停，最后一笔仍可能超额。

技术设计

providers/upstream_costs.py 读取 usage.cost 与现有 usage.currency；精确主机 openrouter.ai 依据官方约定使用 USD credits，不读取 cost_details.upstream_inference_cost。其他网关缺币种时不猜测。只接受有限非负数值，金额最多 18 位小数；流式回执须完整结束，后续 usage 缺金额会清除早先临时费用。金额与 Token 独立验证，缺 Token 不覆盖有效费用。金额有值但币种不明时不计入已知费用，已证实未发送的失败不会阻断后续限额请求。金额原样转十进制字符串入库，Decimal 精确累加，无浮点计费。

schema 14 增加 cost_amount／cost_currency／cost_source，保留旧 cost_nano 和 prices_json 供历史审计。旧价格配置可读取但不再用于计算；旧限额保持 CNY，新配置默认 USD。Go 恢复同步接受 schema 14。model_usage.py 为总计、每日和模型返回分币种 charges 及独立 estimatedCharges，模型按请求数排序，避免跨币种费用排名。费用字符串在前端精确格式化，图表仅在选定币种内比较。上游依据为 https://openrouter.ai/docs/cookbook/administration/usage-accounting；当前 llm-gateway 未返回逐请求费用时仍显示未知，不改造其上游协议。

日内分时修订

用户选择“按天分时”与日期，查看该日 24 个本地钟点的请求数、Token 和分币种费用趋势、可展开分时明细，以及同日总计和分模型统计。日期由节点的今日日期初始化，可查询历史日期；统计选择不会改写限额草稿。请求按账本保存的归属日、发起时间和时区归集；跨小时或跨日请求归入开始时段，夏令时重复钟点合并，不丢失费用。

GET /agent/model-usage?day=YYYY-MM-DD 返回选定日期的单日 statistics 与 24 档 hourly，顶部今日摘要仍为当前日。非法、非标准或未来日期拒绝；所有者校验不变。money_records 与 hourly_statistics 复用同一费用累加，未知与历史估算不混入实际金额。原生日期输入复用 antd Input 和项目令牌；更改日期会取消旧查询，防止晚到结果覆盖新选择，不增加轮询。

本地单价兜底修订 · 2026-10-27

产品与用户故事：用户可在“代理与计费 / 模型单价”为当前主／后台模型设置币种和每百万 Token 的输入、输出、缓存命中价格；缓存留空沿用输入价，0 明确表示免费。上游有有效费用回执时优先采用（包括零费用），否则对完整用量按自定义单价估算。费用、每日／分时模型构成和每日限额包含这些估算，界面单列本地估算来源；旧历史估算及未知费用不自动改账。表单支持统一保存、跨 Tab 保留、失败保留输入、还原和移除单价。

技术设计：model_pricing.py 严格校验最多 32 个模型的非负单价、六位小数与币种，并以 Decimal 计算非缓存输入、缓存命中及输出，缓存不会重复计费。准入将已规范化单价冻结到既有 prices_json；结算串行读取 pending 行，优先回执，缺回执才按该快照估算，重试结算不覆盖原账。完整的本地估算写 cost_source=estimate、cost_amount 和 cost_currency，历史估算仍为 cost_amount=NULL；复用 schema 14，不新增迁移。统计 charges 是计入限额的总额，localCharges 单列其本地估算部分，estimatedCharges 仅保留历史估算；unknown／localEstimated 分开统计。未知用量、取消、中断及未发出的失败不会按单价假设收费。旧 prices 配置按原 CNY 语义兼容读取，仅影响后续请求。

验收：计费／价格／统计定向后端 90 项、前端全量 1,016 项通过。回归覆盖上游费用（含零）优先、缓存不重复计价、缓存默认价、显式免费、请求价格快照、幂等、统计与限额、币种不匹配、旧未知记录不追溯、旧客户端只改限额时保留已有单价及非法配置不落盘。隔离 Go 网关与真实 Python／本地 HTTP 上游验证：无费用回执的 1,000 输入、100 输出、400 缓存按测试单价 2／8／0.2 记为 CNY 0.00208 本地估算，达到限额后上游请求数仍为 1。页面完成保存、部分价格阻断、跨 Tab 草稿、还原、刷新恢复、移除、估算标记及七档宽度／中英／深浅主题检查。证据位于 /tmp/model-pricing-fallback-20261027/。真实 Android 仍为安全锁屏，真机触控与键盘验收未完成，未修改现用服务。
