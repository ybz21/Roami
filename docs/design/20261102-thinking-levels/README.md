# 思考强度：四档与对齐

方案已于 PR #607 合入；产品实现与验收见 [实现记录](implementation.md)。以下为 2026-11-02 的设计方案。

[交互示意](index.html) 支持桌面 / 手机局部预览和四档切换，不发送请求。

## 产品设计

常用入口统一为 **默认、低、中、高**，包括默认在内最多四个选项。名称已由用户确认。
默认保持当前模型原有策略，不承诺自动判断任务难度，也不等同于中档。

| 选项 | 一句话说明 | 常规参数 |
| --- | --- | --- |
| 默认 | 使用模型默认设置 | 不指定强度；现有接口写入 null |
| 低 | 简单任务，优先响应速度 | low |
| 中 | 日常任务，兼顾速度与深度 | medium |
| 高 | 复杂任务，投入更多思考 | high |

不把“不思考、极轻量、超高、最高”继续作为主入口的独立档位。
更高强度可能增加等待和用量；不承诺任何档位一定更准确、一定省钱或固定快多少。
菜单、输入栏与设置统一使用“默认、低、中、高”，不再使用“轻量、标准、深入”作为档位名称。

### 竞品怎么做

下表区分产品界面与 API，不能把 API 枚举数量当成所有用户实际能看到的选项数量。

| 对象与官方来源 | 当前做法 | 对 Roami 的启发 |
| --- | --- | --- |
| [ChatGPT Work / Codex](https://learn.chatgpt.com/docs/models#pick-a-reasoning-effort) | 文档列出 Light / Medium / High / Extra High；另有 Max / Ultra。Work 与桌面端主控制使用 Power 预设，具体模型、强度、速度进入 Advanced；可用项随客户端和计划变化。 | 主入口与精确参数分层；不能宣称它总共只有四档。Ultra 还涉及并行执行，不宜当成普通强度直接照搬。 |
| [Claude 产品](https://support.claude.com/en/articles/8664678-change-the-model-effort-and-thinking-settings) | Low / Medium / High / Extra high / Max，按模型提供；用 Default 标记模型推荐档。Thinking 开关与 effort 分开，部分模型不能关闭思考。 | 默认不是“不思考”；展示能力应依赖模型，不能对所有模型提供关闭。 |
| [Gemini API](https://ai.google.dev/gemini-api/docs/thinking#controlling-thinking) | 按模型提供二到四种原生值：minimal / low / medium / high 的子集；省略时保留模型默认行为。 | 使用能力子集，不为了凑满四档编造映射。这是 API 行为，未据此断言 Gemini 消费者应用界面。 |

归纳为本项目的设计判断：四档是 Roami 为减少选择成本作出的取舍，不是供应商共同标准；同名强度也不能跨模型承诺相同耗时或能力。

### 截图问题与对齐规则

现有截图中输入栏的“高”与菜单的“深入”指向同一值，用户需要自行对照；菜单还混入多个供应商的原始参数。
代码中 `AgentModelPicker` 的标题左留白是 12，选项文字左留白是外层 8 加行内 12，共 20，造成 8px 偏差。
说明文字与选项文字也没有共用起点。截图不足以判断浮层实际锚点是否错误，因此不把浮层位置另列为已证实缺陷。

- 标题从 `--sp-4` 开始；列表外侧 `--sp-2`，行内 `--sp-2`，文字也从 `--sp-4` 开始。
- 若保留说明或错误提示，同样从 `--sp-4` 开始。移除本菜单中“用于首页对话；任务执行器……”的范围说明；任务边界说明留在模型设置。
- 四行均为主标题加短说明，文字整体垂直居中；选中标记放固定的右列，不挤动正文。
- 选中背景用 `--sel-bg`，标记用 `--accent`；关闭与选中标记复用 `icons.tsx`，不加装饰图标。
- 输入栏、菜单、设置和可访问名称使用同一个标签来源，例如都显示“高”，不再一处显示“深入”。
- 桌面复用现有输入区上方浮层，避开视口边界；手机复用短选项底部 sheet，保留安全区与键盘避让。此任务不引入新的页面或弹层体系。
- 使用现有字体、间距、圆角、表面令牌；四个选项正常视口内完整可见，短屏允许菜单内部滚动，文档不滚动。

## 用户故事

- 我只想开始对话：保留默认，不必理解七种底层强度。
- 我希望更快完成简单任务：选低，输入栏立即使用同一名称显示服务端确认后的状态。
- 我需要分析复杂问题：选高，并知道它通常需要更多等待。
- 我更换模型：只看到该模型真正支持的档位，不在提交后才发现不支持。
- 我已配置 xhigh 或 max：打开菜单不会改变配置，也不会冒充已选择 high。
- 我在手机点选：能直接看见说明和选中状态，不依赖悬停提示，返回时保留草稿。

## 技术设计

### 现状与边界

- `frontend/src/components/agent/agent-reasoning.ts` 将默认项追加到能力列表；未知模型回退到七种原始参数，最终形成截图里的八行。
- `AgentModelPicker.tsx` 使用 `agent.reasoning.*` 渲染菜单、`composer.effort.*` 渲染输入栏，两套翻译产生名称差异。
- `components/settings/agent-settings.tsx` 也直接枚举能力；不能只修首页，保留另一个八档的普通设置入口。
- `agent-runtime/src/roami_agent/providers/reasoning_effort.py` 对未知模型宣告全部七种能力。这是“兼容参数可能被接收”的宽松回退，不能直接当成已验证能力。
- 网关负责协议转换与参数准入；本方案不把 token 上限、并发或费用限制混入强度，不调整本机保存的模型路由与执行器选择。

### 模块与数据流

在现有 `agent-reasoning.ts` 中集中定义展示档位、i18n key、原始值投影与可用选项，首页和普通设置共用。
保留现有原始参数存储及 `GET /agent/model-settings`、`PUT /agent/model-settings` 的结构，避免只为四档 UI 引入存储迁移。

| 能力状态 | 主入口 |
| --- | --- |
| 明确支持 low / medium / high | 默认、低、中、高 |
| 明确支持 low / high / max | 默认、低、高；max 不变成第五档 |
| 明确只有 high / max | 默认、高 |
| 仅支持 minimal 等其他值 | 仅默认；精确参数在高级配置处理，不猜测它等于 low |
| 明确不支持强度 | 隐藏选择器，使用模型原有行为 |
| 模型能力未知或加载失败 | 不拿通用七值当能力；保留已有配置，只允许恢复默认，并提示“暂时无法确认可用档位” |

普通设置同样最多四个选项。精确的 none / minimal / xhigh / max 等仍允许在高级原始参数配置中维护，
该处保留原始值与能力校验，不再添加一个超过四档的普通强度菜单；高级配置入口属于后续实现范围，不能假定当前已有。

后端需要明确区分“已确认能力”“不支持”“未知”：可在现有能力回执增加兼容字段，例如 `reasoningSupport`。
前端不得自行按模型名猜测，更不能把当前 Python 的未知模型回退列表当成探测结果。
未被供应商或模型元数据确认的能力应为未知；供应商元数据不一定提供该字段，能力表要注明来源，禁止启动时花费真实 token 探测。
网关继续负责最后的参数校验，展示收敛不等于删除现有协议兼容性。

### 原始参数与旧值

1. 新的显式选择严格映射 `低=low`、`中=medium`、`高=high`；只有能力明确支持才出现。不做 `高=max` 或 `中=high` 的自动替代。
2. 默认在既有保存接口写 null，由后端移除显式强度；不是写入字符串 `default` 或强制 medium。
3. 已保存 none / minimal / xhigh / max 等值原样保留。输入栏显示“自定义”，菜单无四档勾选，菜单状态区显示“当前使用自定义设置”；精确值在高级配置查看。状态区不是第五个选项。
4. 用户选回任一四档后才写入新值；取消、关闭或点击原选项不写。旧值即使已不被能力回执支持，也不能在后台静默重写。
5. 切换模型沿用现有原子保存模型与默认强度的行为；保存失败保留服务端确认值和草稿，保留原选项重试。
6. 当前模型的默认档与显式 medium 可以执行效果相同，但仍保持不同的配置语义。

### 实施顺序

1. 明确能力回执来源与未知状态，补强服务端校验；不扩展真实模型调用范围。
2. 集中四档展示与旧值兼容逻辑，让首页和普通设置共用；中英文翻译与 aria-label 同步。
3. 统一标题、选项、状态区留白和选中列，移除无关说明，复用现有浮层与手机 sheet。
4. 验证映射、未知模型、旧值不改写、原子保存与失败恢复；再完成桌面和真机验收。

## 验收标准与当前证据

本次只交付方案及局部 HTML 示意，不修改前端、Python 或网关运行逻辑，不声称完成真实手机验收。
示意稿用设计工具栏手动切换画布尺寸，生产实现仍必须使用 `useLayout()`。
示意稿中文是开发者设计文档；产品新增文案必须通过现有 i18n，不直接搬 HTML 字符串进组件。

示意稿检查：浏览器桌面与手机画布均为四项，标题和选项文字的左起点差为 0 CSS px，文档无横向溢出。
点选中档后，菜单选中值与输入栏均显示“中”，菜单关闭；行高约 58px，关闭命中区域 44px。
图标路径与颜色、尺寸令牌摘自现有 `icons.tsx` 与 `index.css`，没有引入新的视觉刻度。
这是浏览器画布检查，不代替 Android 真机触控验收。

桌面与手机画布截图随 PR 正文提供，存于 `pr-shots` 分支；设计源文件为本目录的 `index.html`。

后续实现必须满足：

- 所有普通入口最多四个可选档位，默认计入四档，模型能力子集正确。
- 输入栏、菜单、设置、可访问名称一致；标题与行文字起点偏差不超过 1 CSS px。
- 自定义旧值不显示错误勾选，打开关闭不写入；取消、失败、重试不丢配置或草稿。
- 默认确实清除显式参数，不向上游发送 `default`；high 不变成 max。
- 深浅主题、英文长说明、键盘方向键 / Enter / Escape、保存中及失败状态可用。
- 隔离实例完成桌面截图与 Android LAN HTTPS 真实点按、返回、键盘避让检查；命中区至少 44px，文档无溢出。
- 运行仓库规定的范围内门禁；若修改 Python 或网关，同时运行对应检查和参数转换回归。
