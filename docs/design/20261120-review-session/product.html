创建任务

沿用现有「开任务」弹窗。「互审」位于上排工具条，默认收起。点击后下方展开以「审查者」为标题的一行，显示 Agent Logo 和交审方式。再次收起时保留已选设置。

审查 Agent
与作者共用全部已注册 Agent 选项。推荐由另一种已就绪 Agent 审查，也可以选同一种 Agent 的独立会话。点 Logo 改选后保留该选择。
主动交审
由作者决定首次交审时机。
空闲交审
作者空闲且有稳定的工作区变更时，Roami 发起首次交审。

两种方式只决定首次交审时机。后续的新版本都可自动复审，也可由作者主动提前交审。

会话与复审

点击「开干」时同时准备独立的 review 子会话。桌面从项目树或会话标签进入，手机从项目列表或作者会话的对端入口进入。审查者启动后先显示「等待交审」。

  1. 作者提交可审版本，审查者在自己的终端里核对任务范围和改动。
  2. 审查者发出结论。作者在原会话直接收到完整意见，可继续修复和验证。
  3. 作者产出修复版本后，原 review 会话继续下一轮。同一个版本只审一次。
  4. 每批默认最多 3 轮。通过后这一批结束，下一次变更开新一批。3 轮都未通过时保留意见，在作者或审查会话里提供「继续互审」，由用户决定是否重新开启一批。

开工指令由宿主下发。发送命令可以从实际执行记录展开查看。

持续复审

「模型中心改进」的第 1 轮只审了 account-routing-review.md。之后作者工作区合入了 3 个代码提交，列表仍显示「互审通过」。改进后，通过只表示当前工作区与已审快照一致。

当前版本已通过
审查者通过本轮快照，Roami 核对当前变更与该快照一致。轮次、版本摘要和意见留在审查历史里。
待复审
已审工作区出现新变更时，列表和终端切换到「待复审」。作者忙时合并连续改动，等空闲且内容稳定后交给原 review 会话。
审查中
审查者检查提交时的快照。审查期间继续改动时，详情提示有新版本待审。旧快照即使通过，列表也要等新版本通过后才显示「当前版本已通过」。
暂无可审变更
清理临时文件或撤回改动后，若相对开工基准没有变更，记录里仍能查看之前的通过意见。工作区出现新变更后再交审。

按这个现场走一遍：分析文档通过后归档，列表显示「暂无可审变更」。代码提交合入作者工作区后，状态变为「待复审」。作者空闲后，原审查者收到代码版本的下一轮请求。

列表只显示短状态，详情才展示历史和验证依据。独立子任务的改动进入作者工作区后，纳入该会话的互审范围。项目任务完成、PR 评审和合并各有自己的状态。

用户故事

  • 创建任务时，我用两个 Logo 区分作者和审查者，选好何时交审即可开工。
  • 开工后，我从作者下方打开 review，看到所选 Agent 正在等待或审查。
  • 审查者发回意见后，我在作者会话查看涉及的文件、问题和依据，能在两边来回核对同一轮版本。
  • 首轮通过后我继续写代码，能看到「待复审」，并在原审查会话里看到下一轮。打开历史时，我能核对每次通过覆盖了哪些改动。
  • 准备失败时，我能用原配置重试，或收起互审后继续任务。
