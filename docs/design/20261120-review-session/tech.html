会话创建

作者与审查者各有一个独立的普通 Agent 终端会话，绑定同一个任务工作区。宿主启动两个会话，给审查者绑定只读快照来源，并在开工前记录父子关系。持续复审复用这组配对。

  1. 宿主用现有创建意图受理任务。互审配置仅带 Agent 类型和交审方式。用户省略互审时沿用原有创建流程。
  2. 准备 worktree 和作者会话，以同一创建操作预留 review 的稳定 ID，保存父子关系、同一个工作区归属和审查者角色。按当前节点注册表核对审查 Agent 和它的启动参数，检查安装与登录状态。未就绪时保留选择并提示恢复。
  3. 先启动审查者，将作者 ID、任务范围、约定和版本访问方式一起注入启动 Prompt。收到审查 Agent 的就绪标记后启动作者，在原开工 Prompt 末尾追加 review ID 和对应的交审指令。然后展示「等待交审」。
  4. 宿主持久化操作、会话身份和启动阶段回执。回执已确认则复用现有子会话。提交结果未知时先核对接收端身份和实际状态。准备失败时可以重试，或关闭互审后继续开工。

独立原型使用示例数据。实际产品由宿主创建会话、生成版本快照并投递消息。

双方启动 Prompt

作者的原任务、开工说明和能力指南保持原有顺序。互审约定追加在末尾。宿主用实际值替换下方占位符。作者在原会话内写代码、验证并响应审查。审查者核对本轮版本和证据。

发给作者

你是任务作者，工作区为 {{WORKTREE}}。
审查会话 ID 为 {{REVIEW_SESSION_ID}}，每批最多审 3 轮。

主动交审：有可审版本时，向 review 发送验证摘要，由宿主绑定轮次和版本。
空闲交审：首轮等待宿主提交。

收到意见后，逐项修复或说明，再运行相关验证。
后续变更在空闲且稳定后由宿主交审。也可以主动提交新版本及验证摘要。
通过意见只覆盖请求中的版本。继续改动时，等待或主动发起下一轮。
只向下发的对端稳定 ID 发送消息。

发给审查者

你是审查者。作者会话 ID 为 {{AUTHOR_SESSION_ID}}。
首轮任务为 {{TASK_SCOPE}}，每批最多审 3 轮。

输出独立一行 ROAMI_REVIEW_READY，再等待交审。
收到请求后以本轮范围及只读补丁为准，并注明验证证据对应的版本。
发回结论、文件位置、问题、依据和建议，或说明通过的验证依据。
使用 roami session send 发回完整意见，包含请求中的轮次和完整版本摘要。
发出意见后回到等待。收到下一轮请求时重新读取本轮快照。

消息投递

普通会话使用 roami session send SESSION_ID TEXT 提交互审消息。标记消息写入配对队列，宿主在接收端可接收时投递到绑定的终端。发送端和接收端各自保留对话记录。

roami session send "$REVIEW_SESSION_ID" '[review.request] 验证摘要，请审阅'
roami session send "$AUTHOR_SESSION_ID" '[review.changes_requested] r1 rev=ROUND_1_FULL_SHA256 文件:行、问题、依据、建议'
roami session send "$REVIEW_SESSION_ID" '[review.request] 已修复并验证，请复审'
roami session send "$AUTHOR_SESSION_ID" '[review.approved] r2 rev=ROUND_2_FULL_SHA256 已核对改动与验证证据'
  • 每次请求携带轮次、完整版本摘要、基准、只读补丁及审查范围。作者主动交审可附上本轮任务范围和验证摘要。自动交审以本轮快照里的变更为范围，并带上前一轮结论。首轮任务用于提供背景。
  • 补丁生成后不可覆盖。审查者只对本轮快照出具结论。在共享工作区里运行的测试，只有核对输入版本一致后才能作为本轮通过依据。无法核对时，结论写明未验证项。
  • 接收端须仍是配对的 Agent 且能接收输入。路由以稳定 ID 及运行身份核验，遇到退出、变成 shell、忙碌或身份变化时停在可恢复的状态。
  • CLI 成功表示互审消息已排队。宿主通过发送进程的终端归属核验配对身份，记录类型、轮次、版本及投递回执。结果未知时停止投递并显示中断，避免回放重复意见。
  • 此链路覆盖普通交互会话。受管任务继续使用当前修订对应的 task_steer，Swarm 成员继续通过 roami swarm say 续接。

版本核验

  1. 沿用配对记录中的开工 Git 提交作为基准。把已提交、已跟踪和未忽略的未跟踪变更生成规范补丁。复用同一个补丁生成器计算 SHA-256；日常探测只算摘要，正式交审才保存只读补丁。独立工作区的变更以进入作者工作区时为准。
  2. 保存最新核验的工作区摘要、待审摘要和每轮的实际裁决。宿主只有在当前摘要与通过轮次完全一致，且当前没有待处理的请求时，才向会话概览发布「当前版本已通过」。上一轮的通过只留在历史。
  3. 探测到修改时先撤下通过标记。工作区无变更则显示「暂无可审变更」；摘要核验失败或超过核验期限时显示「待核验」。恢复原已审内容且没有待处理请求时，可以复用对应的通过记录。
  4. 发布请求前核对工作区仍是待审摘要。生成补丁期间检测到变化就丢弃候选，重新等待稳定。裁决必须匹配正在审的轮次和摘要；接收后再次核对工作区，避免旧裁决覆盖新版本的「待复审」。终端仍接收上一轮意见，消息同时标明该意见是否对应当前版本。

复审调度

  1. 首轮遵从用户选的交审方式。首轮交审后，只要工作区有未审版本且本批有预算，宿主在作者空闲、变更稳定至少 30 秒后创建下一轮。作者可主动提前交审，仍需核对摘要、轮次和预算。
  2. 配对内同一时间仅有一个在途请求。审查中产生的新改动只更新待审候选，上一轮结束后重新核对并提交最新稳定版本。自动和主动交审在同一配对锁内去重，同一工作区摘要不会因为多次触发而重复计轮。
  3. 复用宿主会话观察器和会话概览。工作区或 Git 元数据事件用于标记待核验，事件丢失时对仍存活的互审配对做低频核验。后台任务去重、限制并发并对错误退避；普通会话和前端页面不增加轮询。核验超时后撤下通过标记，不能沿用过期结果。
  4. 宿主继续核对两端会话和终端身份。关停、身份变化或投递结果未知时暂停自动复审，保留回执，按原有恢复规则核对后续接。

多轮审查

等待交审
双端已就绪。收到有效的新版本后进入第 1 轮。
审查中
显示当前轮次，审查者对该版本发回修改意见或通过结论。
待修复
作者收到意见。出现新版本后按同一批的下一轮继续。
待复审
工作区有更新且当前版本未通过。上一批通过后新开一批；旧轮次仍在审查中时，先等它结束。
当前版本已通过
该版本所在的一批结束，宿主继续核验工作区。
达到轮次上限
同一批 3 轮未通过，暂停自动交审。用户点「继续互审」重新开启一批，有新版本时继续，保留全部意见。
已中断
会话关闭、身份变化或投递需要核对时停在当前轮次，保留回执供核对。取消创建时只回收当前操作创建且已核对的资源。

存储中分别记录批次和每批预算。CLI 的 rN 在整组会话内递增，允许超过 r3；配对锁内校验序号和完整摘要。实际送达审查者才计轮。重复摘要、空变更、核验失败和排队前候选被替代均不计轮。

兼容与验收

  • 旧记录的裁决和只读补丁保留为历史。升级后，仍存活的配对先核对终端身份、工作区和当前摘要；只有当前摘要吻合才恢复通过。两端可用且工作区已变更时，沿用原子会话安排复审。旧启动指令中的停止约定由新版交审请求更新。
  • 先实现当前版本核验和撤下旧标记，再启用自动复审，并联调列表和终端状态。用两个新隔离实例分别验证整条复审路径和关闭互审的普通任务。上线前核对空闲期间的探测次数、队列积压与核验延迟。
  • 以持续复审验收用例为准。至少一条真实 Agent 路径要在首轮通过后继续改代码，并由原审查者通过新的快照。

代码落点

创建表单
作者和审查者都从同一个 Agent 注册表 获取当前节点的 Agent，复用图标和 i18n。TaskComposer 与 NewSessionModal 共享互审配置和创建意图。
宿主生命周期
在 创建生命周期的互审阶段 准备 review 会话与回执，给双方绑定对端稳定 ID。旧 autoReview 布尔值兼容原有路径。
快照与记录
快照生成 负责补丁和摘要，互审存储 持久化版本、批次与回执。
状态与投递
互审协议 校验版本、预算和身份。会话观察循环 调度稳定版本并复用既有终端投递。
会话树与终端
桌面项目树、手机项目列表和终端状态栏共用宿主输出的当前状态，保留现有对端入口。
