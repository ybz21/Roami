会话创建

作者与审查者各有一个独立的普通 Agent 终端会话，绑定同一个任务工作区。宿主启动两个会话，给审查者绑定只读快照来源，并在开工前记录父子关系。每次互审最多审 3 轮。

  1. 宿主用现有创建意图受理任务。互审配置仅带 Agent 类型和交审方式。用户省略互审时沿用原有创建流程。
  2. 准备 worktree 和作者会话，以同一创建操作预留 review 的稳定 ID，保存父子关系、同一个工作区归属和审查者角色。按当前节点注册表核对审查 Agent 和它的启动参数，检查安装与登录状态。未就绪时保留选择并提示恢复。
  3. 先启动审查者，将作者 ID、任务范围、约定和版本访问方式一起注入启动 Prompt。Agent 就绪后启动作者，注入 review ID 和对应的交审指令。然后展示「等待交审」。
  4. 宿主持久化操作、会话身份和启动阶段回执。回执已确认则复用现有子会话。提交结果未知时先核对接收端身份和实际状态。准备失败时可以重试，或关闭互审后继续开工。

原型用浏览器模拟创建、版本和终端记录。用户的任务、图片、会话和代码仅提供设计参考。

双方启动 Prompt

宿主用实际值替换下面的占位符，原任务正文保持在开工提示之前。作者在原会话内写代码、验证并响应审查。审查者核对本轮版本和证据。

发给作者

你是任务作者，工作区为 {{WORKTREE}}。
审查会话 ID 为 {{REVIEW_SESSION_ID}}，最多审 3 轮。

主动交审：有可审版本时，向 review 发送轮次、版本和验证摘要。
空闲交审：首轮等待宿主提交，有意见时在原会话内继续修复。

收到意见后，逐项修复或说明，再运行相关验证。
仍可复审时，发送新版本和新的验证摘要。通过或达到上限时结束。
只向下发的对端稳定 ID 发送消息。

发给审查者

你是审查者。作者会话 ID 为 {{AUTHOR_SESSION_ID}}。
任务范围为 {{TASK_SCOPE}}，最多审 3 轮。

等待交审。收到请求后读取本轮基准和只读快照，核对版本及证据。
发回结论、文件位置、问题、依据和建议，或说明通过的验证依据。
使用 roami session send 把完整结果发回作者会话。
有修复时等待作者提交下一版本，并在同一 review 会话里继续。
只审阅本轮快照。通过或达到上限时结束。

消息投递

普通会话用 roami session send SESSION_ID TEXT。发送端能从执行记录查看命令，接收端把原文当作一次 Agent 输入。两边独立保留各自的对话历史。

roami session send "$REVIEW_SESSION_ID" '[review.request] r1 rev=b7a18c2 验证摘要，请审阅'
roami session send "$AUTHOR_SESSION_ID" '[review.changes_requested] r1 rev=b7a18c2 文件:行、问题、依据、建议'
roami session send "$REVIEW_SESSION_ID" '[review.request] r2 rev=e124dc0 已修复并验证，请复审'
roami session send "$AUTHOR_SESSION_ID" '[review.approved] r2 rev=e124dc0 已核对改动与验证证据'
  • 首轮「主动交审」由作者发起。「空闲交审」由宿主在确认作者空闲且有新变更时发起。后续轮次由作者提交新版本。
  • 每轮保存基准、变更摘要和只读快照。审查端读快照，作者负责写入。恢复时使用已登记的版本。
  • 接收端须仍是配对的 Agent 且能接收输入。路由以稳定 ID 及运行身份核验，遇到退出、变成 shell、忙碌或身份变化时停在可恢复的状态。
  • CLI 成功证明输入已提交。宿主以实际发送方身份、配对、消息类型、轮次及版本建立审查回执。终端正文中的标记仅用于关联。重复请求、旧版本结论及结果未知的投递不新开轮次。
  • 受管任务使用当前修订对应的 task_steer，Swarm 成员通过 roami swarm say。宿主按会话类型选择路由。

多轮审查

等待交审
双端已就绪。收到有效的新版本后进入第 1 轮。
审查中
显示当前轮次，审查者对该版本发回修改意见或通过结论。
待修复
作者收到完整意见，在原会话修复、验证并提交新版本，review 进入下一轮。
通过
当前版本已通过，停止自动交审，保留完整历史。
达到轮次上限
第 3 轮仍有待改项时结束，最后意见留在双方会话。已记录的轮次保留用于追溯。
已中断
会话关闭、身份变化或投递需要核对时停在当前轮次，根据回执恢复。取消时只回收当前操作创建且已核对的资源。

同一版本重复提交不计新轮次。审查通过只对应本轮版本及验证依据，外部 PR 评审与合并沿用原流程。

代码落点

创建表单
作者和审查者都从同一个 Agent 注册表 获取当前节点的 Agent，复用图标和 i18n。TaskComposer 与 NewSessionModal 共享互审配置和创建意图。
宿主生命周期
在 创建生命周期 的作者启动前准备 review 会话与回执。启动指令按双方角色绑定对端稳定 ID。旧 autoReview 布尔值兼容原有路径；新的互审记录走单一流程。
状态与投递
宿主记录作者 ID、review ID、交审方式、上限、当前轮次、版本快照、消息状态和核对结果。普通会话使用既有会话发送路径，审查数据复用 Review Mesh 可用的差异读取与意见结构。
会话树与终端
项目树 先读父子绑定与角色，旧陪跑会话保留兼容。桌面标签和手机入口进入现有会话视图。

验证记录见 原型验收。现阶段交付原型和上线设计。
