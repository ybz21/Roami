## 持续复审验收用例

以下用例用于持续复审回归。

| 场景 | 预期 |
| --- | --- |
| 首轮只审 Markdown，归档后再合入代码 | 查到原通过记录；归档后显示「暂无可审变更」；新代码显示「待复审」，同一审查会话收到新的补丁和轮次；新版本通过后才恢复当前版本通过 |
| 审查中继续改代码；旧轮回传通过 | 保留旧裁决及其版本；自动提交稳定的新版本；旧裁决送达时列表不能显示当前版本通过 |
| 作者连续编辑；与主动交审同时触发 | 最终稳定版本只送达一次；同版本、空变更和未送达的候选不计轮；发生探测错误时展示「待核验」 |
| 同批发回修改 3 次；之前也通过过其他版本 | 当前一批达到上限并保留意见；用户点「继续互审」后以新版本续审；已通过一批后发生的新改动直接开启下一批，CLI 轮次跨批递增 |
| 升级前已有通过记录；重启时工作区已变更 | 存活配对先核验，再显示「待复审」并继续；历史保留；失联或投递未知时不重复投递 |
| 桌面项目树、手机项目列表与两侧终端 | 同一版本的状态一致；项目树只显示短状态，可以通过对端入口查看历史；Android 验证触控进入 review 后返回作者 |
| 两个新隔离实例 | 一个用真实 Agent 完成首轮通过后再交审代码，核对作者、审查者、轮次、摘要、回执和页面；另一个验证关闭互审后开工与取消准备仍能正常工作；记录配对的后台核验频率和普通会话请求数 |
