# 创建任务时配置互审

[打开中文原型](prototype.html?lang=zh) · [英文浅色原型](prototype.html?lang=en&theme=light) · [验收记录](acceptance.md)

## 产品设计

在「开任务」保留原来的互审入口。关着时只显示「互审」，开启后就地选择审查 Agent 和交审方式。任务创建时，在同一个任务工作区为作者创建一个持久的 `review` 子会话，并启动所选审查 Agent。作者开始执行时，审查者显示「等待交审」。桌面在项目树中直接打开子会话，手机从项目或任务页进入独立的审查页。

| 字段 | 原型决策 |
| --- | --- |
| 互审 | 新任务默认关闭。原型首屏已开启，便于直接检查配置 |
| 审查 Agent | 默认选另一种执行器，例如 Codex 的任务由 Claude Code 审。也可明确选择同一种执行器，由独立会话审查。切换作者时仅重算默认配对，保留显式选择 |
| 交审方式 | 默认「主动交审」，作者在有可审版本时主动发消息。「空闲交审」由宿主在作者空闲且有新变更时发出首次交审，之后由作者明确提交复审。两个方式都由同一对会话通信 |
| 最多轮次 | 默认 3 轮，可选 1、2、3。一次有效版本进入审查算一轮。最后一轮有未解决问题时显示「达到轮次上限」，并保留意见 |
| Prompt 预览 | 可分别展开作者和审查者的指令。创建前用占位符，创建后显示实际绑定的稳定 ID。工作区、交审方式与轮次由宿主填入 |

PR 进度、外部评审、合并与任务验收沿用各自流程。审查结果只说明对应版本的本地互审结论。

### 用户故事

- 创建任务时，我能指定谁审、何时审，并看到让双方通信的实际指令。
- 开工后，我能立即点开 `review` 子会话，看到所选 Agent 到位并等待交审。
- 审查开始后，我能从任一会话回到另一方，找到对应版本的意见、修复交审和最终结论。
- 准备失败时，我能在原配置上重试，或明确关闭互审再开工。续接失败时，保留当前轮次与上下文。

## 技术设计

### 现状与迁移点

- [TaskComposer.tsx](../../../frontend/src/components/sessions/TaskComposer.tsx) 和 [NewSessionModal.tsx](../../../frontend/src/components/sessions/NewSessionModal.tsx) 传入 `autoReview` 布尔值。[创建生命周期](../../../backend/api/session-lifecycle-create.go) 在作者启动前登记插件跟踪。
- [Review Mesh](../../../plugins/reviewmesh/reviewmesh.go) 的自动模式通过陪跑会话观察作者空闲，并为每轮调用审查子进程。项目树还会按名称识别旧陪跑会话。[task-tree.ts](../../../frontend/src/components/shell/task-tree.ts)
- 上线时两个入口共用互审配置，向创建意图新增 `review: { agent, trigger, maxRounds }`。旧布尔值继续走原路径。新的配对使用明确的父子关系和 `reviewer` 角色；同一作者只由一条流程驱动，避免旧插件再起审查。

### 创建和恢复

1. 复用会话生命周期完成任务工作区和作者会话的准备。启用互审时，在同一次创建操作中预留并记录子会话 ID，绑定到同一个工作区与作者。审核方读版本快照，写权限只给作者。
2. 注册真实父子关系和双方角色。按当前节点实际可用的执行器与启动参数启动所选 Agent，核对双方目标身份，注入各自 Prompt。审查端先就绪，作者随后开工。启动阶段在 UI 显示「准备审查会话」，以 Agent 就绪回执进入「等待交审」。
3. 复用操作 ID 和阶段回执恢复创建。已确认的子会话重复使用。提交结果未知时先核对当前会话与 Agent，等待核对期间保留草稿。确认取消后只回收本次操作创建且核验过的资源；关闭子会话不清理作者的工作区。审查无法准备时显示「重试」与「关闭互审并开工」。
4. 桌面树依角色显示短名 `review`、Agent 与审查状态。手机用同一个项目上下文打开全屏会话页。原型中的会话、版本、消息和状态都由浏览器模拟。

### 通信约定

作者与审查者是普通交互会话时，双方 Prompt 都绑定对端稳定 ID，使用已存在的 `roami session send SESSION_ID TEXT`。下列语法在本机 CLI 帮助中已核对。

```bash
roami session send "$REVIEW_SESSION_ID" '[review.request] r1 rev=b7a18c2 请审阅该版本'
roami session send "$AUTHOR_SESSION_ID" '[review.changes_requested] r1 rev=b7a18c2 文件:行、问题、建议'
roami session send "$REVIEW_SESSION_ID" '[review.request] r2 rev=e124dc0 已修复并验证，请复审'
roami session send "$AUTHOR_SESSION_ID" '[review.approved] r2 rev=e124dc0 已核对改动与验证证据'
```

- 自动交审复用宿主对作者的空闲观测，只在新版本可审时发送首次交审。切换会话或重连永远不会触发新一轮。
- 宿主为每轮绑定可重现的只读变更快照，包含基准与版本摘要；作者修改后提交新的版本。普通会话投递前核对接收端仍是配对的 Agent，并避免向运行中的接收端或 shell 注入消息。消息中的轮次、版本与类型用于关联；相同配对、轮次和版本去重。能更新审查状态的记录还须由宿主核对发送方身份、配对关系及当前版本。CLI 成功只证明输入已提交。
- 受管任务的同类消息走当前修订对应的 `task_steer`，Swarm 成员走 `roami swarm say`。在宿主能按会话类型路由前，原型的会话直发模式仅适用于普通会话。
- 区分「等待交审」「审查中」「待修复」「通过」「达到轮次上限」「已中断」。状态及结论挂在任务详情和该审查会话下。重复消息、等待回执和失效结论不推进轮次；超过上限、作者关闭或审查暂停后，由用户决定是否恢复。

### 模块落点

| 层 | 复用与变更 |
| --- | --- |
| 前端 | 两个入口复用互审字段、已注册 Agent 查询与 i18n。项目树优先读真实亲缘关系和角色，审查详情订阅现有会话事件 |
| 宿主 | 会话创建工作流记录配对、启动回执、版本快照及消息接收；按普通会话和受管任务分发 |
| 审查能力 | 复用 Review Mesh 的差异读取、问题数据和结论展示；保留旧入口的兼容路径 |

## 原型方向

沿用截图中的深色 Roami 工作区。创建配置在输入区下方展开，首次可见的信息只有审查 Agent、交审方式、轮次和 Prompt 入口。创建后，任务与 `review` 子会话在项目树相邻，可点开查看等待和审查进展。手机沿用项目顶栏与底栏，配置及审查详情各用一个带返回键的全屏页面。原型里的「演示」按钮用于推进示例消息。
