Pi 实际怎么做

文本文件：分页，不一次塞满

read 按行 offset / limit 读取，默认返回最多 2,000 行或 50 KiB，以先达到的为准。返回说明已读范围、是否截断以及下一次 offset；遇到超长单行会提示换方式读取。该版本的工具截取使用行数和字节，和整个会话的 token 压缩机制分开。

Pi read.tsPi truncate.ts

Shell：保留尾部，完整输出写临时文件

bash 的长输出保留最后的行或字节片段，截断时保存完整输出，并返回 fullOutputPath。模型需要更多内容时再次读取文件。结束状态和截断是两件事，不能因为输出长就当作命令没执行。

Pi bash.ts

图片：图片内容块，按能力处理尺寸

read 检测图片类型，调用 processImage，使用当前模型的图片输入限制或回退的图片尺寸策略；成功后返回 text + image 内容块。不能把 base64 字符串当普通文字塞给模型并声称它看过图片。

Pi 图片读取实现

工具结果：content 与 details 分开

agent-core 将工具返回形成带 toolCallId、content、details、isError 的 toolResult 消息；模型请求使用内容块，渲染和追溯可使用 details。内核不会替所有自定义工具自动生成摘要，工具或结果转换层需要主动控制输出。

Pi agent-loop.ts

Roami 已有的基础与缺口

file_read：已有分页，字符边界有缺口

读取最多 4 MiB 的工作区文件，每页最多 16,000 字节，返回 SHA-256、offsetBytes、nextOffset。页解码失败便转 base64；中文恰好跨页也会被误判。因此文件读取还不是完整的文本 / 图片 / 二进制分流。

workspace_files.pyfiles.py

Shell 与 MCP：已有附件外置，策略不一致

Shell 的每个输出流超过 16,000 字节或为二进制时存附件，模型只收到最多 4,000 字节的开头预览和引用；进程单流捕获仍有最多 2 MiB 的硬限，超过会中止而非完整流式存档。MCP 小文本可直接返回；大文本、结构化结果和二进制按不同规则外置，文字预览总计 4,000 字节。这些是现有存储 / 截取规则，不是模型 token 容量。

shell.pyprocess.pymcp_results.py

上下文：结果仍整体 JSON 化

Gateway 把返回值 JSON 编码进 tool 消息；投影会完整带到后续请求。没有统一的模型内容投影时，一份不超过工具硬限但很长的结果仍可能挤满当前工具回合。整体压缩又不能切断正在进行的工具配对。

gateway.pyprojection.py

通用超长返回：执行状态有误判风险

注册器在 handler 执行后检查序列化结果，超过 128,000 字节抛 TOOL_OUTPUT_LIMIT；Gateway 当前将它记成 failed。写操作可能已经完成，模型因此误以为没执行。既有 F02 探针已复现合成写效果一次后被记失败，没有观测真实重复写。

registry.py既有 F02 / F04 探针

附件与视觉：有现成基础，但通路不同

artifact_read 支持文本片段续读，非文本只返回元数据；当前按字节切片并用替换字符解码，也需要处理 UTF-8 边界。用户上传文本已有预览提取；Browser / Computer 当前截图通过专门的 image_url 投影送模型，不能据此声称任意 file_read 或 MCP 图片都已接通视觉。

建议的统一处理流程

工具执行 → 保存状态与必要证据 → 按类型形成模型预览 → 记录配对 tool 消息 → 检查完整请求 tokens → 模型按引用继续读取。

原始结果和模型投影分开。预览按剩余上下文 token 预算分配，文件按字符 / 行边界截取；文件大小、进程捕获量和上传大小仍可以有字节级资源限额。75% 自动压缩负责历史，不能代替单条工具结果治理。

统一结果字段

executionState / outcomeKnown 描述执行结果；modelContent 描述本次送模型的必要片段；artifactRefs 指向完整证据；truncated、展示范围和 nextCursor 说明缺失内容及续读方式。toolCallId 始终保留；展示层、持久化和模型适配不能各自改变工具状态。

主页面怎么展示

调用链显示工具名、执行状态、简要结果、截断提示及附件入口。打开附件看完整日志或文件，模型不必因此再次读取全部内容。用户点击查看和模型主动读取都遵守原有的所有者、来源与遗忘控制。

性能与准确性

分页和截取不额外调用模型；仅在任务确实需要归纳大内容时做摘要。摘要保留来源和范围，禁止把截取包装成已经读完整份文件。写成功后结果投影失败要保留成功证据；无法核实则 unknown，不自动重放写操作。

确认后应覆盖的验收

中文恰好跨页、长单行、EOF 续读、文件读取期间变化；超长 Shell 输出、退出码与尾部报错；MCP 大结构和二进制；支持 / 不支持视觉的模型；写已成功但返回过大、附件落盘失败；同一轮多个结果共享剩余 token 预算；持久化重放和遗忘后不得恢复旧内容。
