## 产品设计

### 目标与路径

刚安装的用户不用理解 Roami 的全部导航，就能配置首页主智能体、接入一个专业智能体、创建项目并提交第一个任务。

默认路径：首次首页 → 配置模型 → 配置智能体（Roami 与执行智能体）→ 创建项目 → 首个任务。它是一条贯穿现有页面的引导，不新增一套独立配置系统，不用遮罩逐个介绍按钮。首页给起步清单；进入步骤后，在真实页面顶部保留进度和下一步动作。

第二版增加可选的「认识 Roami」页面：先了解每个模块做什么，再决定从哪里开始。首次首页保留「开始设置」主动作，旁边提供「认识各个模块」；阅读介绍不作为设置步骤、不计入完成进度。顶部的模块介绍入口可随时重看，离开介绍后保留已有配置和草稿。

### 模块介绍

每个模块按「做什么 / 什么时候用 / 从哪里进入 / 可以试什么」介绍，用一句用途说明和具体例子，避免堆功能术语。以下内容已做进可交互原型，而非只留在设计文档中。

| 模块 | 一句话用途 | 进一步解释 |
| --- | --- | --- |
| 首页 | 和主智能体对话，安排工作、跟进结果 | 主智能体、任务、消息、记忆各自的职责 |
| 项目 | 按工作目录组织任务，和智能体一起推进项目 | 项目、任务、会话与 Git 工作区的区别 |
| 能力 | 统一管理模型与智能体，按需增加扩展 | 大模型、智能体、Skills、MCP、CLI、工具、插件、市场八类 |
| 文件 | 查看、编辑工作文件，打开智能体交付的产物 | 节点目录、内容预览和文件交付 |
| 浏览器 | 查看网页，检查页面和操作结果 | 网页标签、浏览现场和页面检查 |
| 手机 | 查看和控制连接到 Roami 电脑的 Android 设备 | 屏幕与触控，连接和调试的前提 |
| 设置 | 调整节点、外观、通知与安全，重看使用引导 | 模型统一位于能力；节点是运行任务的电脑 |

手机的「工具」是文件、浏览器、手机和能力的集合入口，模块介绍明确展示各自的进入路径；不增加第五个底栏入口。概览等非主导航入口随所属模块说明，不把介绍扩成完整功能手册。

桌面采用左侧模块列表、右侧用途说明，共用页面底色，仅一条分隔线。手机先显示平面模块列表，点开后进入完整介绍，只有一层返回栏和一个滚动容器；浏览器返回按 `#tour` / `#tour/<module>` 恢复。模块详情中能配置的内容提供对应动作，例如「配置主智能体」「接入执行智能体」「创建第一个项目」；未制作的工具页面只标真实产品入口，不用无效按钮冒充已接入。

模块用途核对依据：`frontend/src/app/navigation.ts`、`MobileTools.tsx`、`AgentCatalog.tsx`、`CapabilityCatalog.tsx`，以及首页工作台和项目页面现有结构。

| 页面 | 用户要做的决定 | 主动作 | 完成依据 |
| --- | --- | --- | --- |
| 首次首页 | 从哪里开始 | 开始设置 / 继续设置 | 不把看过介绍计作完成 |
| 能力 · 大模型 | 添加哪个连接及其模型 | 保存连接和模型 | 服务端保存了至少一个模型，不代表调用已验证 |
| 能力 · 智能体 | 为 Roami 选模并接入执行智能体 | 应用、验证；安装或登录执行器 | Roami 主 / 后台模型验证通过，至少一个执行器验证通过 |
| 项目 · 新建 | 使用哪个本机目录 | 创建项目 | 服务端成功登记项目，目录存在且可访问 |
| 项目 · 首个任务 | 让哪个智能体做什么 | 开始任务 | 任务创建回执成功；不要求任务执行成功 |
| 首页 · 已起步 | 跟进任务或继续配置 | 查看任务 | 任务状态来自服务端；不虚构执行结果 |

主智能体负责首页对话、理解需求和安排任务；Claude Code / Codex 等专业智能体负责在项目目录工作。两者的登录和模型配置分别管理。模型源统一管理服务地址、协议和凭据，各智能体共用模型目录，协议适配由已有网关负责；专业智能体也可使用原厂模式和自己的账号。

### 入口、退出与继续

- **首次出现**：登录后读取当前节点的模型目录、主智能体配置、专业智能体和项目；全部加载完才判断，不以空数组初始值判断“新用户”。接口失败显示恢复入口，不冒充空安装。
- **全空节点**：首页主内容显示起步清单，第一步突出；不强制跳走，不妨碍访问工具和设置。
- **部分已配置**：按服务端事实勾选已有步骤；保存模型完成第一步，主智能体和执行器验证完成第二步。已有模型无需重复添加，未验证智能体显示“待验证”。
- **老用户升级**：已有配置或项目不自动弹全屏引导；设置里提供“使用引导”。首页已有缺项按正常能力限制提示，不能把老用户重置为新安装。
- **稍后设置**：每步可以返回首页；已保存内容保留，首页显示“继续设置”。配置并验证 Roami 后可以首页聊天；执行器或项目可以稍后接入。第一步保存模型不会自动配置或调用智能体。
- **跳过的代价**：没有已验证执行器时，不能在引导里提交专业任务，但可继续创建项目；没有项目时仍可首页对话。首个任务页给出具体补齐入口。
- **收起清单**：用户可显式收起，设置中随时找回；收起不等于业务完成，不删除配置。任务提交成功后结束本轮起步清单。
- **重入**：以当前节点真实状态重新计算，不重复创建项目、不重复安装、不重复提交任务。首次提交失败保留任务草稿。

### 各页内容

**首次首页**：一句“让 Roami 开始工作”，四项平面清单，各用一句话说明作用；提供「认识各个模块」入口。桌面在中间阅读列；手机保留首页顶栏和首页 / 项目 / 工具 / 设置底栏。

**配置模型**：复用 #564 的「能力 / 大模型」，连接与模型放在同一份表单，填写服务地址、密钥和一个或多个模型 ID，确认后原子保存。第一步只添加模型，不为任何智能体选模，不发起调用。只有服务端返回至少一个已保存模型，才允许进入第二步；只存空连接不算完成。现有用量、限额和定价入口保留。

**配置智能体**：完整复用原有智能体列表，默认展示使用官方 Logo 的 Roami，以及 Claude Code、Codex、OpenCode、Pi。搜索、安装、升级、模型、额度和刷新间隔全部沿用；不按引导场景筛选或折叠执行器。Roami 从第一步的共享目录选择主 / 后台模型，应用后显式验证，高级配置保持可达；执行器可使用原厂账号或自定义模型，安装、登录 / 选模和验证分别进行。不同客户端协议由 #564 的网关适配，不再要求为每个智能体重复添加来源，也不按旧协议规则隐藏模型。

第二步以主 / 后台模型验证成功、至少一个执行器验证成功为完成条件。目录读取和保存都不算调用验证。相关来源或凭据变更使旧验证失效，无关来源新增保留已有验证。没有验证时可以稍后设置，但首个任务仍给出补齐入口。

**创建项目**：复用原有项目表单，保留本地目录和克隆仓库两种来源。路径明确属于当前 Roami 节点，不是正在访问页面的手机。目录选择复用 DirPicker；本地路径不存在时沿用原接口创建目录的行为。Git 是可选项，不要求先建仓库；克隆由用户明确选择，不复制 / 移动既有文件。重复路径打开已有项目；名称、路径和选择保留。

**首个任务**：直接使用现有 TaskComposer；提供一个“只读了解项目”的可编辑示例，默认选已验证执行器，同时保留完整的执行器和终端选项。展示项目、目录、执行智能体，明确会在该目录运行。创建项目不自动发送任务。只有用户点击“开始任务”才提交；成功回执后进入实际任务详情。界面先显示排队 / 执行中，不把“已提交”当“已完成”。无需强制首个任务；用户可返回首页聊天。

### 手机与桌面

桌面沿用导航轨 / 展开导航，步骤进度横排，表单最大宽度遵循 `--content-form`。不打开空终端或空工作区占空间。手机沿用 Material 顶栏和四入口底栏；步骤显示当前序号和短名称，可点已访问步骤；表单是完整页面，不用多层弹窗。一个内容滚动区，底部主动作固定在内容区外；键盘弹出时底栏隐藏，动作避让键盘，输入自动滚入可视区域。

深浅主题、四档布局复用现有令牌和 `useLayout()`。图标直接导入 `frontend/src/icons.tsx`；文档原型的中文是设计稿内容，正式实现的全部文字和 aria-label 必须加入全局 `zh-CN` / `en-US`，不保留原型私有文案。

## 用户故事与验收标准

| 场景 | 应看到的结果 |
| --- | --- |
| 全新安装，无配置、执行器和项目 | 首页明确展示第一步，所有字段初始为空；没有伪造的成功状态 |
| 不知道主智能体与 Codex 的区别 | 在各自步骤用一句话解释作用；不把它们作为互斥选项 |
| 不知道每个模块能做什么 | 从首页打开模块介绍，查看用途、入口和例子；读完继续原有设置 |
| 不理解 Skills、MCP、CLI 等分类 | 能力介绍逐项解释；仍只要求接入一个执行智能体即可起步 |
| 手机浏览模块介绍 | 工具归属清楚，模块详情不重复顶栏标题，返回列表不重置已填配置 |
| 提供的服务不支持模型列表 | 可手填模型并验证；列表失败不清空地址和密钥 |
| 能获取模型列表，但模型无法调用 | 不显示“已可用”，允许修改和重试 |
| 已经有 Claude Code | 不要求重复安装；检测授权，未知状态保持待验证 |
| 一项安装失败，另一项可用 | 可继续，不被全部成功条件卡住 |
| 尚未登录也不想立即安装 | 可以稍后接入，返回首页聊天或继续建项目 |
| 只用手机访问服务器 | 目录归属清楚，安装和授权入口可达，真触控可完成流程 |
| 刷新、后退或换设备继续 | 已保存配置依据服务端恢复；未提交任务不自动执行 |
| 重复点击创建 / 提交 | 共享进行中状态；服务端幂等或唯一约束，不产生重复记录 |
| 配置接口暂时不可用 | 显示加载失败和重试，不展示“全空新安装” |
| 已提交任务但执行失败 | 引导提交步骤已完成，任务仍显示失败并给恢复动作 |

### 数据、验证与持久化

复用 `GET /agent/model-settings`、`POST /agent/models`、`PUT /agent/model-settings`，以及 `discoverAgents` / `installAgent` / `checkAgent` 与现有项目目录订阅。

注意：现有 `POST /agent/models` 只获取模型目录，不足以证明推理可用；专业智能体注册表的 `authentication: unknown` 和 `modelPreset` 也不能证明可执行。

实现时需补两项服务端能力（下列是设计约定，不声称已存在）：

1. 主模型验证：使用当前草稿连接与选择的模型进行最小调用；复用 Go 网关准入、参数能力和错误码，不绕过额度。返回绑定连接 / 模型指纹及有效时间的验证记录。保存成功才将记录关联到已保存版本，失败或草稿改变则保持未完成。后台模型相同可复用结果；不同则分别验证。
2. 专业智能体验证：非破坏的最小运行检测，分别返回安装、授权和运行结果；验证失败不把主机 / 用户环境的未知状态画成成功。不把获取额度、发现二进制或打开终端当验证通过。必要执行进程必须是明确的测试资源，关闭仅限该资源。

完成状态从服务端事实派生；用户偏好只存引导版本、是否收起、跳过哪些可选项。按用户及节点隔离，不给所有节点共用一个 `onboarded=true`。配置修订变化使旧验证失效；请求失败保留已知状态并标记待确认。不会因为老用户缺少新验证记录而自动打断其正常使用。

本地仅镜像非敏感显示偏好和允许保存的草稿，首帧可恢复；服务端偏好加载后再同步，遵守 `preferencesLoaded()`。API Key 不写 localStorage / sessionStorage / URL / 日志。共享已有 overview、注册表请求和可见性轮询；事件触发重算，不新增逐执行器轮询。引导完成不增加任务轮询，任务视图沿用现有更新。

任务创建复用现有执行链路；新增幂等键仅在既有接口缺少保证时补充。项目创建按规范化路径去重，重复请求返回已有项目。用户离开不回滚已安装执行器、不删已创建项目。

### 原型范围与运行

独立 HTML 保留为第二版设计快照；PR #564 后的模型优先流程以实际产品截图和最新验收为准。

原型位于本目录：`prototype.tsx`、`module-guide.tsx`、`prototype.css`、`build.mjs`，构建产物是可独立打开的 `index.html`（无需 CDN）。它导入项目的 Ant Design、图标、布局入口和主题令牌；没有任何业务 API 调用。演示数据只保存在此标签的 sessionStorage 中，密钥仅留内存。顶端的“页面 / 场景 / 填入示例 / 从头体验”是 review 控件，不进入产品。

```bash
cd frontend
npm ci
node ../docs/design/20261030-new-user-onboarding/build.mjs
```

Review 顺序：从全新安装首页开始，点击“开始设置”；配置页可点顶端“填入示例”，依次验证主模型、接入一个智能体、创建项目、提交首个任务。顶端页面选择器可以直达各页（手机先展开“预览选项”）；场景选择器覆盖失败和已有配置。可切深浅主题，手机直接打开同一 HTML。

第二版先 review 首页「认识各个模块」，或直接打开 `index.html#tour`；选择模块看介绍，点击底部「开始设置」进入原来的四步流程。

原型 review 关注四步先后、可跳过步骤、默认配置字段、账号接入和首个任务。现已根据用户批准进入实现，原型仍保留用于对照；产品代码不使用原型演示数据。
