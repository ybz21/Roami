产品设计

「能力 / 大模型」的用量部分分为两个同级 Tab：

  • 概况：用量、限额、汇总、趋势，以及按模型源 / 智能体 / 模型的分组统计。
  • 审计：逐条调用记录、条件筛选、搜索、分页和单次调用详情。

默认进入概况。概况内可以调整示例每日限额；今日额度覆盖全部调用，不随统计条件变化。未知费用存在时，剩余额度显示待核对。审计直接进入请求列表，不再套一层「概览 / 请求」导航，也不重复概况的限额与汇总模块。点击概况中的分组或趋势进入审计并携带筛选条件；两个 Tab 切换保留已有选择。

本版按用户对信息结构的纠正修订：第一版结构记录。

区域 内容与行为
统计周期 今天、近 7 天、近 30 天、自定义起止日期；示例时钟固定为 2026-11-12 18:08（Asia/Shanghai）
全局筛选 模型源、智能体、模型、调用来源；筛选同时作用于总览、分组、趋势和请求
概况：今日额度 网关状态、今日已记账费用、每日费用上限和剩余额度；限额可在原型内调整，状态只保留在当前页面
概况：摘要 已知总 Token、请求数、已知记账费用、缓存读取占已知输入的比例
用量趋势 按天查看总 Token、输入、输出、缓存读取、请求数或记账费用；点击柱形进入当天请求
用量分布 按模型源、智能体或模型分组；可按 Token、请求数和费用等列排序；占比跟随展示指标
审计 继承全局筛选，可按状态或模型 / 请求 ID 查找；多页才显示分页
单次请求 桌面右侧面板，手机全屏二级页；呈现身份、状态、回执和价格快照；返回保留列表位置
历史归档 依照现有 48 小时保留规则，较早请求只显示聚合；选择已归档日期时说明原因

「模型源」指实际处理调用的连接，如 WorkBuddy、OpenAI；「调用来源」指对话、任务、RSI 等业务入口。两个维度单独命名，避免把原接口的 source=rsi 当成供应商源。智能体先按现有类型 Roami、Codex、Claude Code、OpenCode、Pi 展示；未知归属单列，不凭模型名推测。

总 Token = 输入 + 输出；缓存读取是输入的子集，不能再相加。未知用量 / 费用单独标记，汇总标示「已知」，不把未知记成 0。费用按本地价格快照记账，不能叠加云端账单或供应商积分；原型仅展示 USD 示例。正式版多币种须分币种展示，不直接相加。

桌面沿用能力中心的主分类与左侧模型 Tab。内容铺满剩余空间，只有可选详情面板开启时占用宽度；主内容独立滚动。手机使用顶部栏、同级 Tab 与四入口底栏，筛选按需展开，汇总表改为列表。上下文中的其他能力分类和底部目的地仅用于展示壳层，不模拟完整产品导航。

用户故事

  1. 我想同时掌握用量和限额：进入「概况」，先查看今日额度，再按周期浏览汇总；在原型内调整限额后切换 Tab，选择仍保留。
  2. 我想知道最近一周哪个模型源消耗最多：选择「近 7 天 / 按模型源 / 总 Token」，按降序看占比，进入「审计」查看该源请求。
  3. 我想比较智能体的消耗：切到「按智能体」，在总 Token、输入 / 输出、请求数和费用之间切换，筛选某一模型进一步查看。
  4. 我想解释某笔请求为什么贵：打开请求详情，核对输入、输出、缓存读取及请求时单价；缓存只按缓存价计费。
  5. 我想排查未确认费用：进入「审计」，筛选「待核对」；缺失字段显示未知，不把请求当成免费。
  6. 我在手机上查看：展开筛选、触摸打开请求详情，再返回时保留筛选与滚动位置；只保留一个可见返回栏。
  7. 我想查旧记录：30 天统计继续显示累计用量，早于保留期的请求显示归档提示，不伪造逐条回执。

成员排序交互

Product Design

路由策略决定实际优先级；配置顺序决定固定顺序策略的先后、轮流的轮转顺序，以及自动策略条件相同时的顺序。预览列表展示当前策略与对应的顺序说明。编辑状态直接在预览成员行里提供拖动手柄、上下移和权重；不再在两处重复列出编辑器。

“整理顺序”支持按模型源分组（源内相对顺序不变）、按模型名称排序，操作直接调整待保存的候选顺序；它们是一次整理动作，不是持续覆盖手动顺序的路由策略。手动拖动后保留该顺序，点击保存后提交。

  • 我可以直接拖动预览中的模型，把希望优先调用的放前面，马上看到前 12 轮分配更新。
  • 我可以先按模型源分组，再手动调整同源成员；权重始终跟着原来的成员。

  • 智能、速度、价格等自动策略解释手动顺序只在条件相同或相近时生效，不把手动顺序误当作实时排名。

Technical Design

卡片内容归属修正

Product Design

聚合卡片是其运行状态、策略预览和成员的共同容器，不在卡片列表下方展示公共详情。列表初始仅显示身份、状态、策略和成员数；点击卡片中的“查看调度”展开该卡片，内部用“运行状态 / 调度预览”切换，默认显示真实渠道。切换聚合时收起原卡片，不重复聚合名称，也不同时堆叠示意成员与真实渠道。

聚合策略与运行效果原型

产品设计

聚合列表使用可选卡片，显示名称、调用 ID、启停状态、策略、成员数与核心效果。选中聚合后使用完整工作区，保留同级导航。默认标签为“运行效果”，另有“调度策略”和“成员”。

  • 运行效果：近 1 小时、6 小时、24 小时的请求数、成功率、首字耗时、输出速度、费用和质量通过率。趋势可按源、模型分组，切换请求、输出 Token、首字耗时或成功率。次数 / Token 为堆叠量，耗时 / 成功率为各成员独立指标，不能相加。
  • 调用分布：来源的占比与实际调用数量，提示失败接管会使实际分布偏离配置权重。
  • 最近调度：实际渠道、选择原因和备用接管；打开详情查看条件过滤、候选排序、限流休息与回答成功的路径。请求详情保持源、模型、时间、用量与费用一致。
  • 调度策略：保留 smart、order、drain、rotate、usage、pace、weight、fast、cheap 九种已确认策略。卡片说明目标，选中后展示详细规则。先选源再选模型；只有权重策略突出权重，顺序相关策略提供排序操作。
  • 调度试算：独立于运行效果，展示当前示例状态下的预计选择、原因和接下来 10 轮的成员分配；可模拟首选限流与恢复。不会发起模型调用，未保存的策略不能被当成线上生效策略。
  • 成员：分开显示可用、休息、额度耗尽和价格未确认。WorkBuddy 示例保留 10 个独立账号，可打开账号列表比较额度及重置 / 到期时间。嵌套聚合按一个组成员展示，组内使用自己的账号策略。

免费聚合只允许已确认的免费模型，订阅额度需明确勾选；未知价格不当作免费，未知余额不当作无限额度。少量或无质量样本显示未知。所有页面和试算时间由浏览器自动获取本地时区，不写死北京时间。

用户故事

  1. 看这个聚合是否有效：多少请求、是否更稳定、哪个源承担了流量，是否全部免费。
  2. 知道一次调用为什么去了这个源：查看真实选择理由与失败后的备用接管。
  3. 修改策略前能比较：切换九种策略、编辑权重或顺序、模拟限流，看到选择变化再保存。
  4. 多账号可以解释：查看同一 WorkBuddy 源的 10 个独立账号，而非把一个源误认为一个账号。
  5. 手机上完成同样的动作：切换标签、选择策略、试算、打开全屏账号 / 请求详情，使用一层返回栏。

添加候选先选模型源，再从该源下选择模型，点击「添加候选」。未选源时模型选择不可用；切换源会清空待添加的模型，已经添加的候选保留，可跨源排序和移除。已添加及不符合免费条件的模型不能重复加入，选项直接标明原因。

定价放入模型源编辑器：源默认策略支持继承全局、按 Token、明确免费、套餐额度和未知；源内模型可覆盖默认策略。全局定价页保留兜底策略、币种与各源策略概览，并可直接进入对应源配置。普通输入、缓存读取、输出分别定价；额度与货币不是同一单位。源定价的单位跟随已保存的记账币种，未保存的全局编辑不覆盖源草稿。

免费 API 是默认候选范围；套餐额度通过每个聚合里的开关单独纳入，不与无限免费混为一类。原型中的 Free API A / B 和 demo-free-* 是显式示例，不表示任何真实供应商当前免费。

填写三项 0 元不会自动成为免费候选。源必须有明确的免费策略和条件确认；模型覆盖为付费或未知时，覆盖结果优先。套餐额度只有已知且足够时可用，未知不计为 0，不切换到付费扣费模式。

用量本地时间修正

产品设计

概况和审计使用设备 IANA 时区。日期范围、今天、按小时曲线、时间段跳转及请求详情保持同一时区，跨午夜时也一致。监控现有的设备本地时间格式保持一致。

只保留一天，且容量有上限

监控数据最多滚动保留 24 小时，不是按自然日累计。每次写入先清过期记录；达到 10,000 条或 64 MiB 指标数据中的任一上限，就从最旧记录开始提前淘汰。不承诺容量受限时仍保留完整 24 小时。

原型使用 MonitorRing 有序内存队列，不写 localStorage、IndexedDB 或真实数据库。插入过程中持续限制条数和字节数，允许乱序到达；单条记录超过预算直接丢弃。展示现有条数、序列化指标字节数、过期数量和容量淘汰数量，并可演示推进 24 小时和达到条数上限。抽检未检测、指标未知和空数据保留明确状态。

后端存储设计，待确认后实施

保留策略归监控存储本身管理，不依赖浏览器在线。读取时严格过滤 24 小时边界；写入前清理，独立维护任务每分钟回收过期数据。时间跳变也不能使旧数据变成永久保留。

使用独立监控存储和一分钟聚合桶；仅存指标、错误分类、规则 ID / 版本及通过 / 失败结果，不存完整提示词、模型响应或凭证。限制源 / 模型序列数，防止无限标签基数。生产容量预算应包含索引、数据库空页、WAL、SHM 和临时文件，不能只限制 JSON 内容大小。

可采用独立 SQLite 文件，启用可增量回收的空间策略，设置最大页数，并对 WAL 在写入准入处实行阈值检查与 checkpoint / truncate。建议将 64 MiB 的磁盘预算划分为主文件不超过 48 MiB、WAL 不超过 8 MiB，其余预留 sidecar / 临时空间；到达预算且无法回收时跳过新监控样本，保留丢弃计数，不能继续增长。删除行不等于文件缩小，回收和异常重启均须实测。

此规则只作用于新增监控数据；现有用量汇总、审计回执与记账证据沿用各自保留规则，不能为了监控清理误删账本。
