产品与用户故事

完成任务后，发布应在宿主确认没有进行中的输入和工具时继续。执行器的完成回复不代替宿主状态；不取消任务、不替用户验收、不重复执行结果不确定的外部操作。

技术设计

本机升级停在 AGENT_UPGRADE_BUSY。绑定的 Codex 原生记录已包含根轮次 task_complete，但两个失败的 McpToolCall 结束记录未被完成证据解析器识别，工具仍被算作进行中。

只扩展 internal/agentexecution/session-codex-completion.go 的既有 item_completed 解析：MCP 项要求有效调用 ID、非空服务/工具、终态、匹配的线程与轮次、有效开始/完成时间。沿用完整记录摘要、最终回复、未结束调用、子智能体、进程身份、重复证据等检查，再由既有 execution status 核对并保存停止证据。命令执行仍要求进程和退出码。没有新增路由、任务状态接口或 Python 逻辑。

验证

扩展既有状态核对回归，覆盖 MCP 成功/失败结束、仍在执行、缺失服务/工具、错误线程/轮次、结束时间晚于最终回复、重复结束、存活进程和未结束子智能体；确认核对幂等且不再次提交输入。定向回归已通过。
