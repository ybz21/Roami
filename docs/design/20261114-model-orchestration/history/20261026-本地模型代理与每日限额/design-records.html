本地模型代理与每日限额

Product Design

2026-10-29 修订：在 Roami 进程内运行 Go 模型网关，Agent 的模型 HTTP 请求先经过本地记账和准入，再转发到原配置的云网关或模型服务。模型连接地址和密钥继续由既有模型设置管理。模型与连接页恢复「模型连接 / 代理与计费 / 模型单价」三个标签，使用本地 Go 账本；同时提供 CLI 和受现有登录保护的管理 API。本地统计与价格不依赖云端账单接口。

本地金额是按本机配置单价计算的消费账本，不发起云端余额扣款，不把上游已有账单再相加。未配置单价时使用默认价；默认价为零。初始币种 CNY、时区 UTC、无限额，设置价格和限额后对新请求生效。外部专业 CLI 继续使用它们各自的模型连接。

User Stories

  • 作为使用者，我能在本机配置每百万输入、输出、缓存读取 token 的价格，以及按指定时区重置的每日金额限额。
  • 主对话、后台任务、记忆和宿主机评测使用同一个本地入口，共享每日账本；容器评测沿用宿主机桥接，由宿主机请求同一本地 Go 网关。
  • 我能查看最近 1–90 天按日期、连接角色、模型和币种分组的请求数、token 和金额，以及最近 20 笔请求的状态。usageUnknown 单独标明缺失 token 的请求，人工核账后仍不伪造 token 数。评测请求保留已有评测角色、会话和请求标识。
  • 上游缺失用量、断流或进程崩溃时，非零单价请求保留费用未知状态并提示核账，不阻断后续调用；核对真实金额并填写理由后计入每日消费。

Technical Design

configured_provider / 宿主机评测模型
  -> LocalGatewayTransport (httpx，私有 Unix socket)
  -> internal/modelgateway.Handler
     -> Ledger.Admit：事务检查每日消费并持久化 pending
     -> 原模型地址：转发请求及流式响应
     -> Ledger.Settle：解析最终 usage，按请求接纳时的单价结算

roami agent gateway / 已认证 Web API
  -> 同一个 Go 网关 socket
  -> 价格、限额、统计、未知费用核账

模块划分：configuration.go 校验设置并做整数金额换算；pricing.go 复用云网关的价格选择规则；ledger.go 负责迁移、配置、准入和幂等结算；usage.go 增量解析 OpenAI chat-completions 的 JSON/SSE usage；statistics.go 提供一致快照；handler.go 管理 HTTP 边界和转发；service.go 管理私有 socket、进程锁和关停。

定价核心源自 ~/codes/llm-gateway/internal/observe/pricing.go，版本 1f1ffc1ab080c0da935d063ac79380d2f2a4a079。保留精确模型、前缀、默认单价的优先级，并将重叠前缀改成确定性的最长前缀匹配。本地累计金额使用十亿分之一币种单位的整数；单笔采用有理数计算并四舍五入。OpenAI 的输入 token 含缓存部分，计算普通输入费时先减去缓存，再单独计算缓存价。

本地账本注册到统一存储目录：<DatabaseRoot>/models/gateway.db，catalog ID 为 model-gateway，owner 为 go-model-gateway，随统一数据库备份和迁移处理。旧 Python model_proxy_calls 继续仅作历史账本，不参与新额度计算。

Go launcher 在启动 Python 前开启网关，注入 ROAMI_MODEL_GATEWAY_SOCKET；Web supervisor 和 roami agent serve 共用相同生命周期。socket 权限 0600，路径与 Agent socket 等长，保留长路径回退能力。持久文件锁防止两个网关互相恢复在途记录；重启将非零价格的 pending 请求标记 unknown。关停先取消网络请求、等待结算，再释放进程锁。网关不可用时，已配置本地 transport 的客户端不回退直连。直接运行开发用 Python、没有 launcher 环境时保留原直连能力。

价格在准入时快照保存；更新价格不重算历史金额。启用每日限额后，在途请求先结算再判断下一笔准入；已确认消费达到限额返回 402。2026-11-03 经用户明确确认，未知费用仅提示核账，不再返回 409 阻断后续调用，也不按零费用核销；未核清金额不计入限额，核账后立即计入。检查和 pending 插入处于同一 SQLite immediate 事务，防止并发同时放行。限额是请求前准入线，最后一笔调用仍可能超额；不是按 token 中途截流。未配置限额时不限制并发。币种或时区不能在仍有未决账目或最近账期已有调用时更换，避免重新解释账期绕过限额。

仅持久化模型、角色、token、单价快照、金额、状态和已有不透明评测标识；不落请求正文、响应正文或密钥。SSE 逐块转发，解析缓冲有上限；收到合法终结 usage 和 DONE 后即保留已知费用，不因客户端先于 HTTP EOF 关闭而丢弃回执；模型等待期限沿用调用方配置，不叠加网关固定超时；缺失或非法 usage、未正常结束和服务端错误不记成免费。明确未连接成功、上游拒绝以及零单价调用可记零；HTTP 失败与费用未知分别保留。

使用

Web 入口为「设置 → 模型与连接 → 代理与计费 / 模型单价」，保留原统计图、日期选择、单价编辑和草稿恢复；最近请求可核对未知费用。正常启动新版本 roami server 或 roami agent serve 后，也可使用 CLI：

roami agent gateway settings
roami agent gateway configure --file /path/to/gateway.json
roami agent gateway usage --days 30
roami agent gateway reconcile --call <调用ID> --file /path/to/receipt.json

配置为完整替换，价格单位是所选币种 / 百万 token：

{
  "currency": "CNY",
  "timezone": "Asia/Shanghai",
  "dailyLimit": 20,
  "pricing": {
    "default": {
      "input_per_million": 0,
      "output_per_million": 0,
      "cache_read_per_million": 0
    },
    "models": {
      "your-model": {
        "input_per_million": 2,
        "output_per_million": 8,
        "cache_read_per_million": 0.5
      }
    }
  }
}

dailyLimit: null 表示无限额；0 暂停新请求。示例单价仅展示结构，使用时填入实际价格。核账文件示例：{"amount": 0.75, "reason": "已核对上游用量回执"}；只允许核对 unknown 记录，保留原始错误与核账理由，不能覆盖已知消费。

方法 已认证 API 内容
GET / PUT /api/agent/model-gateway/settings 读取 / 替换本地价格与限额
GET /api/agent/model-gateway/usage?days=7 1–90 天分组及最近调用，0 为累计；day=YYYY-MM-DD 查询指定日及分时
PUT /api/agent/model-gateway/calls/:id 核账未知费用

新增英文帮助仅出现在用户 shell，属于 i18n 规范的终端输出例外。Web 新文案提供中英文。原 /agent/model-usage 仍读取已归档的 Python 历史账，恢复的页面读取 /agent/model-gateway/*。

隔离实例实测

使用 scripts/dev/isolated-roami.sh /tmp/roami-local-gateway-20261029/instance6 ... 启动开发实例，私有 tmux server 与用户会话分离。Go 二进制由当前工作区构建，通过实际 roami agent serve 启动 Python；上游为本地 HTTP/SSE 夹具，没有付费模型调用。

  1. 通过 roami agent gateway configure 配置每日 2 CNY，主对话生成真实流式回复，账本结算 2.000000000 CNY。
  2. 再次发送被本地 MODEL_PROXY_DAILY_LIMIT 拒绝，上游请求数仍为 1。
  3. 重启 Go / Python，价格、限额和已知消费保留。
  4. 将限额改为 5 CNY，上游故意省略 usage，账目保留 unknown；下一次发送以 MODEL_PROXY_USAGE_UNKNOWN 拒绝，上游仍只有 2 次请求。
  5. 通过 CLI 将未知费用核对为 0.75 CNY，已结算总额为 2.75 CNY。
  6. 再发送成功；该轮触发的 Worker 调用也进入同一账本。最终上游 4 次请求，主连接 4.75 CNY、Worker 2 CNY，总计 6.750000000 CNY。最后一笔开始前低于 5 CNY，因此允许完成并超额，符合请求前准入语义。

停止 Agent 后执行统一 roami db backup，再恢复到另一个隔离目录：catalog 保留 model-gateway，账目总额仍为 6.750000000 CNY，价格与每日限额 5 CNY 均保留。

实测日志：/tmp/roami-local-gateway-20261029/smoke.log；完整分组与最近调用：/tmp/roami-local-gateway-20261029/usage.json。实例已停止，统一隔离入口负责关闭其专用 tmux server。

恢复本地计费页面 · 2026-10-29

主题设计

Product Design

在「设置 → 模型与连接」恢复「模型连接 / 代理与计费 / 模型单价」三个标签。沿用原统计、图表和价格编辑组件，数据和保存操作接入本地 Go 网关。移除原先跳转云端管理页的主流程，保留模型服务地址与密钥设置。

计费页显示今日费用、用量、统计周期和最近请求，并可调整每日限额、币种和账期时区。单价页提供默认单价与按模型的输入、输出、缓存价。全部价格使用同一账本币种。最近请求中的未知费用提供短核账对话框，输入已核对金额和依据后才提交。

User Stories

  • 切换连接、计费和单价标签，不丢未保存输入；离开再回来，复用既有设置草稿恢复。
  • 在计费页查看近 7/30/90 天、累计，或选择日期查看分时与模型明细。
  • 保存失败时保留全部草稿，显示恢复方向；核账刷新统计时也不覆盖配置草稿。
  • 手机上通过一个返回栏进入设置子页，保留主导航，触摸操作不依赖悬停；键盘弹出时聚焦字段避开固定保存条。

Technical Design

AgentSettingsWorkspace 管理 URL 标签、模型配置表单及共享的网关设置状态。useGatewaySettings 拥有配置快照、草稿、保存、目录和核账；两个计费标签共享该状态。旧模型连接写入 /agent/model-settings；本地价格、限额、核账和统计只访问 /agent/model-gateway/*。不读取归档的 /agent/model-usage。

local-model-gateway.ts 将 Go 分组账本适配到原统计组件，金额合并采用 BigInt 纳单位；图表只将数值用于绘图，不用浮点数拼合显示金额。按模型、日期和时段汇总保留不同币种与未知费用，人工核账不补造缺失 token。累计趋势最多展示最近 90 天，周期总额保留完整累计数据。

Go StatisticsFor 增加指定日期、时区分时和累计统计；今日摘要独立于所选日期。页面无新增轮询，按标签激活、日期范围、保存和核账更新请求，取消过期读取。

独立记录 daily-retention.html

计费明细保留与日账归并

Product Design

逐笔明细保留结算完成后的 48 小时，超期后按原账期日期、时区、模型、角色、智能体和 RSI/其他来源合并。费用、输入/输出/缓存 Token、请求数、失败数、费用未知数与用量未知数保留，逐笔请求 ID、响应元数据与核账理由到期清理。处理中请求不清理；延迟结算从结算时重新计时。未知费用不补零，仍只提示而不阻断调用。

历史日期已有归并数据时显示日汇总，明确不再提供完整的逐笔/小时明细；不会把缺失小时数据显示成零。来源、智能体、模型及多币种统计保持一致。超过保留期的未知费用只保留日汇总异常数，不再支持逐笔核账。

User Stories

  1. 我能查近两天的 Token、请求 ID 和错误详情。
  2. 我能长期按天查看费用和 Token，不因清理而少账或重复计费。
  3. 旧记录不会按每次模型请求持续累积，且异常或晚到回执不会被误删。

Technical Design

Go 网关 schema v5 增加 gateway_daily_usage。归并每批最多 1000 笔，在同一 SQLite 事务内累加日账并删除对应明细；失败整批回滚，并发归并与重复执行保持幂等。费用保持整数纳单位，溢出拒绝写入，不转浮点数。索引覆盖已结束记录的保留期扫描。

网关持有服务 socket 锁后，恢复中断请求，再执行一次归并；常驻服务每小时继续归并，停服时停止定时器。维护错误记录日志并等待重试，不额外阻断模型服务。没有在 Python 中加入限额或清理逻辑。

统计联合读取未过期明细与日账，所有可加指标再次按既有维度分组；全部历史的起始日同时查两张表。历史单日已有归并数据时返回 dailyAggregated，前端以日数据呈现。配置保护仍计入日账中的未核清费用，归并不绕过既有币种/时区约束。每日额度仍按当天逐笔已知费用执行，当天记录不进入 48 小时清理窗口。

删除后的 SQLite 空闲页由后续请求复用，不做每小时全库 VACUUM；磁盘不再随每笔历史请求线性增长，日账随日期和统计维度缓慢增加。已有备份仍按存储备份策略保留。

Acceptance

  • 回归：48 小时边界、时区日期、未知费用和未知 Token、真实零、来源/Agent 筛选、全历史起始日、重复与并发归并、2505 笔跨批归并、删除失败回滚、货币溢出回滚、延迟结算和处理中保留。

按用户要求将保留期从 72 小时缩短为 48 小时。每小时归并、原账期日汇总、处理中保护、迟到回执重新计时、费用与 Token 计数均沿用已有规则。界面通过 API 的 detailRetentionHours 自动显示“两天”，无需改前端代码。48 小时边界与迟到回执回归同步调整。

独立记录 nonblocking-unknown-charges.html

未知费用仅提示、不阻断调用

Product Design

用户明确允许未知费用只提示、不阻断调用。每日限额只对已确认消费生效；未知金额不计入限额，不能据此判断实际消费没有超额。已有未知费用、错误码、回执和核账入口保留，不补造 token、不归零、不改日限额数值。核账后的金额继续参与准入判断。

User Stories

某次网络中断缺失用量时，我仍能继续使用 Claude、Codex、OpenCode 和 Roami，在计费页看到待核账提示，并在取得账单后补录真实费用。

Technical Design

Ledger.Admit 不再依据 state=unknown 拒绝准入，仍在同一事务内检查已确认消费与 pending 请求。账目结算、崩溃恢复、原始请求失败和协议错误处理保持现有语义。计费页使用普通提示展示未知费用，并明确说明不会阻断调用、未计入限额；每日限额提示同步说明只计算已确认费用。

部署以当前已上线的 OKR 源码树 2f34604fc2df1ee45834beaf7e23345bd3a786cc 叠加本补丁，保留完整 OKR 功能、现有 Python runtime 路径、模型路由、单价、100 CNY 日限额和所有历史账目。已与 OKR 会话确认无更新的上线树。

Acceptance

独立记录 rejected-request-accounting.html

上游拒绝误记未知费用

Product Design

完整收到上游 3xx / 4xx 拒绝时，目录代理与协议转换路径按现有直连路径的规则记零费用，保留失败状态、HTTP 状态、错误码和上游回执，不补造 token。断流、5xx 和成功响应缺失用量仍记未知，启用日限额时继续阻止后续调用。

User Stories

某个 Agent 遇到鉴权或限流拒绝后，其他 Agent 不应因这笔请求被误记未知费用而全部收到 409；真实未知费用仍需要核账。

Technical Design

internal/modelgateway/catalog_http.go 原本两条错误返回分支均未设置零费用结算标记。原协议透传路径现依据 HTTP EOF 标记完整拒绝；转换路径在返回协议错误前丢弃并确认错误正文完整结束，最多读取 4 MiB 加一字节，超限或读取失败保留未知状态。复用 Ledger.Settle，不修改历史账目的状态或迁移规则。

Acceptance

  • 修复前新增回执断言在目录透传、协议转换的 400 / 401 / 403 / 429 共 8 个子用例失败，直连用例通过。
  • 修复后回执回归通过；新增跨 Agent 日限额回归覆盖 OpenCode 原协议、Codex 原协议、Claude 转换及 Codex 转换。每种路径均验证 401 / 403 / 429 后 OpenCode 与 Codex 连续请求可用，并验证 5xx、错误正文截断及缺失 usage 保留未知且不再请求上游。
  • scripts/dev/quality/check.sh quick 通过，包括 Go 全量测试。完整检查结果与界面验收补充见模型编辑验收。未修改 Python，不运行 Python 依赖同步或测试。
  • 本机故障账本中唯一的未知费用来自上游 401。使用现有 roami agent gateway reconcile 接口核账为零，保留原始 401、错误码和核账理由。核账后未知与在途均为 0，已知费用 9.349113600 CNY，日限额保持 100 CNY；随后已观察到真实请求恢复 200 并正常结算。
  • 未重启或替换现用服务。防复发代码需要随新版服务上线；本机账目修复已生效。隔离验收不请求付费模型。

独立记录 request-token-records.html

逐笔 Token 与未知费用请求记录

Product Design

费用未知与 Token 未知分开呈现。请求记录显示输入、输出、缓存 Token 及完整到秒的日期时间；有回执的数字照实显示，缺失字段显示“未知”，真实零保留为零。汇总用量缺失时显示“已知”数量或“未知”，不把缺失回执当作零用量。

记录详情提供账目 ID、HTTP 状态以及已记录的客户端请求、上游请求、会话、本地模型和模型源 ID。错误与核账理由仍放详情，不保存请求或响应正文，也不估造缺失 Token。

未知费用提示提供“查看请求”；记录列表可切换“仅看费用未知”。先按费用状态筛选再取最近 20 笔，旧未知费用不会被后续正常请求挤出窗口。该筛选只影响请求记录，日期、来源和 Agent 筛选继续有效，汇总和每日限额不变。

User Stories

  1. 我能看到费用未知但 Token 已知的请求用量。
  2. 我能区分未收到回执与实际消耗零 Token，并复制记录 ID 反馈问题。
  3. 产生更多正常请求后，我仍能查找旧的未知费用请求并核账。

Technical Design

local-model-gateway.ts 保留 API 已有的逐笔 Token 和关联 ID，不再在适配时丢弃。ModelProxySettings 展示逐笔用量和详情，使用 recentState=unknown 请求过滤记录。ModelUsageStatistics 对缺失回执标记已知部分，图表数字仍是实际已返回用量，不补造缺失值。

Ledger.StatisticsForCalls 仅在近期记录查询中应用费用状态过滤；原统计入口保留兼容包装。API 校验并回显状态，前端检查回显和请求上下文，拒绝将旧节点未过滤的数据显示成未知费用记录。没有新增轮询、账本迁移或准入变更。

Acceptance

  • Go 回归覆盖两笔未知费用（一笔 Token 未知、一笔未定价但 Token 已知）后追加 25 笔正常请求，仍可筛选找回旧记录；验证真实零、缺失用量、关联 ID、汇总不受影响，以及非法状态返回 400。

  • 主分支前端 167 文件、1224 项测试通过；保留完整 OKR 的整合源 173 文件、1252 项测试通过。两者均通过 typecheck、i18n、hover 与生产构建；Go 网关回归及整合 Go 全量通过，仓库 full 门禁复跑通过（首次会话续接测试出现时序失败）。
