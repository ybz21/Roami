Product Design

能力并列“大模型”和“智能体”。大模型保留三个页签：

页签 用途
模型 按连接分组，在同一表单配置地址、密钥及多个模型
用量与限额 原有用量账本、币种、每日金额限额、时区与费用核对
模型定价 原有默认、逐模型及前缀价格，输入、输出及缓存价格

添加连接时填写名称、地址、密钥和模型 ID；显示名称选填，可以继续增加多个模型，一次确认保存。上游的协议和认证方式放在“连接选项”中，普通 OpenAI 兼容服务默认使用 Chat Completions。协议属于连接参数，不再划分可使用它的智能体。列表不展示协议类别或内部路由 ID，名称与地址相同时不重复显示。

连接下面直接展示它的模型。连接编辑表单同时管理所属模型；模型的聚合策略作为单独的高级入口保留。主备候选可以使用不同上游协议，由网关逐个适配。正在使用列表为空时不展示空标题。

智能体页统一安装、升级、启动、登录和模型配置。自动识别本机已有 CC；未安装的 OpenCode 等工具可以安装，已安装则显示版本与升级。模型配置提供：

模式 操作与结果
原厂模式（Default） 确认后交回工具自己的登录和默认模型，移除接管的自定义连接
自定义模式 选已保存的来源，再选模型；确认后连接 Roami 网关，凭据与协议由网关处理

选择选项只编辑草案，“当前使用”始终显示实际配置；确认应用后才写入真实文件，新会话生效。来源目录只读，未登记的模型也能选；目录不可用时可输入已知模型 ID，确认应用才加入共享列表。旧连接预设与“恢复以前配置”放在高级区域，恢复可以回到以前的第三方设置，原厂模式则使用工具默认行为。

User Stories

  1. 配置一次 OpenAI 兼容来源及多个模型后，CC 和 Codex 都能选择同一个模型，无需另建 Claude 来源。
  2. CC 发送 Messages，Codex 发送 Responses，Roami 使用 Chat Completions，均通过 Roami 网关转成上游格式。
  3. 工具调用的名称、ID、参数与结果经过完整往返；客户端能够执行真实工具，继续发送结果并收到最终回复。
  4. 手机在一个全屏表单完成连接与模型配置；地址、已有密钥、模型和聚合策略不会因分开编辑而丢失。
  5. 原有定价、用量、限额继续有效，按真正调用的上游模型和原始用量计价。
  6. 保存失败保留输入；编辑不会改变列表顺序；切换原厂仍保留登录、hooks、MCP、权限等非模型设置。

模块

  • ModelHub.tsx：连接分组、一次提交连接与多个模型，复用原定价与费用表单；协议和认证方式收在连接选项。
  • GatewayModelBinding.tsx：所有智能体共用来源和模型列表，不再按上游协议过滤；原厂与自定义模式独立。
  • RoamiAgentModels.tsx：主智能体与执行智能体从同一完整列表选择模型。
  • catalog_http.go：原生配置写入工具所需的网关协议，独立于上游协议；公开回环推理和私有管理接口分离。
  • protocol_requests.go：将三种协议的消息、工具、工具结果、图片和常用参数转为上游请求；支持命名空间、自定义文本工具和对话中的 system 消息。
  • protocol_results.go：解析 JSON 或 SSE，上游文本增量实时输出，完整收集并校验工具参数。
  • protocol_events.go：输出客户端所需的 JSON 或 SSE 事件，保持调用关联、结束事件和用量字段。
  • native_usage.go / 原账本：计量读取原始上游响应，一次结算实际候选模型，不依赖转换后的客户端数据。

原生配置中只写 Roami 的回环地址与按智能体派生的凭据。CC 固定使用 Messages，Codex 固定使用 Responses，OpenCode / Pi 默认使用 Chat Completions；三种客户端协议都能由网关适配到三种上游协议。上游密钥只保留在节点，不返回浏览器或复制进 CLI。

目录中的 protocol 保留为主来源协议字段，以兼容既有存储，不再代表客户端准入条件。主来源和备用来源可使用不同协议。主备仍仅在连接建立前失败时切换，收到上游响应后不重试其他来源；每个尝试按原账本独立结算，避免重复请求与重复消费。

保存、恢复与兼容

连接及多个模型使用同一个目录修订和一次 PUT 保存，保留路由 ID、已有密钥与主备候选。源被其他模型作为备用时不能直接删除；正在使用或保存在原生预设中的模型仍受后端引用保护。修改连接协议不会要求重新配置客户端，网关在后续请求时适配；进行中的请求保留原快照。

旧 /capabilities/models/sources 及其详情链接统一进入模型页，原有设置和节点参数继续保留。原厂切换和恢复使用现有备份、修订校验、原子写入与读回确认。Claude 保留 Roami 管理标记，避免本机已有同步服务立即覆盖其设置。

适配边界

支持普通回复、文本流、函数工具往返、标准 URL/Base64 图片输入、常用采样参数及可转换的结构化输出。工具参数完整校验后才输出为工具调用；截断、格式错误或缺少可信用量时返回错误，不伪造完成事件或用量。

提供商托管的搜索等能力不能凭协议转换产生。跨协议的 Responses 自动模式会停用不支持的托管搜索/工具检索，保留所有客户端工具并明确告知模型及响应头；强制调用不支持的托管工具则拒绝。同协议透传继续保留原生提供商能力。命名空间恢复到客户端原名称，自定义文本工具用字符串参数承接，并提供原格式说明；语法约束仍由客户端工具验证。

CC/Codex 默认附带的厂商专用思考配置不跨协议强制注入，按上游默认行为执行并通过响应头标明；显式保存的 Chat 推理参数仍按对应字段转发。可见思考文本可进入后续上下文，不伪造提供商签名。CC 的流事件先输出思考再输出正文；若上游在正文后继续追加思考而无法保持这一顺序，明确报错，避免客户端最终回复被覆盖为空。跨协议不接受提供商加密状态、文件 ID 等无法移植的内容；previous_response_id、WebSocket 及跨协议的 responses/compact 仍不支持。模型本身的图片、推理和上下文能力由上游决定，协议转换不改变模型能力。

协议参考：OpenAI Responses 迁移与类型化事件、Responses 流事件、命名空间工具、Claude 消息流。历史 HTML、发布流程和同协议限制仅用于早期设计对照，不代表当前实现。

默认智能体网关记账 V1 已实现：模块设计与验收。支持本地源导入、独立 Key 的自动应用与轮换、按默认智能体归集费用；无需另建接入身份。

交互修订：下游智能体密钥由内部自动管理，移除密钥页面、尾号和手工操作；模型来源与智能体费用统计保留。

本机 Claude 接入修正：问题、实现与真实 Token 验收。旧直连预设不再误判为已接入网关。

其他本机客户端可配置独立的网关调用 Key，智能体自动凭据继续由内部管理：产品、接口与鉴权设计。

添加模型：最短流程

2026-10-31 产品修订提案。用户要求简化添加，并将定价、聚合策略放到后面的选项卡。本文及 可交互稿 用于评审，尚未改动产品运行代码。原型为中文开发评审文档、使用示例数据；正式实现的所有文案接入全局中英 i18n。

Product Design

上一版合并了“来源”和“模型”的页面，但仍要求理解连接命名、模型 ID、显示名称和手动加行。合并表单没有减少用户要做的决定。

这版只问两件事：连接哪项服务，添加哪些模型。普通流程不要求用户理解协议、网关、智能体类型或路由。

页面结构

能力下继续并列“大模型”和“智能体”，不增加一级入口。大模型按以下顺序显示选项卡：

选项卡 内容
模型 统一添加、按来源分组的模型列表、连接设置
定价 保留默认、逐模型、前缀定价，以及输入、输出、缓存读取/写入价格和币种
聚合策略 给已添加的模型选择备用来源与模型、排列备用顺序；默认直接使用主来源
用量与限额 保留真实用量、费用、每日限额、时区、核账和记录

添加页不显示定价、策略、限额，也不显示“对外模型”。已有聚合策略原样保留，不因简化添加而重置。原型只展示策略的主用及一个备用位置，正式实现保留已有多个候选和顺序。

首次添加

  1. 点击“添加模型”，打开添加页。桌面为内容面板，手机为全屏二级页。
  2. 默认只显示“服务地址”“API 密钥”两个输入，主按钮“读取模型”。“连接选项”折叠；“手动填写模型”作为可见的文字操作。
  3. 读取成功后，在同一页将连接输入收为来源摘要及“修改连接”，下面显示可搜索、可多选的模型列表。
  4. 用户勾选模型，底部按钮变为“添加 2 个模型”。不默认勾选，不把整个上游目录自动导入。
  5. 一次保存来源和所选模型，直接显示添加结果。提供“配置智能体”和“完成”，不再弹第二次保存确认。

“读取模型”只读取目录，不发送付费推理请求。成功文案是“已读取模型列表”，不能宣称模型已通过推理或工具能力验证。来源和未选择的目录项此时均未落库。

已有来源再加模型

从某个来源下的“添加更多模型”进入，直接显示该来源的模型选择列表，复用已保存的地址和密钥。主入口“添加模型”默认最近使用的来源；存在多个来源时可切换，并在同一选择器里提供“添加其他来源”。不强迫用户再填一次连接。

已添加的模型标为“已添加”，不可重复选。目录搜索不清空当前选择；“选择本页”仅选择当前过滤范围。切换来源保留各来源的草稿，回到来源时恢复。目录不可用时仍可手动填写已知模型名称，每行一个，支持一次添加多个。

本机网关调用 Key

产品与用户场景

在“本机网关”标签配置其他本机客户端使用的调用 Key。用户可以输入、替换或确认停用；密钥输入在模型标签间切换时仅保存在内存中，不进入设置草稿的持久存储。保存后清空明文，只显示末尾八位。未配置时不新增调用凭据，已有智能体的自动密钥保持独立。

调用 Key 使用 16–512 个可打印的非空白英文字符。客户端可以使用 Bearer 或 X-Api-Key 调用目录及已有推理协议；调用沿用网关的预算、排队、转发和用量记录，不得到管理权限。

技术设计

  • GatewayAccessKey 使用登录保护的 GET / PUT / DELETE /agent/model-gateway/access-key，读取配置状态、设置和停用 Key。写入校验共享目录 revision，冲突后保留输入并允许重新读取。
  • Go 私有管理路由 /v1/model-gateway/access-key 由网关 Unix socket 承接，公网/loopback 推理 handler 不暴露它。
  • catalogDisk 保存独立的 SHA-256 摘要、随机 generation ID 和末尾，不保存 Key 明文；目录快照与目录更新保留私有状态，常规目录 API 不暴露摘要。
  • authenticate 将此凭据归为 external，拒绝与智能体凭据重合；keyAllowed 校验 generation，在替换或停用后唤醒并拒绝旧 Key 的排队请求。已获准的请求正常结束。
  • 调用账目记录 external 与不可变 keyId，用量页面显示“其他客户端”；不更改 AgentKeys、Token 或智能体配置文件。

验证

Go 回归覆盖设置与重新加载、明文不落库、不泄露、推理转发时使用上游凭据、独立用量归属、普通目录更新保留 Key、替换/停用失效、管理路由隔离、排队撤销和已有智能体密钥保持。前端覆盖保存后清明文、冲突恢复保留输入、确认后停用。

Product Design

能力中心并列“大模型”和“智能体”。大模型管理一个节点上的统一接入，添加多个模型源，再发布稳定的对外模型。智能体原来的安装、登录、启动和模型恢复保留在同一个目录，加入 Roami 主智能体与后台智能体。

大模型包含四个页签：

页签 首版行为
模型源 名称、上游地址、协议、认证方式和密钥；同一上游可建多条协议或账户配置
对外模型 稳定标识、真实模型映射、固定来源或有序主备；保存草稿与发布分开
用量与限额 原账本、币种、每日金额上限、时区、统计过滤和未知费用核对
模型定价 原默认价格及模型/前缀价格，分别设置输入、输出、缓存命中单价

价格沿用原来的账本和接口，迁移导航不会删除配置或历史。计价使用实际上游模型 ID，模型别名不会另计一次。高级模型能力、上下文和推理设置仍在 Roami 详情中。

主界面

页头显示当前节点，例如「开发主机」。手机远程操作修改的是这个节点，不能让用户误以为修改了手机上的 CLI。

智能体列表采用平面行：工具名、当前模型、来源、一项必要状态与「切换」。Codex / Claude 初次接入时显示「使用原配置」，保留官方登录。未安装工具显示「未安装」和安装入口；不虚构“已接入”。原配置指接管前快照，不能把任意自定义原配置标成官方订阅。

主路径：给 Codex 换模型

  1. 打开「智能体使用」，在 Codex 行点「切换」。
  2. 桌面进入同页右侧详情栏；手机进入带单一返回栏的全屏二级页，保留底部四个主导航入口。
  3. 先选已保存的连接，再选该连接中适合 Codex 的模型；默认带出当前组合。地址和密钥无需再次填写。
  4. 用一行说明作用范围：「修改开发主机上此用户的默认配置；新启动的 Roami 和本机命令行会话使用。」协议不兼容项仍可看见，但不能选；说明「此连接暂不能用于 Codex，换一个连接」。协议名在详情中展开。
  5. 可选「测试模型」，明确一次小型验证，最多两次模型请求。检测内容是认证、真实模型响应、流式和工具调用回传；获取模型列表不算验证成功。不默认运行代码、不发送项目正文。测试结果只代表所测版本和组合。
  6. 点「应用」。首次接管某工具时用短确认说明本机 CLI 影响，并提供「应用并备份」；已接管且无冲突时后续切换直接应用。
  7. 成功后显示「已更新 Codex 默认配置」，给出所选来源和模型，并提示「重新打开 Codex 后使用」。列表显示「默认已设置」，不能直接宣称运行中的会话已切换。

回退：详情内「恢复原配置」。展示将恢复的工具与快照时间，确认后仅恢复接管过的模型相关字段；原来未登录的官方连接仍可能需要登录。恢复成功不等于模型连通。

另一条路径：连接配好后分给多个智能体

连接保存成功后出现轻量动作「分配给智能体」，不强制弹向导。在连接列表行尾也能进入。页面列出适配工具，用户勾选工具并逐个选择模型；共用连接不要求共用同一个模型。

提交按钮写「应用到 2 个智能体」。首次接管的目标合并成一次范围确认；每个目标独立备份、校验和应用。结果逐项展示，例如 Codex 成功、Claude 配置冲突，主状态为「部分完成」；成功项保留，失败项可单独重试。未安装或不兼容目标不可勾选，原因可见。

首页选择网关模型

Product Design

能力页已经保存 WorkBuddy 的 WorkBuddy Hy4、hy4free，但首页只读取当前直连服务的 /models。本机 Main 和 Worker 仍直连 Blade，返回的 11 个模型不包含这两个模型，因此首页搜索不到。

首页保留当前服务的模型，同时补充网关目录中尚未出现在该服务列表里的模型。选择网关模型时接入网关；连接失败时保留当前选择，错误提供重试或模型设置入口。复用现有桌面弹层和手机全屏模型页，不增加布局或控件。

User Stories

  • 用户在能力页添加 WorkBuddy 后，回首页搜索 hy 即可选择，不必先手动迁移连接。
  • 只切换 Main 或 Worker 时，另一个角色继续使用原模型，并保留图片、上下文和推理参数。
  • 目录修订过期、运行时忙或另一角色无法映射时，不覆盖原模型；刷新目录后可以重试，无法映射时提示先在模型设置绑定两个角色。

Technical Design

  • useAgentModels.ts 复用缓存的网关目录，把补充选择编码为临时 gateway: 标识，避免与直连模型同名 ID 混淆。保存时转回目录 ID，调用现有 /model-gateway/catalog/roles；成功后读回模型配置并广播现有更新事件。
  • roami_binding.go 为 roles 接口增加互斥的 { role, model, revision } 输入，沿用目录修订、禁用凭据、并发锁、原连接备份和运行时保存检查。
  • 接入共享连接时，另一角色仅匹配同地址、同凭据、同上游模型的固定路由，或已经使用的网关 ID；恢复该角色的显式参数。找不到匹配时返回 MODEL_ROLE_REQUIRES_BINDING，不猜测替代模型。
  • 网关凭据只在 Go 侧读取和应用，不返回浏览器。新提示通过现有中英文 i18n 提供。
