Product Design

本阶段只重构模型源和聚合。参考 Linear 的紧凑导航与对齐、Vercel Geist 的中性表面和明确对比。React + Tailwind CSS + shadcn/Radix 控件承载新页面，沿用 Roami 已有 token、国际化、手机导航与手势约束。其他能力页继续使用既有组件。

按用户最终确认，能力顶部 Tabs 和模型功能左侧 Tabs 保持原有形式；手机继续使用原有能力选择和顶部模型 Tabs。聚合调度采用上下结构：紧凑策略配置与预览卡在上，完整优先成员列表在下，编辑和预览不再分居两栏。成员用卡片式可排序行展示；鼠标悬停/键盘聚焦显示置顶和移除，触屏始终可见。

状态从已保存的真实路由渠道读取；新成员未检测时明确未知。上下文来自源目录；延迟只显示具有明确来源和时间范围的实际监控值，不推断、不造在线状态。监控仍为 24 小时滚动，保持原有空间上限。

配置减负与模型范围

  • 聚合常用路径：名称、源、模型。自动生成 ID，默认智能策略。ID、启停和删除收在更多设置。成员列表可筛选已确认的免费模型，已选成员继续按保存的调度配置执行。
  • 来源详情直接提供「删除来源」，确认后移除该来源和其名下启用的模型。有引用时列出相关模型，解除引用后即可删除。单个模型在「管理模型」内移除。
  • 已有源先显示连接摘要与已启用模型；新增连接只先显示地址和 Key。名称、协议、认证方式按需展开。上游目录显式读取后分页展示，每页 30 项。
  • 源内价格先显示当前规则及模型价格，点击修改后出现表单；模型级规则独立保存，明确免费仍须确认。
  • 源清单与价格表、聚合候选共同使用 configured-source-models.ts：只认已保存的非聚合主模型。聚合引用、备用候选和上游全目录均不能自动扩展清单。
  • 历史聚合中未在源里启用的成员保留并标记，可显式取消选择；从源移除模型不会删除对应聚合。聚合成员页不再发起上游发现请求。
  • 手机将策略选择与细则放在同一行，预览与故障测试共用标题行，首屏优先显示完整成员。
  • 成员选择改为左侧源、右侧模型，上方直接展示聚合池；跨源选择与移除不再切换已选视图。单模型隐藏搜索与全选。详见 聚合成员选择。

User Stories

  • 我能在一屏内看到策略、效果和优先成员，沿用熟悉的能力和模型导航。
  • 我能从手柄拖动模型排序，或用键盘上下/Home/End 排序；置顶和移除都有清楚名称。
  • 我能看到来源、可用性和已公布的能力；未知与不可用不混为一谈。
  • 我能跨源核对已选成员，在字段旁定位错误，切换标签或返回后继续草稿。
  • 手机列表可以正常滑动，只有抓住手柄时才排序；控件、弹层和保存均可触达。

Technical Design

Tailwind 使用前缀和隔离的 utility 层，由入口统一加载一次，避免懒加载路由拆 CSS 后丢失基础样式；不引入全局 Preflight，不改其他页面的默认元素。shadcn 风格的本地组件基于 Radix primitives，颜色、字号、圆角和空间映射现有 token。没有新增第二套全局主题。

ModelHub 保留目录与源详情路由和草稿逻辑，能力顶部 Tabs、模型左侧 Tabs 沿用原组件和布局。ModelSourceEditor、SourcePricingSettings 与聚合编辑控件迁入新组件。RoutingStrategyPreview 只显示紧凑模拟；AggregationMemberOrder 独立承载全宽成员列表。现有 Pointer Events 拖动保留触屏滚动和取消语义，新增置顶，移除上下移按钮。

元数据按唯一源读取、限制并发，目录请求按 revision 缓存，离开时取消。真实路由与监控最多各一组可见时轮询；新增草稿不查询虚构运行状态。排序、权重、ID 别名、定价和请求协议语义保持。

Direction contract

THESIS: 让模型路由成为可操作的工作台，以优先列表为主体；配置和预览共同解释接下来会如何调度。

OWN-WORLD: 使用现有中性深浅表面、细边界、标准 sans 和唯一蓝/绿语义色，压缩内容区的配置和控件层级，外层导航保持原样。保留用户指定的独立卡片。

STORY: 先确认源与成员，再选策略；在同一区域观察预览，随后排序并保存。真实渠道状态始终与草稿示意区分。

FIRST VIEWPORT: 原有能力顶部 Tabs 和模型左侧 Tabs；详情标题和保存动作；顶部紧凑策略/模拟卡；下方全宽成员行。宽屏有更多行内指标，手机纵排但不缩小文字。

Design System: Roami model workspace

Overview

Creative North Star: "The model operations workbench"

This is a code-led record of the shipped model-source and aggregation surfaces. The confirmed Linear/Vercel direction means restrained neutral surfaces, compact controls, aligned facts, and clear working hierarchy. It uses Roami's existing identity in both themes. The user pinned the direction (seed: none); no catalog world or new palette was introduced.

This topic record describes a local application of the normative UI specification. That specification, theme source, and base tokens remain authoritative. Frontmatter primitives deliberately reference live CSS variables, including the runtime-derived solid accent; they are bindings to that system, not replacement values. The document does not redesign other capability pages.

Key Characteristics:

  • A full-canvas, flat application shell with independent content cards.
  • Compact hierarchy using the existing sans family and type ladder.
  • Neutral selection; blue actions and focus; green verified readiness.
  • Equal functionality with mouse, keyboard, and touch.
  • Source-backed facts with explicit unknown states.

Colors

Quiet dark neutrals support long configuration sessions; the same semantic variables supply the existing light theme.

The sidecar's tonal ramps are panel-only interpolations of live tokens, not additional application colors. Its component snippets illustrate the existing controls without fixture metrics; production behavior stays in the React/Radix components.

Primary

  • Action blue (--accent): links, focus, insertion markers, and active drag feedback.
  • Solid action blue (--accent-solid, --on-accent): primary buttons and simulation meters. Use the runtime-derived value rather than copying a seed color.
  • Accent boundary (--accent-border): restrained drag and focus-related boundaries.

Secondary

  • Readiness green (--ok): readiness confirmed by saved routing-channel data. Neutral text still states the condition.
  • Danger red (--danger): field errors and destructive actions, with the existing danger surface/border family.
  • Warning amber (--warn): draft or caution states, with the existing warning surface/border family.

Neutral

  • Canvas (--bg-base): page shell, navigation, toolbars, and adjacent modules.
  • Content surface (--bg-container): independent strategy card, member rows, and controls.
  • Popup surface (--bg-elevated): Radix menus, selects, and confirmations.
  • Structural boundaries (--border, --border-subtle): control strokes and one-sided module dividers.
  • Reading hierarchy (--text-bright, --text-dim): identity and actions first; source and metadata second. The existing --text-dimmer is used for neutral status dots and disabled details.
  • Neutral selection (--sel-bg): tabs, ordinal badges, simulation rounds, and a dragged row. Mouse feedback uses --list-hover.

The Evidence Color Rule. Green readiness comes from saved channel facts; unchecked, unavailable, and simulated rest remain distinct text states. A simulation is never proof of availability.

Typography

Body Font: The existing Inter/system sans stack, with the project's Chinese system-font fallbacks. Labels and headings use the same family; this administrative surface has no separate display face.

Character: Compact and legible. Identity carries more weight than metadata; density comes from alignment and disclosure rather than small text.

Hierarchy

  • Title (--fs-title): inherited desktop page heading; the phone uses the established secondary-page bar.
  • Section (--fs-lg): existing pane and dialog headings where present.
  • Body (--fs-body): input text and member identity; member names use medium weight (500). The token grows in compact mode.
  • Label (--fs-sm): buttons, tabs, field labels, and disclosure summaries; button/tab weight is medium (500).
  • Meta (--fs-meta): source, readiness, context, latency, ordinals, and counts. These are secondary facts, not the sole labels for actions.

The Existing Ladder Rule. Reuse the live --fs-* roles. Do not create half-step sizes or shrink text to fit narrow screens; wrap metadata and move controls below identity.

Layout

The workspace fills the available width and remaining shell height. Flex/grid children use zero minimum dimensions; the content container owns scrolling. The document never scrolls. Page and tab bars stay outside the editor's scroll area, and the save/cancel footer remains a separate layout item. Form and explanatory content may use --content-form; the workspace shell and member list do not inherit that cap.

Keep the existing capability tabs above the workspace and the model-function tabs at its left on desktop, using their incumbent AntD components. Preserve the existing capability select and top model tabs on phones. Back navigation precedes the title using the existing BackButton. On phones, content-heavy editors use MobileSubPage with one return bar and one content scroll container. URL-backed source details do not add a second overlay-history entry. Existing app navigation, safe areas, and keyboard handling remain owned by the shared shell.

For aggregation routing, one independent card combines strategy configuration and a compact simulation. The implemented wide layout divides that card into configuration and simulation columns (35%/65%). A full-width, ordered member list follows below it. This composition belongs to this model surface; it is not a universal composition requirement for Roami pages.

Compact and medium layouts stack the combined card, put metadata below identity, and move row controls below the identity column. They keep the full type scale and normal touch scrolling. Responsive decisions come only from useLayout() and the shared HTML data-size/data-pointer attributes; thresholds live in layout.ts. Phone page padding uses the existing Material override, not the smaller base fallback.

Spacing comes from --sp-1 through --sp-5. Strategy cards and wide rows use --sp-4 padding; narrow rows and the narrow strategy card use --sp-3. Row gaps use --sp-2; the member-order section follows the card at --sp-5. Control heights use --ctl-h, with independent touch targets of --tap (44 CSS px).

The Canvas Rule. Give free space to the actual workspace; close optional panes without leaving an empty column. Limit readable fields inside it, not the working canvas.

Elevation & Depth

The implemented model surfaces are flat at rest. Tonal steps, fine boundaries, and space separate content; strategy cards and member rows have no decorative shadow. Popup placement uses the existing elevated surface and named popup layer. Drag feedback uses a neutral fill, accent boundary, and insertion line rather than lifting a row with a shadow. No new shadow vocabulary is introduced.

The Single Boundary Rule. Adjacent modules share the base surface and one subtle divider, owned by one side. Independent cards may have their own perimeter; an entire page is not a card.

Shapes

The shared shell stays square and borderless around its perimeter. Controls and tab items use --r-xs; member rows and menus use --r-sm; the independent strategy card and short confirmation dialog use --r-card. Metadata chips use --r-pill, while member ordinals use the smaller control shape. These roles map directly to the existing radius ladder.

Components

The new model-source and aggregation controls use local shadcn-style components with Radix behavior. Prefixed Tailwind utilities expand from Roami tokens and load once without global Preflight. Model controls own visual states; UI primitives own reusable semantics. Existing Ant Design surfaces elsewhere are not a prescription for new controls in this scope.

Buttons

Compact, familiar actions. Primary uses the solid accent; outline uses the content surface and normal boundary; ghost uses neutral text and transparent fill. All use the small control radius, token padding, and medium label type. Focus has an accent outline. Disabled actions are visibly subdued and noninteractive; saving reflects busy state.

Mouse hover is gated to fine pointers. Coarse-pointer buttons preserve compact visuals and expand their hit area to the touch token. Icon-only actions carry localized accessible names; visible instructions do not depend on tooltips.

Inputs / Fields

Labelled, neutral, and field-specific. Inputs use the content surface, normal border, small radius, and body type. Focus changes the border to the accent; invalid fields use the danger boundary and nearby localized error text. Validation preserves the draft and focuses the invalid field after a failed submission. Select and checkbox behavior comes from Radix; popup content uses the elevated surface and named popup layer.

Common and advanced settings

Create an aggregate with one name field, source selection and configured model checkboxes. Generate the ID and use smart routing by default. Keep the free-only restriction visible; disclose ID editing, enable/disable and deletion under More settings. Existing source connections open as a summary with the saved model list; reveal credentials only through Change connection. New connections initially expose endpoint and Key; source name, protocol and authentication options remain disclosed.

Default pricing is a readonly summary above the model table. Edit default pricing opens an inline form; cancel restores focus without a write. Per-model editing retains its own save boundary and free declarations still require confirmation. Simulated failover is an optional disclosure, not a required configuration field.

Model scope

Use configured source models for source ownership, pricing rows and aggregate candidates. Only saved nonaggregate primary registrations define inventory. Upstream discovery metadata, aggregate references and backup-only candidates cannot create source membership. Read discovery only while explicitly managing a source, paginated at 30. Existing unconfigured aggregate members remain visible with an explicit status and removable selection; never silently delete a group while removing its source model. Cross-source selected views use total scope, not a per-source counter.

Navigation

Outer capability and model navigation keep their original AntD form and placement. Within source and aggregate details, Radix tabs use neutral text at rest and neutral selected fill with bright text. Keyboard focus remains visible. Member selection, routing, and saved runtime are distinct contexts; changing tabs keeps the draft. Source connection, pricing, and routing retain their existing destination semantics.

Chips

Small neutral facts, not colorful decoration. Context, latency, and ordinal chips use meta type and subtle boundaries. Status dots are drawn shapes paired with text. Context and latency explicitly say when unavailable; missing values are never rendered as invented zeroes or capabilities.

Cards / Containers

Independent strategy card and member rows use content surfaces with subtle perimeter borders. The strategy card uses the card radius; rows use the standard row radius. Their token padding reduces one spacing step in compact/medium layouts. No outer rounded wrapper encloses the entire workspace.

Sortable members

On phones, strategy and details share one row; preview and optional failover share their heading row so an initial viewport can show a complete member. The full-width ordered rows show ordinal, model identity, source, readiness, context, and source latency. Quick move-to-top and remove actions appear on fine-pointer hover or keyboard focus and stay visible for coarse pointers. Weight controls appear when the selected strategy needs them.

Only the grab handle starts pointer sorting; ordinary row swipes keep scrolling. The handle supports ArrowUp/ArrowDown and Home/End ordering, Escape cancellation, disabled states, and a polite position announcement. Reordering preserves weights; removal also removes the corresponding weight. Feedback marks the dragged row and target insertion edge. The handle and quick actions meet the touch target independently of their visible size.

Facts come from member-fact collection: readiness is based on matching saved route channels; context comes from the source directory; latency is the source's first-token P95 over the existing rolling 24-hour monitor, not an individual model benchmark. Missing source/directory/monitor data remains unknown. Preview counts and rest choices are explicitly simulated. No fixture measurements belong in the visual system.

Disclosures

Policy details and request options use native details/summary semantics with a shared SVG chevron. The chevron rotates when open and the summary remains touch-sized. Keep both the visible expansion cue and keyboard affordance; a bare text label does not communicate disclosure clearly enough.

Do's and Don'ts

Do:

  • Do reference the existing CSS variables and let both themes resolve them.
  • Do fill the working canvas and keep scrolling inside the active content region.
  • Do retain localized labels, visible focus, explicit unknown states, and field-level recovery.
  • Do keep quick actions visible on touch and preserve the 44 CSS px hit target.
  • Do support handle-only dragging, keyboard ordering, and ordinary phone scrolling together.
  • Do keep disclosure chevrons and save/cancel actions discoverable.

Don't:

  • Don't introduce a competing palette, type ladder, radius scale, or global Tailwind reset.
  • Don't turn adjacent modules or whole pages into enclosing rounded cards.
  • Don't treat simulation, source-level latency, or unchecked data as verified model quality.
  • Don't hide touch actions behind hover or rely on tooltip-only names.
  • Don't replace existing SVG icons with emoji, text glyphs, or new component-local SVG drawings.
  • Don't repeat page titles, explanatory copy, or implementation details in the main flow.

Product Design

截图中的问题是接入地址、生成 Key 与固定 Key 编辑分散在通栏区块里：操作离对象过远，低频表单一直占据主流程，且“服务商提供的 API Key”会使用户混淆网关调用凭据与上游源凭据。

默认页保留“接入与密钥 / 模型目录”两个任务入口。接入页先给 Base URL 和可复制的调用示例，再展示独立调用方的 Key 列表。地址和复制按钮紧邻；调用模型切换会同步更新 curl / Python 示例。复制示例只引用环境变量，不写入明文 Key。

接入地址依据服务端实际返回值；演示使用截图中的回环地址。正式实现仅在确认为回环地址时提示“仅宿主可访问”，不把回环地址替换成未经支持的 LAN 地址，也不声称服务已通过连通性检查。

Key 列表只展示名称、末尾标识、启停状态与行尾菜单。主动作是“新建 Key”；固定 Key 设置收进区块的更多操作。设置完成的固定 Key 与其他 Key 一起展示，避免两套凭据入口各藏一份当前状态。固定 Key 仍使用原有独立单例配置，列表只是展示合并，不改变后端身份或存储。

新建只需名称。右侧检查器承载新建、改名与固定 Key 编辑，手机改为全屏返回页；保存按钮始终属于当前编辑范围。生成或轮换后显示一次性凭据，离开后不再在列表中展示全文。停用、轮换与删除先确认影响；启用可直接完成。固定 Key 替换时明确旧值立即失效。

模型目录提供名称 / 来源 / 类型筛选，保留模型的来源身份；调用名称与上游 ID 分开。已接入模型和聚合可以复制调用名称；仅上游目录模型显示启用提示和配置入口，不提供会被误解为已可调用的快捷操作。不展示虚构的延迟、成功率或在线状态。

手机默认收起调用示例，优先展示地址与 Key；目录改为可读列表，详情全屏。内部滚动、44px 触摸命中、返回位置、校验后保留输入与固定底部保存操作沿用现有规范。

  • 同一插件可新增独立账号源，每个实例独立连接、选模型、定价和调度。演示有两个 WorkBuddy 实例，可继续新增；不把一个插件来源误当成单账号限制。

定价

  • 默认只读：源默认方式、模型生效价、价格来源、输入 / 缓存读取 / 输出单价、币种与计价单位。
  • 点某个模型只编辑该模型；点默认定价只编辑源默认。切换计费方式时，只有按 Token 计费才出现三个单价字段；明确免费必须主动确认。
  • 检查器显示未保存的价格预览，与表中的当前生效价区分。取消恢复原规则；保存只影响当前范围。
  • 倍率与分时选项继续在高级设置中承载。实际实现沿用已有价格解析与请求价格快照，不新增计价算法。

聚合

  • 保留左侧源、右侧该源已启用模型、上方跨源池成员。切源保留选择；移除同步取消勾选；同名模型仍按源身份区分。
  • 默认自动生成对外 ID，常用创建只填名称和选成员；ID 与请求恢复参数按需展开。
  • 调度顶部放策略、短摘要和演示预览，下面全宽展示成员。拖拽手柄有键盘上下 / Home / End 操作；手机非手柄区域仍正常滚动。置顶和移除在触屏常显。
  • 策略定义、64 成员限制、成员权重身份和现有路由算法均保留。HTML 预览仅演示 UI 效果，轮流与权重序列随输入变化，不替代真实运行时调度。

概况、审计与监控

  • 概况默认展示今天，时间与时区由浏览器自动探测。请求量、总 Token、费用三个指标直接切换；按模型 / 源 / 智能体分组，按小时或天查看。
  • 手机将次要筛选收进“筛选”，保留当前筛选条；提供可直接选择小时的“查看时段”，避免要求手指精确点击窄柱。点时段或分组再点“查看这些请求”，把日期、源、模型、智能体和时段带入审计。概况不出现逐条请求详情。
  • 审计列表有状态和搜索，详情放回执、价格快照及失败原因。桌面用右侧检查器；手机用全屏详情。返回仍保留筛选。
  • 监控独立保存自己的源、模型和时间范围，避免与用量的历史时段互相污染。请求成功率、首字时间和质量分别解释，未检测与失败明确区分。
  • 监控仍为 24 小时滚动保留、64 MiB 上限，不保存对话正文。主动检查展示可能计费的提示；设计稿明确标为模拟，不发送模型请求。

网关和语音

  • 网关“接入与密钥”首先显示地址与复制，密钥列表默认只看名称、末尾标识和状态；新增才填名称，完整 Key 只显示一次。停用、轮换和删除均说明影响后确认。
  • “模型目录”标记聚合、已接入原生模型和仅上游目录模型，支持源、能力与名称筛选。未启用模型有明确的源配置入口；不把目录模型画成已可调用。
  • 语音输入先看服务摘要，修改时按服务显示字段，切换服务保留各自参数。

聚合成员选择

Product Design

用户确认：“应该左边源，右边切到每个源的时候把它选出到池子里”。保留能力顶部与模型左侧导航、聚合成员 / 调度 / 运行标签，以及现有设计系统。此次只调整成员选择，不替换视觉系统。

聚合池位于选择区上方，直接展示跨源成员、来源和移除。下方左列列出模型源及“已选 / 可选”数量，右列随源切换显示已配置模型。默认展开第一个源，点击模型卡或复选框加入池中；切换源不自动选中，也不清除已选。

一个模型无需搜索和全选。超过八个模型出现搜索；多个模型允许全选此源或搜索结果，超过三十个分页。历史未在源中启用的成员保留在池中并标记，标题显示数量，由用户显式移除。手机已选成员横向滑动，避免挤占模型列表高度。

User Stories

  • 我先看到源列表，切换后只看到这个源里已配置的模型。
  • 我能跨源加入模型，随时核对池内成员，不用进入另一个“已选”视图。
  • 我能直接移除任意来源的成员，模型卡的勾选同步变化；不同源中的同名模型互不影响。
  • 我能全选当前源或搜索结果，返回列表后继续草稿，保存后读回相同顺序。
  • 我在手机上仍然从左侧选源、右侧选模型，整张模型卡可点，移除按钮始终显示。

Technical Design

AggregationMemberPicker.tsx 用源按钮列表替代源下拉框与 @selected 伪源；池成员始终展示。已选身份仍使用 candidateIdentity，保持插入顺序和按身份绑定的权重。移除只删除对应候选及其权重，首次加入成员沿用源 / 嵌套路由组协议。

原生模型范围继续复用 configuredSourceModelIds，不读取上游目录，不把聚合引用或备用候选当作源内模型。@group 嵌套组入口保留，排除当前组。最多 64 个成员，超限全选禁用，不静默截断。

model-routing.css 用现有 token 实现左右分栏、紧凑池成员条与模型卡。桌面与手机都保留左右关系；手机缩窄源列，名称换行。源和模型列表独立滚动，聚合池和底部保存栏保持可见；展开更多设置后恢复编辑器滚动，保证短屏字段可达。没有新增 API、定价或调度语义。
