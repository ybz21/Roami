技术设计

层次本轮设计
人机交互从监控按调用方、网关模型和最终结果筛选，再进审计看有序尝试与未发送原因。从对应记录进入来源、聚合或限额处理。
对外接口沿用发现、调用和流式响应契约。拟给被接受且已识别模型的请求返回统一关联号，覆盖成功、503 拒绝与候选切换。
控制接口沿用目录、配置、密钥和当前调度入口。拟增加策略预览、请求级监控查询与单次请求详情。按请求记录终态，保留每次上游尝试。

聚合保留已选成员与生效策略，候选免费筛选只负责缩小选模范围。观测里区分策略草稿、当前生效顺位和历史实际命中。按请求统计最终失败与切换恢复，来源侧继续统计每次尝试。聚合调度设计

交互原型

场景可查看的状态
OKR 免费模型 503零次上游尝试的拒绝。可以切到「切换后仍失败」，对照候选耗尽时同样的 503。
切换后恢复首选返回 429，备选完成请求。打开审计可以查看两次尝试，从审计返回保留所选场景。
输出中断客户端已收到 HTTP 200 和部分内容，审计记录最终失败与尝试次数。
聚合策略和来源健康查看生效策略、可调度来源、冷却成员、同源换模型和跨源切换。展开草稿可对照预览与生效顺位。
监控与审计从最终失败和降级结果进入单次调用。来源趋势与失败构成保留原有样例。

实施与验收

  1. 先覆盖请求终态与关联号。零尝试拒绝、候选耗尽和输出中断都能查到。来源、尝试和计费记录沿用各自口径。
  2. 接通聚合观测与监控审计。单次请求切换后成功只计一次成功，保留首选失败和备选结果。草稿预览、冷却状态和历史命中分别可查。
  3. 补齐 OKR 的宿主归因和故障入口。来源授权、额度和调度问题能跳到对应设置。账号体验沿用WorkBuddy 来源设计。
