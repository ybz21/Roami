现行设计

历史设计与验收

截至 2026 年 11 月 19 日。七个页签各有一份设计，网关、聚合、监控、审计与 WorkBuddy 收录可交互样例。

子页设计主要用途
模型源连接、授权和启用模型
聚合配置成员和顺位，查看当前与实际调度
概况看用量、记账费用和每日限额
监控看成功率、延迟和失败分布
审计定位某次调用、命中模型与费用
本机网关人机交互、对外调用、控制接口与故障排查
语音输入配置和验证转写服务

统一口径

  • 模型源维护连接、授权、定价和启用范围。本机网关共享已接入目录，网页、CLI 与 Agent 选模使用同一份模型能力和稳定调用名。
  • 聚合只调度已保存的成员。「仅看免费模型」用于候选筛选。具体费用约束由请求表达，准入与记账由 Go 网关处理。
  • 调度页分别展示策略草稿、当前生效顺位和历史命中。请求级观测方案记录最终结果，来源视图继续统计各次上游尝试。
  • 网关的接入、调用与控制契约集中在本机网关。失败和降级从监控进审计，能查原因、尝试次数和对应处理入口。

在 Roami 内打开本文时，各设计页的「打开现有页面」使用当前节点地址。

跨页流程

  • 接入模型，从模型源启用模型，按需配置聚合，到本机网关复制调用方式。
  • 排查故障，从聚合的切换记录或监控的异常时段进入审计，保留筛选。
  • 核对费用，从概况查看额度和用量，再到审计核对明细。账号积分在 WorkBuddy 插件里看。

技术设计与验收

实施顺序

  1. 聚合与监控先上线现有数据能支持的部分，包括生效顺位、状态、成功失败趋势和带条件跳转。同步修复网关到聚合的定位与 ID 展示。
  2. 补请求关联、成员承载和故障切换，再接失败细分类。概况和审计补充结算时区及请求结果展示。
  3. WorkBuddy 先读账号积分，再接手动签到与真实回执。兼容版升级继续走安装包校验和回退。

验收场景

  • 对照现有页面的桌面四档及手机单滚动区。拖动、Esc、保存、返回、浏览器刷新和返回审计筛选均可用。
  • 用正常、有切换、无可用成员、未检测、无调用与只有抽检的数据比对。成员承载、错误率与审计总数用同一窗口核验。
  • 签到场景覆盖成功、已签、重复点击、授权失效、上游限制与余额暂无法读取。验证操作只影响选中的账号。
