页面总览

2026 年 11 月 19 日

在 Roami 现有「大模型」页签内改进七页。聚合借鉴参考图中的成员承载、健康状态与故障切换。监控借鉴请求走势、失败分布与延迟。下面的可点样例只演示新增区块，使用虚构数据。

子页设计主要用途
模型源连接、授权和启用模型
聚合配置成员和顺位，查看当前与实际调度
概况看用量、记账费用和每日限额
监控看成功率、延迟和失败分布
审计定位某次调用、命中模型与费用
本机网关找已启用模型、能力、调用示例和凭据
语音输入配置和验证转写服务

在 Roami 内打开本文时，每章的「打开现有页面」使用当前节点地址。

跨页流程

  • 接入模型，从模型源启用模型，按需配置聚合，到本机网关复制调用方式。
  • 排查故障，从聚合的切换记录或监控的异常时段进入审计，保留筛选。
  • 核对费用，从概况查看额度和用量，再到审计核对明细。账号积分在 WorkBuddy 插件里看。

打开现有模型源

启用的模型可在本机网关查看或加入聚合。插件来源可进入对应账号详情，看积分、授权状态和版本。

    概况 · 用量与限额

    打开现有概况

    把今日已用、剩余额度、每日限额、结算时区和「调整限额」放在同一处。趋势展示自己的分析区间和时区。费用未知或仍在结算时显示「待核对」。

    从用量趋势或来源分组进入审计，带入所选时段和来源。返回概况时恢复原筛选和位置。

      技术设计与验收

      数据或交互现有依据与新增工作
      当前可调度复用 AggregationRuntime、AggregationMemberOrder、useModelMemberFacts 与 routingView。按来源和上游模型对已保存成员去重，状态只取当前生效配置。聚合列表复用已有信息，避免逐条轮询。
      聚合统计和切换MonitorRecord 已记录 routeId、来源、模型和结果。先补按聚合的筛选。请求总数、最终失败率、切换数与成员承载需要逻辑请求关联和终态。记录同一调用的尝试顺序、最终成员与切换原因。同渠道重试单列。旧数据无法建立关联时，显示「历史记录未统计」，保留真实快照。
      监控统计monitorManagement 已有时间范围、分桶计数、首字 P95、单请求输出速度 P50。首版按监控记录展示样本和成功率，接入逻辑请求关联后才能统计去重请求。抽检样本单列。失败构成需基于窗口内完整计数，最近异常列表的上限为 100 条。P50/P99 延迟、整体耗时分位、在途和进程指标按各自观测字段接入。吞吐按窗口内 Token / 秒计量。
      跨页定位统一可返回的时间、来源、模型、聚合与错误条件。外部调用别名取本机网关。内部 ID 用于查询和关联，详情首屏呈现用户认识的名称。模型源和网关展示同一已启用目录。
      插件账号保留现有包、供应商和账号引用。复用 Go 网关的 AccountQuota 与配额缓存，按账号开放受控签到动作，结果回到同一账号。安装版本与兼容性沿用插件管理。插件包和授权凭据各有独立生命周期。

      实施顺序

      1. 聚合与监控先上线现有数据能支持的部分，包括生效顺位、状态、成功失败趋势和带条件跳转。同步修复网关到聚合的定位与 ID 展示。
      2. 补请求关联、成员承载和故障切换，再接失败细分类。概况和审计补充结算时区及请求结果展示。
      3. WorkBuddy 先读账号积分，再接手动签到与真实回执。兼容版升级继续走安装包校验和回退。

      验收场景

      • 对照现有页面的桌面四档及手机单滚动区。拖动、Esc、保存、返回、浏览器刷新和返回审计筛选均可用。
      • 用正常、有切换、无可用成员、未检测、无调用与只有抽检的数据比对。成员承载、错误率与审计总数用同一窗口核验。
      • 签到场景覆盖成功、已签、重复点击、授权失效、上游限制与余额暂无法读取。验证操作只影响选中的账号。
