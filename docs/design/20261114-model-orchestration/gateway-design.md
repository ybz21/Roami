# 本机网关：接入与 Key 管理

[打开可交互稿](gateway-prototype.html)。使用合成模型和凭据；所有保存、生成、轮换、停用与删除均只影响当前页面内存，不连接网关，不发送模型请求。顶部与左侧导航保留现有形式。本轮只设计本机网关，未修改正式页面或线上服务。

## Product Design

截图中的问题是接入地址、生成 Key 与固定 Key 编辑分散在通栏区块里：操作离对象过远，低频表单一直占据主流程，且“服务商提供的 API Key”会使用户混淆网关调用凭据与上游源凭据。

默认页保留“接入与密钥 / 模型目录”两个任务入口。接入页先给 Base URL 和可复制的调用示例，再展示独立调用方的 Key 列表。地址和复制按钮紧邻；调用模型切换会同步更新 curl / Python 示例。复制示例只引用环境变量，不写入明文 Key。

接入地址依据服务端实际返回值；演示使用截图中的回环地址。正式实现仅在确认为回环地址时提示“仅宿主可访问”，不把回环地址替换成未经支持的 LAN 地址，也不声称服务已通过连通性检查。

Key 列表只展示名称、末尾标识、启停状态与行尾菜单。主动作是“新建 Key”；固定 Key 设置收进区块的更多操作。设置完成的固定 Key 与其他 Key 一起展示，避免两套凭据入口各藏一份当前状态。固定 Key 仍使用原有独立单例配置，列表只是展示合并，不改变后端身份或存储。

新建只需名称。右侧检查器承载新建、改名与固定 Key 编辑，手机改为全屏返回页；保存按钮始终属于当前编辑范围。生成或轮换后显示一次性凭据，离开后不再在列表中展示全文。停用、轮换与删除先确认影响；启用可直接完成。固定 Key 替换时明确旧值立即失效。

模型目录提供名称 / 来源 / 类型筛选，保留模型的来源身份；调用名称与上游 ID 分开。已接入模型和聚合可以复制调用名称；仅上游目录模型显示启用提示和配置入口，不提供会被误解为已可调用的快捷操作。不展示虚构的延迟、成功率或在线状态。

手机默认收起调用示例，优先展示地址与 Key；目录改为可读列表，详情全屏。内部滚动、44px 触摸命中、返回位置、校验后保留输入与固定底部保存操作沿用现有规范。

## User Stories

- 我能直接复制 Base URL，选一个已接入模型，取得与当前选择一致的请求示例。
- 我能为每个调用方创建独立 Key，核对一次性明文，并在以后单独改名、停用或轮换。
- 我能按需设置唯一固定 Key，清楚知道替换影响，不会把上游 API Key 填到这里。
- 我能搜索模型并确认来源、调用名称和能力；未启用模型会引导我先配置来源。
- 我能在手机上输入、返回和继续草稿，校验失败时不会丢掉内容。

## Technical Design

本稿源文件在 `gateway-prototype/`，执行 `node docs/design/20261114-model-orchestration/gateway-prototype/build.mjs` 生成自包含 HTML。直接使用现有 `useLayout()`、`icons.tsx`，构建时提取 `index.css` 与 `theme.tsx` 令牌，没有网络字体、外部运行时或新设计色阶。

依照静态 HTML 的双语要求，演示文案集中在 `gateway-copy.ts`，支持简体中文与英文；这是独立离线交互稿的文案表，正式实现必须迁入产品统一 i18n，不能复制一份页面私有语言系统。主题与语言工具仅供设计评审。

建议正式落地职责如下；不新增接口规范或改变现有 API：

| 模块 | 职责 |
| --- | --- |
| `ModelGatewayWorkspace.tsx` | 页签、真实地址、接入摘要、示例与全屏手机详情壳 |
| `GatewayAccessKeys.tsx` | 调用 Key 列表、行尾动作、一次性明文和独立命名草稿 |
| `GatewayAccessKey.tsx` | 固定 Key 当前状态与保存 / 替换 / 停用，不改独立 revision |
| `GatewayModelDirectory.tsx` | 真实目录筛选、调用身份、来源详情和启用状态 |

Key 生成、轮换、固定值更新继续使用现有 revision 校验；失败保留输入，冲突按现有恢复入口处理。调用示例和模型选项使用当前已接入目录；不把上游发现目录当作可调用集合。目录详情关闭后保留筛选，编辑区关闭后释放宽度；草稿分别归属于新建、改名和固定 Key，避免互相覆盖。
