一个地方接模型、组调用、查一次请求

模型工作台是能力页里的一组页面，给在本机节点上接供应商、把多个模型组成一个稳定调用名、再排查调用结果的人用。桌面和手机走同一套页面，手机把详情做成全屏子页。

  1. 1 接入连接供应商或插件账号，只启用要用的模型。
  2. 2 发布把启用的模型组成聚合，得到一个稳定调用名。
  3. 3 使用会话、委派和外部程序都用这个调用名。
  4. 4 排查一次请求的终态、尝试和费用在同一条记录里。

页面

  • 模型源连接供应商，发现模型，决定启用哪些。入口就是现有的「模型源」页。
  • 插件与账号安装社区插件、给供应商建账号并授权。从模型源的「插件」入口进入。
  • 聚合选成员、定顺位和策略，发布成一个调用名，并看到它实际怎么被调用。
  • 本机网关看当前可调用的模型，复制调用名和接入示例，管理访问密钥。
  • 用量按日期看消耗和费用，按来源、模型、智能体下钻，设置每日限额。
  • 监控看请求趋势、失败原因和来源健康。
  • 审计分页查看请求，展开尝试时间线和费用。
  • 选模新建会话和委派时选 Auto、固定模型或仅免费，并看到实际命中了谁。
  • 语音选转写服务，录一段确认能识别。和聊天模型的能力无关。

本轮实现与验收

页面正式入口和本轮改动
模型源新建连接可单独保存，之后再发现和启用模型。
插件与账号社区目录管理搜索、版本和下载源。授权后，账号页按已加载插件声明展示额度和签到。
聚合调度中的首选、备选和运行统计并排展示，手机按顺位查看。成员管理和草稿编辑继续沿用原入口。
网关列表显示模型名。详情和复制动作提供调用名。同一目录供 CLI 查询。
用量每日限额独立成组件。账本未加载或仍有未确认费用时，余额显示待确认。
监控按时间桶和失败原因筛选请求。网关每日限额与上游限额分开统计。
审计区分实际命中和最后尝试。时间线按尝试关联费用账本并保留原币种。
选模会话与原生委派共用选模。模型路由、费用筛选和预计恢复时间由网关处理。
语音保存配置后可试录，复用会话录音与转写链路，识别结果留在设置页。

隔离实例实测 429 后切换成功和上游 401。桌面四档及安卓真机核对监控筛选、审计返回、聚合顺位及网关入口。试录转写、会话与委派选模使用自动化测试验证。

逐次费用使用服务端生成的请求关联，老账本缺少归属凭据时显示不可关联。网关在能确定免费额度恢复时间时返回 Retry-After。签到由插件处理，成功后刷新当前账号额度。

隔离实例在桌面四档和安卓真机验证插件账号页。测试账号签到后积分从 30 增至 35，仅声明额度的账号只展示额度。回归测试覆盖逐次费用归属和网关恢复提示。查看验收截图。

这版定下来的事

导航保持现状
能力页顶部和模型区左侧的页签不动。本设计只重做各页内部。
监控和审计各自成页
在监控选定时段和结果后直接打开审计。审计按页查看单次请求，返回恢复筛选和选中的记录。
名字和调用名分开
列表一律用展示名。调用名只在网关、接入示例和选模时出现，并且可以复制。重命名保留旧调用名作为别名。
状态只写查得到的
可用、冷却、未检测、价格未知各自成文案。检测没跑过不显示成失败，价格没配不显示成 0。
一次请求一条记录
发出前被拒、候选试完仍失败、中途切换后成功、已输出内容后中断，是四种不同终态。前两种现在都返回同一个 503，记录里要能分开。
草稿和生效分开
聚合改了没保存时，运行中的请求继续用已生效的顺位。页面上两套顺位同时可见。

不变的约束

目录只收录已启用的模型
供应商发现出来但没启用的模型不进网关、不进选模。移除一个模型不连带删除引用它的聚合，而是把该成员标成失效并给处理入口。
配额在网关
准入、切换和记账由 Go 网关决定。智能体运行时只记录用量和传递网关的结论，不另设限额。
密钥分两种
供应商凭据只供网关访问上游。发给外部程序的是网关访问密钥，它不能读配置和审计。
视觉沿用现有规范
颜色、字号、圆角、间距用 docs/development/ui-design-system.md 的令牌。页面底色 --bg-base，相邻区域靠一条分隔线而不是套卡片。
