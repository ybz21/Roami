失败与降级

情况客户端看到的结果
发送前，无可调度成员保留 503 和 MODEL_ROUTE_NO_AVAILABLE_MEMBER。当最早恢复时间可确认时才给 Retry-After。聚合成员数和费用判断留给控制接口上的审计记录。
尝试后，候选耗尽保持现有 503 MODEL_ROUTE_NO_AVAILABLE_MEMBER。控制接口显示尝试次数、各自错误和终止原因，按有尝试的最终失败统计。
网关每日限额保留 402 MODEL_PROXY_DAILY_LIMIT。上游额度耗尽在尝试详情里单列。两者分别指向限额与来源。
可切换失败网关根据策略和发送证据决定换成员。客户端只收到最终响应，审计含所有尝试。记下「切换后恢复」或「切换后仍失败」。同渠道重试单独计数。
已提交响应或带状态续接输出已经开始后保留协议原有中断语义，审计标记「输出中断」，即使 HTTP 已返回 200。带供应商续接状态时只走可证明兼容的通道。请求取消和执行结果未知单独呈现。

请求是否允许降级由网关策略与请求约束共同决定。候选必须满足协议、能力和显式费用约束。切换不能绕过预算、扩大授权、重放可能已执行的请求或跨供应商续接。JSON 错误保留现有稳定错误码，协议客户端的 SSE 事件形状保持兼容。

控制接口

读取配置、应用变更、诊断请求

控制接口沿用 Roami 已登录的节点代理 /api/agent/model-gateway，节点侧对应私有 Unix socket 上的 /v1/model-gateway。调用端口只保留推理与发现。来源密钥、路由策略和详细观测由节点控制接口处理。

职责接口及动作
模型与配置沿用 GET /models 和 GET /catalog，通过 PUT /catalog 带当前 revision 保存配置。沿用 POST /catalog/discover 显式发现。编辑先核对引用、成员能力和顺位，发布后新请求用新版本，已开始的请求保留原配置版本。
策略与预算沿用 GET /catalog/routing?model=free 看当前顺位和状态，沿用 /settings/sources/{source} 设置来源定价与账户调度，/settings?scope=limits 调整限额。提交冲突后重新读取现有配置，保留草稿供操作者处理。
策略预览（拟增）POST /catalog/routing/preview 接收聚合、当前 revision 与草稿策略，返回预览顺位、排除原因和数据时间。复用网关排序。预览不更新顺位状态、消耗渠道额度或写入调用统计。聚合观测样例
凭据沿用 /access-keys 创建、轮换、停用和删除。创建或轮换时显示新值一次，普通列表展示名称、权限状态与尾号。外部调用 Key 不授予目录配置和审计权限。
观测查询（拟增）GET /monitor?view=requests&routeId=free&caller=okr&outcome=failed&hours=6 读按请求聚合的统计和最近记录。支持时间窗、结果、错误阶段与分页游标。原 GET /monitor 保持按来源观测。GET /monitor/requests/{requestId} 读单次执行详情，零尝试也有结果。
验证和回退查看当前顺位只读，不占用模型推理额度。抽检明确标明会发出请求并沿用现有 POST /monitor/check。版本回退拟复用配置保存校验，以新 revision 写入所选旧配置。

请求记录与统计

  • 入口接受请求并识别模型后建立请求记录。保存请求号、规范模型、客户端类型、服务端可信归因、生效 revision、时间与最终结果。OKR 项目和会话来源仅以 Roami 宿主已验证的绑定为准。未绑定时仍可按实际客户端和模型定位。
  • 选路拒绝时保存失败阶段和已知拦截原因。上游尝试记录序号、来源、上游模型、HTTP 状态和网关错误分类。能确认的额度、冷却、协议或授权原因可在详情展示。记录原因分布和有界样本，超出时提示省略。
  • 同一请求号记录一次终态。更换成员后成功计为一次请求成功和一次切换恢复，来源统计保留失败尝试。预先跳过和同渠道重试分别记录。资格拦截且零尝试计为一次最终失败。输出中断计为失败，保留已送达状态和已知用量。计费继续依据各尝试的回执。
  • 最终失败率用失败数除以已确认终态的成功与失败之和。取消和结果未知单列。切换数按请求去重，其中发生过跨源切换的归入跨源，其余换过模型的归入同源。链路里仍可查看每一步。统计显示时间窗、样本量和覆盖状态。
  • 沿用最近 24 小时和有界存储。请求与尝试任一记录被回收时标记详情不完整。老数据继续展示已有来源统计，历史请求级数据无法关联时显示待积累。仅保存状态与关联字段，不记录提示词、响应正文、凭据或未清洗的上游错误文本。

代码与落地顺序

  1. catalog_http.go 负责请求生命周期与对外错误，先捕捉截图所示的零尝试 503。routing_choice.go 提供实际选择、跳过原因与切换决定，response_observation.go 延续尝试记录。
  2. MonitorStore 保存有界事件，monitor_http.go 负责按请求去重、过滤和详情查询。ModelMonitoringWorkspace 展示监控，审计读取同一关联号。网关目录与调用方绑定复用现有组件。
  3. 确认请求口径后接通 OKR 的可信归因与排查链接，再接入告警。连续拒绝以窗口内请求数与持续时间判定，切换成功按比例观察，恢复后自动消警。诊断支持限额、授权、冷却和版本变更几个常见场景。
