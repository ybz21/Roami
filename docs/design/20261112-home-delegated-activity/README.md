# 首页委派任务执行记录精简

## 产品设计

首页对话保留 Main 自身的调用过程、委派任务的主题与真实状态、最终结果和交付链接。委派智能体内部的工具调用不再生成单步提示或「执行过程」汇总卡；内部重试失败不再让首页出现与任务结果无关的失败提醒。

任务失败、状态未知、需要用户处理和 Main 回合失败仍按原状态展示。完整执行记录继续从任务详情展开。首页与项目 Main 共用聊天组件，因此采用相同的展示规则。

## 用户故事

- 提交委派后，看到提交调用、任务状态和交付结果，不被委派智能体的 bash 等内部动作打断。
- Main 自己执行的调用仍可展开查看输入和输出。
- 任务确实失败时能看到失败状态，并进入详情查看执行记录。
- 刷新、实时更新和手机访问采用同一规则。

## 技术设计

`agent-timeline.ts` 仅在聊天投影中排除带 `taskId` 或 `parentTaskId` 的 `kind=tool` 活动，沿用交付工具的过滤规则。任务归属由运行时提供，不依据工具名称、时间或执行成功与否猜测。`kind=task` 和 `kind=turn` 保留。

不修改活动快照、SSE 投影、缓存或记录接口。`AgentTaskRecord.TaskProcess` 继续读取原始任务活动，`AgentActivity record` 保留完整记录。没有新增请求、轮询、设计值或用户文案。

## 页面排版优化

### 产品设计与用户故事

首页回复直接呈现正文，用户提问继续使用气泡区分。复制使用带可访问名称的图标，与时间、记忆动作排成一行。过程区通过细线和紧凑间距区分，任务整行可点开详情，状态仍有明确文字。

- 手机上空输入框仅占一行，输入多行时自动展开，给结果留出更多高度。
- 点任务主题或状态所在的行即可进入详情，不必瞄准行尾箭头。
- 键盘打开后继续输入和换行，发送仍由明确的按钮触发。
- 使用深浅主题、宽屏、窄屏或长结果时，阅读和输入保持可达。

### 技术设计

`ChatMessage` 将正文样式收至 `conversation.css`，仅 `side=native` 使用无框排版和图标复制；其他专业会话保留原有气泡与复制文案。`ConversationComposer.minRows` 默认保持两行，由 Main 对话在手机指定一行；首页输入卡按现有规范使用顶部 12、水平 16 的令牌内距和紧凑控制条。

`AgentTaskActivity` 使用单个原生 button 包含主题、状态与箭头，保留原有任务 ID 和可访问名称，避免嵌套按钮。状态样式和过程区间距全部复用既有令牌；任务真实状态、委派过滤、草稿、缓存和请求不变。

### 排版验收

- 全量前端 233 文件、1713 项通过，typecheck、i18n、hover、build 通过。任务主题点击回归确认只打开一次对应任务。

- ADB 实际点按 Main 调用和任务主题可展开或导航；复制与记忆按钮携带可访问名称，两按钮及中间间隙的逐列命中检查通过。
