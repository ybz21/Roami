## 指标确认与来源接入修订（2026-10-31）

新流程先分析并确认衡量指标，再询问来源或由智能体查找。原型展示抖音/视频号后台、已有接口和文件导入三种方式，并模拟需要登录、读取失败、字段不全与成功取样。只有核对账号、日期、字段与口径后才绑定；正常已授权来源可自动校验，示例中的确认按钮用于展示首次接入。真实平台尚未接入，未登录或读取任何用户账号。

创建时只导入已经核对的样本，不补造历史。无来源可以先生成待接入看板，再从“指标来源”继续。数据字段只覆盖已确认指标；更换账号隔离新旧曲线并保留历史作用域。净增需要有效周期起点；只读到当前总量不能反推过去基线。

桌面修订验证：一 KR 对应多指标、指标确认先于来源发现、登录后重新取样、只取选定字段、样本基线与目标推导、仅采集必需日字段、读取失败的待接入看板、之后接入与部分字段缺失均通过。新版手机验证与范围见 HTML 中的交付与验证。

新版 Android 真机：ADB 点通六步、示例账号输入、登录后重取样、确认绑定与生成、绑定后按日填报、查看来源及取消；键盘 314px，真实滚动 120 到 513.8，392 CSS px / DPR 2.75 / compact-coarse，无横向或文档滚动，底部四入口可达。取样、登录和绑定均为隔离原型演示，不是实际第三方接入验收。

新版面板与指标来源页在 320、392、768、1024、1440 宽度检查通过；320px 的操作组溢出已修复。四个 HTML、93 处本地链接与锚点、14 个一手调研链接的结构检查通过，原型类型与构建通过。

## 按四条故事线顺序重写（2026-10-31）

交互设计书改为从目标的前期讨论开始，两个场景共用四条连续故事线：**聊 OKR、拆 KR 与关键看板、把看板建起来、智能体运转与人的决策**。短视频 19 幕、repo 15 幕，不再以最终数据开场倒叙。前两幕只出现 O 与约束，确认后才展示 KR；第三条有明确的看板生成/保存和更新约定。

第四条拆开项目关联、主责派发、产物验收回填、观测事件回填、独立复盘和下一轮执行。每幕显示主责、执行、数据、复盘的当前状态和接棒条件。`sceneSnapshot()` 按 assigned/delivered/observed/reviewed/next 重建当时状态，交付时不提前出现未来业务数据或复盘；第二轮继续沿用有效 Review 的具体任务。

人可在决策幕继续验证或暂停后续执行，暂停保留目标与数据，恢复后继续。控制仅影响本地回放；不会停止任何真实任务。章节导航在页首持续展示四条线；主动模式从第一条首幕开始，历史自定义输入通过场景 ID 迁移保留。

四线修订验收：契约检查确认两个场景均从 intent 开始，四线严格按序，前三线没有执行事件、复盘或未来观测；交付快照、观测快照、复盘快照分别推进。桌面走通短视频 19 幕和 repo 15 幕，确认 O 在 KR 前、KR 动态修改、看板显式生成、交付事件先于业务数据、第二轮任务继承 Review、继续/暂停/恢复和旧草稿迁移。故事/主动两模式在 320/392/768/1024/1440 均无横向溢出。
