# 页面工作区状态保留

## 产品设计

所有主导航页面在切换后恢复操作状态。文件、浏览器、手机、设置、项目、能力等页面之间切换，或临时进入会话，再返回时恢复各自的选中项、输入、展开状态和滚动。文件页恢复目录、标签顺序、当前标签和分栏。保留隐藏文件、排序、搜索、路径输入，以及未保存的编辑和源码 / 预览选择。手机沿用同一份目录记忆，文件详情仍使用全屏二级页。

页面实例仅属于当前节点；切换节点会释放旧节点实例，避免全局节点地址变化后旧页面误读另一节点的数据。文件页另外按节点保存当前浏览器内的快照。刷新页面、退出登录后清空。文件栏宽度、分栏比例和预览滚动继续使用现有记忆机制。此变更不增加界面控件、文案或新的磁盘持久化。

## 用户故事

- 打开日志与两个 HTML 文件，切到浏览器再返回，文件标签和选中项仍在。
- 浏览器选中某个标签并切到手动模式，去文件页，再回来保持标签、模式和未提交的地址。
- 设置页或项目页输入尚未提交的内容，切到其他入口再返回继续填写。
- 编辑文件但尚未保存，去设置页查看配置，返回后继续编辑。
- 浏览子目录后切到其他页面，回来仍停在该目录，并能后退、前进。
- 切换节点时各自恢复自己的文件目录和标签；关闭的标签不再恢复。

## 技术设计

当前实现采用 [统一工作区状态架构](architecture.md)：`AppShell` 持有一个 `WorkspaceStateStore`，页面与资源使用 `ViewStateProvider` / `ViewBoundary` 及统一 Hooks 接入。文件、浏览器、手机、文件位置和旧表单草稿共用同一仓库，按节点、页面、资源隔离；不存在独立的文件页 Map 或浏览器页 Map。

`definePage` 声明页面生命周期，新增页面默认隐藏后卸载。已有复杂表单显式保留控制器，活动范围仍负责暂停后台任务。状态分为视图、受保护草稿和有界可重建缓存；资源实例不进入仓库。
