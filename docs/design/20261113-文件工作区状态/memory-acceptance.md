# 页面状态与内存验收

2026-11-13。对照基线为初次状态保留实现 `148694f9`，优化版本为同一任务分支的本次修改。原始测量和行为断言见 [memory-acceptance.json](memory-acceptance.json)。没有新增产品文案。

## 测量方法

- 两端均执行生产构建，使用相同的已安装 Roami 后端；通过 `scripts/dev/isolated-roami.sh` 创建独立后端 / tmux 根目录，分别服务修改前后的静态资源。
- 私有镜像 Chrome 与验收 Chrome 使用不同端口和 profile（19482 / 19483），不接入用户的 Chrome 标签。每端新建浏览器上下文，1920 × 1080，使用相同的目录、30 个各 491,520 字节的确定性随机日志、两个静态镜像标签。
- 先打开一个文件，预热同一份 Monaco，再依次打开其余 29 个。切到浏览器、设置，随后重复“文件 → 浏览器 → 设置”20 轮。每个采样等待 1.5 秒，执行两次 `HeapProfiler.collectGarbage`，以 `Performance.getMetrics` 和 `Memory.getDOMCounters` 读取 V8 堆、DOM 和监听器。
- 运行脚本、构建、日志、原始 JSON 和截图保留在 `/tmp/roami-page-memory-20261113/`。行为脚本及测试文件在其 `functional/` 子目录。

## 生产版结果

| 时点 | 初版 JavaScript 堆 | 优化后 JavaScript 堆 |
| --- | ---: | ---: |
| 预热一个文件 | 31.0 MiB | 31.3 MiB |
| 30 个文件，文件页在前台 | 49.4 MiB | 36.8 MiB |
| 文件、浏览器均切到后台 | 49.4 MiB | 28.1 MiB |
| 重复切换 20 轮后 | 51.3 MiB | 29.6 MiB |

20 轮后堆降低约 42.4%；DOM 节点由 3,049 降为 826。优化后第 1、20 轮事件监听器均为 952 个（第 19 轮有一次 954 的采样），隐藏文件页的子节点数为 0。基线文件页仍有内容树。

这不是零增长承诺：优化后首次隐藏至第 20 轮有约 1.5 MiB 的堆变化，最后 5 轮增加约 0.3 MiB；DOM 计数每轮仍有少量增加。当前样本不证明无限次切换完全稳定。此处只报告 V8 堆和 DOM，不把请求减少推断为 CPU 降低，也不将堆等同于整个 Chrome RSS、GPU 或后端内存。后续如需长时间运行预算，应另做更长时间的堆快照 / 原生分配采样。
