# 聚合策略与运行效果原型

## 产品设计

聚合列表使用可选卡片，显示名称、调用 ID、启停状态、策略、成员数与核心效果。选中聚合后使用完整工作区，保留同级导航。默认标签为“运行效果”，另有“调度策略”和“成员”。

- 运行效果：近 1 小时、6 小时、24 小时的请求数、成功率、首字耗时、输出速度、费用和质量通过率。趋势可按源、模型分组，切换请求、输出 Token、首字耗时或成功率。次数 / Token 为堆叠量，耗时 / 成功率为各成员独立指标，不能相加。
- 调用分布：来源的占比与实际调用数量，提示失败接管会使实际分布偏离配置权重。
- 最近调度：实际渠道、选择原因和备用接管；打开详情查看条件过滤、候选排序、限流休息与回答成功的路径。请求详情保持源、模型、时间、用量与费用一致。
- 调度策略：保留 smart、order、drain、rotate、usage、pace、weight、fast、cheap 九种已确认策略。卡片说明目标，选中后展示详细规则。先选源再选模型；只有权重策略突出权重，顺序相关策略提供排序操作。
- 调度试算：独立于运行效果，展示当前示例状态下的预计选择、原因和接下来 10 轮的成员分配；可模拟首选限流与恢复。不会发起模型调用，未保存的策略不能被当成线上生效策略。
- 成员：分开显示可用、休息、额度耗尽和价格未确认。WorkBuddy 示例保留 10 个独立账号，可打开账号列表比较额度及重置 / 到期时间。嵌套聚合按一个组成员展示，组内使用自己的账号策略。

免费聚合只允许已确认的免费模型，订阅额度需明确勾选；未知价格不当作免费，未知余额不当作无限额度。少量或无质量样本显示未知。所有页面和试算时间由浏览器自动获取本地时区，不写死北京时间。

## 用户故事

1. 看这个聚合是否有效：多少请求、是否更稳定、哪个源承担了流量，是否全部免费。
2. 知道一次调用为什么去了这个源：查看真实选择理由与失败后的备用接管。
3. 修改策略前能比较：切换九种策略、编辑权重或顺序、模拟限流，看到选择变化再保存。
4. 多账号可以解释：查看同一 WorkBuddy 源的 10 个独立账号，而非把一个源误认为一个账号。
5. 手机上完成同样的动作：切换标签、选择策略、试算、打开全屏账号 / 请求详情，使用一层返回栏。

## 技术设计

原型为独立 HTML，使用项目令牌与 `frontend/src/icons.tsx` 导出的 SVG，内置中英文文案和深浅主题。不访问业务 API、不调用真实模型、不保存线上配置。代码之外的演示数字仅用于设计评审，页面持续标记“演示数据”。

正式实现复用 `ModelAggregationWorkspace`、`RoutingStatus`、`useRoutingStatus` 及现有网关监控 / 审计。聚合 ID、策略版本和实际路由结果必须可关联；现有状态接口尚不提供完整的效果指标和决策轨迹，不能在前端把预测当作真实执行。缺失观测须按真实记录补充，未知和失败需如实展示。本轮不定义接口规范，不修改正式前后端。

运行效果沿用监控的 24 小时滚动保留与容量上限，详情按既有审计保留策略读取，不引入无限历史或额外永久轮询。新版正式页面遵守当前 `ViewBoundary` / workspace store 的导航状态和资源生命周期规则，编辑草稿与运行资源分开管理。
