# 正式接入：源定价、聚合路由与模型监控

本轮按「实现」要求接入产品代码，接口命名规范仍未调整。原型在 `prototype.html`，既有概况 / 审计实现见 `implementation.md`。

## 产品设计与用户故事

- 在模型源内设置默认定价、模型覆盖、明确免费 / 套餐 / 未知策略，以及可选价格倍率与时段规则。账号路由独立选择，默认 smart。
- 在「聚合」先选源、再选该源模型，添加跨源候选或已发布的路由组；排序、权重、启停和切换条件均保存至网关。默认 smart，免费聚合没有合格渠道就停止，不回退付费。
- 智能体的模型设置将「路由组」作为独立来源，直接选择已发布聚合 ID，避免把聚合误认成首个模型源。
- 在「监控」按源、模型和最近 1 / 6 / 24 小时比较可用率、首字 P95、输出速度 P50 与质量抽检。质量只来自实际抽检，不以延迟推算。
- 手动抽检固定问答、JSON 和工具调用，经过现有 Go 准入并正常记账；不执行模型返回的工具，不保存完整提示词或响应。
- 桌面详情打开侧栏，关闭释放宽度；手机用一个返回栏的全屏二级页。隐藏页面停止轮询，失败退避。

## 技术设计

### Go 网关

`source_pricing.go` 扩展源默认及模型规则。明确免费需要确认；普通 0 元单价不能取得免费资格。源策略独立局部保存，全局设置的旧调用不会清空源策略。调用仍冻结请求时单价；已有对外模型显式单价保持优先，源策略随后生效。

`routing_model.go` 校验九种策略、1–1000 权重、成员数量、嵌套组循环及深度。旧 fixed / failover 配置保持兼容。策略、源及账号缓存都有数量上限。

`routing_choice.go`、`routing_state.go`、`provider_routing.go` 实现账号 / Key 展开、组作为一个成员、持久 drain 游标、轮次、平滑权重、速度探测及动态价格排序。权重先分给模型，模型内按源自己的账号策略选择。drain 游标存入 schema v7，删除模型时一并清理。

`routing_quota.go` 通过现有插件宿主读取额度，保留周 / 5 小时窗口、月度重置与积分批次到期信息。读取合并并发、限制并发数、缓存一分钟；超过两分钟、余额未知、查询失败或过期快照不能取得套餐免费资格。重置和积分到期会提前使缓存失效，已耗尽的短窗口仍能阻止周额度继续使用。

`modelplugins/manager.go` 保留模型免费、单价、工具与账号元数据，并让 Fetch 指向选中的账号；`modelplugins/quota.go` 封装宿主已有用量查询。Python 没有新增额度准入逻辑。

`catalog_http.go` 在发送前选择渠道，明确 HTTP 拒绝或未发送的连接失败可切换；每次尝试独立结算，并尊重更长的 Retry-After。已经向调用方输出后不自动重放。流式速度来自实际首个内容增量和输出 Token，权重偏向新测量；速度状态不从磁盘恢复。

### 监控存储与采集

`monitor_store.go` 使用独立固定大小环形文件，而非账本或 WAL：10,000 个 4,096 字节槽，共 **40,960,000 字节（39.0625 MiB）**，低于 64 MiB 总预算。不会因为不断删除 / 插入而扩大文件。

每次写入 / 读取清理 24 小时边界，独立维护每分钟清理并同步文件，不依赖浏览器在线。达到条数上限覆盖最旧槽，校验过的 JSON + CRC 检测部分写入；重启扫描恢复有效记录，过期或损坏记录不参与统计。单条过大直接丢弃并计数。文件权限 0600，不生成临时备份或 WAL，不影响审计账本。

`response_observation.go` 只用有上限的内存缓冲观测实际输出，区分心跳和首字，采集延迟与输出速度。正常请求的质量为未检测；`monitor_probe.go` 通过已配置源执行固定题、JSON / 工具规则，只保存指标和判定。探测受到网关现有额度与取消机制约束。

### 前端模块

- `ModelAggregationWorkspace.tsx` / `model-routing-api.ts`：聚合配置、可用渠道和保存后的真实状态。
- `SourcePricingSettings.tsx`：源内定价、覆盖、账号策略与倍率。
- `ModelMonitoringWorkspace.tsx` / `model-monitor-api.ts`：筛选、趋势、源对比、详情及手动质量抽检。
- `ModelHub.tsx` / `GatewayModelBinding.tsx`：同级聚合、监控入口和智能体聚合绑定。
- `model-routing.css` / `model-monitoring.css`：现有令牌、平面工作区、独立滚动及手机触控目标。

## 验证

有针对性的 Go 测试覆盖九种排序、额度 / 到期、持久与临时切换、组循环、提供方账号轮流、权重跨账号去重、免费记账、流式中断不重放、Retry-After、实际抽检、并发环形写入、24 小时清理、容量与损坏恢复。

前端交互测试覆盖先源后模型、跨源候选、草稿保留、默认 smart、实际抽检触发以及智能体组入口。完整前端与 Go 质量门、桌面 / 安卓真机验收均已通过。

桌面端到端已使用隔离实例及两个本地假上游，验证真实网关 8 个请求按 3:1 分配，付费 0 元源被排除，以及六次实际探测和页面内 JSON 抽检。没有对用户真实模型源发验收请求。
