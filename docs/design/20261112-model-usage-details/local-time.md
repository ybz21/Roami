# 用量本地时间修正

## 产品设计

概况和审计使用设备 IANA 时区。日期范围、今天、按小时曲线、时间段跳转及请求详情保持同一时区，跨午夜时也一致。监控现有的设备本地时间格式保持一致。

额度的“今日费用”和每日限额使用原结算时区，在额度区说明该时区。已归档记录只剩日汇总，不能恢复跨时区的小时归属；仍保留结算日期，查询含归档数据且时区不同时显示一句提示。

## 用户故事

- 北京时间刚过午夜时，今天应显示新日期，UTC 前一天 16 点的请求出现在今天 0 点。
- 点击某小时查看审计时，看到的请求时间应落在这个本地小时内。
- 不同设备时区可以查看自己的本地时间，额度和历史费用不会因查看时区发生变化。

## 技术设计

`model-usage-workspace-state.ts` 从 `Intl.DateTimeFormat().resolvedOptions().timeZone` 取得设备时区，附于概况及审计 GET 查询。`usage-workspace.go` 验证 IANA 时区，用本地午夜的毫秒边界筛选原始记录，返回显示时区和结算时区。

`usage-local-days.go` 根据原始记录实际涉及的日期建立查询内的本地日窗口，将明细按本地日重新汇总，不修改持久数据。夏令时按日历边界处理，重复小时包含两段记录；保留整数纳币金额。`Today` 仍读取原结算日且不受分析筛选影响。归档日表保留原日期，没有新增数据库表、迁移或常驻存储。

`ModelUsageWorkspace.tsx` 使用接口的显示时区格式化审计时间及详情，并说明结算和归档边界。
