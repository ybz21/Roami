## 产品设计

「能力 / 大模型」的用量部分分为两个同级 Tab：

- **概况**：用量、限额、汇总、趋势，以及按模型源 / 智能体 / 模型的分组统计。
- **审计**：逐条调用记录、条件筛选、搜索、分页和单次调用详情。

默认进入概况。概况内可以调整示例每日限额；今日额度覆盖全部调用，不随统计条件变化。未知费用存在时，剩余额度显示待核对。审计直接进入请求列表，不再套一层「概览 / 请求」导航，也不重复概况的限额与汇总模块。点击概况中的分组或趋势进入审计并携带筛选条件；两个 Tab 切换保留已有选择。

本版按用户对信息结构的纠正修订：[第一版结构记录](revisions/v1.md)。

| 区域 | 内容与行为 |
| --- | --- |
| 统计周期 | 今天、近 7 天、近 30 天、自定义起止日期；示例时钟固定为 2026-11-12 18:08（Asia/Shanghai） |
| 全局筛选 | 模型源、智能体、模型、调用来源；筛选同时作用于总览、分组、趋势和请求 |
| 概况：今日额度 | 网关状态、今日已记账费用、每日费用上限和剩余额度；限额可在原型内调整，状态只保留在当前页面 |
| 概况：摘要 | 已知总 Token、请求数、已知记账费用、缓存读取占已知输入的比例 |
| 用量趋势 | 按天查看总 Token、输入、输出、缓存读取、请求数或记账费用；点击柱形进入当天请求 |
| 用量分布 | 按模型源、智能体或模型分组；可按 Token、请求数和费用等列排序；占比跟随展示指标 |
| 审计 | 继承全局筛选，可按状态或模型 / 请求 ID 查找；多页才显示分页 |
| 单次请求 | 桌面右侧面板，手机全屏二级页；呈现身份、状态、回执和价格快照；返回保留列表位置 |
| 历史归档 | 依照现有 48 小时保留规则，较早请求只显示聚合；选择已归档日期时说明原因 |

「模型源」指实际处理调用的连接，如 WorkBuddy、OpenAI；「调用来源」指对话、任务、RSI 等业务入口。两个维度单独命名，避免把原接口的 `source=rsi` 当成供应商源。智能体先按现有类型 Roami、Codex、Claude Code、OpenCode、Pi 展示；未知归属单列，不凭模型名推测。

总 Token = 输入 + 输出；缓存读取是输入的子集，不能再相加。未知用量 / 费用单独标记，汇总标示「已知」，不把未知记成 0。费用按本地价格快照记账，不能叠加云端账单或供应商积分；原型仅展示 USD 示例。正式版多币种须分币种展示，不直接相加。

桌面沿用能力中心的主分类与左侧模型 Tab。内容铺满剩余空间，只有可选详情面板开启时占用宽度；主内容独立滚动。手机使用顶部栏、同级 Tab 与四入口底栏，筛选按需展开，汇总表改为列表。上下文中的其他能力分类和底部目的地仅用于展示壳层，不模拟完整产品导航。

## 用户故事

1. 我想同时掌握用量和限额：进入「概况」，先查看今日额度，再按周期浏览汇总；在原型内调整限额后切换 Tab，选择仍保留。
2. 我想知道最近一周哪个模型源消耗最多：选择「近 7 天 / 按模型源 / 总 Token」，按降序看占比，进入「审计」查看该源请求。
3. 我想比较智能体的消耗：切到「按智能体」，在总 Token、输入 / 输出、请求数和费用之间切换，筛选某一模型进一步查看。
4. 我想解释某笔请求为什么贵：打开请求详情，核对输入、输出、缓存读取及请求时单价；缓存只按缓存价计费。
5. 我想排查未确认费用：进入「审计」，筛选「待核对」；缺失字段显示未知，不把请求当成免费。
6. 我在手机上查看：展开筛选、触摸打开请求详情，再返回时保留筛选与滚动位置；只保留一个可见返回栏。
7. 我想查旧记录：30 天统计继续显示累计用量，早于保留期的请求显示归档提示，不伪造逐条回执。

## 技术设计

### 产品接入架构

| 模块 | 后续实现方向 |
| --- | --- |
| `frontend/src/components/capabilities/ModelHub.tsx` | 现有 `usage` 对应「概况」，含用量、限额和汇总；新增同级 `audit` 对应「审计」，建议路由 `capabilities/models/audit`；旧链接继续兼容概况 |
| `frontend/src/components/settings/gateway-settings.tsx` | 限额表单与汇总保留在概况；逐条记录与详情归入审计，对账动作复用现有网关流程 |
| `frontend/src/components/settings/model-usage-statistics.tsx` | 复用汇总口径与已知 / 未知状态，拆分筛选、趋势、分组列表和请求详情；避免从最近 20 条请求推算统计 |
| `internal/modelgateway/ledger.go` | 已有 `agentKind`、`sourceId`、`routeId`、`role` 和请求时价格快照，作为归属基础 |
| `internal/modelgateway/statistics.go` | 旧查询兼容保留；新增 `view=overview / audit` 查询分支，支持独立 `sourceId` / `unattributed`、智能体、模型、日期、状态、分页和搜索 |
| `internal/modelgateway/daily_retention.go` | 单次回执默认保留 48 小时；schema v6 日汇总主键加入 `source_id`，新记录归档保持源归属；既有归档回填空 ID，明确显示未归属 |

产品已接入自定义日期、模型 / 模型源聚合、服务端分页和搜索，审计回执携带请求时单价与完成时间。调用来源仍按现有可靠的 RSI / other 分类展示；对话 / 任务没有稳定映射，因此没有把原型里的四分类硬接为错误数据。正式版费用按币种分别展示，不相加折算。

归属优先使用记录中的稳定 ID，名称从目录映射；源被删除或旧记录未归属时保留未知组。列表中的失败与费用结算状态正式接入时必须分别映射真实证据。未知费用不能仅凭失败状态归零。

统计读取复用网关数据入口，避免每个分组自行轮询；切换条件取消过时请求，隐藏时暂停，错误退避，筛选切换保留用户输入。额度的准入与拦截仍由 Go 网关负责。

### 原型文件

- `prototype.html`：内联脚本、样式和数据的独立原型；无需网络依赖，可直接用浏览器打开。
- `assets/prototype.tsx`：示例数据与交互，直接复用项目 `useLayout()`、图标集及 `BackButton`。
- `assets/prototype.css`：布局样式，颜色、字号、间距与圆角均引用现有令牌。
- `assets/build.mjs`：打包入口，从 `index.css` / `theme.tsx` 读取基础与深浅色令牌；编译时仅替换偏好持久化适配，确保原型不会写入真实配置。

原型文案遵循静态 HTML 的最小语言表规则，含中英文并按浏览器语言选择；`I18nProvider` 和返回按钮复用项目实现，偏好写入在打包时替换为空操作，语言只存本地。正式产品新增文案须迁入 `frontend/src/i18n/locales/`。

## 六个页面的完整设计

用户在确认概况 / 审计后，要求把大模型下每一页一起设计。静态原型已补齐以下页面；除已授权接入的概况 / 审计外，其余页面的新布局先供评审，产品现有操作继续保留。

| 页面 | 产品设计与用户故事 | 交互与模块 |
| --- | --- | --- |
| 模型与连接 | 我可以搜索连接、查看它提供的模型，添加或配置连接，并选择可用模型与调用策略 | 自适应连接卡片、凭证保存状态、连接编辑器、模型选择、手动模型添加、固定 / 故障切换。桌面编辑器只在打开时占用右侧宽度，手机用全屏编辑页 |
| 概况 | 我可以同时掌握今日额度、限额和周期汇总，按源 / 智能体 / 模型比较消耗 | 今日额度不随统计筛选变化，限额内联编辑；趋势和分组下钻进入同级审计 |
| 审计 | 我可以从聚合进入逐条调用，按状态 / 关键词筛选，再核对回执与价格 | 请求列表、分页、未知值、历史归档提示；桌面详情面板 / 手机全屏详情 |
| 价格与记账 | 我可以配置默认单价，并为个别模型指定独立单价或恢复默认 | 币种、每百万 Token 的普通输入 / 缓存 / 输出单价、模型覆盖价行内编辑；保存和未保存状态明确，历史账单保留快照 |
| 网关接入 | 我可以找到客户端接入地址，管理访问密钥并查看智能体接入关系 | 地址复制、命名密钥创建、启用 / 停用、仅展示尾号、智能体接入列表；原型不会创建真实凭证 |
| 语音模型 | 我可以配置独立的语音识别服务，选择语言并理解识别结果 | 关闭 / OpenAI 兼容 / 火山引擎选项，服务地址与模型、凭证保留、语言、保存状态；识别演示明确标注为示例，不发起真实识别 |

`assets/model-management.tsx` 承载四个补充页面的静态交互，复用原型令牌、图标、布局入口与语言状态。组件保持挂载，使切换概况、审计或其他管理页后仍保留草稿；只有当前页面拥有滚动容器。源凭证不会显示已保存明文，新填凭证仅在当前原型内临时存在；示例网关域名使用保留域 `.example`。

最新增补：聚合默认 smart，提供九种路由策略与模型权重；新增监控页按模型源对比，数据最多保留 24 小时，并设置条数和容量上限。本轮仍为静态原型，接口规范暂缓。详见 [路由策略与监控](routing-monitoring.md)。
