# 主对话调用链与委派验收

2026-10-18。源于用户在主对话里指定已有会话继续工作，收到“排队中”回复，但目标没有收到消息的问题。

## 定位结果

旧任务把 `kind=session`、`sessionId` 与所属项目的 `projectId` 一起传给执行器，发送前被拒绝为 `CODING_SESSION_TARGET_CONFLICT`。之后的失败回报又因 `CONTEXT_TOO_LARGE` 未能生成，用户只看到了先前的排队说明。入队、提交到会话、执行结束、验证通过是四种不同的事实。

## 实现

- 主对话消息流内展示调用链，连续的工具轮次合并为一个可折叠区块，默认只占一行；错误原因折叠时也保持可见。展示工具、执行器、目标、开始/更新时间和真实状态，已绑定的任务可打开会话。
- `tool.started` 与 `tool.completed` 事务提交后即进入 SSE；原生 Worker 的调用事件转发到发起对话。快照从持久化工具记录和任务尝试重建，刷新和断线恢复不会把失败变成成功。页面只展示有界元数据，不展示原始工具参数、凭据或整段输出。
- `session_send` 是 Main 的短工具，经统一 Go CLI `roami agent execution send-message --file -` 向精确目标发送。支持未接入任务回调的旧会话；回执只说明消息已提交，`executionTracked=false`。发送前落盘未知状态，同一个键重试读取原回执，部分发送或丢失回执都不能自动重放。
- 跟踪任务仍用 `delegate`。指定会话的 `projectId` 作为来源说明保留，路由使用精确 `sessionId`；目录、工作区、基准、远程覆盖仍会被拒绝，且在创建任务之前检查。
- 任务回报使用独立的无工具生成轮次，减少上下文占用。若模型或上下文仍然失败，写入一个结构化、可翻译的任务状态回执；该事实也进入后续 Main 上下文。保留失败的生成轮次用于审计。
- 回执和界面区分待发送、消息已提交、执行中、待核验、失败、结果未知。旧会话的完整执行完成回报需要生命周期回调；没有回调时可追加消息，但跟踪任务会明确拒绝。

## 对话端到端矩阵

使用独立 Roami 配置、数据库、项目目录和 tmux socket；Main 使用用户已配置服务中的 `deepseek-4.1-flash`，Codex 和 Claude Code 使用本机已配置的真实 CLI。输入为自然语言聊天请求，经过实际工具选路、Go CLI、tmux 和外部执行器。API Key 只从私有环境读取。

## 回归与设备验收

自动回归覆盖：工具完成前可见 running、Worker 调用向发起对话传播、回报上下文超限时仍有结构化回执、下一轮模型可读取失败事实、无效覆盖参数不入队、消息幂等与部分提交不重放。前端覆盖折叠错误可见、状态更新、打开精确会话与失败轮次停止忙碌指示。

桌面与 Android 使用同一隔离实例检查折叠/展开、SSE 更新、输入框、软键盘、导航和文档溢出。截图仅包含合成验收内容，发布到 PR 的 `pr-shots` 分支；报告不包含登录凭据和模型 Key。
