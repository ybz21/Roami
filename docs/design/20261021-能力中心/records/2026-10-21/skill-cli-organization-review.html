Skill 与 CLI 职责整理 · 2026-10-21

状态：已实施。两个内置 Skill、公开 CLI 命令族、受管适配与旧路径兼容已经落地；验收使用独立数据目录和 tmux 服务。

1. 评审发现

  • 浏览器职责交叉：roami-dispatch 的 description、决策说明和 references/chrome.md 覆盖网页操作；web-research 又维护检索流程。 WORKER_INSTRUCTIONS 同时重复浏览器操作名、参数和检索步骤，修改一处不能保证其他入口一致。
  • 委派示例漂移：两个 Skill 的入口及 Chrome 手册仍示例 delegate(executor="native", ...)， 但 tools/registry.py 的 Main 目录已经隐藏顶层 executor 并要求 routing；projects-sessions.md 则已使用新格式。
  • 事实过期：projects-sessions.md 声称未知 session 命令透传 tmux，internal/cli/app.go 已明确拒绝； capabilities.md 声称上传导入尚为预留，而 capability_imports.py 和能力页已实现。
  • 重命名涉及代码：research 角色在 tools/foundations.py、tools/registry.py、protocol/research.py 中只允许 web-research， 可用性检查、系统提示、前端翻译和测试也引用旧名。只移动目录会导致研究任务无法发现或读取 Skill。
  • CLI 目录暴露了内部操作：CapabilitySettings.view 的 cli 来自 ToolDirectory.groups，前端又用 flatMap 将组展开， 因而 browser_open / browser_observe / browser_act 各自成为一张卡片。它们实际复用同一个 roami chrome 驱动， 不应被展示或发现为三套独立 CLI。应以真实命令族组织目录，浏览器只保留 roami chrome 一个入口。

2. 产品设计

保留两个内置 Skill：roami 负责 Roami 基础使用，browser_use 负责浏览器使用。网页检索归入 browser_use， 原 web-research 不再作为第三个独立目录项。browser_use 沿用需求指定名称；当前内置加载器与托管名称校验均支持下划线。

入口负责内容边界
Skill：roami项目、会话、委派、后台进度、记忆、文件与节点操作；按需读取专题手册。 遇到浏览器任务只指向 browser_use；不再维护浏览器参数和操作步骤。
Skill：browser_use导航、观察、交互、网页检索、截图、录屏和交付；说明当前角色可走的执行路径。 使用 roami chrome 驱动；研究角色仍仅能导航和观察，不能因读取通用 Skill 获得交互或 Shell 权限。
CLI：roami chrome浏览器唯一命令族入口，关联 browser_use；子命令通过 roami chrome help 按需发现。 不再分别展示或向模型发现 browser_open / browser_observe / browser_act；权限、资源与回执由宿主适配层处理。
其他 CLI按真实可执行程序和命令族登记；外部 CLI 沿用注册的程序与参数。 逐项核对其与基础工具、roami Skill 的关系；内部函数名不直接当成独立 CLI 产品入口。
系统提示角色、路由、授权、真实状态与未知写结果处理等持续适用的约束，以及 Skill 入口。 移出重复命令表和任务流程；不可只靠可选 Skill 承载强制权限边界。

能力页保留 Skill / CLI 分类。Skill 展示 roami 与 browser_use；CLI 中浏览器只展示一张 roami chrome 卡片， 说明其用途并关联 browser_use。详情按需查看子命令；不把子命令平铺成独立能力卡片。 同步 Agent 的 tool_list 目录，让用户与模型看到相同的命令族组织，不能只在页面上把三个旧操作合成一张卡片。

3. 用户故事

  1. 查询项目或继续已有会话时，Agent 读取 roami 后即可找到相应流程，不加载浏览器手册。
  2. 浏览、检索或截图时，Agent 发现 browser_use；公开查询读取检索规范，交互任务读取操作规范，均使用既有 Chrome 驱动。
  3. 原生 Worker 与专业 Agent 均按 browser_use 使用 roami chrome 子命令；宿主按角色绑定任务资源与执行权限，不要求模型学习第二套 browser_* 命令。
  4. CLI 目录只看到 roami chrome 一个浏览器入口，通过 browser_use 学会用法，通过命令帮助了解参数，不在多张卡片间寻找同一浏览器能力。
  5. 旧对话读取旧 Skill 路径仍能到达对应规范；能力目录只展示两个正式 Skill。

4. 技术设计

roami 保留原基础专题并删除过期事实。将原 Chrome 手册迁入 browser_use，检索内容合并自 web-research； 入口只索引当前任务需要的参考文档。参数以注册 schema 和 roami chrome help 为准，参考文档保留必要示例和非显然约束，避免复制完整帮助。

Skill：browser_use → CLI：roami chrome <子命令>
原生任务：bash argv → 宿主命令解析与角色校验 → 任务资源适配 → 既有 Chrome 驱动
专业 Agent：终端 argv → roami chrome → 真实页面与本地文件
内部实现：按需复用 open / observe / act 处理函数，不作为独立 CLI 发布

这同时调整目录与模型调用入口。原生 bash 目前拒绝直接执行 roami chrome，因此实施时要增加命令族适配， 解析真实 argv 后复用受管处理逻辑；不是简单放开通用 Shell，也不是另造一个 browser_use 执行程序。 宿主继续执行 research 导航限制、task/run 绑定、资源租约、停止与未知结果对账。 子命令及 flags 以现有 roami chrome help 和驱动契约为准；不支持的操作明确拒绝，不能静默走不受管执行。

迁移范围与兼容

  1. 统一内置名称与旧名解析：roami-dispatch → roami，web-research → browser_use； 旧 roami-dispatch/references/chrome.md 单独映射到 browser_use/references/chrome-cli.md。 别名不注册成额外 Skill，目录和 tool_list 只展示正式名称；不重写历史执行记录。
  2. 在实际读取与权限校验前统一解析旧路径；research 仅允许 browser_use 及其参考文档，执行限制仍由 protocol/research.py 校验。 旧名与外部配置冲突时显式报错，不静默把用户 Skill 重定向到内置内容。
  3. 同步 tools/skills.py、foundations.py、registry.py、web_research.py、protocol/research.py 与 server/configuration.py 的名称、发现提示、可用性和兼容路径。 旧 web_research 兼容调用与正常目录的隐藏规则保持既有行为，不混同 Skill 重命名与接口删除。
  4. 分离内部操作注册表与公开 CLI 目录：为真实程序 / 命令族建立目录映射，浏览器仅输出 roami chrome，关联 browser_use； tools/foundations.py 的 list 与 groups、CapabilitySettings.view、前端目录共同采用这一粒度。 内部 browser_* 处理函数按需复用；旧调用若保留兼容，不再作为正常目录项展示。
  5. 为原生 bash 增加 roami chrome 命令族的受管适配，统一角色准入、task/run 绑定、观察与回执； 研究任务禁止交互的限制由代码执行。同步系统提示、Skill 与发现结果，模型只学习真实的 roami chrome 子命令。
  6. 逐项评审 artifact_read、executor_catalog、capability_overview 等条目：属于基础 read 的能力归基础工具， 属于 Roami 管理的操作按实际命令族归类；没有真实 CLI 对应的内部操作不冒充独立程序，也不凭名称臆造命令。
  7. 同步 CapabilityCatalog、AgentComposerPlus、中英文翻译和测试引用，更新 CLI 命令族详情与 Skill 关联，使用现有布局组件。

全部 CLI 条目复核 · 2026-10-21

结论：其余内置条目也应按职责收回，公开 CLI 默认保留 roami 与 roami chrome 两个入口，分别关联 roami、browser_use。 roami 详情按 project、session、agent 等真实子命令组织；chrome 为浏览器专用命令族。 用户注册的外部 CLI 独立保留。不是给每个内部函数再造一个新名字，也不是删除其业务能力。

现有条目建议归属源码核对与迁移条件
artifact_read基础 read，移出 CLI 目录。 foundations.resolve 已将 read 的 artifact:// 路径转给 artifact_read；保留分页、所有者与已遗忘来源检查。
capability_overviewtool_list 的目录摘要或宿主提供的运行状态，移出独立 CLI 条目。 普通 tool_list 已提供分类总数与当前角色范围，但 overview 还包含后台能力可用性；迁移需保留按角色区分的可用状态，不能直接删掉该信息。
executor_catalogroami 的 agent execution 专题。 真实命令 roami agent execution catalog 已存在。内部仍保留安装探测，不将安装状态当成登录、额度或能力证明。
workspace_overview、target_search、target_resolveroami 的项目 / 会话专题。 project ls/show/sessions 与 session ls/resolve 已存在；跨类型搜索、完整分页和汇总计数不全等价。 保留这些语义并补齐适配，不能改成数摘要卡片或只读第一页。
session_send、session_dispatch_statusroami 的会话投递与回报专题。 session send 与 agent reply 已存在，但普通 send 不等于带 dispatchId、回报通道的受管投递。 需保留原 Main 回报关联与状态查询；先保证命令族具备等价能力，再撤掉独立操作入口。
task_status、task_cancel、task_steerroami 的 Agent 任务专题。 agent steer 已存在；agent execution status/cancel 操作的是专业执行器 launch key，不能替代基于 taskId 的完整任务生命周期。 需补齐真实任务查询 / 取消命令，并保持 revision、停止证明与未知状态对账。
reminder_create、reminder_list、reminder_cancelroami 的 agent reminder 专题。 真实命令 roami agent reminder add/ls/cancel 已存在；宿主补入会话、稳定请求键及默认时区，保留 daily_brief 分支与真实投递状态。
memory_search、memory_getroami 的记忆专题。 当前没有专用记忆 CLI，只有受管 capability call。先实现对应真实子命令或等价命令族适配，保留用户范围、来源、分页与遗忘约束；方案中的归属不代表已有命令。
browser_open、browser_observe、browser_act一个 roami chrome CLI 入口，关联 browser_use。 复用 Chrome 驱动与受管处理，按前述方案统一原生 argv 路径、资源与角色限制。
computer_open、computer_observe、computer_act桌面资源操作，收回 CLI 分类。 当前是 Python DesktopDriver，未提供 roami computer 之类真实命令；保留按需发现和调用途径，完善资源类别后迁移，不虚构 CLI，也不并入浏览器。
mcp_discover、mcp_* 动态工具保持 MCP 分类，不在 CLI 中重复展示。 tool_list 已按 mcp_ 前缀分类，前端 CLI 也已过滤；迁移需继续支持发现、真实 schema 和按服务调用。
http_* 外部接口外部接口 / 工具，收回 CLI 分类。 worker_catalog 直接使用 httpx 请求配置端点，属于 HTTP 集成。保留连接配置、凭证注入、schema 与启停策略，完善按需发现分类后迁移。
cli_* 用户注册项继续作为外部 CLI。 capability_imports 注册真实程序与 argv；保留注册名称、工作目录、参数模板、启停和移除，不因归并内置操作而隐藏用户注册。

基础 file_read/file_write/file_patch/shell/skill_read 与旧 web_research 在正常 CLI 目录中已经被过滤，继续由 read/write/edit/bash 与 browser_use 承接，不新增重复项。 delegate、ask_user 保持基础工具；任务委派不能被退化成新建 tmux 会话。

迁移顺序：先明确公开目录与内部操作注册表的区别，再补齐缺失的真实子命令和受管适配，随后同步 tool_list、能力页与 Skill。 对暂不具备等价入口的任务、记忆和桌面能力，先保留可达路径再迁移；验收必须覆盖功能可达性与原有授权边界，不能只比较卡片数量。

验收条件与顺序

先建立公开命令族与内部操作的映射、受管 argv 适配和角色回归，再合并 Skill、兼容旧路径并同步前端。 验证 Skill 有两个正式内置项；CLI 页面和 tool_list 均只有一个浏览器入口 roami chrome，不再平铺 browser_*； 新旧 Skill 路径可读取正确内容，旧 Chrome 路径不能让 research 读取 roami 运维文档； research 通过 roami chrome 可导航观察、不可交互或执行通用 Shell；普通 Worker 的交互和专业 Agent 的 roami chrome 路径继续有效。 验证检索、截图交付、会话继续、未知动作恢复，并检查中英文 Skill 展示。 实施后运行相应运行时回归与仓库质量门禁；前端改动执行前端门禁与桌面、Android 真机验收。
