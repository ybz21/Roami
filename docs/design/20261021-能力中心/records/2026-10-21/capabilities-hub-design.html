能力中心设计 · 2026-10-21

基线为本次 main 快照 a9cfaa6。目标是交付能真实管理、持久保存并被 Agent 调用的首版能力中心。

1. 产品设计

交互原型

原型复用实际能力页组件。运行 cd frontend && npm run design:capabilities 生成含原型的单文件设计 HTML，默认输出到 /tmp/capabilities-design.html。

打开设计与原型 · 单独打开原型

原型使用隔离的示例数据，可操作上传、新建、编辑和保存；不访问真实业务接口。

信息架构与页面

导航中的“插件”升级为“能力”。页面设 Agent、插件、Skill、MCP、CLI、基础工具六个 Tab，默认打开 Agent。 设置中的 Agent 能力管理整体迁入；内置 Agent 的模型、运行时、消息、记忆配置仍归设置；Claude Code、Codex、OpenCode、Pi 的管理迁入 Agent Tab。 旧 settings/agent/bin 及其 Agent 深链映射到 capabilities/agents；旧插件深链和 settings/agent 下的 skills、cli、mcp、tools、capabilities 深链映射到新页面。

桌面使用统一页头、分类 Tab 与搜索目录。插件与其他分类统一采用独立能力卡片，展示图标、名称、来源、 简短描述和真实状态；查看与编辑在卡片底部直接可见。详细指令、参数与配置按需打开。页面壳与相邻模块同底、直角，以单条细线分隔。 手机从“工具”进入能力，保留首页、项目、工具、设置四个主入口；长详情、创建和导入使用全屏二级页， 只有一层返回栏和一个滚动容器，输入与提交避让键盘。 编辑表单的保存栏位于字段滚动区外，键盘留白只由 MobileSubPage 处理。

创建、导入与配置

  • Agent：Claude Code、Codex、OpenCode、Pi 使用品牌卡片，展示安装、登录确认状态与可用额度。安装和更新沿用已有白名单接口；列表自动读取已安装版本和程序位置；版本探测合并并发并缓存，“检查”立即重查。管理详情可保存启动命令（包括模型参数），打开已有会话终端完成登录与模型选择。安装成功不代表已登录；没有可靠证据时显示“登录待确认”。
  • 插件：卡片展示来源、名称、版本、描述与启停开关，提供“查看详情”和“配置”入口；桌面按需打开详情弹窗，手机使用全屏二级页。配置入口直接进入表单；保留插件包上传、本地目录安装、内置插件恢复、命令、权限与审计。旧深链直接打开对应详情，返回沿用 URL 历史。
  • Skill：点击“创建 Skill”填写名称、描述与 Markdown 指令，可从发布检查模板开始并切换预览；点击“上传文件”选择或拖入 SKILL.md，也可粘贴内容。读取后先解析名称与描述，进入可编辑确认页，再点“确认导入”。
  • MCP：点击“添加 MCP”选择远程服务地址或本地程序；也可上传单个配置或 mcpServers JSON，解析后编辑确认。 配置保存后显示“未连接”，显式连接才启动进程或访问服务，按真实发现结果显示连接状态与工具数量。
  • CLI：点击“注册 CLI”填写程序、参数数组和可选工作目录，或上传 JSON 后编辑确认；参数中的 {input} 代表调用参数 JSON。 复用运行时的工作目录边界与进程管理，不隐式调用 shell。
  • 基础工具：保留内置工具参数与读写属性查看，固定工具不可编辑或关闭。

卡片上的“编辑”直接打开同一份表单，预填已有内容，名称固定；用户可修改描述、指令或连接配置，并点击“保存更改”。托管能力支持移除；Skill 和 CLI 沿用启停策略。重复名称明确报错，普通导入不覆盖旧配置。 编辑保留名称，批量 MCP 先全部验证再原子保存。失败保留输入，给出可读的纠正提示。 MCP 凭证使用 env_env、header_env、key_env 引用环境变量，不接受或回显明文凭证。 本版外部导入指文件上传或粘贴配置；不把未实现的在线市场、仓库下载或 OAuth 授权显示为可用功能。

2. 用户故事

  1. 作为专业 Agent 用户，我能在能力页找到 Claude Code 和 Codex，安装或更新、检查版本、保存启动命令，并进入终端完成登录和模型选择。旧设置链接继续有效，保存失败保留输入，偏好加载完成前不会用默认命令覆盖已有配置。
  2. 作为已有插件用户，我从“能力 / 插件”继续配置定时任务，旧状态条链接仍能选中原插件。
  3. 作为 Agent 用户，我不用在设置和插件页之间寻找工具；分类地址可以分享、刷新，并跟随浏览器返回。
  4. 作为流程维护者，我上传 SKILL.md，确认名称和内容后保存；立即可在目录找到，重启后仍存在。 重名时收到提示，我的输入不会清空，必须显式编辑才能替换。
  5. 作为外部服务用户，我粘贴 MCP 配置后先登记，再点连接查看真实结果；连接失败可修正配置并重试。
  6. 作为命令行用户，我登记程序和参数，Agent 在已有工作目录约束内调用；停用后旧调用也被阻止。
  7. 作为手机用户，我能通过真实触控完成分类切换、查看、创建和返回，键盘不会遮住保存按钮。
  8. 作为管理员，我移除自行创建的能力后，它立即退出目录；内置能力保持只读，移除失败不伪报成功。

模块与数据流

能力页 → 节点感知 api() → Go 登录网关 → 私有 Agent HTTP
  → CapabilityImports（验证、名称冲突、原子保存）
  → Tools.skills / Tools.registry / MCPConnections
  → CapabilitySettings.view（目录、托管配置、真实状态）
  → 已有 read / bash / tool_list 调用路径

托管数据保存在当前节点 data_root/agents/capability-imports.json，文件权限 0600，父目录 0700。 临时文件写入、fsync 后原子 replace；落盘成功后更新内存，失败保持原目录。启动时验证并恢复托管项。 注册和移除串行化，与启停策略共享互斥；MCP 存在正在执行或排队请求时拒绝改配和移除，避免截断调用。

插件沿用已有 /plugins 与 /plugin 接口，通过 Go 网关访问插件管理器，不重复登记为 Skill。目录只加载身份和状态，按需打开详情才读取配置；配置表单由 manifest 字段生成，秘密字段按 manifest.configFields.secret 或 permissions.secrets 完整打码，表单只提交用户改动项。配置读取失败时阻止编辑并提供重试，安装成功后返回目录，不再另开命令日志弹窗。卡片打开详情写入分类 URL，手机详情不额外压入 overlay history。

Agent 目录复用 /agent/professional 和节点偏好。页面仅一个可见性控制的轮询，错误退避且保留最近快照；安装按需执行。列表自动读取版本，成功缓存 5 分钟，失败退避 1 分钟；可执行文件路径、身份、大小或修改时间变化立即失效，安装成功清缓存，显式检查绕过已完成缓存。版本检查只允许运行已注册 Agent 的默认程序和固定 --version 参数，3 秒超时、输出上限 4 KiB。新窗口不会自动启动 CLI，也不会把本地凭证返回给前端。专业 CLI 的 Skill / MCP 配置继续由各自管理，不声称 Roami 托管能力已自动绑定到它们。

接口与边界

  • GET /api/agent/capability-settings：目录、来源、可变标记、托管配置与 MCP 状态。
  • PUT /api/agent/capability-settings：现有 Skill / 工具启停策略，内置项仍拒绝修改。
  • POST /api/agent/capability-imports/{skills|cli|mcp}：创建或导入，MCP 支持原子批量登记。
  • PUT、DELETE /api/agent/capability-imports/{kind}/{name}：编辑或移除托管项，名称不能暗中改变。
  • POST /api/agent/capability-imports/mcp/{name}/connect：显式连接并发现工具，超时或失败不报告连接成功。

每次导入请求最多 64 KiB，持久目录最多 1 MiB，每类最多 64 个托管项，MCP 沿用最多 16 个服务限制。 名称只接受小写字母开头的短标识；JSON Schema 禁止外部引用。 CLI 参数按 argv 传递，{input} 只做单个参数内替换；执行仍经过既有 Agent 上下文与 shell 权限边界。 不增加常驻轮询，目录在进入分类或成功变更后更新，插件原有状态刷新遵守页面可见性规则。

验证计划与交付边界

自动验证覆盖所有者隔离、格式与体积限制、重名与批量原子性、内置保护、落盘失败、重启恢复、 Skill / CLI 真实调用、启停与移除、MCP 惰性注册和真实发现。界面覆盖旧地址迁移、分类、创建 / 导入和失败保留输入。 交付前运行前后端质量门禁，并在桌面浏览器和 Android 真机检查导航、触控命中、滚动、键盘、安全区及无横向溢出。 此次交付为可审阅的开发版本，不自动发布到用户正在使用的服务或外部托管平台。

原型与交互修订 · 2026-10-21

设计 HTML 默认打开交互原型，并可切换桌面 / 手机、深浅主题与中英文。 原型通过构建脚本将真实页面组件、样式和示例目录打包成单文件，再内嵌到总 HTML 中。 iframe 使用 sandbox 隔离来源，示例 API 完全在页面内处理，不访问真实配置或业务接口。 原型入口为 frontend/prototypes/capabilities.tsx，示例目录为 capability-catalog.ts，构建入口为 frontend/scripts/build-capability-design.mjs。

新建：按当前分类分别显示“创建 Skill / 添加 MCP / 注册 CLI”，直接填写有示例的表单；Skill 提供模板与 Markdown 预览。 上传：选择或拖入文件后立即解析，再进入可编辑的确认页；也支持粘贴文件内容。 编辑：卡片底部直接显示“编辑”，预填现有配置，名称固定，点击“保存更改”提交。
