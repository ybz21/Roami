# 手机 Web Material 界面标准

这份标准适用于 `data-size="compact"` 下的整个 Web 应用。视觉采用 Android Material 的顶部应用栏、底部主导航、分组列表、状态层与清晰的触控层级；颜色、字号、圆角和间距仍以 [Web UI 设计系统](./ui-design-system.md) 的令牌为准。桌面布局沿用现有设计。

## 页面结构

| 层 | 用途 | 实现 |
|---|---|---|
| 顶部应用栏 | 当前页面、返回路径、搜索和当前页的主动作 | `App.tsx` 的 `.tt-mobile-topbar`；固定在页面滚动区外，包含顶部安全区 |
| 内容区 | 当前页面的数据与操作 | `.tt-canvas` 内独立滚动，左右使用 `--pad-page`；一级页不重复顶部栏已有的标题 |
| 底部导航 | 首页、项目、工具、设置四个常驻目的地 | `.tt-bottomnav`；包含底部安全区，页面预留其高度 |
| 二级页 | 项目详情、文件预览、工具详情等 | 优先复用 `MobileSubPage`；设置分类和安装页保留底部导航，会话与文件等覆盖层按场景决定 |
| 会话覆盖层 | 终端和对话 | 保持独立全屏覆盖层，不把底部导航叠在输入区上 |

主导航的职责必须稳定：首页显示状态摘要和最近活动；项目页浏览项目、工作区与会话；工具页只放文件、浏览器、手机镜像和插件等工作入口；设置页管理节点、推送、外观、安装和账户。通知是事件流，由顶部带未处理数量的入口和首页摘要进入，不占主导航位置；返回时回到之前的主页面。首页不复制完整的通知或项目列表。一级页的标题由顶部栏承担，正文不重复标题。四个主页面的顶部栏都显示搜索入口：项目与设置点按后展开本页搜索框，首页与工具打开全局搜索；项目与设置平时不另摆一个搜索框。有标题的二级页返回栏也显示搜索入口，打开全局搜索。二级页只显示一层等高的返回栏；设置分类和安装页底部仍显示四个主导航入口；有独立 URL 的子页由路由管理返回，临时详情层由覆盖层管理返回。详细原型与评审见 [手机导航原型](../design/web/mobile-navigation.html)。

## 视觉和交互

- 顶部应用栏的内容行高为 `calc(var(--tap) + var(--sp-4))`，左右图标按钮各有 `--tap` 的命中区。标题使用 `--fs-title`，长标题截断。顶部与底部栏均用 `--bg-container` 和 `--border-subtle`，内容区用 `--bg-base`。
- 底部导航每项占等宽空间，图标和文字共同标示目的地。选中项使用 `--accent` 与加粗文字；不绘制大面积背景胶囊。未选中项用 `--text-dim`。所有图标来自仓库的 SVG 图标集，图标按钮必须有 `aria-label`。
- 页面横向留白使用 `--pad-page`，区块使用 `--sp-*` 间距。参考 GitHub 手机通知页：筛选是可横滑的浅色圆角按钮，视觉高度为 `calc(var(--tap) - var(--sp-2))`，命中区仍为 `--tap`；选中态有边框和文字强调。信息流是图标、主文、次文、时间组成的平面列表，用细分隔线组织。状态卡只用于需要突出的一组数据，避免卡片套卡片和重复描边。搜索框、列表行与设置组在手机上保持至少 `--tap` 的触控高度。
- 弹层、软键盘、刘海和底部手势区分别遵循 `--z-*`、`--kb` 与 `--safe-*`。文档不能滚动，内容区自己滚动；设置子页只用一层滚动容器，让底部控件也能触达；任何一级页都不能产生横向溢出。
- 底部导航的占位只由 `.tt-canvas` 提供；一级页不要再叠加会话坞的底部留白，否则设置分类列表会在半屏处截断。
- 有数据、加载中、空状态和请求失败必须各自有可读反馈。一个辅助接口失败不能把已拿到的主数据清空。通知页只把仍待确认的会话作为可操作项；允许/拒绝动作只出现在确实支持该操作的提醒上。
- 指针交互遵守 `AGENTS.md`：粗指针触控区不少于 44px、悬停仅限精细指针、无文字图标、所有新文案走 i18n。
- 会话顶栏与一级页使用同一 `--mobile-topbar-h`；会话切换胶囊以视口为基准居中，会话视图切换与 Git 等操作收进右侧菜单。终端只显示 TUI 自己的输入区，点按终端才聚焦并唤起软键盘；进入会话时键盘保持收起。
- 会话输入框上方的状态条保持一行：模型与指标的视觉高度为 `calc(var(--tap) - var(--sp-4))`，可点项命中区仍为 `--tap`。手机用“上下文”“额度已用”短标签，数值和含义都应在窄屏直接可见。
- 手机进入正在运行的 Claude 或 Codex 会话时默认显示渲染对话；用户从菜单切回原始终端后，轮询不能再自动切回。独立会话页遵循同一规则；普通命令行会话仍显示终端。
- Claude 与 Codex 对话界面的操作强调色统一使用 `--accent*` 蓝色令牌，包括气泡、输入区标识和桌面切换按钮；连接与执行状态仍使用各自的语义色，品牌 Logo 保留官方颜色。

## 独立应用与系统状态栏

安装到主屏幕后由 `manifest.webmanifest` 的 `display: standalone` 在独立窗口启动：隐藏浏览器地址栏，保留 Android 的时间、信号和电量栏。状态栏颜色跟随顶部应用栏的 `--bg-container`。普通浏览器页签保留浏览器界面；不能通过 Fullscreen API 自动进入，因为该模式会同时隐藏系统状态栏。手动全屏入口仍由用户自行选择。“装到手机”是获得无地址栏体验的入口。

## 验收

在真实 Android Chrome 上硬刷新后，逐一检查首页、项目、工具、设置、通知及一个二级页：顶部和底部导航都可点，标题不重复，返回路径正确，数据真实出现，空状态居中，滚动与安全区正常，`scrollWidth <= innerWidth`。用真实 CDP 点按验证命中；在已安装入口确认地址栏隐藏且系统状态栏可见。不能只靠 DOM `click()` 或桌面缩窄视口。代码检查按 `AGENTS.md` 的前端门禁执行。
