# Roami UI 设计规范（强制）

更新日期：2026-10-20。适用于 Roami Web 的桌面、手机浏览器与 Android WebView。
所有新增和修改的界面必须遵守本规范；规则入口是根目录 [AGENTS.md](../../AGENTS.md)。

视觉基调：中性底色、清晰层级、平面列表、克制强调。优先展示内容、当前状态和下一步动作；
避免重复标题、卡片套卡片、满屏彩色状态块及无信息的说明文字。

### 首要原则：简洁、用户友好

- **先内容，后说明**：默认只展示完成当前任务需要的信息和动作。用户看得懂的控件不再配一段操作教程。
- **少写文字**：按钮用简短动词，标签直说含义，提示优先一句话；不堆欢迎语、泛泛介绍、重复标题或重复状态。
- **说用户的话**：使用日常、具体的表达，不把内部实现、接口名和调试术语放进主流程。
  错误先说明发生了什么、用户能做什么，完整日志按需展开。
- **按需展开**：列表展示身份和必要状态，详情承载长内容；次要操作收进清晰的菜单，避免满屏按钮。
- **减少选择成本**：同一区域突出当前最重要的动作，相关内容放在一起；保留用户选择和输入，避免反复设置。
- **简洁不牺牲可用性**：保留字段标签、必要风险提示、恢复动作与可访问名称；触屏操作不能只靠悬停或 Tooltip 才看得懂。

本版依据当前产品代码与已确认的
[桌面工作台实现](../design/20261019-桌面智能体工作台/implementation.md)、
[三标签设计](../design/20261019-桌面智能体工作台/messages-layout.md) 整理。
[13 移动端响应式](../design/web/13-mobile-responsive.md) 和
[14 桌面工作区](../design/web/14-desktop-workspace.md) 保留设计背景；历史稿、修订快照中的旧导航和旧尺寸不作为新增界面的依据。
手机细则见 [mobile-material-ui.md](./mobile-material-ui.md)，真机验收见
[web-ui-checklist.md](./web-ui-checklist.md)。

## 1. 配色

颜色由 [`theme.tsx`](../../frontend/src/theme.tsx) 的 `THEME_TOKENS` 统一管理，
同时供给 CSS 和 Ant Design；[`index.css`](../../frontend/src/index.css) 提供启动前回退值与基础令牌，
[`mobile-material.css`](../../frontend/src/mobile-material.css) 提供移动端覆盖。
组件使用 `var(--token)`，不复制色值、不在组件内自行判断深浅主题。

### 中性色与表面

以下色值用于设计核对，实际开发引用令牌。

| 角色 | 令牌 | 深色 | 浅色 |
|---|---|---|---|
| 页面、导航、并排模块、手机上下栏 | `--bg-base` | `#0d1117` | `#f6f8fa` |
| 独立内容卡、输入卡、控件表面 | `--bg-container` | `#161b22` | `#ffffff` |
| 浮层与抬升表面 | `--bg-elevated` | `#1b222b` | `#ffffff` |
| 终端 | `--bg-term` | `#0b0f14` | `#ffffff` |
| 常规边框 | `--border` | `#30363d` | `#d0d7de` |
| 分隔线、弱边界 | `--border-subtle` | `#21262d` | `#e6e9ec` |
| 标题、正文 | `--text-bright` | `#e6edf3` | `#1f2328` |
| 时间、来源、辅助文字 | `--text-dim` | `#8b949e` | `#57606a` |
| 最弱装饰性信息 | `--text-dimmer` | `#6e7681` | `#8c959f` |
| 导航与普通列表选中底色 | `--sel-bg` | 白色 6.5% | `rgb(27, 31, 36)` 的 5.5% |
| 鼠标悬停底色 | `--list-hover` | 白色 2.5% | `rgb(27, 31, 36)` 的 4% |

正文与可操作信息需满足 WCAG AA 对比度；不能只靠弱色或颜色区别状态。
选中行使用中性 `--sel-bg`，配合强调线、字重或当前位置语义；不要给整条导航铺蓝色。
手机底部导航选中项只用 `--accent` 与字重强调，不画大面积背景胶囊。

### 语义色

| 角色 | 令牌 | 深色基准 | 浅色基准 |
|---|---|---|---|
| 主动作、链接、聚焦 | `--accent` | `#58a6ff` | `#0969da` |
| 成功、正在运行、diff 增加 | `--ok` | `#3fb950` | `#1a7f37` |
| 待确认、警示 | `--warn` | `#d29922` | `#9a6700` |
| 失败、危险操作、diff 删除 | `--danger` | `#f85149` | `#cf222e` |

| 变体 | 用途 |
|---|---|
| `--accent` / `--ok` / `--warn` / `--danger` | 对应语义的文字、图标、状态点与线条 |
| `--accent-solid` / `--ok-solid` | 实心按钮、徽标等色块 |
| `--accent-soft` / `--ok-soft` / `--warn-soft` / `--danger-soft` | 强调芯片、徽标、状态淡底；普通选中行仍用 `--sel-bg` |
| `--accent-border` / `--ok-border` / `--warn-border` / `--danger-border` | 对应语义的描边 |

`--accent-solid` 由 `theme.tsx` 使用 `antdTheme.getDesignToken()` 推导后回填。
自绘实心控件必须引用它，不能照抄种子色，否则会与 Ant Design 控件出现色差。
主按钮、Segmented 选中态共用这一来源，不另配一支蓝。

状态同时提供文字或可访问名称。运行中、待验收、失败、已完成必须依真实业务状态呈现；
不能根据执行器报告或局部产物把失败绘成成功。空闲、历史信息使用中性色。
Claude 与 Codex 对话的操作强调色统一为蓝色，绿色不作为 Codex 对话的另一套主题。

四组语义色之外，已有 `--swarm*` 只用于蜂群身份，`--hl-*` 只用于代码语法高亮；
品牌标使用 `--brand-claude` / `--brand-codex` 官方品牌色，裸露呈现，不加 Tag 外框。
这些专用颜色不得借作新状态色。

## 2. 大小与令牌

基础刻度定义在 `frontend/src/index.css`，主题和手机样式按职责覆盖。
表中尺寸单位为 CSS px；**组件里使用令牌，不写死已有令牌覆盖的值**。

### 字号（六档）

| 令牌 | 值 | 用途 |
|---|---:|---|
| `--fs-micro` | 11 | 眉标、角标。**唯一允许 <12 的一档** |
| `--fs-meta` | 12 | 次要信息：时间、路径、计数 |
| `--fs-sm` | 13 | 密集列表行、区块标题 |
| `--fs-body` | 14 | 正文（compact 档 15） |
| `--fs-lg` | 16 | 区块标题 |
| `--fs-title` | 22 | 页面标题 |

**除眉标/角标外不许低于 12px。** 不要出现 10.5 / 11.5 / 12.5 / 13.5 这类半档。

### 圆角（四档）

`--r-xs 6`（控件）· `--r-sm 10`（行、导航项）· `--r-card 14`（卡片、sheet 内块）·
`--r-pill 999`（胶囊、徽标）。

### 间距（五档）

`--sp-1 4` · `--sp-2 8` · `--sp-3 12` · `--sp-4 16` · `--sp-5 24`。一律 4 的倍数，
不要 3/5/7/9/11/13。

### 密度 / 层级 / 安全区

| 角色 | 令牌或既有尺寸契约 | 使用规则 |
|---|---|---|
| 最小触控命中边长 | `--tap` = 44 | 与视觉大小分开；粗指针不能随密度缩小 |
| 控件视觉高度 | `--ctl-h` = 32；compact 为 40 | 粗指针至少 40，命中区仍至少 44 |
| 页面留白 | `--pad-page` = 16 | 当前手机 Material 样式同样为 16；不能照抄基础 compact 回退的 12 |
| 布局间隔 | `--gap` = 10；compact / 紧凑密度为 8 | 复用已有布局令牌；普通新增间距使用 `--sp-*` |
| 列表密度 | `--row-cozy` = 42，`--row-compact` = 34 | 紧凑密度只收视觉留白，不缩触控命中区 |
| 桌面展开导航 | `--nav-w` = 280 | 与壳层布局常量保持一致 |
| 概览 / 表单最大宽度 | `--content-overview` = 1680 / `--content-form` = 920 | 内容居中，窄窗口不强撑最小宽度 |
| Agent 对话阅读宽度 | `calc(var(--sp-5) * 32)` = 768 | 主消息流最大宽度，不铺满超宽屏 |
| Agent 输入区最大宽度 | `calc(var(--sp-5) * 34)` = 816 | 居中，实际宽度不超过可用内容区 |
| Agent 桌面工作台 | `clamp(440px, 34vw, 640px)` | 当前 `agent-workspace.css` 的专用尺寸契约，仅用于 large 档右栏 |
| 手机顶栏、返回栏、底栏内容高度 | `calc(var(--tap) + var(--sp-4))` = 60 | 用 `--mobile-topbar-h` / `--mobile-nav-h`；安全区另计 |
| 手机顶栏操作图标 | 20，命中区 `--tap` = 44 | SVG 的 viewBox 仍是 24 × 24；复用现有按钮组件 |

正文使用项目既有的 Inter / 系统无衬线字体栈，中文回退到系统黑体；代码、路径和终端复用等宽字体。
正文基准行高 1.6；不要用缩小字号来塞下溢出内容。长标题单行截断，摘要最多两行，全文放详情。
基础圆角只用上述四档；已有 `--r-sheet`、`--fs-chip` 是专用令牌，不扩充通用刻度。

层级使用具名 `--z-*`：导航 `--z-nav`、二级页 `--z-subpage`、会话 `--z-session`、
会话内二级页 `--z-session-sub`、抽屉 `--z-sheet`、桌面面板 `--z-panel`、弹窗 `--z-popup` 等。
不要手写 1199/1200/1201；安全区使用 `--safe-t/b/l/r`，软键盘避让使用 `--kb`。

## 3. 通用布局与组件

### 模块背景、边框与圆角：所有页面共用一套

**选择平面同底、细线分隔。** 深色页面统一使用 `--bg-base`，不混用纯黑和灰色模块底；
浅色主题遵循同一层级。首页、文件、浏览器、手机镜像、项目、插件、设置等所有路由均适用。

| 层级 | 背景 | 边界与圆角 |
|---|---|---|
| 页面外壳 `.tt-page` | `--bg-base` | 铺满可用区域；外边距、外框、圆角、阴影均为 0 |
| 并排模块：导航、文件树、预览、设置分类、Agent 工作台 | `--bg-base` | 直角，无包围框和阴影；相邻边仅一条 `1px solid var(--border-subtle)` |
| 模块工具栏、标签栏 | `--bg-base` | 无外圆角；需要分隔时仅留底边线，不另套卡片 |
| 独立内容卡、项目卡、输入卡 | `--bg-container` | `--r-card`；需要轮廓时使用一圈 `--border-subtle`，不再套同类外框 |
| 按钮、输入框、行内交互 | 沿用组件语义表面 | 小控件 `--r-xs`，标准控件 / 行 `--r-sm`；徽标与胶囊使用 `--r-pill` |
| 菜单、弹窗、sheet | 沿用 `--bg-elevated` / 既有 Modal 容器色 | 菜单 `--r-sm`，弹窗 `--r-card`，底部 sheet 使用专用 `--r-sheet` |

分隔线只由一侧绘制，例如右栏的左边线；不得与左栏的右边线叠成双线。
整页有多个功能区不等于每个区都是卡片；独立卡片用于可单独理解的内容项，不能作为页面布局外壳。
页面留白放在内容段内，工具栏和分隔线可以通栏，不能靠整页外边距露出另一圈底色。
镜像舞台的空白区域同样使用 `--bg-base`；远端画面、视频、文档纸张与终端画布保留内容本身颜色，
不为统一页面底色而改写内容。新增样式直接修改对应组件与公共规则，不叠加逐页补丁恢复旧外框。

### 结构与内容

- **固定高度应用壳**：`html, body { overflow: hidden }`，页面在自己的内容容器滚动。
  flex 子区正确设置 `min-width: 0` / `min-height: 0`；不能让内容撑出文档滚动条或挤动旁边终端。
- **页头统一 `.tt-pagehead`**：标题（h2）+ 右侧动作（.acts）；眉标与说明按需添加，不能重复标题或解释显而易见的操作。
  沿用已有结构，不要各写各的标题行。
- **不要嵌套同名壳**：页面已经在 tab 或路由里说明了身份，就别再套一层带同名标题的 Card。
- **区块标题**用 13px 正常字重的亮色文字，**不要**「小号 + 大字距 + 横贯全宽的虚线」——
  那条线不承载信息却横穿版面。
- **少画框**：布局模块共用页面底色，以留白和必要的单条分隔线组织，不给侧轨或内容区再画包围框。
- **箭头等符号用 SVG 图标**，不要 `→ ← ⌃ ✕ ▾ ▸ ✓ ⎇ ⧉` 这类文字符号，也不要 emoji
  （🔄 📎 🤖 📢）：字号下与标点混在一起，粗细跟不上界面的线性图标语言，emoji 还各平台一个样、
  高低不齐。图标统一从 [`frontend/src/icons.tsx`](../../frontend/src/icons.tsx) 取
  （24×24 viewBox / `currentColor` / 1.8 线宽），文件类型图标在 `file-icons.tsx`、
  Git 相关在 `git/parts.tsx`。**同一个动作全站必须是同一枚图标**——关闭曾经在 Dock 是 `✕`、
  浏览器标签是 `×`、文件页签又是第三个写法。
- **图标别写进 i18n 文案**：`'＋ 新建'` 这种把符号焊死在译文里，换图标要改两份 locale，
  而且换不成 SVG。文案只写字，图标在调用处用 `icon={<PlusIcon />}` 给。
- **输入卡统一 `.tt-composer`**：项目页「下任务」和对话页「发消息」是同一件事的两处长相——
  一张卡（`.tt-composer`），上面 `variant="borderless"` 的文本框，下面一条控制条
  （`.tt-cbar`：左边 `.tt-cgrp` 放「怎么干」的选项，右边 `.tt-cend` 贴动作）。
  选项一律是 `.tt-pill`（`.on` 选中 / `.ico` 图标钮 / `.sel` 带值下拉 / `.danger`），
  主动作是唯一那枚实心圆 `.tt-send`。**一条控制条只有一种控件长相**，也只有一个实心块。
  pill 必须是 `<button type="button">`，不是 `<span onClick>`。
- **内容优先**：列表仅展示身份、必要状态、摘要和时间；长错误、修订历史、执行记录进入详情或显式折叠。
  空态只留一句短消息与必要动作；零结果计数隐藏，只有一页时不显示分页。保留失败原因与恢复入口。
- **按钮语义**：动作默认使用 `<button type="button">`，真正导航才用 `<a href>`。
  行尾操作复用 `.tt-act`，危险和确认动作使用 `.danger` / `.ok`；禁用状态与键盘焦点必须可辨。
- **文案**：产品新增文字统一走 [i18n](./i18n.md)，包括 aria-label、错误、空态、提示和按钮；
  不在翻译中夹带图标。开发者设计文档可使用中文。

## 4. 响应式档位

唯一入口为 [`useLayout()`](../../frontend/src/layout.ts)。业务组件不得读取 `window.innerWidth`
或自行调用 `matchMedia`。纯样式差异使用 `<html>` 的 `data-size` / `data-orient` / `data-pointer`。

| 档位 | 视口宽度（CSS px） | 布局规则 |
|---|---|---|
| compact | <600 | 手机单栏，顶部应用栏、底部四入口，详情用全屏二级页 |
| medium | 600–904 | `phone=true`，沿用手机导航与详情模式，不硬塞桌面三栏 |
| expanded | 905–1279 | 桌面导航轨，主内容优先；Agent 工作台不常驻，用原有详情入口 |
| large | ≥1280 | 可展开桌面导航与常驻工作区；Agent 对话右侧显示可收起的三标签工作台 |

触控看 `data-pointer`，不能用窗口宽度代替；触屏电脑同样遵守粗指针规则。
`data-size="compact"`（窄窗口）与 `data-density="compact"`（紧凑密度）是两个独立属性。
旋转、缩放或调整窗口后应保留选中项、草稿和可恢复的滚动位置，不重置用户任务上下文。

## 5. 桌面设计规则

- 壳层沿用左侧导航 / 项目会话树、中间主内容和按需右侧检查器 / 终端区；
  large 可展开导航，expanded 收为导航轨。文件与会话复用现有工作区标签及可拖拽分栏，不另造一套壳。
- 首页 Agent 主对话始终在中间可用，large 右栏顺序固定为**任务 / 消息 / 记忆**。
  首次默认展开，展开状态与当前标签按节点保存在本地；收起后保留明显的展开入口。
  不恢复独立消息导航、独立提醒标签、重复铃铛或上下文 / 概览更多菜单。
- 切换右栏标签、打开任务详情不能遮住主对话或打断输入。任务详情依次呈现身份与状态、
  产物、执行结果；工具 / 命令过程默认折叠。任务与记忆采用平面列表，避免每行再套带边框的卡片。
- 消息合并通知与提醒；未触发的提醒放“待提醒”分组，不计未读。查看来源保持消息标签，
  显式查看关联任务才切任务标签。标已读不取消提醒；通知偏好与投递诊断放设置页。
- 常规刷新由已有自动更新和浏览器刷新承担，不增加常驻刷新工具栏。
  键盘可到达所有动作，保留可见焦点；悬停、右键和快捷键是增强入口，不能成为唯一操作方式。
- 对宽度、折叠等可见偏好，首帧读取本地镜像，再与服务端同步。
  从 `usePreferences()` 一次性初始化时等待 `preferencesLoaded()`，避免默认值覆盖真实偏好。

## 6. 手机设计规则

compact 与 medium 使用手机导航结构；具体样式复用 [手机 Material 标准](./mobile-material-ui.md)。

- **一级页**：顶部应用栏承担当前页标题、搜索和必要动作，正文不重复路由标题。
  底栏固定为首页、项目、工具、设置，等宽分布，图标与文字同时显示；消息从顶栏进入，不增加第五个主入口。
- **二级页**：记忆、后台任务、消息等内容视图使用 `MobileSubPage` 或专用路由，
  仅一层等高返回栏和一个内容滚动区。对话框只用于短确认、聚焦操作。
  URL 管理的子页不再叠加覆盖层 history；设置分类与安装页保留底栏，会话覆盖层独立全屏。
- **手机工作区**：不缩小桌面右栏塞进手机。Agent 任务、记忆等从现有顶栏 / 对话菜单进入二级页；
  长列表与详情完整占据可用内容区，任务结果与产物保持可读。
- **留白与表面**：手机页面水平留白使用 `--pad-page`（当前 16），避开左右安全区。
  顶栏、返回栏、底栏与内容底色使用 `--bg-base`，用 `--border-subtle` 分隔。
  信息流采用图标、主文、次文、时间组成的平面行；筛选可换行，不截断标签。
- **输入区**：Agent 正文 / 输入卡外侧水平留白 16，输入卡文字顶部 12、水平 16；
  工具条顶部 4、水平与底部 8，输入卡与底栏间隔 8，全部由 `--sp-*` 表达。
  手机输入框通过可见发送按钮提交；不能把手机 Enter 换行改成误发送。
- **安全区与键盘**：固定层使用 `--safe-*`，底部按组件约定取 `max(var(--kb), var(--safe-b))`。
  键盘弹出时隐藏底部导航，输入区与底部动作避让，顶部栏保持原有尺寸。
  底栏占位统一由 `.tt-canvas` 管理，不再叠加一份会话坞留白。
- **会话**：顶栏与一级页等高；会话名和项目名分层，长名称截断。终端覆盖层不叠底栏。
  进入会话不主动唤起键盘，用户点击输入后再聚焦；用户切到终端后不被轮询自动切回对话。
- **更新与状态**：复用自动更新与到顶下拉刷新，不放常驻刷新按钮；保持当前 URL。
  加载、有数据、空、失败各有反馈，辅助请求失败不能清空已有主数据。

## 7. 指针与触控

- 粗指针（`html[data-pointer="coarse"]`）下所有可点目标命中区 ≥ **44**。
  **用伪元素撑命中区，不要撑视觉尺寸**。
- 视觉小于 44 的控件（角标、行内链接）必须显式补 `::after` 命中区，并在真机上用
  `document.elementFromPoint` 验证——截图看不出来。
- 相邻小图标按钮的命中区向间隙外扩 `--sp-1`（4px），真机验证缝隙也能命中。
- 所有 hover 写成 `:where(html[data-pointer="fine"]) X:hover`；依赖 hover 显示的复制、关闭、
  下载等操作在粗指针下必须常显。粗指针隐藏 Tooltip，图标按钮的名称由 `aria-label` 提供。

## 8. 反复踩到的坑

这几条都在真机或 CDP 上咬过，改相关代码前先读：

| 现象 | 真因 |
|---|---|
| 页头 `position: sticky` 不生效 | 祖先里有个**不滚动的** `overflow:auto`。任何非 `visible` 的祖先都会成为 sticky 的参照系 |
| antd `Dropdown.Button` 把兄弟节点挤没/盖住 | 它内部的 `Space.Compact` 在 flex 容器里是块级 flex 子项，会一路撑开。包一层 `flex:0 0 auto` |
| `--kb` 与 `env(keyboard-inset-height)` 对不上 | VirtualKeyboard API 的 `geometrychange` 没订阅，`--kb` 只能靠 resize 顺带刷新 |
| 中间省略的名字读成两个词 | 头尾两段之间留了 gap。它俩是同一个名字被切开的两半，间距只加在项目前缀之后 |
| `项目 · 会话` 两截都被截成碎片 | 两段等比例挨压。给项目前缀 `flex: 0 100 auto`，让它先被吸收干净 |
| 软键盘收起后终端仍然只有半屏 | Chrome 的 keyboard inset 可能卡住不复位。**量高度前先确认 `env(keyboard-inset-height)` 是 0** |
| CDP 改视口后档位不变 | `Emulation.setDeviceMetricsOverride` 不触发 `resize` / `matchMedia change`。**每个视口重载一次**；纯 CSS 容器查询不受影响 |

## 9. 验收

界面修改按 [web-ui-checklist.md](./web-ui-checklist.md) 检查桌面与真实 Android：

- 深浅主题、中文 / 英文及四个档位均检查；重点覆盖 320 / 390 / 820 / 1100 / 1280 / 1600 / 1920 宽度。
- 文档无滚动、页面无横向溢出；桌面分栏与终端输出不引起布局横跳。
- 逐页检查首页、文件、浏览器、手机镜像、项目、插件与设置：页面无圆角外框，模块同底，分隔线没有重叠；独立卡片与输入控件的圆角层级一致。
- 手机上下栏、安全区、二级页返回、触摸滚动、按钮命中、键盘打开 / 收起均正常。
- 桌面三标签切换、收起后刷新恢复、任务详情中继续聊天正常；窄窗口入口仍可达。
- 空、加载、失败、长名称、长正文与产物均可读。手机验收必须包含真实点按，桌面缩窄不能代替真机。
- 首屏是否能直接找到主要内容和下一步操作；每段说明是否确实必要，能否删去或缩成一句话。

前端修改运行：

```bash
cd frontend && npm run typecheck && npm run i18n:check && npm run hover:check && npx vitest run && npm run build
```

`i18n:check` 除了查两份 locale 对齐，还会查 `t('key')` 引用的 key 是否存在——
key 拼错时界面会**原样显示这个 key**，而两份 locale 都缺它，只查对齐是发现不了的。

提交前运行 `scripts/dev/quality/check.sh quick`；有运行时行为变化的 PR 运行 `full`。
PR 截图与提交要求见根目录 `AGENTS.md`。仅文档修改核对链接、令牌与当前代码，不冒充产品 UI 已重新完成真机验收。
